# 기존 게임 실행·별도 창 작업의 사용자 확인 조건

2026-10-12 최신 [AGENTS.md](../AGENTS.md)의 실행 확인 규칙을 반영했다. 이 안내는 cpppj·dotnetpj와 공통 분석 도구에서 함께 사용하며, 규칙의 기준은 AGENTS.md다.

## 실행 전 확인과 시스템 예외

일반 시스템에서 기존 게임을 실제로 구동하거나 작업 중 별도 창을 띄울 때는, 실행 목적과 필요성을 개발자(사용자)에게 설명하고 명시적인 확인을 받아야 한다. CLI/MCP `start_session`, `mcp_smoke.py --live`, 검증용 원본/복사본 직접 실행과 클론·도구의 GUI 창 실행이 해당된다. `guide`·`record-play`처럼 기존 세션에 안내/녹화 창을 여는 작업도 창 생성 조건에 따른다.

## 작업 요청과 확인 범위

- 개발자가 **기존 게임 수동 컨트롤 방식** 또는 **기존 게임 플레이 녹화 분석 방식**으로 분석 진행을 직접 요청하면, 해당 작업 단계에서는 시스템과 관계없이 실제 게임 구동 확인을 다시 받지 않아도 된다.
- 일반적인 작업 진행 지시나 과거 실행 이력만으로 새로운 게임 실행의 확인을 대신하지 않는다. 일반 시스템에서 받은 실행 확인은 해당 작업 단계가 완료될 때까지 유지한다.
- 게임을 구동하거나 별도 창을 띄우지 않는 빌드·정적 분석·단위 테스트·기본 MCP 프로토콜 검사는 확인 대상이 아니다. Ghidra 헤드리스 내보내기와 격리된 기계어 관찰도 실제 게임이나 GUI를 실행하지 않으면 이 범위다.
- 작업 단계의 실행 확인과 함께 원본 파일 보호 및 사용자의 별도 중단·실행 금지 지시를 준수한다. 실행 허용 여부와 기술적인 실행 가능 여부는 각각 확인한다.

## 인수인계 문서 적용

과거 기록의 시스템 번호·예외 목록·“이 PC” 또는 “현재 PC” 표현은 기록 당시 날짜와 호스트의 이력이다. 특히 2026-09-29 표에서 `HJOW-Athlon`을 시스템 2로 적은 것은 당시 번호이며, 최신 목록에서는 시스템 3이다. 지금 작업할 때는 위 세 시스템 목록과 현재 호스트·사용자 지시를 기준으로 적용한다.

인수인계는 [cpppj·공통](../LEFT_JOBS.md), [dotnetpj](../LEFT_JOBS.dotnetpj.md)에 남긴다. 실행 안내는 [분석 도구](analyze-manager.md), [C++ 빌드](cpp-build.md), [C# 뷰어](map-viewer.md)에서 이 문서를 참조한다. AGENTS.md 자체는 AI가 수정하지 않는다.
