# dotnetpj 0.975 — Build에 전투 설명 0x71·참가자 제거 0x21 수신기 연결

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 같은 장기 기본 표를 공유하는 `ClientPacketDispatch.Build`/`InstallDefaults`에 원문 앱 전역 0x71 전투 설명·0x21 참가자 제거 수신기를 연결했다. 0x0f Build 연결과 제품 기존 경로는 바꾸지 않는다. 세션·메뉴 결합 후크 중 0x20·0x22·0x23·0x24·0x25·0x67·0x88(번역·안내·생성·좌석·Chat·표시·NSInfo 장치 필요)과 Root Source 공개·제출 갈래, RU-3 나머지·R4-4 정기 두 단위는 후속에서 잇는다.

## 변경과 원문 대응

- 0x71 후크는 실제 장기 장치와 0x1d와 같은 호출자 진단 장치를 공유한다. 분배·CS·진단은 실제 owner이며, 설명 본문(`NativeMetaBattleDescription.Receive` 재사용)은 CS0이면 조용히 건너뛰고 무효 전투는 수준9 로그만 남긴 뒤 돌아가며, 초과 길이는 로그 뒤 전투 번호 갱신 앞에서, 유효 설명은 복사·정제 뒤 표시 갱신 앞에서 명시 실패한다. 새로 만든 본체가 없다. 0.975에서 추가됐다.
- 0x21 후크는 실제 장기 장치와 같은 호출자 진단 장치를 공유한다. CS·모드·검사·진단·로그는 실제 owner이며, 범위 밖 번호는 진단·로그 뒤, 유효 제거는 좌석 삭제·버전 경계 뒤 NSInfo·전투·Chat·하차 표시 앞에서 명시 실패한다. 모드 거짓이면 버퍼·CS를 요구하지 않고 조용히 돌아간다. 새로 만든 본체가 없다. 0.975에서 추가됐다.
- 0x71·0x21의 수준9 로그는 원문 `WriteDiagnosticLog(9, …)` 대응으로 같은 호출자 진단 장치에 코드 9를 붙여 기록한다(cpppj `ClientMetaBattleDescription.cpp`·`ClientMetaPacketReceivers.cpp` 확인).
- 수송 팩토리(`ClientCampaignTransport.Make`)는 같은 `InstallDefaults`를 공유하므로 두 항목을 자동으로 공유한다.
