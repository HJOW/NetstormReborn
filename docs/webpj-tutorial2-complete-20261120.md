# Tutorial2 완주와 공통 객체(발사기) 메뉴 (WB04-E1086)

한국어 Tutorial2를 실제 Chromium에서 시작부터 완료 창까지 자연 진행으로 마치고 완료 창의 다음 튜토리얼 단추로 Tutorial3을 시작하는 데까지 확인했다. 신전·워크샾 건설과 연구 생산 뒤 D~G(발사기 네 개 배치, 신전 선택으로 에너지 범위 표시), H(에너지는 건설할 때만 쓰임), H1(회수), I(미션 완료)가 모두 통과한다.

## 구현

- **공통 객체 메뉴 열기.** 사제·Factory가 아닌 건물·방어물(발사기 등)의 오른쪽 클릭은 원본 공통 열기(+ac `004adb30`)를 쓰는데 앱은 사제·Factory만 열 수 있었다. [ClientObjectMenuOpen](../webpj/www/ui/client-object-menu-open.js)이 같은 `RawObjectMenuOpen`에 연결해 가상 표의 작성 주소가 Damageable(`0044cbd0`: 내 객체의 가상 개수 → 회수 행 → 공통 항목)이면 `ClientObjectMenu.openDamageable`을, 일반 객체(`004b1270`)이면 `open`을 쓴다. 건설 중 객체는 열지 않고 열릴 때만 원본 효과음을 낸다. 입력 프레임의 오른쪽 클릭은 사제 → Factory → 공통 객체 순으로 시도한다.
- **회수.** 메뉴의 회수 행(명령 `0x0200005d`)을 누르면 기존 회수 요청이 Session에 전달되고 Tutorial2의 H 단계가 이를 보고 I(미션 완료)로 넘어간다.
- **생산 보충 대기.** 처음 세 발사기를 집으면 생산 항목이 다음 보충 시간이 지날 때까지 대기 표식(`0x100`)을 달고 있어 네 번째는 시간이 지나야 집을 수 있다. 시험은 표식이 풀릴 때까지 기다린다.

## 검증

한국어 Tutorial2 흐름(`e2e/korean-mission.spec.js`, 약 1.7분)이 D→E→F→G→H→H1→I와 다음 튜토리얼 시작까지 통과한다. `tests/client-object-menu-open.test.mjs` 2건이 가상 표별 지원 판정·Damageable/일반 작성 선택·건설 중 거부·효과음을 대역 Session으로 확인하고 변형(작성 분기 뒤바꿈·효과음 제거)이 시험 실패로 잡힌다. 공통 열기 가드 변형은 다른 조합이 원본 표에 없어 동등 변형으로 본다.

## 남은 경계

Tutorial2 외 미션의 목표 수행·승리, 파생 +ac(운반체·사제 외의 편집·메타 변형), 영어 Tutorial2의 같은 흐름 확인, 완료 기록(`DoneTutorial2`)의 저장 확인은 남아 있다.
