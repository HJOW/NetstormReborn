# dotnetpj 0.507 — 사제 후반과 일반 Pop 가상 분배

2026-11-14, HJOW-Athlon. 사제 접두 다음에 현재 상태를 다시 읽는 후반과 공통 PostPop의 명시 분배를 옮겼다. 실제 호스트의 요새 사제 Pop·낙하/보호막 소비자는 아직 미연결이다.

## 구현

기준은 `d95b07dfb8da8b6b1f2b0bc794b9740773e0c493`의 `o/RawPriestPostPopTail.h/.cpp`, `o/SquidPostPop.cpp` 사제 연결/분배, `o/RawPriestState.cpp`의 같은 실제 HP 공유 계약이다.

`RawPriestPostPopTail`은 접두→실제 Carrier→현재 extra→현재 Immobile→조건부 지면/방향→낙하/보호막 순서를 보존한다. 지면은 float0.9999를 double 합산한 뒤 절삭하고, 낙하 플래그0x800이면 지면/프레임 조회 자체를 생략한다. 낙하 콜백이 extra를 바꿔도 선택했던 이동 불가 분기의 보호막 요청을 유지한다. 프레임 표는 원문처럼 생성 시 복사한다. 아직 도달하지 않은 소비자는 구성 때 요구하지 않는다.

`RawPriestState`에 기존 독립 HP 조회기 외 실제 `RawSquidReward`를 받는 연결을 추가했다. 접두와 상태가 같은 HP 배율을 읽으며 실제 메서드 delegate가 HP 장치의 수명을 유지한다. 기존 검사 경로는 유지한다.

`RawPostPop.SetPriestPostPop`는 같은 풀의 전체 조합만 연결한다. 일반 Pop/Activate는 현재 사제 가상표의 지원을 확인하고 실제 후반으로 분배한다. 직접 PATCH 가상 진입은 TYPE158을 추가 관문으로 만들지 않는다. 사제의 Carrier가 공통 장부 깊이를 한 번 끝낸다. 접두만으로 파생 지원을 허용하지 않는다.

## 다음과 실제 한계

최신 cpp의 `RawCarrierPostPop`은 PATCH에서 사전 검사를 호출하지 않고 도달한 효과만 요구하며 실제 권한/로딩/간헐천TYPE/현재TYPE 표를 다시 읽는다. C#의 기존 Carrier는 아직 무조건 사전 검사·구성 때 모든 효과 요구 계약이다. 이번 원본2048입력은 그 차이를 선택하지 않는 정상 입력이고, 일반 Pop 합성도 정상 상태 검사다. **호스트 결선 전에 Carrier를 HEAD의 현재 계약으로 보정해야 한다.**

그다음 보호막 조회/생성·낙하 모듈과 Tail 보호막 어댑터를 옮겨 실제 소비자를 채운다. 공통 사제 분배 장치는 생겼지만 실제 요새 Pop 연결/AI 생성 완료를 뜻하지 않는다. 다른 파생 PostPop·농지·전체 장부·요새 이미지·메뉴 시작·M1 대조도 계속 잔여다.
