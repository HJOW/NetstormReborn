## 현재 상태와 부작용 순서

ClientLocalStateGlobals.MonitorTime이 초기화 DWORD·기한8BYTE·monitor/alert의 두 signed DWORD를 한 번 소유한다. ClientMonitorOptions는 최초/Config 변경에 AutoRestart1→monitor→alert 순서로 해석하고 기한·초기화 비트·누락 옵션을 보존한다. Dispose는 자기 구독만 해제한다. 같은 Config의 다른 소비자를 바꾸지 않는다.

RawMonitorTime.Step은 처음 bit0만 켜고 기한0을 쓴다. 두 옵션이 모두0이면 비영 기한을 보존하며 시계/달력을 읽지 않는다. 활성 때만 현재 벽시각으로 예약·비교하고, 만료되면 달력→현재 이름→고정 서식→현재 monitorFormat→제출→새 현재 시계 재예약을 수행한다. 콜백이 상태를 바꾸는 위치와 NaN/부호 있는0·전체 DWORD를 보존한다.

임시 서식은 첫 manager의 NUL front를 보관하고 같은 실제 물리에 strncpy60(PATCH)/16(CD) padding·마지막BYTE0을 쓴다. 그 뒤 현재 manager로 제출하며, 정상 복귀 뒤에만 현재 manager를 다시 읽어 이전 서식을 복원한다. 제출 실패는 앞선 임시 변경을 남긴다. finally 복원이나 manager 사본은 없다.

실제 Game은 같은 Subscriber Handle·현재 Config의 원문1252 서식·기존 SubmitNativeChat을 빌린다.
