# 0.709 장기 Player 실제 할당과 고정뷰 대여

cpppj `ClientPlayerRecords`의 Player/factory 실제 할당·현재 opaque32 주소·단일 고정뷰 대여·실제 Core 별칭·같은 로그인 카운터를 이식한다. 생성/대여만으로 할당하지 않고 원문 초기화 부모가 Player 전체와120바이트 공장을 만든다. PATCH180간격 외 CD172간격 부모의 현재base 재조회·행 캡처·동맹 인자도 옮긴다.

집중14건(Core6·Client8)이 통과했다. Core는 `extracted/dotnet-0709/core-initial.log`/`player-initialization-initial.trx`, Client 최종은 `client-final.log`/`player-owner-final.trx`다. `verification-summary.json`으로중복없이집계했다. 기존 PATCH 원본202입력 검사를 함께 수행했다. CD는 C++ 원문과 독립 전체바이트/효과 검사를 사용하며 새 원본PE CDfixture를 확보한 것으로 판정하지 않는다.

현재 공장 목록의 getter 연결과 제품 HostSession/Root의 실제 장기 Player/옵션/Core 소비자 전환은 후속이다. 기존 실제 Runtime/brain/Deck 반납 증빙을 우회하지 않는다. 실제 플레이·포획/희생·특정 적 공격·시나리오 승리는 수행하지 않는다. 전체목표와M1은 미완료다.

초기 Client 검사는6통과/2실패였다. 실제 Core0 선택이 `TryGetArray`로같은주소를판별하므로Player를DWORD전용MemoryManager로만공개하면캐시복사가생략됐다. Player는같은실제byte배열, 공장은정렬된uint배열의바이트관리뷰로제공해Core별칭/캐시10바이트정리를보존했다. 정렬검사입력은120바이트물리범위를먼저통과하도록용량을1로고쳤다. 공장입력은기본적으로현재네이티브힙할당의실제바이트를복사/즉시반납하며, C++의CRT malloc대신Marshal.AllocHGlobal을쓴다. 미초기화바이트를일치상수로가정하지않으며검사는명시120바이트공급자를사용한다.
