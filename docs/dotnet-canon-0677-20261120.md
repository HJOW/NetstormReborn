# 0.677 공장 가상 그림과 실제 SHP 캡처

- 일시: 2026-11-20, HJOW-Athlon.
- 근거: `cpppj/src/o/RawFactoryDraw.cpp/.h`, `cpppj/tests/ShapeToBufferTests.cpp`, `factory-capture-x86.tsv`.
- 범위: Factory/Outpost의 기본·추가 프레임 선택, 실제 ShapeToBuffer/VFX 소비, 기존 제품 캡처 분배 연결.

## 구현

`RawFactoryDraw`는 실제10.78 풀과188개 프레임 표를 빌려 두 가상 표만 분배한다. 기본 그림은 상태 상위3비트의A~H 첫 프레임이며 없는 레벨은-1이다. 추가 그림은 extra의1/8과dead를 먼저 검사하고, 기본 그림과 다른 현재 signed 프레임만 실제 소비자에 보낸다. 원문에 없는free/void 선행 필터를 넣지 않았다. 미복원 가상 표/TYPE는 실제SID·TYPE·VT를 남겨 실패한다.

`HostMissionBurning`의 실제 캡처는 같은 세션 프레임 표와SHP/VFX로 공장 파생도 처리한다. 다른 파생의 경계와 전용 소유자 색표·실제 월드뷰 미연결 진단은 유지한다. 공장 캡처가 연결됐다고 전체 건설/업그레이드 또는R5 월드 출력이 완성된 것은 아니다.

## 검증

Release 집중 **17/17건 통과·실패0**다. Core 계약2건(`extracted/dotnet-0677/factory-core.trx`)과Client 최종15건(`factory-client-final.trx`, `client-final.log`)을 확인했다. 원본 fixture의 입력 여섯 칸으로만 장면을 만들고, 기대 메타데이터·전체 픽셀·확보량·문맥 복원 네 칸은 실행 뒤에만 대조했다. fixture는201행(머리1+입력200)이며 두 공장 가상 표·실제 보호SHP·기준점·배율·추가 그림60회가 모두 일치했다. 기존 연결337개 SHA 목록에 추가했다. 기존캡처13건과제품사제 추가그림1건도 통과했다.

첫 집중 실행에서Core 계약2건과 기존 캡처13건은 통과했고, 새 픽셀 대조는 클라이언트 슬롯5를 요구한 준비 코드가 기본 서버 할당15000을 사용해 실패했다. 검사 입력을C++의명시client 할당과 같게 고쳤다. 제품 본체 변경은 없었다.
