# dotnetpj 1.106 — 공통 내용물 분리의 Native 부모 통지

2026-11-27, HJOW-Athlon. `cpppj/src/client/RawSurfaceStorage.cpp`의 공통 종속 해제는 Native 전송 장치가 있으면 현재 `NoticeContent`를 사용하고 독립 저장소는 기존 `RawContentParentNotice`를 사용한다. dotnet의 장기 종단도 같은 분기를 선택하도록 고쳤다. 파생 부모의 현재 Runtime 대여가 없으면 여전히 명시적으로 실패한다.

- 실제 같은 풀의 워크샾 가상표와 내용물 Form을 분리해, 종단 생성 뒤 연결된 현재 소비자가 해제 후 통지받고 정상·예외 양쪽에서 호출 대여가 한 번 반납됨을 확인했다. 독립 저장소의 미연결 파생 통지도 검사했다.
- 최초 집중 검사 빌드는 새 검사 파일에 `Netstorm.Core.Simulation`을 가져오지 않아 실패했다. 수정 후 관련 Core 검사 **15건 통과**, `cpp_sync.py` 종료 0, 게임 Release 빌드 오류 0·경고 0이다.
- `extracted/dotnet-l2-1106-content-notice/`의 `thewarbegins`, `tutorial1`, `surrounded`는 CPP·DN 여섯 실행 모두 종료 0, DN `f090.tsv`는 0.998 기준과 바이트 일치, 원본 1,392개 파일은 전후 불변이다. 비교기 종료 1은 기존 L2 차이이며 전체 34경로 재측정은 아니다.

저장소의 현재 Runtime을 실제 세션에 등록하는 작업은 아직 남았다. 사제 포획 안내 본체, 부모 삭제의 UI 중첩 통지, 생산 Form 생성·부착과 실제 게임 플레이 결과도 이 단위의 완료 범위가 아니다.
