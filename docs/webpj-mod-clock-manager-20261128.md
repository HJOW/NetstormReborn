# WB04-E1479 시계 장벽·미션별 모드 관리자

`ModTimeSource`는 원래 ClientTimeSource의 uint32 밀리초를 감싸 모드 처리 대기 시간을 제외한다. 게임 시각뿐 아니라 wall 기반 Native 기한도 정지한다. 중첩 대기·사용자 GamePause·49일 감김을 유지하고, 대기가 없으면 원래 시각과 ClientFrameClock의 모든 필드가 같다. 고정 시각 판정/전진과 초기 seed용 unixSeconds는 원래 장치에 위임한다.

`ModManager`는 준비된 Session 사본의 id마다 켜진 패키지를 복사해 새 Worker/RNG/구독/sequence 수명으로 시작한다. 효과는 경계→사건 phase→id ASCII 순서이고, 직전 결과사건은 모드당1회/최대16항목·tick은 게임1초당1회/큰 점프 합침이다. 모드마다 다른 sequence를 섞어 정렬하지 않는다. 출력은 다음 `beforeInput`까지 사본으로 보류하고 실제 큐 수용은 ModGameHost에 위임한다. 설치0개/모두오류/고정오라클 경로에는 비동기 사건 장벽을 만들지 않는다. 실제 앱의 시계/주 루프/World 반납 연결은 다음 단위이며 이 단위의 새 관리자는 아직 자동 실행되지 않는다.

오류 모드는 즉시 반납한 뒤 저장 활성도 끈다. 저장 실패를 숨기지 않고 메모리 비활성 상태와 다른 모드를 유지한다. 이탈은 마지막 상태 사본만으로 기존 VM에 sessionEnd를 보내며 늦은 입력은 버린다. 앱 종료는 host의 앱 참조·시계 장벽을 즉시 반납하고 종료 사건/늦은 Worker를 사본만으로 정리한다. ModStore에도 disposed 경계를 추가해 이미 대기 중인 설치/읽기 검증과 뒤의 쓰기가 ResetAll 뒤 키를 복원하지 못하게 했다. 이 정책은 앱 연결 단계에서도 사용해야 한다.

Node26 관련71/71(API23·호스트3·입력9·패키지/저장소21·관리자9·시계6), Node22 관리자/시계/저장소36/36을 통과했다. 새17건은 무모드 비트3원점·중첩/감김/고정위임·결과8+tick8→16결과1회·모드별번호/효과순서·다음입력보류·등록/사건예외/저장실패·미션설정격리/새VM·대기중이탈/종료·ResetAll뒤늦은쓰기를 검사한다. 관리자 검사는 제품 ModRuntime을 실제 호출하며 Worker/호스트 외곽만 유계 장치로 주입했다. 실제 iframe/Worker 검증은 E1478이며 실제 앱 자동 연결/플레이 검증으로 확대하지 않는다.
