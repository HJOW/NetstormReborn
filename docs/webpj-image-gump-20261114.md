## 구현

- **`ImageGump`(원문 00419fc0/004198f0/00419990/00419cd0/00419cb0, VT `00501bb0`, 종류 3)**: `construct`는 공통 `GumpCreate`로 크기 0 기본 생성 뒤 가상 표/종류 3을 쓰고 `setFrame`한다. `setFrame`은 TYPE/프레임/모드를 저장하고 프레임 헤더의 폭/높이를 float32 기본 크기로, 표시 크기는 헤더×현재 배율을 float32로, 기준점은 정수를 먼저 float으로 좁히지 않고 `(헤더 기준점 − TYPE 기준점)`의 최종값만 float32로 쓴다. `draw`는 배율 비트가 정확히 `0x3f800000`일 때만 단위로 보며, 모드 4는 **먼저** 그림자 색표(`00556338`)와 현재 그림자 오프셋으로 mapped 출력(단위면 y−1)한 뒤 본체를 생략하지 않고 이어가고, 모드 1/2는 선택(`00556438`)/비활성(`00556038`) 색표로 mapped 출력하고 끝내며(1 비트가 선택), 그 밖에는 TYPE별 owner 색표 토큰이 있고 현재 owner가 부호 있는 비교로 0보다 크며(단위 배율에서 모드 8이 아닐 때) `토큰 + (owner<<8)` 색표로 mapped 출력하고 아니면 색표 없이 출력한다. 기준점은 `ftol(위치 + 기준점×(단위면 1, 아니면 배율))`, 16.16 배율은 단위면 65536 아니면 `ftol(배율×65536)`이며, TYPE 번호가 owner 색표 배열 밖이면(그 분기에 도달할 때만) RangeError다. `hit`은 검사점(`ftol(x)`, `ftol(y)`)과 기준점(`ftol(기준점×배율+노드 위치)`)·배율을 실제 판정에 넘기고 `attach`는 기본 부착을 그대로 호출한다.
- **`bindImageGumpAssets`**: TYPE 번호는 70부터이고 SHP 블록은 번호−70이다(표시 이름으로 바꾸지 않음). `type(번호)`는 타입 표 188칸 안만 허용(밖은 RangeError)하고 `{ shape: 번호−70+1, 기준점 }`을, `header(번호, 프레임)`은 실제 Squid 그림 헤더를 돌려주되 프레임 수를 `클러스터 수 × (그림자 플래그 0x440000이 있으면 2)`로 제한한다.
- **`ImageGumpPixelTarget`**: 색표 토큰을 공급자로 해석해 공유 256색 문맥에 제자리 복사(누락/미복원 표를 항등으로 바꾸지 않음), 일반 출력은 기준점에 프레임 rect를 더한 `image`, 확대/축소는 같은 배율의 `scaledImage`(특수 프레임은 그리지 않음), 적중은 원본 4daca0→4dabf0의 200×200 임시 버퍼에서 기준점을 0..199로 clamp하고 넘친 만큼(`0−기준점` 또는 `199−기준점`) 검사점을 옮긴 뒤 보정한 검사점이 버퍼 밖이면 RangeError, 255가 아니면 1이다.
- 웹 적응 표기: `std::reference_wrapper`로 읽는 현재 전역은 읽는 시점에 값을 보는 `state` 객체, `std::map` 캐시는 `Map`, `ColorMap` 값 복사는 `Uint8Array.set`, 10.78 판본 검사는 웹이 10.78 전용이라 생략, `logic_error`→`Error`, `out_of_range`→`RangeError`.

새 시험 파일 1개, **10건 통과**(`image-gump.test.mjs`): 본체는 기록 장치 위에서 실제 `GumpCreate`로(기준점 (3,4)·헤더 20×10/(8,6)·위치 (10,20)·그림자 (2,3) 손 계산), 자산 연결은 실제 `TypeTable`/SHP 로(dude=타입 70·banner 등), 표면/적중은 실제 `GumpPixelTarget`/`ShapeDatabase` 위에서 한다. 적중의 이동량은 한 칸 어긋나면 이웃 투명 픽셀을 읽도록 런/열의 시작·끝 픽셀을 탐침으로 써서 확인했다(기준점 −8~250, 경계 0/199/200 포함, 그림이 기준점의 왼쪽/위에 놓이는 dude 프레임 0과 오른쪽/아래에 놓이는 fortGump 프레임 4).
