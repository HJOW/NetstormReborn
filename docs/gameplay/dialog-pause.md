# 안내·브리핑 창과 게임 시간

> 분석 상태: **사용자 확인 규칙 + 원본 exe 정적 분석(시계 정지·재개 경로 전부 확정, 2026-09-30 `HJOW-Athlon`) + 클론 구현 현황.**
> 원본 게임은 실행하지 않았다(동적 확인 없음). 창이 떠 있는 동안 벽시계와 게임 시계가 실제로 어긋나는 것을 화면에서 재 본 것은 아니다.

## 규칙 (사용자 확인, 2026-09-30)

1. **튜토리얼 안내 창이 떠 있는 동안 게임 시간은 멈춘다.**
2. **캠페인 미션의 초기 브리핑 창도 닫히기 전까지는 게임 시간이 흐르지 않는다.** 미션은 브리핑을 닫은 뒤부터 진행된다.
3. 일부 미션은 **게임 도중에 창이 뜬다.** 그때 원본에서 시간이 흐르는지는 확인이 필요했다. **클론은 이 경우도 시간을 멈추는 것으로 구현해도 된다**(사용자 허용).
4. 위 규칙은 스크립트의 안내(Tell) 창에 대한 것이다. `Game` 메뉴와 `Leave Mission` 확인 창은 별개이며 기존 구현대로 미션 시간이 계속 흐른다([map-viewer.md](../map-viewer.md)의 미션 메뉴, 원본 관찰 기준).

## 결론 요약 (exe 정적 분석)

- 게임 시계를 멈추는 함수 `FUN_00460df0`의 호출 지점은 **정확히 4곳**이다(직접 `call` 4곳, 함수 포인터·가상 함수 표 등 주소 값 참조 0곳, 정지 카운터 `DAT_0055b4b0`을 시계 함수 밖에서 쓰는 코드 없음 — `tools/exe_callscan.py`로 확인).

  | 호출 지점 | 함수 | 정지되는 상황 | 재개 |
  |---|---|---|---|
  | `0x4c2a56` | `FUN_004c2a40` = **미션 스크립트 객체 가상 함수 표 슬롯 10** | 스크립트가 섹션을 Tell해서 창이 열렸을 때(아래 표) | 프레임 함수 `FUN_004c34c0`(`0x4c35b5`) |
  | `0x4837d1` | `FUN_00483680` = **Moviegump 열기**(가상 함수 표 `+0x48`) | 영상(Smacker) 창이 열릴 때(`+0xa8` 플래그) | 창 닫기 `FUN_004837f0`(`0x48387d`) |
  | `0x4d82b5` | 메인 프레임 함수 `FUN_004d62b0` 안의 이벤트 분기 | **개발자용 `Pause - Shift-F9` 토글**(`DAT_00594fa4`·`DAT_005c85a4`가 켜졌을 때만 메뉴·이벤트가 있다) | 같은 분기(`0x4d8293`) |
  | `0x4e090b` | 어설션 오류 처리 `FUN_004e0620` | 프로그램 오류 대화상자 | 같은 함수(`0x4e0919`) |

  전투 상태 해제 `FUN_004b2df0`(`0x4b2ea0`)은 재개 전용이다(미션이 끝났을 때 남은 정지를 모두 풀어 준다). **캠페인·튜토리얼 미션의 창은 위 표 1행(슬롯 10) 하나로 처리된다.**
- **영어 튜토리얼과 캠페인 미션은 모두 같은 "Tutorial" 미션 클래스다.** 미션 종류 이름 `Tutorial`이 이 클래스(정지 슬롯 있음), `Normal`은 다른 클래스(정지 슬롯이 빈 함수)에 등록되어 있고, 헤더 `missionType`이 그 이름을 고른다(아래 "미션 클래스"). 그래서 튜토리얼 안내 창(규칙 1)과 캠페인 초기 브리핑 창(규칙 2)은 **같은 코드 경로**로 시계를 멈춘다. 캠페인 브리핑은 섹션 `[A.]`다(예: `thewarbegins.english`, 버튼 `Review Knowledge`·`Play Mission`).
- **게임 도중에 뜨는 창(규칙 3)은 창을 여는 쪽이 스크립트인지 게임 코드인지로 갈린다.**
  - 스크립트 객체가 여는 창은 **모두 시계를 멈춘다**(아래 표): 단계 섹션, 성공·실패, AI 신전·사제 이벤트, 튜토리얼 소용돌이·공장 이벤트. 사용자 허용("멈추는 것으로 통일")과 **원본 동작이 일치한다.**
  - 게임 코드가 `Tell`을 **직접** 부르는 경고·안내 창은 **시계를 멈추지 않는다**(`NoBridgeYet`, `NewTech`, `AltarUpgrade`, `SacrificeForStormpower`, `NoTechTheme`, `BuildNoBucks`, `ZoneLocked`, `WarnAscend`, `DrawNotAccepted`, `NotRestart`, `SacrificeMenu(...)` 등 약 40곳). 원본은 이 창이 떠 있어도 미션 시간이 계속 흐른다(정적 분석 결론). **같은 부류인 F6 지식 창은 2026-10-01 녹화 재판독으로 확인**: 창이 열린 13초 동안 SP 가 3,450 → 3,650 으로 늘고 전투 소리가 이어졌다([녹화 노트](../videos/the-war-begins-record-play-20260930.md) 3절 4번). **클론이 이 창을 만들 때 시간을 멈출지는 별도 결정 사항이다**(아래 지침).

## 창이 열리는 경로와 정지 (Tutorial 클래스)

**"섹션을 Tell → 창이 열렸으면(`FUN_00482de0`이 nonzero) `FUN_00466710()` → 슬롯 10(정지)"** 패턴이 아래 호출자 전부에 똑같이 붙어 있다. `FUN_00482de0`은 `Mission.cpp`의 `Tell` 래퍼로 `FUN_004cf960`을 부른다.

| 창(섹션) | 부르는 곳 | 언제 |
|---|---|---|
| **`A.` `B.` … / `Demo`** (단계) | `FUN_004c2a90` ← 프레임 함수 `FUN_004c34c0` | 아래 "초기 브리핑 흐름". 캠페인은 `A.` 하나, 튜토리얼은 단계마다 글자가 하나씩 오른다(`FUN_004c33f0`이 `DAT_005ca8e8`을 올림). `demo`이면 섹션 이름이 `Demo`. |
| `Success` / `Failure` | `FUN_004c31a0`(슬롯 6) | 미션 종료 |
| `ai<N>TempleHalfDead`, `ai<N>TempleDead`, `ai<N>PriestDead`, `ai<N>PriestCaptured`, `ai<N>PriestSaved` | `FUN_004c3940` ← `FUN_004c36c0`(프레임마다 AI 1~8 검사) | 해당 AI 신전 체력이 절반 아래·신전 파괴·사제 사망·사제 포획·사제 구출. **각 이벤트는 미션당 한 번만.** 다이얼로그 gump가 열려 있으면 다음 프레임으로 미룬다. 데모에서는 이름 앞에 `Demo`가 붙는다. |
| `NotVortex` | `FUN_004c3bb0`(튜토리얼 2 판정 함수) | 튜토리얼 2의 소용돌이 조건 |
| `VortexDestroyed`, `FactoryDestroyed` | `FUN_004c42b0`(튜토리얼 5) | 소용돌이·공장 파괴 |
| `tellAtList` 항목 | `FUN_004c3470` | 미션 시작 후 지정한 게임 시간 초가 지났을 때(사제가 죽지 않았고 다이얼로그가 없을 때). **출하 미션 어디에도 `tellAtList`가 없다**(`extracted/tarc` 검색 0건). |

정지하지 않는 것: 위 표 밖에서 게임 코드가 `FUN_004cf960`/`FUN_004cf730`을 직접 부르는 곳(경고·안내). 이 창이 떠 있어도 시계는 흐른다.

## 초기 브리핑 흐름 (규칙 2, 캠페인·튜토리얼 공통)

1. 생성자 `FUN_004c2990`: 단계 글자 `DAT_005ca8e8 = 'A'`, **단계 잠금 카운터 `+0x84 = 10`**, 단계 지연 `+0x80 = 0.5f`, 다음 단계 시각 `+0x78 = 0.0`, `DAT_005ca8ec = 1`.
2. 미션 로딩 뒤 시작 조건 읽기(슬롯 4)가 `+0x88 = 1`(시작됨)로 바꾼다. 이 전에는 프레임 함수가 아무것도 하지 않는다.
3. 프레임 함수 `FUN_004c34c0`이 프레임마다 `+0x78 ≤ 게임 시간`(0.0이라 항상 참)이고 잠금 카운터가 양수인지 본다. **다이얼로그 gump가 없으면(`FUN_004c8e90() != 0`) 카운터를 1 줄이고, 있으면 10으로 되돌린다.** 카운터가 0이 되면 `FUN_004c2a90`이 섹션 `A.`를 Tell하고 창이 열리면 슬롯 10이 시계를 멈춘다.
   → 브리핑 창은 미션이 시작한 뒤 **다이얼로그 없이 연속 10프레임**이 지나야 뜬다. 그 10프레임 동안은 시계가 흐른다(길이는 원본 프레임 간격에 비례하며 간격은 재지 않았다).
4. 캠페인 미션은 `tutorialNumber`가 없어 `DAT_005ca8e4 == 0`이다. 프레임 함수 끝의 단계 판정 함수(`FUN_004c3a20`~`FUN_004c45e0`, 튜토리얼 1~6)는 튜토리얼만 돈다. 따라서 **캠페인의 단계 섹션은 `A.` 하나**이고 나머지 창은 위 이벤트 표의 것이다.
5. 재개: 프레임 함수가 `+0xb8 != 0`이고 `+0x84 == 0`일 때 아래 세 조건이 **7프레임 연속** 참이면 `FUN_00460e30`으로 재개하고 `+0xb8 = 0`으로 되돌린다(하나라도 거짓이면 연속 카운터 `+0xc8`을 0으로 되돌린다).
   - `FUN_004c79a0() == 0`: 열린 안내창이 없다.
   - `FUN_004c8e90() != 0`: 열린 다이얼로그 gump가 없다(우클릭 메뉴 같은 팝업. 브리핑의 `Review Knowledge`로 여는 지식 창이 여기에 들어가는지는 확인하지 않았다).
   - `FUN_004641d0() == 0`: 플래그 `0x4000`을 가진 자식 gump가 없다.
   → **안내창이 모두 닫힌 뒤 수 프레임이 지나야 시간이 다시 흐른다.**
6. 게임 도중 새 창(예: AI 신전 이벤트)이 이미 정지 중에 열려도 정지가 겹치지 않는다(`FUN_004c2a40`은 정지 중이고 이 객체가 이미 잡았으면 다시 잡지 않는다).

## 영상(Moviegump)

- `FUN_00484010(파일명)`이 창을 만들고(`FUN_00483ea0`) 곧바로 **옵션 1과 2를 켠 뒤**(`FUN_00483970` = `SetOption(옵션, 값, 미사용)`, `+0xa4`·`+0xa8`, 바이트로 확인: `push edi(=0); push 1; push 1|2; call [vtable+0x5c]`) 열기(`FUN_00483680`)를 부른다. `+0xa8`이 켜져 있으면 열기가 `FUN_00435dc0(1)` + 시계 정지, 닫기(`FUN_004837f0`)가 `FUN_00435dc0(0)` + 재개를 한다 → **이 함수로 재생하는 영상은 항상 시계와 프레임 갱신을 모두 멈춘다.**
- 호출자는 두 곳이다: 상태 기계 `FUN_004b6dd0`의 상태 `0x27`(설정 키 `introMovie`가 있을 때 시작 영상, 이어 상태 `0x28`이 끝나기를 기다린다)과 메인 프레임 함수의 "이름으로 영상 재생" 이벤트 분기(`0x4d8fb9`). **출하 영어 미션 파일에는 영상을 재생하는 명령이 없다**(`extracted/tarc/d/*.english`에서 `movie`·`.smk` 검색은 `tell.english`의 화면 녹화 문구뿐, `introMovie`는 `extracted/tarc` 전체에서 0건). 미션 중간 영상은 없다고 봐도 된다. `introMovie` 키를 가진 설정 파일이 있는지는 확인하지 않았다.

## 이미 측정한 다리 붕괴 시각에 미친 영향

[bridge-pieces.md](../exe/bridge-pieces.md) 8.3의 두 영상 측정(T자·한 칸짜리)은 **벽시계 기준**이고, 각 기록은 배치 직후 튜토리얼 안내창이 잠깐 열려 있었다. 열려 있던 시간의 **상한**은 배치 클릭부터 창을 닫은 클릭까지의 간격이다: T자 2.2초(13:24:55.75 → 13:24:57.96, 영상으로는 창이 13:24:56.5~57.0에 나타나 약 0.9~1.5초), 한 칸 2.4초(13:39:57.91 → 13:40:00.27, 창이 나타난 프레임은 확인하지 않음). 규칙 1에 따르면 이 시간은 게임 시간에 들어가지 않으므로 게임 시간으로는 금·낙하 시각이 그만큼 짧다. (튜토리얼 1의 그 안내창은 단계 섹션이라 위 표대로 시계를 멈춘다. 재개는 창을 닫은 뒤 수 프레임 뒤라 실제 정지 구간은 여기 적은 상한보다 약간 더 길 수 있다.)

- 한 칸짜리: 금 +32.4초 → 게임 시간 **30.0초 이상**(32.4 − 최대 2.4), 낙하 +72.4초 → **70.0초 이상**. 모델의 하한(금 30초, 제거 70초)에 닿는다.
- T자: 금 +36.9초 → 약 35.4~36.0초, 낙하 +77.1초 → 약 75.6~76.2초.
- 금에서 낙하까지 40.0초(한 칸)·40.2초(T자)는 사이에 창이 없어 그대로다.
- 결론은 그대로다: **두 관찰 모두 모델(금 30~40초, 제거 70~80초)과 맞는다.** 위 스캔 위상 값(한 칸 2.4초, T자 6.9초)은 안내창 시간을 뺀 값보다 최대 2.4초·약 0.9~1.5초 크다. 한 칸 기록의 위상은 0에 가까워진다(보정 후 0~2.4초).
- 2026-09-29 두 칸 막대 기록은 그 사이 안내창이 열려 있었는지 알 수 없다(40초 간격 네 단계는 창이 없었다면 벽시계와 게임 시계가 같으므로 그대로 맞는다).

## 남은 확인

- **원본 동적 확인**(선택): 게임 중간 창(AI 신전 이벤트 등)이 떠 있는 동안 시간이 멈추는지, 그리고 `NewTech`·`AltarUpgrade` 같은 경고 창이 떠 있는 동안 시간이 흐르는지를 미션 타이머·다리 붕괴 스캔·사제 이동으로 확인. 위 결론은 exe 정적 분석뿐이다. `playingVideos` 영상·스크린샷 대조 또는 사용자 수동 녹화가 필요하다. 실제 게임 실행이 필요하므로 AGENTS.md의 실행 확인 규칙을 따른다(`HJOW-Athlon`은 예외 시스템).
- **프레임 수 단위 오차**: 브리핑이 뜨기까지·재개까지의 프레임 수(10, 7)는 코드에서 읽었고 원본 프레임 간격은 재지 않았다.
- **`tellAtList` 조건 하나**: 프레임 함수가 `tellAtList`를 실행하는 조건 중 `FUN_00445330() == 0`(= `DAT_005325c8 != 0`, 이 카운터를 올리는 `FUN_00446a10`·`FUN_00446a70`은 커서 조각 회전·잡기 쪽으로 보임)의 뜻은 확인하지 않았다. 출하 미션이 `tellAtList`를 쓰지 않아 조사하지 않았다.
- **성공·실패 섹션 이름**: exe는 `Success`/`Failure`를 부르는데 미션 파일은 `[Succeeded][BadTeamDead]`·`[Failed]`다. 섹션 이름 대응 규칙은 [mission-script.md](../formats/mission-script.md)에 있다.
