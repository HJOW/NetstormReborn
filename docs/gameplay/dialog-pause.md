# 안내·브리핑 창과 게임 시간

> 분석 상태: **사용자 확인 규칙 + 원본 exe 정적 분석(일부) + 클론 구현 현황**. 미션 진행 중에 뜨는 창에서 시간이 흐르는지는 원본에서 **아직 확인하지 않았다.**

## 규칙 (사용자 확인, 2026-09-30)

1. **튜토리얼 안내 창이 떠 있는 동안 게임 시간은 멈춘다.**
2. **캠페인 미션의 초기 브리핑 창도 닫히기 전까지는 게임 시간이 흐르지 않는다.** 미션은 브리핑을 닫은 뒤부터 진행된다.
3. 일부 미션은 **게임 도중에 창이 뜬다.** 그때 원본에서 시간이 흐르는지는 **확인이 필요하다**(미확인). **클론은 이 경우도 시간을 멈추는 것으로 구현해도 된다**(사용자 허용).
4. 위 규칙은 스크립트의 안내(Tell) 창에 대한 것이다. `Game` 메뉴와 `Leave Mission` 확인 창은 별개이며 기존 구현대로 미션 시간이 계속 흐른다([map-viewer.md](../map-viewer.md)의 미션 메뉴, 원본 관찰 기준).

## 원본 exe 근거 (정적 분석, 2026-09-30)

게임 시계와 일시정지 구조 — `extracted/decomp/Netstorm.c`:

| 함수·변수 | 뜻 |
|---|---|
| `FUN_00460cd0(double*)` | **게임 시간**(초). 정지 카운터 `DAT_0055b4b0`이 0이 아니면 멈출 때 저장한 값(`DAT_0055b4f0/f4`)을 그대로 돌려준다. 아니면 `timeGetTime()` 기준 시각에서 누적 정지 시간(`_DAT_0055b4f8`)을 뺀다. |
| `FUN_00460df0` | **정지**: 카운터가 0이면 그 순간의 게임 시간을 저장하고, 카운터를 1 올린다(중첩 가능). |
| `FUN_00460e30` | **재개**: 카운터를 1 내리고 0이 되면 `_DAT_0055b4f8`에 멈춰 있던 시간(`현재 − 저장값`)을 더한다. 즉 **정지 구간은 게임 시간에 들어가지 않는다.** |
| `FUN_00460de0` | 정지 중인지(`0 < DAT_0055b4b0`). 튜토리얼 단계 처리(`FUN_004c34c0`)도 이것을 읽는다. |
| `FUN_00460d70` | 정지와 무관한 **벽시계**(`timeGetTime()` 기준). 안내창 소멸자 등이 쓴다. |

- 다리 붕괴 스캔(10초 주기, [bridge-pieces.md](../exe/bridge-pieces.md) 8.1)은 게임 시계를 쓴다. 그래서 정지 구간에는 붕괴도 멈춘다.
- **안내창(Tell) 객체**: 생성자 `FUN_004cf120`이 `DAT_005cab2c`(열린 안내창 수)를 1 올리고 소멸자 `FUN_004cf1c0`이 1 내린다. `FUN_004c79a0()`이 `0 < DAT_005cab2c`다.
- **미션 스크립트 객체**: `FUN_004c2a40`이 시계를 정지하고 객체의 플래그 `+0xb8`을 켠다(이미 이 객체가 정지시켰으면 다시 올리지 않음). 프레임 함수 `FUN_004c34c0`은 플래그가 켜져 있고 단계 잠금 카운터(`+0x84`)가 0일 때 아래 세 조건이 **7프레임 연속** 참이면 `FUN_00460e30`으로 재개하고 플래그를 끈다(하나라도 거짓이면 연속 카운터 `+0xc8`을 0으로 되돌린다).
  - `FUN_004c79a0() == 0`: 열린 안내창이 없다.
  - `FUN_004c8e90() != 0`: `DAT_00565dd4 == 0`(의미 미확인).
  - `FUN_004641d0() == 0`: 플래그 `0x4000`을 가진 자식 gump가 없다.
  - 결과: **안내창이 모두 닫힌 뒤 수 프레임이 지나야 시간이 다시 흐른다.**
- `Moviegump.cpp`의 창 닫기 `FUN_004837f0`은 창의 플래그(`+0xa8`)가 켜져 있으면 재개한다(동영상 창도 시간을 멈추게 할 수 있음).
- 전투 상태 해제 `FUN_004b2df0`(`State.cpp`)은 정지 카운터가 0이 될 때까지 `FUN_00460e30`을 반복한다(미션 종료 뒤 정리). 어설션 오류 처리도 정지한다.
- **`FUN_004c2a40`은 스크립트 객체의 가상 함수 표 10번 슬롯(+0x28)이다**(표 시작 `0x5149ec`, `tools/exe_callscan.py --table`로 덤프). `FUN_004c2a90`(단계 섹션을 알리는 함수)이 섹션을 찾으면 `FUN_00466710()` 뒤 `(**(code **)(*param_1 + 0x28))()`로 이 슬롯을 불러 **정지한다.** 섹션 이름은 `param_1[0x1a] == 0`이면 `<단계 글자>.`(예: `A.`), 아니면 `0x514a18`의 문자열 `Demo`다. `FUN_004c2a90`의 호출자는 프레임 함수 `FUN_004c34c0`(단계 잠금 카운터 `+0x84`가 0이 될 때) 하나뿐이다. 즉 **튜토리얼 단계 안내와 데모 안내는 이 경로로 시계를 멈춘다**(규칙 1과 일치).
- **직접 호출 지점 스캔(exe 바이트, 2026-09-30, `tools/exe_callscan.py`):**

  | 대상 | 호출 지점(가상 주소) | 디컴파일 본문에서 보이는가 |
  |---|---|---|
  | 정지 `FUN_00460df0` | `0x4c2a56`(`FUN_004c2a40`), `0x4e090b`(어설션 처리) | 보임 |
  | | **`0x4837d1`**(Moviegump 창 열기 근처로 추정), **`0x4d82b5`** | **안 보임** |
  | 재개 `FUN_00460e30` | `0x48387d`(`FUN_004837f0`), `0x4b2ea0`(`FUN_004b2df0`), `0x4c35b5`(`FUN_004c34c0`), `0x4e0919`(어설션 처리) | 보임 |
  | | **`0x4d8293`**(`0x4d82b5` 바로 앞) | **안 보임** |
  | `FUN_004c2a40` 직접 `call` | 없음(가상 함수 표로만 호출) | — |

  `0x4d8293`~`0x4d82b5`는 디컴파일에 `0x4d7000~0x4d9fff` 구간의 함수 헤더가 하나도 없어 **그 구간이 통째로 빠져 있다.** 같은 함수가 재개와 정지를 차례로 부르는 모양(`0x4d8293` 재개 → `0x4d82b5` 정지)이라 미션 시작·브리핑 같은 창 처리일 수 있으나 **추측이다.**
- **미확인:** `FUN_004cf960`(Tell)은 많은 곳에서 불리지만(튜토리얼 경고 `NoBridgeYet`, `NewTech`, `AltarUpgrade` 등) 그 함수 안에서 `FUN_00460df0`을 직접 부르지는 않는다. **캠페인 초기 브리핑과 게임 중간 창이 정지를 일으키는 경로**는 위 "안 보이는" 지점과 표의 누락 슬롯에 있을 것이며 exe에서 확정하지 못했다.

## 이미 측정한 다리 붕괴 시각에 미치는 영향

[bridge-pieces.md](../exe/bridge-pieces.md) 8.3의 두 영상 측정(T자·한 칸짜리)은 **벽시계 기준**이고, 각 기록은 배치 직후 튜토리얼 안내창이 잠깐 열려 있었다. 열려 있던 시간의 **상한**은 배치 클릭부터 창을 닫은 클릭까지의 간격이다: T자 2.2초(13:24:55.75 → 13:24:57.96, 영상으로는 창이 13:24:56.5~57.0에 나타나 약 0.9~1.5초), 한 칸 2.4초(13:39:57.91 → 13:40:00.27, 창이 나타난 프레임은 확인하지 않음). 규칙 1에 따르면 이 시간은 게임 시간에 들어가지 않으므로 게임 시간으로는 금·낙하 시각이 그만큼 짧다.

- 한 칸짜리: 금 +32.4초 → 게임 시간 **30.0초 이상**(32.4 − 최대 2.4), 낙하 +72.4초 → **70.0초 이상**. 모델의 하한(금 30초, 제거 70초)에 닿는다.
- T자: 금 +36.9초 → 약 35.4~36.0초, 낙하 +77.1초 → 약 75.6~76.2초.
- 금에서 낙하까지 40.0초(한 칸)·40.2초(T자)는 사이에 창이 없어 그대로다.
- 결론은 그대로다: **두 관찰 모두 모델(금 30~40초, 제거 70~80초)과 맞는다.** 위 스캔 위상 값(한 칸 2.4초, T자 6.9초)은 안내창 시간을 뺀 값보다 최대 2.4초·약 0.9~1.5초 크다. 한 칸 기록의 위상은 0에 가까워진다(보정 후 0~2.4초).
- 2026-09-29 두 칸 막대 기록은 그 사이 안내창이 열려 있었는지 알 수 없다(40초 간격 네 단계는 창이 없었다면 벽시계와 게임 시계가 같으므로 그대로 맞는다).
- 2026-09-29 두 칸 막대 기록은 그 사이 안내창이 열려 있었는지 알 수 없다(40초 간격 네 단계는 벽시계 기준으로도 맞는다).

## 디컴파일이 필요한 항목 (인수인계, 이 PC `HJOW-X3D`에서는 사용자 지시로 중단)

2026-09-30 사용자가 "디컴파일 작업은 이 PC에서 더 진행하지 말라"고 지시했다. 아래는 **다른 PC(Ghidra가 준비된 곳)에서** `tools/ghidra/decompile_at.sh`(Linux) 또는 `decompile_at.ps1`(Windows)로 복구할 함수 목록이다. 사용법: [mission-header-flags.md 7절](../exe/mission-header-flags.md). 이 PC에는 Ghidra(`C:\Tools\ghidra_12.1.4_PUBLIC`)와 `extracted/decomp/Netstorm.c`가 있지만 실행하지 않았다.

| 우선 | 주소 | 이유 |
|---|---|---|
| 1 | **`0x4d8200`~`0x4d8300` 근처 함수**(재개 `0x4d8293`, 정지 `0x4d82b5`) | 디컴파일에 없는 구간에서 시계를 재개하고 곧바로 정지한다. 캠페인 미션 시작·초기 브리핑·중간 창의 정지 경로일 가능성. 구간 전체(`0x4d7000~0x4d9fff`)가 빠져 있으니 함수 경계부터 확인. |
| 2 | **`0x4837d1`을 포함하는 함수**(Moviegump 창 열기 쪽 추정) | 동영상 창이 시계를 멈추는 조건(`FUN_004837f0`이 읽는 창 플래그 `+0xa8`이 언제 켜지는지). |
| 3 | 스크립트 객체 가상 함수 표(`0x5149ec`)의 **누락 슬롯**: `0x4c2a70`(1), `0x4c3290`(2), `0x4c2b00`(3), `0x4c2b20`(4), `0x4c3170`(8), `0x4c33a0`(9) | 스크립트 객체의 생성·섹션 읽기·종료 처리. 캠페인 미션이 이 객체를 같은 방식으로 쓰는지, 시작 브리핑을 어느 섹션 이름으로 Tell하는지 확인. `0x4c3290`·`0x4c2b20`은 이전 [LEFT_JOBS.md](../../LEFT_JOBS.md) 인수인계에도 디컴파일에 없는 함수로 적혀 있다. |

## 그 밖의 남은 확인 (디컴파일 아님)

- 게임 중간에 창이 뜨는 캠페인 미션에서 창이 떠 있는 동안 시간이 흐르는지 **원본 관찰**(`playingVideos` 영상·스크린샷 대조, 또는 사용자 수동 녹화). 사용자가 확인을 요청한 항목이다. 예: 창 앞뒤로 타이머·다리 붕괴 스캔·사제 이동이 이어지는지. 클론은 확인 없이 정지로 통일해도 된다.
- 캠페인 미션 초기 브리핑 창을 클론에 구현할 때 닫기 전까지 세션 틱을 시작하지 않게 한다(규칙 2, 위 지침 표).
