# TEST02 원본 분석의 클론 반영

2026-10-04. `AGENTS.md`와 `LEFT_JOBS.md`를 먼저 읽고 다른 작업자가 남긴 [TEST02 원본 분석](../videos/auto-test02-construct-20261004.md), [건설 흐름](priest-construction-flow.md), [입력 규칙](input-controls.md)을 클론에 반영했다. 원본 관찰·사용자 확인·exe 정적 분석을 팬게임보다 우선했다. 이번 작업에서는 원본 게임을 실행하지 않았고 `originals/`·`originalCD/`·`AGENTS.md`를 수정하지 않았다.

## 반영한 동작

| 항목 | 클론 동작과 근거 |
|---|---|
| 마우스 커서 | 원본 RT_CURSOR 5개를 동봉하고 화살표·금지·사제 이동·템플·건물 배치 상태에 연결했다. 각 32×32 크기, 원본 핫스폿과 AND/XOR 배경 반전을 유지한다. 게임 그림 위에 그리는 방식이 아니라 MonoGame가 사용하는 SDL의 커서 핸들을 바꾼다. 메뉴·생산 창·대화상자는 화살표다. |
| 사제 선택 | 선택된 사제 자신을 우클릭하면 메뉴 없이 선택이 풀린다. 선택된 사제로 허공을 좌클릭해도 이동을 명령하지 않고 선택만 푼다. 진행 중이던 작업은 이어진다. |
| 건설 메뉴 | Construct 중심은 우클릭점에서 아래 21px, 첫 하위 창 Temple/Workshop은 각각 아래 21/38px, 최종 워크샵은 Sun·Wind·Rain·Thunder 순서와 21px 행 간격을 쓴다. 원본처럼 앞선 두 창을 남긴 채 제목 없는 원소 아이콘 목록을 겹친다. 가려진 부모 줄은 눌리지 않는다. 창 가장자리에서는 화면 안으로 밀린다. |
| 건물 발자국 | 원본의 실제 타입 로딩 보정 `foot_y = 6 → 8`을 복원했다. Sun Workshop은 **7×8칸**이다. 모든 칸이 같은 본섬 안이어야 하며 다른 건물과 겹치면 거부하지만 경계가 맞닿는 것은 허용한다. 사제는 설치 자리의 장애물로 세지 않는다. |
| 건물 잡는 위치 | 사제 건물은 셰이프 헤더의 원점·그림 크기로 중앙을 잡고 가장 가까운 칸에 붙인다. 생산 유닛의 기존 오른쪽 열 기준 배치는 유지한다. |
| 개수 제한 | 템플은 대기 공사장도 포함해 플레이어당 1기다. 워크샵에는 별도 개수 제한을 추가하지 않았으며 14채 검사로 확인했다. 원본 관찰 자체는 14채까지의 측정이다. |
| 건설 진행 | 설치 때 비용 차감·현장 예약, 사제가 둘레에 도착하면 10초 건설, 시작 후 사제가 떠나도 계속 완공한다. 기존 코어 동작을 유지하고 수정된 발자국으로 회귀 검사했다. |
| 취소·환불 | 도착 전 유효한 새 이동 명령은 공사장을 즉시 제거하고 전액 환불한다. 화면에만 그림자를 잠시 남기고 환불 숫자는 약 0.85초 뒤 따라오게 했다. 같은 사제의 새 건설 지시는 사용자 확인에 따라 이전 현장을 즉시 교체하며 이 지연을 남기지 않는다. |
| 숫자 표시 | 기존 전역 SP 롤링을 설치·환불에도 사용한다. 기존 분석의 ‘설치·환불에는 롤링 없음’은 코드 대조로 정정했다. 논리 자원과 늦게 따라오는 표시값을 구분한다. |
| 건설 그림 | 대기 중에는 원본 그림자와 어두운 바닥 띠를 남긴다. 시작 후에는 완성 그림을 바닥부터 드러내고 완공 직전에 워크샵 창문을 켠다. 플레이 화면의 개발용 진행 막대를 없앴다. |
| 소리 | 하위 창 `openGump`, 최종 선택 `openSubGump`, 설치 `dropPiece`, 시작 이후 화면 안 건설 `jimbuild` 1.14초 반복, 건물 완공은 타입의 `templeComplete`/`workshopComplete`만 낸다. 유닛 생산의 `buildDone`은 유지한다. 취소·환불에는 소리를 추가하지 않았다. |

`TEST02.fort`·`TEST02.english`를 클론 데이터에 복사해 `--test-battle TEST02`로 재현할 수 있다. 원본 맵 파일은 변경하지 않았다.

## 발자국·그림 중앙의 정적 근거

`extracted/decomp/Netstorm.c`의 `Rifttype.cpp FUN_0049b0d0`에는 세로 발자국 값이 6이면 8로 바꾸는 로딩 코드가 있다. `.type` 원문만 읽던 클론은 이 보정을 빠뜨려 Sun Workshop을 7×6칸으로 검사했다. `Footprint.TypeHeight`에서 같은 보정을 적용하므로 새 건물과 저장된 건물의 점유·선택·공급 중심도 같은 크기를 쓴다.

`Cursor.cpp FUN_00446b50`의 건물 배치 경로는 그림 원점에서 가로·세로 크기의 절반과 한 칸(16, 11px)을 빼고 `FUN_0043fa60`의 가장 가까운 정수 반올림으로 칸을 고른다. 클론도 같은 계산을 한다. 여기서 크기는 디코딩한 텍스처의 포함 경계 크기가 아니라 **ShapeFrame 헤더의 Bounds1/Bounds0**, 원점은 **Origin1/Origin0**다. Sun Workshop 헤더는 가로 111·세로 114px, 원점 (111, 114)이다. 포함 경계로 디코딩하면 1px가 추가되므로 헤더와 혼용하지 않는다.

커서의 단색 변환과 네이티브 연결은 [SDL_CreateCursor](https://wiki.libsdl.org/SDL2/SDL_CreateCursor)와 [SDL_SetCursor](https://wiki.libsdl.org/SDL2/SDL_SetCursor)의 규약을 사용한다. 원본 리소스 출처는 [커서 자산 기록](../../assets/game-data/cursors/README.md)에 있다.

중앙 계산에서는 원본처럼 월드 픽셀을 먼저 정수로 변환하고 홀수 그림 크기의 절반도 정수로 나눈다. 확대·카메라 이동으로 소수 픽셀이 생겼을 때 칸 경계에서 한 행 일찍 바뀌지 않도록 소수 좌표 회귀 검사도 포함했다.

## 검증

- Release 빌드 성공. 전체 단위 테스트 **Core 521 + Assets 262 = 783개** 통과, 실패·건너뜀 0. 전체 재빌드에는 기존 `TextResourceTests.cs`의 CA2014 경고가 남는다.
- 새 `tools/clone_test02_smoke.ps1`: 한국어·영어 각각 커서 27 + 취소 12 + 건설 15 = **54개, 합계 108개 단언** 통과. 세 창 겹침과 SDL 현재 커서 핸들까지 확인했으며 원본 커서 파일의 파싱·반전·상하 방향은 단위 테스트로 검사했다.
- 기존 건설 27개, 이동 22개, 전투 56개, 생산 19개, TEST01 화면/언어 4개 구성·96개 단언, 일반 UI·전체화면 왕복/설정 저장·도움말/옵션 검사 통과. 건설·생산 검사의 이전 좌표는 실제 7×8 발자국이 섬 안이고 다른 건물과 겹치지 않는 자리로 보정했다.
- 원본 게임 실행·OS 입력·영상 녹화 없이 클론 UI 자동화만 사용했다. 설정은 별도 검사 폴더로 격리했다. PNG와 로그는 Git 제외 `extracted/screens/test02-implementation/`에 있다.

```powershell
# 이미 빌드된 Release 클론으로만 실행한다.
powershell -NoProfile -File tools/clone_test02_smoke.ps1
powershell -NoProfile -File tools/clone_test02_smoke.ps1 -Language english -OutputDirectory extracted/screens/test02-implementation/test02-english
dotnet test tests/Netstorm.Core.Tests -c Release --filter "ConstructionTests|PlacementCursorTests"

```

## 정밀 복원에 남은 부분

- 취소 그림자 유지 **0.35초**는 측정 범위 0.2~0.9초 안의 근사값이며 정확한 상수로 확인된 값은 아니다. 환불 표시 지연 0.85초도 관찰값이다. 경제·자리 해제는 지연하지 않는다.
- 대기 바닥 띠 **20px**, 건물의 선형 높이 증가, 창문 점등 진행률 **90%**는 관찰된 순서를 구현한 화면 근사다. 원본의 공사장 초목 마스크·실제 증가 곡선·완공 직전 조각 합성을 복원한 것은 아니다. 그림자 음영도 기존 근사를 쓴다.
- 건설 메뉴의 세 창 겹침·목록 아이콘·행 간격은 구현했으나 글꼴·가장자리에서 밀리는 정확한 위치·돌 질감은 완전 일치하지 않는다.
- 들고 있는 건물의 허공 좌/우클릭 취소, 다른 유닛 선택·정지 키에 따른 대기 취소는 원본 미시험이다. 수송·제단·주문 커서, 알타 개수 제한의 원본 대조, 일반 이동 충돌 회피도 남는다.
- Linux GUI 실행, 실제 효과음 청취, 안정적인 30/60/120FPS 및 캠페인 완주 검증은 기존 후속 작업이다.
