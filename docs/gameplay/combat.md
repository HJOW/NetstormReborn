# 포대 전투 1차 구현과 추정 사항

2026-10-01. `BattleSession.Combat.cs`에서 포대 자동 공격·체력·피해·파괴·사제 기절을 구현하고
클론 맵 뷰어에 연결했다. **전투 전체의 복원이 아니라 캠페인 구현을 위한 첫 동작 모델**이다.
원본 게임은 실행하지 않았다. 기존 바이너리의 디컴파일, 실제 타입 파일, 매뉴얼과 로컬 영상을 사용했다.

후속 구현: **Whirlibase·Whirligig 출격·공격·귀환·보급·재생성**을 추가했다.
아래 포대 설명의 공중 공격체 미구현 표기는 당시 범위이며, 최신 상태는 [flyers.md](flyers.md)를 따른다.

2026-10-03: [TEST01 추가 판독](../videos/test01-combat-20261003.md)으로 고정 캐논 방위·충전·연속 사격·탄속·원본 그림,
아이스 타워 재성장, 썬 바리케이트 연결·흡수, 캐논 착탄점 회피를 반영했다. 정확한 한 발 피해량·얼음 파편·세부 회전은 후속이다.

## 구현한 규칙

- 매 틱: 명령 → 수집 → 수송·사제 이동 → 건설 완료 → 전투 → 희생 의식 → 튜토리얼 → 다리 공급·붕괴 → 미션 승패 이벤트.
- 완공된 `group = cannon` 또는 `archer` 포대가 자동으로 공격한다. Whirlibase는 별도 비행체 처리로 공격한다.
  Rain/Wind 공중 기지·fence·주문은 아직 공격하지 않는다.
- 소유자 0, 같은 소유자, `BattleMap.AreAllied`가 참인 상대, 체력이 없는 타입, 기절한 사제는 목표에서 제외한다.
- 논리 칸 좌표의 **발자국 중심 거리**로 사거리를 검사한다. 가까운 적부터 선택하고 동률은 엔티티 번호순이다.
  선택한 목표가 살아 있고 사격 가능한 동안 유지한다. 사거리 밖으로 이동하거나 사선이 막히면 다시 찾는다.
- Sun·Ice·Thunder Cannon은 포대 중심의 가로·세로 선으로만 발사한다. **썬 캐논(Sun Cannon)만 배치 방향에 구속되지 않으며, 목표물이 바뀌어 방향이 달라지면 스스로 회전한다.** 아이스 캐논(`rainCannon`)·썬더 캐논은 **배치 전에 우클릭으로 방향을 정하고, 설치 후에는 그 방향으로만 공격한다.** 설치 후 수동·자동 회전은 없다(사용자 확인, 2026-10-03).
  Crossbow 등 다른 포대의 방향각은 미구현이다. 썬더는 3.5초 충전·0.125초 복귀, 아이스는 0.08초 그림·4초 사격·6초 휴식을 적용한다.
- `shotblocking`과 지상 블로커가 사이에 있으면 뒤의 적을 쏘지 않고 앞의 공격 가능한 적을 탐색한다. 성장 중인 얼음은 차폐하지 않는다. 반 칸 간격의 발자국 검사를 사용한다.
- 피해 = `hpPerSec × 사격 간격`. Sun Cannon은 현재 16 × 5 = 80, Vander Tower는 35 × 1 = 35, 썬더는 40 × 3.625 = 145, 아이스는 20 × 0.24 = 4.8이다.
  **값의 출처는 원본 타입이지만 곱셈식·반올림·실제 공격 애니메이션 주기는 근사**다.
- 일반 탄은 발사·도착 틱을 예약한다. 피해는 도착 때 적용하며 발사자가 파괴되어도 이미 발사한 탄은 남는다.
  대상이 먼저 파괴되면 탄은 소멸하고 중복 보상은 없다.
- 세 캐논의 탄속은 원본 상수 20칸/초다. 캐논은 착탄점에서 현재 목표 위치를 검사해 이동 회피를 허용한다. 다른 탄은 기존 예약 피해 방식이다.
- 아이스 타워는 일반 사격 파괴 시 받침을 남기고 약 34.667초 동안 원본 14성장 그림을 거쳐 1060HP로 돌아온다. 성장 중에는 체력·차폐·처치 보상이 없으며 회수 대금은 0이다. 주문에 의한 영구 제거는 미구현이다.
- 썬 바리케이트는 같은 행·열에서 50칸 미만의 가장 가까운 동맹 기둥끼리 연결한다. 중간 적 기둥은 연결을 끊는다. 아군 사격은 통과하고 적 탄·번개는 흡수한다. 기둥 제거·비행 중 새 방어선도 반영한다. 원본 선·아이스/썬더 탄 그림을 표시한다.
- Vander Tower는 다음 1틱에 피해를 주고 번개 경로를 0.2초 표시한다. 피해 틱과 표시 수명은 따로 둔다.
- 공중 타입(`balloon`/`flyer`)에 `useairdamage = 1`이면 `airdamage`를 사용한다.
  비행 수송의 지상/이륙 상태가 없으므로 풍선은 현재 항상 공중 대상으로 본다.
- 파괴 시 점유·공급원·워크샵 등록·신전 소유권/생산·선택·관련 수집 작업을 정리한다.
  비용과 기존 `KillRewardPercent`로 최종 타격 소유자에게 보상을 한 번 지급한다. **캠페인·튜토리얼(싱글 플레이) 보상 비율은 25%다.**
  exe 전투 초기화 `FUN_004b2df0`이 보상 비율 `DAT_005424bc = 0x19`로 두고, 옵션 표 값(`FUN_0041ca70`, 기본 인덱스 2 = 50%)은 네트워크 옵션 동기화 `FUN_004b4900`에서만 덮어쓴다.
  클론은 `BattleSessionFactory`가 `BattleOptions.ApplySinglePlayerKillReward()`를 부른다(멀티플레이 구현 때 분리). 자기·동맹 오브젝트가 휘말려 파괴되면 보상을 주지 않는다(임시).
- **파괴 폭발(2026-10-01, 사용자 설명 + exe `FUN_0044b9e0`):** 전투로 파괴된 **템플(`vortex`)과 포격 건물(group `archer`·`cannon`: Sun Cannon, Sun Disc Thrower(`sunArcher`), Vander Tower 등)**은 발자국 주위 1칸의 지상 오브젝트에 피해를 준다.
  - 피해량: 템플 고정 **400**(타입 플래그2 `0x200` = `vortex`). 포대는 **최대 체력/2 + 1**(Sun Cannon 301, Sun Disc Thrower 151).
  - 범위: 원본은 중심에서 발자국 크기/2 + 1. 클론은 발자국을 1칸 넓힌 사각형과 겹치는 오브젝트로 계산한다.
  - 템플 옆 골렘(HP 50)은 한 번에 파괴되고 사제(HP 100)는 기절한다(사용자 설명과 일치).
  - 대상은 소유자 구분 없이 범위 안의 피해 가능한 지상 오브젝트다. 비행체·비행 수송·운반/묶인 사제·이미 기절한 사제는 제외한다(제외 조건은 원본 비트 의미 미확인 근사).
  - 피해는 처치한 플레이어 이름으로 들어간다. 그래서 휘말려 파괴된 적 오브젝트의 보상(각 25%)도 그 플레이어가 받고, 휘말린 포대는 다시 폭발한다(같은 틱, 오브젝트 번호순).
  - 판매(회수)·낙하·의식 소멸은 폭발하지 않는다(exe 는 제거 이유 플래그 `0x200000`일 때 건너뜀 — 회수 플래그로 추정).
  - 이벤트 `EntityExploded`가 난다. 폭발 그림·효과음은 아직 연결하지 않았다.
  - 캠페인 1-2 녹화 08:25의 SP +3,487은 적 템플 25%(1,250)와 주위에서 함께 파괴된 적 골렘·건물 보상의 합으로 설명된다(사용자 설명).
  기존 건물형 오브젝트 제거의 주변 다리 약화도 적용한다. 회수와 파괴는 같은 정리 함수를 쓴다.
- 다리 격자는 현재 살아 있는 엔티티의 점유·`dropBlocking`을 보므로 파괴/회수된 건물이 옛 자리를 계속 막지 않는다.
- 사제는 체력 ≤ 50%에서 50%로 제한하고 기절·보호막 상태로 전환한다. 수집을 취소하고 추가 공격 대상에서 제외한다.
  지지 칸에 있고 자기 완공 신전이 있으면 완전 회복 후 깨어난다. 신전 파괴 자체가 사제를 기절시키지는 않지만, 신전 주위 1칸에 있던 사제는 파괴 폭발(400)로 기절한다.
- 발밑 다리·건물 받침 소멸은 피해와 별도로 틱 끝에 처리한다. 지상 보행 유닛은 낙하로 제거하며 처치 보상을 주지 않는다. 사제는 HP를 낮추지 않고 허공에서 기절하고, 그동안 신전 회복을 적용하지 않는다. 발판 복구 시 HP가 절반 이상이면 회복하며 비행 수송으로도 포획할 수 있다. 낙하 시간·결정 소지·해방 HP의 임시 정책은 [이동 경로 문서](movement-pathing.md#34-낙하-규칙-구현과-임시-정책)에 있다.
- 기절한 적 사제의 수송 포획, 알타 운반·구속, 내 사제 이동, 다섯 룬 의식과 의식 중단·사제 구출을 구현했다. 의식의 룬 간격·소멸 시점·희생·알타 제거·승패 이벤트 지연은 영상 측정 또는 exe 상수를 쓴다. 확인된 사실과 임시값은 [희생 의식 구현](sacrifice.md)에 나눈다.
- 신전 완공·파괴·회수 뒤 지면은 살아 있는 신전의 원소·소유자를 따른다. 신전이 없으면 Sun/중립이다.
  원본 섬 생성 시드·마스크와 장식 위치를 유지하고 지면·절벽·장식 외관을 갱신한다.
- 체력·기절·목표·다음 발사 틱·비행 중 피해 예약은 `Checksum()`에 포함한다. 번개 표시 목록은 화면 전용이다.

새 영상에 이 동작들이 보인다는 이유로 구현됐다고 간주하지 않는다.
Sun 공중 공격체의 첫 구현과 지상 수송·희생 의식의 첫 모델은 완료했다. 비행 수송의 이륙·착륙 애니메이션과 원본의 정밀 타이머·외관 대조는 후속이다.

## 사용·검증

- `--mission 이름`: 브리핑을 닫은 뒤 자동 전투. 안내 창의 기존 시간 정지 정책을 그대로 따른다.
- `--map 이름`: 처음에는 전투 꺼짐. **F3**으로 전투와 맵 세션 시간 진행을 켤 수 있다.
- `--script "combat 1; wait 1"`: 개발용 전투 진행. `combat 0`은 피해 처리를 끈다. 아이스 타워 재성장은 시간이 흐르면 계속한다(시간 일시정지는 Space).
- 커서 위 **T**: 선택한 오브젝트의 체력 수치. 손상된 오브젝트는 체력 막대, 기절 사제는 금색 고리.
- 선택한 수송 유닛으로 기절한 사제·알타를 차례로 클릭하고, 내 사제도 선택해 알타를 클릭하면 운반·의식 명령을 낸다. `D` 뒤 빈 칸 클릭은 사제를 내려놓는다. 전체 입력·스크립트 명령은 [map-viewer.md](../map-viewer.md#수송-사제-포획과-알타-의식)에 있다.
- `.type`의 `fireSound`가 있으면 발사 효과음 요청. 삭제된 발사자의 소리·위치 음량과 번개 고유음은 미완성이다.

검증: Release 빌드 성공. 전투 당시 Assets 186·Core 170 테스트 통과(전투 신규 14, 지면 신규 1). 포획·희생 추가 테스트 결과는 [희생 의식 구현](sacrifice.md)에 기록했다.
기존 테스트의 CA2014 경고가 클린 컴파일 때 나온다. 마지막 증분 빌드는 경고·오류 0이었다.
클론의 Dissolved Alliance 맵에서 양측 발사·피해 이벤트와 체력·탄 PNG를 확인했다
(`extracted/combat-clone-dissolvedalliance.png`). 원본과 일대일 전투 시간·피해 비교, 실제 청취,
Linux 실행, 캠페인 완주는 아직 검증하지 않았다.

샌드박스의 기존 MSBuild 작업 프로세스가 쓰기 거부를 일으켰다. 권한 상승만으로는 재사용 프로세스에 남았고,
승인된 `dotnet build/test ... -m:1 -nr:false -p:UseSharedCompilation=false`로 빌드·검사를 완료했다.
