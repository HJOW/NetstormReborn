# 원본 조작키와 입력 UI

> 2026-10-02 정리. 원본 10.78의 [네 번째 사용자 녹화](../videos/ui-controls-record-play-20261001.md),
> 특히 내장 `NetStorm User Interface` 도움말 프레임 `g1190`·`g1280`·`g1330`·`g1420`을 근거로 한다.
> [동봉 GAME.HLP 요약](../sources/game-manual.md)의 4절 조작 요약과도 대조했다.

**실제 조작 결과**와 **도움말에 기재된 키 설명**을 구분한다.
이번 녹화의 키 이벤트는 Escape 한 번의 누름/해제뿐이다. 표의 나머지 키를 직접 시험한 기록은 아니다.
키 안내와 클론의 개발용 키 배정을 혼동하지 않는다.

이번 자료는 우클릭이 **현재 상태와 클릭 대상에 따라 다르다**는 근거다.
생산 창 항목 우클릭의 정보 메뉴, 지도 오브젝트 명령 메뉴, About 설명창을 구분해 복원한다.
다리를 든 상태의 우클릭 회전은 기존 도움말·관찰 근거를 사용하며 이번의 짧은 연속 클릭만으로 확정하지 않는다.

도움말은 **여러 단축키가 채팅 창을 숨긴 상태에서만 동작한다**고 안내한다.
이 녹화에서는 채팅 창이 열린 상태와 비교하지 않았다.
F7의 섬 색과 Shift+F3의 섬 테마는 서로 다른 항목이다.
동봉 HLP는 F7을 섬 소유 표시로 설명하므로 색 전환을 지형 테마 교체로 해석하지 않는다.

## 도움말의 마우스 스크롤 설명

왼쪽 클릭은 유닛 선택, 오른쪽 클릭은 창이나 유닛의 명령 메뉴로 안내한다.
**Alt를 누르면 커서 방향으로 화면을 이동**시키며, IntelliMouse의 가운데 휠 버튼을 누르는 것도
Alt와 같은 동작으로 설명한다. 이는 휠을 굴리는 이벤트와 구분한다.
전체화면 또는 바탕화면이 640×480인 창 모드에서는 커서를 화면 끝으로 옮겨 스크롤할 수 있다고 적혀 있다.
이번 1024×768 창 녹화에는 Alt·가운데 버튼·전체화면 전환 기록이 없어 실행 여부를 추가 확인한 것은 아니다.
Options에는 `Edge Scroll in Fullscreen` 선택 항목이 실제로 보인다.

### 화면 이동 실측 (2026-10-03, 30FPS 사용자 녹화)

[녹화 노트](../videos/record-play-edit-test01-20261003.md) §4에서 측정한 값이다(1280×960 캡처 기준, 게임 논리 좌표는 ÷1.25).

| 조작 | 결과 |
|---|---|
| **Alt를 누른 채 커서 이동** · **가운데 버튼을 누른 채 커서 이동** | 같은 동작. 카메라 속도 = k × (커서 − 지도 영역 중심). 가로 k≈9.2/s, 세로 k≈8.3/s, 중심 ≈(692, 485). 거리에 비례하고 놓으면 0.05~0.1초 안에 정지. 편집기와 시험 전투에서 같다(상관 0.95~0.98). |
| **미니맵(왼쪽 아래 검은 상자) 왼쪽 버튼 누르기·끌기** | 현재 화면 범위 사각형이 커서를 따라가고 화면도 따라온다. 편집기·전투 모두 같다. 미니맵은 1px = 2칸으로 **화면 중심을 가운데 둔 156×148칸 창**만 보여 주므로, 누른 지점이 새 화면 중심이 되고 누르고 있는 동안 계속 그 방향으로 흘러간다. 사각형이 상자 안을 움직이는 것은 월드 끝에서뿐이다([좌표 규칙](../videos/test01-visuals-20261003.md) 5절, 2026-10-03 클론 반영). |
| 지도 위 왼쪽 드래그(편집기, 도구 없음) | 화면 변화 없음 |
| 창 가장자리에 커서 | **전체화면에서만 동작**(사용자 보고, [edge-scroll.md](../exe/edge-scroll.md)의 정적 분석과 일치). 창 모드 녹화에서는 시도 없음 |
| **Shift+1 화면 위치 저장** | 사용자 보고: **동작하지 않았다**(도움말은 Shift+0~9 저장). 이번 녹화에는 입력이 없어 영상 증거는 없고 원인 미확정 |
| 방향키·휠 굴리기·오른쪽 드래그·F4/F5/H/U·숫자 복귀 | 이번 녹화에서 시도하지 않음 |

클론의 Alt/가운데 버튼 이동은 일정 속도(600px/s)라 원본의 거리 비례 속도와 다르다([비교](../videos/record-play-edit-test01-20261003.md#43-클론과의-차이후속-과제)).

### 들고 있는 유닛의 자리 (2026-10-03, 같은 녹화의 입력 기록 대조)

| 항목 | 원본 |
|---|---|
| 커서가 가리키는 칸 | 화면에 보이는 그 칸(지면 타일은 칸 기준점의 왼쪽 위에 그려진다) |
| 발자국 위치 | 오른쪽 아래 칸의 **열 = 커서 칸의 열**, **행 = 커서 칸의 행 + 1 + 타입의 `height`**. 3×3 유닛은 커서가 오른쪽 열·가운데 행에 놓이고, Thunder Cannon(`height = 2`)은 커서가 발자국 위쪽 한 칸 밖에 놓인다 |
| 고정 캐논 우클릭 | 방위만 돌고 발자국 사각형은 그대로다. 발사 방향으로 사거리 반짝임이 5칸 간격·약 15칸/초로 흘러간다 |
| 표시 | 유닛 그림 + 흰 발자국 사각형 + 왼쪽 원소 아이콘(충족하면 밝게) + 아래 노란 비용·Storm Power 보석. 에너지 부족은 "Energy not satisfied", 겹친 자리는 붉은 사각형 |

근거·측정값: [TEST01 화면 요소 대조](../videos/test01-visuals-20261003.md) 9절. 클론은 `PlacementCursor`·`FortMapViewer.PlacementPreview.cs`에 반영했다. 건물(사제 Construct)에 같은 규칙을 쓰는 것은 추정이다.

## 클론 적용 (2026-10-02)

공개 캠페인의 플레이 조작을 원본 키 배정으로 바꿨다. [적용·검증 기록](../screens/recorded-ui-clone-20261002.md).

- F1 일반 도움말, F2 건물 그림 숨김, F4/H 홈 템플, F5 현재 사제 위치, F6 지식, F7 섬의 소유 색, F8 목표 다시 보기.
- P/R 사제 선택과 이미 선택한 사제 보기, Ctrl+F5/N 수송 유닛 순환, T 타이머(원본 녹화처럼 꺼진 채 시작), Tab 최근 배치한 유닛 최대 다섯 개 순환.
- **2026-10-02 추가:** Shift+F3 섬 테마 숨기기/보이기(모든 섬을 기본 초록 지면으로, 1-1 녹화 05:02), U 마지막으로 잃은 내 오브젝트 위치로 이동(exe `0x4b0b89`가 `unitLost.wav`와 함께 위치를 저장). Esc 메뉴 막대의 View 목록은 원본 8항목(F2·Shift F3·F4·F5·F6·F7·F8·F9)을 같은 순서로 보이며 F9 플레이어 목록은 비활성이다([녹화 최종 판독](../videos/record-play-final-20261002.md#화면)).
- Shift+F9/Pause 일시정지. 플레이에서 Space는 일시정지에 사용하지 않는다.
- Shift+0~9 카메라 저장·0~9 복귀. 숫자 1~6의 개발용 다리 선택은 플레이에서는 사용하지 않는다.
- Q/W/A/S/Z/X 다리 집기(칸 자리 고정), E 집을 수 있는 마지막 다리 칸, 들고 있는 다리 우클릭 회전, C 회전 방향, D 생산 창에서 마지막으로 집은 유닛 다시 집기. 다리 키는 커서가 생산 창 위에 있어도 동작한다(2026-10-02, [생산 창](../screens/clone-deck.md)).
- Alt/가운데 버튼을 누르면 커서 방향으로 카메라가 이동한다. 플레이에서는 오른쪽 드래그 카메라 이동과 휠 확대를 사용하지 않는다.

[개발용 맵 뷰어](../map-viewer.md)의 F4 사제 이동·F3 전투 전환·Space 일시정지 등은 유지한다.
미션에서 화면 설정의 F7/F9 단축키는 차단해 섬 색과 Shift+F9에 충돌하지 않게 했다.
채팅(F3)·온라인 목록(F9)·Shift+F7 파일 캡처는 아직 연결하지 않았다(Shift+F3·U는 2026-10-02 연결).

이 배정은 원본 도움말과 녹화 UI를 반영한 클론 구현이다. 이번 원본 녹화에서 모든 키를 실제로 누른 것으로 해석하지 않는다.
포획·의식 구간의 원본 입력 지연 확인은 별도 후속이며 클론 UI 검사로 대체하지 않는다.
