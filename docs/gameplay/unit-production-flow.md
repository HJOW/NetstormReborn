# 유닛 생산 자원 운송과 실체화

> 2026-10-04 구현. 원본 실행·추가 원본 분석 없이 로컬 팬게임 코드와 기존 프로젝트 자료를 참고했다.

생산 창에서 유닛을 놓으면 비용을 즉시 내고 자리를 예약한다. 덱에 등록할 때 사용한 **워크샵**에서 스톰 파워가 출발한다. **골렘은 템플**이 기점이다. 배치 위치를 덮는 제네레이터·템플은 필요한 원소 에너지를 별도로 보낸다. **두 종류의 자원이 모두 도착한 뒤** 유닛이 반투명하게 나타나 실체화하고, 실체화가 끝나면 이동·전투·에너지 공급·받침 생성이 활성화된다.

## 참고한 팬게임

로컬 `originalFanGame/www/assets/battle-CdfxIFuq.js`의 다음 흐름을 참고했다. 팬게임 파일은 수정하거나 복사하지 않았다.

| 함수·값 | 팬게임 동작 | 클론 적용 |
|---|---|---|
| `sf` | 배치·비용 차감·`energyDeliveries`·`teleporterSparkWaypoints` 생성 | 자리 예약과 독립적인 자원 운송 생성 |
| `qa`, `Vd`, `jd=18` | 원소 요구를 먼저 채우고 아무 원소 요구를 남은 공급원으로 채움. 보석은 18칸/초 직선 이동 | 기존 요구값 유지, 각 요구마다 서로 다른 공급원 선택·보석 직선 이동 |
| `Hd`, `Ud`, `za` | 기점 발자국의 목표에 가까운 칸에서 지면 경로를 따라 스톰 파워 이동 | 같은 출구 규칙과 지면·다리 경로 사용. 속도는 동봉 `teleportEffect.type`의 12칸/초 |
| `Ud` | 여러 후보 중 가까운 경로를 선택 | **사용자 요청에 따라 덱의 `SourceId`에 있는 워크샵·템플로 기점을 고정** |
| `HC`, `BC` | 실제 공급 원소의 `manabolt` A/B/C/D 그림 | 원본 보석 그림 사용. 아무 원소 요구도 실제 공급원 원소로 표시 |
| `eE`, `PT/FT` | 파랑→흰색 입자 꼬리 | 이동한 경로의 짧은 파랑·흰색 꼬리로 근사. 규칙 난수와 분리 |
| `zd`, `Ld=600`, `yv=1000` | 포대 0.6초·나머지 유닛 1초 실체화 | 모든 자원이 도착한 틱부터 같은 시간을 고정 틱으로 예약 |

팬게임은 스톰 파워의 도착 시각을 기준으로 실체화 시간을 잡는다. 클론은 사용자 요청에 따라 **원소 에너지가 더 늦으면 그 도착도 기다린다**. Sun Generator 등 팬게임 전용 유닛은 추가하지 않았다.

## 규칙과 예외 처리

- `ProductionDeck.Entries()`의 기점 번호를 사용한다. 다른 가까운 워크샵으로 바꾸지 않는다. 없어진 기점이 덱에만 남아 있으면 비용 차감 전에 거부한다.
- 원소 공급원은 기존 범위·동맹·원소 요구 규칙을 만족해야 한다. 같은 원소에서는 배치 중심과 가까운 공급원을 먼저 쓰며 거리 동률은 오브젝트 번호로 정한다. 하나의 공급원은 요구 글자 하나에만 대응한다.
- 운송 중인 지상 유닛은 목적지를 점유해 중복 배치를 막는다. 자원 자체는 점유·유닛 충돌·피해 판정에 참여하지 않는다. 기존 비행 수송은 지상 점유를 만들지 않는다.
- 운송·실체화 동안 체력은 0이고, 이동·채집·포획·회수 명령은 완성되지 않은 유닛으로 거부한다. 포대·방어선·비행 기지·제네레이터·받침도 아직 동작하지 않는다. 생산 수는 활성화 때 증가하므로 튜토리얼이 생성되지 않은 유닛을 세지 않는다.
- 스톰 파워는 소유 다리의 연결 방향과 지면 경로를 사용한다. 지형 버전이 바뀌면 현재 위치에서 재탐색하되 안전한 진행 중 걸음은 이어 간다. 경로를 잃으면 그 지점에서 공중 직선 이동으로 전환하고 목적지까지 계속 간다. 처음부터 경로가 없을 때도 같은 방식이다.
- 출발 뒤 워크샵·템플·원소 공급원이 사라져도 이미 지불한 자원은 계속 도착한다. 요구값을 다시 검사하지 않는다. 이는 [기존 줄기 설계](movement-pathing.md#43-설계-요구-줄기는-이동-불가-상태에-빠지지-않는다)의 기본 권장을 적용한 정책이다.
- 목적지의 발판이 사라지면 자원 도착 또는 실체화 중에 **전액 환불**하고 예약·선택·점유를 정리한다. 낙하·폭발·다리 약화는 발생하지 않는다. 받침을 만드는 유닛은 둘레에 지지하는 다리 끝이 남으면 완성할 수 있다. 비행 수송은 지상 발판 소멸로 취소하지 않는다.
- 생산 창 재충전은 배치 때 시작하는 기존 Unit Rate 규칙을 유지한다. 지도에 처음부터 있는 유닛·AI의 미션 시작 수집자·생산 규칙을 끈 개발용 배치는 완성 상태로 시작한다.

## 코드와 검증

`UnitProduction`·`ProductionDelivery`는 기점·공급 원소·현재 좌표·도착 여부·지상 경로·공중 전환을 보관한다. `BattleSession.Production.cs`는 운송과 실체화를 진행하고, `UnitMaterializing`·`UnitCompleted`·`UnitProductionCancelled` 사건을 알린다. 운송 상태는 세션 검사합에 포함한다. 렌더 보간·꼬리·색·효과음 주기는 검사합에 영향을 주지 않는다.

화면은 `FortMapViewer.Production.cs`에서 파란 스톰 파워 꼬리와 원본 보석을 그리고, 도착 후에는 진행 막대 없이 유닛이 불투명해진다. `teleportEffect.wav` 이동음·`buildDone.wav` 완료음을 연결했다. 반복 이동음은 임시 0.25초 주기이며 실제 소리 청취·원본 주기 대조는 후속이다.

재현 명령:

```powershell
dotnet test tests/Netstorm.Core.Tests -c Release --filter UnitProductionTests
powershell -File tools/clone_production_smoke.ps1
```
