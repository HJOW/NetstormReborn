## Core 동작

1. 수송 유닛은 `.type`의 `speed`로 이동한다. 지상 수송은 섬과 자기 다리 칸을 따라가고, `balloon`은 현재 직선 이동을 쓴다. 모든 이동 유닛은 타입별 속도를 따르지만, 비행형 수송의 이륙·착륙 상태와 애니메이션은 아직 없다.
2. 수송 유닛은 기절한 적 사제를 포획한다. 보통 체력이 절반 이하가 되면 기절하지만, 발판을 잃은 사제는 체력과 관계없이 허공에서 기절한다. 허공 사제는 비행 수송만 집을 수 있다. 미션의 `allowAnyCapture`가 켜져 있으면 기절 여부와 관계없이 포획할 수 있다. 포획 사제는 수송 유닛에 점유·회복되지 않는 운반 상태로 붙는다.
3. 수송 유닛이 내 완성 알타에 도달하면 포획 사제가 알타에 묶인다. 포획 사제를 내 섬에 내려놓으면 구출 이벤트를 내고 사제를 회복한다. 수송 유닛·알타가 파괴되거나 의식이 깨져도 포획 사제를 **그 위치에서** 풀어 회복한다. 발밑 지지가 없으면 곧바로 허공 기절시킨다(지면으로 순간이동하지 않는다).
4. 내 자유 사제가 알타 옆으로 이동하면 의식이 시작된다. 순서대로 다섯 룬을 진행한다. 내 사제가 기절·이탈하거나 알타 체력이 기준 아래로 내려가면 의식을 중단하고 포획 사제를 풀어준다.
5. 다섯 번째 룬 뒤 완료·희생·알타 소멸 단계를 밟는다. 희생 사제는 알타가 사라진 뒤 3초 더 내부 상태에 남고, 제거 시점에 팀의 사제가 없어졌는지 다시 판정한다.

미션의 `[aiNTempleHalfDead]`, `[aiNTempleDead]`, `[aiNPriestDead]`, `[aiNPriestCaptured]`, `[aiNPriestSaved]`, `[GoodTeamDead]`, `[BadTeamDead]`, `[Failed]` 조건은 `MissionTell` 이벤트로 알린다. 같은 섹션은 한 세션에서 한 번만 알린다. 미션 스크립트에 표시 가능한 섹션이 있으면 맵 뷰어 안내 창이 열리고, 안내 창이 열린 동안 세션 시간이 멈춘다. 튜토리얼 번호가 있는 미션은 캠페인 승패 이벤트를 별도로 알리지 않는다.

**점검 보완(2026-10-01, 원본 미션 전수 검사):**
- 신전·사제·팀 전멸 이벤트(`TempleDead`·`TempleHalfDead`·`PriestDead`·`GoodTeamDead`·`BadTeamDead`·`Failed`)는 그 대상이 **한 번이라도 살아 있는 것을 본 뒤에만** 낸다(`_seenAlive`). 이전에는 적 사제·신전이 처음부터 지도에 없는 미션(`tnron8ex` 등)이 시작 즉시 성공·실패 창을 띄우고, 동맹이 없는 거의 모든 미션에서 `GoodTeamDead`가 첫 틱에 참이 됐다. 원본은 AI 의 신전·사제를 미션 시작에 연결해 두므로 정상 미션의 결과는 같다. 회귀 검사: `MissionOutcomeTests`(원본 미션 전부 5초 진행).
- 동맹은 `aiNAllyList`뿐 아니라 사람 플레이어의 머리 값 **`myAllyList`**("4;6;7;8")도 읽는다(한쪽만 적어도 동맹).
- 실패 창의 Continue(`Tell,TryAgain`)는 미션 스크립트가 아니라 공용 `tell.english`의 `[TryAgain]`(Replay Mission / Leave Missions)을 연다. `{mission.title}`·`{mission.fileName}`은 현재 미션 값으로 치환한다(`TutorialDialogScript`의 공용 스크립트·미션 값 인자).
- 희생 음악은 의식 완료 뒤에도 제단이 소멸할 때까지 "진행 중"으로 본다(원본 제단 프레임이 단계 1 이상인 동안).

`Checksum()`에는 운반 상태·이동 작업·의식 단계·이미 알린 섹션이 들어간다. 같은 초기 상태와 명령 순서는 같은 상태를 만든다.

**점검 보완(2026-10-01, 코드 점검 후속 수정):**
- 내려놓기(`DropPriest`)도 포획·운반·알타 이동과 같이 지형이 바뀌면 같은 목표 칸으로 길을 다시 찾는다. 원본의 옛 경로 추적 결함은 사용자 결정대로 수정했다. **길이 없으면 목표와 포로를 유지한 채 대기하고, 다리를 복구하면 새 명령 없이 재개**한다. 회귀 검사 `DropPriest_RecomputesRouteWhenBridgeIsCutMidTransit`는 이 전체 흐름을 확인한다. 수확·수송·사제 이동은 `MovementRoute`의 공통 상태·재탐색 코드를 쓴다([이동 경로 3.2절](movement-pathing.md#32-길-막힘-대기와-남은-보완)).
- 사제는 발밑 다리·받침 소멸 시 허공에서 기절하고 지상 점유를 비운다. 비행 수송으로 포획하거나 그 칸에 다리를 다시 놓을 수 있으며, 발판 복구 시 HP가 절반 이상이면 기절에서 회복한다. 운반체 해방 시 `NearestStandable`로 가까운 땅에 옮기던 처리는 제거했다. 허공 회복 금지·해방 HP·결정 유지 등 미확인 정책은 [이동 경로 3.4절](movement-pathing.md#34-낙하-규칙-구현과-임시-정책)에 있다.
- 희생된 사제를 제거할 때도 전투 파괴·회수와 같은 `RemoveEntity`를 거친다. 전에는 `_entities`에서만 지워 그 사제를 보고 있던 선택 상태가 죽은 오브젝트 번호를 계속 가리킬 수 있었다. 회귀 검사: `Ritual_RemovingVictimClearsSelectionLikeOtherDestruction`.

## 적용한 시간과 임시값

| 단계 | 구현 시간 | 근거와 오차 |
|---|---:|---|
| 의식 시작 → 첫 룬 음성 | 1.2초 | 캠페인 1-1 녹음에서 측정 |
| 룬 음성 사이 | 14.8초 | 캠페인 1-1 녹음과 1-5 영상·소리 대조 |
| 룬 음성 → 룬 소멸 | 12.1초 | 두 미션의 효과음·프레임에서 약 12초로 측정한 평균 |
| 마지막 룬 완료 → `priestSacrifice2` | 4.0초 | exe 상수와 녹음이 일치 |
| 의식 완료 → 알타 제거 | 9.3초 | 1-1 약 9.4초, 1-5 약 9.2초의 평균 |
| 알타 제거 → 희생 사제 제거·미션 재판정 | 3.0초 | 1-5에서 알타 폭발 뒤 성공 창까지 약 3초 |
| 알타 건설 클릭 → 완공 | 14.5초 | 1-5 한 번 관찰. 사제 이동과 순수 건설 시간을 나누지 못한 임시 총시간 |
| 알타 피해 중단 기준 | 최대 체력의 50% | 도움말은 “too much damage”라고만 설명해 비율은 미측정 |

첫 룬 지연·룬 간격·피해 임계값·알타 건설 시간은 추가 미션에서 다시 확인해야 한다. 화면에서는 진행 단계를 읽기 쉽게 다섯 칸으로 표시하며 원본 알타 프레임 연출은 복원하지 않았다.

## 맵 뷰어 조작

1. 수송 유닛 위에 커서를 두고 `T`를 눌러 선택한다.
2. 기절한 적 사제를 클릭해 포획한다. 수송 유닛이 이동한 뒤 알타를 클릭해 운반한다.
3. 내 사제를 `T`로 선택하고 알타를 클릭한다. 사제와 수송 유닛이 알타 주변에 도착하면 의식이 시작된다.
4. 수송 중 사제를 내려놓으려면 `D`를 누른 뒤 빈 칸을 클릭한다.

검증 스크립트 명령은 `capture tx,ty px,py [ax,ay]`, `deliver tx,ty ax,ay`, `altar ax,ay`, `drop tx,ty x,y`다. 입력 세부사항은 [map-viewer.md](../map-viewer.md#수송-사제-포획과-알타-의식)에 있다.

## 검증 상태

- `SacrificeTests` 10개: 기절 전 포획 거부, 포획·운반·의식 시작, 룬 타임라인과 승리 판정 지연, 구조 미션의 포획·구출 안내, 수송 파괴 구출, 다리가 끊겼을 때 내려놓기 대기·복구 재개, 희생된 사제 제거 시 선택 해제, 알타 피해로 의식 중단, 결정론.
- 후속 이동·낙하 회귀 검사 **19개**(`MovementPathingTests` 4·`GroundSupportTests` 15) 포함, 전체 테스트 **403개 통과**(Assets 187·Core 216). 원본 실행 없이 검사했다.
- `dotnet build Netstorm.sln -c Release --no-restore` 성공. 현재 클린 빌드에서 기존 `TextResourceTests.cs`의 CA2014 경고 1개가 발생했다.
- 이 의식 구현의 전체 GUI 동작은 검증하지 않았다. 후속 Windows 클론 GUI 검사에서 받침 회수 전후 화면만 확인했다. 적 수가 여럿인 미션에서 다른 적 사제가 남았을 때의 음악 복귀, 비행 수송의 이륙·착륙, 시각 효과와 전체 캠페인 결과 창은 후속 검증 대상이다.
