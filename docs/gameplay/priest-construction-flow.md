# 사제 건물 건설 흐름 (Construct 메뉴 · 걸어가서 건설)

2026-10-04, 원본 자동 분석 기록(2026-10-03)과 웹 팬게임 코드(`originalFanGame/www/assets/battle-*.js`)를 대조해 클론의 건설 흐름을 고쳤다. 이 작업에서 **원본 게임은 실행하지 않았다**(기존 녹화·분석 문서와 팬게임만 사용).

고친 문제 두 가지:

1. 이미 템플이 있는데 사제 우클릭 → Construct 메뉴의 **Temple 줄이 활성**이었다.
2. 멀리 떨어진 자리에 워크샵을 설치해도 사제가 걷지 않았는데 **명령 즉시 건설이 시작**됐다.

## 1. 원본·팬게임에서 확인한 동작

| 항목 | 원본 자동 분석 ([auto-war-begins-20261003.md](../videos/auto-war-begins-20261003.md) 4.5절) | 웹 팬게임 | 클론 구현 |
|---|---|---|---|
| Temple 줄 | 1-1에서 `Temple >`가 **어둡게** 표시 (이미 템플이 있음) | 줄 `enabled = 사제 유효 && 플레이어에 vortex 없음`(`ql`) | `BattleSession.GetBuildingRestriction` → `TempleExists`일 때 줄 비활성 |
| 다른 원소 워크샵 줄 | Sun Workshop만 활성, Wind·Rain·Thunder는 어둡게 (1-1은 Rain 발전기 지식을 가졌지만 Rain Workshop도 어두웠다) | `fo`: 같은 원소(theme) 지식 중 **발전기(`classFlags & 2048`)가 아닌 것**이 하나라도 있어야 | `NoKnowledge`: 같은 원소의 비발전기 지식이 있어야 (**메뉴에만** 적용) |
| 알타 | `Build Level 1 Altar for 500` 활성(알타가 없을 때) | `wr`: 플레이어에 dais 없음일 때만 | `AltarExists`: 건설 중 포함 1기 (**팬게임 규칙, 원본 직접 확인은 없음**) |
| 비용 차감 | 설치 클릭에서 SP가 줄고(2600 → 1800) 공사장 그림자가 나타남 | `Ro`→`uy`: 명령 수락 때 차감 | 설치 명령에서 즉시 차감 (원본 `00442c80`→`00442b50` 정적 분석과 일치) |
| 공사장 | **공사장 그림자**(어두운 실루엣+나무 윤곽) → 사제 도착 후 건물이 바닥부터 차오름 | 건물 엔티티를 `startTime=null`로 만들고 사제가 이동 | `GameEntity.AwaitingBuilder` 공사장, 화면은 어두운 반투명 실루엣 |
| 사제 이동 | 사제가 **직접 걸어가** 도착(설치 후 약 7초에 보이기 시작, 약 158~159초 도착) | `Fo`: 사제 경로 계산(`builderCannotReach`면 거부), `Ba`: 이동 | 수집·이동과 같은 `speed` 이동(`UnitMovePurpose.ConstructBuilding`), 길 없으면 `NoRoute` |
| 건설 시간 | 도착 뒤 약 10~11초(설치 클릭~완성 약 23초 중 걷기 제외) | 도착 시 `Lo`: `vv = 10,000ms` 모든 건물 공통 | `ConstructionTimes.BuildingSeconds = 10` (.type `constructionRate` 템플·워크샵·아웃포스트 모두 10) |
| 도착 전 중단 | 미확인 | 사제의 모든 새 명령(이동·정지·수확·희생·새 건설)이 `Io`로 **도착 전 공사장을 환불하고 제거** | 같음 (`UpdatePendingConstructions`, 환불 전액) |
| 건설 시작 뒤 | 미확인 | `Io`는 시작 전 공사장만 취소 → 사제가 떠나도 건설 계속 | 같음 (건설은 사제와 무관하게 완공) |

## 2. 클론 동작 (코드: `BattleSession.Construction.cs`)

* `ConstructBuildingCommand(Player, TypeName, X, Y, BuilderId = 0)`: `BuilderId`가 0이면 첫 자유 사제. 우클릭 메뉴는 메뉴를 연 사제를 넘긴다.
* 판정 `CheckBuilding(player, type, x, y, builderId)`: 기술 허용 표 → 위치(템플·알타 1기 포함) → 자리 → SP → 에너지 → **사제가 둘레 칸까지 걸어갈 수 있는지**(섬·내 다리). 사제 도달 판정은 같은 자리·같은 다리 상태에서 한 번만 계산한다(미리보기가 매 프레임 길 탐색을 되풀이하지 않게).
* 실행: 사제가 이미 현장 옆이면 곧바로 건설 시작(`BuildingStarted`), 아니면 공사장을 놓고 `ConstructionOrdered` 이벤트 → 사제가 걸어가 도착하면 `BuildingStarted` → 10초 뒤 `BuildingCompleted`. 걷는 도중 건설 지시를 받으면 진행 중인 걸음을 이어 받는다(화면에서 뒤로 튀지 않음).
* 취소: 도착 전 공사장은 맡은 사제가 더 이상 그 공사장으로 걷는 중이 아니면(다른 이동·정지·수확·희생 명령, 기절·포획·사망) 매 틱 점검에서 `ConstructionCancelled`와 함께 **비용 전액 환불**·자리 해제·제거된다. 파괴·회수가 아니므로 주변 다리는 약해지지 않는다. 같은 사제의 새 건설 지시도 앞선 공사장을 취소한다.
* 생산 규칙을 끈 개발용 세션(`EnforceProductionRules = false`, 맵 뷰어 배치 시험 모드)은 사제 없이 곧바로 짓는다.
* 캠페인 AI도 같은 경로를 쓴다: AI 사제가 현장까지 걸어가야 건설이 시작된다.
* 검사합: `AwaitingBuilder`·`BuilderId`가 오브젝트 상태에 들어간다.

화면(`FortMapViewer`): 사제 우클릭 → `Construct >` 하위 창에서 `Temple >`(템플이 있거나 건설 중이면)와 기술·지식이 없거나 SP가 모자란 건물 줄이 어두워지고 눌러도 열리지 않는다. 고른 건물은 그 사제가 짓는다. 설치 위치가 사제가 갈 수 없는 곳이면 미리보기가 붉게 표시된다. 사제를 기다리는 공사장은 어두운 반투명 실루엣(진행 막대 없음), 사제가 도착하면 반투명 건물+진행 막대, 건설 중 소리(`jimbuild.wav`)는 도착 뒤에만 낸다.

## 3. 확인하지 못한 것 / 가정 (후속)

* 어두운 실루엣은 원본의 "공사장 그림자(어두운 실루엣+흩어진 나무 윤곽)"와 **정확히 같은 그림이 아니다**. 건물이 **바닥부터 차오르는** 연출, 도착 때의 소리·사제 동작은 구현하지 않았다.
* 건설 시간 10초는 워크샵 관찰(10~11초)과 `constructionRate = 10`, 팬게임 값의 일치로 정했다. 템플·알타를 가까운 자리에서 직접 재지는 못했다(이전 16초·14.5초는 걷기가 섞인 값으로 해석했다).
* 건설이 시작된 뒤 사제를 다른 곳으로 보내면 건설이 계속되는지는 원본에서 확인하지 못했다(팬게임 가정). 도착 전에 사제에게 새 명령을 내리면 환불·취소되는 것도 팬게임 기준이다.
* 알타 1기 제한과, 어두운 줄이 되는 정확한 조건(SP 부족 포함 여부)은 팬게임 기준이다. 원본에서 확인한 것은 "템플이 있으면 Temple 줄 어두움"과 "지식 없는 원소의 워크샵 줄 어두움"이다.
* 사제가 건설 중인 건물이나 다른 유닛을 가로질러 걷는 것(충돌 없음)은 기존 이동 구현의 한계를 그대로 따른다.
* 이동 중인 사제의 경로 선택(대각선 우선)·걷는 속도(`speed` 1.8칸/초)는 기존 이동 분석을 그대로 쓴다([movement-pathing.md](movement-pathing.md)).

## 4. 검증

* 단위 테스트 `tests/Netstorm.Core.Tests/ConstructionTests.cs`: 먼 자리는 비용이 즉시 나가도 도착 전엔 시작 안 함·도착 틱에 시작·10초 뒤 완공, 현장 옆이면 즉시 시작, 이동·정지 명령 시 환불 취소, 시작된 건설은 사제가 떠나도 완공, 같은 사제의 새 지시가 앞선 공사장 교체, 대기 중인 템플도 "이미 있음"으로 계산, 알타 1기, 기술·지식 제한, 길 없는 섬 거부, 사제 없음·개발용 세션, 검사합.
* UI 스모크 `tools/clone_construct_smoke.ps1`(원본 실행·OS 입력 없음): 1-1에서 `Temple >`가 눌러도 열리지 않고 Rain·Wind·Thunder Workshop 줄이 눌러도 선택되지 않음, 사제에서 약 23칸 떨어진 자리에 워크샵을 설치하면 SP가 800 줄고 `sites=sunfactory:waiting` → 사제가 걸어가(`:moving`) 도착 후 건설되어 `workshops=sunfactory:1`로 완공. 화면 PNG는 Git 제외 `extracted/screens/construct-smoke-20261004/`.
