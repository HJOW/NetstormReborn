# 제단 우클릭 메뉴 연결과 건설 e2e 안정화 (WB04-E1137)

LEFT_JOBS 의 "제단 업그레이드 실사용 확인"을 실제 미션에서 해 보다가, 완성된 제단을 우클릭해도 메뉴가 열리지 않는 결함을 찾아 고쳤다.

## 증상

- The War Begins! 에서 사제로 제단(`Build Level 1 Altar for 500`)을 짓고, 완성된 제단을 오른쪽 클릭해도 아무 메뉴가 열리지 않았다(화면에서 맨 앞에 잡히는 것은 제단 받침 `dais`).
- `openObject` 를 직접 불러 보니 받침(`dais`)은 `사제 메뉴 제단 조회 미연결` 예외를 던졌고, 제단 본체(`altar`)는 정상으로 열렸다.

## 원인

- 원본 공통 열기(+ac 004adb30)는 `flags2 & 0x400000` 인 객체(제단 받침)를 열 때 같은 좌표의 제단(`447930`)을 찾아 그 제단의 가상 열기로 위임한다. 웹 `netstorm.js` 의 객체 메뉴 연결은 이 두 훅(`altar`·`delegate`)을 "미연결" 예외를 던지는 자리 표시자로 두었다.
- 제단과 받침 모두 객체 메뉴 작성 주소는 Damageable(`44cbd0`)이고 열기는 공통 열기라 본체 메뉴는 이미 동작했다.

## 수정

| 위치 | 내용 |
| --- | --- |
| `www/netstorm.js` | `open.altar` 를 실제 월드 조회로 연결한다(받침의 좌표에서 `world.find(x, y, 제단 TYPE)`). |
| `www/ui/client-object-menu-open.js` | 제단 위임은 받침과 같은 열기 몸체를 제단에 다시 부른다(제단의 열기가 공통 열기일 때만, 아니면 임의 메뉴로 바꾸지 않고 거부). `delegate` 장치는 더 이상 필수가 아니다. |

- 이제 제단 받침을 우클릭하면 `Altar Level I`(소유자·성향·분류), `Salvage gains 125`, `About`, `Player ›` 메뉴가 열린다.

## 시험

- `e2e/mission-build-placement.spec.js` 의 제단 시험: 제단 완성 뒤 받침을 실제로 우클릭해 제단 객체의 메뉴가 열리는지 본다. 미연결 상태로 되돌리면 시간 초과로 실패한다.
- 같은 spec 의 미리보기 위치 확인을 안정화했다. 눈 지형에는 순백(255,255,255) 픽셀이 흩어져 있어 전체 흰 픽셀의 바깥 범위로 상자를 찾으면 제단 시험이 가끔 실패했다. 이제 가로 80픽셀·세로 50픽셀 넘게 이어진 선만 상자로 보고, 미리보기가 쓰는 화면 원점이 살아 있는 카메라 픽셀 원점과 같은지(E1135 원인)를 직접 비교한다.
- `tests/client-object-menu-open.test.mjs` 등 netstorm.js·객체 메뉴 관련 Node 시험 317건이 통과한다.

## 남은 것

- 제단 업그레이드(`Upgrade Altar to Level %d`)와 `Get 5,000 Storm Power` 행은 원본에서 HTML 기술 목록(`TechnologyListMenu::AppendAll`, 004cb690)의 끝에 붙는 행이다. 웹은 이 목록(원소별 기술·전체 기술 창)을 아직 앱에 연결하지 않았다. 제단 메뉴 본체에는 해당 행이 없다(원본 제단·받침의 작성 주소가 Damageable 이기 때문).
