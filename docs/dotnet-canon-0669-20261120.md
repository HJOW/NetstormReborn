# 0.669 플레어 생성·정기 수명 본체

- 근거: `cpppj/src/o/RawFlare.cpp/.h`, `cpppj/tests/FlareTests.cpp`, 불변 원본 관측 `flare-x86.tsv` 139행·`bomb-status-flare-x86.tsv` 60행.
- 범위: 업그레이드 효과 연결에 필요한 플레어 본체의 L1 이식. 실제 세션 장치와 건설 진행 연결은 다음 단위다.

## 구현

`RawFlare`는 같은 PATCH 풀·TYPE·프레임·난수를 사용한다. 생성 억제·로딩 관문, 현재 Kernel 개수와 30000 경계, 매 생성의 현재 부모 좌표와 SHP 기준점, genus에 따른 분포, float 저장·좌표 제한, 깊이 감김과 소유자, 예약 성공 때만 추가 난수를 소비하는 순서를 보존했다. 기준점은 SHP 추가 헤더의 signed 값이며 이미지 폭/높이가 아니다.

정기는 signed 사건·개수, 첫 단계의 주기 난수, 마지막 직전 후속 생성과 반올림/절삭, 최종 표시 갱신→삭제, 방향별 프레임과 B구간 `powerup.wav`를 실행한다. Native의 후속 단계는 원문에 없는 가상표·억제 시각·난수 조회를 요구하지 않는다. 실제 소유자·Pop·프로세스 예약·표시·삭제·음향은 명시 장치로 받아 아직 세션에 연결하지 않았다.

## 검증

- Release 집중 **5/5건 통과·실패0**, 종료0: `extracted/dotnet-0669/flare-final.trx`.
- 원본139행과 방향60행을 typed/Native 각각에서 실행한 **398회**의 반환 float 비트·난수 상태·부모/후보11개 전체550바이트·모든 호출 순서와 인자가 일치했다. 별도 후속 단계 검사1건도 통과했다.
- 초기 `flare.trx`는 검사 입력의 보존 패턴을 쓰면서 free 비트 뒤 할당 검사를 다시 실행한 하네스 오류다. `flare-recheck.trx`의 남은 불일치는 Kernel 개수 -1의 signed 기록을 unsigned로 출력한 하네스 오류다. 입력 쓰기/기록을 원본 실행기와 맞췄고 제품 본체 변경 없이 최종 통과했다. 최초 결과도 보존했다.
- 연결 fixture 332개 동기화와 포트 맵 등록을 확인했다. 원본 fixture 내용은 변경하지 않았다. 실제 게임·사제 포획/희생·특정 적 공격·승리 재현은 수행하지 않았다.
