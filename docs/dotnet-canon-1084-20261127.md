# dotnetpj 1.084 — 공통 저장소 미니맵 변경 알림

2026-11-27, HJOW-Athlon. `RawMinimapControls.BindStorageExecutors`가 같은
장기 `RawSurfaceStorage`의 Pop/Unpop에 기존 미니맵 큐를 연결한다. 미션
시작은 이 대여를 실제 미니맵 부착 전에 설치하며 시작 실패 시 이번에
설치한 대여만 반납한다. 호스트 정상 종료 반납은 1.083을 사용한다.
세션 전용 지형·Player Pop/Unpop은 다른 인스턴스이므로 이 변경의 완료
범위에 넣지 않는다.

- 새 집중 검사는 실제 저장소 Pop/Unpop의 등록·제거가 큐에 도달하고
  반납 뒤 등록은 도달하지 않으며 중복 대여를 거부함을 확인했다(1/1).
  최초에는 표시 View 미설치로 실패했고, View를 갖춘 뒤에도 일반 타입
  `Flags2=0x4000`은 원문 알림 대상이 아니라 큐가 비어 실패했다. 실제
  알림 조건 `(Flags2 & 6) != 0`의 `0x4002`와 크기 있는 프레임·발자국을
  갖춘 입력으로 교정한 뒤 통과했다.
- 대표 세 미션의 CPP/DN 실제 실행 모두 종료 0이며 DN 90프레임 덤프는
  0998과 각각 바이트 일치다. 비교 도구는 기존 CPP/DN 차이로 종료 1이다.
  `extracted/dotnet-l2-1084-storage/`의 원본 1,392파일은 전후 불변이다.
- `cpp_sync.py` 종료 0. 정기 전체 회귀(`--no-build --no-restore`): Assets 383·Core 4,113·Client 2,890, 합계 7,386 통과·실패 0. 콘솔은 Windows 음향 장치 검사 한 건에 건너뜀 메시지를 출력했으나 Client 집계는 건너뜀 0으로 표시했다. 실제 하드웨어 음향 검증 성공으로 세지 않는다. 이 실행은 빌드된 어셈블리를 사용했다.

다음은 세션 전용 실행기의 실제 사용과 교체·실패·정리 수명 및 미니맵
픽셀 차이를 검증하는 것이다. 현재 제품에서 등록/삭제를 직접 수행하는
실행 검사는 하지 않았으며 단위 실행 결과와 구별한다.
