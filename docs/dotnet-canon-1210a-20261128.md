# 1.210a 표준 출력 복제 검사의 프로세스 격리

1.210의 실패는 선행 HostErrorLog.Setup이 프로세스1회 캡처 표식을 남긴 뒤 검사가 Console.Out만 교체해서 발생했다. 같은 동결 검사 DLL의 직접 순서 재현과 과거 TRX 순서는 [첫 실패 기록](dotnet-canon-1210-20261128.md)에 보존했다. 제품 ErrorLog·HostErrorLog의 캡처/Reset 정책은 변경하지 않았다.

`ErrorLogTests.StandardStreamsTeeToBuffer`는 전용 환경 표식이 있는 새 자식에서 기존 복제·중복 설치 방지·원래 출력/메모리 검사를 수행한다. 부모는 같은 xUnit v3 검사 DLL의 정확한 단일 메서드를 dotnet으로 실행하고, 종료0뿐 아니라 실제 본문 완료 표식도 확인한다. 두 파이프를 동시에 비동기로 읽으며 검사 취소/60초 제한과 실패 시 자기 자식의 종료·짧은 합류를 적용했다. 보이는 콘솔 창을 만들지 않는다. 검사 간 순서나 private 캡처 표식 변경에 의존하지 않는다.

실제 수정은 검사1파일뿐이다. Release 검사 프로젝트 빌드는 종료0·오류0·기존 경고13,4분30.99초다(`extracted/dotnet-1210a-build.log`). 빌드 종료를 확인한 뒤 실행한 로그/호스트 로그 집중 검사는 **11/11통과·실패0·종료0**,2초다(`extracted/dotnet-1210a-tests/logs-final.trx`·`extracted/dotnet-1210a-tests-final.log`). 자식 결과는 부모의 해당 한 검사로만 집계한다.

빌드 도중 먼저 시작했던 검사는 이전 DLL의10통과·1실패였으며 `logs.trx`·`dotnet-1210a-tests.log`로 보존하고 교정 검증에서 제외했다. 위 최종 집중 결과로 구분한다. 제품 소스는 같아도 이번 빌드의 AssemblyInformationalVersion에는 새 Git 커밋 `f2db70e80…`가 들어가 관리 DLL SHA는 앞 단위와 달라질 수 있다. 변경되지 않은 Core/Assets 코드의1.210 결과를 재실행으로 표시하지 않는다.

첫 전체 회귀 실패의 종결은 아직 아니다. 다음1.211 장기 음향 owner 조립·집중/실제 경계 확인 뒤1.212에서 Client 전체를 다시 검사한다. SceneMusic·옵션 UI·State 왕복과 미니맵 잔여 차이는 미완료로 유지한다.
