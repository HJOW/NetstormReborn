# 0.727 장기 ProcessHost 현재 Runtime과 정리 증빙의 약한 소유

원문 RawProcessHostStorage.cpp/.h의 current_.lock/expired와 ClearPass weak_ptr를 대조했다. C# 저장소의 현재 슬롯과 정상 Clear 증빙을 WeakReference로 바꿨다. Use와 실제 호출의 RuntimeCallGuard snapshot은 기존 강한 대여를 유지한다. Host/legacy 회수/중복 Bind/반납은 각 사용 위치에서 살아 있는 같은 Runtime을 잠그며, 장기 저장소나 남은 증빙 자체가 짧은 Runtime을 역소유하지 않는다.

장치 결합도 원문 순서를 보존했다. 같은 Kernel/Frame/pollType 주소의 재확인은 현재 대여 중에도 먼저 반환하며 값이나 시각 상자를 교체하지 않는다. 그 이후의 실제 교체/최초 설치 가지에서 현재 Runtime 또는 살아 있는 legacy 회수 대여를 거부한다. 특히 외부 Kernel이 아직 없는 상태에서 legacy 대여 뒤 첫 BindDevices가 허용되던 경계를 고쳤다. 같은 장치 재확인을 잘못 거부하도록 바꾸지 않았다.

최초 Core85건 중 기존81건은 통과했고 새4건은 검사 입력으로 만든64슬롯 풀이 허용 크기보다 작아 준비 단계에서 실패했다. 게임의 실제 PoolCapacity를 사용하도록 입력을 고쳐 새4건이 모두 통과했다. 제품 코드는 이 입력 교정 때 바꾸지 않았으며 Client125건도 통과했다. 중복을 제외한 이번 집중 검증은 Core85/Client125 합계210건이다. 근거는 extracted/dotnet-0727/core-initial.log·core-weak-process-storage.trx, core-fixed.log·core-weak-process-storage-fixed.trx, client-initial.log·client-weak-process-storage.trx다.

새 검사는 별도 NoInlining 호출 프레임을 사용해 관측용 지역 참조가 Runtime을 숨겨 보유하지 않도록 했다. Use/snapshot이 끝나고 저장소만 남을 때 Runtime을 GC할 수 있고 같은 Host를 다음 대여에 재사용함을 확인했다. 정상 Clear 증빙만 남아도 이전 Runtime을 GC할 수 있다. 같은 장치 재확인은 현재 시각 상자/값/Runtime을 보존하고 다른 Frame은 거부한다. 살아 있는 legacy 회수 대여 중 최초 외부 장치 설치도 거부한다. 이 검증은 전체 Native World/공장 장치의 모든 역참조 정리가 완료됐다는 판정이 아니다.
