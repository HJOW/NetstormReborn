# WB04-E1472 모드 명령의 실제 Client 호스트

`mod-input.js`가 격리 실행기 출력의 사건/명령 번호·미션·허용 이름·필드·보조 키·개수/로그를 호스트에서 다시 검증한다. 모든 요청 형식을 먼저 검사하고, 정상 요청은 다음 원래 입력 단계에서 기존 InputQueue.tryPushBatch로 누름/뗌을 함께 추가한다. 선행 사람 입력 FIFO와39칸 용량을 유지하고, 포화/세션 이탈·교체/화면 크기 변경/모달·정지는 결과 코드로 거절한다. 실패한 클릭은 포인터를 옮기지 않는다.

`ModGameHost`는 현재 Ready World/Guide/GameClock/Layout·Player 참여 flags/방향별 동맹·SP·선택 자산의 TYPE/소유자/HP만 사본으로 읽는다. 초기화 안 된 SP는 읽어서 초기화하지 않고 미션 준비를 기다린다. 원래 모드 seed만 복사하고 게임 RNG를 소비하지 않는다. 월드 정체성은 WeakRef로만 기억하며 앱 반납 시 신뢰 호스트도 dispose한다. 실제 주 루프의 사건/비동기 장벽과 관리/격리 실행기는 다음 단위다. 이 클래스를 모드에 공개하지 않는다.

집중 검사는 신규 호스트9건+E1471 API20건+기존 원자 큐2건=31/31·실패/취소/건너뜀0이다. 위조된 뒤 명령/로그가 앞 명령을 반영시키지 않음, 실제 고리 감김과 포화/모달/세션 교체, 크기 변경을 포함한다.

Chromium 실제1-1에서 아군AI를 활성화하고 브리핑 거부, 조회 전후 전체 풀/RNG/프레임 불변, 원래 큐2사건 수용, 다음 원래 프레임의 사제 선택과 원래 사제 조회 일치, 공개 선택 필드3개/게임 오류0을 확인했다. 첫 실행은 테스트가 사제 TYPE을163으로 잘못 가정해 실제158과 달라 실패했으며 trace/스크린샷을 ignored extracted/e1472-first-run에 보존했다. 고정 번호 추정을 제거하고 같은 Session의 원래 사제 조회/타입에 대조한 수정본은1/1 통과(35.8초)했다. 승리/포획/희생/특정 적 공격은 검사하지 않았다.
