# WB04-E1483 모드 관리 화면과 설치·실행 저장 경계

공통 v0.1.0 명세의 모드 패키지를 webpj에서 설치하고 다음 미션에 사용할 수 있도록 Options의 모드 관리를 추가한다. 공통 명세/패키지/검증/격리/사건의 선행 구현은 E1470~E1482이며 이 단위는 관리 화면과 설치 변경의 저장 경계를 다룬다. DN에는 공통 규칙과 MOD-5 인계만 반영하고 구현·빌드·실행은 하지 않는다.

## 사용 방법

1. 메인 메뉴의 **Options → Mods**(한국어: **옵션 → 모드 관리**)를 연다. 미션 중에도 우측 상단 메뉴 버튼이나 ESC로 여는 **Options → Mods**에서 같은 화면을 연다.
2. **모드 가져오기…**로 UTF-8 `.nsmod.json` 파일을 선택한다. 공통 형식의 최대 1 MiB 패키지만 받으며 설치할 때 코드를 실행하지 않는다. 새로 설치한 모드는 꺼져 있다.
3. 목록의 **사용**을 켜고 화면을 닫은 뒤 새 미션을 시작한다. 켜기/끄기·교체·삭제는 다음 미션에 적용한다. 현재 미션에서 이미 실행 중인 모드는 종료나 자체 오류 전까지 같은 패키지 사본으로 계속한다.
4. 같은 id를 가져오면 새 이름·id·버전을 확인한 뒤 **이 모드로 교체** 또는 **교체 취소**를 선택한다. 교체한 패키지도 꺼진 상태로 저장한다. **삭제**는 설치 목록에서 제거한다.
5. 다른 탭이 목록을 바꿨다면 **목록 다시 읽기**를 눌러 현재 저장값을 다시 읽는다. 저장 공간 부족/읽기 실패/손상된 자료가 있으면 원래 저장값을 보존하고 오류를 표시한다.

**Reset All** 확인 창에는 설치 모드도 삭제한다는 안내가 나온다. 취소하면 모드를 유지하며 확정하면 설정·진행·설치 모드를 지우고 게임을 다시 로딩한다. 다른 앱의 저장 키는 보존한다.

공통 [예제 패키지](../shared/modding/v0/examples/session-observer.nsmod.json)와 [API 명세](netstorm-common-mod-api-v0-20261128.md)를 사용한다. 원래 게임의 고정 시각/오라클 검사에서는 모드 실행을 강제로 끈다. 플랫폼별 자원 한도와 격리 보장 차이는 명세 §6을 따른다.

## 구현과 경계

- `ModPanel`은 텍스트 전용 DOM 모달이며 영어/한국어/일본어 문구를 제공한다. 한국어는 별도 배포한 갈무리11을 정수 크기 12px/24px로 사용한다. 이름/설명/오류를 HTML로 해석하지 않는다.
- 파일 검증은 격리 검증기를 사용하고 저장소에서 재검증한다. 기본 꺼짐·명시 교체·직렬 쓰기·다른 탭 원문 대조·실패 시 이전 캐시 보존은 `ModStore`가 맡는다.
- 모드 오류의 자동 꺼짐도 직렬 쓰기 안에서 실행 때의 정규화 패키지 원문과 비교한다. 이미 다른 패키지로 교체했거나 삭제한 경우 옛 오류로 새 설치를 바꾸지 않는다. 현재 VM은 저장 결과와 관계없이 먼저 중단한다.
- 관리 화면은 원래 게임 시계의 정지 한 단계만 빌려 닫기/World 반납/앱 종료 때 돌려준다. Native 모달 SID를 만들거나 입력 큐를 비우지 않고 기존 입력을 보류한다. Tab/Shift-Tab은 화면 내부를 순환하고 ESC로 닫는다. 늦은 파일 검증 결과는 닫힌 화면을 다시 만들지 않는다.
- 일반 웹 미션 메뉴의 Tell 명령을 사용하며 원본 비교/고정 오라클 메뉴에는 추가 행을 제공하지 않는다. 새 모듈은 WEB_ONLY 분류에 등록했다. webpack은 기존 ESLint 선행 관문을 따른다.

[결과 원문·현재 작성 입력·이전 실패의 경로/크기/SHA-256](webpj-e1483-evidence/provenance.json)과 [직접 확인한 한국어 화면](webpj-e1483-evidence/korean-mod-panel.png)을 보존한다. 중간 실행들을 같은 최종 번들의 실행으로 합쳐 세지 않는다.

저장 경계 보완 전 새 검사 3실패(30/33), 새 메뉴 import 누락의 ESLint 빌드 거부, 새 검사 초기 전역 누락(109/110), 실제 미션 메뉴 행 전달 누락(2/3)을 보존했다. import/검사 장면/ClientGameMenuBar 전달을 교정하고 각각 새 검사로 확인했다. 기존 오류 검사의 패키지 원문 비교와 Reset All의 삭제 대상 단언을 강화했으며 기존 단언을 약화하거나 원본 fixture·시간 한도를 바꾸지 않았다. E1480의 별도 동시 Worker 시간 초과 원인 해결을 주장하지 않는다.

이번 단위에서 Node 새7건을 추가했으나 전체를 다시 수행한 것은 아니다. 최신 Node26 전체는 UI 수정 전 E1482의7,023/7,023이며 정기 주기는v26=1/4·v22=6/8이다. 실제 플레이는 아군AI1-1의 짧은 상태/입력/반납만 사용했고 새 승리 검사를 추가하지 않았다. DN 구현/양쪽 적합성·사용자 이월 목표/승리·사람 언어 검수·물리 표시/청취는 미완료로 유지한다.
