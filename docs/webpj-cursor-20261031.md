## 3. 동작

- **링크 글자 위 → 손(16).** 본문이 스크롤돼 있어도 링크가 우선한다(링크이면서 스크롤 가능하면 16).
- **넘치는 본문의 링크가 아닌 곳 → 상하 화살표(15).** 글자 위뿐 아니라 글자 줄 오른쪽 빈 곳도 본문 안이면 15 다.
- **본문이 한 화면에 들어가면 → 기본(1).** 도움말 창은 스크롤바가 항상 달리지만 쪽 크기가 범위와 같으면(스크롤할 내용 없음) 15 가 아니다. 도움말 128개 주제 중 55개가 넘치고 73개는 들어간다. Tell 창은 스크롤바가 없으면(대부분의 섹션) 링크 위 16 과 그 밖 1 뿐이다.
- **스크롤바(화살표·홈·손잡이) 위, 본문 밖(패널 가장자리·돌 버튼·Back/OK·창 밖) → 기본(1).**
- **포인터를 움직이지 않아도** 스크롤·키 입력·창 닫힘으로 아래 내용이 바뀌면 다음 프레임에 커서가 바뀐다. 예: 링크를 눌러 창이 닫히면 포인터가 그 자리에 있어도 기본 화살표로 돌아온다.
- 화면 배율에 맞춰 커서 그림을 정수 배율로 키운다(기존 규칙). 화면을 키우면 이전 배율의 캐시를 버리고 새로 만든다.

## 4. 원본과 다르게 둔 점·가정

- **도움말 창과 Tell 창의 Overlay 대상:** cpppj 의 `GumpInput::Overlay` 는 overlay 로 등록된 위젯만 훑는다. 본문 말고 다른 위젯(돌 버튼 등)이 overlay 인지는 cpppj 소스에서 확인하지 못해, 본문이 받지 못하는 모든 곳을 기본 화살표로 두었다(원본의 fallback 과 같은 결과이거나 다른 위젯이 자기 모양을 정하는 경우만 다를 수 있다). 돌 버튼 위 커서는 메인 메뉴에서 이미 기본 화살표로 확인된 동작과 같다.
- **끌기 중:** 본문 글자를 누른 채 끄는 중에도 같은 규칙을 포인터 위치마다 적용한다(본문 밖으로 끌어내면 기본 화살표). 원본이 캡처 중에 Overlay 를 어떻게 하는지는 cpppj 에서 확인하지 못했다(`NotifyPointer` 는 캡처 여부를 보지 않고 모달이 열려 있으면 항상 실행한다는 점만 근거).
- **웹에서 CSS 커서로 구현:** 원본은 윈도우 커서를 바꾸지만 웹은 Canvas 의 `cursor` 스타일에 데이터 URL 그림을 넣는다(기존 기본 커서 방식 그대로). 브라우저가 거부하면 기존처럼 기본 커서를 쓴다.
