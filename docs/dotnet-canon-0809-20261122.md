# dotnetpj 0.809 — 섬 정리 선행 파편의 본체와 공통 수명

2026-11-22 · HJOW-Athlon · 제품11.01 · 새 `Netstorm.Game` 경로를 유지했다. 전체 목표와 M1은 미완료다.

## 구현

35h 섬 정리의 실제 선행인 `RawShrapnelFrame`·`RawShrapnelLifetime`·`ShrapnelVisualSystem`을 이식했다. 폭발·붕괴·셋째 Variant2의 생성, 중력과 수명, 원본 캡처 색의 픽셀 출력, 실제 process16/더미110/상호 감시 쌍과 공통 표시 목록의 수명을 포함한다. 생성 중에는 pending이 소유하고 실제 부착 뒤에는 같은 Host/Kernel이 소유한다.

float 저장 위치와 넓은 중간 계산, 게임 난수와 별도 CRT 난수의 호출 순서, 매 반복 조건에서 다시 뽑는 묶음 크기, 역순 난수 끝점, 전체 용량과 사용 꼬리의 차이를 보존했다. 프레임 간격을 임의로 제한하지 않으며, 진입 양수 수명이 없는 다음 프레임에 실제 Form을 삭제한다. 캡처 원본은 유지하고 작업 복사본만 선택 표시로 바꾼다.

수명은 부모0의 공통 목록 등록→더미 생성→현재 원천 좌표 Pop→수동 부착→감시 쌍→현재 캡처/준비→원천 깊이 재조회 순서다. 소멸은 bitmap→입자→목록/base→선택 객체 순서이며, 쌍 구성 전 실패한 더미만 별도로 삭제한다. 원본의 해제 후 dangling 포인터/용량 대신 실제 관리 배열을 반납하는 표현 차이는 수명 대조에서 두 저장소 필드만 구별했다.

`RawFieryTailFrame.h`의 공통 `FieryTailFrameState`/dirty 데이터 형식도 추가했다. **FieryTail 실행 본체를 이식한 것으로 집계하지 않는다.** 실제 캠페인 Host/Game 장치의 파편 설치와35h 수신은 다음 단위다. 현재 고정 수신은 **17/26**, 나머지35/38/39/3a/3b/3c/73/74/86의9본문을 유지한다.

## 검증

- 기존 독립 PE 자료의 **생성198·Frame/Draw782·수명216, 합계1,196입력**을 전수 대조했다. 전체76/92BYTE 의미 상태·전체24BYTE 입자 용량·게임/CRT 최종 상태·요청 순서·실제 clip/pitch/padding을 포함한 픽셀·캡처 원본 보존·목록·삭제 순서가 일치했다. 기대값을 C# 결과로 생성하거나 변경하지 않았다.
- 신규 **14건**은 원문 소비자3건과 실제 Host/Kernel/감시 쌍 검사11건이다. 세 생성기 모두 원천 삭제 후 소진하며 더미/감시 Form을 반납한다. 투명 최소 용량1, wrapper104 실패, Pop 전/쌍 구성 후 캡처 실패, 입자/작업 그림 확보 실패, 생성 중 재진입, 현재 배율 불일치를 확인했다.
- 마지막 집중 회귀는 위 신규14건을 포함해 **Core98건 통과·실패0·미실행0**이다. 공통 표시·건설·Host 부착 소유권·자료 등록 검사를 함께 실행했다. 기존 검사 이름이나 본체를 변경하지 않았다.
- Release 솔루션 전체 빌드는 오류0, 이번 증분 빌드의 기존 Client 검사 경고3개다. 최초 검사 작성 중 누락된 using과 uint 단언의 컴파일 오류를 교정했으며, 최종 제품/검사에는 신규 경고가 없다.
- 같은 새 Game 실행본으로 `thewarbegins`·`tutorial1`·`surrounded`의 대표3시작이 모두 종료0이었다. 세 경로의 전체 덤프 바이트와 지표는0.808과 같았다. 검사에서 사용한 DLL과 실행본의 DLL이 같고 실행6파일의 전후 해시가 같다.
- 보호 원본 **1,392파일**의 이름/전체 해시가 전후 및0.808과 같다. Source7파일·AGENTS.md·README.md 전체도0.808과 같다. 원본 게임 실행이나 포획/희생·특정 적 공격·승리 GUI 재현은 수행하지 않았다.

정기 전체는0.808의 **5,744통과/실패0**, 다음은0.812다. 이번98건을 전체 회귀 결과로 바꾸어 쓰지 않는다. M1은 마지막 전체 기준 **0/34**이며 월드 표시·입력·규칙과 DN 데모 진입은 미완료다.
