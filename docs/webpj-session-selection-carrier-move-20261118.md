# WB04-E764 실제 선택과 세 운반 유닛 이동

cpppj 기준 `225553df`의 `RawCampaignSession::MakeUserSelection`과 `CampaignSession_CarrierMoveRequestThroughActualLocalTransportAndKernel`을 대조했다. 기준선 뒤 Session 구현 변경은 없으며 해당 시험 밖의 변경 11줄 추가·7줄 삭제만 있다. 웹 Session에 같은 Pool·TYPE·표시 갱신·선택 비트·종속 Process·마나/사거리·내용물 미리보기·현재 Guide demo 및 위치 음향을 빌리는 선택 생성 경로를 연결했다. 이동·낙하·공통 재확인은 현재 살아 있는 선택을 약한 참조로 읽고, 반납 후 오래된 Session을 다시 사용하지 않는다.

TheWarBegins 실제 로그인 후 사제(TYPE 158), 골렘(TYPE 133), 벌룬(TYPE 111)을 각각 독립 Session에서 선택하고 원본 선택 비트와 현재 상태를 확인했다. 현재 demo 값이 바뀌면 선택 해제를 막는 것도 확인했다. 40h 요청이 선택을 먼저 해제하고 Pump 이후 같은 전송에 도착해 실제 경로를 만드는지, 같은 목적지 재요청이 중복 송신되지 않는지, 같은 Kernel을 실제 시각으로 진행해 자연 도착하는지 검사했다. 도착 전후 SP와 삭제·장부 깊이도 확인했다. 경로 발소리는 원본 `CampaignClientServices`처럼 외부 음향 장치를 시험에서 공급했다. 포획·희생·특정 적 공격·승리와 사용자 제한 공중 세 종류의 전용 행동은 실행하지 않았다.

이는 Session 선택 몸체와 실제 이동의 통합이며 브라우저 GameWorld의 입력·선택 UI 연결은 아직 남는다. MetaMap 설치 전 선택 경로 역시 후속 범위다. 워크샾 자연 완공·생산, 미션 프레임과 앱 수명도 미완료다.

첫 전체 회귀 중 기존 AI·낙하 선택 수명 검사 두 건이 실패해 원인을 확인했다. 기존 소비자가 약한 참조에서 `{ selection }` 링크를 읽는데 이를 직접 선택 참조로 바꾼 것이 원인이었다. 선택이 링크를 소유하고 Session은 링크를 약하게 참조하도록 교정해 기존 계약을 유지했다. 신규 통합과 기존 두 수명 집중 검사 3건이 통과했다. 최종 Node v26.13.0 전체 회귀 6,261건이 통과했고 실패·취소·건너뜀은 0건이다. 대응표 오류는 0건이다. E761의 Node v22 전체 검사 뒤 두 번째 v26 전체 회귀다.
