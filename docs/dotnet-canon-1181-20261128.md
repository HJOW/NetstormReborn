# 1.181 초기 SP 쓰기의 실제 State 정리 호출자

1.180의 별도 CPP 진단 실행본에 실제 `CleanupStateWorld` 진입과 `SetPlayerSpAmount` 호출을 추가 기록했다. 첫 지형 장식 이전 `reason=0` 정리 뒤 `SetPlayerSpAmount(1..8, 0)`과 SP 쓰기 8회가 순서대로 발생했다. 이어 `reason=1` 정리에서 로컬 소유자1은 직접 SP를 쓰고, 소유자2..8은 `SetPlayerSpAmount`를 거쳐 나머지 8회를 썼다. 즉 1.180의 두 8회 묶음은 각각의 실제 State 정리에 대응한다.

진단 실행은 종료0, 40프레임의 전체 픽셀과 전체 슬롯은 같은 CPP 제품 관측과 같았고 원본 1,392파일은 전후 불변이다. 로그·화면·덤프·진단 소스는 `extracted/dotnet-rng-parent-1181/`에 있다. 사제 포획·공격·승리 입력은 없다.

DN에는 `ClientStateWorldCleanup`과 원문 부모가 있으나 현재 `--mission` 직접 진입은 원본과 같은 전체 State 전환을 거치지 않는다. 정리의 다른 전역·커서·템플릿·UI·음향·수명 효과를 생략하고 SP 쓰기나 난수 소비만 추가하면 실제 순서를 복원한 것이 아니므로 그렇게 처리하지 않았다. 두 전환의 실제 선행 상태와 장치를 연결한 뒤 시드·장식·L2/L4a를 재검증해야 한다. 2,245회 중 SP 횟수 차이의 2,240회 외 나머지 5회 원인은 여전히 미확정이다.
