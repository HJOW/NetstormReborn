# dotnetpj 1.002 — R4-7c3a 진단 전체 Client 연결

2026-11-25, HJOW-Athlon. R4-7 F3 보류 검사 중 `TemplateDiagnosticClientTests` 전체 Client 연결이다.
저장소 쪽 덤프 호출은 `CampaignTemplateLoginTests`가 먼저 대조했고, 여기서는 실제 Client의 level 29 필터·
FILE·공유 버퍼·NULL Chat 연결을 `ClientDiagnosticLog`·`ClientTraceGlobals`·`RawTraceLog`로 이었다.
제품 본체 변경은 진단 경로에만 있다.

## 변경과 원문 대응

- `dotnetpj/src/Netstorm.Client/ClientTraceLog.cs`: 신규. `TraceLogState`(수준·Stream·들여쓰기·복제·
  flush·1024문자 버퍼), `TraceLogHooks`(Console·Write·Flush), `RawTraceLog.Write`·`Flush`를 이식했다.
  원문 `RawTraceLog.cpp`의 필터·접두·공백·개행 정리·console→복제→FILE→flush 순서와 버퍼·NUL·범위 검사를
  그대로 둔다. FILE* 대신 `Stream?`(null이면 표준 출력으로 연다)을 쓴다. 근거: cpppj
  `client/RawTraceLog.h`·`.cpp`. 1.002에서 추가됐다.
- `dotnetpj/src/Netstorm.Client/ClientDiagnosticGlobals.cs`: 신규. `ClientTraceGlobals`(Log·Depth·
  Suppress·TraceToChat; 건설 기록·재생은 메뉴·시각 장치와 함께 후속 단위)와 `ClientDiagnosticLog` 진입점
  (`WriteDiagnosticLog`, NULL Chat용 `NullChatHooks`)을 두었다. 근거: cpppj
  `client/ClientDiagnostics.h`의 `ClientTraceGlobals`·`Client::DiagnosticLogHooks`·
  `Client::WriteDiagnosticLog`. 1.002에서 추가됐다.
- `dotnetpj/tests/Netstorm.Client.Tests/TemplateDiagnosticClientTests.cs`: 신규 1건. cpppj
  `tests/TemplateDiagnosticClientTests.cpp`의 `TemplateDiagnosticClient_UsesSameFilterFileBufferAndActualNullChat`을
  옮겼다. level 28 필터(공유 상태·Stream 보존), level 29 두 로그의 같은 FILE 기록, 공유 버퍼의 마지막 줄,
  들여쓰기·flush·TraceToChat 유지, NULL Chat 생략을 대조한다. 1.002에서 추가됐다.

  실패했으나 같은 Client 전체 재실행과 단독 실행에서는 통과한다. 원인은 0.994 선택 수명 장치의
