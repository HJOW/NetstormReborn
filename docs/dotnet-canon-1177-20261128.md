# 1.177 HUD 구분선 질감 프레임 교정

임시 제품 HUD의 세로 및 미니맵 구분선은 프레임0을 사용하고 있었다. `UberRootGump`의 실제 생성 경로는 두 구분선에 원본 `00542664`의 값을 사용하며 정적 초기값은 **1**이다. 두 곳을 프레임1로 바꾸고 채팅 구분선은 원본 배경 프레임0을 유지했다. 원본 값과 C++ 경로 근거는 `docs/exe/cpp-main-menu-texture-20261023.md`, `cpppj/src/client/UberRootGump.cpp`, `RawButtonControls.cpp`다.

Release 빌드는 오류0·기존 경고8, HUD 구분선·도킹·미니맵·생산 덱 관련 집중 검사는 **23/23 통과**, `cpp_sync.py`는 종료0이다. 실제 제품 `thewarbegins`, `tutorial1`, `surrounded`의 진입·대기는 모두 종료0이고 90프레임 DN 덤프는 1.175와 각각 바이트 일치한다. 원본 1,392개 파일은 전후 불변이며 포획·공격·승리 입력은 없다.

1-1의 30·40·45·50·60·70프레임에서 각각 세로 구분선 `(80,0)-(85,688)`과 미니맵 구분선 `(0,688)-(80,693)`은 CPP와 **0픽셀 차이**다. 수정 전 DN 대비 화면에서 각 프레임 3,988픽셀이 바뀌었고, 40프레임 전체 CPP 차이는 **35,202→31,214/786,432픽셀**이다. 30·40·45프레임 미니맵은 0픽셀, 50·60·70은 기존대로 1픽셀 차이다. 같은 프레임의 게임 시각은 여전히 다르며 전체 L4a·실제 전환 수명은 미완료다. 상세 결과·화면·실행 인자는 `extracted/dotnet-hud-divider-1177/`에 있다.
