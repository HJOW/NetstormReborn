# 1.204 정기 전체 회귀와 기존 옵션 결함 노출

1.200~1.203 네 작업 단위 뒤 팀 실제 소스를 동결한 Release 솔루션 빌드를 그대로 검사했다. 오류0·기존 경고25·종료0, 51.82초이며 `extracted/dotnet-1203-build.log`·`extracted/dotnet-1200-artifacts/`다. 이후 문서/대응표 커밋만 진행했고 다음 옵션 수정은 이 검사 DLL에 포함되지 않았다.

Assets **383통과**, Core **4,121통과**, Client **3,039통과·2실패**, 합계 **7,543통과·2실패**다. Client TRX 총계3,042 중 실제 음향 하드웨어1건은 `NotExecuted`이며 실제 장치 재생 성공으로 세지 않는다. 각 종료 코드는0/0/1, 시간은17초/5분27초/7분15초다. 무응답 진단은 중단/덤프를 일으키지 않았다. 결과는 `extracted/dotnet-1204-regression/{Assets,Core,Client}.trx`·`summary.json`, 원시 로그는 `extracted/dotnet-1204-{Assets,Core,Client}.log`다.

실패는 기존 `HostReadOnlyInstallTests.ReadOnlyInstallKeepsOptionsRunningInUserRoot`와 `HostUserOptionsRootTests.UserOverlayWinsOverInstallValues`이며 둘 다 사용자 soundVolume5 저장 뒤 재개에서 설치3을 읽었다. 이번 실행은 `NETSTORM_DATA=extracted/dotnet-oracle-data`를 명시했다. 보호 사본에는 soundVolume3이 이미 있고 기본 배포 자료의 options.cfg는 주석뿐이라 설치 키가 없는 기존 입력에서는 드러나지 않았다. 이 기간에 Startup/OptionsFile/Core Config와 두 실패 검사는 변경되지 않았다.

원인은 기존 HostStartupScene.OverlayUserOptions의 뒤쪽 Append와 원문 Config.Get의 첫 키 조회 조합이다. 데이터 override를 해제해 실패를 숨기지 않는다. 다음1.205에서 Core 원문 파서를 유지한 채 호스트 사용자 덮어읽기를 고치고 명시 설치값/중복/치환/부호화/현재 설치 경로를 검사한다.1.206에서 수정된 Client 전체를 재실행한다. Assets/Core 결과와 최초 실패는 별도로 보존한다.

동기화는 종료0(`extracted/dotnet-1204-sync.log`)이며 PORT_MAP 물리1,925줄/자료1,920행(port1,431·L1 482·session7), fixture519개다. 재집계는 CPP1,244단위170,238줄 중 DN 대응697단위117,304줄·미대응547단위52,934줄이다(`extracted/dotnet-1204-port-inventory.log`·남은 계열 `dotnet-1204-inventory.log`). 부분 이식/대응표 등록 집계이며 플레이 완료율이 아니다.

실제 전체 State GUI 왕복·장치 음악·M1/L4a·미니맵1픽셀은 계속 미완료다. 다음 실제 작업과 준비된 미검증 초안의 반영 순서는 [후속 계획](dotnet-state-followup-plan-1204-20261128.md)을 따른다.
