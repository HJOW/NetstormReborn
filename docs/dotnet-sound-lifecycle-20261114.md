# dotnetpj 0.515 — 소리 이름표·위치 재생과 프로세스 수명

2026-11-14, HJOW-Athlon. cpppj 기준은 `0c24d0181e17933b23f8dbbd4ef84874a26939f2`다. `client/Sound.h/.cpp`, `SoundProcess.h/.cpp` 전체와 `RawCameraView.h/.cpp`의 공통 좌표 투영 함수를 `Netstorm.Client/Audio/`의 다섯 파일로 옮겼다. 원본 게임 파일·디컴파일 소스는 변경하지 않았다. 선행 부품은 [보호막 수명](dotnet-forcefield-lifecycle-20261114.md)과 [사제 낙하](dotnet-priest-fall-20261114.md)다.

## 이름표와 실제 재생 경계

`SoundList`는 원문의 고정0x8000BYTE 공간,0x1cBYTE 머리와 NUL 이름, 정렬 여백 없는 물리 순서를 유지한다. `nonexistant.wav`는 원문의 철자를 보존한다. 이름 조회는 ASCII 대문자만 접고 복제 항목도 같은 순서로 지난다. 새 항목의 Volume 필드를 추가 초기화하지 않으며 복제도 원문이 쓰는 필드만 갱신한다. 이름 포인터는0x1f를 빼는 명시 값 변환이며 호스트 주소를 역참조하지 않는다. 원본BYTE 이름용 span 경계가 있고 문자열 경계는 Latin1이다. 실제 게임의 소리 파일 이름은 ASCII이며 유니코드 문화권 비교를 추가하지 않았다.

`SoundPlayer`는 이름 등록·지연 적재·소리 없음 표식·복제 사슬·동시 재생 상한·일련번호·정지/재계수·음량 보류를 같은 순서로 처리한다. 실제 장치는 여덟 함수로 구성 때 확인하고 함수 객체를 복사한다. HRESULT 실패·원본 진단·기록 문장의 판본별 줄 번호를 보존했다. 재생 수가 현재 장치 상태와 어긋나더라도 임의로 정규화하지 않고 원문의 재계수 호출에 맡긴다.

위치 계산은 축별 double 투영/64비트 절삭 하위DWORD, signed 경계,32비트 곱 감김과 idiv를 따른다. 현재 카메라는 투영→화면 판정→좌우→음량의 네 소비 위치마다 따로 읽는다. 장치의 상태 조회나 재생 콜백이 카메라를 바꾸면 이후 좌우/음량만 새 화면을 읽으며 앞에서 계산한 점을 다시 투영하지 않는다. `RawCameraView` 전체 이식이나 실제 월드 카메라 완성을 뜻하지 않는다.

## 부모에 붙는 실제 소리 수명

`SoundProcess`는 실제 `SquidProcessHost`와 `Kernel`에 현재 역할DWORD/client0x10으로 붙는다. 부모WORD의 대체 이름 선택→double 벽시각→타입별 재생 프레임→PATCH checking 진단→현재 좌표→위치/전역 재생→현재 타입/프레임 기록→한 번 재생의 실제 Kill 순서다. 두 진단 사이 checking을 다시 읽고 재생 효과 뒤 부모TYPE/현재 프레임을 다시 읽는다. float 지연을 double 벽시각에 더하는 폭과 PATCH/CD NaN 관문도 구별했다.

한 번 소리는 Form 삭제 후에도 장치가 계속 재생한다. 반복 소리는 Form 파괴 때 현재 항목 정지와 후속 상태 진단을 수행한다. 보호막의 이름/부착/안내와 사제 낙하의 위치 요청을 같은 실제 재생기로 잇는 어댑터를 추가했다. 기존 보호막/공유Form/공장/공간/프레임 부품을 대역으로 바꾸지 않았다.

**이번 단위의 실제 장치 경계는 관측 장치다. MonoGame 효과음 backend와 캠페인 HostSession 전체 결선은 후속 작업이다.** 기존 메뉴의 `HostButtonSound`는 아직 그대로다. 실제 오디오 출력·플레이 동일성·M1 완료로 세지 않는다.
