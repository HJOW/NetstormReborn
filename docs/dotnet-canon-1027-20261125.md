# dotnetpj 1.027 — R4-5b 수집자 호출자 결선

2026-11-25, HJOW-Athlon. R4-5b 세션 호출자의 첫 묶음이다. 세션에
`BuildAiCollectorsDevice`를 두고 런타임 `Collectors` 갈고를 실제
`RawAiCollectors.Ensure` 호출로 이었다. 실제 장치가 있는 하위 5종(생산
조회·최대 HP·로그·현재 전역 3종·공용 난수)은 세션 값에 묶고, 아직 없는
하위 5종(구매 비교·참여 상태·배치 검사·생산 배치·효과음)은 원문 순서
도달 시 명시 거부하도록 두었다(R6).

## 변경과 원문 대응

- `dotnetpj/src/Netstorm.Client/Host/HostSession.AiCollectors.cs`: 신규.
  `BuildAiCollectorsDevice`가 `Product=strategy.FindProduct`,
  `MaxHitPoints=hp.MaxHitPoints`, `Log=실제 로그`,
  `Now/LocalOwner/InvalidGraph` 세션 전역, `Game` 공용 난수를 묶는다.
  `CanAfford`·`EnemyAvailable`·`MayPlace`·`Deploy`·`DropSound`는 해당
  백엔드(지갑·flags22·일반 MayPlace·생산 배치·음향)가 없어 명시 거부한다.
  `ManageAiCollectors`는 `ManageAiFactories`와 같은 owner 범위·brain
  확인 뒤 `Ensure`를 부른다. 1.027에서 추가됐다.
- `dotnetpj/src/Netstorm.Client/Host/HostSession.cs`:
  `BuildAiRuntimeDevices`에서 수집자 장치를 조립하고 런타임 `Collectors`
  갈고를 `AiCollectors.Ensure` 호출로 바꾸었다(기존 `미연결(R6)` throw
  제거). 1.027에서 추가됐다.
- `dotnetpj/tests/Netstorm.Client.Tests/HostSessionAiRuntimeTests.cs`:
  3건 추가. brain 없음·범위 밖 거부, 관문 닫힘(신전 없음) 무효과, 미연결
  참여 상태 도달의 명시 거부와 원문 순서(기한·난수·깃발·개수·적 SID)를
  대조한다. 1.027에서 추가됐다.

## 검증

- Release 전체 빌드는 오류 0이다. 신규 경고 0이다.
- `HostSessionAiRuntimeTests` 27건은 통과 27·실패 0이다(신규 3건 포함).
  초회 1건 실패(0 채움 본체·비결정 난수 가정)는 원문 바이트와 대조해
  확정 입력(0x28c=1·`SetState(1)`)으로 바로잡았다.
- `cpp_sync.py --ports`는 종료 0이다(신규 PORT_MAP 행 없음, 기존 행 이상 없음).
- L2 덤프에 영향이 없다(프레임 미연결, 세션 결선만). L2 기준선은 0998을
  유지한다(M1 0/34).
