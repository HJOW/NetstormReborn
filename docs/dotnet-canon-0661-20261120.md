# 0.661 AI 수집자 배치의 선행 본체 (R4-5)

- 일시: 2026-11-20, HJOW-Athlon.
- 범위: `RawAiDeployment` 본체와 건설 요청 인자 구조. 수집자 세션 결선에 앞서 누락된 의존을 이식했다. 실제 서버 확정·로컬 예측 건설 본체는 후속이다.
- 근거: 커밋 `3a0459751`의 `cpppj/src/o/RawAiDeployment.cpp/.h`, 요청 인자는 `RawConstructionConfirm.h`와 `RawConstructionLocal.h`의 해당 구조체만 대조했다. 헤더 전체 이식은 아니다.

## 구현

`RawAiDeployment.cs`는 생산 조각 삭제 → 같은 기술 부모의 `0x108` 대기 내용물 생성 → 사건 0 Regular 예약·현재 주기 부착 → 비용 → 서버/로컬 배치 → 이동 플래그 해제 → 종류별 현재 시각 +20초의 순서를 보존한다. 예약 실패는 나머지 배치를 계속하며 선택된 하위 예외 시 이전 쓰기를 되돌리지 않는다.

비용은 signed64 절삭의 하위 DWORD다. 음수 비용·NaN·DWORD 감김·데모 하한과 하위 호출 이후 현재 TYPE/owner/시각 재조회를 유지한다. SP는 여기서 직접 차감하지 않는다. 같은 PATCH 풀·내용물 생성 계약을 확인하고 기술 부모를 WORD로 미리 잘라내지 않는다.

`ConstructionConfirmRequest` 10인자와 `ConstructionLocalRequest` 5인자를 추가했다. 아직 패킷 직렬화·실제 건설을 제공하지 않으므로 요청 인자만 사용한다. PORT_MAP의 `port` 4행도 이 부분 범위를 뜻한다.

## 검증

- 최초 집중 빌드는 새 검사 파일의 `SidAllocation` 네임스페이스 누락으로 실패했다. `Netstorm.Core.Simulation` using을 추가했으며 제품 본체의 컴파일 오류는 없었다.
- Release 집중 재검사 9/9건 통과·실패 0. `extracted/dotnet-0661/deployment.trx`와 `test-output.log`에 결과를 보관했다. 초기 비동기 검사 호출의 종료 결과를 회수하지 못해 로그 파일을 남기는 명령으로 재실행했고, 실제 종료 0을 확인했다.
- `cpp_sync.py` 종료 0, 연결 fixture 330개 정상. 기존 fixture는 변경하지 않았다. 정기 전체 회귀는 기존 주기대로 0.664에 수행한다.
- 검사 입력·기대값은 cpppj `AiDeploymentTests.cpp`의 합성 계약에 근거한다. 원본 x86 fixture 신규 확보나 전체 L1 통과를 뜻하지 않는다.
- 실제 게임 실행·사제 포획/희생·특정 적 공격·시나리오 승리 재현은 수행하지 않았다.
