# 메뉴 비활성·그림자 색을 원본의 어두운 갈색으로 (WB04-E1136)

E1135 에서 남긴 "비활성 하위 메뉴 행에 `›` 가 보이지 않는다"의 원인을 찾아 고쳤다.

## 증상

- The War Begins! 처럼 신전을 이미 가진 상태에서 사제 메뉴 → Construct 를 열면 `Temple` 행은 원본처럼 비활성(어두운 갈색)이다. 원본 스크린샷(`The War Begins! - High Priest Context Menu.png`)은 이 행에도 어두운 `Temple ›` 표식이 있는데, 웹은 `Temple` 글자만 있고 `›` 가 보이지 않았다.

## 원인

- 하위 메뉴 표식은 그려지고 있었다(행 flags 에 CHILD 비트, 그리기 조건 충족). 다만 비활성 행의 표식 색을 `screen.colors().basic[8]`(회색 `(128,128,128)`)로 칠해 석판 배경(`(122..152, ...)`)에 묻혔다. 캔버스 픽셀에서 `x=772` 의 회색 세로선으로 확인했다.
- 원본(005c78d0)과 cpppj `RawMenuControls.cpp`(1106행)는 메뉴 그리기 상태의 비활성 색과 위젯 그림자 색을 모두 같은 어두운 갈색 이름 색 `(47,24,17)`(`dim`)으로 둔다. 웹 `client-production-menu.js` 는 `disabled: basic[8]`, `shadow: basic[0]`(검정)을 넘기고 있었다.

## 수정

| 위치 | 내용 |
| --- | --- |
| `www/ui/client-production-menu.js` | 팔레트 이름 색에서 `(47,24,17)` 을 찾아 `disabled` 와 `shadow` 로 넘긴다(없으면 명시 오류). |

## 시험

- `e2e/mission-build-placement.spec.js` 의 "비활성 Temple 행에도 하위 메뉴 표식이 어두운 색으로 그려진다"(Chromium): `Temple` 행의 어두운 갈색 픽셀 가로 범위가 글자 40픽셀에서 표식까지 49픽셀로 늘었는지 본다. 회색으로 되돌리면 40 으로 실패한다.
- 생산 메뉴를 쓰는 Node 시험과 메뉴·건설·게임 메뉴 e2e 묶음이 그대로 통과한다(LEFT_JOBS 0.1 절).

## 남은 것

- 그림자 색 변경(검정 → 어두운 갈색)은 C++ 와 맞춘 것으로 눈에 띄는 차이는 없으나, 원본 스크린샷과 메뉴 글자 가장자리를 픽셀 단위로 비교하지는 않았다.
