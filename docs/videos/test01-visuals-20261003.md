## 1. 방법

- **같은 화면 겹쳐 보기.** 클론에 `--test-battle TEST01` 을 더해 원본의 Edit → Game → Test Battle 과 같은 시작 화면을 띄우고, 1280×960 창 캡처를 녹화 37.5초 프레임과 나란히 놓았다. 전체 정렬은 캡처 (0, +1)px 에서 가장 잘 맞는다(4절 수정 뒤).
- **스프라이트 맞추기.** `tools/shp.py export` 로 내보낸 프레임을 1.25배로 키워 녹화 프레임과 비교하는 [`tools/sprite_match.py`](../../tools/sprite_match.py) 를 만들었다. 불투명 픽셀의 평균 RGB 절대차가 점수다(작을수록 맞음, 10 안팎이면 확실).
  - `--anchor x,y` 주변 `--radius` 픽셀을 다시 찾으므로 기준점 규칙이 틀려도 어긋난 양이 `(+dx,+dy)` 로 나온다.
  - 같은 이름 클러스터가 여러 개인 타입(Sail Skater 의 `A01` 36개)은 원본 셰이프에서 순번대로 읽어 `A01#순번` 으로 구분한다.
  - `--locate` 는 프레임 전체에서 찾는다. 왼쪽 생산 창의 아이콘에 먼저 걸릴 수 있어 큰 건물에만 쓸 만하다.
- **좌표.** 시작 화면에서 칸 (cx, cy) 의 기준점은 캡처 `((cx − 171) × 20 + 660, (cy − 202) × 13.75 + 495)` 다(사제 칸 (171, 202) 이 논리 (528, 396)).
- **입력 기록의 시각.** `input-0001.jsonl` 의 `sessionElapsedMs` 는 세션 시작 기준이고 영상 시각(0 = 첫 프레임)과 **28.07초** 어긋난다. 영상 시각과 맞추려면 `recordingElapsedMs` 를 쓰거나 첫 프레임의 `sessionElapsedMs` 를 뺀다. 커서 좌표 `x`·`y` 는 창 기준 캡처 픽셀이다.

## 3. 플레이어 색과 섬 테두리

- **버그.** `FortMapViewer.DeckRemap` 의 반환형이 `ReadOnlyMemory<byte>?` 여서 null 배열이 "값이 있는 빈 표"로 바뀌었다. 그래서 `DeckRemap(color) ?? _isleColors.Table(color)` 가 항상 빈 표를 골라 **섬 소유자 색 변환이 전혀 적용되지 않았다**(F7 로 켜고 꺼도 화면이 같았다). 배열을 그대로 돌려주게 고쳤다.
- **색 번호 규칙(exe).** `FUN_0043b540` 이 소유자 → 색 번호 표 `DAT_00531b08` 을 "색 번호 = 소유자 번호"로 초기화한다. 색 이름 목록은 `/none/blue/red/white/green/purple/yellow/lightblue/orange/`(순번 = 색 번호 0~8)이며 `IsleColorRemap` 의 행 순서와 같다. AI 플레이어를 만들 때(`FUN_00417e50`) 미션 머리 값 `aiNColor` 가 목록에 있으면 `FUN_0043ca70` 이 덮어쓴다. 키 조회는 대소문자를 가리지 않는다.
- **녹화.** 내 섬 테두리 표본 (81,104,122)·(75,110,138) 은 파랑 행(팔레트 80·76번)과 맞는다. 소유자 2 섬은 빨강, 소유자 3 섬은 흰색이었다. `TEST01.english` 는 `ai2color=orange`·`ai3color=red` 인데도 기본색이 보였으므로, **편집기의 Test Battle 은 AI 플레이어를 만들지 않아 덮어쓰기가 적용되지 않는 것**으로 해석했다(추정: AI 행동은 이 녹화에서 확인하지 않았다).
- **클론.** `PlayerColors`(Core)가 기본 표와 이름 해석을 맡고 `MissionStart.AiColors` 가 `aiNColor` 를 읽는다. `--test-battle` 은 덮어쓰기를 비운다. 이전의 개발용 표(플레이어 1 → 청록 7)는 없앴다. 받침(island·islandStalag)에도 같은 색 변환을 적용한다.
- 캠페인 스크립트의 `ai7color = cyan`·`ai5color = magenta` 는 목록에 없는 이름이라 원본에서도 무시된다.

## 4. 그림 기준점과 시작 카메라

같은 프레임에서 건물(비율 없음) 대비 어긋난 양을 쟀다(캡처 픽셀 → 논리 픽셀).

| 타입 | hotFootRatio (X, Y) | 측정 | 비율 × (16, 11), 소수점 버림 |
|---|---|---|---|
| geyser | 0.22, 0.22 | (−3, −2) → (−2.4, −1.6) | (−3, −2) |
| rainBattery | 0.5, 0.4 | (−10, −6) → (−8, −4.8) | (−8, −4) |
| priest | 0.5, 0.2 | (−10, −3) → (−8, −2.4) | (−8, −2) |
| rainBalloon | 1.0, 0.7 | (−20, −9) → (−16, −7.2) | (−16, −7) |
| windWalker | 없음 | (0, 0) | (0, 0) |

- 원본은 **칸 기준점에서 `hotFootRatio × 한 칸 크기`만큼 왼쪽·위에 그린다.** `.type` 의 주석(`// hotFootX = 1; hotFootY = 8;` ↔ 비율 0.0625·0.5)으로 보면 비율은 16분의 n 단위다.
- 클론: `StructureAnimation.HotFootShift` → `FortMapViewer.ObjectSprite` 가 모든 오브젝트에 적용한다(그리기·클릭 판정·선택 표시 공통).
- 건물 6종의 위치로 시작 카메라를 다시 맞췄다. 원본은 화면 왼쪽 위를 칸 경계에 두어 **사제 칸 기준점이 (528, 396)** 에 온다(화면 왼쪽 위 = 사제 칸에서 33칸 왼쪽·36칸 위). 클론의 `OriginalStartOffset` 을 (13, 9) → (16, 12) 로 바꿨다. 사제 그림은 여기서 (8, 2) 왼쪽·위이므로 이전 측정값 (525, 393) ±4 와도 맞는다.
- **칸이 보이는 자리.** 지면 타일·건물은 기준점 `(16·cx, 11·cy)` 의 왼쪽 위로 그려지므로 칸 (cx, cy) 는 월드 픽셀 `(16(cx−1), 16cx] × (11(cy−1), 11cy]` 에 보인다. 클론의 `CellAt` 은 내림이라 보이는 칸보다 한 칸 왼쪽·위를 가리켰다 → 올림(`PlacementCursor.CellUnder`)으로 고쳤다. 건물 클릭 선택·이동 목적지·개발용 발자국 표시가 한 칸씩 바로잡혔다.
  - `CellCenterScreen`(체력 막대 대체 표시·탄·번개·방어선의 칸 중심)은 여전히 "칸 = 기준점 오른쪽 아래" 가정이다. 방어선 위치 등이 그 가정 위에서 녹화에 맞춰져 있어 이번에는 건드리지 않았다(12절).

## 5. 미니맵

- 위치: 캡처 x 1~98, y 866~958 → 논리 약 (1, 693) 에서 78 × 74.
- **1픽셀 = 2칸**, 상자는 156 × 148칸만 보여 준다. 창은 **현재 화면 중심을 가운데** 두고 월드(256칸) 끝에서만 멈춘다. 그래서 흰 사각형은 평소 상자 한가운데에 있고 월드 가장자리에서만 움직인다.
  - 37.5초: 화면 중심 (172.7, 201.2) → 원점 (93.2, 106.8). 가로 172.7 − 78 = 94.7, 세로는 256 − 148 = 108 에 걸림.
  - 275.4·345.0초와 1-1 시작 캡처([the-war-begins-start.md](../screens/the-war-begins-start.md) 2.3절: 원점 (17.6, 33.6), 사각형 중심 = 상자 중심)도 같다.
- 색: 내 섬·다리 (155,210,206)(팔레트 88), 빨강 플레이어 (255,0,0)(254), 흰색 플레이어 (255,255,255)(195), 소유자 없는 섬 (63,88,40)(140), 시야 사각형 흰색. 가이저는 1-1 캡처의 노란 2×2 점이며 소유자 색 위에는 보이지 않는다.
- 누르기·끌기: 누른 지점이 화면 중심이 된다. 누르고 있는 동안 반복하므로 커서가 상자 중심에서 벗어나 있으면 화면이 계속 흘러간다(앞선 판독의 "0.2초마다 전혀 다른 곳").
- 클론: `MiniMapLayout`(Core) + `FortMapViewer.MiniMap.cs`. 월드 전체를 128×128 그림으로 만들어 두고 창만큼 잘라 그린다. 초록·보라·노랑·연파랑·주황 플레이어의 미니맵 색은 순색으로 둔 **추정**이다.

## 6. 그림자

- `.type` 의 typeflags 가 방식을 정한다: `shadow` → 고르게 어두운 그림자, `flyershadow` → 한 픽셀 건너 체크무늬(풍선·비행체). 둘 다 없는 타입(sunArcher·thunderCannon 등)은 그림자가 없다.
- 셰이프의 둘째 레이어(프레임 번호 = 클러스터 수 + 클러스터)는 한 가지 팔레트 색(150 또는 217)으로 칠한 **모양 틀**이다.
- 어둡기: 가이저 그림자가 덮은 지면은 주변의 0.59~0.70배(평균 약 0.64)이고 색이 거의 일정(약 (51,47,38))했다. 원본은 음영표로 어둡게 하는 것으로 보인다. 클론은 검정 36% 덮기로 근사했다(색조는 정확히 같지 않다).
- 클론: `FortMapViewer.Sprites.cs` 의 `DrawShadow`. 본체 바로 앞에 같은 기준점으로 그린다.

## 8. 브리핑의 글 사이 그림

- `~[I타입.프레임]`(일부 스크립트는 `,`) 은 그 자리에 스프라이트를 넣는 표기다. 프레임은 클러스터 번호(숫자), 클러스터 이름(`D1`·`E3`), `*` 이다. 원본 스크립트 전체에서 `~[Iicon.12]`·`~[IfortGump.46]` 등 수백 번 쓰인다.
- TEST01 의 `~[IsunBalloon.a1]<h2>TEST01</h2>` 는 A01 이 없는데도 풍선 그림(A00, 기본 프레임)이 나왔고, 제목은 그림 **옆**(그림 아래 끝 높이)에, `<i>` 글은 그 아래 줄에 있었다.
- 클론: `TutorialTextStyle.Picture` 구간 + `InlinePicture.Resolve`. 제목 앞에 그림이 있으면 제목을 창 위쪽으로 떼지 않는다(`TitleInBody`). 지식 창 도움말 본문에도 같은 그림이 그려진다. 창 폭·버튼 배치(원본은 약 200px 폭, 버튼이 좌우 끝)는 맞추지 않았다.

## 9. 배치 미리보기와 커서 규칙

녹화 103~162초(Crossbow 550, Ice Cannon 600, Thunder Cannon 1200, Sun Disc Thrower 300).

- **구성.** 들고 있는 유닛 그림, 발자국을 두른 **흰 1픽셀 사각형**, 사각형 왼쪽에 위에서부터 쌓인 **필요 원소 아이콘**(`mana` 타입: 어두운 4장 + 밝은 4장, 순서 Wind·Rain·Thunder·Sun), 사각형 아래 **노란 비용 숫자 + Storm Power 보석**. 에너지가 모자라면 흰 글 "Energy not satisfied" 가 비용 위에, 다른 건물과 겹치면 **붉은 사각형과 붉은 채움**이 나온다. 1-1 자동 분석에서는 섬 밖에서 "Only on Controlled Island" 를 봤다.
- **커서 규칙.** 입력 기록의 커서와 사각형을 맞춰 보면 발자국의 오른쪽 아래 칸은 **열 = 커서 칸의 열, 행 = 커서 칸의 행 + 1 + height** 다. Crossbow·Ice Cannon(height 없음)은 커서가 3×3 의 오른쪽 열·가운데 행, Thunder Cannon(`height = 2`)은 커서가 발자국 위쪽 한 칸 밖이었다. 캐논을 우클릭으로 돌려도 사각형은 움직이지 않았다. `height` 가 있는 타입: priest·sunWalker·fireWalker 1, sunBlocker·thunderCannon·windVortex 2, rain/thunder/windBlocker 3.
- **사거리 반짝임.** 고정 캐논은 발사 방향으로 `range` 타입의 반짝임(노랑 `A00`~`A12`)이 **5칸 간격, 약 15칸/초**로 흘러나간다(Ice Cannon 사거리 30). Crossbow 는 두 갈래(V 자)로 나갔다 — 부채꼴 사격 범위의 양 끝으로 보이나 각도 규칙을 확정하지 못했다. `range` 타입의 `B`(분홍)·`C` 묶음의 쓰임도 미확인이다.
- 클론: `PlacementCursor`(Core) + `FortMapViewer.PlacementPreview.cs`. 건물(사제 Construct)에도 같은 커서 규칙을 쓰는 것은 **추정**이다. 안내 글은 확인한 두 문구만 넣었다.

## 10. 선택 괄호와 체력 막대

exe 렌더러 0x498841 부근과 `FUN_004972f0` 에서 좌표식을 옮겼다(녹화의 연청록 괄호·초록 막대와 모양이 맞는다).

- 기준은 오브젝트가 지금 그리는 프레임의 **그림 상자**다. 셰이프 프레임 헤더의 앞 네 값은 `(높이, 폭, 기준점 y, 기준점 x)` 순서다.
- 괄호: 상자의 **아래 두 모서리에만**, 2픽셀 두께. 가로 길이 = 폭 ÷ 4, 세로 길이 = (높이 − 1) ÷ 4. 색은 색 번호별 팔레트 번호 표(VA 0x5319c4: 84, 84, 249, 184, 140, 150, 112, 156, 222) — 파랑 플레이어는 84번 (125,176,179).
- 체력 막대: 상자 위 끝 바로 위, 검은 바탕 안의 2픽셀 막대(폭 = 상자 폭). 색은 (95,188,92) → 절반 이하 (255,255,22) → 4분의 1 이하 (255,22,22). 다른 막대(충전 등)는 3픽셀씩 위로 쌓인다(색 0x7b·0xbe·0xd9 등, 용도 미분석).
- 클론: `SelectionMarks`(Core) + `FortMapViewer.Combat.cs`. 플레이 화면에서는 이름·체력 글자를 쓰지 않는다.

## 11. 클론 실행·진단 옵션
