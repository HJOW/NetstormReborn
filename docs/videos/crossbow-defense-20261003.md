# 석궁·방어 건물 전투 후속 복원

## 구현과 정정

`CrossbowAnimation`은 실제 각도표로 조준 방향을 고른다. 석궁은 설치 사격 방위 ±30도를 유지하면서 그 안의 목표를 향해
본체를 돌리고, 조준이 끝난 뒤 발사한다. 장전 그림은 네 단계가 각각 0.2초다. 장전 자체가 발사 간격을 정하므로 기존
임시 1초 대기를 추가하지 않는다. 목표 상실 시 장전을 취소하며 프레임·장전 여부·다음 진행 틱을 검사합에 넣었다.
원본 그림과 회전·발사 효과음을 연결했고 일시정지 때 상태가 멈춘다.

저장 조준 그림의 방위를 앞선 L/M/N/O 글자로 읽던 방식도 원본 각도표로 교체했다. 예를 들어 그림 20(71도)은 동쪽,
69(256도)는 서쪽, 98(345도)는 북쪽이다. 새 서쪽 배치도 가장 가까운 272도 그림 70을 사용한다.

원반·석궁 탄속은 임시 24에서 원본 35칸/초로 바꿨다. 세 캐논의 20칸/초는 유지한다.
이동 목표가 착탄점을 벗어나면 피할 수 있는 기존 판정도 유지한다.

Wind Tower는 설치 전 우클릭으로 면역 면을 네 방향으로 돌린다. 미리보기와 설치 후 그림이 같은 방위를 사용한다.
면역은 목표 선택과 착탄 피해 양쪽에 적용하고, 발사자가 없어져도 탄의 저장 타입·출발점으로 판정한다.
공중 공격체·폭탄·Thunder Fence는 해당 면에서도 공격할 수 있다. 타입 없는 시설 파괴 폭발도 면역을 우회한다.
Bulwark는 비행 공격체에 면역이므로 Whirligig가 다른 유효 목표를 선택한다.

이전 문서의 **Wind Tower “반사”는 방향 면역으로 정정**한다. 확인한 원본 경로는 피해 무효화이며 탄을 되돌리는 동작을 구현하지 않는다.

## 검증

- Release 전체 빌드 성공, 오류 0. 기존 `TextResourceTests.cs:353`의 CA2014 경고 1건은 이번 범위에서 수정하지 않았다.
- Assets **255** + Core **460** = **715** 단위 테스트 통과, 건너뜀 0. 기존 692건 대비 새 23건.
  석궁 조준 지연·연속 장전·목표 상실·탄속·30/120Hz 결정론, 네 면의 정상 피해/면역,
  공격 종류 예외·벌워크 대신 다른 목표 공격·실제 설치 명령의 방위를 검사한다.
- 전투 UI **12개 시나리오·56개 단언** 통과: 영어 1024×768과 한국어 1280×720에서 장전 그림 3→2→1과
  재발사 그림 4, 태양 조준/탄·신전 폭발, 석궁 발사음의 실제 API 재생 성공을 확인했다.
  정지 전후 지도 PNG **12쌍의 픽셀이 동일**했다.
- 버튼음·사거리·캐논/석궁 배치 검사 기존 **9개 시나리오·97개 단언** 통과.
  새 Wind Tower 검사 **1개 시나리오·13개 단언**으로 배치 커서 유지·북/동/남/서/북 순환과 원본 미리보기 네 장을 확인했다.
  미리보기 검사는 덱 미등록 상태에서 그림과 입력만 검사한다. 실제 설치 규칙은 코어 테스트에서 공급·비용·소유 섬을 거친다.


## 남은 정밀 복원

원본 한 발 피해는 피해 시계와 정수 반올림을 더 확인해야 한다. **석궁은 장전 주기를 복원했지만 한 발 피해는 기존 임시 25를 유지한다.**
원반 본체의 가속 회전·스프링·탄 방출 상태, 아이스 파편, 경로 중 다른 유닛 충돌, 건설 연출·탄의 높이/총구 위치도 남았다.
논리 24Hz에서는 0.1초를 3틱, 0.2초를 5틱으로 올려 진행한다. 원본의 연속 녹화와 실제 발사 간격·피해·청취를 대조해야 한다.
회전 효과음 변종은 프레임에 고정해 세션 난수를 소비하지 않으며 원본의 난수 선택을 복원한 것은 아니다.
방향 면역 예외를 검사했다고 해서 폭탄·번개 울타리 자체의 공격을 구현한 것은 아니다. Linux 실행·캠페인 완주도 이번 범위 밖이다.
