# 원본 공통 메뉴 버튼 동작 분석 (2026-10-03, 원본 10.78 자동 분석)

메인 메뉴·팁 창·대화상자의 돌 버튼과 펼침 메뉴 행이 **눌렀을 때·오래 눌렀을 때·누른 채 바깥으로 옮겨 뗄 때** 어떻게 동작하는지, 어떤 효과음이 나는지 측정했다. 클론의 공통 버튼 동작은 이 결과로 다시 만들었다.

- **실행 환경:** `HJOW-Athlon`(Windows 10, RDP), analyzeManager 자동 분석 + 자동 녹화(영상 AVI·WAV·입력 JSONL, 모든 입력 `injected=true`). 원본 복사본은 1024×768 창 모드이며 AGENTS.md상 이 호스트는 실행 확인이 필요 없다.
- **세션(Git 제외, `extracted/analyzeManager/`):** `20261003T145438684Z-0221dd2e5297`(정찰), `…T151502300Z-347cc063a381`(1차: 호버·길게 누르기·끌기·Credits 경계 일부), `…T153237584Z-ef1cbf31fd6e`(2차: 팁 창·경계), `…T153849965Z-b6fab57a5c43`(3차: 경계·Options 행), `…T155740941Z-452941dd7534`(4차: Campaign 행).
- **시각 기준:** 영상 시각 = 세션 경과 ms − 첫 프레임의 경과 ms. 녹화는 실제 약 18~30FPS이므로 프레임 번호가 아니라 `*.frames.csv`로 계산했다. `SetCursorPos` 이동은 입력 로그에 없고 `SendInput` 누름/뗌만 남는다.
- **도구:** [`tools/audio_events.py`](../../tools/audio_events.py)(입력 사건 앞뒤의 녹음만 원본 효과음과 상호 상관, 배경 음악을 줄이려 고역 강조) · [`tools/button_state.py`](../../tools/button_state.py)(한 버튼 영역이 평소/눌림 어느 쪽 모양인지 프레임마다 판정). 분석기 `drag`에 경유점·대기 옵션을 추가했다([analyze-manager.md](../analyze-manager.md#원본-버튼-누름-시험용-drag-옵션-2026-10-03)).

### 판정 영역 (Credits 버튼, 윗줄 y 311~329·아랫줄 y 334~352)

그려진 버튼은 가로 **75px**(Credits x 435~509, 이웃과 간격 4px)·세로 **19px**(y 334~352)이다. 한 픽셀씩 클릭한 결과:

- 가로: x **507·508·509는 눌림**, **510·511은 안 눌림** → 오른쪽 끝 제외, 폭 75px(그려진 폭과 같다).
- 세로: y **331~333은 안 눌림**, **334~353은 눌림**, **354는 안 눌림** → **그려진 높이(19px)보다 1px 더 아래까지** 눌린다(원본 `FUN_004248e0`: 0 ≤ x < 폭, 0 ≤ y < 높이, 높이는 그려진 값+1).
- 왼쪽·위쪽 끝은 시험하지 않았다. 그려진 시작점(435, 334)과 같다고 가정한다.

## 3. 키보드

사용자가 **"키보드는 버튼에 영향을 주지 못한다. 키보드로 버튼을 누르거나 Tab 키 포커스는 기존 게임에 없었다"**고 알려 주었다. 3차 시험의 키보드 단계(Tab·Enter·Space·↓·C·Esc)는 도구 오류로 실행되지 않았으므로 **영상 근거가 아니라 사용자 설명**이 근거다. 클론은 일반 버튼의 키보드 실행·포커스 표시를 모두 없앴다.

## 4. 확인하지 못했거나 추정인 것

- **Campaign 행의 효과음:** 4차 실행의 녹음이 너무 작아 일치하는 효과음이 없었다. 클론은 Options 행과 같은 `openSubGump.wav`로 추정해 연결했다.
- **하위 메뉴 행(`>`)의 두 번째 소리 `openGump.wav`:** 정적 분석(`FUN_00476820`)으로만 추정했고 직접 듣지 못했다. 클론은 `>` 행에서 `openSubGump.wav` 뒤에 `openGump.wav`를 낸다.
- **메뉴 바깥 누름이 뒤쪽 버튼을 누르지 않는지:** 메뉴가 닫히는 것은 확인했으나 같은 누름이 아래 버튼까지 눌렀는지는 구별하지 못했다. 클론은 누름을 소비하는 것으로 구현했다.
- **Esc로 메뉴 대화상자 닫기:** 시험하지 않았다. 클론에는 Campaign/Missions에서 Back으로 가는 Esc가 남아 있다.
- 호버 훑기 중 펼침 메뉴 행의 호버 표시는 별도로 구별하지 못했다. 클론은 행의 어두운 호버 표시를 유지한다.
- Demo·Edit·Credits·Multiplayer는 원본에서 열리지만 클론은 아직 비활성이다.
- **RDP 지연 주의:** 분석 PC가 RDP 세션이라 RDP 창이 가려지면 분석기 호출이 57~305초 멈췄다(`SLOW game_input 166.7s` 등). 멈춤이 45초를 넘으면 Auto-Demo가 시작되어 실험이 어긋난다. 실험은 승인 프롬프트가 없는 단일 스크립트로 돌리고 시작할 때 Auto-Demo를 꺼야 한다([analyze-manager.md](../analyze-manager.md)의 "가림으로 영구 중단"·RDP 항목).
