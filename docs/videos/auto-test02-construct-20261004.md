## 6. 건설 메뉴·비용·한도

### 6.1 메뉴 (사제 우클릭 → Construct)

우클릭 메뉴는 클릭 지점이 `Construct >` 줄 위에 오도록 뜬다(오프셋 (+51,+21), 화면 가장자리 근처에서는 안쪽으로 밀림). 사제를 **선택하지 않은 상태에서** 우클릭했다(선택한 채 우클릭한 첫 시도에서는 메뉴·건설이 되지 않았고, 허공을 눌러 선택을 푼 뒤 우클릭하자 정상이었다 — 선택된 사제의 우클릭은 메뉴 대신 선택 해제로 동작하는 것으로 **추정**). 이번 TEST02(`myTech="all"`):

| 단계 | 항목 | 비용 | 상태 |
|---|---|---|---|
| Construct Building | `Temple >` → Build Wind Temple / Rain Temple / Thunder Temple | **5000** | 템플이 **없을 때만** 활성 |
| | `Workshop >` → Build Sun Workshop / Wind / Rain / Thunder Workshop | Sun **800**, 나머지 **1000** | 모두 활성(지식 all) |
| | Build Level 1 Altar | **500** | 활성 |

- 템플 하위 창에는 **Sun 템플이 없다**(Wind·Rain·Thunder). 템플 비용은 원소와 무관하게 5000이다.
- 항목을 고르면 `openSubGump.wav` 와 함께 건물 그림·발자국 테두리·비용이 커서에 붙는다. **들고 있는 건물을 취소하는 방법(허공·우클릭 등)은 시험하지 못했다**(계획한 시험 C는 중단됨, 11절).
- 설치는 **마우스를 누르는 순간** 일어난다(S1: 누름 418.137초 → 418.2초 프레임에 그림자, 뗌 418.265초). 설치 때 비용이 차감되며 숫자가 굴러 내려간다(500000 → 495000이 약 1.0~1.5초).

### 6.2 템플: 한 번에 1기 (건설 중 포함)

- 템플 완공 후 사제를 다시 우클릭 → `Construct >` 하면 `Temple >` 줄의 글자가 **어둡고**(활성 줄은 흰색) 클릭해도 하위 창이 열리지 않는다. `Workshop >`·Altar 줄은 그대로 활성이다.
- **S5(중단 전 확인):** 템플을 **설치한 직후 사제가 아직 걷기 시작하기 전/걷는 중**(공사장 그림자만 있고 건물은 아직 없음)에 사제를 우클릭해도 `Temple >` 줄이 **이미 어둡다**. 따라서 **공사장만 놓은 템플도 "이미 있음"으로 센다**(클론이 팬게임 기준으로 가정한 동작과 일치).
- 건설 시간: 설치(클릭) → 사제가 걸어가 **도착한 순간 건물이 드러나기 시작** → **도착 후 정확히 약 10.0초**에 완공(S1 템플: 공사 시작 약 586.8초(첫 `jimbuild`가 낮은 상관으로 586.79 추정, 첫 화면 변화 587.13) → 완공음 596.80). 설치 클릭에서 완공까지는 사제 이동 거리에 따라 S4 20.5초(사제가 (520,388) 근처에서 출발) / S1 25.1초.
- 완공되면 **섬의 지면이 풀밭에서 눈 덮인 얼음 지형으로 바뀌고**(Rain 템플의 원소 테마, 테두리 색 포함) 템플이 선다.

### 6.3 워크샵: 개수 한도는 없고 자리로만 막힌다

- **발자국**은 **7칸 × 8칸**(화면 112×88픽셀, 칸 16×11)이다. 커서가 가장 가까운 칸에 붙어 테두리가 움직인다: `왼쪽 = 16 × (round(x/16) − 4)`, `위 = 11 × round(y/11) − 34`(기준 카메라, 칸 번호 col = round(x/16), row = round(y/11)). 테두리가 **순백(255,255,255)이면 설치 가능, 붉은 테두리(255,0,0)·분홍 채움이면 불가**. 불가일 때 문제 칸(땅이 아니거나 이미 건물이 있는 칸)이 붉게 보인다.
- **건물끼리 붙여 지어도 된다**: 가로 112픽셀·세로 88픽셀 간격으로 정확히 맞닿게 놓은 배치(S4의 (26,21)·(26,29)·(26,37) 등)가 모두 허용됐다. 집·템플 발자국과는 겹치면 안 된다. 사제가 선 자리는 막지 않는다.
- 섬 가장자리(절벽·초목 쪽)에서는 발자국 전체가 땅 위에 있어야 한다(오른쪽 아래 모퉁이 (900,520)은 발자국 일부가 절벽이라 불가).
- **개수 한도:** S4에서 템플 1 + 워크샵 **14채**(SP 500000 → 483800 = 5000 + 14×800)를 한 섬에 지었고 거부·메뉴 줄 어둡게 되는 일이 한 번도 없었다. S1에서도 12채 연속(SP 485400)이 정상이었다. 이 섬에서 더 못 짓게 되는 것은 개수가 아니라 **빈 땅이 7×8칸 발자국을 담지 못하기 때문**이다(아래 6.4절). 더 큰 수(예: 20 이상)에서 한도가 없다는 증명은 아니다 — 이 섬에서는 도달할 수 없었다.
- 워크샵 Sun 한 채 건설: 사제가 현장에 도착한 뒤 **10.0초**(S4 14채 중 첫 `jimbuild`부터 완공음까지 10.01~10.03초). 건물은 바닥의 나무·화단부터 위로 차올라 완공 직전에 창문에 불이 켜진다.

## 7. 건설 명령 직후 사제를 이동시키면 — 취소와 전액 환불

**설치 클릭 직후, 사제가 아직 현장에 도착하기 전에** 사제에게 이동 명령(P 로 선택 → 땅 클릭)을 내렸다(S1, 영상 프레임·SP 숫자 프레임 판독).

- 시험하지 않은 것: 정지·다른 유닛 선택이 같은 취소를 일으키는지(11절). 새 건설 지시는 아래 7.1절.

### 7.1 사제가 이동 중일 때 다른 건설을 지시하면 — 이전 건설 즉시 취소·환불 (사용자 확인)

**템플이든 워크샵이든 건설 명령을 내려 사제가 현장으로 이동하는 중에 다른 건설(예: 다른 자리의 워크샵)을 지시하면, 이전 건설은 즉시 취소되고 비용이 환불된다**(2026-10-04 사용자가 원본에서 확인해 알려 준 규칙). 새 건설 지시도 사제에게 내리는 새 명령이므로 7절의 이동 명령과 같은 취소 규칙을 따른다.

- 이것은 영상·입력 로그로 내가 직접 판독한 값이 아니라 사용자 보고다. S5 에서 템플 공사장이 대기 중일 때 워크샵을 설치한 직후의 프레임(설치 클릭 한 프레임 안)에 템플 그림자와 워크샵 그림자가 함께 보였는데, 7절의 이동 명령 취소도 그림자가 사라지기까지 0.2~0.9초가 걸렸으므로 **이 관찰은 규칙과 모순되지 않는다**(앞선 공사장은 같은 지연 뒤에 사라지는 것으로 해석된다. 이후 프레임은 시험 중단으로 얻지 못했다).
- 결과: 어느 시점에도 두 공사장이 동시에 지어지지 않고, 마지막에 지시한 건설만 사제가 걸어가 짓는다. 비용은 새 건설분만 남는다(앞선 건설분 환불).
- 건설이 이미 시작된 건물(사제 도착 뒤, 8절)은 취소 대상이 아니다 — 7.1절은 **사제가 도착하기 전의 공사장**에만 적용된다.

**클론 반영 완료(같은 날 후속, 원본 추가 실행 없음):** 커서·7×8 발자국·그림 중앙 배치·사제 선택 해제·건설 메뉴 위치/순서·취소 연출·건설 그림/소리를 구현했다. [구현 근거·검증·근사값](../gameplay/test02-clone-parity-20261004.md). 새 건설 교체는 사용자 확인대로 지연 없이 처리한다. 남은 원본 분석은 들고 있는 건물 취소 방법, 정지·다른 유닛 선택의 취소 여부, 정확한 공사장 마스크·취소/증가 시각이다.

## 11. 중단된 추가 시험과 한계

- **중단된 시험(S5, `tools/analyze_test02_pending.py`):** A. 템플 설치 직후 메뉴 상태 — 완료(6.2절: Temple 줄 어두움). B. 템플 공사장이 대기 중일 때 다른 자리에 워크샵을 설치 — 설치 클릭 직후 한 프레임 안에서는 템플 그림자와 워크샵 그림자가 동시에 보이고 SP 가 −800 굴러 내려갔다. 그 뒤 프레임은 **사용자 요청으로 중단되어 관찰하지 못했다**. 이 시험의 결론(이전 건설 즉시 취소·환불)은 사용자가 알려 준 규칙으로 대신한다(7.1절). C. 들고 있는 건물 취소 — 실행하지 못했다.
- 워크샵 **개수 한도 없음**은 "14채까지 거부가 없었다"는 관찰이며 더 큰 수에서 한도가 없다는 증명은 아니다(이 섬에서는 겹침 없이 최소 16채가 들어가나 실제 지은 것은 14채).
- 템플 위 커서(안쪽 화살표 4개)의 의미는 추정이다. 사제 선택 상태가 아니면 템플 위에서도 화살표다(확인).
- 이동 명령 직후 그림자가 사라지는 시각은 영상 프레임 간격(0.1~0.9초)으로 잰 값이며 정확한 지연은 더 촘촘한 시험이 필요하다.
- 영상은 12~17FPS 로 기록되어 0.1초 이하의 짧은 사건은 볼 수 없다.
- 사제 우클릭 메뉴 오프셋은 가운데 지역 기준이다(가장자리에서는 안쪽으로 밀림). 사제가 건물 뒤에 가려지면 클릭이 건물에 가려지므로 스크립트는 매번 HOME(560,470)으로 불러 세운다. P 키를 이미 선택된 사제에게 한 번 더 누르면 카메라가 사제 위치로 이동한다(스크립트가 템플·집 그림으로 카메라 이동량을 측정해 보정).
