# 애니메이션 진행 속도 (영상 측정 + exe 대조)

> 분석일: 2026-09-28. 자료: 로컬 플레이 영상 4개 (60fps, [README.md](README.md)), 디컴파일 `extracted/decomp/Netstorm.c`
> 측정 도구: `python tools/videoframes.py cadence <영상> <시작> <초> [--max-y Y]`

## 1. 측정 방법

1. 게임 영역을 1024×768 회색조로 줄여 읽고, 연속한 영상 프레임의 차이를 구한다.
2. 맵 영역에서 5% 이상 픽셀이 바뀐 프레임은 카메라 스크롤로 보고 뺀다.
3. 32×32 칸마다 평균 차이가 6 을 넘는 순간을 "애니메이션이 바뀐 순간"으로 보고, 그 사이 간격(영상 프레임 수)의 분포를 센다.
   60fps 영상이므로 간격 1 = 16.7ms. 2·3 이 번갈아 나오면 평균 2.5 → **24Hz**, 5 가 반복되면 **12Hz** 다.

* 25Hz(0.04초 정확히)라면 간격 평균이 2.4 가 되어야 하지만 측정은 2.52 → 24Hz 에 가깝다.
* 12.5Hz(0.08초 정확히)라면 5·5·5·5·4 가 섞여야 하지만 4 는 나오지 않았다 → 12Hz.
* 가이저 증기 칸 옆 칸에서 5 가 섞이는 것은 증기 모양이 칸 경계를 넘나들며 일부 전환이 작게 잡힌 결과로 본다.

## 3. exe 대조 — "다음 시각 = 현재 시각 + 간격" 방식

* 화면 갱신 상한: 설정 `maxFPS = 75` (`options.cfg`, 코드 기본값도 75 = `0x4b`). 프레임 간격 = `1.0 / maxFPS` (`_DAT_00501580` = 1.0). `sleepPerLoop = 0`.
* 게임 시각: `timeGetTime()` 기반 초 단위 double (`00460cd0`·`00460d70`), 루프마다 `DAT_0055b4d0` 에 저장.
* 애니메이션 타이머 예 — `Flyer.cpp` `0045d2c0`:
  ```c
  if (next <= now) { frame = frame + 1; next = now + 0.04; }   // _DAT_00509db0 = 0.04
  ```
  다음 시각을 **이전 예정 시각이 아니라 현재 시각 기준**으로 잡으므로 실제 간격은 "0.04초를 게임 루프 주기 단위로 올림한 값"이 된다.
* `Lightning.cpp` `00471fc0` 는 0.08초(`_DAT_00507828`, float) 를 비교 기준으로 쓴다.
* 루프 주기 ≈ 13.9ms (maxFPS 75 의 13.3ms + 처리 시간) 라고 하면
  * 0.04초 → 3루프 = 41.7ms → **24Hz** (가이저 측정과 일치)
  * 0.08초 → 6루프 = 83.3ms → **12Hz** (신전·연기 측정과 일치)
* 가이저·신전·연기 각각의 간격 상수가 들어 있는 함수는 아직 찾지 못했다 (위 두 함수는 같은 방식의 예). 4단계에서 `Geyser`·`Vortex`·`Damage` 관련 모듈을 확인한다.

## 4. 클론 구현 방침 (제안)

* 원본 속도는 PC 성능·`maxFPS` 에 따라 조금씩 달라지는 구조다. 클론은 결정론(멀티플레이·리플레이)을 위해 **고정 간격**을 쓰고,
  원본을 maxFPS 75 로 돌렸을 때의 실제 체감 속도(영상 측정값)를 기준값으로 삼는다: 0.04초 계열 → 41.7ms(24Hz), 0.08초 계열 → 83.3ms(12Hz).
* 개발용 스프라이트 뷰어의 기본 10fps 는 임시값이다. 타입별 간격이 exe 에서 확인되면 뷰어 기본값도 그 값으로 바꾼다.
* 이동(위치)은 애니메이션 프레임과 별개로 매 화면 갱신마다 시간 비례로 움직이는 것으로 보인다 (위 표 마지막 줄, 추가 확인 필요).

## 4.1 TEST01 녹화 추가 측정과 클론 반영 (2026-10-03)

스프라이트 맞추기(`tools/sprite_match.py`)로 프레임 순서를 직접 읽었다. 이 녹화는 30FPS 캡처 환경이라 0.08초 계열이 약 0.11초로 나왔다(게임 루프가 느려진 영향으로 본다). 클론은 2절의 기준값(24Hz·12Hz)을 쓴다.

| 대상 | 프레임 순서 | 이 녹화의 간격 | 클론 |
|---|---|---|---|
| 가이저 | `A00`~`A16` (17장) | 약 24Hz 계열 | 24Hz |
| Thunder 신전 | `B00`~`B06` (본체 교체) | 약 0.11초/장 (한 바퀴 약 0.77초) | 12Hz |
| Cloud Floater | `A00`~`A19` | 약 0.11초/장 (한 바퀴 약 2.2초) | 12Hz |
| Rain 워크샵 물 반짝임 | 없음 → `02` → `03` | 0.5초 | 0.5초 |
| 사거리 반짝임(배치 미리보기) | `range` `A00`~`A12`, 5칸 간격으로 약 15칸/초 이동 | 그림 교체 간격은 못 잼 | 24Hz (추정) |

규칙과 한계는 [TEST01 화면 요소 대조](test01-visuals-20261003.md) 7·9절, 코드는 `Netstorm.Assets.StructureAnimation`.

## 5. AGENTS.md 2026-10-03 변경과의 관계

* AGENTS.md는 목표를 **"기존 게임의 사운드, 그래픽, 애니메이션 등 거의 모든 요소를 가능한 한 동일하게, 최대한 모방"**으로 넓혔다. 따라서 애니메이션 간격도 요소별로 원본과 같게 맞추는 것이 목표다.
* AGENTS.md의 **"기존 게임은 요소마다 애니메이션 프레임이 달랐던 것으로 추정된다"**는 위 2절의 측정과 맞는다(가이저 증기 약 24Hz, 신전 회오리·피해 연기 12Hz). 2절은 일부 요소만 잰 것이므로 나머지 요소(유닛 걷기·공격, 건설, 포탄, 폭발, 생산 창 깜빡임 등)의 간격 상수를 exe와 영상에서 더 확인해야 한다.
* 클론은 **30·60·120프레임**을 지원해야 한다(30 먼저). 화면 갱신 속도가 달라져도 애니메이션은 위 고정 간격(41.7ms·83.3ms 계열)으로 진행해야 원본 체감 속도가 유지된다. 요구사항과 현재 상태는 [map-viewer.md](../map-viewer.md#프레임-속도-요구사항-agentsmd-2026-10-03).
