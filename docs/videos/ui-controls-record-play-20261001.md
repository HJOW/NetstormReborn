## 도움말 UI의 형태

본문 전체·인용문·목차·유닛 목록은 [도움말 텍스트 문서](../gameplay/help-text-record-play-20261001.md)에 옮겼다.
`help.english`의 원본과 녹화 세션 아카이브가 바이트 일치하며, 전체 2,727행·138앵커 정의를
[113본문 묶음](../sources/in-game-help.md)으로 보존했다. `unitHelp` 첫/뒤 정의의 레벨·목록 차이도 기록했다.

목차와 일반 도움말은 클라이언트 대략 `(287,40)~(738,390)`의 돌 프레임이다.
본문은 어두운 배경, 흰 글자와 청록색 링크이며 우측 세로 스크롤을 쓴다.
하단 Back / OK는 본문과 분리되어 스크롤해도 고정된다.
목차 → 주제 → 하위 링크 → Back으로 이전 페이지를 되짚는다.
긴 누름은 입력 밀림의 증거가 아니다. 예를 들어 01:58.402~02:22.496의 좌버튼 누름 동안
스크롤 영역의 드래그와 페이지 위치 변화가 이어진다.

High Priest 상세창은 상단 그림·능력치(Hits 100, Range 30 등)를 고정하고 **아래 본문만** 스크롤한다.
Three Furies의 그림은 일반 본문에 포함되어 글과 함께 스크롤한다.
이 차이는 설명창 복원에 사용할 수 있다. 도움말 내용의 수치는 실제 패치판 전투 판정과 별도로 대조한다.

## 입력 지연 비교와 한계

입력 훅 전용 스레드·비동기 저장 수정 후 실제 녹화가 정상 중단된 것을 확인했다.
Windows 이벤트 `hookTimeMs`와 훅 진입 시각의 차에서 전체 최솟값을 빼,
서로 다른 시계 원점을 제거한 **상대 도착 대기**를 계산했다.
Windows 이벤트 시각의 약 16ms 양자화도 포함된다.

| 영상 구간 | 입력 수 | 중앙값(ms) | 95백분위(ms) | 최대(ms) |
|---|---:|---:|---:|---:|
| 00:00~01:00 | 1090 | 9.9 | 15.6 | 17.0 |
| 01:00~02:00 | 1087 | 10.5 | 15.7 | 17.3 |
| 02:00~03:00 | 737 | 9.2 | 15.6 | 17.1 |
| 03:00~04:00 | 750 | 8.8 | 15.5 | 16.9 |
| 04:00~중단 | 194 | 10.0 | 15.3 | 16.2 |

처음 영상보다 앞선 입력 4건은 이 표의 구간 밖에 있다. 모든 훅 입력의 최대는 **17.3ms**다.
[세 번째 녹화](master-of-whirligigs-record-play-20261001-2311.md#입력-지연과-커서-증상)의
09:00 이후 중앙값 155.5ms·최대 1051.5ms와 같은 큰 누적 대기는 이번 UI 시연에서 나타나지 않았다.
삭제된 세 번째 원자료를 다시 검사한 비교가 아니라 **삭제 전 보존한 통계**와 비교한 것이다.

영상 프레임 간격은 01:09.404 부근 255.033ms, 01:11.829 부근 296.336ms의 짧은 증가가 있다.
이번 최대 간격은 약 296ms이고 이전의 수초 공백은 없다. 화면 캡처·압축 시간과 훅 지연은 구분한다.
모든 기록 입력은 `injected=false`지만 이것만으로 게임이나 외부 프로그램의 커서 이동을 배제할 수 없다.
이번 시연에는 적 사제 포획·의식이 없으며 플레이 시간도 이전보다 짧다.
**훅 콜백 종료·게임 클릭 적용·화면 커서 반영의 지연은 직접 측정하지 않았다.**
따라서 이전 증상의 원인 확정과 포획·의식 구간의 개선 확인은 남아 있다.

## 재현과 세션 정리

아래 명령은 저장된 녹화만 읽고 게임을 실행하지 않는다.

```powershell
python extracted/record-play-20261001-2354/audit.py
python tools/recordplay_frames.py sheet playingVideos/20261001T145330210Z-425636a2e82c -o extracted/record-play-20261001-2354/overview --step 50 --width 320

```

분석 중 게임·녹화 창 프로세스가 이미 종료된 것을 확인했다. 관리 세션에 관찰 메모를 남기고
`end_session force=false`가 `closed=true`를 반환했다. 분석을 위해 새 게임을 실행하지 않았다.
원자료와 파생 증거는 유지하며 삭제된 세 번째 녹화 폴더와 혼동하지 않는다.
