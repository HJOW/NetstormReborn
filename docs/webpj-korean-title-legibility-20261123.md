# 한국어 큰 슬롯(제목) 글자가 다른 글자로 읽히던 문제의 수정 (WB04-E1254 발견, WB04-E1259 수정)

[다음 작업 3](../LEFT_JOBS.webpj.md#next)의 "한국어 미션의 실제 화면 확인"(E1254)에서 찾은 문제를 사용자 결정("크기만 고쳐 주세요", 2026-11-23)에 따라 E1259 에서 고쳤다. 굵기(원문 Bold 고정)는 그대로 둔다(결정 없음).

## 발견(E1254)

실제 Chromium(`?lang=ko`, 1024×768)의 캠페인 브리핑 세 장면에서 본문(작은 슬롯, 갈무리11 11px 보통체)·단추·HUD 는 정상인데 **큰 슬롯 제목**(`<h2>`, 슬롯 3)이 다른 글자로 읽혔다: `섬을 구하라!` 의 `라` 가 `다` 처럼, `잔혹한 힘!` 의 `잔` 이 `산`, `혹` 이 `폭` 처럼 보였다(번역 원문은 정확).

## 원인(E1259 에서 정정)

E1254 에서는 "슬롯 3 이 19px(슬롯 4 는 45px)의 비정수 배율이라 가로획이 합쳐진다"고 적었으나 실측해 보니 **그것만이 원인이 아니었다.** 래스터라이저로 22px 와 기준선 15·18 의 `잔` 을 직접 그려 보니 글자 그림(21줄)은 맨 위에 `ㅈ` 의 가로획이 온전히 있는데 **글자 윗부분이 줄 맨 위(0) 위로 나가** (`image.top = -6`(기준선 15)·`-3`(기준선 18)) 텍스트 영역에서 잘렸다. `ㅈ` 의 맨 위 가로획이 사라지면 `ㅅ`, `ㄹ` 의 맨 위 획이 사라지면 `ㄷ` 처럼 보인다. 원인은 둘이다.

1. **크기**: `assets/unicode-font.js` 는 큰 슬롯의 글자 크기를 `round(슬롯 높이 × 13/14)` 로 정해 슬롯 3(높이 20) 19px·슬롯 4(높이 48) 45px 였다. 갈무리11 은 11px 비트맵 글꼴이라 11 의 배수가 아니면 보간돼 획이 번진다. 원문 `BitmapFont.cpp:207~221` 은 `scale = max(1, (높이 + 5) / 11)` 의 정수 확대(단색 픽셀 복제)이다.
2. **기준선**: 글자 그림은 기준선 위 20줄(22px)·41줄(44px)을 차지하는데 줄의 기준선은 원본 Arial 20 의 15줄(슬롯 4 는 Arial 48 값)이라 윗부분이 줄 밖으로 나갔다. 원문은 글자가 기준선 위보다 크면 위쪽을 0 줄에 맞추고(`shift = max(0, ascent - bearingY*scale)`) 칸을 키운다.

## 수정(E1259, `assets/unicode-font.js`)

- `koreanEmSize(슬롯 높이)` = `11 × max(1, floor((높이 + 5) / 11))`: 슬롯 높이 `[14, 13, -, 20, 48, 14, 12]` 에서 작은 슬롯 11px, **슬롯 3 → 22px, 슬롯 4 → 44px**. (`EM_PER_SLOT_HEIGHT` 상수와 `MIN_EM_SIZE` 는 쓰는 곳이 없어 없앴다.)
- `koreanAscentRows(emSize)` = `배율 × 10 + (배율 ≥ 3 ? 1 : 0)`(22px → 20, 44px → 41; 44px 의 +1 은 실측으로 래스터라이저 반올림 몫): 정수 배율로 키운 큰 슬롯의 기준선을 `max(원본 기준선, 이 값)` 으로 올려 글자 윗부분이 줄 밖으로 나가지 않게 한다. **작은 슬롯(11px)은 원본 기준선 그대로**라 기존 글자 위치가 변하지 않는다. 줄 높이는 원본 값을 유지하고 `descent` 는 0 아래로 내려가지 않게 막았다(줄 배치는 높이와 기준선만 쓴다).

## 확인

- 실제 화면(확대 캡처): 브리핑 `섬을 구하라!` 의 `라` 에 `ㄹ` 세 획이, `잔혹한 힘!` 의 `잔` 맨 위에 `ㅈ` 가로획이 보인다. `설정 초기화`(Reset All 창)·`캠페인`·`사제 훈련`·`NetStorm 11.01 패치 크레딧!` 제목도 선명하고 겹치지 않는다.
- `tests/korean.test.mjs`: 모든 슬롯의 글자 크기가 11의 배수이고 `koreanEmSize`·`koreanAscentRows` 경계값(16→11, 17→22, 28→33, 39→44; 22px → 20, 44px → 41)과 슬롯 3 기준선 20(`descent` 0)·작은 슬롯 불변을 고정한다.
- `e2e/korean-title-glyph.spec.js`(실제 Chromium·실제 글꼴): 슬롯 3·4 의 글자 크기가 22·44px 이고 120개 한글 음절 모두 **잉크의 첫 줄이 줄 맨 위(0) 이상**이며 `잔` 의 맨 윗줄에 가로획(10칸 이상)이 있다. 이전 값(기준선 15 등)에서는 윗부분이 -3~-6줄 나가 실패한다.
- 한국어·채팅·Reset All·난이도 e2e 와 한국어 Node 시험 전부 통과.

## 알려진 남은 문제(이 수정과 무관, 기록만)

- **Credits 목록 창의 제목이 잘린다**(수정 전 19px 에서도 `NetStor` 까지만 보임, 22px 에서 한 글자 더 잘림): `tell-window.js fit()` 이 제목 자연 폭(`NetStorm 크레딧` 186px)이 버튼 폭 기준 후보(약 160px)보다 넓으면 폭을 좁은 쪽으로 다시 맞추는 원본 알고리즘을 따르는데, 영어 제목(약 125px)과 달리 한국어 제목은 이 갈래로 들어가 본문 폭이 74px 로 줄고 한 낱말(`NetStorm` 111px)이 잘린다. 같은 이유로 좁은 캠페인 목록 창의 소개 문구 끝(`플레이하시겠습니까?`)도 잘린다(작은 슬롯, 이 수정과 무관). 제목·소개 번역을 줄이거나 낱말이 잘리지 않게 폭 규칙을 넓히는 별도 단위가 필요하다.
- **슬롯 1·6(Arial 13·12 기준)의 작은 한글 글자도 윗부분이 1줄 잘린다**(실측: 잉크 첫 줄이 -1). 단독 미션에서 이 슬롯으로 한글이 그려지는 곳은 확인하지 못했다(슬롯 0·5 는 정상, 첫 줄 +1). 쓰는 곳을 찾은 뒤 같은 방식으로 보정한다.
- 굵기(원문 Bold 고정)는 의도적 선택이라 결정이 남아 있다.

## 재현

`?lang=ko` 로 첫 캠페인 미션을 시작해 브리핑 제목을 확대해서 본다(임시 Playwright 캡처). 위 e2e 는 같은 원인을 렌더링 없이 글리프 수준에서 고정한다.
