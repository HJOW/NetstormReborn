# 1.203 실제 음악 열기와 전체 선택 대조

같은 MusicChannel의96BYTE·실제 재귀 잠금에 Open/EnsureBuffer를 추가했다. 두 검색 경로와 null/빈 문자열 차이, 실패 열기의 부분 헤더 writeback·로그 위치, 기존 버퍼 재사용과 생성 HRESULT에 따른 ref 토큰 출력을 원문 순서로 보존한다. 버퍼는 원문 flags0xe2·크기0x2af80을 요청하며 생성 실패 출력도 남긴다. Open callback 예외는 채널 writeback 전에 중단한다.

같은 파일/버퍼 함수 슬롯 사본을 `BindPlaybackDevices(files,buffers)`로 공개 Play/Select에 연결한다. 초기 미준비 반환은 그대로이며 실제 WindowsMusicFileStore로 RIFF 파일을 열고 위치/수명을 유지한다. Create COM 응답과 Find/실패 입력만 독립 원문 검사 장치가 공급하며 제품 장치를 성공으로 합성하지 않는다. 실제 DirectSound 음악 버퍼/Fill/worker·HostMissionAudio 조립은 후속이다.

`musicopen-x86.tsv` **1,872행(판본별624)**의 사건·공개 반환·전체96BYTE·실제 파일 위치/열림을 전수 대조했다. CPP와 같은 `raw96_53`을 주기준으로 사용한다. Patch72행에 남은 `raw96_64`와의1ulp 차이는 별도 단언으로 보존했으며 둘 중 하나를 골라 통과시키지 않는다. 원문 파일은 수정하지 않았다.

`musicselection-x86.tsv` **2,064행(판본별688)**을 실제 선택/제어/채널/열린 파일로 대조했다. 앞선 미준비372행과 나머지1,692행 전체이며 현재256BYTE 이름·96BYTE·파일 위치/생존 수·재귀 잠금·fallback 순서를 비교한다. 연속 곡 교체/현재 전역 음악 옵션 fallback/실디스크 보조 경로와 토큰 수명도 확인했다. 새 Open5·전체선택6, **11/11 통과**다.

팀 전체 실제 소스를 동결한 뒤 Release 솔루션 **오류0·기존 경고25**, 51.82초·종료0이다. `extracted/dotnet-1203-build.log`, 출력은 `extracted/dotnet-1200-artifacts/`다. 수정한 FileStore7·HUD35·채널/음소거/선택/효과음/목록을 합친 집중 **91/91 통과·실패0**, `extracted/dotnet-1203-tests/focus.trx`다. 최초 FileStore 실패와 교정은1.202에 따로 남겼다.
