# 1.226 실제 CD 확인과 설정 전 시작 순서

2026-11-28 HJOW-Athlon. H의 선행 장치로 CD 확인 본체와 실제 Windows 경계, 설정 적재 전 최초 확인, 같은 Game 소유자 인계를 연결했다. 집중63/63통과·대표3진입 정상이다. State7 전체 몸체나 전체 Native 시작 순서를 완료한 단위가 아니다.

## 구현 범위

CdPresence는 원문의128BYTE 캐시/루트 목록과 CD-ROM 종류5의 열거를 복원한다. 현재 BYTE를 읽는 시점, 콜백 뒤 현재 source 복사, 용량 부족의 첫BYTE0/필요 폭 반환, 실패 뒤 앞선 쓰기와 미작성 꼬리를 보존한다. 캐시 성공은 열거 없이 반환하며 실패 뒤에만 새 루트를 조회한다. 같은 RawFileName 고리의 -2루트/-3표시 이름으로 경로를 작성한다.

ClientCdGlobals는 같은128BYTE BSS 캐시, 최초 결과0054db6c, 별도 재확인 serial005c85ec를 소유한다. State7의005c85b8은 기존 ClientLocalStateGlobals에 유지한다. Check는 최초 결과/현재 State7 결과/serial을 임의 대입하지 않는다.

WindowsCdPresence는 실제 GetLogicalDriveStringsA/GetDriveTypeA와 UTF-8 경로의 GetFileAttributesW를 사용한다. 표시 파일은 디렉터리도 속성 성공으로 판단한다. 매체 오류 창 억제는 현재 스레드 모드를 잠시 바꾸며 성공·실패·UTF-8 해석 예외 뒤 이전 모드를 복구한다. 네트워크나 게임 난수를 사용하지 않는다.

HostStartupScene의 기존4인자 생성자는 유지했다. 실제 Program은 새5인자 경계를 명시해 파일 이름 소유자 생성→최초 CD 확인→설정 Startup/사용자 설정 적재 순서로 실행한다. Game는 같은 CD 소유자와 파일 이름 고리를 인계받는다. 콘텐츠 재적재나 새 Session으로 재생성하지 않는다.

이 순서는 **CD→Config의 상대 순서**를 검증한 것이다. CPP의 선행 SP 초기화와 DN의 기존 Game 생성 시점 등 전체 Native 시작/RNG·시드 동등성은 R4/M1에 남는다. CdDirectory의 재귀 탐색이나 CD10.72 복원, RecheckCD 입력 명령을 완료한 것으로 세지 않는다. State7의 현재 결과 대입도 이후 실제 부모 위치에서 수행해야 한다.
