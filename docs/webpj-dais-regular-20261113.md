# webpj 다이스 의식 상위 몸체 RawDaisRegular (WB04-E367, 2026-11-13, 7-P3 신전·제단·의식 부품 세 번째 항목)

3.1절 7-P3 항목 "RawDaisRegular 374줄(+12)"을 `core/raw-dais-regular.js`(상위 몸체·상태·훅 공장)와 `core/raw-ritual-regular.js`(룬 304·다이스 305/306/307 공용 분기)로 옮겼다. 사제가 신전 목표점에서 의식을 마치면 다이스(Dais)가 단계를 진행하고, 단계 4 이후에는 희생(획득·업그레이드)을 시작·진행·종료하는 중심 몸체이다. 기준선(20261106) 뒤 `20261109-95 CP`(다이스·제단 고유 삭제용 정적 `StopPriestRitualIn`, 실제 Player 기록 대여)와 `20261110-52 CP`(의식계 네 정기의 현재 장기 연결: `boss`/`alliance`/`count`/`priestType` 훅, 장기 획득 종류·다리 TYPE)를 반영했다(PORT_MAP base `21bb2550`). `RawRitualRegular` 의 제단 정기(`RunAltarRegular`)는 다음 단위 RawAltarSacrifice 에서 같은 모듈로 이어서 옮긴다.

## 1. 규칙

- **구성:** `new RawDaisRegular(pool, hash, types, frames, ritual, rune, carrier, host, lookup, path, state, hooks)` — 풀은 PATCH, `types`·`frames` 는 188칸(TYPE 레코드, `FrameCodeTable`), `ritual`(RawTempleRitual)·`rune`(RawRunePostPop)·`carrier`(RawCarrierPreDestroy)·`host`(SquidProcessHost)·`lookup`(RawContainedLookup)·`path`(RawPathStart)는 모두 같은 풀이어야 한다. 하나라도 다르거나 표 크기가 다르면 `TypeError`. 훅은 **도달한 위치에서만** 요구하고(없으면 `Error('다이스의 선택된 실제 장치 미연결')`), 연결하지 않은 훅을 빈 함수로 대신하지 않는다. 훅 이름은 cpppj 와 같다(`setFrame`·`destroy`·`reserveShared`·`addShared`·`playAt`·`reserveSound`·`loadSound`·`attachSound`·`wallSeconds`·`setSoundStart`·`stopVoice`·`processType`·`pathMetadata`·`damageable`·`addLocalSp`·`normalizeForeignSp`·`grantForeignType`·`localSpecial`·`localType`·`refreshOwner`·`refreshLocal`·`priestExists`·`multiplayerStatus`·`chat`·`assertion`·`notifySurface` 와 선택 `boss`·`alliance`·`count`·`priestType`).
- **상태 (`DaisRegularState`):** 신전 의식 상태(권한·사제 종류)·룬 상태(룬/다이스/제단 TYPE·시간 억제)를 빌리고, 희생 코드표 TYPE 169·획득 SP 종류 154·noIsland 93·방향별 동맹 9×9·플레이어별 획득 플래그/희생 결과 DWORD·로컬 플레이어(`bindLocalOwner({ value })` 로 장기 값 대여)·진단(checking) 값(숫자·불리언·getter, 소비 위치마다 다시 읽음)·장기 획득 종류/다리 TYPE getter 를 갖는다. 실제 Player 기록 9칸(0xb4 바이트씩)을 묶으면 희생 결과는 `+0xa0`, 획득 플래그는 `+0x71` 을 읽고 쓰며, 크기가 다르면 거부한다.
- **정기 분배 (`handle`):** 가상표가 실제 룬(0x005075d8)이나 다이스(0x00507950)가 아니면 거부한다. 룬은 304 에서만 같은 소유자 다이스 검색 → (범위 안이면) 전체 진행 → 룬 삭제(flags 0x48) 후 -1 이고 그 밖의 사건은 payload 를 그대로 돌려준다. 다이스 305 는 현재 프레임 f 와 f+1(int32 감김)의 단계를 **f+1 먼저, f 나중**에 조회해 f+1 을 지정하고 같은 단계면 0.1(float32)·아니면 0, 306 은 희생 진행, 307 은 count 가 0 이 아니면 현재 강한 사제로 의식(mode 1) 후 0·0 이면 공통 Damageable, 그 밖은 Damageable 이다.
- **진행 (`progress`):** 단계는 처음 한 번 읽고, 강한 사제가 있으면(풀 범위 안) 604 중지를 한 뒤, 단계 4 미만이면 권한이 있을 때 다리 명령(`bridgeCommand(dais, 0, 0)`) → 붕괴(`collapse`: 새 공유 305 예약 → 현재 단계 목표점에서 `altarBurnCollapse.wav`)이다. 단계 4 이상이면 `itIsDone2.wav` → 포획 업그레이드 여부(`mask 4`, 종류 = 다이스 TYPE)에 따라 `priestSacrifice4.wav`(1.5초)/`priestSacrifice2.wav`(4.0초)와 `thunderCrack.wav`(2.8초) 지연 소리(각 확보·부착 성공 뒤에만 벽시계+지연을 기록) → 업그레이드면 희생 시작, 아니면 포획 종류가 있거나 시간 억제 중일 때 제단 이탈(조회 결과를 버리는 다이스 조회 → 제단 L 프레임 → 공유 24 예약 0.12)이다.
- **희생:** `startSacrifice` — 희생 중 비트(extra +40 의 비트 1) → 제단 M 프레임 → count 1 이면 다이스 0, 2 이면 45 → 공유 306 예약. `sacrificeAdvance` — 전역 169 코드 구간에서 같은 글자 구간 안으로 한 칸 돌아 `current <= next` 이면 다음 프레임 지정 후 0.12, 아니면 희생 중 비트만 지우고 종료 본문(0)이다(코드표 밖/음수 프레임은 거부). `finishSacrifice` — cue 정지 → 제단 P 프레임 → (시간 억제가 아니고 업그레이드 포획이 있으면) count 별 다음 첫 프레임 `[3, 64, 120, 0]`·**가상 count 앞에서 보관한 Player 결과 주소**에 현재 count·포획 Form 삭제(flags 0x400048)·사제 포획 Form 삭제 후 제단 표면 WORD 0 지정(현재 다리 TYPE 이 제단 TYPE 이면 표면 통지)·로컬이면 업그레이드 안내, 아니면 포획 종류 획득(시간 억제가 아니면 `grantCapturedType`)·결과 기록 → 항상 owner 1..8 갱신 → (시간 억제가 아니면) 로컬 메뉴 갱신·사제 사망 안내(원래 owner 가 로컬이면 상태 helper 값 포함, 둘 다 아니면 타인 안내) → 시간 억제 중이고 다이스 owner 가 로컬이면 SP 5000 과 사제 존재/동맹 확인 뒤 죽은 상대가 있으면 안내이다.
- **다리 (`canBridge`·`moveAwayDepth`·`bridgeCommand`):** 자격은 4단계 추상 룬 거부 → 제단 조회 → 제단 방향 M/L(12/11) 거부 → 내용물 첫 후보·next 를 사제 genus 진단(`priest.getGenus() & gPRIEST`, `.\Dais.cpp:0x140`) **전에** 저장 → 사제 genus 비트(0x200000)와 owner 일치 → 후보(`mask 0x20` 이고 종류 = 현재 사제 종류)의 원래 owner(하위 7비트)와 현재 동맹이 0 인지이다(진단 뒤에도 현재 TYPE/owner/종류/동맹을 다시 읽음). 이동 깊이는 현재 첫 경로 Form 에서 읽고(없으면 0) 진단은 저장 깊이(음수 `0x87b`, 3 초과 `0x87c`)·반환은 현재 깊이이며 진단 중 경로 수명이 끝나면 거부한다. 명령은 사제 확정 → 자격 → 단계 5 이상 거부 → 목표 단계(`단계 + (currentStage ? 0 : 1)`, 4 초과 거부) → 사제가 이미 목표 칸이면 의식 mode 0 → 권한 → 깊이+1 이 4 이상이면 중단 → `PathStart`(replaceStart 1·꼬리 = 다이스/목표 단계) → (null 이면 진단 `p`, `.\Dais.cpp:0x18e`) 마지막 꼭짓점 교체 → Prepare(0, 속도, 회전) → 깊이 기록이다.
- **훅 공장:** `makeDaisRegularHooks(pool, frame, host, assets, reward, state, hooks)` 는 실제 `SquidFrame.set`·`Host.addSharedRegular`·`RawAssetRegular.damageableHandle`·`SquidReward.addSp(현재 로컬 owner, delta)` 를 연결한 새 묶음을 돌려주고 나머지 훅은 보존하며 풀이 다르면 거부한다(CD 의 로컬 SP 직접 저장은 옮기지 않았다).

## 4. 변형 확인과 남은 경계

- 연산자·상수 변형 314 + 29 = 343회를 적용했다. 1차(원관측+DaisChecking 이식만)에서 약 100개가 남았고 그 대부분은 **시험의 공백**이라 위 웹 계약 시험을 추가해 잡았다(관측의 장면은 한 가지 자산·한 가지 owner·획득 플래그 초기값이라 상태 객체의 폭·경계, 풀 밖 SID, 희생 count 별 프레임, 단계 읽기 횟수, 좌표 절삭 경계, 원래 owner 의 WORD 폭 등이 가려져 있었다).
- 남은 동등 변형 18개(이유 9가지): `floatAt` 의 임시 버퍼 크기 4→5(`setUint32/getFloat32` 만 쓰므로 무관)·좌표 절삭 하한 −2147483648 → −2147483649(그 사이에 표현되는 float32 가 없음)·독립 희생 결과 저장소 크기 확대 두 건(필요 이상으로 커도 같은 칸)·`#localOwner` 초기값(생성자가 덮어씀)·4바이트 보기에 대한 `<=`/`4→5` 쓰기 네 건(범위 밖 쓰기는 무시)·`codes` 안 글자의 구간 내 포함 조건 `&&→||`/`<`→`<=`(현재 프레임은 항상 자기 구간 안)과 `count <= 0` 보호 두 건(존재하는 글자의 구간 길이는 1 이상)·사제 SID 범위 보호 두 건(그 앞의 자격 판정이 사제 슬롯을 먼저 읽어 도달하지 못함)·`captured && captured < capacity` 세 건(finder 가 돌려주는 SID 는 항상 실제 슬롯이며 첫 포획 Form 은 업그레이드 조건에서 이미 존재가 확인됨)·`findDaisAt` 의 `return 0`(결과를 버림).
- 시험 중에 먼저 실패한 곳은 모두 시험 쪽이었다(604 삭제가 부르는 경로 프로세스 정리 훅이 금지 훅이었던 입력, 강한 사제를 찾지 못하는 합성 위치, 해시 사슬에 남은 표 밖 TYPE 제단이 finder 에서 먼저 거부되는 입력). 모듈은 관측 대조에서 바뀌지 않았다.
- 다음 7-P3 항목은 **RawAltarSacrifice**(263줄 +24; RawDaisRegular·RawDamageablePreDestroy 선행은 끝남)이며, 같은 `raw-ritual-regular.js` 에 제단 정기 `RunAltarRegular` 를 이어 옮기고 `daisprogress` 의 handle 1,056행으로 대조한다.
