# dotnetpj 0.508 — Carrier의 실제 PATCH 도달 순서와 현재 전역

2026-11-14, HJOW-Athlon. 0.507에서 확인한 기존 Carrier의 선행 검사 차이를 최신 cpp 계약으로 바로잡았다. 호스트 요새 Pop과 AI 생성은 아직 미연결이다.

## 구현

기준은 `0a67c2bf41336c6751ef6668a790ea583735d876`의 `o/RawCarrierPostPop.h/.cpp`, `CarrierParentCurrentTests.cpp`, `CarrierPostPopTests.cpp`다.

- PATCH의 직접 Carrier/Damageable은 일괄 사전 검사를 부르지 않는다. 비최초 flag에서 현재 boss가 거짓일 때만 check를 부르고, 그 뒤의 현재 raw로 지면/공통 효과를 수행한다. 선택된 효과만 도달 시 요구한다. 실패 전 check/ground 변경은 유지한다.
- 최초 flag의 반환을 버리는 genus 조회도 현재 TYPE의 물리 범위 접근을 먼저 한다. 로딩0이나 간헐천/extra 관문이 생략하는 읽기와 구별한다. 낮은 내부 TYPE·예약SID·free/contained를 PATCH의 추가 사전 관문으로 쓰지 않는다. 실제 하위 몸체가 필요한 계약은 해당 하위에서 검사한다.
- 권한·로딩 깊이·간헐천TYPE는 실제 현재 getter가 있으면 그 값을 읽고 독립 입력은 보존한다. C++의 포인터 대여는 C#에서 현재 값을 읽는 delegate로 표현했다.
- TYPE는 생성 시 원문처럼 소유 사본을 만들고, 실제 PATCH 월드는 `BindCurrentTypes`로 현재188TYPE를 빌린다. 잘못된 새 대여는 기존 연결을 보존하고 빈 입력은 원래 소유 사본으로 돌아간다. 효과 함수도 원문 함수 객체처럼 복사해 보관한다.
- CD 독립 몸체의171TYPE·owner32·extra35·기존 사전 검사 계약도 보존했다. CD 게임 호스트나 CD 복원 작업을 추가한 것은 아니다.

## 검증

기존 `carrierpostpop-x86.tsv`의 3판본 각2448입력, 총7344입력을 전수 재생해 실제 효과순서와 raw50/36바이트가 일치했다. 기존 C# 검사가 PATCH에서 기대하던 사전 검사 횟수1을 원문처럼0으로 바꾸고 CD는1을 유지했다. 값 자체를 바꾸는 원본 관측 파일은 수정하지 않았다. SHA256은 `4efa1cd19250a64a436a9c9bddeaa15f88429fcd8e5b7aa2c9b0dfd4eca31124`다.

C++ 현재 부모 계약12건과 공유 boss 검사1건을 옮겼다. 현재 TYPE/깊이·좌표/owner 재조회, 조건부 읽기 생략, 실패 전 부분 효과, 대여 검증·소유 사본 복귀, 예약/비활성 슬롯, 최초flag의 boss 읽기 생략을 검사한다. 원래의 선행 검사 거부 검사는 cpp처럼 CD 계약으로 유지했다. PATCH의 AI 통지 실패는 앞선 지면 효과 뒤에 오므로 해당 기존 기대 순서도 수정했다.

검사 입력 풀은 cpp 장면과 같이 판본별 한 번 확보한 뒤 매 행 raw 입력을 다시 채운다. 이전 행의 출력으로 다음 입력을 만들지 않으며 불필요한 반복 대용량 풀 할당을 줄였다.

신규 공유 boss 추가 전 관련 집중24건이 통과했다. PATCH의 사전 검사를 다시 넣는 대표 변이는 현재 계약13/13 실패를 검출했고 원복했다. 원복 뒤 전체 비증분 Release 빌드는 경고0·오류0이고, 자산 후처리의 낡은 사전 검사 횟수 기대도0으로 맞춘 뒤 관련집중64건을 통과했다. 자산 원본 기대값은 그대로 유지했다. 산출물은 `extracted/dotnet-carrier-current-0508/`에 둔다.

PORT_MAP은 기존 CPP행의 기준을 현재 구현으로 갱신하고 헤더1행을 추가해710행(L1 346·port364)이다. fixture245개·기존 해시는 유지한다. 새 게임 실행·포획/희생/공격/승리·MP·신규 NB·외부 접속·기존 경로 은퇴는 없다. 보호 파일·cpppj·LEFT_JOBS.md·병행 webpj는 보존했다. M1은0/34다.
