## 실제 소유자와 시작 순서

HostMissionAudio.SceneMusic은 기존 같은 SceneMusicState·GameRandom·현재 Surface 희생/대기실 조회·현재 이름/길이/선택기·동적 벽시각·현재 옵션을 사용한다. 표시 갱신·같은 파일 팔레트·실제 TYPE55·효과음도 C/D/E의 장치를 빌린다. 생성/바인딩에서 시계·파일·곡·난수를 소비하지 않는다. 명시 누락과 중복 바인딩을 거부하며 장치 닫기/재열기가 감독을 새로 만들지 않는다. StartScene(bool)은 CPP처럼 fallback Battle만 쓰고 실제 CurrentBattle getter를 덮어쓰지 않는다.

실제 색표/장기 음향 준비 위치에서 감독을 한 번 연결하고, 현재 Tints는 기존 fort 후단에서 공급한다. SP 표시 갱신은 원문처럼 현재 메뉴가 있을 때만 실제 갱신기를 호출한다. 희생·대기실을 임의 false로 채우거나 별도 BattleSession을 만들지 않았다.

Clock/Player·Issue·Intro·첫 Scene·Chat·전체 domain은 각각 ClientStartupStep으로 완료 접두와 최초 ExceptionDispatchInfo를 보관한다. action 정상 복귀 뒤에만 완료로 기록한다. 부분 실패 뒤 자동 재실행·rollback은 없으며 재진입도 명시 실패한다. 내부 action이 재진입 예외를 잡더라도 성공으로 바꾸지 않는다. Clock만 성공하고 Player가 실패한 경우 Clock을 반복하지 않는다. 기존 Issue/Chat을 한 bool 아래 연속 실행하던 경계를 나누고, UI 생성 뒤 늦게 하던 Intro 감지를 Issue 뒤로 옮겼다.

LoadContent는 GPU 출력과 Native domain을 구별한다. GPU 텍스처/SpriteBatch는 반납·재생성하고, 성공한 같은 메뉴·입력·미션·채팅·음향·Scene·생산 문맥은 유지한다. 새 출력에는 현재 논리 픽셀 전체를 업로드한다. MonoGameScreenOutput에 실제 Texture2D.Dispose를 연결했으며 Game 최종 반납에서도 같은 출력/배치를 장치보다 먼저 폐기한다. GPU 할당 실패/실제 장치 손실 전체 복구와 Native State 재시작을 이 경계의 완료로 확대하지 않는다.
