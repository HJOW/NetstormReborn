# 커서 사정거리 표시 이식 (WB04-E550)

F(입력·커서·선택)의 "커서" 중 `client/RawCursorRange`(원문 10.78 474520 생성자·474b80 프레임·474c30 직선·474ed0 원형·474790 통지·474870 소멸과 `CursorRangeProcess`)를 `webpj/www/core/raw-cursor-range.js`로 옮겼다.
기준선 `225553df`와 현재 cpppj 소스가 같음을 확인했다. 마나(E549)와 같은 `CursorManaGlobals`(맵 한계·대체점)·`CursorDropState`(커서 토큰)·`SquidProcessState`(현재 시각)를 빌리고, 방향/발자국/프레임은 실제 `RawGunTarget`에 맡긴다.

## 옮긴 범위

- 필드: 원본 `new(0x200)` 512바이트를 `Uint8Array`로 보존한다(100칸 DWORD SID 목록·+1a4/1a8 개수·+1b0 사거리·+1b4 반경·+1d0/1d8/1e0 double 시각·+1f0 네 방향 허용). float는 저장 위치에서만 단정도로 좁힌다.
- `construct`(474520): 현재 부모 TYPE의 group에 따라 직선(group 1 캐논·group 6 펜스는 Cannon 방향 제한을 읽지 않음) 또는 원형을 고른다. Wind 아처는 모드×45°로 관측각(시작/끝/반폭)을 정규화해 만든다.
  사거리는 현재 TYPE 또는(flags2 0x30000) 첫 내용물의 WORD로 조회하고 변당 개수는 `_ftol(사거리×0.2)`이다. 직선은 방향별 현재 개수로 100칸 목록에 색인해 만들고 원형은 8개를 A/B 첫 프레임으로 만든 뒤 대체점에 둔다. 마지막에 `attach(…, 0x10)`와 시각/상태 초기화를 한다.
- `frame`(474b80)·`rays`(474c30)·`circle`(474ed0): 직선은 간격·성장 위상·방향별 발사구/핫스폿 원점·거리로 위치와 애니메이션 프레임(`_ftol(거리×2) % 개수 + 첫 프레임`)을 정하고, 원형은 반경을 키우거나(15/초) 줄이며(30/초) 각도·Wind 관측각(최소 구간 포함 판정·가까운 끝점·계수)으로 둘레에 놓는다. 가상 효과 뒤에는 현재 개수·시각·부모·목록·숨김을 다시 읽는다.
- `notify`(474790)·`destroy`(474870): 이벤트 3/1/그 밖, 100칸 고정 SID0 건너뜀, 소멸은 free만 제외(dead도 제외하는 마나와 다름).
- `CursorRangeProcess`/`createCursorRangeProcess`/`bindCursorRangeLifecycle`(생성 `createRange`만; 제거·이벤트 분배는 마나 쪽 `bindCursorManaLifecycle`이 같은 Kernel 번호로 처리)와 공개 정적 보조 `normalize`/`contains`/`angleDistance`(직접 값 검사용).

## 시험

1. 원본 관측 `cursor-range-x86.tsv` **593행**: 58 DWORD 독립 입력(생성·직선/원형 프레임·통지·소멸·연속 호출)의 효과 순서·512바이트 필드·전역·raw 슬롯 102개·단계별 필드 전부, 방향/발자국은 실제 `RawGunTarget`을 같은 풀·해시에 연결. 기본/64비트 두 관측이 같은 행(뒤 다섯 열 `-`)이다.
   처음에는 시험 장면의 `LetterRun` 필드 순서(C++ 집합 초기화는 `{first, count}`)를 잘못 넣어 어긋났고 장면을 고친 뒤 **593행 전부 일치**했다(모듈 수정 없음).

3. 변형 확인에서 드러난 미관측 경계의 계약 시험: 각도 정규화/포함/거리 직접 값(0·−360·360·180도 구간 양 끝), 좌표 제한 경계와 정수 감김, 생성의 대체점/목록 넘침(정확히 100개)/TYPE 범위(부모·현재)/내용물 사거리 WORD/Wind 모드 부호 없는 폭,
   원형의 Stop/델타 float 저장/기한·닫힘 경계/void·dead 건너뜀/Wind 상한 360/중심 합 경계, 직선의 단정도 중간 저장(간격·위상·원점·시작·거리·가시·좌표 제한)을 각각 구분하는 탐색 입력 7종, Run 개수 0·변형 전달·dead 재해제.

**변형 확인:** 각도/좌표 보조·생성(group/범위/개수/Wind)·직선·원형·통지/소멸·프로세스/수명 연결의 비교·상수·필드 오프셋·효과 인자·단정도 저장 위치 243가지를 넣어 226가지가 시험에서 잡혔다.
처음에는 85가지가 살아남았고 위 계약 시험으로 68가지를 잡았다. 남은 17개는 동등 변형(또는 시험으로 구성할 수 없는 경계)이다:
① 구간 끝이 같은 때의 교환 조건·각도 거리 180 경계(두 식이 같은 값). ② `raw` 상한·부모 SID 상한(풀 크기와 같을 때도 뒤따르는 슬롯 조회가 같은 `RangeError`). ③ 직선 생성 목록 하한(`index<0`)은 도달할 수 없다(개수와 항목이 모두 0 이상).
④ Wind 관측각의 이중/재정규화 4개(`normalize`는 한 번 적용하면 [0,360]에 들어 멱등). ⑤ 개수 배율 `fround(0.2)`↔`0.2`(사거리가 단정도여서 같은 정수로 절삭). ⑥ 직선 곱 단계(`item*step`에서 `step`이 이미 단정도). ⑦ 반경이 한계와 같을 때 성장 상한과 닫는 중 하한 `value<=0`↔`<0`(같은 값 저장, −0 도달 불가).
⑧ 원형 위상의 시간 정수부(`timeInteger`↔`trunc`)는 게임 시각이 2^31초 미만이면 같다. ⑨ `contains`는 끝점 순서를 바꿔도 같다(함수 내부에서 교환). ⑩ 가까운 끝점 선택의 `<=`↔`<`는 두 거리가 정확히 같을 때만 다르며 연속 각도에서는 구성하지 못했다. ⑪ 수명 연결의 Form 상한(65535↔65536)은 호스트가 같은 `RangeError`로 거부한다.
