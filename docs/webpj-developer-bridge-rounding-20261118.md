# WB04-E759 개발자 다리 주기 단정도 반올림 교정

[E756](webpj-developer-bridge-period-20261118.md)의 `setbridgekillperiod` 입력이 JavaScript double을 거친 뒤 `Math.fround`를 사용해 단정도 경계 바로 위 값을 중간값으로 잘못 반올림하는 오류를 고쳤다. 긴 16진수에서 앞 13자리만 사용하던 경로도 같은 문제가 있었다. 십진·16진 유효숫자를 정확한 정수 비율로 해석하고 IEEE 754 단정도로 한 번만 반올림하며, 정확한 중간값은 짝수 가수 쪽을 선택한다. 부호 있는 0·비정규 값·오버플로와 기존 입력/출력 순서는 보존한다.

예를 들어 `0x1.0000010000000001p0`와 `1.0000000596046447753906251`은 이전 코드에서 1이었지만 Windows UCRT `%f`와 같이 단정도 `0x3f800001`로 바뀐다. 두 값의 정확한 중간점은 `0x3f800000`이다. UCRT로 별도 확인한 경계 19건을 비트 단위 회귀 검사에 추가하고, 고정 난수 시드로 만든 십진수·16진수 500건도 UCRT와 대조해 모두 일치했다. 기존 명령 집중 검사 3건과 실제 Session의 31h 패킷 집중 검사 1건이 통과했다.

기준 cpppj `RawCampaignSession.cpp`의 주기 명령은 `225553df` 이후 변경되지 않았다. 이 검사는 Windows UCRT와의 정적 함수 비교이며 원본 게임을 실행하지 않았다. 전체 IEEE 입력과 각 브라우저의 저장 상태는 이 검사 범위 밖이다.

Node v26.13.0 전체 회귀 6,258건이 통과했고 실패·취소·건너뜀은 0건이다. 대응표 오류는 0건이며 E753의 v22 검사 뒤 여섯 번째 v26 전체 회귀다.
