# dotnetpj 0.821 — 미니맵 기하·셀 그림과 공유 갱신 전역

작업일 2026-11-22, PC HJOW-Athlon. 0.820 전체 감사 뒤 실제 게임 Root에 필요한 미니맵 선행 본체를 이식했다. 실제 미니맵 공통 부모와 Root 설치는 다음 단위에 남아 있다. 유일한 실행 경로는 `dotnetpj/src/Netstorm.Game/bin/Release/net10.0/Netstorm.exe`다.

## 변경

- `MinimapGeometry`는 Source의 Rebuild/Target/Drag/ClampAttachment/PlanDraw 다섯 본체다. 원본 ftol의 하위 DWORD, signed 감김, float 중간 저장 위치, 자동 crop 억제와 바깥 드래그의 경계 포함 여부를 보존했다. 실제 지도 영역과 현재 칸 배율을 입력으로 받으며 화면 전체를 대신 쓰지 않는다.
- `RawMinimapRaster`는 같은 실제 Pool/Hash/TYPE와 현재 전용 색 전역을 빌린다. 2×2 초기화 → 지면의 Y/X 순서 → 해시 2/1/0의 X/Y·현재 next 순서, 일반점/Challenge 표식과 색 억제의 현재 프레임 BYTE를 이식했다. 지면/타입/좌표를 별도 아이콘 목록으로 바꾸지 않는다.
- 기존 `MetadisplayDirtyState`에 `SharedFullRefresh`를 추가했다. 연결한 `UIntBox`의 같은 DWORD를 즉시 읽고 쓰며, 생략한 독립 입력의 자체 값도 유지한다. 실제 Root에서는 같은 `ClientGameplayGlobals.MapRevision`을 공급해야 하며 이번 단위에서 그 설치를 완료한 것으로 기록하지 않는다.

## 검증

최종 집중 검사는 **Core 13·Client 215, 합계 228건 통과/실패 0**이다. 실제 신규 검사 이름은 Core 5·Client 3의 8개이며 0.819의 모든 Client 집중 검사 이름도 보존했다. 전체 회귀의 마지막 기준선은 계속 0.820의 5,848건이며 다음 정기 전체는 0.824다.

기하의 외부 콜백 변이·중단 26행은 순수 API가 소유하지 않는 범위여서 통과 수에 포함하지 않았다. 실제 공통 부모의 입력/수명/콜백 검사에서 별도로 대조해야 한다. 기존 관측 파일은 복사·변경하지 않고 Core 1개·Client 2개 소비자 링크만 추가했다.

첫 관문은 순환 체인 검사의 잘못된 풀 크기 22,000 때문에 Core 12통과/1실패로 종료했다. 실제 최소 범위를 확인하고 테스트 풀을 24,000으로 고친 뒤 Core 13건이 통과했다. 제품의 풀 범위 검사를 완화하지 않았다. 이어 새 테스트 보조 함수에서 생긴 xUnit2031 경고를 없애고 Client 215건을 다시 통과했다. 최종 솔루션 증분 Release 빌드는 오류 0·기존 Client 경고 3이며 새 경고는 없다. Core 검사 어셈블리는 이 정돈 전후에 동일했고 Core/Client의 실제 제품 사본 각 4/6개도 실행본과 바이트·해시가 같다.

같은 제품 빌드로 thewarbegins/tutorial1/surrounded에 진입해 모두 종료 0을 확인했다. 전체 덤프 바이트와 경로 지표가 0.820과 같으며 원본 1,392개 파일과 실행 6개 파일이 불변이다. 테스트 보조 함수 정돈 뒤에도 실행 6개 파일이 같은 해시임을 확인했으므로 시작 수집을 중복하지 않았다. 플레이 재현 입력은 보내지 않았다. M1은 0/34, 고정 수신 본문은 18/26으로 남아 있다.

제품·검사·대응표 1,856개 파일의 최종 관문 전후 해시가 같다. 자료는 433건/439개 물리행, 대응표는 1,558건/1,563개 물리행(port 1,070·L1 481·session 7)이다. 이전 모든 값·순서·base를 보존하고 자료 3건/대응 5건만 추가했다. `cpp_sync --ports-add`가 전체 행을 재정렬한 것은 새 행만 추출해 기존 순서로 복원했고 독립 감사로 확인했다. 새 Source 쌍은 현재 내용과 동일한 마지막 실제 Source 커밋을 가리킨다. AGENTS·README·공통 인계·CPP Source/검사·원본/CD는 변경하지 않았고 원격 push도 하지 않았다.
