# webpj 채팅 이름 자동완성 원본 관측 연결 (WB04-E484, 2026-11-15)

3.8절 이월 목록의 채팅 계열 중 `chat-completion`을 원본 10.78 독립 x86 관측 **189행**에 대조했다. 189행 모두 첫 실행에서 일치했고 이식 결함은 나오지 않았다. `PORT_MAP`과 모듈·시험 머리의 "전용 PE fixture 없음/cpppj에도 직접 시험이 없다"는 오기였다.

## 비교한 것

`tests/chat-completion-native-fixtures.test.mjs`가 cpppj `ChatNameCompletionTests`의 입력 구성을 옮긴다. 행 사이에 원문 BSS(0x4090바이트 상태)를 유지하고 `reset` 열이 1인 행에서만 새 상태로 시작한다.

- **입력 열**: 상태 초기화 여부, 현재 Chat 기록 4800바이트(100행 × 48), 번역 모드(1 프랑스어형·2 전부 `dup`·3 ALLIES 빈 값·4/5 BATTLE 을 127/128자로), 질의(`~`는 null), 길이, 방향.
- **관측 열**: 반환(후보 문자열 또는 `~`=없음), 상태 0x4090바이트 전체(끝의 0은 줄여 비교), 외부 호출 순서(번역 키 `T:`와 단언 `A:`).
- **다룬 경로**: 번역 중복/빈값, 128바이트 넘침(127·128), 100행 기록의 Subscriber 수집, 현재 기록 변경, 접두 잔류, 정/역방향 순환, 두 번째 이탈에서만 없음.

## 독립 확인과 변형 확인

자동 변형 108개 중 77개가 잡히고 31개가 생존했다. 생존 중 실제 공백 12개를 기준선 소스(`ChatNameCompletion.cpp`)의 계약으로 독립 시험을 더해 닫았다:

- 번역/질의 안의 첫 NUL 절단(`'ab\0cd'`→`ab`, `'\0xyz'`→빈 후보, 질의 `'ab\0cd'`→접두 `ab\0\0\0`, `'\0ab'`→전부 0).
- 대소문자 경계(`z`는 `Z`와 같고 `[`는 `{`와 다름).
- 길이 진단 경계(126 은 진단 없음, 127 은 `0x354`)와 strncpy 물리 한계(0x4088 허용·0x4089 거부), 접두 폭 밖의 이전 꼬리 보존과 폭 안의 영 채움.

남은 19개는 동등 변형이다.

| 줄 | 개수 | 사유 |
| --- | --- | --- |
| 12·62·70 | 4 | 후보 수 128 한도와 채널 이름 128자 한도: 채널은 고정 이름(≤8자)이고 후보는 채널 5 + 기록 100 이하라 도달 불가 |
| 23 | 5 | 상태 DWORD(인덱스·길이·개수)의 값 범위가 작고 음수는 −1 뿐이라 높은 바이트 이동 변경이 같은 결과 |
| 29·30·37·46 | 8 | 상태 물리 범위 방어(NUL 없는 문자열·후보 복사·비교 범위)로 상태가 항상 NUL 종단이라 도달 불가 |
| 38·78 | 2 | `<=`가 쓰는 한 칸은 이미 쓰는 종단 0 과 같은 값(`charCodeAt(len)`은 NaN&255=0) |

## 남은 것

채팅 계열 나머지는 `chat-callbacks`(30행)·`chat-input-recipients`(721행)·`chat-window`(180행)·`chat-window-base`(167행)이다. 장치 구성(노드/버퍼/Slider/할당 블록)은 이미 E483 의 `EntryScene` 으로 갖춰져 있다.
