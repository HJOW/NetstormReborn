## 이식 (증거)

- `dotnetpj/src/Netstorm.Client/Host/HostSession.AiBrains.cs`: `BuildLiveAiCreateHooks`에 live `InitialUpdate` 결선을 추가했다. `initialUpdate` 주입이 있으면 그대로 쓰고, 없으면 `typeTable`이 있을 때 실제 기술·목록 몸체를 잇는다(`typeTable`도 없으면 기존처럼 생성 전 명시 거부). live 몸체는 같은 세션 풀·기록·TYPE의 `RawSquidFactory`+`RawContainedCreate`(풀 체인 부착)+`RawCarrierPreDestroy`+`RawPlayerTechnology`(`BindPlayerTechnologyTypes` 실제 표 조회)+`RawAiBrainInitialUpdate`를 공유한다. 워크샾 `{86,87,88,85}`·제외 `133`·`MissionMode=WorldGlobals.MissionPost`는 cpp 563~564·2806행 상수와 같다. `player`/`contained` 주입 시 흐름의 live 몸체를 쓰고, null이면 최소 live(빈 풀 찾기 0·공장 생성·풀 체인 부착)로 잇는다. 근거: cpppj `src/client/RawCampaignSession.cpp` 2793~2806행의 초기 갱신 조립이다.
- 같은 파일에 `CreateMissionAiBrains(players, table, definitions, defaultName, ...)`를 추가했다. 원문 `RawMissionStart` 163~165행 루프와 같이 활성·전산 소유자 중 로컬이 아니고 사제가 있는 소유자만 실제 brain을 만든다. 요새 장치가 연결됐으면 live 화신·내용물 몸체를 쓰고, 아니면 최소 live로 잇는다. 사제 조회는 `RawPriestLookup`으로 같은 세션 사제 목록을 읽는다. NoTemple 소유자는 삭제 몸체가 없어 명시 거부한다(출하 미션에 NoTemple 인공지능이 없음을 `originals/d`·사본 영문 대본·TEST01 전수 grep으로 확인).
- `dotnetpj/src/Netstorm.Client.Host/ClientHostGame.cs`: `StartMission`의 `worldLoad.Load()` 뒤에 `CreateMissionAiBrains` 호출을 연결했다. 기본 AI 이름은 설정 `defaultAiName`→표시 부호화 live 조회다(근거 cpppj `CampaignClientServices.cpp` 132행).
- `dotnetpj/tests/Netstorm.Client.Tests/HostSessionAiLiveCreateTests.cs`: 신규 2건(live 초기 갱신 기술 확보·이름 기록·지갑 보존, 사제 없음 스킵). `thewarbegins` 2번 AI로 기술 부모(+0x9c)·시작 기술 3종 체인·이름 `The Jailer`·지갑 보존을 대조했다.
