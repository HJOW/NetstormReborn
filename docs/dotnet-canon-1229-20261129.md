## 구현과 범위

ClientOptionsInterpreter는 현재 CPP ClientMain::InterpretOptions에 복원된 순서를 같은 실제 소유자에 연결한다. 압축→Monitor→tracelevel→showSoftAsserts→언어/커서→요청 창 기하→우선순위/위치→도움말/기록 요청·DebugBurst0→음향 값 읽기/안내→채팅/파일→양보/구름/FPS→치트/네트워크 순서다. 같은 Config/Client/활동/언어/값 하위를 검증한다. Monitor의 명시 재해석 입구도 같은 기존 본체를 재사용한다.

ClientOptionGlobals는 별도 우선순위/초기 위치/양보/FPS/간격과 기존 ClientTraceGlobals를 보유한다. 누락 FPS는 원문75에서 다시 읽고 양수만1/FPS,0이하 간격은0이다. 같은 기록 요청 상자만 지우며 열린 파일/enabled는 유지한다. 음향 옵션은 CPP처럼 읽기만 하며 장치 Apply/재열기를 추가하지 않는다. 새 Trace는 실제 Graph 로그의 필터/FILE/공유 버퍼와 현재 Chat/8DWORD 문맥에 연결했다.

ClientWindowOptions는 논리/표시 요청과 별도 창 치수를 유지한다. 설정 정규화 뒤 먼저 요청 크기를 쓰고 WindowRect→ClientRect→두 기하 계산→Move 순서다. 원문 MoveWindow의 높이 인자에도 WindowWidth를 쓰는 동작을 그대로 유지한다. 변경이 없으면 HWND getter/OS를 선택하지 않는다. 이 몸체는 Screen 버퍼를 재생성하지 않는다.

실제 Windows 어댑터는 선택된 변경에서만 HWND를 한 번 캡처하고 두 사각형/MoveWindow에 재사용한다. 실제 Game에서는 SDL의 고정 창 제한 때문에 프로그램 이동이 기존 크기로 되돌아갔다. 이동 동안만 AllowUserResizing을 허용하고 정상/예외 뒤 이전 상태를 복원하도록 보완했다. 계산/인자는 원문 그대로이며 선택되지 않은 경로에는 이 대여도 없다.

같은 부모가 사용하는 새 공통 해상도 정책을 기존 ScreenResolutions에 반영했다. 기본7행은 원본3개와1280×720/800/960/1024다. FSR12출력/논리1280 변환·현재 지원 판정·옛 큰 값/잘못된 작은 값/거리 동률의 복구를 CPP와 동일하게 제공한다. 실제 FSR 장치가 아직 없어 Game/최초 할당은false로 판정하며 고해상도 저장값을 먼저 복구한다. HostOptions와 해상도 메뉴도 이 목록을 사용한다.1920을 일반 해상도로 노출하지 않는다.

**미완료 범위.** 현재 복원 CPP 몸체의 부모/실제 장치까지 연결한 단위다. 원문435220의 미복원 부분, 전체 Native 시작/SP 순서, 변경 구독의 전체 원문 순서, 실제 State cleanup/State7 호출은 남는다. Native FPS/양보/우선순위 값의 나머지 실제 루프·명령 소비자도 후속이다. DN-RES-1의 HostOptions 표시/논리 크기 분리와 DN-RES-2~4의 실제 FSR·SETSIZE/Screen/메뉴·입력·세션 재생성/전체화면·배포 관문을 완료로 세지 않는다. 옛11파일 후보를 수입한 작업도 아니다.
