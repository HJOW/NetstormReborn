## 구현

`HostSession.SquidMutations.cs`는 기존 `RawSquidMutationReceive`를 실제 Host의 공장/WORD setter/내용물/HP환불과 연결한다. 2dh 내용물은 현재 ContentForm6의 실제 정렬·부모 통지를 필수로 사용하며, 다른 세 내장 Form과 지원 자산의 실제 가상50을 구별한다. 65h 감시는 현재 가상74의4af160→4ac800 점프만 공장 부착으로 연결한다. 네 내장 VT를 중복 정의하지 않도록 기존 `RawSquidForms.Vtable` 조회를 공개했다.

감시/공통 Form Pop이 요청하는 실제 전송은 Native면 같은Storage.TransmitPop, typed면 같은 월드 writer로 보낸다. Source의 현재 TYPE/버퍼/헤더를 사용하며 별도 패킷을 합성하지 않는다. 2eh는 현재 로그→HP 비례 환불→전체 가상삭제→SP 감사 순서다. 감사는 같은 사제 추적 표본/남은횟수·Client 진단·분산SP의 실제 offset/Get/첫pool/순열을 원문 위치에서 읽는다. PlayerKnown이 아닐 때 SP Get을 생략하고 첫 표본과 조건부 조회 뒤 표본을 구별한다.

53h/62h는 기존 실제 본체에 같은 월드의 전체 가상삭제 경계를 공급한다. 다중 삭제는 각 효과 뒤 현재 signed count/WORD를 다시 읽는다. `HostSquidPacketEffects.VirtualDestroy`는 실제 전체 가상10 분배를 받아야 하며 미설치 시 선택된 위치에서 실패한다. 일반 삭제 Pre/Post로 대체하지 않았다. 공통 진단 TYPE 이름은 Source처럼 첫NUL까지만 사용하며30h 상세 이름도 같은 조회를 빌린다.
