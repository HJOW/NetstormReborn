# 파일·디렉토리 경로 길이 기준

Windows의 긴 경로 설정과 Git `core.longpaths`에 의존하지 않도록 이름을 짧게 유지한다. AGENTS.md와 보호 원본게임 자료는 수정하지 않는다.

- 새 소스·도구·문서·보고서 파일명은 **확장자 포함40자 이하**, 디렉토리 이름은 **24자 이하**로 만든다.
- 저장소 상대경로는 **160자 이하**, 작업공간 루트를 포함한 실제 절대경로는 **200자 이하**로 유지한다. 더 긴 체크아웃 루트를 쓰는 PC에서는 실제 절대경로 검사를 먼저 수행한다.
- 분석 이력은 `cpppj/hist/<짧은 단위명>/`에 둔다. 저장할 파일을 명시하고 기존 `hist`, 빌드, 영상, 캐시 디렉토리를 재귀 복사하지 않는다. 이미 보존한 전체 원문은 경로·SHA로 참조한다.
- 보고서 파일명에는 같은 뜻의 `recovery-`와 `-evidence`를 반복하지 않는다. 작업단위 로그에는 짧은 `run15-...` 형식을 사용한다. 뜻이 긴 경우 디렉토리를 깊게 중첩하지 말고 설명을 문서 본문에 쓴다.
- 이름을 바꾸면 CMake/include/import, 실행 명령, 문서 링크, JSON의 파일키·전체SHA 참조를 함께 점검한다. 실제 원본 입력/기대출력은 이름 변경을 이유로 바꾸지 않는다.

기존 경로의 정리 대응은 [path-map.json](path-map.json)에 기록한다. 과거 파일에는 소스·보고서48자/이미지·로그64자까지의 예외를 두지만 신규 파일에는 예외를 확장하지 않는다. 새 파일을 만들기 전 `python -X utf8 tools/path_audit.py --candidate cpppj/src/client/NewWorld.h`로 확인한다. 작업단위 마감 때는 `python -X utf8 tools/path_audit.py`를 실행하며 CI도 같은 검사를 수행한다.

보존 이력 내부의 과거 `.gitattributes`가 원문 바이트를 변환할 수 있으므로 분석·스테이징 전에 `python -X utf8 tools/path_setup.py`로 로컬 `-text` 규칙을 설치한다. 기존 로컬 속성은 유지한다. 새 PC의 체크아웃에서 줄바꿈만 달라졌다면 `--restore`로 HEAD SHA와 내용 일치가 확인된 이력만 복원할 수 있다. 원래 Git/이동 전/이동 후 SHA와 후속 편집의 SHA를 구분하며, 엄격한 이전 보고서를 새 빌드 결과로 덮어쓰지 않는다.

2026-10-14 재개에서는 최장 180자·위반 0 및 두 프로젝트 Release 빌드가 확인됐다. 사용자가 최종 검사를 생략하도록 요청했으므로 마감 후 전체 SHA/참조/스테이징 blob 검사는 다음 작업에서 수행한다. [완료 결과와 인수인계](path-done.md)를 따른다.

2026-10-14 정리 전 Git 추적파일의 최장 절대경로는280자였고240자 초과55개/200자 초과200개였다. 분석 이력의 중첩복사 디렉토리와 긴 보고서·도구 이름을 줄인다. 참조와SHA 장부만 이관하며 원본 PE/입력 fixture/게임 동작 변경은 이 작업의 범위가 아니다. 전체 대응표는 당시 기준 `9d7acad`와 이관 전·후 SHA를 보존한다.
