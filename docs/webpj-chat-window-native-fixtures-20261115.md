# webpj 채팅 창 원본 관측 연결 (WB04-E485, 2026-11-15)

3.8절 이월 목록의 채팅 계열 중 `chat-window`를 원본 10.78 독립 x86 관측 **180행**에 대조했다. 180행 모두 첫 실행에서 일치했고 이식 결함은 나오지 않았다. `PORT_MAP`과 모듈·시험 머리의 "전용 PE fixture 없음/cpppj에도 직접 시험이 없다"는 오기였다.

## 비교한 것

`tests/chat-window-native-fixtures.test.mjs`가 cpppj `ChatWindowTests`의 입력 구성을 옮긴다. TextEntryGump 시험과 같은 장치 지원 틀(노드/버퍼/Slider/할당 블록/명시 장치)을 `tests/text-entry-gump-native-support.mjs`로 분리해 두 시험이 공유한다(E483 의 `EntryScene` 을 옮긴 것이며 E483 시험은 그대로 통과).

- **입력 열(앞 21열)**: 진입 이름(construct·create·destroy·normalize·handle), root 크기, 사건·인자·문자열 입력, 전투/도전/설정/수신 대상/이름 조회 결과, 세 자동완성 목록, 중첩 Console 노드 48필드·버퍼 10DWORD·할당 블록. 전역 읽기는 고정 값 표(없는 주소는 오류)를 쓴다.
- **명시 장치**: 자식 노드 생성/배경/로그/헬퍼, 가시 크기 맞춤, 번역/제목/도움말, 글자 측정(6×14), 명령 등록, 프레임 수/높이(−1·7·8·9·16·17·32767), 스크롤 요청, 기본 사건 처리(77 반환)/통지, 이름 조회·채팅 전송·진단 기록, 도우미 메뉴 장치 전체.
- **관측 열(뒤 10열)**: root 16필드, Console 48필드, 로그 4필드, 입력 접두, 입력 본문, 세 자동완성 목록, 호출 순서(공유 trace), 반환, 스택 정리량(construct 12·handle 16·그 밖 4), native 명령 수.

## 변형 확인

자동 변형 314개 중 236개가 잡히고 78개가 생존했다. 생존 78개를 기존 `chat-window` 시험과 `client-chat-window-globals`·`text-entry-gump` 시험까지 합쳐 다시 돌리면 21개가 남는다. 이 21개를 줄별로 확인했다.

- **실제 공백 1개**: 관측 fixture 의 `frameCount` 장치가 항상 7 이라 `count | 0`→`count | 1`(짝수 개수가 홀수가 됨)이 가려지지 않았다. 프레임 수 6 인 독립 시험(6 프레임만 높이를 읽고 높이 8..16 프레임만 아이콘 후보)으로 닫았다.
- **동등 변형 20개**:

| 줄 | 개수 | 사유 |

## 남은 것

`chat-window-base`(167행)는 cpppj 가 31열로 확장하기 전의 30열 보존본(83입력/166행, `docs/exe/cpp-chat-window-20261023.md`)이고 cpppj 시험이 읽지 않는다. 새 31열 자료(`chat-window`)가 같은 관측을 유지하며 초기화/수신자 제거/그룹 경계를 더한 것이라 이 단위가 대체한다(별도 소비자를 만들지 않는다). `chat-callbacks`(30행)·`chat-input-recipients`(721행)는 실제 Client(`RawMenuControls`·`RawChatRuntime` 허브)에 연결된 시험(`ChatWindowClientTests`)이 소비하므로 허브/Client 조립 이식 때 연결한다.
