# webpj 처음 방문 시작 화면 안정화 (WB04-E1300, 2026-11-24)

사용자 제보(2026-11-24): 배포본(`https://shuttingstars.pages.dev/etc/netstorm/`)의 "클릭하여 시작" 화면에서, 처음 한 번(캐시 없음)만 정적 파일을 받기 전에 스크립트 오류가 나거나 언어를 탐지하지 못해 영어로 뜨는 일이 있었다. 이후에는 캐시되어 재현되지 않는다. 요구: 처음 화면에서 리소스 로딩이 끝날 때까지(정 방법이 없으면 6초쯤) 기다린 뒤에야 클릭이 가능하게 한다.

## 재현과 원인

- 배포본을 브라우저 창에서 열어 보면(한국어 선호 `ko`) 이 한 번은 오류 없이 한국어로 `clickToStart`에 도달했고 요청 98개가 모두 200이었다. 재현은 못 했지만 코드에서 처음 방문 때만 생길 수 있는 경합·단일 실패점을 찾았다.
- **단일 실패점(영어 대체·오류 화면의 원인).** `AssetLoader.loadBundle`은 묶음의 파일(메뉴 약 40개, 한국어 묶음 60여 개)을 `Promise.all`로 한꺼번에 받고 **하나라도 실패하면 묶음 전체가 실패**한다. 캐시가 없는 처음 방문에서 이 100여 요청 중 하나가 일시적으로 실패(연결 끊김·429·5xx·잘린 응답)하면 한국어 묶음 실패 → "영어 메뉴로 계속"(사용자가 말한 '언어를 탐지하지 못해 영어'로 보이는 현상), 메뉴 묶음 실패 → "Failed to load game data" 오류 화면(스크립트 오류처럼 보임)이 됐다. 재시도가 없었다. 실제로 이 상태를 시험으로 재현했다(아래 변형 확인: 재시도를 끄면 한국어가 영어로 대체됨).
- **시작 허용이 너무 일렀다.** `clickToStart`는 메뉴·언어 묶음만 받으면 열렸다. 뒤에서 받는 메뉴 음악 묶음(`ser22.mus`)과 글꼴 적용은 클릭 뒤에도 진행 중일 수 있었다.
- **번들 스크립트 자체.** 번들 도입(E1293) 뒤 `index.html`은 3.4MB 스크립트 하나를 `<script defer>`로 불렀다. 처음 방문에서 이것이 끊기면 앱이 아예 시작하지 않고 빈 화면이 된다.
- 언어 탐지는 `navigator.language`만 읽었다(이 값은 동기라 시점 문제는 아니다).

## 변경

1. `www/assets/asset-loader.js` — **일시적 실패 재시도.** 파일·매니페스트 읽기를 간격 400·1200·2800ms로 최대 3번 다시 시도한다(네트워크 오류, HTTP 408/425/429/5xx, 잘린 응답·스트림 도중 끊김, 매니페스트 형식 오류). 404·403 같은 영구 실패는 바로 던진다. 실패한 시도가 알린 진행 바이트는 음수로 되돌려 진행률이 부풀지 않는다. 묶음은 동시에 12개까지만 받아(`DEFAULT_CONCURRENCY`) 처음 방문의 요청 폭주를 줄이고, 한 파일이 영구 실패하면 새 파일을 더 시작하지 않는다. 옵션 `retryDelays`·`concurrency`·`sleep`(시험용).
2. `www/netstorm.js` — **시작 관문.** 적재가 끝난 뒤 `_awaitStartReadiness()`가 `document.fonts.ready`와 뒤에서 받는 메뉴 음악 묶음(`_musicSettled`, 성공·실패 모두 끝날 때까지)을 기다린 다음에야 `clickToStart`로 넘어간다. 그때까지는 로딩 화면(100%)에 머물며 클릭을 받지 않는다. 어느 쪽이 끝나지 않아도 20초(`START_READY_TIMEOUT_MS`)가 지나면 시작을 허용한다(음악은 계속 받는다). 앱 옵션 `assetRetryDelays`로 재시도 간격을 바꿀 수 있다.
3. `www/netstorm.js` — **언어 탐지.** `detectBrowserLanguage()`가 `navigator.languages[0]`를 우선하고 없으면 `language`·`userLanguage`로 대체한다(저장된 선택 > `?lang` > 브라우저 선호 순서는 그대로).
4. `www/index.html`·`www/bootstrap.js` — **번들 로더.** 인라인 로더가 번들 스크립트를 동적으로 넣고 실패(`onerror`)하면 500·1500·3500ms 뒤 최대 3번 다시 넣는다. 받는 동안 중앙에 안내 문구(한국어 선호면 '불러오는 중...', 아니면 'Loading...')를 보이고(`#netstorm_boot`), 계속 실패하면 '게임 스크립트를 불러오지 못했습니다. 페이지를 새로고침하세요.'를 보인다. `bootstrap.js`는 동적으로 늦게 실행돼도 시작하도록 `document.readyState`를 보고 바로 시작하고 안내 요소를 지운다. 번들 파일은 여전히 하나이다.

## 고정 최소 대기 6초 (WB04-E1308, 2026-11-24 사용자 요청 "6초 추가")

처음에는 완료 신호(적재 약속·글꼴·음악 내려받기)만 기다리고 고정 대기는 넣지 않았으나, 사용자가 고정 대기도 더하라고 했다. 이제 `_awaitStartReadiness()`가 위 자원 신호에 더해 **첫 적재가 시작된 뒤 최소 6초(`START_MIN_WAIT_MS`)가 지나기 전에는 `clickToStart`를 열지 않는다**(자원이 일찍 와도, 그 동안 클릭도 받지 않는다). 기준은 첫 `_load()` 시작 시각(`_loadStartedAt`)이라 느린 연결에서는 자원 대기가 이미 6초를 넘겨 추가 지연이 없고, 빠른 연결·캐시 적중에서는 6초에 맞춰 열린다. 이후 재적재(언어 변경 등)는 6초가 이미 지났으므로 다시 기다리지 않는다. 20초 상한(`START_READY_TIMEOUT_MS`)은 최소 대기보다 짧아지지 않게 `max(상한, 최소 대기)` 로 쓴다.

- 끄기·바꾸기: 주소 `?startwait=밀리초`(0~60000)나 옵션 `startMinWaitMs`. `navigator.webdriver`(자동화 브라우저: e2e·MCP)에서는 기본을 0 으로 두어 기존 e2e 가 느려지지 않는다. 6초 동작을 시험할 때는 `?startwait=6000` 으로 직접 켠다.
- 단위 시험 `tests/start-readiness.test.mjs`(총 7건: 값 정리·6초 전에는 열리지 않음·이미 지났거나 0 이면 기다리지 않음·상한이 최소 대기를 끊지 않음)와 e2e `e2e/start-gate.spec.js`(총 7건 중 새 2건: `?startwait=6000` 이면 6초 전 로딩 화면·클릭 무시·열린 시각이 6초 이상, `?startwait=0` 과 자동화 기본은 즉시)로 고정했다.

## 검증

- Node: `tests/asset-loader-retry.test.mjs` 8건(503·429·연결 끊김·잘린 응답·스트림 끊김 재시도, 404·403 무재시도, 한도 초과 시 마지막 오류, 진행량 되돌림, 매니페스트, 동시 12개 한도, 영구 실패 시 새 요청 중단), `tests/start-readiness.test.mjs` 4건(관문이 글꼴·음악이 모두 끝나야 열림, 제한 시간 만료로 열림, 기다릴 것이 없으면 바로 열림, 언어 탐지 순서).
- e2e `e2e/start-gate.spec.js` 5건(한국어 브라우저 로케일, 실제 Chromium): ① 음악 파일을 붙잡아 두면 `loading`에 머물고 클릭을 받지 않으며 풀면 `clickToStart`가 열림 ② 매니페스트 503·한국어 글꼴 연결 끊김·번역표 429·한국어 Tell 503 두 번을 겪어도 한국어 번역·글꼴로 시작 ③ 번들 스크립트가 한 번 끊겨도 다시 받아 시작하고 안내 요소를 지움 ④ 계속 못 받으면 안내 문구와 요청 4번 ⑤ `?lang` 없이 `ko-KR`은 한국어, `en-US`는 영어.
- 변형 확인: 시작 관문을 빼면 ①이 `loading` 기대에서 실패하고, 재시도를 빼면 ②가 한국어 대신 영어로 시작해 실패한다(제보된 증상의 재현).
- 시작·언어·글꼴·정적 배포·title·오류 보고 관련 e2e 15건, `external-access`(index.html 바깥 주소 검사) 통과. 번들(`www/dist`)을 다시 만들어 함께 커밋했다.

## 배포

배포본(Pages)에는 이 커밋의 `www`를 다시 올려야 효과가 있다(번들이 바뀜). 처음 방문 재현은 캐시를 지운 새 프로필에서 해야 한다.
