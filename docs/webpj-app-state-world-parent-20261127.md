# 실제 앱의 공통 State 정리와 Runtime 반납

- 단위: WB04-E1384, 2026-11-27, HJOW-Athlon. 실제 앱 연결과 해당 검증을 완료했다.

`netstorm-state-world.js`는 앱의 같은 Client 장기 소유자·표면·Player·SP·시계·UI·음향을 기존 `cleanupClientStateWorld`에 공급한다. State7은 시작 정보를 보관한 뒤 reason1의 전체 부모를 호출한다. 미션 이탈은 reason0으로 여덟 AI·Player 링크·Kernel의 실제 반납 증빙과 Core0 선택을 거친다. 새 HUD는 원문 ReplaceUber 위치에서 생성되고, 이후 이전 Runtime만 반납하므로 새 Chat·Console을 다시 닫지 않는다. 일반 앱 수명 종료와 World 생성 전 실패 정리도 구별한다.

Scene 구동기가 보유한 곡 기한은 double 비트를 직접 쓰며 곡 선택·난수를 소비하지 않는다. 구동기가 없으면 보유 기한도 없다. 설정 재해석은 현재 웹의 기존 클라우드·도움말·소유자 색·회전·압축·trace·음향 소비자에 연결했다. 초기 인트로/메인 메뉴의 SP 전용 어댑터를 전체 정리로 바꾼 단위는 아니다.

## 발견과 교정

- 공통 Gump 삭제가 먼저 정리한 생산 패널을 `close`가 다시 삭제하는 문제를 고쳤다. 같은 노드가 남아 있을 때만 삭제하며 호스트 자식 정리는 유지한다.
- 창 크기 변경은 같은 Client의 Screen 객체를 교체한다. 공유 Chat 글자/그림 버퍼는 유지하면서 현재 Screen·팔레트를 다시 빌리도록 고쳤다. 이전 Screen을 계속 캡처하거나 같은 Client의 새 Screen을 다른 소유자로 거부하지 않는다.
- 직접 World를 조립하는 기존 Node 검사는 전체 State가 요구하는 실제 SoundPlayer·글꼴·현재 Renderer/강조 장치를 설치하도록 보완했다. 선택되지 않아야 할 오디오 재생 장치는 호출 시 실패한다. 가짜 HUD 대신 실제 입력 트리에 들어오는 HUD 모드 통지를 관찰한다.
- 원래 필터 수준30을 가정한 Player 로그 검사는 현재 Config 재해석 결과를 먼저 확인하고 명시 필터1에서 실제 로그 장부 연결을 확인한다. State/로그 규칙을 검사 편의로 고정하지 않는다.
