## 구현

- **`checkChatRecipients`(원문 0042dc70→0042d910)**: manager 0이거나 text가 없으면 false. 그 밖에는 레코드를 mode 0으로 초기화하고 text(첫 NUL까지)를 고정 정규식 `^[CR LF TAB SPACE]*([^…]+)(.*)`로 반복한다 — 구분자는 CR/LF/TAB/SPACE 네 개뿐(VT/FF/NBSP는 이름의 일부). 토큰마다 레코드의 선택 필드(앞 8바이트·이름 첫 바이트·주소 48..51)만 지우고 이름을 40바이트까지 복사해 NUL을 쓰며, `resolve`가 실패했을 때만 **여덟 채널 키(`""`×3, `BATTLE`, `""`, `EVERYONE`, `ALLIES`, `OBSERVER`)를 순서대로 번역**해 이름과 ASCII 대소문자 무시(확장 바이트는 접지 않음)로 비교하고 일치하면 멈춘다. 다음 토큰의 시작은 40바이트 절단 전 끝이다. 공백뿐인 나머지는 true이고 하위 장치는 도달 시에만 요구한다. 이름 NUL은 레코드 물리 끝(60) 안에서만 찾고 없으면 거부한다.
- **`completeChatName`(원문 0042e540)**: 후보/접두/순환 상태는 Client 수명의 0x4090바이트(순환 인덱스+0·길이+4·접두+8·후보 수+0x88·후보 슬롯 128바이트+0x90)다. **새 질의(문자열, 빈 문자열 포함)**는 번역이 필요한 네 채널(빈 값/128 이상은 건너뜀)을 번역해 `strcpy`로 복사한 뒤 현재 Chat 100×48바이트 행 중 Subscriber(+44)가 비영인 행의 이름(NUL까지, 128 미만만)을 후보로 모으고 후보 수를 쓴다. 길이 127 이상이면 원문 진단 `0x354` 복귀 후 `strncpy`처럼 `length`바이트만(질의 첫 NUL 뒤는 0 패딩) 접두에 복사하며 이전 접두의 꼬리는 남기고 길이/인덱스 0을 쓴다. **NULL 질의**는 인덱스를 ±1 한다. 이어서 signed 인덱스가 범위를 벗어나면 한 번 후보 수로 감기고(순방향은 0부터 다시) 두 번째 이탈에서만 `undefined`를 돌려주며, 후보와 접두는 `strnicmp`처럼 ASCII 대소문자를 무시하고 첫 NUL 또는 명시 길이에서 멈춘다.

새 `tests/chat-name.test.mjs` **12건 통과**. Identity 조회/번역/현재 Chat 기록은 호출 기록 대역이다.

**최초 실패와 교정(제품 결함 아님, 시험 기대값 오류 4건):** 후보 수는 4+Subscriber 있는 3행=7, 마지막 일치 뒤 순방향 순환은 감겨서 처음 일치를 다시 돌려준다, 짧은 후보는 패딩 NUL에서 비교가 끝나 일치한다, 폭 128 이상 이름은 행을 가로질러 센다는 점을 바로잡았다.
