# DN1.216 — 1280 화면과 FSR 출력의 다음 구현 계획

2026-11-28 사용자 후속 지시로 **계획만 반영**한다. 현행 제품은1.215이며 R5/R6 복원 중이다. 실제 FSR 출력은 아직 없는 R8 8차 대상이므로 이번에 준비한 후보 코드를 제품에 수입하지 않는다. 기존 장기 복원 중지·재개 순서는 그대로 유지한다.

## 적용할 정책

[공통 정책 표](resolution-policy-1280-20261128.md)를 따른다. 기본 최대는1280×720(16:9)·800(16:10)·960(4:3)·1024(5:4)이며 원본 세 해상도는 유지한다. FSR 사용 가능 시1920·2560·3840 폭의 같은 네 화면비를 지원하고 입력은 같은 화면비의1280 폭이다. 예:3840×2160←1280×720,3840×2400←1280×800,3840×2880←1280×960,3840×3072←1280×1024. 사용자 확인대로3840×2560은 오타다.1920도 일반 렌더링 크기가 아닌FSR 전용 출력으로 바꾼다.

## 순서와 완료 기준

1. **DN-RES-1 공유 정책과 시작 설정.** `Netstorm.Client/Display/ScreenResolutions.cs`의 원본/호환 목록을7행으로 만들고 네 화면비의12개FSR 출력을 별도 목록으로 둔다. `HostOptions`에서 표시 크기와 논리 크기를 분리하고 `Program`이 큰 `Screen`을 할당하기 전에 정리한다. 옛1366×768·1600×900과FSR 미지원 저장값은 가장 가까운 화면비의1280으로 복구한다. 잘못된 값도 안전하게 정리한다. CLI·options.cfg·메뉴가 같은 정책을 사용해야 한다.
2. **DN-RES-2 실제 FSR 장치.** DesktopGL 출력에 AMD 공식 EASU→RCAS를 연결한다. cpppj의 `third_party/fsr1` 공식 헤더와 라이선스를 공유하되 창/문맥의 소유권을 MonoGame에 둔다. 실제 셰이더 컴파일·표면 준비 성공 뒤에만 지원 상태를 공개한다. 실패하면 같은 화면비의1280 기본 출력으로 복구한다. 입력 텍스처는1280 폭으로 제한하고 출력만 선택 크기로 확대한다. GL 상태를 전부 되돌려 MonoGame 캐시와 불일치하지 않게 하며 resize/context 재생성/Dispose 실패 수명도 검사한다.
3. **DN-RES-3 메뉴와 실제 변경.** `HostPopupMenu`의 독자적인10행 배열을 공유 목록으로 바꾸고FSR12행/토글은 실제 장치 준비 상태로 제한한다. 체크는 논리 크기가 아닌 표시 크기로 읽는다. 고해상도는FSR 자동 ON이며 끄기/낮은 해상도로 복귀/설정 저장/다음 실행 정책을 일치시킨다. 원본`SETSIZE` Tell부터 실제 호스트 변경까지 잇는다. 현재Screen은 불변 크기이므로 기존 창·Screen·메뉴·입력·미션 소유자가 모두 바뀌는 수명을 먼저 설계한다. 미션 중 변경 허용 여부와 재진입/저장·재시작은 기존 상태 전환과 합쳐 검증한다.
4. **DN-RES-4 검증.** 일반7행/FSR12행과 화면비 교차곱, 실제 입력1280·대상 출력 크기, 장치 미지원·옛 설정·잘못된 쌍·CLI·메뉴 직접 Tell을 검사한다. 실제 GPU에서 단색/상하 방향/가장자리·문자·입력 역변환/레터박스·같은 문맥의 상태 복구를 읽어 확인한다. 일반 메뉴와 대표 미션도 통과하고 fullscreen→종료→재실행,60/120 표시 경로를 별도 확인한다. 실제 물리 모니터·Windows11/ARM은 사용자 확인 잔여로 구분한다. 마지막으로 해당 변경의 Client 전체 회귀, Game 배포/라이선스 동봉, 인계와 로컬 커밋을 마친다.

## 이번 후보와 실패 기록

`extracted/resolution-1280-dotnet-draft/`에11개 후보 파일을 로컬 보관했다. **ignored·미수입·최종 검증 실패 상태**이며 배포 코드가 아니다. 다음 작업에서 현행 source SHA와 다시 비교해 필요한 부분만 수입한다. 자동으로 적용하거나 완료로 표시하지 않는다.

최초 집중은49개 중47통과·2실패였다. 기존 Options 검사에서FSR 미지원 행 수 변경을 다 반영하지 못했고, 새 GPU 검사는SDL 경로를 명시하지 않았다. 후속에서는AMD 헤더의`packHalf2x16`에GLSL4.2(또는 해당 확장)가 필요함을 실제 컴파일 오류로 확인했다. 이를 보완한 세 번째 실행은 기존 팝업1통과·GPU1실패였다. GPU에서 검정이 읽혔으며 **검사 Screen이 모드/clip을 초기화하지 않아 FillRect 입력이 비어 있는 문제를 먼저 해결**해야 한다. 셰이더 컴파일 성공을 정상 이미지 출력 성공으로 세지 않는다. 후보의 상태 복구/실제 Game/성능/해상도 재시작은 아직 검증하지 않았다.

원문 로그는 `extracted/resolution-1280-dotnet-{tests,gpu-second,gpu-third}.log`와 해당TRX다. 제품 소스를1.215로 되돌리고 Game/검사 참조도 다시 빌드한다. 이 문서 작성은 정기 제품 회귀 주기에 더하지 않는다(직전1.215 전체 뒤0/4 유지). 이번 cpppj CP1384 검증을 DN 검증으로 세지 않는다.
