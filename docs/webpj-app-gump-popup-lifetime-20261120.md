# WB04-E972 앱 Gump 팝업 관문

현재 Client Gump 루트에 원본 `BlockingGumpOpen`과 팝업 닫기 경계를 연결했다. 차단 조회는 루트 직계의 `0x4000`만 읽고 숨김·삭제 대기 여부를 추가로 거르지 않는다. 닫기는 다음 형제를 먼저 보존하고 삭제 대기가 아닌 직계 팝업에만 실제 Gump Kill을 요청한다. 손자 팝업은 별도로 닫지 않는다.

검증: 실제 Client Gump 트리에서 직계·손자, 숨김, 복수 팝업의 차단과 지연 삭제·반복 닫기를 확인했다. 기존 메뉴 팝업 처리기 및 루트 수명과 함께 Node 32건 통과. Tutorial 프레임의 실제 사용과 앱 팝업 메뉴 연결은 후속이다. E966 고정 Node 26·22 전체 회귀는 각각 6,547건 통과했고 E970 고정 Node 26 전체 회귀를 진행 중이다.
