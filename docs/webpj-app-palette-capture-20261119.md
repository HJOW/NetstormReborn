# WB04-E899: 앱 시작 팔레트와 고정 입력

## 근거와 범위

cpppj 기준선 `225553df`의 `ClientMain.cpp` 시작 흐름은 설정의 `fortPal`을 `GamePalSpec`으로 해석해 Screen에 `clear=1`로 적재한 다음, 그 논리 팔레트를 Client 수명의 `ClientColorSortInput`에 캡처한다. 캡처는 이후 전투 팔레트를 바꾸어도 다시 실행하지 않는다. 앱은 이미 같은 설정 경로에서 `GameAssets`를 만들고 있으므로 해당 자산의 팔레트를 이용해 `Screen.init` → `loadPalette` → `captureWithPrimary` → `bindColorSortInput`을 실행한다. 최초 화면 모드 이전이라 clear는 원본처럼 표면 출력을 요구하지 않는다.

앱 적재와 재시작은 새 소유자를 만들고 종료는 두 참조를 반납한다. 소유자 생성이 실패하면 앱 슬롯에 부분 결과를 발행하지 않는다. `Screen`은 현재 팔레트 계산 수명에만 연결되어 있으며, 브라우저 표시 표면·DIB 모드·해상도 변경·9표 캐시·소유자 표·Session 소비자·구름 및 전투 팔레트 전환은 아직 연결하지 않았다. 따라서 실제 미션 시작이나 화면 전환이 완성된 것은 아니다.

## 검증

- 실제 `GIFCLOUD.COL`로 색 256개와 원본의 0/255 고정색을 확인하고, 화면 팔레트를 변경해도 최초 논리 색과 primary가 유지되는지 검사했다. 초기화 전·중복·잘못된 화면 크기도 확인했다.
- Node 집중 및 Screen·ColorSort 연관 검사 42건 통과.
- 첫 전체 회귀에서 수동 적재 시험 4건이 레이아웃·선행 수명 누락으로 실패해 해당 시험의 준비 상태를 실제 시작 순서에 맞게 고쳤다. 수정 후 관련 Node v22 검사가 통과했다.
- 재실행에서는 E898에서 추가한 실제 Renderer 초기화의 화면 배치를 기존 Guide 로그인 시험이 빠뜨린 것을 확인했다. 시험의 카메라 초기화를 앱의 실제 초기화 경로로 교정했다.
- 실제 Chromium 앱의 자산 적재와 종료·재시작에서 생성 및 반납을 1건 확인했다.
- Node v22.23.3 전체 회귀 6,451건 통과(실패·취소·건너뜀 0). 대응표 1,160행 오류 0.
