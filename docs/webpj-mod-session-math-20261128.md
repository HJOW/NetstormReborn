# WB04-E1480 실제 미션 연결과 고정 공통 수학

모드 관리자를 실제 앱의 초기 적재·Client 시각 공급원·프레임 종료 사건·Guide 뒤 원래 입력·World 반납/재시작/앱 종료에 연결했다. 고정 오라클은 저장 검증/실행을 강제로 건너뛴다. 비고정 모드는 첫 시계 원점 준비 전에 저장 패키지를 비실행 검증하고 Ready인 실제 Session마다 새 격리 VM을 만든다. Worker 대기 중에는 capture/Guide/입력/Kernel/RNG를 실행하지 않고 부모 DOM/실제 시간 감시는 계속한다. 종료 사건은 마지막 공개 사본만 보유하며 부팅 중 이탈은 AbortSignal로 취소한다. 앱 종료는 설치 검증도 취소하고 저장소 쓰기를 금지한다. Guide가 먼저 반납된 잠깐의 World는 조회에서 제외한다.

ResetAll은 설정/진행과 함께`netstorm.mods.v0`를 제거한다. 모드 키 삭제 실패도 앞서 지운 두 키를 복원하며 다른 앱의 자료를 지우지 않는다. 기존 확인 창·삭제→앱 정리→새로고침 순서를 유지한다. Options 모드 관리/파일 선택 UI는 다음 단위다.

실제 Worker 수학을 확대하자 Node26 native의`cos(0.1)=3fefd712f9a817c0`와 Chromium/Firefox의`...c1` 차이를 재현했다. 초기 ‘V8 native 기준’을 플랫폼 공통 경로라고 본 설계를 교정했다. 공통`stdlib-fdlibm-js-v0` 프로필은`@stdlib/math-base-special-sin/cos/atan2/pow` 각0.3.1의 고정 JS 구현과 ES의 인수 변환/NaN/±0/Infinity 규칙을 양쪽에 주입한다. C 포트의 pow 최적화에 맡기면`NaN**0`·`1**Infinity`·`(-0)**0.5` 등의 JS 의미가 달라져 별도 shim으로 먼저 처리한다. 네 함수/Math 객체는 동결하고 해당 guest의 tamed Math를 바탕으로 만들어 Math.random/함수 생성자 제한을 유지한다. 게임 자체 Math/난수는 수정하지 않는다.

초기29행 원문과SHA-256`fd2bcad22ad9c17ecc190fef27c03c496f353bb0a050d4a6ebe24f6fb6eee647`는[원문](webpj-e1480-evidence/native-math-original.json)에 보존했다.29행 중 cos1행만 고정 JS 기준으로 교정했고, 추가256입력은 고정 정수열·큰 지수/서브노멀·명시 pow 특별값이다. 전체 영역의 올바른 반올림 정확도를 독립 증명한 자료로 세지 않는다. DN MOD-3에도 같은 JS shim/프로필/29+256벡터를 반영했고 DN 구현 중지는 유지한다. 직접/전이 고유200패키지의 라이선스/NOTICE와 lib 원문 선두 고지(Sun/FreeBSD 포함)를 동봉했다. 사용하지 않는 빌드 의존성도 포함하는 보수적인 고지 집합이다.

최종 검증은 Node26/22 관련각98/98, 운영빌드/선행ESLint 종료0(68.665초)·별도마지막lint0·단일번들5,845,775바이트/9.9MB이내다. 실제 미션/고정모드/기존오라클3/3, 최종격리Chromium/Firefox순차2/2이다. [원문/해시](webpj-e1480-evidence/provenance.json). 검사 범위는 실제 아군AI1-1(250ms 대기 전후 전체풀FNV32/두 RNG/프레임/live game·wall 불변·실제 사제선택·오류모드만저장꺼짐·정상모드지속·이탈/iframe반납), Chromium/Firefox의285수학/공통5경계/권한/시간중단, 고정모드 손상저장 무시, 기존4:3 시작그림360프레임/화면0픽셀·90/130덤프 오라클이다. 실제 플레이는 아군 AI의1-1 짧은 조회/선택만이며 승리 검사는 없다.

실패도 보존했다:

- 최초 연결 검사22통과/2파일실패는 동기`_setState`에 잘못 들어간 await 구문 오류다. 비동기`_load`로 옮긴 뒤 관련 검사를 다시 실행했다.
- 외부 감사66/67의 Worker 생성 거부는 정확한 자체 Blob 선언 한 줄과 그 CSP만 예외로 등록했다. 다른 파일/인자/추가코드 거부 단언을 추가했으며 전체 파일을 허용하지 않는다. Native debug의 같은 출처 번들 텍스트 읽기도 문서화했다.
- 실제 미션 첫 실패는 기능 단언을 모두 지난 뒤 Playwright 저장소 주입 스크립트가 불투명 iframe에서도 실행되어 SecurityError4건을 낸 것이다. 주입 대상을 top 문서로 한정했으며 제품 sandbox를 완화하지 않았다.
- 최초 두 브라우저 수학 실패는 위 cos1ulp 차이다. 초기 원문을 보존하고 고정 구현으로 교정했다. 중간 pow 특별값 검사25/26·관련97/98도 음수0의 제곱근 부호 차이를 잡았으며 ES 특별값 shim으로 고쳤다. 새 기대값 덮어쓰기로 이 실패를 숨기지 않는다.

별도 실제미션/오라클과 동시에 확대한 Worker 검사에서는1/2(Chromium의요청 timeLimit, phase미기록) 실패가 있었다. 한도는1000ms 그대로이고 요청 phase/시간 계측을 추가한 뒤 두브라우저순차2/2를통과했다. core등록Chromium163.7ms/Firefox148ms·수학등록368.5/353ms였다. 앞 실패의 부하 원인을 확정하거나 해결했다고 세지 않는다. 원문/trace를 보존한다.

완료 뒤 주기는v26=4/4·v22=4/8이고 다음 Node26 전체 예상7021이다. 전체 실행 중 작성 소스/설정/공통 적합성/의존성/자산을 고정한다. 다음 구현은 Options의 가져오기·명시 교체·켜기/끄기·삭제/오류 UI와 실제 관리 경계 검증이다. 기존 사용자 직접 승리/후반 목표·물리60/120Hz/청취·Linux 과거 실패 한계는 유지한다.
