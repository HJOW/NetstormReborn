# 0.621 지역 소유자 확정 세션 결선과 L2 3경로 재측정 (R4-2 잔여)

- 일시: 2026-11-19, HJOW-Athlon
- 범위: R4-2 지역 소유자 확정의 세션 결선. 요새 적재 소유자 지정의 가상 Owner 분배(`SetFortObjectOwner`)와 Pop 시점 실제 좌표 분배(`DispatchRegionTempleOwner`)를 잇고 L1 6건과 L2 3경로 재수집으로 확인한다.
- 목표: 0.620에서 닫은 가상 본체를 실제 적재 경로에 연결해 섬 소유자→Player 첫 지역(`+0x78`) 사슬을 동작시키고 소유자 일치율을 확인한다.

## 원인

- 0.620까지 가상 본체(`RawVortexOwner`)의 L1 전수 재생은 닫혔으나 세션 적재는 기존 공통 부모로만 소유자를 정했다. 섬 소유자·첫 지역·현재 신전 기록의 확정 입력이 세션에 닿지 않았다.
- cpp 근거는 `RawCampaignOwnership.cpp` 54~60행의 소용돌이→섬 소유자→첫 지역 조립, 78~80행의 SetOwner 분배, `RawAssetPostPop.cpp` 91행의 Pop 시점 SetOwner 분배다.
- DN 공장 파생(R6)의 정기 트리거와 실제 outpost 목록(R11)은 전제이며, 이번 단위는 적재 경로의 두 분배(적재 SetOwner·Pop 분배)만 잇는다.

## 수정

- `dotnetpj/src/Netstorm.Client/Host/HostSession.cs`
  - `BuildRegionOwnershipDevices` 끝에 `BuildRegionVortexDevices`를 잇고 `RegionVortex`·`RegionVortexRevision`·`RegionVortexRefreshes`·`RegionVortexDiagnostics`·`RegionIslandAt`을 노출했다. 별도(outpost) 목록은 같은 투표의 추가 목록을 빌리며 실제 목록 생산자는 R11에서 잇는다.
  - `SetFortObjectOwner`를 추가하고 요새 적재(`FortObjectLoadHooks.SetOwner`) 갈고리를 여기로 바꿨다. 신전 가상 표면이면 가상 Owner로 분배하고 아니면 기존 공통 경로를 쓴다. 도장·사제 경로의 `SetWorldObjectOwner`는 재귀를 피하려고 기존 공통 경로를 유지한다.
  - `DispatchRegionTempleOwner`를 추가하고 요새 Pop 갈고리에서 Pop 성공 뒤에 불렀다. 적재 SetOwner(좌표 0·void)와 달리 실제 좌표·배치 상태로 섬 소유자·첫 지역을 전파한다(적재 순서 SetOwner→Pop은 cpp `RawFortObjectLoad.cpp` 104·121행과 같고, 분배 위치는 cpp `RawAssetPostPop.cpp` 91행과 같다).
- `dotnetpj/tests/Netstorm.Client.Tests/HostSessionRegionVortexTests.cs`: 신규 L1 6건. 장치 연결·가상 분배·일반 fallback·Pop 분배의 빈 섬 보고·미연결/미복원 표 거부와 `RegionIslandAt` 빈 지역(127) 동작을 확인한다. 합성 장면은 지형을 생성하지 않아 존재 섬 전파는 실제 Generate 덤프로 대조한다.
- `dotnetpj/tests/Netstorm.Client.Tests/HostSessionRegionOwnershipTests.cs`: 장면에 지형 바인딩을 추가했다(가상 Owner의 섬 갈고리가 읽는다. 섬이 비어 거주 전파를 부르지 않는다).

## 검증 (증거)

- `dotnet test Netstorm.Client.Tests -c Release`: 0 실패·1281+ 통과(최종 코드로 전체 회귀).
- `dotnet test Netstorm.Client.Tests --filter HostSessionRegion`: 0 실패·9 통과(신규 6·기존 3).
- L2 3경로 재수집(시드 1760000000, `extracted/dotnet-l2-0621/`, 각 120프레임·90프레임 덤프, 종료 1=미완료 예상):
  - `thewarbegins`: type 1793·owner 497·frame 127·slot 80·graph 240/255, 난수 CRT `296677442` 일치. 0.619와 동일.
  - `tutorial1`: 832·140·37·31·graph 254/255. 0.619와 동일.
  - `bc1menu76`: 802·213·67·28·graph 254/255, `dn_only` 2. 0.619와 동일.
  - Player 첫 지역(`+0x78`): DN은 9경로 모두 127 유지, cpp는 `thewarbegins` p1=0·p2=1, `tutorial1` p1=0, `bc1menu76` p1·p2·p4~p7=0이다.
- 실행 진단(창 실행·표준오류, 커밋 제외)으로 원인 확정: 사원 Pop 갈고리에서 `TryPopFortTerrain`이 거짓·슬롯 `state11=4(void)`·`extra=2` 유지다. 가상 Owner 관문(`slot[11]&4`·`extra&9`)이 Pop 전에는 열리지 않으며, 사원 Pop 자체가 전용 파생(R6) 대기라 Pop 뒤 분배도 아직 발화하지 않는다. 구조 변경 뒤 DN 재실행 덤프는 프레임 행(90→91, 실행 타이밍)을 제외하고 0621 수집본과 바이트 일치한다.
- 공장 정기 트리거·실제 outpost 목록·cpp 전용 슬롯·정기 처리·AI는 잔여이며 L2 지표에 남는다.
