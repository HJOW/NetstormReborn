# webpj StyleText 다중 줄 버퍼·공백 줄바꿈 (WB04-E422, 2026-11-14)

RawMenuControls 선행 **StyleTextBuffer 428줄(.cpp/.h, partial→port)**을 새 모듈 [`www/ui/style-text-buffer.js`](../webpj/www/ui/style-text-buffer.js)로 이식했다. 기준선 `1f00a25a` 전체 소스와 [CPP 정적 복원 문서](exe/cpp-style-text-buffer.md)를 읽었다. 두 소스의 기준선 뒤 변경은 없다. **전용 PE fixture는 없다.** cpppj에도 이 버퍼의 직접 시험이 없고 CPP 문서도 당시 시험/원본 직접 대조 미수행을 기록한다. 아래 검사는 기준선 소스 계약·독립 단어 배치 모형·실제 글꼴/그림 연결이며 원본 직접 관측 수치로 세지 않는다. CD 10.72 주소·판본 인자는 옮기지 않았다. 앱 메뉴가 쓰는 간소화판 `www/ui/scroll-text.js`는 그대로 두고 실제 `StyleTextState`/`StyleText` 위에 같은 규칙을 연결했다.

## 입력 줄 저장소

- **상태**: `StyleTextBufferState`는 최대 칸·완료 줄 수·`hardLines`(소유 head 배열)·센티널·표시 줄 Map(토큰 → 줄)·표시 줄 수·dirty·noWrap·다음 표시 줄 토큰·문자열 추가 통지(`onAppend`)를 가진다. `hardLines[lineCount]`는 아직 LF를 받지 않은 **미완료 끝 칸**이며 완료 줄 수에 포함되지 않는다.
- **`appendText`**: 통지 → 길이/NUL 결정 → LF 분할 순서다. 통지는 길이 0·오류 입력에서도 먼저 호출된다. 음수 길이는 범위 안 첫 NUL까지, 비음수 길이는 명시 범위(중간 NUL/LF와 무관)이며 범위 밖 LF는 읽지 않는다. LF 앞의 빈 구간도 실제 빈 문자열 조각이 되고 CR/탭은 개행으로 바꾸지 않는다. 마지막 미완료 구간은 끝 칸에 보관하고 줄 수를 늘리지 않는다. 문맥은 복사본이고 태그는 모든 구간이 공유한다. 문자열 추가는 성공 시 dirty를 켠다.
- **가득 찬 칸**: LF에서 `lineCount == maxLines-1`이면 완료된 첫 줄을 scalar 삭제하고 미완료 끝 칸까지 포함한 전체 배열을 앞으로 옮긴다(이전 끝 칸 체인이 한 칸 앞으로 오고 새 구간이 그 뒤에 붙는다). 최대 줄 수 1에서는 삭제할 완료 줄이 없어 거부한다.
- **`appendPicture`**: 새 그림을 만들고 두 맞춤 값 중 하나라도 비0이면 `Markup.fit`을 부른 뒤 끝 칸에 붙인다. 줄 수는 늘리지 않고 dirty를 켠다. 한쪽 값이 0이면 그 비율이 0이라 배율 0이 된다(원본 규칙 그대로).
- **`removeLine`**: 완료 줄만 삭제하며(`index < min(maxLines-1, lineCount)`) 삭제 뒤 전체 칸을 이동하고 줄 수를 줄인다.

## 표시 줄과 공백 줄바꿈

- **표시 줄**: head·높이·폭·y·양방향 링크이며 토큰 0은 센티널이다. 새 줄의 y는 **삽입 시점의 전임 y+높이**로만 정하고 이후 다시 계산하지 않는다. 반납한 토큰은 재사용하지 않고(다음 토큰은 계속 증가) 외부에서 먼저 넣은 토큰은 건너뛴다. 마지막 DWORD 다음은 0이며 0은 **소진**이라 앞쪽 빈 토큰으로 돌아가지 않는다.
- **`layout(width)`**: 폭 0 이하이면 기존 표시 목록을 유지한다. 양수 폭이면 이전 표시 조각만 반납(입력 조각은 남김)하고 개행이 완료한 입력 줄마다 빈 표시 줄을 먼저 만든다. 마지막 미완료 칸은 순회하지 않는다. dirty는 호출자가 관리한다.
- **문자열 조각**: 현재 줄 폭 + 전체 폭이 제한 폭 **미만**이거나 noWrap이면 전체를 새 조각으로 복사하고, 정확히 같으면 분할 경로로 간다. 분할은 ASCII space만 단어 경계로 삼아 다음 단어까지의 전체 접두 폭(현재 줄 폭 포함, 뒤 공백 제외)을 명시 길이로 측정하고, 받아들인 구간은 뒤 공백까지 복사한다. 첫 단어가 들어가지 않을 때 현재 줄 폭이 비0이면 새 빈 줄로 먼저 옮기고, 빈 줄에서도 크거나 같으면 **그 단어를 강제로 배치**한다(글자 단위로 쪼개지 않으며 강제 배치 뒤에는 새 빈 표시 줄이 생긴다). 마지막 단어 복사는 원래 NUL도 명시 길이에 포함할 수 있다. 연속 space·탭·빈 문자열·태그를 유지하고 폭/y/카운터는 signed DWORD 감김으로 더한다.
- **비문자(그림) 조각**: 측정 높이를 **이동 전에** 현재 줄에 쓰고, `현재 폭+그림 폭 >= 제한 폭`이고 noWrap이 아니며 줄에 head가 있을 때만 새 줄로 옮긴다(새 줄의 높이는 0으로 남는다). 빈 줄의 그림은 폭이 제한 폭 이상이어도 강제 배치한다. 복제는 `Markup.clonePicture`라 배율 1·색 치환 0으로 새로 만들어지며 입력 조각의 Fit/색 필드를 복사하지 않는다. 그림 외 다른 외부 조각은 이전 복제 경계가 있어야 한다.
- **`maximumWidth`/`totalHeight`**: 표시 줄 수만큼 순회한 최대 폭(초기 0)과 마지막 표시 줄의 y+높이(없으면 0)다. 카운터가 링크보다 크면 센티널을 만난 뒤 거부한다.
- **`destroy`**: 완료 입력 줄 → 입력 배열 → 표시 줄 → 센티널 조각 순서로 반납한다. **원본 소멸자는 미완료 끝 칸을 삭제하지 않는다**(같은 누락 유지, 호출자가 먼저 닫아야 함). 카운터는 재초기화하지 않고 저장소만 `initialized=false`로 둔다.
- **연결 함수**: `bindStyleTextBufferFonts`(실제 `GumpText`의 첫 폭 표와 논리 슬롯 높이, 길이 -1이면 NUL까지), `bindStyleTextBufferMarkup`(같은 `Markup`의 그림 복제, 그림 외 조각은 이전 경계로 위임).

## 검사와 발견

새 `tests/style-text-buffer.test.mjs` **18건 통과**.

1. 생성자/새 상태 기본값/호스트가 깨뜨린 상태 거부(초기화 안 됨·최대 칸 0·배열 길이 불일치·끝 줄 범위 -1/최대).
2. `appendText`의 통지 시점·명시 길이/NUL/범위 오류·LF 분할·빈 구간·CR/탭·태그/문맥 사본·기본 태그 0·가득 찬 칸 삭제와 끝 칸 이동·release 순서, `removeLine`, `appendPicture` Fit 규칙.
3. 손으로 계산한 레이아웃 사례: 폭 정확히 같음/미만, 연속 공백, 강제 배치와 뒤 빈 줄, 앞 조각 뒤 이어붙임, noWrap, 끝 공백 문자열(`'abc def '`가 폭 8에서 빈 줄을 더 만들지 않음), 폭 1, 내장 NUL.
4. 그림: 이동 전 높이 갱신·새 줄 높이 0·비교 경계(133/134, 폭 130 대 높이 120)·빈 줄 강제 배치·noWrap·복제 배율 1/치환 0·복제 장치 없음.
5. 표시 줄 토큰(건너뛰기·마지막 DWORD 뒤 소진)·최대 폭/전체 높이·소멸 순서·미완료 끝 칸 보존.
6. **독립 단어 배치 모형 600라운드**: 문자열 인덱스로 규칙을 다시 쓴 모형이 무작위 폭(3~26)·글꼴 높이·공백 개수·끝 공백·noWrap에서 표시 줄 문자열/폭/높이/y/줄 수/최대 폭/전체 높이와 같다(줄바꿈 150건 이상, 강제 배치 20건 이상).
7. 실제 FontStore/GumpText 연결(시험 글꼴은 `A` 한 글자만 폭 2): 줄 폭이 실제 `StyleText.measure`와 같고 여러 조각 줄은 폭 미만이다.

**최초 실패와 교정(제품 결함 아님, 시험 기대값 오류):** 끝 칸 문맥 사본을 확인할 조각 위치, 시험 글꼴의 폭이 `A` 하나뿐이라 단락을 `A`로 다시 구성한 것, 모형에 입력 줄 끝 LF가 만드는 빈 조각과 appendText가 만들지 않는 빈 입력을 반영한 것이다.

**변형 확인:** 연산자/정수 상수 변형 179개 중 167개를 잡았고(처음 생존 40개 → 호스트가 깨뜨린 상태·새 상태 기본값·끝 공백·그림 폭 경계·명시 길이 밖 LF·토큰 건너뛰기 보강), 남은 12개는 동등 변형이다. 2 GiB 입력/문자열이 필요한 signed 상한 세 곳, 저장 문자열에 항상 NUL이 있어 닿지 못하는 `wordEnd` 방어, 기본 인자 `length=-1`→`-2`, 범위 밖 읽기가 0이라 이미 0인 칸을 다시 쓰는 `removeLine` 끝 반복, 폐기하는 줄 객체의 필드 초기화 셋, 첫 NUL 뒤를 아무도 읽지 않는 `count+1`→`count+2`, 항상 채워지는 측정 출력의 초기값이다.

## 남은 경계

- `TextGump`/`ScrollingText`가 이 버퍼의 `applyScrolling`(E421) `restricted`/`appendPicture`와 표시 줄 y/높이를 사용해 그리고 스크롤한다.
- 앱 메뉴(`www/ui/scroll-text.js`)는 아직 간소화판을 쓰며, `RawMenuControls`·`ClientRendererFrame`·`GameWorld`·`ClientGameplayGlobals`/Session 연결이 남아 실제 미션은 플레이할 수 없다.
- 원본 파일 변경과 게임/브라우저 실행은 없다.
