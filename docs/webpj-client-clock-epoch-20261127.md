# 비고정 초기 시계의 epoch와 최초Capture

WB04-E1392, 2026-11-27, HJOW-Athlon. CP1375의 공통 InitFullTime을 실제 웹 부팅에 반영했다. 완료.

ClientMain의 비고정 초기화는 UTC초가 바뀔 때까지 기다린 뒤 현재 밀리초 원점과 `ClientUnixSeconds()-0x32c85780`을 선택한다. 이 변경은 LAN 전용이 아니므로 단독 웹 부팅에도 적용했다. `client-clock-origin.js`가 Native Sleep(1)을 이벤트 루프에 양보하는 비동기 대기로 옮긴다. 준비 중에는 로딩 화면만 갱신하고 Client 프레임·Guide·Kernel·게임 난수를 소비하지 않는다. SP/RNG 최초 초기화는 기존처럼 이 대기보다 먼저 수행한다.

GameClock은 초기 초에1000을 곱한 값도 DWORD로 감싼 뒤 밀리초 차이/현재 보정을 합산한다. 큰epoch를 나중에double초에 더하지 않는다. Wall과Game에 같은base를 사용하고 Game의 공유 보정·누적 정지 산식은 유지한다. 독립 생성자의 기본base0은 C++ 생성자와 같으며 **실제 앱 부팅은 상대시계로 계속하지 않고** 원래epoch 준비를 마친다.

최초Capture는 Native처럼 보정 상자 연결 전에 실행한다. 첫 주루프delta가epoch 전체가 되지 않도록 같은 공유 프레임 객체를 초기화하며 창 비활성이 보유한 정지 깊이도 보존한다. 고정 시각은 이 절차에서 원점/프레임을 다시 잡지 않아 기존프레임0·시계4틱(0.1초)·첫0.125초가 유지된다.

준비 중 destroy/재초기화나 적재 세대 변경은 이전 준비 결과를 버린다. 공개init의 동기 반환형은 유지하고 기존 비동기 로딩 안에서 준비를 기다린다. 브라우저의 로딩/입력 화면이 준비 중 막히는 바쁜 대기는 없다.
