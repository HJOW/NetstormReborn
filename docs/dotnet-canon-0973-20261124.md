# dotnetpj 0.973 — Build에 챌린지 로그인 응답 0x1d 수신기 연결과 Root 진단·설정 갈래

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 같은 장기 기본 표를 공유하는 `ClientPacketDispatch.Build`/`InstallDefaults`에 원문 앱 전역 0x1d 챌린지 로그인 응답 수신기를 연결하고, Root(`ClientHostGame`)의 실제 설정 조회·진단 로그를 묶었다. 0x66·0x26 Build 연결과 제품 기존 경로는 바꾸지 않는다. 세션·메뉴 결합 후크 중 0x0f(NsInfo owner 필요)·참가자/전투 묶음(NSInfo·생성·좌석 장치 필요)과 Root 송신·제출 갈래, RU-3 나머지·R4-4 정기 두 단위는 후속에서 잇는다.

## 변경과 원문 대응

- `ClientPacketDispatch.Build`/`InstallDefaults`는 선택적 `config`·`diagnosticLog`·`tell`을 받는다. 없으면 받는 즉시 명시 실패하며, 수송 팩토리(`ClientCampaignTransport.Make`)는 기본값으로 같은 표를 공유한다. 0.973에서 추가됐다.
- 0x1d 후크는 실제 장기 장치만 묶는다. 상태·구독자는 `connections`·`game`의 같은 owner이며, 응답코드 기록과 버전 차이 확인(`ClientMetaVersion.Check` 본체 재사용)은 호출자가 묶은 진단·설정·알림 장치를 쓴다. 구독자·28/12 쓰기까지 수행한 뒤 동기 Run만 실제 UI State 부모 요구로 명시 실패한다. 메뉴가 있을 때의 성공 합성과 미설치의 침묵 통과를 모두 두지 않는다. 새로 만든 본체가 없다.
- Root는 실제 설정 조회(`HostStartupScene.Configuration.GetInt`)와 실제 진단 로그(`ErrorLog.Note`)를 묶어 0x1d의 진단·버전 갈래를 연결했다. Tell·Run은 메뉴가 없어 기본 명시 실패를 유지한다.
