# WB04-E835 Client 다리 붕괴 스캔

기준선 `225553df`의 `ClientBridgeDecay.cpp/.h`를 웹 코어에 이식했다. 메뉴에서도 같은 장기 표면 저장소와 현재 권한의 원본 스캔 커서·기한·주기를 사용한다. Client 프레임은 표면 저장소가 있을 때 스캔하고 선택된 칸만 현재 Session의 `decayBridgeCell`에 넘긴다. 읽기 전용 진단은 실제 활성 후보 수와 현재 전역을 보고한다. 기준선 뒤 해당 C++ 본체 변경은 없다.

월드 없는 실제 Pool에서 커서 15000→15400, 기한 10과 정지·권한·편집기 관문 및 다른 권한 소유자 거부를 확인했다. 선택된 칸을 현재 Runtime 경계로 전달하고 처리 뒤 같은 시각·주기가 바뀌면 재조회하는지와 진단의 비변경을 검사했다. 처음에는 할당 직후 원본 void 상태의 슬롯을 활성 후보로 잘못 가정해 호출되지 않았고, 명시 활성 입력으로 수정했다.

실제 적재 Session의 다리를 Client 스캔에 넣어 같은 게임 시각 전달과 스캔 기한을 확인했다. 이 검사는 스캔 본체가 칸별 예외를 삼키므로 다리 붕괴 전체 성공이나 실제 Client 메인 루프 연결을 증명하지 않는다. 게임 창은 실행하지 않았다.

검증: 무월드/Runtime 경계 2건과 실제 적재 Session 1건, Node v26.13.0·v22.23.3 전체 각각 6,333건 통과(실패·취소·건너뜀 0), 대응표 1,160행 오류 0. 두 버전은 순차 실행했고 v22 전체 검사 뒤 v26 회귀 0/8회다.
