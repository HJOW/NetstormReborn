# 시간 동기화 일반 등록·수신 이식 (WB04-E515)

재기준선 `225553df`의 `o/RawClockSynchronization.cpp/.h`에서 서버 초기화,
일반 수신기 등록, Commander 연결과 수신을 기존
`webpj/www/core/raw-clock-synchronization.js`에 옮겼다. E335의 같은
`ClockSynchronizationData`와 Client 전역, E306의 실제 `RawPacketDispatch`를
빌리므로 별도의 월드나 복제된 시간 장부를 만들지 않는다.

- 일반 등록은 패킷 5의 빈 observer와 수신기를 순서대로 설정하고 버전·길이
  정책을 유지한다. 분배기 어댑터는 입력의 처음 32바이트를 복사해 수신하며,
  Node의 `Buffer`도 같은 독립 복사본이 된다.
- 서버 초기화는 표본·기한·연결을 보존하고 송수신 수와 응답 모드만 바꾼다.
  연결은 70개 표본의 헤더와 미사용 바이트까지 모두 지운 뒤 현재 벽시각을
  조회하고, 그 다음 카운터·모드·기한·연결을 쓴다. 시각 장치가 실패하면
  앞서 지운 표본은 되돌리지 않는다.
- 응답은 현재 게임 시각을 패킷에 쓰고 주소를 조건부로 보낸다. 주소의 선행
  복사와 시각 조회 뒤 flags 재조회 순서를 보존한다. 측정 수신은 현재 벽시각을
  기록한 뒤 요청 시각이 같은 첫 표본만 갱신하며 수신 수는 DWORD로 감긴다.

`tests/raw-clock-synchronization.test.mjs`에서 실제 웹 분배기와 서버 응답,
복사본, 중복·NaN·미일치, 주소 관문 변경, 실패 뒤 부분 효과를 확인했다.
기존 Client 상태·패킷 분배기 검사와 함께 집중 46건이 통과했다. 전용 원본
관측 fixture는 사용하지 않았고 원본·클론 게임도 실행하지 않았다.
복사 검사의 첫 초안은 `Buffer.slice()`로 기대값을 만들어 원본과 저장 영역을
공유했다. 독립 `Buffer.from()`으로 고친 뒤 Node 22·26에서 검사를 다시 통과했다.

이 단위는 **partial**이다. 표본 만료·빠른 절반 평균·시계 보정·송신을 하는
`Poll`, 장기 고정 Native 수신기와 baseline 승격, 실제 Session/Client 결선 및
단독 미션 도달 검증이 남았다. 후속 Poll 구현 시 동률 정렬에 주의한다. 이 PC의
Windows UCRT `qsort`를 같은 비교자로 호출하면 왕복 시간이 같은 2개 표본은
입력과 반대 순서가 되는데 JavaScript의 안정 정렬은 입력 순서를 유지한다.
제품 1313 오라클 실행 파일의 import 표에서도 `qsort`가
`api-ms-win-crt-utility-l1-1-0.dll`에 연결됨을 파일 읽기로 확인했다.
두 표본의 offset이 다르면 빠른 절반 1개의 선택과 시계 보정이 달라질 수 있다.
실제 제품 1313 실행과 원본 10.78의 CRT 차이도 포함해 재현 근거를 확인하고
동률을 임의로 안정 정렬해 완료로 판정하지 않는다. Node 22·26 전체 회귀
검사를 수행했다.
