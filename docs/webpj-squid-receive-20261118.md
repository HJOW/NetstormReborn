# WB04-E722: 공통 객체 35바이트 수신

`RawSquidReceive.cpp/.h` 기준 `8ee7666b`의 10.78 공통 객체 수신을 `raw-squid-receive.js`로 이식했다. 일반 수신은 현재 Pool의 좌표 비트·표시 좌표·WORD·소유자·HP·상태/프레임을 원본 순서로 쓰고, 선택된 첫 Pop·기술 경고·표식·배치를 호출한다. 검증 수신은 같은 현재 슬롯의 다섯 필드를 순서대로 비교하며 로그 효과 뒤 다음 필드를 다시 읽고 마지막에 verify SID를 지운다. 누락된 선택 장치나 물리 범위 오류는 앞선 실제 쓰기를 되돌리지 않는다.

일반 비행체가 아닌 타입의 독립 Pool로 필드 폭·소유자/기술 경고·첫 Pop 순서, 검증 중 현재 필드 재조회와 원본의 마스크 값, 장치 누락 시 부분 효과를 검사했다. 집중 검사 3건이 통과했다. 이 검사는 공중 3종 전용 생성·행동이나 사제 포획·희생·자연 승리를 실행하지 않는다.

Node v26 전체 6,182건 통과 후 Node v22 전체를 순차 실행했다. 최초 v22에서는 후속 단위 초안을 검사 도중 `www/core`에 미리 만든 탓에 대응표 검사 2건이 실패했다(6,180/6,182 통과). 초안을 검사 대상 밖으로 옮긴 뒤 v22 전체를 다시 단독 실행해 6,182건 모두 통과했다. 이후 단위는 대응표 등록을 마친 다음 전체 검사를 시작한다.

본체는 아직 실제 Session의 Factory·기술 장부·표면과 2ch 등록에 연결하지 않았다. 다음은 같은 Client 검증 전역과 현재 Player/World 장치 연결이다. 압축·변경·검증 수신의 다른 모듈과 나머지 Carrier 등록, Native 경로, 외곽 앱·서버 왕복도 미완료다. 실제 게임이나 브라우저 창은 열지 않았다.
