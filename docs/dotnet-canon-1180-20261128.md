# 1.180 초기 장식 이전 SP 쓰기 추적

1.179와 같은 1-1 진단에 실제 SP 저장 진입을 추가해 첫 장식 선택 이전까지 기록했다. CPP는 소유자1~8에 각각 0을 **두 번씩 16회**, DN은 소유자1에 2840의 float 비트와 소유자2에 0을 **각 1회, 총 2회** 썼다. 두 진단 실행은 종료0이고 각각 제품 대비 40프레임 전체 픽셀과 슬롯이 같으며 원본 1,392파일은 불변이다.

양쪽 SP 저장 본체의 정상 경로는 32비트 각각에 잡음 난수를 다섯 번 사용하므로 한 쓰기당 **160회**, 두 기록 횟수 차이 14회는 **2,240회**다. 1.179에서 실측한 첫 장식 전 2,245회 상태 차이와의 산술 차이는 5회다. 이는 소비 횟수의 대응 관계이지 각 쓰기의 실제 호출자나 나머지 5회의 원인을 특정한 것은 아니다. 시각 보정이나 인위적 난수 소비를 제품에 넣지 않는다.

CPP의 전체 State 정리 본체는 소유자1~8의 SP를 초기화하는 경로를 갖고 현재 DN에는 동일 정리 본체가 있으나 `--mission` 직접 진입은 실제 상태 전환 전체를 아직 호출하지 않는다. 이것은 추가 추적 대상이며, 이 코드 정적 관계만으로 관측된 두 묶음이 모두 같은 정리 호출이라고 단정하지 않는다. 각 진단의 실행 인자·로그·SP 기록·화면·슬롯은 `extracted/dotnet-rng-sp-1180/`에 있다. 포획·공격·승리 입력은 없다.
