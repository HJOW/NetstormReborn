# dotnetpj 1.119 — 다리 가상 타일과 미니맵 드래그 재검증

2026-11-27, HJOW-Athlon. 1.118 실제 실행을 중단한 다리 VT `0x005034c8`의 가상 그림을 연결했다. 해당 VT의 +78은 현재 프레임이고 +a4는 수명 숫자 전역이 0이면 반환한다(`cpppj/src/client/ObjectHitVtables.inc`, `cpppj/src/o/RawBridgeDraw.h`). 비0인 개발용 숫자는 명시 미복원 상태로 남긴다. 다른 가상표는 계속 명시 실패한다. 타일의 TYPE별 공통 소유자 색표와 현재 Player 색 번호, 특수 모드의 원본 필터·타입을 제품 화면 경로에 연결했다. `005453ac`은 장기 Gameplay의 실제 DWORD로 보관하며 다리 붕괴의 같은 전역 연결은 후속이다.

- Release 빌드 오류 0, 기존 nullable·중복 using 경고가 출력됐다. 다리 현재 프레임·소유자 색·수명 숫자 관문과 미니맵을 포함한 집중 검사 **20/20 통과**, `cpp_sync.py` 종료 0이다. 다리 숫자 비0은 본체를 그린 뒤 명시 실패하는 경계도 확인했다.
- `thewarbegins`에서 1.118과 같은 미니맵 누름·드래그·놓기를 수행해 DN과 CPP 모두 120프레임 정상 종료했다. DN의 전후 화면은 `extracted/dotnet-minimap-1119-bridge/`, CPP는 `extracted/dotnet-minimap-1119-cpp/`다. 두 실행 모두 원본 1,392파일 전후 불변이다.
- 프레임별 재수집 `extracted/dotnet-minimap-1119-frames/`도 두 실행 종료 0·원본 불변이다. 미니맵 80×75 영역의 CPP/DN 차이는 75·81·84·86·89프레임 각각 **1/6,000픽셀**, 놓기 뒤 95·105프레임은 **961/6,000픽셀**이다. DN의 89→95프레임 미니맵은 960픽셀이 바뀌고 CPP는 변하지 않았다. 원인은 아직 확정하지 않았다. 스크립트 입력·논리 화면 관측이며 물리 입력·전체 화면 동일성을 뜻하지 않는다.
- 대표 `thewarbegins`·`tutorial1`·`surrounded`의 CPP/DN 여섯 실행 종료 0, DN 90프레임 덤프는 1.116과 바이트 일치, 원본 1,392파일 전후 불변이다. `extracted/dotnet-l2-1119-bridge/`의 비교기 종료 1은 기존 L2 차이다. 전체34경로는 재수집하지 않았다.

R5-4c3c는 드래그 놓기 뒤 960픽셀 변화, 기존 한 픽셀, 실제 미션 전환과 물리 입력이 남아 미완료다. 전체 R5-3은 다른 가상표·일반 객체/건설/UI 출력과 소유자 상태, 나머지 실제 그리기 분배가 남는다. 1.120에서 정기 전체 회귀를 수행한다.
