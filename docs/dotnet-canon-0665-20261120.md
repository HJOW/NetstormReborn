# 0.665 AI 시설 생산의 실제 세션 연결

- 일시: 2026-11-20, HJOW-Athlon.
- 근거: `cpppj/src/client/RawCampaignSession.cpp`의 시설 조립·`ManageAiFactories`와 현재 `contentFinder.sharedBoss` 연결이다.
- 범위: 시설 생산 등록과 현재 레벨/기술 조회의 실제 세션 연결. 업그레이드 요청·수신·착공·완료는 후속이다.

## 구현

`HostSession.AiFactories.cs`는 같은 AI 메모리·실제 풀·TYPE·내용물 조회 상태·현재 시각을 사용한다. 실제 Player 기술 부모를 DWORD 범위 확인 뒤 조회하고, 기존 `RawAiStrategySetup`의 `FindProduct`와 `AddProduct`로 실제 생산 조각을 생성·부착한다. 가상 level80은 원문 조립과 같은 두 가상표만 허용하고 현재 상태 바이트 상위3비트를 읽는다.

`ManageAiFactories(owner)`와 런타임 시설 갈고리를 연결했다. brain이 없으면 효과 없이 거짓이며 owner1..8만 허용한다. 실제 업그레이드 요청은 아직 없으므로 선택 시 명시 오류를 유지하고 큐·기한을 성공한 것처럼 소비하지 않는다. 전체 AI 매 프레임 호출도 아직 남는다.

전략과 시설이 공유하는 내용물 조회는 같은 현재 `Gameplay.Authority.Boss`를 빌리도록 연결했다. 로그는 기존 AI 순서 기록에 남기고 화면 로그 UI는 R6 범위다.

## 검증

- 최초 Release 집중 결과: 23통과·1실패(`extracted/dotnet-0665/factories.trx`). 비로컬 기술 부모의 기존 기술 조각을 검사에서 가상표0으로 만들었고, 실제 `RawFormAttach`가 그 조각의 이전 링크를 쓰며 미지원 가상표를 거부했다. 제품 본체의 관문을 유지하고 검사 입력을 실제 `RawSquidFactory.CreateContained(2)` 생성자로 바꿨다.
- Release `HostSessionAiRuntimeTests` 재검사 **24/24건 통과·실패0**, 종료0이다. `extracted/dotnet-0665/factories-recheck.trx`에 보관했다. 기존19건과 새5건이며, 로컬/비로컬 생산, 같은 실제 풀, 현재 기술/생산 목록, 기한 전 중복 방지, 가상표 거부, 미연결 업그레이드 전 큐 보존을 확인했다.
- 게임·사제 포획/희생·특정 적 공격·승리 재현은 수행하지 않았다. 실제 AI 전체 프레임 진입과 L2 대조는 아직 남으며 정기 전체 회귀는 0.668이다.
