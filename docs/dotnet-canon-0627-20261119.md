- 목표: 0.626에서 고정한 세션 정기 발화가 실제 공장 Fort 경로에서도 Pop 등록까지 이르는지 확인하고, 프레임·정기 집계의 잔여 격차를 R4-4·R4-5·R6 항목으로 특정한다.

## 대조 (증거)

- 공장 등록: cpp 공장 가상표(`48915000`) 7건(타이머 종류 `0x55`=85 7건)과 DN 공장 가상표 7건이 모두 있다. 앞 3건(sid 15005·15014·15021)은 양쪽 sid·가상표·종류·소유자가 일치한다. 공장 Fort 객체가 전용 파생 관문에 걸리지 않고 지형 Pop으로 등록됨을 L2에서 확인했다(0.625 분기의 실측 증거).
- 뒤 4건의 sid가 갈린다. cpp 15037·15038·15052·15062 위치에 DN은 15034·15035·15047·15055를 공장 가상표로 두었다. `cpp_only` 290슬롯에서 sid 재사용 순서가 갈린 결과이며, 공장 분기 자체의 거부가 아니다(뒤 4건도 DN에 공장 가상표 7건 중 일부로 존재한다).
- 프레임: 일치한 앞 3건의 슬롯 바이트 차이는 오프셋 4·5·6(좌표 float 하위)·11(상태)·36(프레임)뿐이다. DN 공장 프레임은 7건 모두 `00000000`이고 cpp는 `05`·`07`·`0a`·`0b` 등 0이 아니다. Pop 등록 뒤 프레임 갱신(정기 발화 경과)이 DN에 오지 않았음을 뜻한다.
- 정기·목록 집계: `process` 행 cpp 72·DN 23, `regular` 행 cpp 62·DN 23이다. DN 정기 행 꼬리 필드가 0으로, 예약 부착(0.626 L1 확인)은 있으나 발화·재예약 집계가 잇지 않았다. `totalmade`는 cpp 21·DN 13이다. DN 덤프에는 `object` 행이 없고 cpp에는 3660행 있다(표시·목록 집계의 별도 결선 잔여).
- L1 재확인: `dotnet test Netstorm.Client.Tests -c Release --filter HostSessionFactoryTests` 0 실패·4 통과(코드 변경 없음, 0.626 유지).
