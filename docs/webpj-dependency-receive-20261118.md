# WB04-E732 감시 Form 수신

`65h` 감시 Form 패킷을 13바이트로 등록하고 현재 Session의 타입과 공장에 연결했다. 수신기는 슬롯을 가져온 뒤 상태와 두 WORD를 기록하고, 현재 가상 표가 감시 Form인지 확인한 다음 같은 부모 슬롯에 부착한다. 첫 Pop 플래그나 소유자를 별도로 설정하지 않는다.

근거는 기준선 `225553df`의 `RawSquidMutationReceive.cpp`와 `RawCampaignSession.cpp`다. 수신기 행의 근거 커밋은 `541624a9`이며 기준선 이후 해당 파일 변경은 없다. 새 원본 fixture는 추가하지 않았다.

독립 검사에서 필드·호출 순서와 부착 실패 시 선행 효과를 확인했고, Tutorial 1 통합 검사에서 실제 분배기와 Session 공장을 거쳐 부모에 부착했다. 처음에는 슬롯 조회 사본을 다시 검사하고 서버 상태에서 수신해 각각 실패했으며, 현재 슬롯 재조회와 클라이언트 수신 상태로 교정했다. 집중 검사 27건이 통과했다.

Node v26.13.0 전체 회귀 6,202건을 통과했다. Node v22 전체 재검사 주기는 2/8회다.

다음은 `2eh` 일반 삭제다. 나머지 Carrier 등록, 서버·클라이언트 로그인 왕복 및 앱의 미션 연결은 남아 있다.
