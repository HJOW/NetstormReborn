# dotnetpj 0.967 — MakeClientCampaignTransport 수송 팩토리(생성·재결합·Publish)

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 수송 생성·재결합·Publish 부모와 그에 필요한 전송 식별·재결합 장치를 이식했다. 0x7b·0x7c Build 연결과 제품 기존 경로는 바꾸지 않는다. 메타 연결 kaynağı 결선(`BindMetaSource`)과 월드 세션 기록(`RecordConnectionPacket`의 세션 갈래)은 R11 후속에서 잇는다. 세션·메뉴 결합 후크 수신기(0x71·1a/1b·0x1d/0x66·0x0f/0x26/2번·참가자/전투 묶음)도 후속에서 잇는다.

## 변경과 원문 대응

- `MissionNetwork`는 빈 묶음이면 새 장치 생성, 값이 있으면 같은 두 owner를 대여하는 원문 소유권 묶음이다. DN에 Editor 전송 장치가 없어 editor 칸을 두지 않음을 명시했다. R11에서 잇는다. 0.967에서 추가됐다.
- `ClientTransportGlobals`는 Player/게임/시계의 실제 소유권만 묶는다. 명목 토큰 대신 팩토리가 만든 같은 묶음을 수송 수명으로 넘긴다. 0.967에서 추가됐다.
- `CompositeMissionTransport.SharedNetwork`는 같은 실제 내부 coordinator를 공유할 때만 참을 돌려준다. 비어 있거나 다른 owner·TCP/UDP 묶음이면 거짓이다. DN은 내부 backend만 보유하므로 TCP/UDP가 있으면 공유하지 않는다. 0.967에서 추가됐다.
- `CompositeMissionTransport.RebindWorld`는 등록 반납 뒤 같은 coordinator를 새 World 장치에 인계한다. 기존 backend의 분배 후크를 바꾸고 역할·서버 조회·수명 owner를 교체한다. 내부 전송은 생성 때 Player9 물리를 고정하므로 같은 Records 배열 재결합만 지원한다. 원문의 같은-서버-주소 검사는 DN 대리자 캡처 방식과 맞지 않아 같은 Records·Registry·동일성 검사로 대신하며 문서에 밝혔다. 0.967에서 추가됐다.
- `ClientCampaignTransport.Make`는 호출자의 BindSession보다 먼저 같은 기본 표를 채우는 원문 순서로 전체 설치를 한 부모에서 호출한다. InternalMission만 지원하며 Editor/LAN은 명시 거부한다(R11). Player 미초기화·역할·길이·소유자 불일치를 명시 실패한다. 지연 분포·현재 Player·벽시계·송수신 기록·종료 후크를 같은 장기 장치로 묶고, 닫기·반납 후크는 실제 backend 미연결로 명시 실패한다(R11, 기존 Build 묶음과 같은 규칙). 생성·재결합 뒤 기본 표 설치와 Source 장부 공개를 같은 순서로 수행한다. 0.967에서 추가됐다.
- `ClientPacketDispatch.InstallDefaults`는 Build와 팩토리가 공유하는 같은 설치 순서다. 새로 만든 설치 본체가 없으며 0x7b·0x7c를 포함한 기존 묶음을 그대로 재사용한다. 0.967에서 추가됐다.
