# dotnetpj 0.798 — 건설 환불과 경로 정리 하위 어댑터

2026-11-22 · HJOW-Athlon · 제품11.01 · .NET10 Release. 사용자 요청으로 개발을 재개했다. 전체 목표와 M1은 미완료다.

## 구현

`RawConstructionPlace.cs`에 Source `RawConstructionPlace.cpp/.h`의 Refund·Money·AddMoney만 이식했다. TYPE 비용의 signed64 절삭과 하위 DWORD, PATCH의 현재 너겟 제외, 현재 PlayerKnown/로컬 번호에 따른 가산 생략, 가산 이후 양수6ch 통지 순서를 보존한다. CD는 가산 없이 양수 통지만 실행한다. 이 모듈은 해체 보상 `RawSquidReward.Refund`를 호출하지 않으며 실제 SP 가산 장치는 기존 `Reward.AddSp`를 사용한다. 전체 Place·ActualPlace·ChargeShortfall·Reject·Player 바인딩은 아직 이식하지 않았다.

`RawPathCleanup.MakeHooks`는 Source의 `MakePathCleanupHooks`와 같이 동일 풀의 실제 carrier.FindContained·anchor.GraphFor·Host.AddSharedRegular·place.Refund를 연결한다. 예약·의식·가상 삭제는 받은 실제 경계를 유지한다. 다른 풀을 첫 효과 전에 거부하며 일반 삭제 Pre/Post나 빈 성공으로 대체하지 않았다.

`HostSession.PathCleanup.cs`는 기존 객체 패킷 장치 설치에서 같은 현재 TYPE/SP/Reward와 장기 너겟 번호·현재 PlayerKnown·로컬 번호를 연결한다. 양수 환불의 실제 통지 장치가 없으면 가산 이후 해당 소비 위치에서 명시 실패한다. `BuildPathCleanupWorldDevices`는 같은 Host/Pool을 사용하는 전체 하위 어댑터를 제공한다. 아직 Motion/30h에서 이를 설치하는 실제 상위 호출자는 없다. 수명 종료는 프로세스를 정리한 뒤 세션 참조를 반납한다.

## 검증

- Release 전체 빌드 오류0·기존 테스트 경고6. 최종 집중 검사는 Core14·Client62 합계 **76통과/실패0**이며 신규6건이다. 전체 회귀는0.796의5,663통과가 기준이고 다음 정기 전체는0.800이다.
- 독립 PE 자료 `constructionplace-x86.tsv`의 **288호출**: PATCH 환불144·잔액48·가산24, CD10.72 환불36, 10.37 환불36. 원문 사건 순서와7BYTE 통지 본문을 대조했다. 전체3,682행 파일을 등록해도 나머지 배치/비용부족/거부 관측을 검증했다는 뜻은 아니다.
- 기존 Cleanup의1,408본문·324질의와 PathProcess/Search/Start 관련 집중 검사도 통과했다. 실제 어댑터 검사는 환불→통지→삭제 순서, 같은 Host의 공유 정기 등록, 잘못된 풀 거부를 확인한다. 세션 검사는 같은 실제 SP 잔액과 현재 PlayerKnown/로컬 번호 변경, 반납 뒤 조회 실패를 확인한다.
- 같은 제품 빌드의 `thewarbegins`·`tutorial1`·`surrounded` 시작3회 종료0. 전체 덤프 바이트와 지표가0.796과 같다. 원본1,392파일은 전후 및0.796 전체 해시 장부와 불변이다. 포획/희생·특정 적 공격·시나리오 승리 재현은 수행하지 않았다.
- 기존413자료의 머리말·항목을 보존하고 한 자료를 추가해414개다. 기존 PORT_MAP 행을 보존하고 실제 부분 이식5쌍을 추가했다. Source·기존 fixture·보호 원본은 수정하지 않았다.

초기 빌드에서 선택 인자5개인 `FindContained`를4인자 delegate로 직접 대입한 컴파일 오류를 발견해 명시4인자 lambda로 수정했다. 초기 로그를 보존했다. 최종 검사 실패나 기대값 수정은 없다.
