## 변경

- FlyerProcessFields는 기본112BYTE와 Sun추가24BYTE를 나눠 보존하고 둘 다 값 복사한다. 원문 Form/부모 DWORD의 하위WORD 조회와 writer의 전체DWORD, 홈 WORD와 padding을 보존한다. Rain/Sun 전문화와 RawWindFlyer::Specialize의 전용 VT/타이머 쓰기만 이식했으며 큰 Wind Frame을 구현한 것으로 세지 않는다.
- 공통 본체는 Source span처럼 현재 TYPE를 빌린다. 전역 구조체는 서버/시각/TYPE owner를 공유하면서 checking 뷰를 값 복사한다. 기본 생성자의 진단 복귀 뒤 현재 시각/TYPE/dirty와 flags8 부착·leaf전문화 순서, 첫 nondead Form의 홈 Bind/Home, 현재 leaf 기반 ReturnDelay와 명령 기한, 파편 효과 뒤 현재 부모 삭제를 보존한다. 큰 Frame/Notify/ParentDying 누락을 성공으로 바꾸지 않는다.
- 상태 codec은 두WORD/세DWORD/두8BYTE의 고정 폭과 dirty 소비를 보존한다. 최대45BYTE 부족 writer는 어떤 변경보다 먼저 거부하고 read는 선택 필드 직전 검사해 선행 부분 효과를 유지한다. 네 원문 VT의 실제 빈 전/후 observer만 허용한다. 수신 leaf는 실제 추가 필드만 초기화하며 임시 소멸의 innerVT와 Form/부모 두전체DWORD -12345도 이식했다.
- 실제 FlyerProcess는 같은 이미지/Host 식별자/Kernel 프레임·통지·부모 사망을 공통 본체에 연결한다. Native는 같은2048BYTE/현재39·1헤더를 읽는다. GameAux의 현재31 TYPE/헤더는 일반 월드 준비가 초기화하지 않는다.
- flyer-postpop-x86.tsv를 Core한 소비자에 읽기 전용 링크했다. 파일은 비주석 머리글 포함1422행이며 실제 입력은C38/P329/B30/W1024다. 이번에는C/B/W 총1092관측만 전수 비교했고 P329는 후속이다. fixture457개/기존456행의 순서·값·해시를 보존했다. PORT_MAP 기존1669자료행을 유지하고 새4파일에9쌍을 추가했다(자료1678, port1190/L1 481/session7). 부분 대응632/1240단위107500/169438줄·미대응608단위61938줄이다.
