# 0.703 현재 Clock 동기화와 Reset 공유

`RawClockSyncReset.cpp/.h`의004c1f20을 Core에, `RawClockSynchronization.cpp/.h`의 서버/Commander 등록·수신·70표본 선별/평균/송신을 Net에 이식했다. 같은 연결/응답/게임보정 DWORD를 빌리고, 표본은 실제70×32바이트를 유지한다. 서버 초기화는 등록 뒤 두 카운터0과응답1만 쓰며, Commander는 등록→표본 전체0→현재 벽시각→카운터/모드/기한→연결 순서다. Reset은 연결→응답→보정만0으로 쓴다.

서버 수신은 시계 조회 전에 주소를 보관하고 전달 여부는 조회 뒤 현재 flags로 결정한다. 요청 수신은 현재 벽시각을 쓴 뒤 요청시간이 같은 첫 표본만 복사하며 중복 수신도 횟수에 포함한다. 만료/2초이상/NaN 표본은 세 double만 지우고 헤더/미작성DWORD를 유지한다. 빠른 절반(최소1)의 RTT/offset을 원문 순서로 합산하고 signed64절삭의 하위DWORD로 지연/보정을 쓴다. 송신은 첫 빈 실제 표본을 빌리며 callback 뒤 현재송신수와 기한을 처리한다. 실패는 앞서 발생한 표본 쓰기만 남긴다.

원본CRT004e6010/004e5fa0의 피벗·동률·작은 선택정렬 순서는 기존 `ParticleGradient` 복원에서 재사용했다. C++ 시간 몸체는 호스트 `std::qsort`를 호출하므로, 이번 DN 동률 처리는 원본CRT를 기준으로 했다. 새 Clock 전체의 독립PE 관측 fixture가 있는 것으로 주장하지 않는다. 원본자료가 존재하는 Reset64행은 최초/반복 모두 두96바이트 전체로 일치했고, 나머지는 C++ 몸체/기존CRT와 명시 외부 입력을 근거로 검사했다.

장기 owner가 주어지면005번 고정F004c1f60이 같은 Client 전역/실제 시계/송신만 보유한다. readonly 입력의 앞32바이트만 지역 writable 응답으로 복사하고 NULL연결/짧은 물리를 진단한다. 초기화는 version/길이/정책을 유지하며 실제 고정F/observer baseline도 등록 대여 반납 뒤 유지한다. `ConnectionSyncState`에는 같은Client DWORD를 공개 getter/setter로 빌리는 생성자를 추가했다. 기존 대기 개수는 보존하며 Registry는 자기 현재 개수를 계속 쓴다. 같은보정이 실제 GameClock과 Registry뷰에 즉시 반영됨을 확인했다.

초기 빌드는 공개 동기화 참조 생성자 누락으로 실패해 실제Client 결선용 입구를 추가했다. 이후22통과·2실패에서 주소 없는 응답이 빈 `ReadOnlyMemory`로 변환되는 오류를 발견했다. nullable 조건식의 암시 변환을 피하고 명시 NULL초기화/조건부 대입으로 수정했다. 현재 flags4입력과 실제고정F prefix복사를 재검사5건 통과했다. 현재 고유25건(새 Clock21·manifest4) 전부 통과·실패0이다. 기존 경고3개는 유지됐고 새 경고는 없다. 근거는 `extracted/dotnet-0703/core-initial.log`, `core-final.log`, `null-address.log`, 대응TRX와 `verification-summary.json`이다. `cpp_sync.py` 종료0, fixture357개다.

제품Root의 장기Client owner/게임 프레임에는 아직 설치하지 않았다. 실제 게임/공격/포획/희생/승리 재현은 수행하지 않았다. 다음0.704는 전체 회귀/시작 덤프, 이후 장기 전역과Root 연결이다. 전체 목표와M1은 진행 중이다.
