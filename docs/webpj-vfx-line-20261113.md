# webpj VFX 일반 선 VFXLine 클립 알고리즘 (WB04-E379, 2026-11-13, 5-A 여덟 번째 단위)

5-A 의 시각 효과 소단위 중 client **VFXLine**(cpppj `client/VFXLine.cpp/.h`, 120줄)의 partial 상태를 끝냈다. 웹 `render/vfx-line.js` 는 WB03-G(스크롤바 화살표)에서 "클립 경계의 선도 전체를 걸으며 밖의 픽셀만 건너뛴다(결과 같음)"는 단순 구현이었는데, 원문은 **원래 시작점 기준으로 양 끝점을 따로 잘라** 그리는 알고리즘이라 가장자리에서 서로 다른 픽셀이 나올 수 있다. 이번 단위에서 원문의 클립(Cut/Inverse/DIV 범위, 위상 재계산)을 그대로 옮겼다. 기준선 뒤 cpppj 변경이 없다(base `1f00a25a`). 원본 004011f1/CD 00464bd1 의 mode 0(단색 8비트)이다.

## 1. 규칙

- **`drawVfxLinePixels(pixels, pitch, height, clip, first, last, color)` (cpppj `DrawVfxLine`):** 표면 용량(`pitch ≥ 1`, `height ≥ 1`, `pitch × height ≤ 픽셀 수`) 오류는 `RangeError`. clip 은 반개방이며 표면 전체와 교차하고 비면 돌아온다. 색은 하위 BYTE. 수평·수직선(한 점 포함)은 양 끝을 포함해 클립과 교차한 부분을 채운다. 그 밖의 선은 `|dx|`·`|dy|` 가 signed 31비트(`2³¹−1`)를 넘으면 `RangeError`, 아니면 기울기 `slope = (짧은 변 << 32) / 긴 변`(두 변이 같으면 `0xffffffff`)과 주축(`|dx| ≥ |dy|` 이면 x)·부호(`(dx<0) != (dy<0)`)를 정한다.
- **클립(`clipLine`):** 포함 경계 `[left, right−1]×[top, bottom−1]` 로 두 끝점의 분류 비트(왼쪽 8·오른쪽 4·위 2·아래 1)를 구해 둘 다 0 이면 보임, 공통 비트가 있으면 안 보임, 아니면 (첫 끝점이 밖이면 첫 끝점, 아니면 마지막 끝점)을 `cut` 하고 반복한다(32번 상한). `cut` 은 현재 끝점이 아니라 **원래 시작점**에서 거리 `|경계 − 시작 좌표|`(부호 없는 32비트로 자름)를 잰다. 같은 축이 주축이면 `round(거리 × 기울기 / 2³²)` = `high32(거리×기울기) + (low32 ≥ 0x80000000)`, 다른 축이면 DIV 역산 `((시작이면 거리−1(부호 없는 32비트 감김), 아니면 거리) << 32 | 0x80000000) / 기울기` 에 시작이면 +1, 나머지가 0 이면 −1 한다(32비트를 넘는 몫은 `RangeError`). 부호는 `(경계 < 시작) != 음의 기울기`, 반대 축 좌표 = 시작 ± 오프셋(32비트 감김).
- **그리기:** 잘린 첫 끝점의 주축 거리로 분수 위상 `(거리 × 기울기 하위 32비트) + 0x80000000`(32비트 감김)을 다시 계산해 잘린 시작~끝(`|끝−시작|+1` 걸음) 사이를 걷는다. 걸음마다 포함 경계 안이면 색을 쓰고, 위상에 기울기를 더해 32비트를 넘으면(carry) 부축을 한 칸 옮긴다(주축 x 면 `x += sx` 와 `carry`(또는 45도)면 `y += sy`, 주축 y 면 반대). 좌표 갱신은 32비트 감김이다.
- **`drawVfxLine(surface, first, last, color, clip)`:** `{ pixels, width, height, bounds }` 표면의 얇은 포장이며 clip 기본값은 표면 전체다. 슬라이더 화살표(`ui/slider.js`)와 VFX 타원의 반경 0 선이 쓴다.

## 2. 웹 범위

- 소비자는 이미 있는 `ui/slider.js`·`render/vfx-ellipse.js` 와, 후속 단위의 `RawCampaignParticles`·`DrawWater`·`RendererDiagnostics`·`GumpDraw` 다. 후자의 원본 관측 fixture(`draw-water*`·`renderer-diagnostics`·불꽃 꼬리/EvilRay 입자)가 이식되면 같은 선 모듈로 다시 대조된다. DOM 을 쓰지 않는다. 큰 값의 곱·몫은 BigInt, 걸음 순회는 Number/`|0` 이다.
- E377 문서의 "반경 0 인 거대한 좌표에서는 걷기 비용이 크다" 경계는 이번 클립으로 해소됐다(선 길이가 아니라 보이는 구간만큼 걷는다).

## 3. 검사 (`tests/vfx-line.test.mjs` 9건 + 기존 `help.test.mjs` 선 6건·`vfx-ellipse.test.mjs` 270행 재확인)

- **원본 독립 관측(10.78):** `fierytail-pixels-x86.tsv` 기본 027f **30행**(12 입자 불꽃 꼬리, 64×48 표면, 배경 199, pane/클립/카메라/끝점/오프셋 변화)을 실제 `RawFieryTailFrame.draw` 가 요청한 선으로 그려 **첫 실행에서 전체 화면 일치**했다(선 끝점이 표면 밖에 걸쳐 클립 교차가 실제로 일어난다). 확장 정밀도 037f 30행은 중복 가산하지 않고 건너뛴다.
- **독립 참조 모델:** 같은 C++ 알고리즘을 모든 값 BigInt 로 다시 쓴 모델과 3만 라운드(표면 8~47×8~37, 끝점 범위 24~240, 가끔 45도/축 정렬/한 점, 부분·빈 clip, 색 0~299)에서 표면과 오류 종류가 같고, 끝점이 모두 표면 안인 선 3000개는 양 끝점이 항상 칠해진다.
- **계약:** 표면 용량 오류와 정확히 맞는 길이, 1×N/N×1 표면, 수평·수직·한 점의 포함 끝과 표면 밖 연장, 색 하위 BYTE(0x1ff→255·256→0), 빈 clip 8종과 한 칸 clip, 기울어진 선의 방향·위상(손으로 따라간 값: dx=4·dy=2, 역방향, 45도, 급경사, 표면을 가로지르는 선), 선 길이 한도(`2³²−1` 거부·`2³¹−1` 허용), `drawVfxLine` 위임.
- **옛 전체 걷기와의 차이(참고):** 옛 구현과 새 구현을 무작위 20만 선(40×30)에서 비교하면 91건(0.05%)이 가장자리 몇 픽셀 다르다. 대표 사례: 클립 위 경계 행에서 시작해 위로 올라가는 완만한 선의 마지막 끝점을 잘라낼 때, 거리 0 의 부호 판정(`delta < 0` 가 아님)이 원문대로 오프셋을 반대 방향으로 적용해 끝점이 시작점 뒤쪽으로 잡히고, 왼쪽 경계에서 다시 잘리며 선이 짧아진다(예: (9,6)→(31,5), 위 경계 6: 옛 12픽셀·새 5픽셀). 이런 칸은 원문이 정말 그렇게 그리는지 원본 관측이 없어(불꽃 꼬리 30행은 옛 걷기도 통과한다) cpppj 의 원문 복원을 따랐다. DrawWater/RendererDiagnostics 입자 fixture 이식 때 선이 클립에 걸린 행이 생기면 이 경계를 다시 대조한다.

## 4. 변형 확인과 남은 경계

- 자동 연산자·상수 변형 96개와 손으로 쓴 구조 변형 35개(경계 반올림, 시프트 폭, 시작/끝 +1·−1, 부호, 우선순위, 포함 경계, 분류 비트, 길이 한도 등)를 적용했다. 손 변형은 `ax === ay ||`(45도에서 carry 가 항상 참이라 동등) 하나만 남았다.
- 남은 동등/도달 불가 변형 30개: ① 32번 클립 반복 상한(`CLIP_ITERATIONS` 및 루프 시작 값)과 수렴 실패 `Error` — int32 극단 좌표 30만 건에서도 5번 안에 끝나고 DIV 범위 초과·수렴 실패는 한 번도 나오지 않았다(이론상 부축 역산은 `거리 ≤ 짧은 변`이라 몫이 `2³¹` 이하, 시작 거리 0 + 반대편 끝이 같은 분류 비트를 공유해 먼저 거절됨), ② `BigInt.asUintN(32→33)` 폭(값이 항상 32비트 안), ③ 빈 clip 조기 반환의 `||`/`>=`(없어도 한 번의 cut 뒤 공통 비트로 거절돼 결과 같음), ④ 수평·수직 분기의 `||`(일반 분기도 같은 픽셀)와 빈 구간 `>=`(빈 채움), ⑤ `0xffffffff` → `0x100000000`(45도 반올림/역산 결과 같음)·`ax >= ay` → `>`(45도 대칭), ⑥ `dx < 0`/`dy < 0` 의 `<=`/`0→1`(이 분기에서 0 이 아님), `delta < 0` 의 `<=`/`0→1`(−0), ⑦ 위상의 `asUintN` 폭(뒤의 `>>> 0` 이 자름).
