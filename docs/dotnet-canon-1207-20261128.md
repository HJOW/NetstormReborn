# 1.207 음악 버퍼 갱신과 실제 COM 경계

같은 MusicChannel의96BYTE/재귀 잠금에 FillBuffer를 연결했다. 재생 상태·손실 복구·음량·재생 커서·링의 두 구간 Lock·실제 파일 Read·Unlock·첫 반복 Play를 원문 순서로 실행한다. 오류의 로그/Stop, 부분 읽기와 선행 위치 쓰기, 예외 때 Unlock 및 실제 잠금 반납을 보존한다. 두 구간은 ref struct의 Span으로 같은 메모리를 빌리며 표본을 다른 배열에 복사해 대신 쓰지 않는다.

WindowsSoundDevice의 기존 장치/버퍼 토큰에 음악용 Create·Status/HRESULT·Restore·두 커서·Lock/Unlock·Play와 개별 Release를 추가했다. 포인터 폭을 유지하고 길이0인 비영 구간 주소도 Unlock에 그대로 돌려준다. Span 변환 실패도 실제 Lock을 반납한다. 좁은 플랫폼 포인터 경계용으로 Game 프로젝트에 AllowUnsafeBlocks를 설정했다. ForPrimary helper와 Update는 같은 명시 primary·기존 음악 명령 잠금을 공유한다. callback 전용 기존 생성자와 Play/Stop 경계는 유지한다.

`musicstream-x86.tsv` **5,088행(10.78 1,704·CD1,692·10.37 1,692)**의 상태/사건·전체96BYTE·출력128BYTE·파일 위치/열림을 대조했다. 실제 링 감기·IO 예외·잘못된 구간/커서·자연 미준비 관문을 포함한 Stream6건과 장치4건이 통과했다. 장치 검사는 실제 제품 vtable/포인터 경계에 합성 COM 응답을 공급하며, 실제 Winmm 파일 읽기·직접 unmanaged 구간 쓰기·빈 구간 주소·개별 반납을 검사한다. DirectSound DLL/하드웨어의 정상 재생이나 청취 완료로 확대하지 않는다.

모든 제품/검사 소스 동결 뒤 Release 솔루션 **오류0·기존 경고25·종료0**, 2분14.46초다(`extracted/dotnet-1207-build.log`). 새 출력은 `extracted/dotnet-1207-artifacts/`다. 기존 채널/열기/전체선택/음량/효과음/파일/자료 목록과 합친 집중 **66/66 통과·실패0**, 13초이며 `extracted/dotnet-1207-tests/music.trx`·로그에 있다. 전체 회귀는 제품4단위 주기에 따라1.210에서 수행한다.

자료는 사본 없이 Client에 링크하고 공통 목록에5,088행/SHA `636f944204f7483fb1c2fab30be37381687636882995495899e4275108e03767`를 등록했다. 목록520개이며 기존 전체 반영 커밋은 유지했다. 새 부분 소스의 대응8행을 PORT_MAP에 등록했다. 별도 미검증 준비본은 아직 제품에 넣지 않았다.
