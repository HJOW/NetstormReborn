## 현재 소유자와 목록

`RawCommonOwner`는 현재 challenge→범위 진단→현재 편집/전투와 TYPE의 목록 제거→소유자BYTE 쓰기→현재 모드/TYPE의 목록 추가 순서다. 선택한 효과만 요구하며 진단이 정상 복귀하면 원래 요청의 하위BYTE를 계속 적용한다. 전체 TYPE/free/Player 목록을 앞에서 검사하지 않는다. PATCH는 소유자 쓰기 뒤 모드를 다시 읽고 CD는 쓰기 직전 battle→fort를 둘 다 읽어 저장한다. 조건의 short circuit도 유지한다.

`SquidOwner`는 생성 시 TYPE의 독립 깊은 사본을 갖고 `BindDiagnostics`로 현재 표를 명시 대여한다. 빈 표는 사본을 사용하고 잘못된 재연결은 이전 대여를 보존한다. 함수 객체는 복사하며 선택한 목록만 실제 Player 물리 범위를 검사한다. 따라서 도전20은 유효 요청이며, 작업장 목록을 선택하면 이전 목록 제거·소유자20 쓰기 뒤 없는 Player 행에서 실패한다. 기존의 "모든 실패는 무변경" 검사는 현행 cpp의 부분 효과로 교정했다.

`RawPriestOwner`는 현재 실제 사제 가상 표로 분배하며 TYPE/free를 추가 검사하지 않는다. 최초 전투/로딩 분기가 원래 소유자를 바꿀지와 effective 값을 정한다. 원래 소유자BYTE 쓰기→알림→선택된 공통 부모→현재 로딩/모드로 로컬비트 쓰기→알림 순서다. 진단·알림·공통 부모가 모드나 WORD를 바꾸면 후단은 변경 후 값을 읽되 최초 effective는 유지한다. 높은WORD BYTE는 보존하고 입력 함수 객체 사본도 유지한다.

`RawPostPopList`는 별도 파일로 분리했다. 독립 배열/개수 또는 현재 저장소·용량·개수·개수쓰기 네 경계를 같은 소비 위치에서 선택한다. 빈 독립 목록에만 완전한 연결을 허용하며 실제 owner/행 정체성은 물리 조회 없이 비교한다. 가득 찬 Append는 배열을 읽지 않고, 저장 뒤 개수를 증가시킨다. 중복 전체 제거는 현재 개수/배열을 다시 읽어 안정 압축하고 stale 꼬리를 유지한다. 개수 쓰기가 모드를 바꿀 수도 있으므로 Owner가 후단의 현재 모드를 다시 읽는다.

실제 HostSession의 Player/요새 객체 Owner와 지형 도장 Owner, RawSurfaceWorld의 공통 Owner에 같은 현재 TYPE 표와 선택된 진단을 연결했다. 장치 구성 후 TYPE genus를 바꿔도 두 경로가 바뀐 표를 소비하는 호스트 검사를 더했다. 이것을 전체 사제 후처리 결선이나 M1 완료로 세지 않는다.
