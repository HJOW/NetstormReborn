# 0.612 Fort 배치 어댑터 결선 훅 메이커 (MayPlace 실결선 준비)

- 일시: 2026-11-18, HJOW-Athlon
- 범위: R4-2 농지 잔여의 MayPlace 실결선 준비. `RawFortRandomPlacement.MakeFortRandomPlacementHooks` 추가와 L1 2건 검증이 중심이다.
- 목표: 0.608에서 기각된 MayPlace-true(`dn 144셀 대 cpp 152셀 중 21셀만 겹침`) 대신, 실제 파이프라인·공장·HP 조회를 꽂는 결선기를 마련한다.

## 원인

- 0.608 검증에서 MayPlace-true 대역은 선택 집합이 어긋나 기각됐고, 결선을 전부 되돌렸다.
- 0.609~0.611에서 권한·관계·앵커·서라운딩·파이프라인 본체와 전체 MayPlace 3건 전수 일치를 닫았으므로, 다음은 cpppj `RawFortRandomPlacement.cpp` 130행 상당의 어댑터를 옮길 차례였다.

## 수정

- `dotnetpj/src/Netstorm.Core/Original/RawFortRandomPlacement.cs`: `MakeFortRandomPlacementHooks(pool, placement, factory, hp, hooks)` 추가.
  - 네 몸체의 풀이 모두 같은 인스턴스인지 확인하고, 다르면 `ArgumentException`으로 거부한다.
  - `MayPlace`는 파이프라인 실제 판단, `Create`는 공장 생성, `Construct`는 공장 생성자, `HasHitPoints`·`TypeHitPoints`는 HP 조회에 연결한다. 나머지 갈고리(지역·owner·Pop 등)는 호출자가 둔 것을 그대로 둔다.
  - `using Netstorm.Core.Simulation;` 추가는 `SidAllocation` 열거 참조용이다. 제품 동작 변경은 없으며 새 정적 메서드 1개 추가가 전부다.
- `dotnetpj/tests/Netstorm.Core.Tests/FortRandomPlacementHookTests.cs`: 신규 L1 2건.
  - `WiresRealHooks`: 같은 풀에서 다섯 갈고리가 모두 연결되고 같은 묶음을 돌려준다.
  - `RejectsForeignPool`: 풀 하나라도 다르면 거부한다.

## 검증 (증거)

- `dotnet test Netstorm.Core.Tests -c Release --filter "FullyQualifiedName~FortRandomPlacementHookTests"`: 0 실패·2 통과(약 77ms).
- Release 빌드 0경고·0오류(기존 xUnit2020 안내 2건 유지).
- PORT_MAP 변경 없음: `RawFortRandomPlacement.cpp/.h` 행(391·394번, L1)이 이미 같은 파일을 가리키며, 새 메서드는 같은 단위 내 추가라 행 추가가 필요 없다(1031행·L1 455·fixture 324개 유지).
