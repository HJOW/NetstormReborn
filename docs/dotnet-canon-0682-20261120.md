# 0.682 실제 업그레이드·감시 쌍 세션 연결

- 일시: 2026-11-20, HJOW-Athlon.
- 근거: `RawCampaignSession.cpp`의 `ConnectFactoryUpgrade`, `RawSurfaceDepend.cpp`, `RawSurfaceAssetDeletion.cpp`, 앞 단위에서 원본 대조한 업그레이드/감시 본체다.
- 상태: Client와Core 집중 검증 완료다. 전체 목표는 미완료다.

## 연결

`WorldFactoryUpgrade`는 같은 공장·풀·Host·현재 레벨/최대HP·프레임/표시·실제 건설 진행·플레어·음향에 연결된다. 공장 정기 사건3의 첫 호출은 실제 클라이언트 그림/건설/감시 쌍을 만들고, 후속 호출은 실제 완료를 실행한다. 현재 Player 기록의 brain을 다시 읽어 AI 시설 목록과 지갑에도 완료를 통지한다. 원본00541250의 현재 아웃포스트 역할 상자는 공장 고정프레임과 업그레이드가 공유한다.

`WorldDependencies`는 복제 공장 없이 같은 실제 Form 공장과 현재 Depend TYPE를 사용한다. 생성/검색/쌍 삭제·부모 죽음 통지를 연결했고, 공통 삭제가 감시 클래스의 가상 수명을 지나도록 연결했다. 실제 ProcessForm 통지만 같은 Host의 실제 PID로 전달한다. 자산은 보호83개 VT 표의 원본+34를 선택한다. 빈 ret8은 TYPE·owner·상태·통지 인자를 선행 검사하지 않는다. 원본의 자산 통지 표를 새로 복제하지 않고 기존 장기 저장소 분배와 공유한다.

제품 음향은 같은 이름표/위치 재생기와 priority1 전역 완료음을 사용한다. 진행 로그의 원본 종류는 실제 오류/활동 기록에 남긴다. 게임 내 메시지 표시는 후속R5 HUD 연결이 남아 있다. 미션 반납은 감시 쌍과 업그레이드 장치를 반납하며 외부 Kernel 프로세스를 보존한다.

## 검증

Client Release 집중 **59/59건 통과·실패0**, 명령 종료0이다(`extracted/dotnet-0682/upgrade-once.trx`, `extracted/dotnet-0682-once.log`). 신규6건과 기존 사제/연소/건설/플레어·지역·AI 런타임 검사를 함께 실행했다.

- 정상 공장을 먼저 실제 건설한 뒤 SharedRegular 사건4/3으로 업그레이드를 시작하고, 클라이언트 그림의 다음 레벨/소유자·실제30 진행·양방향 감시·현재 정기 개수와 완료 후 레벨/HP/프레임·그림/사건4/3/감시 정리를 확인했다.
- 복수 예측 그림의 저장next 순서 정리와 현재 아웃포스트 역할의 완료 생략을 확인했다.
- 실제 감시 생성/검색/쌍 삭제·다른 감시 보존·미션 종료 반납·외부 Kernel 보존을 확인했다.
- 부모 공통 삭제가 실제 ProcessForm의 가상2 통지에 사건/감시Form/부모를 전달하고 쌍을 정리하는 것을 확인했다.
- 자산의 빈 원문 통지가 잘못된 TYPE/owner/상태와 인자를 추가로 읽지 않는 것, 미복원 VT가 명시 실패하는 것을 확인했다.
- 명시적으로 초기화한 실제 AI 메모리 본체/목록과 현재 Player brain으로 시설 추가·현재TYPE 비용 차감이 이어지는 것을 확인했다. 이 검사는 AI 전체 생성/플레이 재현을 대신하지 않는다.
