2026-11-27 HJOW-Athlon. 실제 와이드 미션이 E1449에서11.3~14.1FPS에 머무는 원인을 CPU 표본으로 좁혀 네 모듈을 수정했다. 같은 논리 화면/게임 상태를 보존하면서, 본 소스 재적재의 정상rAF 실제 아군AI1-1 표본은36.4~45.0FPS였다. **60/120FPS 달성은 확인하지 못했고 M5 성능 목표는 남는다.**

원래 반복 호출마다 전체 RGBA 변환/Canvas 전송이 일어나던 곳을 발견했다. 부분 변환만 적용한 첫 후보의 개선은 작았고 프레임 전송 합산과 행 복사/객체 조회까지 단계적으로 검증했다. 초기3검사는 원래 소스에서 모두 실패했고 후보 집중은44→46→47→88개로 보강됐다. 최종 본 소스88/88, 후보4모듈 각각ESLint0 및 전체 선행ESLint/운영빌드0, 재번들1/1, 기존 Chromium 시작/덤프 L2 1/1이다. 번들은3,517,008바이트다. 대응표1160행/오류0·기존CPP변경0/새10파일 판정은 유지한다. fixture1331개는1319개 정규화해시 일치/존재 누락0이며 source종류12개는 기존 규칙대로 해시 대상이 아니다. 느린 CPP Git기준선 전체 CLI는 별도 실행 중이며 이 파일 검사와 구분한다.

최종 후보와 본 소스 네 파일은 원시 바이트/SHA가 같다. 수정 전/후 실제 아군AI1-1을 각각 같은523고정프레임까지 진행하고 첫 안내·일반 진행·F5·1920×1080/1280×800/1024×768복귀의 각8시점에서 실제 Canvas 전체 픽셀을 검사했다. 모두0픽셀 차이이고, 전후 각 시점의 전체RGBA SHA도 같았다. 실제 게임/AI 덤프는 소유자0 SP와 주소 잔재 Player행의 기존 비교 정책 밖 차이0이다. 관측 최종 Canvas호출은1104→479였다(행/사각형 출력 횟수로 게임 프레임 생략을 뜻하지 않는다). 별도3확대방식×4배율×6변경의 실제Canvas72시점도 원래 전체 표시기와0픽셀이다.
