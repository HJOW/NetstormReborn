# dotnetpj 0.906 — RU-3 NSInfo 등록 명부 정렬·행 작성 이식

2026-11-24, HJOW-Athlon. RU-3 두 번째 묶음이다. 메타 NSInfo의 실제 참가자 등록 명부 정렬·행 작성을 이식했다. 제품 기존 경로는 바꾸지 않는다.

## 변경과 원문 대응

- `HudNsInfoMeta`는 `cpppj/src/client/HudNsInfoMeta.h·cpp`의 `HudNsInfoMetaGlobals`/`HudNsInfoMetaHooks`/`RefreshNsInfoRoster(0047e630: 전체 39명 초기 순서·원문 쌍교환 정렬·이름/문맥/행 metadata)`를 이식했다. 같은 실제 CS 참가자40·`RosterOrder` 40DWORD·현재 메타맵/인식/소유자 조회를 빌린다. 후속 배치·입력·특수 그림과 NativeRoot/HUD 창 생성·Enter·HUD 작성자·Root reply 저장은 후속 단위에서 잇는다.
- 0번을 보존하고 1..39행만 초기 순서로 쓴 뒤, 유효한 상대의 레벨 BYTE를 먼저 비교하고 동률 때만 상대→현재 순서로 기술 합계를 읽어 원문 쌍교환으로 재배치한다. 유효행만 추가하되 metadata는 실제 참가자 번호가 아닌 정렬 배열의 행 번호다.
- 행 본문은 ` level+1.rank 이름\n`이며 120BYTE 이상은 명시 거부한다. 자신이면 실제 소유자 판정과 메타 모드 조회로 소유 문맥을 고르고, 부전공 78은 `0xc4`·초과는 `0x9d`·미만은 `0xdf`를 쓴 뒤 `0x5c78d0`·고정 꼬리를 채운다. 관문 미달은 조용히 반환하고(원문 관문), 미연결 장치는 일반 Pre/Post/no-op으로 통과시키지 않고 명시 실패로 둔다.
- PORT_MAP은 이전 1828행의 값·순서·base를 보존하고 2행을 추가했다(자료 1830행). fixture 496개는 그대로다(합성 CS 기록 검증이라 신규 fixture 없음).
