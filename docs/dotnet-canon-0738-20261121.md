# 0.738 실제 서버 목록 파일과 파일명 출력 고리

RootServerListDisk.cpp/.h의 읽기·저장을 같은 실제 ClientHostGame.NsInfo 소유자와 연결했다. 생성자는 물리 Surface 준비 뒤 첫 메뉴 앞에서 한 번 서버 목록을 읽는다. 실제 Root reply/메타 UI가 선택할 SaveRootServerList 경계도 같은 목록과 파일 장치를 사용한다. 전체 Native Root reply/UI의 설치는 아직 후속이며 이번 단위에서 저장을 종료 시마다 강제로 실행하지 않는다.

읽기는 사용자 Saves/!rootservers.dat → 설정 DataDir/!rootservers.dat → DataDir/rootservers.dat 순서다. rb 열기 실패만 뒤 경로로 넘기며, 열린 파일의 길이/부분 읽기 실패나 긴 행 파싱 실패는 뒤 정상 파일로 숨기지 않는다. 존재하는 빈 파일도 성공이므로 목록을 비우고 fallback하지 않는다. 모든 파일이 없으면 현재 목록/체크섬을 보존하며 읽기만으로 사용자 폴더를 만들지 않는다.

저장은 원문 root/DataDir/!rootservers.dat 파일명 작성 효과 뒤 사용자 Saves 경로에만 w+b로 쓴다. 사용자 정책을 생략해도 UserDataRoot.Resolve를 사용한다. 폴더 생성 실패는 전파하고 fopen에 해당하는 파일 열기 실패는 조용히 복귀한다. 행은 첫NUL까지만 쓰며 그 앞에 LF가 하나도 없을 때만 LF 한 개를 추가한다. 원문 비ASCII BYTE·중간LF·빈행과 stale 체크섬을 유지하고 열린 파일은 모든 경로에서 반납한다. 원문 fwrite/fclose의 실패 반환값을 사용하지 않는 경계도 유지한다. 설치 자료는 쓰지 않는다.

저장에 필요한 RawFileName.Format(459c60)과 Index/CurrentBytes를 Assets에 이식하고 실제 GameFileSystem이 같은 10×256BYTE 고리를 소유하게 했다. Core가 Assets를 참조하므로 역방향 참조 없이 파일 장치에서 제공한다. 부품 종류/순서·고정 연결 역슬래시·separator 치환·한 문자 후행 slash·확장자 dot·선행 clear와 입력 별칭·10회 재사용·부분 실패 출력을 보존한다. 다른 Device/Name/Directory/Full 몸체, 전체 BaseFile 읽기 정책의 같은 고리 소비와 ClientStaticStrings 파일명 owner 일원화는 아직 후속이다. PORT_MAP의 RawFileName 행은 이번 Format/조회 범위의 부분 이식이다.

기존 원본 fixture file-name-formatter-x86.tsv의352입력(정상186/실패166)을 모두 읽어 성공/실패·선증가 번호·현재256BYTE 전체가 일치했다. 신규10건 포함 최종 집중29건 통과·실패0이다. 파일 없음/빈 파일/우선순위/긴 행/사용자 열기 실패, 행 바이트·고리 작성·설치 불변·stale 합계, 쓰기 열기/폴더 실패를 실제 임시 디스크로 검사했다. 첫 집중24건도 통과했고, rb 열기 실패 분기를 보강한 뒤 최종 검사를 수행했다. 근거는 extracted/dotnet-0738/client-initial.log·client-initial.trx·client-final.log·client-final.trx다.

대표 thewarbegins/tutorial1/surrounded 시작은 같은 시드1760000000·25ms/90프레임·영어1024×768 창/음소거 조건으로 모두 종료0이었다.0.736 전체 덤프 바이트/기존 비교 지표가 같고 원본1392파일 SHA가 불변이었다. 근거는 extracted/dotnet-0738/capture.py·capture.log·capture-summary.json·capture-originals-audit.json·audit.py·final-audit.json이다. 포획/희생·특정 적 공격·승리는 재현하지 않았다.

PORT_MAP에 확인한 d97301d(RootServerListDisk 두 파일)·c2d2922(RawFileName 두 파일)를4행 추가했다. fixture manifest에는 위 원본 fixture의 정규화SHA-256 9abf8632875f9fd1c362814ec3668e2c4f619a1eda081effb0cfc74f94e25834/352행/Client 한 개만 추가했다. 기존365행 해시는 보존하며 cpp_sync 종료0, 총366개다. 새 네트워크 연결·DNS·폐기 클라이언트 검증 소비자는 없다.
