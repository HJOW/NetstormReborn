# 0.706 실제 현재 Runtime의 준비 대여와 배송 수명

`ClientGameplayGlobals.cpp/.h`의 AcquirePrepared·Use::Publish/Withdraw·RequireSession·BindRuntimeOwner·PinCurrentRuntime·RuntimeCallActive를 실제 제품 HostSession에 연결했다. C#의 HostMissionRuntime은 해당 세션, 같은 Pool의 RawSurfaceStorage, 실제 음향/표시/UI 객체 묶음을 보유한다. 명목 토큰을 실제 owner로 사용하지 않는다. 호스트는 월드·장치를 완성한 뒤 준비 대여/Session 공개/weak owner를 연결하며, 준비 대여는 기존 Player/권한/시계/옵션/저장 값을 재초기화하지 않는다.

장기 전역의 현재Session과외곽owner 공개는 weak다. 선택 위치에서 같은Session/owner인지 확인한 뒤 실제 전체 owner를 강하게 빌리고 실행 횟수를 올린다. 호출 반납은 횟수 감소 뒤 마지막 실제 owner 반납 순서다. 외부 Runtime을 반납해도 실행 대여가 남으면 마지막 복귀까지 유지된다. 참조 수명 제어는 기존 공통 ConnectionDeviceLifetime을 재사용하지만 Registry의 실제 전송Source 대여와 섞지 않는다. Node등록은 계속 CompositeSource를 빌리고 이 Runtime 대여는 선택된 게임 배송만 보유한다.

호스트 종료와 전체 AI/Player/건설/연소 반납은 실행 배송 중 거부한다. 정리 성공처럼 상태를 비우지 않으며 기존 대여를 유지한다. 이전 Session의 저장된 pin 장치는 현재 Session이 교체되면 새 owner로 몰래 연결하지 않는다. 호스트는 연결/Source를 먼저 정리하고 실제 Runtime 공개를 반납한 뒤 기존 자식/음향/UI를 정리한다. 실제 장치의 반납 효과는 같은 호스트가 수행하고 Runtime은 호출 동안 장치를 보유한다.

집중18건(새Runtime8·기존공유전역6·실제Flare4)이 통과했고 실패는0건이다. 준비 대여의 값 보존, 미공개/다른Pool/다른Session/중복대여 거부, 공개와반납의 분리, 중첩pin·실행중전체반납거부·외부owner지연반납, 하위예외복귀, 이전Session pin 거부, weak공개가 실제owner를 강하게 소유하지 않음과 GC 뒤 실제 세션/저장소/MemoryStream장치의 배송 수명을 확인했다. 최초 빌드는 항상throw하는 검사lambda가 xUnit의 비동기 overload로 선택돼 실패했다. Action을 명시한 뒤 통과했다. 제품 본체를 해당 실패에 맞춰 바꾸지 않았다. 근거는 `extracted/dotnet-0706/client-initial.log`, `client-final.log`, `mission-runtime-final.trx`다. 기존 nullable경고3개 외 새경고는 없다.

실제 DN `thewarbegins` 시작/종료1회는 종료0, f090전체바이트0.704일치, 원본1392파일SHA불변이다. `extracted/dotnet-0706/smoke/thewarbegins/dn/`, `smoke-summary.json`, `smoke.log`에 보존했다. 원본게임 실행이나 공격/포획/희생/승리 재현은 수행하지 않았다. `cpp_sync.py` 종료0이며 fixture357개를 유지했다.

이 단위는 준비 대여/현재 제품 owner/배송pin의 기반이다. C++ 일반 Acquire의 전체 커서/선택 초기화와 WithdrawForState의 자식반납 증빙은 해당 부모 이식에서 잇는다. 기존 Core World/PostPop/건설의 개별 pin 전달도 남았다. 특히 기존 Func<object?> 입구는 GC.KeepAlive만 수행하므로 IDisposable pin을 그대로 연결하면 호출수를 반납하지 못한다. 해당 소비자의 Dispose 경계까지 같이 고쳐야 한다. 고정App15수신기·장기Player/옵션/Core의 실제 필드·전체로그인/제품게임시계 설치는 후속이며 완료로 확대하지 않는다. 다음0.707은 이 고정F의 선행부모와 연결이고, 정기전체회귀는0.708이다. 전체목표와M1은 진행 중이다.
