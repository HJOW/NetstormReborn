# dotnetpj 0.911 — RU-3 원문 NSInfo 입력 라우팅 이식

2026-11-24, HJOW-Athlon. RU-3 여섯 번째 묶음이다. NSInfo 루트의 원문 입력을 같은 정렬표/CS와 현재 메뉴·카메라·송신 장치에 연결하는 라우팅을 이식했다. 제품 기존 경로는 바꾸지 않는다.

## 변경과 원문 대응

- `NativeNsInfoInput.Handle`은 `cpppj/src/client/NativeNsInfoInput.cpp`의 `HandleNativeNsInfo(0047c8c0)`를 이식했다. 같은 실제 CS/정렬표/메뉴/카메라/송신 장치를 빌리며 미연결 장치는 일반 성공으로 꾸미지 않고 명시 실패로 둔다. 네 공장 설치·바깥 UI·NativeRoot/HUD 창 생성·Enter·HUD 작성자·메타 배치 입력/특수 그림·Root reply 저장은 후속 단위에서 잇는다.
- 비교만 26비트로 마스킹하고 기본 처리에는 수정하지 않은 event/first/second를 전달한다. 원문 모드/known 관문을 추가하지 않으며 실패한 행은 원래 입력으로 기본 처리를 계속한다.
- 정렬 메뉴행(`0x542790`)은 둘째가 양수일 때 정렬표→참가자 기록의 원문 test BYTE 한 개만 보고 활성일 때 현재 마우스 좌표로 메뉴 공장을 호출하고 1을 반환한다.
- 중심행(`0x54278c`)은 활성일 때 참가자 `0xb8` SID를 실제 카메라에 전달하고 1을 반환한다.
- 직접 추방행(`0x5429dc`)은 둘째를 정렬표 없이 참가자 번호로 직접 보고 활성일 때 기록 4번과 8을 패킷에 쓰고 추방음을 재생한 뒤 1을 반환한다. 송신 헤더 조립(`1fh/12BYTE` 뒤 `11` 전송)은 호출 측 `Status` 장치가 소유한다.
- CS DWORD/flag BYTE/패킷 DWORD 밖 접근은 원문 폭 경계에서 명시 거부한다. 합성 CS 기록 검증이라 신규 fixture는 없다.

## 검증

- Release 클라이언트 빌드는 오류 0이다. 신규 경고 0이다.
- 신규 7건은 통과/실패 0이다. 활성 메뉴 열기, 비활성 기본 전달, 활성 중심 SID, 직접 추방 패킷·음향, 둘째 0 이하 기본 전달, 26비트 마스킹, 미연결·짧은 기록·null 명시 실패가 이웃 36건(`HudNsInfoMeta` 묶음·`HudNsInfoCreate`·`HostNsInfoWindows`)과 함께 43건 통과한다.
- 같은 최종 빌드에서 대표 3경로(`thewarbegins`·`tutorial1`·`surrounded`)는 모두 L2 미일치(예상)이며 전체 덤프/지표가 0.908과 같다(`thewarbegins` cpp1941/dn1911/only30, `tutorial1` cpp843/dn838/only5, `surrounded` cpp6420/dn6408/only12). 원본 파일은 작업 전후 `git status`에 없고 전후 불변이다. 근거는 `extracted/dotnet-l2-0911-*/`의 각 실행 로그와 요약이다.
