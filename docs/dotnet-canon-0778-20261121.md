# 0.778 UI 수신 원문 대조와 부분 버퍼

제품을 바꾸기 전에 기존 ChatReceiveBody를 원문238관측과 대조했다. 전체256BYTE 패킷, 현재 구독자/모드, 진단·필터·소리·문맥·표시의 순서와 중단 상태가 모두 일치했다(baseline.trx 1건 통과). 기존 수신 본체의 동작 수정은 필요하지 않았다.

기존 byte[] 입구를 유지하고 같은 Span<byte> 부분 물리를 받는 입구를 추가했다. 배열 입구도 복사 없이 같은 본체를 호출한다. 현재 창0은 빈 버퍼와 미선택 장치를 읽지 않는다. 실제 효과가 빠진 경우 앞서 수행한 NUL 기록을 보존하며 오류를 드러낸다. 콜백이 발신자·본문 위치·글자색을 바꾸면 이후 사용 위치에서 현재 값을 다시 읽는다.

신규3건 포함 집중19건이 통과했다. 기존 원문238관측, 부분 버퍼 앞뒤 보존/동일 별칭/콜백 현재 읽기, 창0·선택 장치 실패의 실제 기록을 검증했다. Client41h와 중계 검사도 함께 통과했다. 원문 fixture는 복사하거나 고치지 않고 Client 프로젝트에 링크했으며 기존395항목/헤더 유지에 수신1개를 더해 총396개다. 수신 fixture는 일반 헤더1행과238관측으로 구성된다. PORT_MAP의 수신2쌍은 이미 같은 최신 cpp 근거를 가리켜 추가 변경이 없다.

대표3시작 모두 종료0·덤프 전체바이트/지표0.776 일치·원본1392파일 불변이다. cpp_sync와 최종 감사가 통과했다. CPP/디컴파일 변경·외부 접속은 없고 실제 포획/희생·특정 적 공격·시나리오 승리는 재현하지 않았다.

근거는 extracted/dotnet-0778/의 baseline.log·baseline.trx·test.log·client.trx·register.log·source-revisions.json·fixture-audit.json·cpp-sync.log·capture.py·capture.log·capture-summary.json·capture-originals-audit.json·capture/*/dn/*·audit.py·audit.log·final-audit.json이다.
