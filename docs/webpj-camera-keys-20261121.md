# TAB·U·숫자 저장 키(화면 위치 키) 연결 (WB04-E1154)

원본 도움말(`interfaceHelp`)의 키 목록을 웹에서 하나씩 짚다가, 다음 세 키의 분배기가 모듈과 Node 시험만 있고 앱 입력 루프에 연결돼 있지 않아 **아무 일도 하지 않음**을 확인해 연결했다.

| 키 | 원본 동작(도움말) | 웹 모듈 |
| --- | --- | --- |
| Shift+숫자(0~9) | 현재 화면 위치를 기억(10칸) | `core/saved-camera-key.js` |
| 숫자(0~9) | 기억한 화면 위치로 이동 | 같은 모듈 |
| TAB | 최근에 놓은 유닛 다섯 곳을 차례로 이동 | `core/construction-history-key.js` |
| U | 가장 최근에 잃은 유닛 위치로 이동 | 같은 모듈(`dispatchLostPositionKey`) |

## 원인과 수정

- 앱 입력 루프(`netstorm.js`)가 이 키 코드를 지원 목록에 두지 않아, 키가 큐에 들어가도 미구현 사건으로 막혔다(E1150 안전장치로 3초 뒤 버려질 뿐 아무 동작도 없음). 또 브라우저 keydown 이 TAB·숫자 줄·`u` 를 큐에 넣지 않았다.
- **최초 초기화 누락**: 원본은 클라이언트가 처음 만들어질 때 저장 10칸과 최근 건설 위치 5칸을 무효 좌표(−10000, −10000)로 쓴다(`ClientMain.cpp` 553~554행, 원문 00439928·0043994c). 웹에서는 이 초기화가 없어 값이 모두 `(0, 0)` 이었고, 연결만 하면 저장하지 않은 숫자 키가 월드 왼쪽 위 끝으로 이동했을 것이다. 초기화를 Client 전역 생성 시점으로 옮겼다(미션·Renderer 교체에서는 다시 쓰지 않는다).

수정 내용(`www/netstorm.js`):

- `_dispatchCampaignCameraKey(event)`: 원본 `UberGump.cpp` 1740~1757행 순서(TAB → U → 숫자/Shift 기호)로 세 분배기를 부른다. 이동은 미니맵 클릭과 같은 중심 요청(`world.centerCamera`)이고, 저장은 선택음(`select.wav`) 뒤의 현재 지도 영역 중심(칸 좌표)이다.
- 입력 루프: TAB(9)·U(0x55/0x75)·숫자와 영어 Shift 기호 표 `)!@#$%^&*(` 를 카메라 키로 분류하고, 대화창이 열려 있으면 처리하지 않는다.
- keydown: 숫자 줄은 키보드 배열과 무관하게 `Digit0~9` 코드로 원본 문자 코드(Shift 면 영어 기호 표)를 만든다. TAB 은 브라우저 포커스 이동을 막고, `u` 를 문자 키 허용 목록에 더했다.

## 원본과 같은 점(오류로 오인하기 쉬운 것)

- 숫자 키 이동은 **지도 영역이 아니라 화면 전체 크기**를 기준으로 중심을 잡는다(`CenterViewPoint` → 화면 폭·높이). 반면 Shift+숫자는 HUD 를 뺀 지도 영역의 중심을 저장한다. 그래서 저장 직후 숫자 키를 눌러도 화면이 HUD 폭의 절반(약 2.6칸)만큼 옮겨진다. 시험은 저장 값과 이동 뒤 화면 전체 중심을 비교한다.
- 월드 가장자리 한계(카메라 이동 한계) 때문에 가장자리 근처에서 저장한 위치는 정확히 화면 중심이 되지 못할 수 있다.
- 이력은 전투 유닛(궁수·대포·방벽·비행장·포대·울타리·보행자·기구)을 놓을 때만 쌓이고 제단·워크샾·신전·다리는 쌓이지 않는다(원본 그룹 10 제외). 실제로 제단을 놓아도 이력은 비어 있다.

## 시험

- `e2e/mission-camera-keys.spec.js`(`NETSTORM_E2E_ASPECT` 로 화면비 선택, 4:3·16:9 통과) 2건.
  - Shift+1 저장(값이 저장 직전 지도 중심과 같음) → Alt 스크롤로 멀리 이동 → `1` 로 복귀, 저장하지 않은 `2` 는 이동 없음, `Shift+0`·`0`(10번째 칸).
  - 이력 두 칸을 채운 뒤 TAB 이 첫째 → 둘째 → 다음 칸이 무효라 순번 0 으로 돌아와 첫째로 순환, `U` 가 손실 좌표로 이동하고 무효(0)이면 이동하지 않음.
  - 변형 확인: 최초 초기화를 빼면 첫 시험이 `처음에는 무효 칸(-10000)` 에서, TAB 분배를 빼면 두 번째 시험이 `TAB 1` 에서 실패한다.
- 한계: 이력을 쌓는 실제 유닛 배치는 생산이 필요해 시험은 이력 칸을 직접 채운다(통지 본문은 Node 시험이 다룬다). 손실 위치도 파괴 경로가 쓰는 전역 값을 직접 쓴다.
- Node 41건(`command-inputs`·`popup`·`progress`)과 인접 e2e 6건(카메라 Alt·회전 키·T 키·Pause·monkey·유닛 메뉴)이 통과한다.

## 남은 것 (원본 도움말 키 목록 중 아직 확인하지 않은 키)

- F1(미션 중 일반 도움말)·F2(건물 숨김)·F3(채팅 창 숨김/표시)·F8(목표 보기)·Shift-F3(섬 테마 숨김)·Ctrl-F5/N(운반체 순환)·D(생산 창에서 마지막으로 고른 유닛 쥐기)는 실제 미션에서 키별로 확인한다.
