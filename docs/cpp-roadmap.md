## 목표와 기준

**AGENTS.md의 cpppj 목표(2026-10-05 변경):** "cpppj - C++ , 기존 게임을 디컴파일하여 C++ 코드로 최대한 복원하는 것이 1차 목표이다. 이후 윈도우10, 11에서 실행 가능한 수준으로 만들고, 요구사항 반영 및 MCP 추가한다. 윈도우용만 개발한다." / "dotnetpj - C# + MonoGame 기반으로 개발. cpppj 완성 후 이를 분석하여 개발."

최신 사용자 요청은 복원의 완료 기준을 **기존 게임의 실제 플레이**로 구체화한다. 빌드·자료 읽기·검사 창만으로 완료하지 않는다. 메뉴→캠페인→브리핑→실제 조작·경제·전투→승패·결과·메뉴 복귀를 먼저 연결하고, 나머지 원본 기능까지 복원한다. 원본 코드의 구조와 규칙을 유지하며 실제 실행에 필요한 Windows 10/11 호환성도 검사한다. dotnetpj는 cpppj가 완성된 뒤 그것을 분석해 개발한다.

cpppj는 원본 게임을 분석·디컴파일하여 **Windows 10/11에서 실행 가능한 C++ 게임**으로 복원한다. 게임 규칙·화면·사운드·애니메이션은 패치판 10.78을 기준으로 삼고, CD판 10.72는 함수 해석·자료형·판본 차이를 확인하는 비교 자료로 사용한다. CD판의 동작이나 팬게임의 커스텀 요소를 패치판 규칙에 섞지 않는다.

**원칙(2026-10-05 사용자 결정): cpppj는 기존 게임 원본을 되살리는 것이 목적이다. 기능 변경을 최소로 하고 원본과 같은 방식으로 만든다. 이후 MCP를 붙여 원본 게임 분석에 쓴다.** 그래서 플랫폼은 원본처럼 Win32 API를 직접 부르고(외부 라이브러리 없음), 초기화 순서·화면·입력의 경로를 원본 구조대로 옮긴다. cpppj는 **Windows 전용**이며(빌드가 다른 OS를 거부한다) Linux 지원은 dotnetpj의 후순위 목표다. 한국어 지원은 cpppj에서는 후순위다.

원본 수준의 동작과 요소별 애니메이션 속도·영어 UI·4:3 화면을 먼저 맞춘다. 원본 전체화면과 가장자리 스크롤·정상 재실행도 원본 기능/안정성 복원 범위다. **한국어·16:9·16:10 확장·60/120프레임·MCP·새 기능은 실제 플레이 복원 뒤**에 둔다. 멀티플레이는 후순위다.

완료 결과는 MCP 프로토콜 검사, 캠페인 자동 시나리오, 사용자 실행 안내다. `analyzeManager`는 원본 분석 도구이며, cpppj의 게임 제어 인터페이스와 연결 방식은 별도로 정의한다.

## 디컴파일 신뢰도를 높이는 작업 방식

1. 구현할 동작과 원본 함수 범위를 먼저 좁힌다. [모듈 맵](exe/modules.md)과 `decomp_refine.py --show <주소>`로 패치/CD 대응을 확인한다.
2. 호출 규약·인자·반환·구조체 필드·전역·부호를 역어셈블과 함께 확인한다. 주소가 비슷하거나 자동 매칭 점수가 높다는 이유만으로 같은 의미라고 판단하지 않는다. 판본별 오프셋·크기·기능 차이를 보존한다.
3. 순수 함수는 원본 x86 제한 실행과 C++의 반환·출력 메모리를 대조한다. 외부 호출 대체가 필요한 경우 대체한 범위를 기록하고 그 호출의 실제 동작까지 검증했다고 주장하지 않는다.
4. 파일 형식은 두 판본의 실제 자료와 독립 판독기로 대조한다. 런타임은 입력·게임 시각·난수·상태 기록을 고정하여 차이를 좁힌다. 영상·스크린샷은 화면·타이밍 근거로 보완한다.
5. 함수 주소·근거·검증 범위·미확정 항목을 코드 주석과 복원 문서에 남긴다. 검증 기대값·생성 도구·판본 해시를 함께 갱신한다. 새 코드의 상수·함수·반복문에는 한국어 설명 주석을 달고 UTF-8을 사용한다.

자세한 절차는 [C++ 복원 규칙](cpp-build.md)과 [디컴파일 신뢰도](exe/decompile-reliability.md)를 따른다. 완성도는 파일 수나 함수 수보다 실제 동작과 완료 기준으로 판단한다.

## 검사와 원본 실행 규칙

기본 빌드·회귀 검사는 다음과 같다. 파일 계층을 바꾸면 `cpp_recovery_smoke.py`, 타입·그래픽·자산 경로를 바꾸면 `cpp_assets_smoke.py`, 설정 계층을 바꾸면 `cpp_config_smoke.py`, 타입 표·요새·미션 읽기를 바꾸면 `cpp_fort_smoke.py`, 영역 배치·창·화면 장치를 바꾸면 `cpp_window_smoke.py`(cpppj 창이 잠깐 뜬다. 원본 게임은 실행하지 않는다)로 실제 자료 비교를 추가한다. 설정 조회·치환 코드를 바꾸면 `decomp_config_oracle.py`의 기대값도 함께 본다. 문서만 수정할 때는 링크·UTF-8·차이를 검사한다.

```powershell
cmake -S cpppj -B cpppj/build -DCMAKE_BUILD_TYPE=Release
cmake --build cpppj/build --config Release
ctest --test-dir cpppj/build --build-config Release --output-on-failure
python tools/cpp_recovery_smoke.py
python tools/cpp_assets_smoke.py
python tools/cpp_config_smoke.py
python tools/cpp_fort_smoke.py
python tools/cpp_window_smoke.py
python tools/cpp_renderer_smoke.py
```

AGENTS.md와 `originals/`·`originalCD/`의 기존 파일은 수정·삭제하지 않는다. **AGENTS.md의 허용 예외와 사용자 결정에 따라 `options.cfg`·`fullScreenStateFile.dat`는 원본과 같은 경로에서 처리한다.** 검사 도구는 두 파일을 보관하고 검사 후 복구한다. 보고서·추출물은 `extracted/`에 둔다. 원본 실행을 수반하지 않는 빌드·정적 분석·단위 테스트·제한된 x86 함수 검증·MCP 프로토콜 검사는 계속 진행할 수 있다.

원본 또는 복사본 게임을 실제 실행하는 분석 단계는 [AGENTS.md](../AGENTS.md)의 확인 규칙을 따른다. 해당 단계의 목적·필요성을 설명하고 명시적 확인을 받아야 하며, 일반적인 개발 지시나 이전 실행 이력으로 새 실행을 허용받았다고 간주하지 않는다. AGENTS.md가 정한 호스트/IP 예외와 사용자가 직접 요청한 원본 수동 제어·플레이 녹화 분석 예외는 그대로 적용한다. cpppj 자체의 창·게임 실행 검증은 원본 실행과 구분한다.
