# 0.743 첫 메뉴 전 장기 자산 표 준비

CPP ClientMain.cpp의 MakeRawSurfaceStorage 위치처럼 실제 TYPE·프레임·SHP 표를 첫 메뉴보다 먼저 준비했다. HostAssetTables가 최초 TYPE와 정의·SHP 바이트를 Client 수명에 보관하고, 기존 RawSurfaceStorage의 같은 물리에 생성자 초기화를 한 번 실행한다. 최초 자산 Source와 수정 가능한 현재 TYPE를 구분한다. 실제 프레임 코드 사본과 Pool 부모 꼬리의 삭제 기록/실패 좌표도 기존 전체 생성자와 같은 순서로 준비한다. 별도 풀이나 Player/Runtime은 만들지 않는다.

RawFrameTableStorage는 최초 구성 뒤 같은 프레임 배열을 공개한다. 실제 HostSession은 이 배열을 빌리며 프레임 표를 다시 채울 수 없다. 연속 미션도 같은 배열을 사용한다. 독립 조합 검사의 FillWorldFrames는 WorldFrameTables의 같은 순수 작성기를 사용한다. 프레임 벡터 확장은 초기 구성에만 허용하는 기존 TYPE 물리 표와 같은 대여 계약이다.

제품 미션 진입에서는 TYPE·정의·SHP를 다시 읽거나 저장소 표를 다시 설치하지 않는다. Fort 판독은 같은 최초 TYPE를 받고, 지형/공장/연소 장치는 준비된 현재 표를 빌린다. 이전 InstallMissionStorageTables는 독립 기존 검사에 유지했지만 제품에서는 호출하지 않는다. 첫 메뉴 장기 표 준비로 전체 Native State/UI/음향 기본 장치 설치가 완료된 것은 아니다.
