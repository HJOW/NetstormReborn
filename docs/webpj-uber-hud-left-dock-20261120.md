# 좌측 HUD 틀과 지도 영역 도킹 (WB04-E1082)

실제 Tutorial1 화면을 원본 10.78 스크린샷(`screenShots/Bridge the Gap - Started.png`)과 비교하면 좌측 사이드바의 원점·폭(0,0·80)과 월드 원점은 이미 같았다(월드 오프셋 0,0). 어긋난 것은 사이드바를 둘러싼 틀이었다. 임시 지도 영역 `{0,28,W,H}` 때문에 화면 위쪽 28줄이 검은 띠였고, 세로 구분선(x80·폭5)·미니맵 구분선(y=H−80)·하단 80픽셀의 미니맵 칸이 없었으며, 생산 패널은 Uber 루트 없이 Gump 루트에 직접 붙어 있었다.

## 구현

cpppj `UberHud.inc`의 `InstallHud` 순서를 앱의 미션 시작에 연결했다. 새 [ClientUberHud](../webpj/www/ui/client-uber-hud.js)가 원본 `UberRootGump.Replace`로 Uber 루트를 만들고(구분선 세 개 → 미니맵 → 생산 패널), 기존 직계 자식을 옮긴 뒤 HUD 모드 3으로 세로 구분선을 x80에, 미니맵 구분선을 아래 80에 둔다. 생산 패널(폭 80·높이 H−80)과 미니맵(80×75, y=H−75)의 크기는 원본 슬레이브 등록(1·2·8 관계)이 정한다. 채팅 창은 원본 미션 화면처럼 숨겨 채팅 구분선을 화면 끝으로 내리므로 지도 영역은 `{85,0,W,H}`가 된다. 이 영역은 Gump 트리의 같은 객체(`ClientGumpRoot.mapView()`)에 쓰이고 World·Renderer·Gump 재그리기가 같은 객체를 읽는다.

- [ClientMinimap](../webpj/www/ui/client-minimap.js): 이식해 둔 `RawMinimapControls`를 실제 Gump 루트에 연결한다(파생 노드 등록·출력·idle·월드 Pop/Unpop dirty 대여·카메라 중심·이동 입력). 미니맵 노드를 파생 클래스로 바꾸고 `tree.token(node)`로 같은 주소를 등록한다.
- 생산 패널을 원본 `Construct`/`Open` 순서로 분리했다(`construct()`·`handleHudMode()`·`finishInstall()`·`open()`). Uber 루트가 `construct()` 결과를 직계 자식으로 붙이고, 도킹 뒤 `finishInstall()`이 두 격자를 현재 기술에 연결해 다시 부착한다.
- `UberRootGump`는 지식(NSInfo)·채팅 창 공장이 없으면 해당 자식 생성만 건너뛰고(필드 0), `HudDock`의 HUD 모드 1/3/4는 지식 토큰 0의 플래그 쓰기만 건너뛴다. 나머지 순서·값은 그대로다.
- 화면 크기 변경은 `ClientUberHud.reflow()`가 원본 `Reflow` 순서(세로 → 미니맵 → 채팅 구분선 이동)로 처리한다. 구분선을 하나씩 옮기는 사이 미니맵 높이가 잠깐 커져 crop이 음수가 되므로(1920×1080에서 발견) 마지막에 한 번 갱신해 같은 호출의 그리기 전에 crop을 다시 계산한다.
- `CampaignGameWorld.centerCamera(x, y)`를 추가해 미니맵 누름·드래그가 세션의 카메라 중심 요청(`requestCameraCenter`)으로 이어지게 했다.
- 월드 해제 때 HUD 자식을 모두 지우고 미니맵의 월드 대여를 끊은 뒤 Session을 반납한다(해제 뒤 Gump 15개 → 빈 Uber 루트 1개).

## 검증

- **원본 화면 대조.** 4:3 1024×768 Tutorial1 시작 화면을 원본 스크린샷(게임 영역 오프셋 4,32)과 비교했다. 월드 위치 오프셋은 0,0이고, 하단의 미니맵 구분선·세로 구분선 아랫부분·미니맵 칸(섬 그림과 흰 카메라 테두리 포함) 85×82픽셀 6,970개가 모두 일치한다. 이 비교는 새 Chromium 검사 `e2e/uber-hud-layout.spec.js`가 매번 수행한다. 상단 SP 칸과 돌 질감은 같은 위치이지만 스크린샷의 색 양자화 때문에 평균 차이가 약 4라서 픽셀 일치로 세지 않았다. 생산 격자의 다리 조각 모양은 무작위 공급이라 비교하지 않았다.
- **화면비.** 같은 검사가 미션 중 창 크기를 1366×768(16:9)·1280×800(16:10, 논리 1228×768)·1920×1080·1024×768로 바꾸며 지도 영역 `{85,0,W,H}`와 세로 구분선·미니맵 구분선·미니맵·생산 패널 위치가 매번 도킹 규칙과 같은지, 페이지 오류가 없는지 확인한다.
- **Node.** 새 `tests/client-uber-hud.test.mjs` 4건(설치 도킹·재배치·정리 후 재설치·장치 누락)과 `UberRoot`·`HudDock`·미니맵·Gump 루트·구분선·`campaign-request-frame` 등 관련 15개 파일 84건이 Node 22.23.3·26.13.0에서 모두 통과했다. 변형 확인으로 HUD 모드 3 생략·채팅 숨김 생략·재배치 높이 오류·정리 생략 4종이 모두 시험 실패로 잡힌다.
- **Chromium.** 새 검사 2건과 Tutorial1~6·세 캠페인 묶음 진입(`tutorial-menu-start` 전체), 한국어 Tutorial1·2 전체 흐름(신전·워크샾 자연 완공과 생산), 생산 항목 우클릭 정보, 와이드 레이아웃, 게임 시계, smoke, Reset All이 통과했다.
- **교정한 기존 검사.** 예전 임시 지도 영역 `{0,28,…}`를 기대하던 `campaign-request-frame` 한 줄을 도킹된 `{85,0,…}`로 바꿨다. E1081이 상단 28줄을 검은 바탕으로 검사하던 한국어 Tutorial2 확인은, 같은 영역이 지도가 되었으므로 전체 다시 그리기 전후의 영역 해시가 같은지(비용 글자 잔상이 없는지)로 바꿨다.

## 남은 경계

지식(NSInfo) 패널과 채팅 창 공장은 앱에 연결되지 않아 자식 필드가 0이고 채팅 숨김은 구분선 이동만 수행한다. 미니맵 클릭·드래그의 실제 Chromium 입력과 원본 fixture 전체 대조, 여러 번 미션을 시작하는 World 교체, ESC 게임 메뉴 상단 바, 원본 Gump serial, 오라클 L2 대조는 남아 있다.
