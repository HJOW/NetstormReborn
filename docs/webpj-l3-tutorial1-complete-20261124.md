# webpj L3: Tutorial1 시작부터 미션 완료 창까지 cpp 와 같음 (WB04-E1304, 2026-11-24)

[L3](webpj-l3-tutorial1-20261123.md) Tutorial1 단계표를 2000프레임에서 4200프레임으로 늘려 **사제가 수확을 이어 가 SP 600 에 이르러 'Mission Accomplished!' 완료 창이 열릴 때까지**(단계 F→G) 이어 보았다. **결과: 웹을 고칠 차이는 없었다.** 이로써 Tutorial1 은 시작(메뉴 1프레임 → 미션 시작)부터 완료 창까지 4200프레임 동안의 입력 진행을 cpppj 와 대조했고 체크포인트 20곳의 화면이 모두 0픽셀, 덤프 16개가 환경 의존 행(`sp`·`player:*`) 밖에서 같다.

## 입력(1024×768, Tutorial1, 2000프레임 뒤)

| 프레임 | 동작 | 인자 | 결과 |
| --- | --- | --- | --- |
| 2020 | click-if | `OK` | 단계 F 'The Temple' 안내 창을 닫아 게임이 재개된다(안내문: 600 SP 가 될 때까지 사제가 수확을 이어 가고 그동안 다른 간헐천에 다리를 놓는 연습을 하라) |
| 2600·3200·3800 | snapshot·session-dump | `c2600`·`c3200`·`c3800` | 수확이 이어지며 SP 가 오르고 다리 붕괴 스캔이 진행되는 중간 상태 |
| 4200 | snapshot·session-dump | `c4200` | SP 600(생산 창 위 숫자)에 이르러 단계가 71(`G`)이 되고 'Mission Accomplished!'(Leave Tutorials·Next Tutorial) 창이 열려 정지 |

단계 값은 cpp `report` 의 `mission_gate` 두 번째 값이다: `D`=68·`E`=69·`F`=70·`G`=71(완료). 단계 F 가 3600~4200프레임 사이에 G 로 넘어간다. 입력은 안내 창 닫기 하나뿐이고 사제는 간헐천과 신전을 알아서 왕복한다.

## 이번 비교가 덮는 것

- 사제의 왕복 경로(다리 위 이동), 크리스털 줍기·신전 배달, SP 갱신(0→200→…→600)과 생산 창 숫자 표시.
- 매달린 다리의 붕괴(E1301 에서 고친 다리 붕괴 스캔이 2000프레임 넘게 도는 동안의 수명 감소·금 간 프레임·제거): 4200프레임 화면에서 처음 놓은 조각들 일부가 사라진 것도 cpp 와 같다.
- 단계 판정(`mission_gate`)·안내 창 열림/정지·승패 판정 소비: 완료 창이 cpp 와 같은 프레임에 열린다.

덤프 `c200`·`c300`·`c400`·`c540`·`c680`·`c760`·`c880`·`c1000`·`c1200`·`c1400`·`c1700`·`c2000`·`c2600`·`c3200`·`c3800`·`c4200`, 화면은 여기에 `p345`·`d364`·`e470`·`p1070` 이 더해진다. 새 오라클(`c2600`·`c3200`·`c3800`·`c4200` 의 `.tsv`·`.png`)과 갱신된 `steps.json`·`oracle.json` 을 fixture manifest 에 올렸다(891개). 웹 시험(`e2e/l3-tutorial1.spec.js`)은 약 4분이 걸린다. 이 단위에서 웹 코드는 바꾸지 않았다.
