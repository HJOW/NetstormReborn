# 생산 창(덱) — 원본 동작과 클론 구현

작성일: 2026-10-02. 작업 환경: Linux `vm-debian-codex`. 원본 게임은 실행하지 않았다.

화면 왼쪽 세로 패널은 원판 매뉴얼의 **Production window**이며, 사용자와 이 문서에서는 **덱**이라고 부른다.
이번 작업에서는 클론의 사이드바를 원본 구성과 동작에 맞게 다시 만들었다. 덱 등록 규칙 자체(워크샵 원소, 칸 수, 파괴 시 해제)는 [workshop-deck.md](../gameplay/workshop-deck.md)를 따른다.

## 원본 구성 (1024×768)

위에서부터 다음 순서다. 별도 명령 버튼은 없다.

| 영역 | 위치·크기 | 근거 |
| --- | --- | --- |
| Storm Power 숫자 | y 0~22. `fortGump` `A04` 위에 숫자와 `A03` 결정 그림 | `FUN_0043da10`: 1000 이하 빨강, 2000 이하 노랑, 그 위 흰색 |
| 생산 창 바탕 | `fortGump` `A02`(80×774, 위 26px은 검은 SP 칸)를 (0,0)에 둔다 | 셰이프 추출 |
| 다리 칸 | y 26부터 2열, 행 높이 36, 열 폭 40. 칸 수 = Bridge Slots(2·4·6) | `FUN_0043e640`: 위치 26(0x41d00000), 높이 = 칸 수 × 18, `FUN_0043d790(2, 칸 수/2, 0x40)`, 고정 격자 |
| 다리 조각 그림 | 배율 0.63, 칸 가운데 | 다리 패널 +0xc0 = 0x3f2147ae |
| 유닛 칸 | 다리 칸 바로 아래부터 미니맵 위까지. 1열, 행 수 = max(6, 마지막 칸 번호 + 1) | `FUN_0043d790(1, 6, 8)`, 배치 `FUN_0043e1e0`. 녹화의 칸 중심 약 182·275·370·465(간격 약 94) |
| 유닛 그림 | 원래 크기로 칸 가운데. 칸보다 크면(여백 2) 줄인다 | `FUN_0043ce40` |
| 미니맵 | 맨 아래 약 76px | 기존 클론 유지 |

유닛 칸 순서는 **골렘 → 워크샵에 등록한 순서**다. 1-1에서는 골렘, Rain Generator, Sun Cannon, Whirlibase 순서로 고정 위치에 나타났다.
템플이 없으면 골렘이 없다. 워크샵에 등록하기 전에는 골렘만 보인다(네 번째 녹화 01:24.6에 Rain Generator가 처음 추가됨).

## 항목 상태 표시

`FUN_0043ce40`은 항목마다 그리기 모드를 고른다. 모드에 따라 팔레트 변환표(`FUN_0043c010`이 만든다)를 쓴다.

| 모드 | 조건 | 변환표 | 녹화 확인 |
| --- | --- | --- | --- |
| 1 어둡게 | 항목 플래그 0x100. 배치한 유닛의 재충전 중(`Cursor.cpp` `004468b0`), 집고 있는 다리 조각 | `DAT_00556438`: RGB × 0.6에 L1 거리가 가장 가까운 팔레트 색 | 첫 녹화 03:30 Rain Generator, 03:42 Sun Cannon. 네 번째 녹화 01:11~01:20 집은 다리 조각 |
| 2 빨갛게 | 유닛 플래그(0x418)이고 비용 > 현재 SP(`FUN_004af010`) | `DAT_00556038`: R만 × 2.1(최대 1)에 유클리드 거리가 가장 가까운 팔레트 색 | 첫 녹화 03:32~03:36·03:44~03:50 SP 350에서 400 SP 유닛 전부, `Playing 9` SP 200 |
| 0 보통 | 그 밖 | 없음 | |

모드 1을 먼저 검사하므로 재충전 중인 유닛은 SP가 부족해도 어둡게 보인다(03:30: 방금 놓은 Rain Generator만 어둡고 나머지는 빨갛다).
SP 숫자는 바뀔 때 천천히 따라가므로(네 번째 녹화 01:03: 2200 → 2100 → 1830 → 1813 → 1800) 화면 숫자와 빨간 표시가 잠시 어긋날 수 있다.

## 입력

| 입력 | 원본 동작 | 근거 |
| --- | --- | --- |
| 유닛 칸 좌클릭 | 배치 커서로 집는다. 마지막으로 집은 타입을 기억한다(D 키) | `FUN_0043d4c0` 0x10000, `DAT_00557d6c`. 01:01.1 (41,186) 클릭 → 01:02.97 지도 배치, SP −400 |
| 유닛 칸 우클릭 | 정보 창: `<이름> Level I`, Owner, Alignment, Class, `Cost: N`, SP 부족 시 빨간 `Need more Storm Power to Build!`, About. `opengump.wav` | `FUN_0043d330`. 01:05.5 Golem 메뉴 |
| 다리 칸 좌클릭 | 조각을 집는다. 조각은 놓을 때까지 **제자리에 어둡게 남고** 칸 수를 차지한다 | 01:11.15 집음 → 01:13.97 놓기까지 같은 칸 어둡게. 01:15.04 집음 → 01:19.2 빈 칸 → 01:20.0 같은 칸에 새 조각 |
| 다리 칸 우클릭 | 들고 있는 조각이 있으면 회전, 없으면 Bridge 정보·About | `FUN_0043d4c0` 0x20000. 01:08.6 |
| Q W / A S / Z X, E | 다리 칸을 직접 집기, E는 집을 수 있는 마지막 칸 | 내장 도움말 |

다리 칸은 **자리가 고정**이다. 조각을 놓아 빈 칸은 다음 1초 채우기에서 같은 자리가 채워지고, 다른 조각은 움직이지 않는다.
생산 창의 조각 오브젝트는 집은 동안에도 컨테이너에 남아 개수를 차지한다(`FUN_0043ef10` 다리 개수 계산).

| 파일 | 내용 |
| --- | --- |

| `src/Netstorm.Core/Simulation/BattleSession*.cs` | 다리 놓기에서 칸 비우기, 검사합에 빈 칸·집은 칸 반영, `IsUnitRecharging` |

| `src/Netstorm.Game/FortMapViewer.PlayUi.cs` | 기존 14개 버튼 격자(워크샵·제단·골렘·생산 3칸·다리·강화·사제·정지·회수·지식·취소·기타) 삭제, `A02` 위치 (0,0) |

버튼으로 하던 기능은 원본 조작으로 대신한다.

| 기존 버튼 | 원본 조작 |
| --- | --- |
| 워크샵·제단 | 사제 우클릭 → Construct |
| 골렘·생산 3칸 | 생산 창 유닛 칸 클릭 |
| 다리 | 다리 칸 클릭, Q W A S Z X, E |
| 강화·회수 | 워크샵·오브젝트 우클릭 → Upgrade / Salvage |
| 내 사제 | P / R, F5 |
| 지식 | F6, 사제 우클릭 → View Netstorm Knowledge |
| 취소 | 배치 중 지도 우클릭, 다리는 Backspace 또는 다른 항목 선택 |

이전 클론은 생산 버튼을 누르면 등록하지 않은 유닛도 워크샵에 자동 등록했다. 원본에는 이런 동작이 없어 지웠다.
이제 유닛은 워크샵 우클릭 `Put Knowledge into Production`으로 등록해야 생산 창에 나타난다.
정지(Stop) 명령은 원본 메뉴에서 확인되지 않아 화면에서는 뺐다(코어 명령은 남아 있다).

## 검증

- Release 빌드 오류 0(기존 테스트 CA2014 경고 1). Assets 200, Core 246 통과. 신규 `ProductionTintRemapTests` 3개, 다리 칸 자리 고정 단언(`Tutorial1_PickAndPlaceBridgePiece`, `Tray_RefillsLikeOriginal`).
- Linux 클론 직접 실행: 1-1 시작 시 골렘만 → 등록 뒤 Rain Generator·Whirlibase가 고정 위치에 추가, 집은 다리 칸 어둡게, SP 200에서 골렘·Rain Generator 빨갛게, Golem 정보 창 문구를 확인했다(`extracted/screens/deck-20261002/`).
- 바뀐 좌표로 `tools/clone_ui_smoke.ps1`·`tools/clone_help_options_smoke.ps1`(Menu·Mission·Workshop) 명령을 Linux에서 실행해 모두 통과했다. Windows PowerShell 실행은 하지 않았다.

## 남은 차이·추정

- 유닛 칸 패널의 실제 높이는 exe의 좌표 단위(+0x38 배율)를 끝까지 풀지 못했다. 1024×768 녹화의 칸 간격(약 94px)에 맞춰 "미니맵 위 70px까지"로 정했다. 다른 해상도의 간격은 추정이다.
- 골렘 자리(0번)는 기술 표가 골렘을 허용하면 템플이 없어도 비워 둔다. 템플을 잃었을 때 원본 유닛 칸이 당겨지는지는 확인하지 못했다.
- 7개 이상 등록하면 행 수가 늘어 칸 간격이 줄어드는 것은 `FUN_0043e1e0` 계산을 따른 것이며 화면으로 확인하지 않았다.
- 새 항목 깜빡임(`FUN_0043d690`, 0.1초 간격 4번 전환)이 있으나 켜지는 조건을 찾지 못했다. 녹화 01:24.2~01:25.2의 10 FPS 표본에서는 깜빡임이 보이지 않아 구현하지 않았다.
- SP 숫자의 점진 변화, 정보 창의 빨간 경고 글자색, 다리 조각의 금 간 그림은 아직 반영하지 않았다.
