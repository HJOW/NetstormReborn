## 4. 확정된 화면 변환 (템플릿 매칭)

원본 `_shapes.shp` 의 각 타입 기본 프레임을 캡처와 픽셀 비교(밝기 평균 오차 2.5~8)해 스프라이트 기준점 위치를 찾았다.

1. **칸 크기 = 가로 16px × 세로 11px (정확값)**
   * 같은 타입끼리: rainBattery (182,96)→(472,149), (183,127)→(488,490), (193,106)→(648,259) — x 는 칸당 16.0, y 는 칸당 11.0
   * sunBlocker·sunFence 쌍도 35칸 차이가 정확히 385px (= 35 × 11)
   * "The War Begins!" 가이저 두 개도 8칸 차이가 (128, 88)px (= 8 × 16, 8 × 11) 로 재확인 → 이전 문서의 11.25 는 근사값이었다
2. **모든 타입이 같은 변환식을 따른다**: 이 캡처에서 `화면 x = 16·월드x − 2438`, `화면 y = 11·월드y − 907` (±4px)
   * 3×3 포대(발전기·돌탑·바리케이드·가이저), **8×6 신전**, 1×1 프리스트가 모두 이 식에 맞았다
   * 즉 **오브젝트의 칸 좌표를 변환한 화면 점에 스프라이트 기준점(프레임 좌표 (0,0))을 그린다.** 발자국 크기에 따른 위치 보정은 스프라이트 프레임의 xmin~xmax, ymin~ymax 안에 이미 들어 있다 (프레임 영역이 xmax = 0, ymax = 0 인 경우가 많은 이유)
   * 상수(−2438, −907)는 카메라(스크롤) 위치에 따라 달라진다
3. **영역 청크 배치 확인**: `Terr07` 청크 4개를 월드 청크 (10,6), (11,6), (10,7), (11,7) (y 바깥·x 안쪽 순서) 로 두면 신전·프리스트·작업장 위치가 맞는다
   → `TerrNN` 은 **월드 청크를 y 바깥, x 안쪽 순서로 훑으면서 그 영역에 속한 청크만** 저장한다 (저장 코드 `FUN_004be230` 의 이중 루프와 일치)
4. 미니맵: 1px = 2칸 (이전 캡처와 동일)
