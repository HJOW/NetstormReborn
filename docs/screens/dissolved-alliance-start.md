## 2. 시작 카메라 (원본 캡처 3장 공통)

템플릿 매칭으로 캡처별 `화면 = (16·x + Cx, 11·y + Cy)` 를 구하고 플레이어 1 사제 칸을 넣었다.

| 미션 | Cx, Cy | 사제 칸 | 사제 기준점의 클라이언트 위치 |
|---|---|---|---|
| The War Begins! | −979, −795 | (94,108) | (525, 393) |
| Save the Island! | −2438, −907 | (185,118) | (522, 391) |
| Dissolved Alliance! | 약 −1455, −969 | (124,124) | (529, 395) |

→ **원본은 미션 시작 시 플레이어 1 사제 칸 기준점이 1024×768 클라이언트의 약 (525, 393) 에 오도록 카메라를 둔다** (±4px, 측정 오차 포함).
화면 중심 (512, 384) 에서 (+13, +9). 사이드바(폭 약 82px) 를 빼고 맵 영역 중심에 맞추는 방식은 아니다.
정확한 계산식(사제 발자국 중심·반올림 등)은 exe(`Renderer.cpp`·`Screen.cpp`)에서 확인할 일이다.

맵 뷰어는 이 규칙으로 시작 카메라를 잡는다 (`FortMapViewer.OriginalStartOffset`). 1024×768 창의 뷰어 캡처와 원본 캡처의 남은 차이는
세 미션 모두 템플릿 3곳 기준 ±6px 이내다 (캡처별 창 테두리 측정 오차 수준).

## 3. 뷰어와 원본의 차이 (2026-09-28)

| 항목 | 결과 |
|---|---|
| 본섬·작은 섬 모양, 다리, 가이저, 건물 위치 | 일치 (나란히 놓은 비교 이미지 `extracted/screens/dissolvedalliance-compare.png`) |
| 테두리 색 | 가운데 섬(플레이어 1) 청록·파랑 계열로 비슷. 소유자 3(Duke of Rain) 은 뷰어 개발용 색상표에 없어 색 변환 없음 |
| **거주지(Residence) 외관** | 원본은 섬 원소별 그림(바람 = 흙집, 비 = 모래빛 돔 집). 뷰어는 기본 프레임(해 원소, 초록 바닥)을 그렸음 → **수정**: `randframe` 타입은 영역 원소의 lit 그림 중 하나를 좌표로 고정 선택 (`MapSpriteFrames.BodyFrame(FortMapObject, theme)`) |
| 신전 회오리, 가이저 증기 | 원본은 애니메이션 중. 뷰어는 정적 프레임 |
| 오른쪽 thunderCannon | 저장 프레임(27)은 같고, 원본에는 발사 중 폭발 효과가 겹쳐 보임 (정적 차이 아님) |
| 섬 가장자리 풀 장식, 배경 구름, 사이드바 | 뷰어 미구현 (기존 남은 일) |

### 거주지 그림 선택 (exe 확인 범위)

* `residence.type`: `typeflags residence randframe …`, 클러스터 25개 = 원소별 6개(lit/unlit 번갈아) × 4 + 도움말
  `residence.gif`(해, P01~06), `THRESIDENCE`(번개, A07~12), `WRESIDENCE`(바람, A13~18), `RARESIDENCE`(비, A19~24), `b_residence`(A00 help)
* `randframe` = 타입 플래그1 비트 0x100000 (로더 `Rifttype.cpp`). 놓을 때(`0040dda3`) 이 비트가 있으면 `0049aa90('P','P', -1, -1)` 로
  측면·변형 `P P` 후보 중 무작위 선택 → 해 원소 그림이다.
* 캡처에서는 섬 원소 그림이 보이므로, 원소에 맞춰 다시 고르는 경로가 따로 있을 것이다. 지면 타일은 `0046fxxx`·`004703b0` 계열에서
  원소 번호(0~3)를 `0049aa90` 의 마지막 인자(후보를 4등분한 구간)로 넘겨 고른다. 거주지도 같은 방식인지는 미확인이다.
