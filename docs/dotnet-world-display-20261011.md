# dotnetpj 월드 표시 목록·선택 통합

2026-10-11, Windows 10 / `HJOW-Athlon`. 기존 인계의 5-1 후속을 진행했다. 원본 실행·새 디컴파일·cpppj 수정은 없으며 마지막 디컴파일 호스트도 `HJOW-Athlon`이다.

## 변경

저장 객체 뒤에 새 객체·다리·비행체를 별도 패스로 그리던 방식을 공통 `WorldDisplayItem` 목록으로 바꿨다. 생성 순서 때문에 뒤에 있어야 할 새 시설이 앞의 저장 시설을 가리던 문제가 해결된다.

- 지면, 절벽, edgeFarm, 받침 하단/윗면, 저장 객체, 신규 객체, 실제 다리 상태, 취소 공사장, 낙하체, 비행체, 생산 운송, 방어막, 탄·착탄·번개를 함께 수집한다.
- 기존 x86 대조를 통과한 `DrawOrder.Sort`로 깊이 내림차순, 현재 y·x 오름차순을 적용한다. 동일 키는 수집 순서를 유지한다. 지면/다리/받침 윗면은 타입 깊이 0, 절벽/받침 하단은 20, 시설/사제는 -20이다. 비행체 그림자는 `zoFLYER_SHADOWS`, 낙하체는 `zoFALLING`을 사용한다.
- 저장 여부와 무관하게 이동형 유닛에는 `VisualCell`, 비행체에는 실제 비행 위치를 적용한다. 프레임·소유자 색·그림자·건설 마스크·생산 불투명도는 기존 선택기를 사용한다.
- 저장 다리도 현재 `BridgeCellState.Condition`으로 그리며 별도 저장 다리 패스와 중복하지 않는다.
- 실제 클릭·우클릭·커서 판정은 같은 표시 목록의 앞쪽부터 검사한다. 사제/수송체의 기존 그림 사각형과 4픽셀 여유를 유지한다. 고정 객체는 불투명 본체 화소와 기존 발자국을 사용한다. 공사장은 실제 드러난 높이만 본체 클릭에 사용한다.
- 숨김/제거/운송 대기 객체와 수송체 안의 사제는 선택 대상에서 제외한다. 비행체는 기존처럼 직접 선택 대상이 아니다. 체력·선택 표시도 건물 숨김을 따른다.
- 카메라·화면 중심·배율·건물 숨김이 바뀌면 입력 전에 같은 수집기로 목록을 갱신한다. 미니맵에서 먼 곳으로 갔다가 Home으로 복원한 직후 이전 화면 범위의 목록으로 사제를 놓치는 회귀를 해결했다.
- 커서가 들고 있는 다리, 배치 미리보기, 사정거리·체력·선택·희생 표시와 메뉴는 화면 오버레이로 유지한다. 자동 검사에만 `world-order` 세부값을 제공한다.

## 직접 검사

`python tools/clone_world_order_smoke.py`는 `extracted` 아래에 격리된 데이터와 한 섬의 검사 미션을 만든다. 원본·배포 데이터와 사용자 설정은 읽기만 한다.

앞의 Stone Tower(112,116)와 뒤의 Wind Tower(112,113)는 발자국이 겹치지 않지만 본체 그림이 겹친다. 원본 RLE와 기본 클러스터·hotFootRatio로 겹친 불투명 화소를 독립적으로 계산한다. 다음 세 경우 모두 앞 객체만 있는 별도 클론 화면과 **509개 화소가 일치**하고 실제 클릭도 Stone Tower를 선택해야 한다.

1. 저장 앞 객체 + 신규 뒤 객체.
2. 저장 뒤 객체 + 신규 앞 객체.
3. 앞 객체를 먼저 생성한 신규 객체 두 개.

4:3 화소 검사 외에 16:9·16:10의 동일한 논리 위치 선택 및 F2 숨김/복귀를 검사한다. 표시 목록 상태는 실제 그리기가 끝날 때까지 조건 대기한다. 이동 검사에서는 저장 사제가 새 골렘보다 뒤에서 시작해 남쪽으로 이동하면 `priest, sunwalker` 순서가 `sunwalker, priest`로 바뀌고 도착한 본체도 선택되어야 한다.

TEST01의 신전 클릭은 오른쪽 Sun Workshop에 가린 발자국 대신 드러난 신전 본체로 옮겼다. 기존 사제 클릭 좌표·원본 선택 해제 규칙은 유지한다.

## 남은 범위

공통 목록 통합은 원본 전체 렌더러를 화소 단위로 복원한 결과와 구분한다. 완전히 동일한 키의 원본 qsort 순서는 미확정이며, 절차적 태양 탄·번개·스톰 파워는 기존 근사 그림이다. 이들의 타입 없는 깊이는 확인된 효과 계층을 적용한 클론 정책이다. 검은 알파 그림자, 원본 파티클 난수/팔레트, 전체 네이티브 월드 수집 순서는 후속 원본 대조가 필요하다.

다음은 인계의 9-1 의도적 차이 판정(A → C → B → D·E·F), 실제 캠페인 완주 → 진행 저장 → 재실행 → 다음 미션 해제의 전체 경로 검사, 실제 Graph/표면 identity 연결이다.
