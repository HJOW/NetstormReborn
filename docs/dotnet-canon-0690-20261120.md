# 0.690 실제 연결표와 등록·반납

- 일시/호스트: 2026-11-20, HJOW-Athlon.
- 상태: 연결표/등록/정리와 선택된 장치 수명 본체·집중 검증 완료. 실제 제품 양끝/Poll 설치와 전체 목표는 미완료다.

## 같은 표와 실제 장치

`cpppj/src/o/RawConnectionRegistry.cpp/.h`와 `RawTransportPolling.h`를 같은 `Netstorm.Net` 모듈로 이식했다. 실제22칸 송수신/별도 버퍼·32칸pending·BSS 개수·단조opaque token, 같은 노드의 등록/재배치/존재/주소/현재ID 조회, 실제 송신/준비/flush/수신/close/free를 연결했다. Player flag1 이전의 현재 슬롯 조회와 Native1e/b0/b3/b6/bb/fa 진단 뒤 재조회를 유지한다. 논리적으로 허용되는-32와 물리32칸의 상한도 구별한다.

동기화는 실제 외부 `ConnectionSyncState` 주소를 빌리고pending 개수는Registry가 소유한다. 값 복사나 외부 개수 공유를 넣지 않았다. 새 동기화 주소로 바꾼 뒤에도 기존 뷰는 이전 주소를 계속 빌린다. 같은 표의 원문 등록/정리는 기존 `ConnectionRegistration`/`ConnectionCleanup` 본체를 사용한다.

접속 초기 버퍼는0.689의 실제observer1/현재길이/순방향 복제로 생성한다. 기존 버퍼free/칸0 뒤 새 복제본을 공개하고, bootstrap1은 기존 수신기/버전/정책/observer를 덮지 않는다. 송신은 같은 소유 배열을 유지하고callback 뒤 현재 버퍼 칸을 다시free/0으로 만든다. 전체 양수 종료는 초기 버퍼/pending을 임의 정리하지 않으며 앱 최종 종료만 잔류 노드와 복제본을 반납한다. 진행 중 노드/부모의 강제 깊이 초기화는 없다.

## Source 대여와 예외

`ConnectionDeviceLifetime`/`ConnectionDevicePin`은 실제 전송Source 객체 전체와 최종 반납을 소유하는 결정적 대여다. 실제 제품Source 설치 시 이 소유권을 사용하고 getter는 선택된 실제Source 대여를 반환해야 한다. token이나빈명목 객체를Source로 대신하지 않는다. 현재 독립 장치 검사는 실제 사용하는 배열을Source가 반납하도록 구성했다. 제품Source 자체의 설치/왕복은 다음 단위다.

등록 노드와 동기 호출은 같은 제어 블록을 보유한다. 원문Binding 값 복사에 대응하는 선택 뷰는callback이자기Binding을반납해도등록당시Source를계속보유한다. 새coordinator와등록당시Source가다르면둘다최외곽Native부모의마지막칸/count쓰기까지보유하고,목록을먼저분리한뒤반납해최종소멸의재진입도구별한다.

기존 `DeferConnectionClose`의close/free 선행NULL검사를원문선택지점으로옮겼다. 깊이가비영이면실제장치를요구하지않고flags40만쓴다. 깊이0에서장치가누락되면이미쓴flags/sync와아직남은칸/버퍼를보존한다. 관리Source반납도예외를발생시키는경우원래부모예외와반납예외를함께AggregateException으로보존한다. 이는.NET장치반납/로그경계이며원본의새성공효과가아니다.
