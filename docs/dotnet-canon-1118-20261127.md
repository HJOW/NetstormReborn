# dotnetpj 1.118 — 미니맵 카메라 입력 연결과 실제 화면 실패

2026-11-27, HJOW-Athlon. 미니맵의 일반 클릭·드래그가 현재 세션의 카메라 목표를 요청하도록 연결했다. 원본 cpppj `GameWorld::CenterCamera`와 같이 현재 화면 크기로 `RequestCenter`를 호출하고 실제 적용은 기존 프레임 처리에 맡긴다. 선택 모드는 장기 `Selection.Mode`에서 읽고 드래그 좌표는 기존 `Poll(0xffff)`를 사용한다. 선택 이동 모드 2·5의 실제 이동 명령은 미연결이다.

- 공통 미니맵 트리의 클릭·드래그가 동일 세션의 목표 좌표와 지도 갱신 번호를 바꾸고 놓기에서 캡처를 반납하는 검사와 관련 타일 검사를 포함해 **19/19 통과**했다. Release 빌드 오류 0, 기존 nullable·중복 using 경고가 출력됐다. `cpp_sync.py` 종료 0.
- 실제 `thewarbegins`, 1024×768, 고정 시드 1760000000, 25ms, 120프레임 실행에서 75프레임 화면을 저장하고 80프레임 미니맵 누름을 전달했다. 이동 후 타일 출력의 미연결 가상 분기에 도달해 **종료 1**이며 나머지 드래그·놓기와 이후 화면은 검증되지 않았다. 최초 결과는 `extracted/dotnet-minimap-1118-live/`, 진단 정보를 추가한 재현은 `extracted/dotnet-minimap-1118-diagnostic/`이다. 두 실행 모두 `originals/` 1,392파일 전후 불변이다.
- 진단 결과는 SID 15097, TYPE 82, frame 35, flags `0x82`다. 기존 `RawTileSprites`는 이 가상 분기를 의도적으로 명시 실패한다. 오류에 SID·TYPE·프레임·플래그를 넣어 실제 분배 대상을 식별할 수 있게 했다. 이 분기는 가상 프레임과 추가 Draw의 실제 분배를 요구하므로 일반 프레임으로 임의 대체하지 않았다.

R5-4c3c의 실제 이동 성공·픽셀 일치·미션 전환 수명은 미완료다. 다음에는 R5-3의 실제 `SpriteDraw`/가상 프레임·추가 Draw와 같은 세션 물리 결선을 복원하고 같은 실행을 재시험한다. 선택 이동, 물리 입력, 전체 HUD, 생산 내용물과 완전 적재 세션도 미완료다. 기존 1.115의 정기 전체 회귀 및 M1 0/34는 새 전체 회귀나 L2 재수집 결과가 아니다.
