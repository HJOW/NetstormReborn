조회2948을 같은 실제 owner에 연결했다. Session.cpp 및 다섯 AI 하위 cpp는

## 구현

- 공통 PostPop과 삭제 전처리의 AI 통지를 같은 실제 Player 포인터/본체에
  연결했다. 현재 시각·Outpost 역할·모드, 실제 Path Form의 TargetA/B와
  같은 GunTarget 발 중심의 배정도 거리, 현재 TYPE 이름/종류29 로그를 쓴다.
- PostPop은 통지 뒤 같은 현재 Client 로컬 owner를 읽으며, 선택 재검사는
  살아 있는 약한 UI 수명 토큰을 쓴다. UI가 없을 때는 원문처럼 실제 Select가
  필요한 조건에 도달해야만 오류를 낸다. Host 뒤에 이 Session 통지만 분리한다.
- 같은 hash0 WORD뷰/방향 동맹/통지기로 World 등록을 만들고 실제 자산의
  간헐천 등록과 연결했다. 신전 발 중심·b00 로그 관문·표면 진단을 보존한다.
- 준비는 같은 사제/신전·HP/Graph·청크 경계·분산 SP·커서 잠금/현재 Gump

  ContainedCreate·Finder·TYPE/난수와 현재 전역을 빌린다. 경제는 같은 본체
  지갑/SP와 현재 데모·사제 상태 조회를 사용하며 실제 포획을 실행하지 않는다.
- 등록 시점에는 새 AI 본체·자산·행동을 실행하지 않는다. 실제 하위 서비스를
  도달 위치에서 요구하고 임의 성공이나 별도 근사 월드를 만들지 않는다.

미준비 전략의 자연 반환·약한 선택 수명·통지 반납을 확인했다.
