## 수집에서 발견한 Carrier 통지 연결 누락

최초65실행 중 DN `runforit`만 현재 부모의 가상+24 `00429560` 미연결로 종료1이었다. 최초 관측은 `extracted/dotnet-l2-0688-initial/`과 `extracted/dotnet-0688/l2-initial.log`에 보존했다. 원문 `RawCarrierContentNotice.cpp/.h` 전체 분기를 Core에 이식하고 실제 내용물 부모 분배기에 연결했다. 저장 게임/로딩은 SID를 읽기 전에 반환한다. 이후 폭탄의 두 번 투영·번개·중심 재조회·음향·TYPE 추가 DWORD·로컬 Sound47 생성, 사제 포획음, 조건부 Carrier 검사, 해방음의 공간 재조회 순서를 유지한다.

기존 독립 원본 `carrier-content-notice-x86.tsv`의1,731입력에서 효과 인자/순서·현재9전역·두 전체50바이트 슬롯이 일치했다. 효과 뒤 kind/owner/좌표/로딩/TYPE 변경과 signed 카메라·CRT 변환을 포함한다. saved/load 접두의 무접근 검사도 통과했다. Core2건과 실제 Host의 내용물 생성/정렬 부착·현재 loading/saved 관문 및 기존 생산3건, 합계6건 통과다. Host 검사는 창이나 포획/희생/공격을 실행하지 않는다.

실제 세션은 같은 내용물 생성기·현재 로딩 깊이·장기 saved/bomb 관문·현재 사제/Rain Walker 역할·실제 Carrier 검사/TYPE 공간 탐색을 공유한다. `HostMissionBurning.SetView`의 현재 픽셀 카메라를 통지 투영에도 전달한다. 번개·소리·Sound47 예약/타이머·genus 탐색의 나머지 실제 장치는 R6에서 연결하며, 선택 시 미연결을 명시 실패한다. 로딩 오류를 숨기는 빈 통지를 넣지 않았다.

수정 후 `extracted/dotnet-l2-0688-probe/`의 Run For It 양쪽2실행과 최종65실행이 모두 종료0이다. fixture는345개이고 기존 관측값은 변경하지 않았다. `cpp_sync.py` 종료0과 `git diff --check`를 확인했다.
