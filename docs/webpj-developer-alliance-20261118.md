# WB04-E742 개발자 동맹 변경 명령

`31h`의 `setAlly`/`sally`, `clrAlly`/`cally`를 현재 Session의 Player 참여 장치에 연결했다. 10.78 기준 소스처럼 설정과 해제 별칭 모두 같은 방향 동맹 추가 함수를 부른다. 두 정수 변환이 모두 성공한 경우에만 호출하고 부호 있는 입력을 DWORD로 전달한다.

근거는 기준선 `225553df`의 `RawCampaignSession.cpp`와 `RawPlayerParticipation.cpp`이며 이 파일들의 기준선 이후 변경은 없다. Player 참여 본체는 기존 단위에서 10.78 fixture 608행 및 동맹 패킷 288행을 대조했다. 이번에 새 원본 fixture나 직접 cpppj 검사는 없다.

독립 검사에서 두 별칭·미완성 입력·부호 있는 변환과 선택된 장치 누락을 확인했다. Tutorial 1 Session의 `31h` 분배기에서 실제 방향 비트·동맹 표·서버 요청을 확인했다. 최초 통합 검사에서는 전투 모드의 요청 전송 장치가 없어 실패했으며 관찰 장치를 연결한 뒤 집중 검사 35건이 통과했다.

Node v26.13.0 전체 회귀 6,224건을 통과했다. 대응표 오류는 0건이며 Node v22 전체 재검사 주기는 4/8회다.

다음은 `31h`의 나머지 개발자 명령과 내부 로그인 서버 후반·응답 왕복이다. Native 분기, 행 base 뒤 변경 판정 및 앱 미션 연결도 남아 있다.
