# 0.725 실제 Client 장기 Surface와 메뉴 프레임

ClientSurfaceGlobals를 추가하고 실제 Root가 첫 메뉴/미션보다 먼저 같은 Surface 저장소를 소유하도록 연결했다. Surface는 같은 ClientGameplayGlobals의 Authority/GameAux를 빌리고, 장기 ProcessHostStorage에는 같은 Kernel/FrameTimeBox를 연결한다. 미션 시작은 이 저장소의 Pool/공간/공장을 재사용한다. 현재 게임 시각·권한·Kernel 슬롯을 초기화하지 않는다. 같은 Frame.game을 프로세스 장치의 상자가 양방향으로 빌린다.

원문 ClientMain.cpp 442행의 장기 물리/권한·보조 전역, 533행의 Graph 시각, 535행의 실제 Kernel/Frame 결합과 대조했다. Graph는 프레임 캐시가 아니라 매 호출의 Clock.GameSeconds(ClientMilliseconds())를 읽는다. 새 소유자는 실제 밀리초 장치를 보유하고 그때의 보정/정지값을 조회한다. 초기 구현의 Frame 캐시 연결을 이 원문 위치에 맞게 보완했다. 현재 Runtime의 장기 Host 대여와 자식 반납, 자산/TYPE 소비자 일원화와 나머지 Native 장치들은 다음 단위다. 현재 개발용 미션 부모의 자산 단일 설치 관문을 유지하며 전체 State 재시작을 구현했다고 판정하지 않는다.

주변음→바람은 미션 유무 대신 실제 Client 시계 초기화 뒤 실행한다. 메뉴에서도 같은 장기 바람과 난수를 진행한다. 실제 주변음 재생/모달/번쩍임과 영화 갱신 잠금은 후속이다. 메뉴 덤프에 남아 있던 게임 시각 상수0을 없애고 Frame의 실제 번호/게임 시각 비트를 넘겼다. world1의 ProcessTime도 같은 Frame 주소를 빌린다. 미션 없는 Kernel 전체 실행과 장기 효과 연결은 아직 남는다.

집중116건이 모두 통과했다(신규 ClientSurfaceGlobals 2건). 같은 Gameplay/Authority/GameAux/Kernel/Frame/프로세스 시각·현재 GeyserType 주소, 양방향 시각 변경, 기존 Frame/Kernel/false 권한 보존, 설치 중 시각 미조회, 현재 시각/보정 변경과 이전 Frame 고정값의 구분을 확인했다. 초기116건 뒤 Graph 조회를 보완했고, 검사 생성자 한 곳의 새 인자 누락(CS7036)을 고쳐 최종116건이 다시 통과했다. 근거는 extracted/dotnet-0725/client-initial.log, client-final.log, client-final-fixed.log 및 client-surface-globals-fixed.trx다. 메뉴 덤프 수정 뒤 실제 호스트 최종 빌드도 경고0/오류0이며 host-final-build.log에 보존했다.

실제 thewarbegins/tutorial1/surrounded와 미션 없는 메뉴, 총4시작이 모두 종료0이다. 세 미션은0.724와 전체 파일 바이트/기존 비교 지표가 같다. 메뉴는 world0·Frame90·게임시각2.25초(bits4612248968380809216)·Kernel0/39999·난수2069314263/1을 관측했다. 원문 전체와 같은 메뉴 상태라는 판정은 아니며, Native Frame과 환경 경로의 실제 실행을 확인한 것이다. 시드1760000000·25ms·90프레임 덤프·영어1024×768 창/음소거 조건이며 포획/희생·특정 적 공격·승리는 재현하지 않았다.
