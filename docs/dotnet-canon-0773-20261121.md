# 0.773 실제 스타일 그림 자산과 본문·메뉴 출력

전체 Chat helper의 아이콘 메뉴를 연결하기 전에 공통 본문/스타일의 실제 TYPE/SHP 자산 누락을 정리했다. 기존 Markup/StyleTextMarkup 본체는 재사용하고 같은 최초 TYPE 표188슬롯·자산 정의116개·SHP 바이트를 빌리는 어댑터를 설치했다. 내장/후행 무자산 슬롯을 실제 자산과 구별하며 이름 조회는 파일 별명이 아닌 원문 런타임 이름을 사용한다. 각 Type 조회는 기본/Gump/방향글자/첫 프레임을 값으로 반환하고 제한 그림은 실제 헤더+1a의 signed 높이를 읽는다.

같은 HostHtmlText의 그림 조각/스타일/버퍼/파서와 controlled 메뉴를 실제 메타데이터와 픽셀 출력에 연결했다. 공통 그리기와 직접 본문 그리기는 잠긴 표면에서만 그림 출력 문맥을 빌리며 예외에도 해제한다. 최초 그림 치환표는 원문처럼 실제 자산 파일 COL의 그림자 표다. 현재 Native 색표7 getter를 받을 경계는 열었고 해당 Native 팔레트 부모 설치는 후속이다. zone 옵션은 실제 Config에서 읽으며 나머지 옵션 변경 소비자 연결도 후속이다.

신규3건 포함 집중68건 통과·실패0이다. 별도 Assets 판독기로 자산116개 전체의 논리 프레임 수/런타임 이름과 모든 프레임의 signed 높이를 대조했다. 무자산/범위 밖/값 반환, 실제 제한 아이콘의 본문 삽입·측정·8비트 출력과 controlled 메뉴 출력·수명을 검증했다. 잘못된 색표 실패 뒤 현재 색표를 다시 조회해 정상 출력함도 확인했다. 이 실자산 조합 검사를 원본 전체 UI 픽셀 일치로 확대하지 않는다.

최초 컴파일에서 검사 코드의 독립 판독기 속성명(Height 대신 DisplayHeight)을 교정했다. 첫 실행67통과/1실패는162번 타입의 파일 별명을 원문 런타임 이름으로 찾으려던 검사 기준 오류였다. 원문의20바이트 이름/설명 덮어쓰기 규칙과 독립 Assets RuntimeName을 확인해 검사를 교정했고 최종68건이 통과했다. 제품 이름 조회와 기존 fixture/기대값은 유지했으며 기존 nullable 경고 외 새 경고는 없다.

기존394fixture 항목/헤더/기대값은 모두 유지했다. PORT_MAP에 실제 자산/본문 그림/Host 설치의4쌍을 추가했다. 대표3시작 모두 종료0·전체 덤프 바이트/지표0.772일치·원본1392파일 불변이다. cpp_sync와 최종 감사 종료0이다. CPP/디컴파일 변경·외부 접속은 없고 실제 포획/희생·특정 적 공격·시나리오 승리는 재현하지 않았다.
