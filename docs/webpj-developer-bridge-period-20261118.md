# WB04-E756 개발자 다리 붕괴 주기 명령

기준선 `225553df`의 `RawCampaignSession.cpp` 31h 개발자 명령 중 `setbridgekillperiod`/`sbkp`를 현재 Session의 `RawSurfaceStorage`에 연결했다. 단정도 입력을 저장한 뒤 수준 29 추적을 출력하고, 그 호출이 돌아온 후 현재 주기와 Graph 시계를 다시 읽어 `resetStateBridgeDecayScan`으로 같은 스캔 범위·커서·기한을 초기화한다. 추적이 실패하면 이미 쓴 주기는 유지하고 뒤 초기화는 하지 않는다.

집중 검사에서는 별칭·단정도·16진수·부호 있는 0과 무한대/NaN, 입력 누락·불완전 지수, 추적 실패 및 재진입을 확인했다. 실제 TheWarBegins Session의 31h 분배기에서도 같은 저장소의 주기, 시계, 스캔과 로그가 갱신되는 것을 확인했다. 입력·출력의 경계값은 현재 Windows UCRT의 스캔/고정 소수 출력과 입력 40종을 비교해 일치했다. 정확히 절반인 여섯째 자리 출력도 실제 UCRT 결과에 맞춰 교정했다. 이 비교는 원본 게임을 실행한 검사가 아니다.

점검 도중 16진수의 0과 큰 지수 조합이 JavaScript에서 NaN이 될 수 있음을 발견해 부호 있는 0을 유지하도록 교정했다. 불완전한 `nan(...)`도 변환 실패로 처리하도록 보정했다. 진행 중이던 전체 회귀 두 번은 각각의 교정 전에 중단했고, 수정된 코드로 집중 검사와 전체 회귀를 다시 실행했다.

나머지 31h 명령과 기준선 이후 Login 변경 판정, 선택 UI·미션 Start·앱 수명은 여전히 남아 있다. 사제 포획·피해·희생, 세 공중 유닛 전용 행동, 게임 창 실행은 하지 않았다.

Node v26.13.0 최종 전체 회귀 6,253건이 통과했고 실패·취소·건너뜀은 0건이다. 대응표 오류는 0건이며 E753의 v22 검사 뒤 세 번째 v26 전체 회귀다.
