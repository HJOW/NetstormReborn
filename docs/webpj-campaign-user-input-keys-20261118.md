# WB04-E798 사용자 입력 정지·커서·단축키 앞단

캠페인 `CampaignUserInput.event`에 원본 `UserInput::Event` 앞단을 부분 연결했다. 키/버튼 뗌과 현재 정지 상태를 먼저 거부한 다음 현재 커서 설정과 회전 모드를 읽고 실제 커서 입력을 호출한다. 소비되지 않은 사건은 기존 생산 단축키와 선택 키 처리기를 순서대로 거쳐 같은 40칸 입력 큐에 명령을 예약한다. 다음 유닛·사제 선택은 호출자가 공급하는 경계이며, 아직 옮기지 않은 좌·우 마우스 사건은 성공으로 넘기지 않고 명시 오류로 남긴다.

TheWarBegins 실제 Session과 World에서 뗌·정지의 조기 반환, 활성 커서의 우선 소비, 잠긴 실제 커서 뒤 Q 생산 명령과 H 홈 명령의 같은 큐 예약을 확인했다. 우선 소비 여부는 독립 콜백으로 관찰했다. 마우스 사건·전체 선택 명령 장치와 브라우저 앱 연결은 남으며 실제 미션 플레이 검사가 아니다.

검증: Node v26.13.0 전체 6,294건 통과(실패·취소·건너뜀 0), 대응표 1,160행 오류 0. 마지막 Node v22 전체 검사는 E795이며 이번 단위까지 이후 v26 전체 검사 3/8회다.

후속 E800에서 우클릭 취소와 후보 반환을 연결했다([단위 문서](webpj-campaign-user-input-right-click-20261118.md)). 좌클릭·상위 메뉴·앱 연결은 계속 남는다.
