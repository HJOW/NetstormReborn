# 우클릭 컨텍스트 메뉴 바깥 클릭 닫기와 사제 건설 위치 미리보기 위치 수정 (WB04-E1135)

사용자가 두 가지를 확인해 달라고 했다. ① 유닛 등을 우클릭해 연 컨텍스트 메뉴가 바깥 클릭에도 닫히지 않는다. ② 사제로 신전·워크샾·제단을 짓는 과정, 특히 건설 위치를 지정할 때. 둘 다 실제 미션에 들어가 실제 마우스 조작으로 재현했다.

## ① 컨텍스트 메뉴가 바깥 클릭으로 닫히지 않음

- 재현: The War Begins! 에서 사제를 오른쪽 클릭하면 메뉴가 뜨고, 맵의 빈 곳을 왼쪽 클릭해도 팝업(루트 직계 `0x4000`)이 그대로 남았다.
- 원본 근거: `UberGump.cpp`(cpppj) 1486행 — Gump 입력이 소비하지 않은 **왼쪽·오른쪽 버튼 누름**은 `RequestClosePopups()` 로 팝업을 닫은 뒤 같은 사건을 월드로 진행한다("UI밖누름은팝업Kill뒤같은사건으로월드에진행한다").
- 원인: 웹 `netstorm.js` 미션 입력 루프(`_runCampaignInputFrame`)가 `gump.input().route(...)` 가 소비하지 않은 사건을 월드로만 넘기고 팝업을 닫지 않았다. 메뉴 항목을 누르는 경로는 메뉴 자신이 닫아서 가려져 있었다.
- 수정: 같은 위치에서 버튼 누름(뗌 제외)이고 안내·대화창이 열려 있지 않으면 `_closeCampaignPopups()` 를 먼저 부른다. 다른 객체를 우클릭하면 이전 메뉴가 닫히고 새 메뉴 하나만 남는다.

## ② 사제 건설 위치 미리보기가 마우스와 어긋남

- 재현: 사제 메뉴 → Construct → 건물을 고른 뒤 마우스를 움직이면 건물 그림·사각 테두리·비용 표시가 마우스에서 (+285, +165)픽셀쯤 떨어진 곳(섬 밖)에 그려졌다. 유효/무효 색(흰색/빨강)은 마우스 위치 기준이라 그림과 맞지 않았다. 실제 배치도 마우스 위치 기준이라 놓으면 마우스 자리에 지어졌다.
- 원인: 미리보기·비용 표시는 카메라 픽셀 원점을 `sharedScreenOrigin[0]`/`[1]` 로 읽는데, 세션 커서 연결(`raw-campaign-cursor.js`)이 `CameraView.pixels` 접근자(값 사본 `{x, y}`)를 넣었다. 인덱스로 읽으면 항상 0 이라 그림이 카메라 위치만큼 밀렸다. 같은 함정은 `client-cursor-state-cleanup.js` 주석에 이미 적혀 있었고(그쪽은 살아 있는 `Int32Array` 를 쓴다), 취소(ESC) 한 번 뒤에는 정상으로 돌아와 가려졌다. 시험 대역이 `{ pixels: Int32Array }` 라서 기존 Node 시험도 못 잡았다.
- 수정: 카메라 바이트의 `+28/+32` 를 가리키는 살아 있는 `Int32Array` 를 연결한다(`bytes` 가 없는 시험 대역은 기존 `pixels` 를 그대로 쓴다).
- 비교: 원본 스크린샷 `Tutorial - Temple - Generating Range.png`(건물 그림에 사각 테두리, 아래에 비용 `5000`)과 같은 모양이 마우스 자리에 그려진다.

## 확인한 건설 흐름

| 건물 | 미션 | 확인 내용 |
| --- | --- | --- |
| 신전 | Tutorial2 | 사제 우클릭 → Construct → Temple → 첫 신전, 위치 지정(미리보기가 마우스를 따름) → 클릭 → 건설 완성 |
| 워크샾 | Tutorial2 | 같은 사제로 Construct → Workshop → 첫 워크샾, 같은 과정 |
| 제단 | The War Begins! | Construct → `Build Level 1 Altar for 500`, 같은 과정 |

- The War Begins! 에서는 `Temple` 이 비활성이다. 이미 신전(Player+0x7c)이 있으면 비활성이 되는 원본 규칙이며, 원본 스크린샷(`The War Begins! - High Priest Context Menu.png`)에서도 `Temple` 이 어두운 색이다. The War Begins! 의 첫 섬에서 워크샾은 배치 규칙(`mayPlace`)이 거부해 자리가 없다(섬이 좁고 다리로 이어지기 전). 원본도 다리 뒤 옆 섬에 짓는다. 이 둘은 웹 이탈이 아니라고 보지만 원본 직접 대조는 하지 못했다.

## 시험

- `e2e/mission-context-menu-close.spec.js`(Chromium): 사제·신전 우클릭 후 왼쪽/오른쪽 바깥 클릭이 팝업을 닫고, 다른 객체 우클릭이 메뉴를 겹쳐 쌓지 않는다. 수정을 빼면 팝업이 남아 실패한다.
- `e2e/mission-build-placement.spec.js`(Chromium): 위 표의 세 흐름을 실제 마우스로 진행한다. 캔버스에서 미리보기 테두리(흰/빨강 선) 픽셀을 읽어 중심이 마우스에서 110픽셀 안인지 본다. 수정을 빼면 테두리를 마우스 근처에서 찾지 못해 실패한다.
- `tests/raw-campaign-cursor.test.mjs`(Node): 실제 `CameraView` 를 연결했을 때 화면 원점이 카메라 바이트를 살아 있게 따른다. 수정을 빼면 실패한다.
- netstorm.js·커서를 쓰는 Node 시험 358건과 관련 e2e 묶음은 LEFT_JOBS 0.1 절 기록을 따른다.

## 남은 것

- 비활성 하위 메뉴 행의 화살표: 원본은 비활성 `Temple` 도 어두운 `›` 를 그리는데 웹은 빠뜨린다. 하위 메뉴 행 flags 에는 CHILD 비트가 있어 그리기 조건은 만족하나 표식 위치/색에서 사라지는 것으로 보이며 원인은 미확정이다(메뉴 글자 폭 측정과 `~x` 접두 처리 의심).
