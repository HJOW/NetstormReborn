## 현재 전투와 주기 생성

원문처럼1..9의 유효 전투 수/첫 빈 슬롯과1..39의 활성 참가자 수를 계산한다. 전투 목표는 **이 부모에서 상수10**이며 fakeBattles 옵션으로 대체하지 않는다. 매회1..9 첫 빈 전투를 검색하고 현재 게임 시각-현재 전투+150 FullTime이 현재 signed deadTime보다 클 때 생성한다.0044c3f0의 flags1/id/identity6/위치·8회원0/버전ffffffff·100/현재 game 시각만 쓰며 나머지 현재 바이트는 보존한다. 기존23h writer/공유scratch와 실제 Broadcast를 사용한다. 정상 반환값은 원문처럼1이다.

## R 프로세스 난수와 실제 생성자

R0048bad0은 CRT TLS 함수가 아니라 **004cda10 process 전역 DWORD**를 `state*0x343fd+0x269ec3`로 갱신하고 상위15비트를 돌려준다. PE 초기값은1이고0048bac0은0도 그대로 쓰는 seed다. root::Random은 기존 CrtRandom의 계산만 Borrow로 재사용하며 ThreadCrtRandom/std::rand 스트림을 사용하지 않는다. CCh/서버 재생성 시 자동으로 재시드하지 않는다. 최종 R owner가 모든 소비자와 같은 Random을 유지해야 한다.

identity는 초기6BYTE0 뒤 두 난수로 형상rand%21/BYTE3/bit100을 작성한다. 원문 추가 위치/Core 인자는 이 함수에서 사용하지 않는다. 가상 Core는 초기10BYTE0에서26번 난수로 능력22비트/각 WORD·BYTE를 작성한다. 이어 위치→identity→PE25이름 선택→전투 배정 분기 순서다. 이름의 공백/구두점 제거는 로컬 로그인·Root 요약과 같은 실제 참가자 생성자를 사용한다. ctor는 같은 ClockState/Random 참조를 추가로 요구하며 기존 별도 시각/새 seed를 만들지 않는다.

## 위치와 가상 참가자의 특이동작

00457d40은 기본거리225/범위50, 후보5개를 사용하고 먼저 y,그다음 x 난수를 소비한다. 현재 전투10개 위치는 유효 여부와 무관하게 검사한다. **참가자 구간의 실제 거리 참조는40개 위치가 아니라 stale 참가자0+10/+14다.** 기계어457e77..9d에서 별도 참가자 포인터를 초기화/증가하지만457ea6/eb2는 전투 순회가 끝난 다른 포인터를 읽는 것을 확인했다. 이 참조와 float32 dx/dy·최종 거리 저장,엄격한 threshold/best 비교를 보존했다. 미정 best를 임의0 위치로 대체하지 않는다.
