## 부착과 현재 콜백 상태

부착은 void 비트 **8**을 지우고, parent 인자가 0이면 기존 부모를 재사용한다. 루트가 아닌 부모에 붙이고 **bit 0x200000**이 없으면 부모 깊이에서 기본 **3**을 빼거나, 자신의 비영 secondaryDepth를 더한다. DWORD 넘침을 보존한다. 루트 직계 자식은 기존 깊이를 유지한다.

**bit 0x4000**은 현재 부모의 같은 비트 형제에 삭제를 요청한다. 삭제 대기 bit 0x10000으로 필터하지 않으며, 호출 전에 저장한 next를 따라간다. 이후 현재 부모의 자식 머리에 삽입하여 previous=0, next=기존 머리, parent.child=this, 기존 머리.previous=this를 쓴다. 삭제 요청 자체의 몸체와 큐/등록 해제는 후속이다.

mode bit **1** 또는 자체 bit **0x20000**이면 화면 제한을 생략한다. 일반 위치는 루트에서 오른쪽/아래 초과를 먼저 제한하고, 음수 위치를 0으로 바꾼다. 객체가 화면보다 커도 이 원본 순서를 유지한다. 월드 부착 bit **0x2000**은 투영 정수 위치를 float에 더해 저장한 뒤 화면 제한을 적용하고, 이후 **현재** world 비트가 남아 있으면 그 정수 위치를 뺀다. 투영이 바꾼 현재 부모/화면 크기/플래그도 재조회한다.

10.78의 화면 제한은 signed 화면 정수를 그대로 x87에 올린다. CD는 화면 정수를 **float으로 먼저 저장**한다. 화면 폭 16,777,217과 객체 폭 2의 실제 관찰로 차이를 확인했다. 하한 처리에서도 패치는 음수 0을 보존하고 CD는 양수 0으로 바꾼다. 호스트에서는 double 계산 후 원본 저장 위치마다 float으로 반올림한다.

위치 저장→mode bit **2**의 정렬 적용→가상 redraw(false) 순서다. redraw 이후의 **현재 child**부터 자식 재배치를 시작한다. 각 자식의 next는 가상 Push 전에 저장한다. alignFlags 또는 secondaryDepth가 있는 자식은 가상 Push→현재 secondaryDepth로 깊이 갱신→정렬→가상 Attach(x,y,0,0)를 호출한다. Push가 바꾼 현재 정렬/크기/깊이를 읽지만 순회 next는 이전 값을 사용한다.

## 밀어내기·정렬·깊이·이동

밀어내기는 void 비트를 세우고 previous.next 또는 parent.child를 자신의 next로 연결하며, 다음 형제의 previous도 갱신한다. 그 뒤 가상 redraw(true)를 호출한다. **자신의 parent/next/previous는 지우지 않는다.** 이후 parent=0 재부착이 같은 부모를 사용한다. 패치 진단 전역의 3/4는 이전 형제/부모를 자기 자신으로 연결하는 원본 분기이며 CD는 이 전역을 읽지 않는다. 이 진단 입력은 일반 정상 트리를 의도적으로 깨뜨릴 수 있으므로 후속 수집의 순환 거부 계약과 구분한다.

정렬은 부모의 **기본 크기 +0x3c/+0x40**를 사용하고, 루트이면 현재 화면 정수를 float으로 먼저 저장한다. bit 1/2로 기본 크기를 부모에 맞추고 현재 크기에는 scale을 곱한다. bit 4/8의 가운데→0x10/0x20의 끝→0x40/0x80의 지도 중심 순서로 위치를 덮는다. 위치는 반환만 하고 자신의 x/y는 직접 바꾸지 않는다. 지도 중심은 signed DWORD 합의 감김 후 2로 나눈 값이며 지도 중심 정렬은 루트 직계 자식만 허용한다.

깊이 더하기/지정은 visible/dead/void와 관계없이 모든 자식을 먼저 처리한 뒤 자신을 갱신한다. 재귀 뒤 현재 next를 읽는다. 깊이 더하기는 DWORD 덧셈이다.

단순 이동은 bit **0x10**의 드래그 기준점을 먼저 빼고, void가 아니면 가상 Push를 호출한 뒤 가상 Attach로 넘긴다. 상대 이동은 가상 Push가 끝난 뒤 현재 부모와 기준 노드를 비교하여 필요한 위치를 더한다. anchor bit **8/4**로 기준 폭/높이를 순서대로 더하며, 현재 부모가 기준이면 기준 위치 자체는 더하지 않는다. 이 두 함수가 직접 기본 부착 몸체를 호출하는 것은 아니다.

## 같은 저장소의 실제 연결

통합 검사는 기본 생성→실제 부모/자식 부착→수집→CRT 정렬→kind 2/클립 보호→선 픽셀 출력을 연결한다. 실제 밀어내기 후 수집 대상에서 사라지고, 기존 부모 재사용의 재부착 후 새 좌표/캐시가 반영되는 것도 확인했다.

별도 통합 검사에서는 가상 Push/Attach를 실제 기본 `GumpTree` 몸체에 바인딩하여 자식 정렬/깊이와 형제 재삽입까지 실행한다. 깊이 변경이 수집 signed WORD 키로 전달되고, 콜백 예외에는 이미 쓴 링크/위치를 유지하는 호스트 계약도 검사했다. 원본 PE 예외 전파와 실제 GUI 캡처 일치는 실행하지 않았다.

생성/트리 상태와 노드 저장소는 처리기보다 오래 살아야 하며 콜백 중에도 노드 주소를 안정되게 유지한다. 이미 void인 Push의 로그 입력, CD 비void 부착의 assert 입력, 누락 토큰/필수 처리기와 순환/과도한 재귀는 호스트에서 예외로 거부한다. 이러한 손상 입력의 실제 PE 로그/assert를 실행한 근거는 아니다.

## 독립 관찰과 검증

`tools/decomp_gumptree_oracle.py`는 세 PE의 위 **9개 전체 몸체**를 제한된 x86에서 실행한다. 가상 처리·삭제 요청·월드 투영만 완성 입력 응답 경계다. 기대 링크/정렬/깊이/위치를 응답 경계에서 계산하거나 C++ 구현으로 생성하지 않는다. 지도 중심과 내부 정렬/깊이 재귀는 실제 PE 몸체를 실행한다.
