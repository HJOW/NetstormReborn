# AI 다리 탐색 초기화의 원본 전체 본체 복원

2026-10-22 작업 단위313. 현재/마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-22**로 같다. 단위312 전체 회귀 통과 뒤 남은 AI 다리 탐색 중 `0040fde0`을 복원했다. 원본 Step600 fixture와 기존 미완성 하위 경계는 덮어쓰지 않았다.

원본 명령은 this=Brain+5f0에서 caller의 네 float를 실제 CRT `004e49c0`으로0쪽 절삭한다. 소스 정수 XY(+48/+4c)와 목표(+50/+54), 후보 집계(+a0/+a4), 나선 시작(+b0/+b4), 단계2/길이1(+a8/+ac), 비용0x10000(+b8)을 기록한다. 결과 XY(+d0/+cc)는 float-10000의 비트 `c61c4000`으로, 검색 진행(+d4/+dc)은0으로 초기화하고 현재 개수(+38)-1을 마지막 인덱스(+d8)에 감김 그대로 쓴다. Brain의 다른 바이트·현재 단계·입력 개수는 유지한다.

새 `tools/decomp_ai_bridge_initialize.py`는 보호 PE를 읽기 전용으로 매핑해 **0040fde0과 실제 CRT 몸체만** 격리 실행했다. 하위 함수를 C++ 결과나 Python 절삭으로 대체하지 않았다. 정상/음수/소수/서브노멀/음수0/32·64비트 경계/NaN/무한대와 개수0·1·80000000·ffffffff를 포함한 **144입력**을 두 x87 정밀도에서 **288정상 반환**시켰다. 전체0xb08 본체 **813,312바이트**, ret16 이후 스택·반환1·비휘발 레지스터·CRT4회·FPCW 복원을 확인했다. 출처는 `cpppj/ai-bridge-initialize-20261022.json`과 새 `ai-bridge-initialize-x86.tsv`다.

제품의 `RawAiBridgePath::Initialize`는 같은 쓰기 순서와 signed64 절삭의 낮은 DWORD/indefinite 하위0을 구현했다. 독립 원문의 매 전체 본체를 대조하므로 덮으면 안 되는 주변 메모리도 함께 검증한다. 별도 조립 검사에서는 Step 상태1이 실제 Initialize를 호출한 뒤 상태2로 한 번만 진행하고 caller 좌표는 보존되는지 확인한다. 기존 초기화 콜백을 성공 더미로 바꾸거나 후보 준비/검색을 완료 처리하지 않았다.

첫 빌드는 테스트의 `<filesystem>` 누락으로 실패했고 헤더를 추가해 해결했다. 최종 Release는 **종료0·경고0·오류0**, AI 다리 집중 **15개·실패check0**이다. 원본 초기화144개와 기존 Step600개 및 소비/배치/기한 경계를 모두 재생했다. 로그는 `extracted/cpp-ai-bridge-initialize-20261022-{build,build2,tests}.log`다. 세 출처 SHA도 다시 확인했다. 전체 CTest는 이 단위에서 반복하지 않아 최신 전체는 단위312의 **2,217개·실패check0**로 유지하며 새 두 검사를 포함한 전체 통과로 합산하지 않는다.
