# CD 10.72 기본 화면 크기 유지 (제품 1306, 2026-11-14)

마지막 디컴파일 PC: HJOW-Athlon(변경 없음). 기존 양판본 산출물을 읽었으며 재디컴파일·원문 변경은 없다.

CD 자료 사본을 일반 클라이언트의 `--run <사본> --cd --window --no-audio --frames 50`으로 실행하면 `ScreenSurface`의 `dibBuffer` 오류로 종료했다. CD의 setup 설정에는 `SCREENW`·`SCREENH`가 없는데 `Client::InterpretOptions`가 두 축을 0으로 초기화한 뒤 `ReadInt`를 호출하여 0×0 DIB를 요청한 것이 원인이다. `ReadInt`는 누락된 키의 목적지 값을 유지한다. CD 원문 `00484ac0`의 옵션 해석에는 두 해상도 키 읽기가 없고, 시작 부모 `00485b20`은 창 크기를 640×480 기준으로 계산한다(`extracted/refined/originalCD/NETSTORM.c`).

`InterpretOptions`는 기존 표시 크기를 두 축의 초기값으로 사용한다. 아직 표시 크기를 정하지 않은 최초 실행에서는 기존 논리 크기 640×480을 사용하며, FSR 표시 크기를 이미 정했다면 그 표시 크기를 유지한다. 설정에 명시된 축은 기존 `ReadInt` 경로로 읽는다.

Release `NetstormCpp` 빌드가 종료 코드 0으로 완료됐다. 같은 CD 자료 사본·동일 인자로 다시 실행하면 `dibBuffer`가 사라지고 `MessageGump.cpp:73`의 판본 검사에서 `Pause 메시지 실제 TextGump/이름/번역/측정 연결 누락`으로 종료한다. 따라서 화면·글꼴·자산 초기화까지 진행한 것으로 관측되며 **메인 메뉴 표시 성공은 아니다**. 수정 전·후 원시 결과는 `extracted/cpp-cd1072-1306/`에 남겼다. 기본 10.78 자료의 40프레임 대조 실행은 종료 코드 0이며 State 42→41→3→4가 관측됐다.

보호된 `originalCD` 전체 파일의 실행 전후 SHA-256이 일치했다. 실제 게임은 CD 사본과 클론만 실행했고, 사제 포획/희생·특정 적 공격·승리·MP·사용자 직접 확인 검사는 실행하지 않았다. 다음 단위는 CD 메시지 UI의 원문 대응 복원과 `CDDir` 설정 지원이며, 이후 튜토리얼 진입과 마지막 M8 관문이 남는다.
