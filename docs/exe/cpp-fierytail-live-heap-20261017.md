# 실제 데모3의 Fiery Tail 색 표와 인접 heap 메모리

현재 PC는 **HJOW-Athlon**이며 마지막 전체 정밀 디컴파일도 **HJOW-Athlon / 2026-10-16**으로 일치한다. 단위101은2026-10-17에 원본10.78 복사본의 **Demo of Dissolved Alliance!**를 실행해 실제 할당 메모리를 관찰했다. 새 디컴파일과 C++ 제품 변경은 없다. 작업 전 AGENTS.md와 양 LEFT 인수인계, 직전 단위100 커밋 `3fda610`·깨끗한 트리를 확인했다.

## 실행과 증거

AGENTS.md의 HJOW-Athlon 실행 확인 예외를 적용했다. `analyzeManager`가 만든 독립 복사본을1024×768 창 모드로 실행했고 원본 PE의 SHA와 복사본이 같음을 확인했다. 원본 PE나 설정을 직접 수정하지 않았다. 세션 ID는 **`20261016T150059038Z-1e0a848c4a86`**이다. ID는 UTC이므로 한국 날짜2026-10-17과 다르게16일이 들어간다.

computer-use의 창 선택은 성공했으나 캡처가 `FrameArrived timed out: timed out waiting on channel`, 재선택 후 `window capture timed out: timed out waiting on channel`로 실패했다. 이전 좌표를 재사용하지 않았다. 게임 전용 analyzeManager의 화면 캡처는 정상이라 그 현재 화면/입력 증거를 사용했다. 시작 팁과 버전 검증 안내를 닫고 Demo 목록의 세 번째 미션을 선택한 뒤 안내창을 닫았다. 검증 안내는 최신판 확인 실패로 멀티플레이를 막지만 싱글플레이/LAN은 허용한다고 표시한 정보창이며 인증 정보를 입력하지 않았다.

실제 게임 PID는3344였다. 읽기 도구는 세션 PID의 전체 실행 파일 경로와 PE SHA를 확인한 뒤 `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ`만 요청했다. 디버거 중단, WriteProcessMemory, 임의 코드 실행·패치, 게임 파일 수정은 없다. 현재 공유 색 표와 표시 목록의 TYPE11 객체·입자만 읽었다.

## 실제 색과 인접 DWORD

공유 표 객체는 `0x04c12ea8`, 색 배열은 `0x04c0fdb0`, count는11이었다. 실제 앞11개 DWORD는 다음과 같다.

```text
217,226,62,56,51,200,221,218,218,197,196
```

이는 단위99에서 실제 생성자를 실행한 GIFCLOUD 팔레트 결과44바이트와 같다. 원본 기대값을 바꾸거나 제품에서 재계산한 결과로 대체하지 않았다. 색수11 바로 뒤의 DWORD, 즉 배열+44는 이번 관찰 내내 **1**이었다. 이는12번째 색의 정의가 아니라 이 할당 옆에서 실제 읽은 값이다. 뒤16바이트 전체도 보존했고 그중 더 뒤쪽 DWORD 일부는 후속 관찰 중 변했다.

`005e5370`의 실제 heap mode는1, small-block threshold는0이었다. 현재 정밀 C의 `__heap_alloc @ 004e429b`를 대조하면 이 모드는 작은 블록 분기와16바이트 요청 크기 반올림을 건너뛰고 **`HeapAlloc(heap,0,44)`**로 간다. 0 플래그는0 채움 요청이 아니다. 이는 실제 모드와 정적 분기를 대조한 근거이며 HeapAlloc 호출 자체를 디버거로 추적한 관찰은 아니다.

따라서 다음 구현에서 배열 뒤를0으로 초기화하거나 마지막 색으로 clamp하거나 고정1을 덧붙여서는 안 된다. 원본은11색을 할당하고 최대 수명의 조회가 그 다음 DWORD를 읽는 몸체다. 실제 런타임 allocator/읽을 수 있는 메모리 경계를 연결해야 한다. 다른 실행·미션 최초 할당·64비트 클론 heap에서 값이 항상1이라는 증거는 얻지 않았다.

## 보존 자료와 검증 범위

[`cpppj/fierytail-live-heap.json`](../../cpppj/fierytail-live-heap.json)에 세 원문 변형, 각 읽기 수·주소·색수·실행 범위와 SHA를 보존했다. 원본 PE·정밀 함수표·관찰기·독립 생성자 fixture의 SHA를 고정했다. 원문45초/3초 전체 객체·입자 자료와 녹화는 Git 제외 경로에 있으며 해당 원문 SHA도 보고서에 기록했다.

```powershell
python tools/capture_fierytail_heap.py --verify
```

이 오프라인 감사는 보존된 실제11색을 원본 생성자 fixture44바이트와 비교하고, 배열 뒤 원문과 읽기 수를 확인한다. 실제 게임을 다시 실행하지 않는다. 도구는 관찰 뒤 `--verify` 기능을 추가했으며 기존 관찰 데이터는 바꾸지 않았다. 두 실제 관찰 호출이 정상 종료했고 읽기 오류는0이다. C++ 제품/빌드 구성이 바뀌지 않아 빌드·전체 CTest를 다시 실행하지 않았다. 직전 전체 검사 **1424개 중1422통과·기존2실패**는 단위100의 결과이며 새 검사 결과로 합산하지 않는다.
