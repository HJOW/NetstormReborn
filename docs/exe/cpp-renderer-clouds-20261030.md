## 618의 경계 이름 정정과 같은 실제 저장소

618은 상위 앞단을 실제 PE로 실행했지만 `4977f0`은 명시 하위 경계였다. 당시 `fullInvalidate`라는 API 이름과 설명은 일반 화면 dirty로 오해할 수 있었다. 실제 함수는 `0059a940..97f`의4개 사각형과 `0059a8d4`의 개수를 다루므로 **`queueCloudDirty`로 이름/한국어 주석을 고쳤다.** 기존 fixture의 F 사건은 그 명시 호출 경계의 기록이며 바이트를 바꾸지 않았다.

새 `ClientRendererFrameGlobals`는 BSS0의19DWORD 스캔 상태·구름4칸/count·별도 묶음 숨김 `0059a8b4`를 보관한다. F2의 건물 숨김 `0059a8ac`와 합치지 않는다. 실제 PE에서 이19DWORD/4칸/count/묶음 숨김의 최초0을 별도 읽기로 확인했다. 복제 금지와 안정된 저장소를 제공하며 Client가 소유하는 연결은 다음620에서 한다.

원문 앞단과 새 구름 저장 함수를 같은 owner/count로 합성한 검사에서는 기존 사각형을 보존하고 화면 flags 변경/세계 redraw의 구름 요청을 쌓은 뒤 원문의 count0 위치를 확인했다. 일반 화면 dirty 개수는 별도이며 마지막 force redraw에서만 따로0이 된다.

## 원문 처리

- `4977f0`: signed count<4이면 해당 칸의LTRB를 저장하고 count를 증가한다. checking이 비영이고 count>=4이면 원문 진단을 먼저 호출하고, 돌아온 뒤 바뀐 현재 count를 다시 읽는다. 여전히4 이상이면 쓰지 않는다.
- `497860`: signed count가 양수인 동안 현재 Y→분모→IDIV→현재 X→IDIV 순서로 좌표를 구하고, 실제 현재 사각형을 **별도 시차 표면**의 `471410`에 전달한다. 표시 효과 뒤 바뀐 count/다음 사각형·카메라/분모를 반영하며 정상 반환에만 count0을 쓴다.
- `499bfd..cfe`: 묶음 숨김의 검정 지우기가 먼저다. 그 효과 뒤 UI 전용 flags4 또는 배경 덮임이면 일반 배경 처리를 생략한다. clouds8이 꺼졌으면 현재 날씨색, parallax16/fullscreen1/비DIB2이면255 표식, 나머지는 현재 카메라 또는 signed 분모로 나눈 카메라로 일반 구름 `4711d0`을 요청한다.

배경 선택은 right/bottom을 먼저 보존하고 left/top은 실제 호출 직전에 읽는 원문 순서를 유지한다. Y 또는 X의0 나눗셈/INT_MIN÷-1은 선택된 위치에서 명시 오류가 되며 성공값0으로 바꾸지 않는다. 실패 뒤 count를 가짜로 정리하지 않는다.

음수 append의 앞선 메모리 쓰기와4칸 뒤의 읽기는 제공된 물리 범위를 벗어나므로 호스트 범위 오류로 구별한다. 음수 refresh count의 자연 생략은 원문대로 수행한다. 임의 배열 확장/양수 index 정규화는 하지 않는다. 이 경계는 임의 손상 메모리 전체의 동일성을 보장한 것이 아니다.
