# 채팅 제출 해석과 실제 수신자 배열 — 단위579

원본 **0042da00**의 대상 접두/본문 해석과 **0042d1b0**의 수신자 중복 제거·배열 확장을 복원했다. 실제 Client 소유자의 미초기화 수신자 할당/이전 배열 반납을 같은 메모리 장치에 연결했다. **실제 Console Enter의 `sendChat` callback과 메시지 서식/송신은 아직 연결하지 않았다.** 이번 결과는 제출 부품과 실제 메모리 소유자까지이며 사용자 채팅 전송 완료가 아니다.

## 원본 동작과 구현

마지막 전체 디컴파일은 **HJOW-Athlon / 2026-10-23**, 현재도 HJOW-Athlon이다. 보호 PE의 제출550BYTE/수신자 추가153BYTE,0042d120 채널 조회,Identity 초기화/재초기화,실제 Regexp 컴파일/검색/캡처/오프셋과 실제 `__chkstk`를 격리 CPU에서 실행했다. Identity 응답/변경·번역·CRT·할당/free·입력줄/분배 진입은 명시 외부 장치다. 게임/GUI/네트워크를 실행한 관측이 아니다.

대상/본문 패턴은005049c8을00548718에 컴파일한 원문이다. 아래 제어 문자는 읽기 쉬운 escape로 나타냈다.

```text
^[\r\n\t ]*([^:]*)($|:[\r\n\t ]*(.*))
```

- 진입 때 같은 manager의 수신자 count와 직접 지정 표시를0으로 쓴다.
- 콜론이 있으면 본문을 먼저 복사하고, 접두를 뒤의 인접 버퍼에 복사한다. 두 캡처는 각각2048BYTE 상한과 그 다음NUL을 사용한다. 본문 상한의NUL이 접두 캡처로 덮이는 원문 인접 효과도 보존했다.
- 접두는 CR/LF/TAB/space 네 구분자로 토큰화한다. 각 이름은40BYTE와 인접 주소 첫BYTE의NUL을 포함하는 같은60BYTE Identity 지역을 사용한다.
- Identity 성공은 같은 subscriber를 추가한다. 실패하면 빈 키를 포함한 여덟 채널을 번역/비교하고 직접 지정 표시를0으로 바꾼다. 번역 장치 뒤 이름은 현재 지역에서 다시 읽는다.
- 알 수 없는 대상은 앞서 모은 수신자를 버리고 mask0x20으로 바꾸며, **입력 전체**를 본문으로 복사한다. 이 fallback만 끝2047번째 BYTE를 강제로NUL로 만든다.
- mask가 있으면 현재 Chat100×48행의 비영 subscriber와 signed flags BYTE를 순서대로 읽어 추가한다. 빈 본문은0042f270(0), 나머지는0043f6f0 진입으로 전달한다.

수신자 추가는 기존 DWORD의 중복을 먼저 찾는다. signed capacity≤count이면 `capacity*4+128`BYTE를 할당하고 **capacity 전체**를 복사한 뒤 이전 배열을 반납한다. 같은 manager의 현재 포인터를 새 토큰으로 바꾸고 현재 capacity에32를 더한 다음 현재 count에 쓴다. 선택된 할당/free/진단이 중단되면 앞선 부분 쓰기를 유지한다. 지원하는 실제 span 밖의 접근과 잘못된 수명 토큰은 명시 예외다.

`ClientChatManagerGlobals`는 manager 객체와 반납 가능한 수신자 배열의 종류를 구별한다. 원래2712/128BYTE startup 할당 계약은 유지하고 확장용 DWORD 배열 할당/반납을 별도로 추가했다. 현재 manager 전역이 바뀌어도 명시 this 토큰의 옛 manager 객체는 유지한다. 새 `MakeClientChatSubmitHooks`가 같은 소유자를 보유해 조회/확장/반납만 연결한다. 조회/번역/입력줄/실제 분배는 후속 연결에서 공급해야 한다.
