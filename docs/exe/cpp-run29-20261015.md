# 단위29 — 실제 캠페인 클라이언트 서비스 준비

작업 PC와 마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex, 2026-10-15**다. 기준 커밋은 `82cc438`이다. AGENTS와 두 LEFT를 재독했다. 현재 PC에서 재생성한 `extracted/refined/`의 10.78 C와 보호 PE 기계어를 읽었다. 이번에는 Ghidra 재내보내기나 원본 게임 실행을 하지 않았다.

## 변경

`CampaignClientServices`는 실제 `Client`, `RawButtonControls`, 현재 미션의 제목/Tell 처리기를 빌려 `RawCampaignSessionServices`를 만든다. 이 단위는 **호출 가능한 서비스 생성부 준비**이며, `UberGump::BeginMission`의 Battle 차단은 아직 유지한다. 검사 fixture의 성공/관찰 콜백을 기본 게임 동작으로 복사하지 않았다.

- 현재 Unix 초를 time32 범위에서 공급한다.
- `You`는 요청 시 실제 Xlat에서 조회한 뒤 원본 Windows-1252/NUL 바이트로 반환한다. 설정 쓰기는 첫 NUL까지 UTF-8로 변환하여 같은 `ConfigInterface`에 기록한다. CP1252로 표현할 수 없는 글은 기존 인코더의 예외를 유지한다. 한국어 확장은 별도다.
- `theammode`는 원본 철자와 기본값 1을 유지하여 호출마다 다시 읽는다.
- 실제 `SoundList`와 `SoundPlayer`에 보호막47·안내·낙하·신전·발사/충돌·이동음을 연결한다. 총 회전/발사 이름 기반 소리는 세션 내부에서 같은 부모 SID의 **현재 raw float 위치**를 읽고 동일한 위치 재생 경계를 사용한다.
- 원본 총 명령은 실제 `InputQueue::PushCommand`로 전달한다. 후속 명령 소비자/생산 UI 완성을 뜻하지 않는다.
- 생산 갱신은 실제 현재 Gump의 캡처/dialog/루트 분배기에 사건 `02000003`, 인자0/0, includeHidden1을 보낸다. 현재 트리에 생산 패널 노드가 없으면 실제 미처리 반환을 유지한다.
- Player 로그는 실제 프로세스 로그 스트림으로 전달한다.

`Client::WorldAudio`를 추가했다. 일반 실행은 기존 장치/음악 묶음을 빌리고, `--no-audio`는 OS 장치·음악 스레드를 열지 않은 실제 묶음의 이름표/재생 계층을 빌린다. 이름표를 초기화하므로 실제 이름 조회는 유지되며, 미초기화 장치의 `SoundPlayer::Play`는 기존 몸체에서0을 반환한다. `Audio()`는 noAudio에서 여전히 NULL이다. 메뉴/월드/해상도 변경의 화면 영역도 같은 묶음에 전달한다.

`Client` 종료 순서는 메뉴/월드/소리 프로세스 → 번개 → 음향/음악 → Renderer/화면 → 창이다. 기존 순서에서는 장치 묶음을 월드보다 먼저 해제하므로 실제 소리 프로세스를 연결하면 이미 해제한 `SoundPlayer`를 참조할 수 있었다. 실제 세션은 원본 무상태 다리 진단을 사제 Owner 통지의 기본 몸체로 재사용한다.

## 빌드와 범위

최종 **NetstormCpp Release 빌드 종료0·경고0·오류0**이다. 자료는 `extracted/run29-build.log`와 최종 `extracted/run29-build-final.log`다. `git diff --check`에 공백 오류가 없다. 새 테스트 추가·테스트 실행·클론/원본 GUI 실행은 하지 않았다. 기존 전체1,145개 통과는 단위28의 과거 결과이며 이번 변경의 실행 근거가 아니다.

보호 PE SHA-256도 기존 기준과 같다.

- 10.78: `A305414CFE0B94494BB32FEF2B359E920E9DABA225E0821B76AEA1F9F8E7D236`
- 10.72: `613500A394B3062E914604EB7D09896D678192BE24545D0E575082A87C851233`

Battle를 활성화하기 전에 실제 Form 직렬화/삭제 전파, 내용물 부모 가상 통지, 피해 owner/AI 통지, fencemark 코너, Ready/login/미션 프레임을 연결해야 한다. 새 생성부를 실제 `UberGump`에 넘기는 작업도 그 단계에 포함한다. `themes/elements` 보충 표가 현재0으로만 초기화되는 문제는 TYPE+98 파서와 함께 후속 복원한다. 초기 지도 로드/독립 전투의 이전 성공만으로 Early Missions/1-1~1-2 완주 동일성을 주장하지 않는다.
