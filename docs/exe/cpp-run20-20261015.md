# 단위20: 캠페인 전체 Kernel과 현재 자산 예약 연결

## 작업 기준과 원문 보존

기준 커밋은 `6fabde2`, 현재 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon, 2026-10-15**다. AGENTS와 양 LEFT를 다시 읽었다. 보호 PE/원본 자산/AGENTS는 수정하지 않았다. 직접 영향16파일 전체를 `cpppj/hist/run20-base`에 편집 전 보존했다. 기존 이력을 재귀 복사하지 않는다.

같은 PC에서 읽기 전용 Ghidra export를 실행했다. `vortex-update`는 PATCH4/CD3 함수, `campaign-frame`은 각6 함수다. 원본 게임·복사본 게임·GUI·OS API는 실행하지 않았다.

## 실제 월드 연결

`RawCampaignGunQueries`는 동일 Pool의 현재 방향·실제 표적 finder·Q16 시간 압축·8DWORD 발사 문맥·TYPE 발사 대기를 기존 `RawGunProcess`에 연결한다. 실제 방향은 새 `RawGunMode`가 현재 raw Graph/Frame에서 읽는다. windArcher의 extra8이 없으면 Graph*2, 그 밖은 signed 방향 문자*2-152를 읽고 범위 밖이면0이다. 패치는 DWORD frame, CD는 BYTE frame이다. 고정 방향/별도 거리 모형을 사용하지 않는다.

`CampaignInstallSupport`는 기존 같은 SP 저장소의 Rotate를 실제 회복 추적 전역에 연결한다. 실제 `RawPlayerRegular`와 `RawPlayerTemplateState`를 동일9 Player/로딩 깊이/State 섹션에 연결한다. 다른 부모의 미복원 Regular는 예외를 반환한다. TYPE 보충 표는 보호 속성 `range`, `height`, `hpPerSec`, `theme`, `delayBetweenShots`와 같은 프레임 Run을 사용한다. 보호 썬 디스크 발사기는 range9/hpPerSec15이고 별도 대기 속성이 없으며 원문은 애니메이션이 발사 간격을 제어한다고 설명한다. 초기 자기 동맹 마스크는 검사에서 명시 입력한다.

신전 가상8c에서 WORD+12가0인 레인/윈드/썬더 신전은 각 `{12,29,12,23}`, `{39,30,33,34}`, `{27,0,28,30}`의 inset으로 본그림의 일부만 갱신한다. 오른쪽/아래 inset은 뺀다. 실제 사각형 보조는 표시 억제를 먼저 검사하고, viewport의 각 모서리를 독립 clamp한 뒤 양의 면적만 flags0으로 등록한다. 이 경로는 선택 확장/그림자 갱신을 추가하지 않는다. WORD가 비영점이면 실제 기본88을 사용한다. 패치 썬 신전8c는 기본88의 thunk다.

## 단위19 Factory SetState 교정

단위19는 가상+88을 상태 프레임 보정으로 오인했다. 두 PE의 실제 가상 표 및 wrapper는 다음과 같다. 과거 보고서/원본 fixture는 변경하지 않고 이 절로 교정한다.

| 기능 | 10.78 | 10.72 | 실제 처리 |
| --- | --- | --- | --- |
| Gun 방향 | 004d4d00 | 00443110 | 현재 Graph 또는 signed FrameCode 방향 |
| Factory +84 | 00475290 | 0042b230 | baseLevel 저장 후 가상88 표시 |
| Factory 기본88 | 004ad500 | 004ae380 | 공통 표시 갱신 |
| Factory Handle +5c | 004549c0 | 0047ac20 | 사건별 프레임/반환 후 Damageable |
| 신전 부분 사각형 | 00499240 | 00456c10 | 본그림 inset/clip/dirty |

Factory `SetState`는 `RawSquidLevel::Set` 다음 실제 표시 갱신을 호출한다. 상태 프레임 보정은 기존 PostPop의 별도 helper에 그대로 남긴다. 새 독립 원본 상태 입력은 frame이 변하지 않고 표시 요청 당시 Level BYTE가 이미 바뀌었음을 검사한다.

Factory 사건1은 기존 `RawFrameAdvance(1,0)`에 연결한다. 사건2는 현재 Level의 첫 프레임+동일 게임 난수 Next(현재 구간 길이)를 실제 지정기에 전달한다. 사건4는 count가 비영점이면0을 반환한다. 패치 사건5는 Level0~2에서 추가 효과 없이 공통 반환이며 Level3 이상 입자효과는 아직 명시 미연결이다. **CD는 사건5 분기 자체가 없다.** 큰 upgrade 사건3은 아직 명시 거부다.

## 독립 원본 PE와 C++ 비교

최종 새 fixture에는 **1,412고유 입력**을 기록했다. 기존 원본 입력과 실험 재실행을 재합산하지 않는다.

| 최종 fixture | 10.78 | 10.72 | 비교 범위 |
| --- | ---: | ---: | --- |
| campaign-frame-x86.tsv | 378 | 386 | 방향 반환, Factory 상태/예약 반환, raw 전체, 난수, 표시 요청 순서 |
| vortex-display-x86.tsv | 324 | 324 | 실제 파생8c/공통88/사각형/dirty 변경표 전체, raw 불변 |

원본 정상 반환은 총1,412회, 원본 assert는0이다. 합성 TYPE/FrameCode/SHP/카메라/슬롯을 사용한 독립 PE 명령 실행이다. 방향/Level/Handle/난수/Advance는 실제 명령을 실행한다. Factory Frame 지정/표시 요청은 명시 외부 경계이며 C++ 소비자는 기존 실제 Frame/Advance와 같은 풀을 사용한다. 신전 검사는 실제 bounds/dirty까지 실행한다. CD의 atexit 함수 포인터 등록만 명시 외부 경계이며 종료 callback은 실행하지 않는다.

실험의 실패 원문/로그는 `run20-compile`, `run20-fail1`, `run20-nfail1`, `run20-nfail2`, `run20-regression`, `run20-delay`에 보존한다. 새 관찰 형식/해시 단계 입력을 바꾸기 전 전체 fixture/보고서/생성기는 `run20-native1/2/3`에 보존했다. 첫 합성 Handle 입력은 현재 해시 단계 BYTE를0으로 두어 실제 C++ Frame 지정이 재Pop을 요구했다. 최종 입력은 명시1칸/표시 지정 경계와 같은 해시 단계1을 제공한다. 원본 기대값은 PE를 다시 실행하여 얻었다.

신전 첫 C++ 비교는 실제 Renderer의 변경표 병합을 적용하지 않아 실패했다. 기존 `DirtyRegions`를 같은 sink에 연결하여 교정했고 원본 fixture는 바꾸지 않았다. 발사 대기가 양수라는 새 검사 가정도 보호 썬 디스크 발사기 원문 확인 후 교정했다.

## 실제 캠페인 전체 프레임 검사

등록된 프로세스를 선택적으로 건너뛰지 않고 동일 Kernel 순서로1/60초씩 진행했다. 실제 `.fort`/TYPE/프레임/SHP를 읽고 동일 설치·Player·SP·사제·간헐천·신전·거주 구역·총·팩토리 예약을 실행한다.

## 빌드와 회귀 검사

최종 Release 로그는 `extracted/run20-build20.log`다. 새 집중6검사는 `run20-focused13.log`, `run20-nfocused5.log`, `run20-vfocused4.log`에서 모두 통과했고 표시 주소 소비자 집중1검사도 통과했다.

첫 전체 CTest는 내부1,116개 중 **실패 체크7**이다. 새 신전8c 지원7개를 기존 공통 표시 전용 mask와 비교한 소비자에서만 실패했다. 원본151행 fixture/주소/공통 mask는 변경하지 않고, 실제 복원한 파생 함수 주소7개만 소비자 기대 지원 범위에 추가했다. 실패 당시 전체 로그/소스도 보존했다. 첫 CTest 도중 후속 테스트 링크를 시도한 작업은 실행 파일 점유로 LNK1104가 발생했다. 해당 로그를 보존하고 CTest 종료 후 재빌드했다.

최종 전체 CTest는 **1/1 통과, 내부1,116개/실패 체크0, 188.85초**다. 최종 Release 경고/오류는0이다. 전체 로그는 `extracted/run20-all2.log`다. `tools/check_campaign20.py`는 최종 빌드/집중/전체 로그·Native/fixture·보존본·보호 PE·현재 전체 소스/바이너리 SHA와 신규 C++ 전체 원문을 `run20.json`에 고정한다.
