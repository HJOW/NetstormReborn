# 가장자리 스크롤 (전체화면에서 커서를 화면 끝에 대면 카메라 이동)

> 분석일: 2026-09-29. 기준: 보유 `Netstorm.exe`(10.7x 패치판)의 정적 디컴파일·역어셈블(`capstone`).
> 위치: 메인 프레임 함수 `FUN_004d62b0` 안 `004d65de`~`004d67ad`. 동적 분석으로 확인하지 않은 항목은 "미검증"으로 표시했다.

## 동작 조건

가장자리 스크롤은 아래 조건을 **모두** 만족할 때만 동작한다 (`004d65de`~`004d6624`).

| 조건 | 원본 코드 | 의미 |
|---|---|---|
| 설정 `edgeScroll` ≠ 0 | `[005318f8]` (`00441270("edgeScroll")` 로 등록, 보유 `setup.cfg` = 1) | Options 의 `Edge Scroll in Fullscreen` 체크 |
| 창 테두리 오프셋 = 0 | `[005c7904] == 0 && [005c7908] == 0` | 아래 "창 테두리 오프셋" 참고. **전체화면(또는 바탕화면과 같은 크기라 테두리를 없앤 창)에서만** 참 |
| 열린 팝업 메뉴 없음 | `[00565dd4] == 0` | 우클릭 메뉴 등 팝업이 떠 있으면 스크롤하지 않는다 |
| 왼쪽 마우스 버튼이 눌려 있지 않음 | `FUN_00452e00(상태, 0x10000)` → `GetAsyncKeyState(VK_LBUTTON)`, 결과 비트31 = "눌려 있지 않음" | 드래그 중에는 스크롤하지 않는다 (미검증: 비트 극성은 코드 해석) |
| 모달 창(`0x4000` 플래그) 없음 | `FUN_004641d0()` | 있으면 스크롤하지 않고 가속 시각도 초기화 |

AGENTS.md(2026-10-03 문구 변경)도 원본이 **"옵션에서 해당 기능을 켰을 때"** 가장자리 이동을 지원했다고 적는다. 위 표의 첫 조건(`edgeScroll`, Options 의 `Edge Scroll in Fullscreen`)과 같은 내용이다.

`FUN_00452e00` 은 입력 상태 읽기 함수다. `GetAsyncKeyState`·`GetCursorPos`·`GetWindowRect` 로 커서 위치를 창 안쪽 좌표(테두리 오프셋 제외)로 바꾸고 **0..화면 폭/높이 로 자른다**. 결과 비트 `0x4000000` 은 "커서가 창 밖이거나 앱이 비활성"이다. 가장자리 스크롤 코드는 이 비트를 따로 보지 않으므로, 창 밖 커서는 자른 좌표 때문에 가장자리로 판정될 수 있다 (전체화면에서는 의미 없음).

### 창 테두리 오프셋 (`FUN_004a4fe0`, `004a5xxx`)

화면 모드 전환 함수는 `DAT_005c7904`·`DAT_005c7908`(창 클라이언트 영역의 좌·위 오프셋)을 다음과 같이 정한다.

* **전체화면**: 둘 다 0.
* **창 모드**이면서 `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 이 게임 해상도와 같음(바탕화면 = 게임 해상도): 테두리 없는 창(`WS_POPUP`)으로 만들고 둘 다 0.
* 그 밖의 창 모드: `SM_CXSIZEFRAME` + 캡션·프레임·메뉴 높이로 **0 이 아님** → 가장자리 스크롤 비활성.

동봉 패치 문서(`docs/sources/README.md` 10번)의 "전체화면 또는 640×480 창 모드에서만"은 이 규칙의 결과다 (원본 시대 바탕화면이 640×480 이었던 경우).

## 가장자리 판정

커서 좌표 `(mx, my)` 는 위에서 자른 클라이언트 좌표, 화면 크기는 `DAT_005c78f0`(폭)·`DAT_005c78f4`(높이)다.

| 방향 | 조건 | 비고 |
|---|---|---|
| 왼쪽 (x = −1) | `mx < 2` (코드는 `mx <= 1`) | |
| 위 (y = −1) | `my < 2` **그리고** `FUN_00464020(DAT_005cad24) == 0` | `DAT_005cad24` = 화면 맨 위 **게임 메뉴 막대**(Game·View·Options·Players·About, 생성 함수 `004cc210`)의 ID. 메뉴 막대가 열려 있으면 위쪽 스크롤은 하지 않는다 |
| 오른쪽 (x = +1) | `mx >= 폭 − 1` | |
| 아래 (y = +1) | `my >= 높이 − 1` | |

* 가장자리 폭은 **1픽셀**(맨 바깥 두 줄)이다. 커서를 화면 끝까지 밀어야 한다.
* 두 방향이 모두 0 이면 가속 시각을 "없음"(`[005cafc8] = 0.0`)으로 되돌린다.
* **모서리(대각선)**: Shift(`FUN_00452e00(상태, 0x100000)` → `VK_SHIFT`)를 누르고 있으면 한 축만 남긴다 — 두 축 절댓값을 비교해 x 가 y 보다 크면 y 를 0 으로, 아니면(같은 경우 포함) x 를 0 으로 만든다. Shift 를 누르지 않으면 대각선 스크롤이 된다 (미검증: 비트 극성은 코드 해석).

## 속도

* 처음 가장자리에 닿은 시각을 `[005cafc8]` 에 기억한다 (게임 시각 `[0055b4d8]`, 초 단위 `double`).
* 매 프레임: `v = (현재 시각 − 시작 시각) × 30.0 + 2.0` (상수 `[00501708] = 30.0`, `[00506590] = 2.0`), `속도 = min(edgeScrollSpeed, 정수로 자른 v)`.
  * 시작 속도 **2**, 초당 **+30** 씩 늘어나 `edgeScrollSpeed`(보유 `setup.cfg` = **35**)에서 멈춘다. 35 에 닿는 시각 ≈ 1.1초.
* 이동량 = `자른(속도 × 방향)` 픽셀을 카메라 객체(`[0059a8bc]`)의 `FUN_00497e00` 에 넘긴다. 이 함수는 카메라 **목표 위치**(`+0x50`, `+0x54`)를 **현재 위치(`+0x1c`, `+0x20`) + 이동량**으로 설정한다.
* 이 코드는 화면 루프마다 한 번 실행되므로 **속도의 단위는 "프레임당 픽셀"** 이다. 화면 루프 상한은 `maxFPS = 75` (보유 `setup.cfg`, [animation-timing.md](../videos/animation-timing.md)) → 상한을 그대로 곱하면 35 × 75 = 2,625 픽셀/초지만, 원본의 프레임 제한은 밀리초 눈금 시계로 재므로 실제 루프는 14ms 간격(초당 약 71.43바퀴)이고 최대 약 35 × 71.43 = **2,500 픽셀/초**다([main-loop.md](main-loop.md) 4절, 2026-10-05). 원본 실제 속도는 PC 성능과 시스템 타이머 해상도에 따라 달라진다.

## 클론 구현 기준

* 클론은 프레임 수에 흔들리지 않도록 **초당 픽셀 = 프레임당 픽셀 × 71.43**(원본 루프의 실제 속도 1000 / 14, `FramePacing.OriginalFramesPerSecond`. 2026-10-05 에 75 에서 변경)로 환산하고, 속도 곡선(2 → +30/초 → 상한 `edgeScrollSpeed`)과 1픽셀 가장자리, 전체화면 한정 조건을 그대로 쓴다. 코드: `Netstorm.Core.Display.EdgeScrollController`.
* "테두리 오프셋 = 0" 조건은 클론에서 **테두리 없는 화면(전체화면 또는 화면 전체 창)** 여부로 표현한다. 일반 창 모드에서는 켜지지 않는다.
* 위쪽 가장자리 예외(게임 메뉴 막대)는 클론에 메뉴 막대가 생기면 `TopEdgeBlocked` 입력으로 연결한다. 현재 개발용 뷰어에는 메뉴 막대가 없어 항상 위쪽 스크롤이 가능하다.
* 창 밖 커서 자르기 동작은 재현하지 않는다 (창 밖 커서는 스크롤하지 않는다).

## 클론 구현 검증 (2026-09-29)

* 단위 테스트 `tests/Netstorm.Core.Tests/EdgeScrollTests.cs`: 1픽셀 가장자리 판정, 조건별 비활성, 메뉴 막대 예외, Shift 한 축, 속도 곡선(2·3·17·32·35), 초당 환산.
* **실제 전체화면 확인**: 1920×1080 테두리 없는 전체화면에서 커서를 놓은 채(0, 540) 시작해 15프레임 뒤 스크린샷을 찍으면 지도가 왼쪽으로 크게 이동했다. 시작 직후 MonoGame 이 로딩 시간을 따라잡는 갱신이 한 번에 몰려 0.75초 안팎(갱신 47회)이 지난 상태였고, 곡선 합계 ≈ 779 논리 픽셀 ↔ 스크린샷 측정 ≈ 775 논리 픽셀로 일치했다. 오른쪽 아래 모서리는 대각선으로 스크롤되어 월드 끝(뷰어가 카메라를 월드 안으로 제한)에 멈춘다.
* 창 모드에서는 스크롤하지 않는다 (`BorderlessScreen = false`).

## 동적 확인 (사용자 보고, 2026-10-03)

사용자가 원본 게임(10.78)을 직접 조작한 경험에서 **"화면 가장자리에 커서를 두면 화면이 이동하는 기능은 전체화면일 때만 동작한다"**고 알려 주었다(창 모드와 전체화면을 어떤 조건에서 비교했는지는 듣지 못했다). 위의 "창 테두리 오프셋 = 0" 조건(창 모드에서는 오프셋이 0이 아니므로 꺼짐)과 일치한다. 이 확인은 영상 증거가 없는 사용자 보고이며, 창 모드 30FPS 녹화([노트](../videos/record-play-edit-test01-20261003.md) §4.0)에는 가장자리에 커서를 둔 구간이 없다. 같은 날 전체화면 녹화는 없다.

## 남은 확인 (동적 분석)

* 왼쪽 버튼·Shift 상태 비트 극성 (`GetAsyncKeyState` 결과 변환) — 원본 실행 중 드래그·Shift 조합으로 확인.
* 카메라 목표 위치가 실제로 화면에 반영되는 방식(즉시 이동인지 보간인지)과 맵 가장자리 제한.
* 실측 프레임 수에서의 초당 이동 픽셀 (60Hz 모니터·`maxFPS = 75` 상한 상황).
