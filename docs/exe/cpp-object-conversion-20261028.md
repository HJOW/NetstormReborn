## 공통 타입 변경과 원문 대조

새 `SquidFactory::Retype`은4b1620→4af720의 void 진단22d→footX 진단22e→footY 진단22f→TYPE BYTE→현재 타입 생성자 순서다. 새 SID를 할당하거나 postCreate/postTake를 실행하지 않으며 HP·소유자·zOrder를 초기화하지 않는다. 진단이 복귀하면 원문처럼 계속하고, 선택된 미연결 진단/생성자는 앞선 쓰기를 보존한 채 실패한다. 예약/free/dead 슬롯을 추가로 제외하지 않는다. CD10.72 대응은4ab6b0/4ab770이며 이번 구현은10.78만 받는다.

`RawObjectConversion`은 비석에서 Unpop 뒤 현재 QA를 TYPE로 바꾸고 그 TYPE+118 기본 프레임을 직접 쓴다. 주문에서는 Unpop 뒤 TYPE를 보관해 비석으로 바꾸고 frame0→이전 TYPE를 QA WORD에 쓴다. 이어서 같은 좌표로 Repop한다. 두 원문은 release를 별도 거부하지 않으며 다른 명령은4ae010 부모로 전달한다. 일반 UI의 Editor 노출 조건을 객체 명령에 추가하지 않았다.

`tools/decomp_object_conversion.py`는 **타입 변경128입력·가상 입력36입력, 고유164개 정상 반환**을 확보했다. 기존 TSV를 바꾸지 않는 `--verify` 재실행도164개 모두 같았다. void/free/dead·foot 진단 조합, constructor0 fallback, release 플래그, 부모 반환, Unpop 경계 뒤 TYPE/QA 변경을 포함한다. 공간 Unpop/가상Pop·공통 부모 입력·진단은 명시 외부 경계이며 타입 변경/생성자/QA/실제41c0d0 위임은 기계어를 실행했다. 전체50BYTE·효과 순서·반환값과 코드 이미지 불변을 기록했다. 게임/창/OS나 공중 공격3종을 실행하지 않았다. [원문 보고서](../../cpppj/object-conversion-native-20261028.json)와 `squid-retype-x86.tsv`·`object-conversion-x86.tsv`를 본다.

## 실제 Edit의 전환·저장·재적재

최종 같은 제품의 **1280×720·1024×768 두 실행**에서 새 주문→비석→주문→비석→Yes 저장→Edit 재진입→다시 주문을 통과했다. 각 최초 Session의 SID15432·소유자1·위치는 세 전환 중 유지됐고, 일시 range 표시를 제외한 다른3351개 객체의 TYPE·소유자·좌표도 유지됐다. 각 실제 팝업의 Form 참조·명령030000ce·대상 SID·활성과 창 활성1을 확인했다.

재적재 후 새 SID15000의 중립 비석을 같은 위치에서 선택해 Devastation114가 복원됐다. 비석은 원본 Fort의 owner 저장 마스크에 없어 재적재 시 owner0이며, Session 내 owner 보존과 구별한다. 별도 Fort 판독기도 두 저장 파일3416BYTE의35섹션·남은 바이트0·비석3개와 QA `[114,114,114]`를 확인했다. 저장 후 마지막 전환은 다시 저장하지 않았다. `tools/cpp_object_conversion_smoke.py`는 화면비마다 동일한 입력 사본과 형제 Editor 작업본을 따로 사용한다.

원래 캠페인의 중립 비석88,119도 별도 실행에서 같은 SID15021·위치·owner0을 유지하며 Devastation으로 전환됐다. 이 경우의 남아 있는 Regular/후속 애니메이션까지 새 주문 사례와 동일한 상태라고 합산하지 않는다.

검사 도구의 초기 시도는 세 가지 잘못된 전제를 드러냈다. 덱 선택 뒤 배치 위치로 이동하는 입력을 먼저 주지 않으면 현재 커서 위치/적법성의 관측이 달랐다. 저장 후 비석을 내 객체 전용 selector로 찾으면 owner0 때문에 실패했다. 전환 뒤 전체 객체 수 불변을 요구하면 메뉴의 일시 range8개 때문에 실패했다. 최종 도구는 실제 위치의 버튼 올림→배치 클릭, 재적재한 중립 위치 클릭, range를 제외한 기존 객체 필드 비교를 사용한다. 원문 상태/메뉴 활성이나 제품 판단을 검사 통과용으로 바꾸지 않았다. 중간 실패를 최종 두 성공에 합산하지 않는다.
