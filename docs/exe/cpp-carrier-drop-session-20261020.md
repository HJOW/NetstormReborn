## 검증과 한계

기존 독립 원문 `carrier-drop-x86.tsv`의 **413입력·826정상 반환·107290명령**과 생성 도구를 변경하지 않았다. 이 원문의 최초 수집 호스트 VM-W11-Codex는 보존 이력이며 현재 정밀 디컴파일 호스트와 구별한다.413입력 제품 비교 한 개가 최종 바이너리에서 통과했다. 이 원문은 하위 효과를 경계로 두므로 Session 전체를 증명하지 않는다.

새 Session 검사 두 개는 실제 `thewarbegins.fort`를 읽고 골렘과 Devastation 내용물을 실제 월드에 만든다. 시험 입력으로 SP를 지정하고 이미 연결된 로컬 전송을 사용한다. 요청 직후 수신·주문 생성이 없고 Flush/Poll 후 실제9BYTE 패킷을 수신하여 주문·493·활성화 예약·QA·소유자를 만드는지 확인했다. SP 한 번 차감, 선택 해제, 팝업 요청, 부모 좌표·공간 복귀, 내용물 보존, SP 부족 시 송신·팝업·493 미생성도 확인했다.

실행 기록은 `extracted/goal-carrier-drop-session-20261020-` 접두이며 집중2개와 기존 네이티브 집중1개가 통과했다. 전체 회귀 결과와 바이너리 해시는 `cpppj/carrier-drop-session-cpp.json`에 고정한다. 현재 소스 핀 **116보고서·297항목**을 갱신했고 새 핀과 이력을 되돌렸을 때 시작 HEAD와 의미가 같음을 확인했다. HEAD의 LF/CRLF 표현을 모두 대조하여 현재 경로 핀을 찾았으며 과거 실행·바이너리·원문 이력은 유지한다. 전체 검사 후에는 설명 주석을 고친 `RawCarrierDrop.h`의 CRLF만 LF로 맞췄다. 코드 내용과 바이너리는 그대로이며 전후 해시를 `staging-newline.json`에 보존했다.

구형 `cpp_carrier_drop_native_audit.py`는 이번에 변경하지 않은 소스 네 개와 자기 도구의 LF/CRLF 해시 차이 때문에 종료1이다. 이들 파일은 HEAD와 텍스트가 같음을 별도로 확인했다. 당시 다른 PC의 원시 실행 자료11개도 이 PC에는 없다. 이 옛 감사의 기대값과 누락 자료를 새로 합성하지 않았다. 실패 로그와 줄바꿈/누락 목록을 `legacy-audit1`·`legacy-newlines` 기록으로 보존한다. 현재 사용할 수 있는 독립413행/동결 도구·보호PE·현재 Session 실행은 새 `cpp_carrier_drop_session_audit.py`가 별도로 감사한다.
