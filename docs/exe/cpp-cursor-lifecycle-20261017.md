# 커서 취득·취소·임시 객체 수명 복원

2026-10-17, `HJOW-Athlon`. 마지막 전체 정밀 디컴파일은 같은 PC의 2026-10-16 산출물이다. 원본 파일과 디컴파일 소스는 수정하지 않았다. 원본/클론 게임이나 GUI 창은 실행하지 않았다.

## 이번 범위와 다음 연결

사제 메뉴 `RawPriestMenu::SelectBuild`의 성공 결과는 건설된 건물이 아니라 실제 Contained Form이다. 지금까지 이 Form을 넘길 `00447000(form,0x160)`은 외부 경계였다. `RawCursorLifecycle`이 원본 취득 `00447000`, 취소 `00446e70`, 임시 표시 객체 정리 `00445aa0`를 복원한다. 내려놓기의 기존 `CursorDropState`를 직접 빌리며 중복 잠금·Form·입력 WORD·비용 flags·커서 프로세스 상태를 만들지 않는다.

이번 조각으로 실제 UberGump의 Construct를 활성화하지 않았다. `00445b30`의 임시 객체 생성, `00445440` 위치/비용 판정, `004458e0` 위치 준비, 기본 객체 메뉴, MenuGump의 실제 Client 트리/입출력, 일반 건설 확정/배치가 남아 있다. 상위 연결이 이 계산들을 비어 있는 콜백이나 고정 성공으로 대체해서는 안 된다. 다섯 경고 문구와 비용 측정의 복원은 실제 건설 위치가 적법하다는 증거가 아니다.

## 원본 근거

`tools/decomp_cursor_lifecycle.py`는 보호 10.78 PE를 Unicorn의 별도 주소 공간에서 읽어 세 몸체와 실제 CRT `_ftol`을 실행한다. 실제 게임·OS 호출은 없다. 두 x87 정밀도(`027f`, `037f`)에서 **565고유 입력·1,130정상 반환·차이0**이다. 새 `cursor-lifecycle-x86.tsv`를 기존 커서 내려놓기2,058행과 구별해 보존한다.

실제 기계어의 `004470b9 mov eax,[esp+18h]`는 함수 두 번째 인자 `flags`다. 디컴파일의 `unaff_retaddr`는 잘못된 인자 추론이다. 마지막 `004472fb jmp 00446b50`는 두 입력 인자 칸을 현재 마우스 좌표로 덮어쓴 뒤 수행하는 cdecl 꼬리 호출이다.

565입력은 일반/다리/보텍스/배터리 TYPE flags, Form의 기존 WORD, 기본 프레임과 명시 프레임, 마나/범위 프로세스의 덮어쓰기, 음수·NaN·큰 비용, signed 그림 치수, 잠금·dead Form·부모 flags, 강조/준비 콜백 뒤 현재 전역 재조회를 포함한다. 각 입력의 **78DWORD, 비용 문자열, raw3슬롯150바이트, 전체 가상 효과/측정 인자 순서**를 저장한다. TYPE/SHP/프로세스/합성 가상 표 포인터는 명시 호스트 식별값으로만 정규화한다.

가상 source/통지/해제·소멸, 위치 준비/판정, 임시 객체 생성, 마나/범위 생성, 번역·글자 측정, sprintf는 명시 외부 경계다. 이 경계의 실제 게임 계산까지 원문으로 증명했다고 합산하지 않는다. 비정상 프레임/TYPE 진단,30칸 초과 및 차단된 텔레포터는 정상565입력 밖의 보호 경로다.

## 처리 순서와 공유 상태

- 취득은 이전 취소 → 팝업 정리 → Form/type/기본 인자 저장 → 기존 WORD 저장과0x100 설정 → source 가상+24 → 입력 flags/다리0x200 → 잠금0 → 임시 생성 → 커서 선택 → 마나/범위 → 판정 → 다섯 문구와 비용 치수 → 현재 마우스 꼬리 호출 순서다.
- 취소는 잠금0/미리보기 존재에서 강조 뒤 깊이를 재조회한다. 기존 WORD를 복구하고 BYTE0x80이면 source 가상+48/+4c를 실행한다. 비용 flags0x100이면 Form을 삭제하며, 아니면 source 가상+24로 반환하고 BYTE0x80 비용을 원본 순서로 차감한다. 끝에서 임시 객체와 마나 프로세스를 정리한다.
- 임시 정리는 먼저 실제 준비를 호출한다. flags0x200 또는 force에서 현재 signed 개수/각 SID를 다시 읽어 가상 삭제하고30칸을 지운다. 강제 정리는 잠긴 취소에서도 실행한다.
- `BindCursorLifecycle`은 기존 사제 선택과 내려놓기의 activate/invalidGui를 같은 수명 몸체에 묶는다. `BindCursorLifecycleAssets`는 실제 `.type` 기본 프레임, 같은 SHP의 물리프레임3 추가 헤더와 `GumpText` 측정기를 사용한다. 현재 저장소와 수명 경계의 조립이며 실제 UI 자동 연결은 아니다.

## 검증

두 Release 빌드는 종료0·경고0·오류0이다. 집중 검사3개가 통과했고 전체 CTest는 **내부1,456개 전부 통과·227.15초·종료0**이다. 원본565입력의 모든78DWORD/문자열/raw150바이트·효과 순서가 일치했다. 공유 어댑터/누락 경계·판본/범위 보호와 실제 보호 자산·기존 글꼴 측정 연결도 검사했다. 첫 집중 검사 실패는 dead 입력 슬롯을 다음 행에서 다시 초기화하지 못한 테스트 준비 코드였고 입력 전용 접근으로 교정했다.

새565행·기존 커서 내려놓기2,058행·필요 에너지2,352행의 SHA 감사가 통과했다. 기존 사제 메뉴 감사 도구는 이 PC에 과거 별도 내보내기 `extracted/priestmenu/originals/creation.c`가 없어 실패했다. 과거 보고서와 기대값은 보존했고 사제 메뉴의329/64/512 원문 C++ 검사는 모두 통과했다. 현재 전체 정밀 산출물은 같은 PC의 것으로 유지했다.

로그 접두사는 `extracted/goal-cursor-lifecycle-20261017-`이며 `ctest-output.log`에 내부 전체 결과를 보존했다. 새 보고서에 검증한 제품 소스의 SHA도 기록했다. 공유 CMake2개는 필요 에너지 보고서의 이전/현재 핀과 통합 이력만 갱신했다. 기존 기대값을 구현에 맞춰 재생성하지 않았다. 모든 실행 핸들은 종료했다.
