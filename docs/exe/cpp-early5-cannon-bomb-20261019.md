# Early5 전진 캐논의 실제 공격과 훨리기그 폭탄 삭제

2026-10-19 단위213. 기준 `9c07d58c`, 현재/마지막 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-19**다. AGENTS와 양 LEFT를 재독했고 같은 PC의 보호 PE/정밀 분석을 재사용했다. AGENTS의 최신 단계 순서는 LEFT 맨 위에 이미 반영돼 있다.

## 실제 배치와 실패 이력

산출물 접두는 `extracted/goal-early5-forward-20261019-`다. 기존 실제 A→D 입력을 유지하고 전진 다리·제네레이터·캐논을 실제 메뉴/마우스로 건설한다. 시간·자금·HP·미션 단계를 주입하지 않는다.

- ui1은 생산 메뉴 재열기 입력이 실패했다. ui2는 실제75생산 부재와 B단계/미션 화면 조건을 만족할 때만 메뉴를 다시 여는 입력으로 수정했다. 자연 D와 전진 제네레이터139,102 HP700·SP1700을 관측했고, 타워137,109 뒤 캐논 탐색이 합법24/사격0으로 실패했다. `forwardGenerator2`라는 보고 이름은 실제 두 번째 건설을 뜻하지 않는다. 새 객체/자금 차감이 없어 한 개로만 센다.
- ui3은 같은 조건부 준비에서 캐논을 타워보다 먼저 배치하도록 순서를 바꿨다. 제네레이터139,105 HP700까지 진행했으나 합법27/사격0으로 실패했다.
- ui4는 같은 `plan3.tsv`를 추가 진단이 들어간 빌드로 재생했다. 실제 전진 제네레이터137,104를 건설하고, **썬 캐논137,110 SID15132**를 배치했다. SP1700→1300, 배치 순간HP0에서 다음 보고 때 **HP600**으로 완공됐다. 이때 적 **썬더 캐논136,126 SID15006의 HP가1000→958**이었다. 새 스톤 타워138,101은 아직HP0·SP900이었다. 뒤에 `캠페인 다른 실제 자산 가상 삭제 미연결 TYPE163 SID3629`로 종료1이었다. 이를 전투 완료나 Early5 완주로 세지 않는다.

실제 프레임/생산 조각/다리 모양이 실행마다 다르다. 진단 코드가 ui4 성공을 만들었다거나 순서 변경만으로 사선 문제가 항상 해결됐다고 주장하지 않는다. 추가 진단은 이미 실패한 자동 사격 좌표 탐색에서 합법 후보의 MayShoot/MayTarget·표적 발자국·네 방향 사정선을 기록할 뿐 기존 후보 순서/배치 판정/공격 규칙은 바꾸지 않는다. ui4는 탐색이 성공해 추가 실패 로그를 실행하지 않았다.

요구 에너지 설명에서 `.level=1`을 내부level1로 읽고 썬 캐논에 두 개가 필요하다고 한 것은 잘못이었다. 로더가1을 빼므로 내부level0이며 범용`s` 한 개다. 기존 독립 fixture `type-required-energy-x86.tsv` 행191의 내부level0/theme3도 `73`이다. 내부level1의 `7373`을 이 캐논의 요구로 사용하지 않는다. Wind 공급은 범용`s`를 충족할 수 있다. 제품/원본 기대값을 바꿔 설명 오류를 덮지 않았다.

## 보호 PE의 삭제 경로

실제10.78 TYPE163 생성자 **0045d2a0**는 슬롯에 **00509b98**을 쓴다. 이 가상 표의 +10은 **004af780**, +14는 **004b0950**, +18은 **004b0840**, +48은 **004afe50**이다. 모두 기존 복원된 공통 삭제/전처리/후처리/Unpop 몸체다. 폭발음/큰 효과를 추가하는 별도 Bomb 전처리0041e960/VT00502370으로 보내지 않는다.

Session의 기존 Bomb 수명 분배기에 **TYPE163/VT00509b98의 정확한 쌍**을 추가했다. 일반 Bomb 속성 비트와 별개로 이 전용 그림 자산을 인정하며, 다른 타입/미확인 가상 표를 포괄 허용하지 않는다. 같은 World/Pool의 공통 수명을 재사용한다. 실제 `RawSunFlyerFrame::ClearBomb`는 기존대로 삭제flags10h를 전달한 뒤 +96을0으로 만든다.

새 정적 관측기 `decomp_sun_bomb_lifetime.py`는 기존 독립 생성자 fixture의 주소로 보호 PE를 읽어 대입 명령과 네 가상 진입을 별도 fixture에 보존한다. **두 행은 정적 관측이고 정상 반환 횟수는0**이다. 기존 기계어 destroy/Pre/Post/Unpop fixture는 수정하지 않는다. CD10.72 TYPE163은 별도로 **004990f0→005050f0**, +10=004ab7e0/+14=004add20/+18=004adbe0/+48=004ad0b0을 기록했으며, CD 실행 복원이 완료됐다고 해석하지 않는다.

## 검증 진행

실제 Session 회귀는 보호 Tutorial5 스크립트가 지정한 fort를 로드하고 원래 Factory로163을 생성한다. 공간에 떠 있는 경우와 이미 빠진 경우에 각각 실제 전용 ClearBomb→World.Destroy를 실행하고, 전체 네 단계 공간 해시·점유 지도·Kernel 수·SP·공통 수명 중첩 깊이가 복구되는지 확인한다. 최초 검사 입력에서 미션 이름을 fort 파일 이름으로 잘못 가정한 `d/tutorial5.fort`를 사용해 파일 없음으로 실패했다. 이 실패를 `bomb-focused1.*`에 보존하고 보호 미션 스크립트의 실제 FortPath/FortName을 읽도록 고쳤다. 제품/PC 문제로 취급하지 않는다.

Release build2/3은 경고·오류0이다. 최종 집중1검사 실패0/0.384초, **전체1732검사 실패0/341.355초**다. 동일 검사 실행 파일 SHA-256은 `be4bddce04ae74f2848903bd8aa7ce49d2a4d425f0dda71540581d8e1bdd22b1`이며 실행 원문·이전 잘못된 입력 실패·빌드 로그를 각각 보존했다. 새/기존 정적 폭탄 관측 재생, 기존 훨리기그410입력 및 별도 Bomb 전처리96입력의 출처 검사도 통과했다.

수정 후 앱 `75d3eef765a7a81837e6b2c6155855c9ff36d9c91ebf3b2c3501dc5204a20841`의 ui5는 같은plan3에서 합법31/사격0으로 캐논 배치 전에 실패했다. 요청136,110의 place0/source1이며 해당 사선 영역에 실제 다리 타일이 있었다. ui6은 다리 목표만136,114→132,112로 옮긴plan4지만 합법25/사격0·요청desc0/place0/source1로 실패했다. 이때 전진 제네레이터136,105는 배치 보고 순간HP0이다. 캐논 취득 직전 보고가 없어 그 순간 제네레이터 완공/공급까지 확인한 것으로 세지 않는다. 두 재생 모두 종료1·원본 전체 불변·설정 복구이며 수정 후 자연 폭탄 정리가 관측됐다는 주장을 하지 않는다.

기존 **81보고서/157현재 핀**만 기준 일치분을 이전 값/이력과 함께 갱신했고, 새 이력과 핀을 메모리에서 되돌리면 모든 기존 JSON이 HEAD와 의미적으로 일치했다. 원래 방송/생산/적 베이스 선택 출처 검사도 통과했다. 새 저장 관측 검사기 `cpp_sun_bomb_lifetime.py`와 보고서 `cpppj/sun-bomb-lifetime-runtime.json`은 현재11소스/85근거 파일을 고정하고, ui4의 캐논 완공·적 피해와 TYPE163 오류, ui5/6의 실제 배치 실패를 별개로 요구한다. 이전 원본 기대값/실행 파일 해시를 새 실행 값으로 바꾸지 않았다.

원본 게임 실행·새 디컴파일·보호 원본/AGENTS/dotnetpj 변경·push는 없다. 이 단위는 **실제 캐논 피해 관측·정확한 폭탄 삭제 연결과 회귀 검사** 범위에서 완료하며 `20261019-21 CP`로 커밋한다. 목표는 계속 active다. **Early5 자연 E/F/완료 및 나머지 지정 미션의 플레이/동일성은 미완료**이며 실패 원인을 PC/파일시스템/모델 용량으로 단정하지 않는다.
