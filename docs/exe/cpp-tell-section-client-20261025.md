# Tell 섹션 선택과 이전 이름 기록 — 2026-10-25

단위408은 원본10.78의 `4cf730` 중 파라미터 처리 뒤의 이름 기록과 본문 선택을 실제 Tell 경로에 연결한다. 현재/마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 새 전체 디컴파일과 원본/클론 GUI 실행은 없다. 이번 `/goal` 재개 요청으로 단위407의 일시 중지는 해제되었다. 전체 목표는 미완료다.

## 변경과 실제 경로

[TellSection](../../cpppj/src/client/TellSection.cpp)은 좁은 이름을 지역 문자열에 복사하고 현재 이름과 대소문자를 무시하여 비교한다. 이름이 달라지면 먼저 `global.priorTell`을 쓴 뒤 현재256BYTE의 첫NUL까지 새 이름을 복사한다. 콜백이 현재 이름을 바꿔도 지역 이름은 유지하며 NUL 뒤의 기존 바이트는 지우지 않는다. 실패한 조회도 이름 기록은 남는다.

첫 점이 있으면 **등록된 Config 객체의 이름/점 뒤 섹션**을 찾는다. 없는 접두어를 파일 이름으로 적재하지 않는다. 점 뒤가 비어 있어도 이 조회를 생략하지 않는다. 없을 때는 **현재 미션에서 점을 포함한 전체 이름**을 찾고, 마지막으로 **새 `tell` Config를 만들고 현재 `missionSpec(tell)` 파일을 적재**해 조회한다. 빈 본문이 존재하면 성공으로 간주하므로 다음 소스로 넘어가지 않는다. 임시 tell은 본문을 소유 문자열로 복사한 뒤 실제 Registry에서 반납하며 기존의 장기 tell 객체와 구별한다.

[UberGump::TryTell](../../cpppj/src/client/UberGump.cpp)은 같은 실제 `param` Config의 수명 안에서 이 처리를 호출한다. 이전의 접두 파일 강제 적재와 캐시된 tell 본문 폴백을 교체했다. 빈 입력을 BLANK와 합치던 조기 처리도 제거했다. 원문처럼 BLANK 조기 분기는 파라미터를 해석하기 전의 이름에만 적용한다. 원래의 오류 진단·기존 페이지 표시/입력 어댑터는 이번 교체 범위 밖이다.

[ClientHtmlWindowGlobals](../../cpppj/src/client/ClientHtmlWindowGlobals.h)에 현재 Tell 이름을 두어 표시 부모/미션/지역 Config가 반납되어도 같은 Client 상태가 유지된다. 이름 객체 조회는 원문 `43fb90`처럼 **먼저 등록한 객체**를 고른다. 값 치환의 **나중에 등록한 객체 우선**과 다르며 기존 Config 코드는 변경하지 않았다.

## 독립 원문 관측과 검증

[관측 도구](../../tools/decomp_tell_section.py)는 보호 PE의 실제 `4cf730..4cf95e` 정상 본체를 격리CPU에서 실행했다. 파라미터 처리 뒤의 이름 선택 부분을 **429입력×두 정밀도=858행**으로 투영했다. 현재 이름256BYTE 전체 지문, 선택한 본문/빈 본문/없음, 이전 이름 쓰기와 조회 순서가 C++와 같다. 이전 이름 쓰기 콜백이 현재 이름과 미션 존재 상태를 바꾸는 경우도 포함한다. 두 정밀도 차이0이며 `--check` 재생은 fixture를 쓰지 않는다.

[신규5검사](../../cpppj/tests/TellSectionTests.cpp)는 원문858행과 실제 Config 등록부 우선순위·없는 접두어의 미션 폴백·빈 본문·매번 새 파일 적재/임시 객체 반납·실패한 이름의 이력·지역 파라미터 수명·물리 범위 거부를 확인한다. 첫 두 결합 실행은 이름 조회에도 최신 등록 객체가 우선한다고 가정한 새 검사의 기대값이 틀려 실패했다. 기존 원문43fb90/Config의 전방 순회를 확인하고 실제 첫 등록 본문과 LF 보존을 검사하도록 고쳤다. 제품 Config 동작을 검사에 맞춰 변경하지 않았다.
