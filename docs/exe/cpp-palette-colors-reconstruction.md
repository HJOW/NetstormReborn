# 파일 팔레트의 전체 색 표 복원

2026-10-10, **HJOW-Athlon**. AGENTS.md·두 LEFT_JOBS 문서를 먼저 읽었으며 현재/마지막 디컴파일 PC가 일치했다. 새 `palettecolors` 목록 **2/3/3개**를 읽기 전용으로 내보냈다. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-10**. 원본 게임·분석 프로그램은 실행하지 않았다.

파일 팔레트를 읽을 때 원본 로더가 만드는 기본 9색과 전체 색 표를 복원했다. 10.78은 **58개**, CD/10.37은 **50개**의 RGB 검색을 수행한다. 날씨 네 색은 이 결과의 별칭을 그대로 복사한다. 1024바이트 파일의 예약 바이트를 버리던 문제도 고쳤으며, RGB COL이 앞 팔레트의 예약 바이트를 유지하는 원본 동작을 구현했다.

## 원본과 구현

| --- | --- | --- | --- |
| 파일 로더 | `004a4850` | `00424760` | 파일 크기별 읽기·전체 적용·기본/전체 색 검색·날씨 별칭 |
| 가장 가까운 색 | `004a2820` | `004246e0` | 논리 팔레트의 기존 독립 대조 검색 몸체 |

| 기본색 배열 | `0054d928` | `00539570` | PE 초기 개수 9·필요할 때 할당·이후 재사용 |
| 날씨 별칭 | `005b5da8..b4` | `00549b40..4c` | 기본 노랑/파랑/빨강·갈색 결과를 복사 |

[`PaletteColors`](../../cpppj/src/client/PaletteColors.h)는 기본색·날씨 별칭·전체 검색 순서의 목표 RGB와 색 번호를 저장한다. [`PaletteColors.cpp`](../../cpppj/src/client/PaletteColors.cpp)의 각 항목에 결과를 저장하는 원본 전역 주소를 적었다. 용도 미확정 항목에 GUI 역할을 임의로 붙이지 않았다. 같은 RGB를 여러 전역에 저장하는 흰색·회색·청록 항목도 별도로 남겼다. CD판에서는 10.78이 추가한 여덟 검색만 제외한다.

[`Screen::LoadPalette`](../../cpppj/src/client/Screen.cpp)는 저장 팔레트 적용 뒤 전체 색 표를 계산한다. `Screen::Colors()`는 마지막 파일 로딩의 결과이며 번개의 일시 부분 적용·복구와 `SetMode`의 재적용으로 다시 계산하지 않는다. `ClientMain`의 초기/날씨 팔레트와 해상도 변경 복사는 선택 판본을 전달한다. `ClientAudio`에는 저장된 `Colors().weather`를 공급한다. 기존 `WeatherTints()`는 현재 논리 팔레트를 검색하는 계산 도우미로 유지한다.

## 파일 형식과 예약 바이트

- **776바이트(`0x308`) COL:** 첫 8바이트는 건너뛴다. 256색의 R/G/B를 각 저장 RGBQUAD의 +2/+1/+0에 읽으며 **+3 예약 바이트는 쓰지 않는다**. 앞 팔레트의 예약값을 유지한다.
- **1024바이트(`0x400`) BGRX:** 256 RGBQUAD를 통째로 읽는다. **네 번째 바이트도 파일 그대로 보존**한다.
- 원본 전체 적용은 0번을 검정, 255번을 흰색으로 강제하고 두 끝점의 예약값을 0으로 만든다. 논리 PALETTEENTRY는 R/G/B/플래그이며 내부 플래그는 4, 끝점은 0이다. 예약 바이트는 색 거리나 논리 플래그로 쓰지 않는다.
- 파일 형식 판별은 크기 기준이다. 안전 C++ API는 다른 크기를 거부한다. 원본의 잘못된 크기/assert 이후 경로를 그대로 실행하지 않는다.

## 독립 원본 관찰

[`decomp_palettecolors_oracle.py`](../../tools/decomp_palettecolors_oracle.py)는 세 실제 PE의 **전체 정상 파일 로더와 모든 색 검색 몸체**를 제한 x86으로 실행한다. 새 독립 입력 **24개**(8×3), 두 x87 정밀도에서 로더 전체 진입/정상 반환 **48회**, 색 검색 진입/정상 반환 **2,528회**다. 단색 동률·회색·임의 색·중복 정확 색, 두 형식, 기존 기본색 배열 유무와 예약 바이트를 조합했다. 색 검색 반환값·원본 전역의 최종 값·기본 배열·날씨 별칭·저장/논리 팔레트 바이트를 실제 관찰했다.

파일 열기/크기/seek/read/닫기·9색 메모리 할당은 합성 경계다. 전체 `SetPalette`는 기존 논리 팔레트/끝점 계약을 공급하는 명시 경계로 대체했다. **로더의 채널별 저장·기본/전체 검색·별칭 대입은 실제 명령**이다. 실제 GDI/DirectDraw·파일 장치·게임 호출은 0이다. 화면 지우기 인자 0의 정상 경로만 대상이며 실패/assert·전체화면 지우기·SEH 예외 처리는 범위 밖이다.

보존 레지스터·스택·SEH·x87 균형, 허용 실행/쓰기 범위, 파일 소비량·호출 수·입력 순서·SHA를 감사한다. 기존 fixture/근거 도구는 변경하지 않았다. 전체 근거 감사 **84종 통과**, 새 입력 포함 누적 **455,386개**다. 내보낸 소스와 실행 로그는 Git 제외 `extracted/palettecolors/` 및 `extracted/palettecolors-*.log`에 있다.

[`PaletteColorsTests.cpp`](../../cpppj/tests/PaletteColorsTests.cpp)는 24개 원본 관찰과 전체 RGB/색 번호·기본/날씨 배열·예약 바이트를 대조한다. 추가 검사에서 일시 번개 뒤 파일 색 표 유지, BGRX→COL의 예약값 보존, CD판 해상도 복사의 전체 색 표/예약값 유지를 확인한다. 최종 빌드/전체 검사와 창 회귀 수치는 [LEFT_JOBS.md](../../LEFT_JOBS.md)의 최신 절을 따른다.

## 남은 범위

전체 색 표의 **각 GUI 소비자/역할**, 원본 팔레트 갱신 표시의 소비, tint 후속 효과, raw 번개 부모 수명과 실제 전체화면 표시는 남아 있다. 네 날씨 COL은 보존 자료에 없으므로 [합성 COL 창 검사](cpp-weather-palette-integration.md)가 원본 날씨 RGB 재현을 증명하지는 않는다. 월드 효과음 호출자/SoundProcess·건설·경제·전투·AI·승패도 남았으며 **미션 완주는 아직 불가능하다**.
