# 생산·지식 하위 메뉴와 회수 조건 (단위915)

UI1번의 실제 워크샾 생산/지식 슬롯과 회수 메뉴를 검증했다. 새4개와 기존19개, 최종 고유23사례가 통과했다. 제품 소스는 바꾸지 않았고 실행 파일은913/11.01이다.

## 원문과 실제 상태

현재/마지막 전체 정밀 디컴파일 호스트는 **HJOW-Athlon / 2026-11-03**이며 정밀 산출물은 수정하지 않았다. PATCH004752b0은 생산 bit16의 내용물을 순서대로 표시하고 같은 종류는 슬롯을 한 번만 차감한다. 금지된 종류도 슬롯/Deck에 들어간다. 004540d0은 현재 전역 Deck에 생산 중인 후보를 숨기고, 생성 제외 목록은 include에, 남은 슬롯은 enabled에 적용한다. 후보가 있지만 모두 제외된 창과 모든 후보가 생산 중인 완료 안내는 다르다. 0044cbd0 및 공통 회수 부모의 소유자/편집/금지/확인 조건도 대조했다.

원문453b50은 부모 통지에서 플레어 뒤 **첫 일치 하나만** 검색해 자신이 아닌 클라이언트 내용물만 지운다. 클라이언트 중복 제거 후 순서1만 남으면 새 서버 내용물이 빈 순서0에 먼저 삽입된다. 첫 검색이 자신을 가리켜 뒤의 클라이언트 항목은 남으며, 후속 서버 중복까지 세 행이 한 슬롯을 사용한다. 이 경우를 모두 찾아 지우는 동작으로 바꾸지 않았다.

CD0042b270도 생산 bit16/종류별 한 번 차감·허용 표/Deck 구별을 유지하며 raw stride는0x24다. 대응 부모 통지0047a6c0을 정적으로 기록했다. 실제 메뉴 검사는 PATCH 전용이고 CD UI를 실행하지 않았다.

## 검증한 UI

보호 자산·Client·GameWorld/Session·실제 내용물 생성/부착/부모 통지/Deck 재계산·VT 메뉴·Gump/StyleText와 controlled 입력 큐를 사용했다. 하위 메뉴는 실제 Gump idle로 확장을 마친 뒤 클릭한다. 게임 Kernel이나 공격/생산 시각은 진행하지 않는다. 음향·시계·dump·설정/안내 장치는 현재 Client와 명시 출력 관측 장치다.

- 네 테마 워크샾에서 비생산 내용물, 중복 생산2개, 서로 다른2종/3종의 네 상태를 누적했다. 현재 생산/지식 메뉴를 각각 다시 열어 **32메뉴**에서 각 행/TYPE·슬롯2/1/0/−1·테마 후보를 확인했다. About12클릭과 양수 슬롯의 지식8명령/0·음수 슬롯의 비활성8클릭을 확인했다. 서버 내용물은 **pfDONT_TRANSMIT(0x40)** 으로 부착하며 연구 요청은 실행하지 않는다.
- 예측 중복 정리와 서버 순서 빈자리의 별도 사례에서 첫 클라이언트 항목 반납, 현재 순서0/1/2·세 행 표시/슬롯 한 칸 사용을 **2메뉴**에서 확인했다.
- 허용 금지/생성 제외/모두 생산 중의 **3메뉴**에서 현재 생산의 빈 안내와 Deck 포함, include가false인 빈 하위 메뉴, 비활성 완료 안내 클릭을 구별했다.
- 제네레이터75·썬 캐논128·워크샾85·원래 미션의 신전124·간헐천122의 owner0/1/2/8 × editor0/1 × DenySalvage0/1, **80메뉴**를 확인했다. 직접 회수의 SID와 DenySalvage/SalvageInf/SalvageVortex의 정적 섹션 인자를 실제 클릭 큐에서 대조했다. 원래 신전의 섬/QA를 유지하고 소유자를 복원하며 새 검사 대상만 반납한다.
- 새 최종 실행은 **117메뉴**다. 각 메뉴를 닫으면 원래 대상 바이트·Form 링크·풀 수량이 보존된다. 실제 회수/업그레이드/연구 요청과 포획/희생·공격 효과는 실행하지 않는다. 명시 상태 입력이며 자연 상태 도달·물리 입력/픽셀 동일성의 증거는 아니다.

## 실패 이력과 수락

첫 세 실행은 설정 reader 누락, 잘못된 client Pop/신전 섬 입력, Gump 확장 미진행, 클라이언트 예측 중복을 서버 중복으로 간주한 기대, 용량0인 제외 목록에 Append한 입력 오류를 드러냈다. 현재 Client 설정 reader·실제 로딩 구간/원래 미션 신전·Gump idle·서버 내용물·목록 저장 용량으로 교정했다. 네 번째는 잘못된 서버 attachFlags0에서 Form 전송 앞 client SID 진단2회가 나서 0x40 부착으로 교정했다. 전송/수신 테스트로 확대하지 않았다. 다섯 번째의 새 순서 빈자리 사례2단언은 원문 첫 검색과 실제 순서0/1/2를 확인해 세 행 기대를 명시했다. 기존 검사 기대/fixture는 바꾸지 않았다.
