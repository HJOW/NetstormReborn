# Fiery Tail 실제 프레임·색 조회·선 요청 복원

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 단위98은 보호10.78 TYPE11의 `004580f0` 프레임과 `004583a0` Draw를 `RawFieryTailFrame`으로 복원했다. 실제 게임·GUI와 새 디컴파일은 실행하지 않았다. CD10.72는 이번 대조에 포함하지 않았다.

## 프레임과 출력 동작

원본 `0041bfb0`은 같은 SID 풀에서 부모를 읽고 head가0이 아님을 확인한다. 부모 raw x/y에 현재 픽셀 배율을 곱해 float로 저장한다. 최초 호출은 timer 초기화·표시 영역/직전 좌표 설정·10입자 방출을 수행하고 돌아온다. 이때 수명 감소와 dirty 제출은 없다. 최초 방출은 좌표 offset을 더하지 않는다.

다음 호출은 `00418470`의 최대0.05초 조각마다 입자2개를 먼저 추가하고 **용량 전체**의 양수 수명을 감소시킨다. 사용 꼬리 밖에 active 입자가 있어도 처리하며, 감소 후 죽은 입자도 이번 영역에 포함한다. 사각형은 시간 조각 사이에 초기화하지 않는다. 각 조각에서 이전 영역과 누적 새 영역을 차례로 dirty 소비자에 제출하고 직전 부모 좌표를 갱신한다. 같은 시각의0간격 호출도 두 입자를 방출한다.

원본 timer의 넓은 시간 차이 비교, 간격 float 저장,10배 delta와 배율 적용 scaledDelta 저장 순서를 보존했다. 경과 시각에는 저장한 float delta를 double로 더한다. 나머지 시간이 있으면 최대 조각을 더하며 따라잡고, 마지막 조각은 현재 시각으로 맞춘다.

각 방출은 **Y 난수→X 난수→Append** 순서다. 용량이 부족해도 두 난수는 소비한다. Append는 꼬리 여유가 있으면 그 위치를 먼저 쓰고, 꽉 찼으면 첫 수명<=0 슬롯을 재사용한다. NaN은 재사용하지 않는다. 좌표와 수명 외의 속도/마지막 DWORD는 바꾸지 않는다.

정적 메모의 “픽셀 출력”을 더 구체적으로 바로잡았다. 실제 Draw는 점 출력이 아니라 **입자의 카메라 적용 좌표에서 호출자가 준 부모 화면 끝점+offset까지의 선**을 `004dade0`에 요청한다. 사용 수까지만 순회하고 양수 수명만 표시한다. 입자 좌표의 `__ftol`과 끝점의 signed32비트 감김, 반환 색의 전체 DWORD를 보존했다. 실제 픽셀 래스터화는 이번 몸체의 외부 소비자다.

`005318ec == 2` 분기는 색수를0x17655, 최대 수명을0x315a로 바꾼다. 의미를 화면 모드로 추측하지 않고 입력 전역과 실제 쓰기로 보존했다. 이때도 제공된 색 메모리 밖은 읽지 않는다.

## 독립 원본 대조

`tools/decomp_fierytail_frame.py`는 현재 정밀 함수표의11개 실제 몸체만 허용한다. Frame/Draw·부모 조회·timer·난수·Append·영역 포함·SetRect·색 조회·`__ftol`은 실제 PE 코드를 실행한다. **dirty 큐 소비 `00499310`과 선 래스터 `004dade0`만 요청 관찰 경계**다. heap/생성자·공통 등록·Host/Kernel은 이 실험에서 실행하지 않았다.

- 고유 입력은65개다. 용량0/1/2/10/12/120, 최초/후속, 꼬리 여유/가득 참, 양수/0/음수/NaN/무한대 수명, 같은 시각/여러 시간 조각, offset/카메라/배율/난수 시드, 진단2와 끝점 감김을 포함한다.
- 두 x87 정밀도 `027f`·`037f`에서 **Frame130회·Draw130회 정상 반환, 결과 차이0**이다. 같은 입력의 두 설정을 고유 입력 수에 중복 가산하지 않는다. 원본 CRT의 기본53비트 설정은 [색 띠 검증](cpp-particle-gradient-20261016.md)의 실제023f 초기화 증거를 따른다.
- 원본 객체의 의미68바이트, 용량 전체의24바이트 입자, 색수/읽기 메모리, 최종 난수 상태, 순서대로 발생한 dirty/선 인자를 보존했다.
- 반환 ESP·비휘발 레지스터·x87 제어어/TOP/tag·스택 sentinel과 쓰기 범위를 확인했다. 부모 슬롯과 색 메모리 및 객체의 포인터/미사용 필드 불변도 검사했다.
- 프레임 내 실제 timer306회·난수1504회·Append752회·SetRect306회·색 조회572회가 실행됐다. 외부 dirty612회·선572회는 요청 개수이며 새 고유 입력 수로 더하지 않는다.

C++ 기본53비트65행은 모든 의미 필드·입자·난수·dirty/선 요청과 처음부터 일치했다. 별도 경계 검사는 최대 수명의 인접 색 DWORD가 없으면 선을 제출하기 전에 거부함을 확인한다. 이 검사 준비 단계의 잘못된 SID 풀 크기128을 원본 고정 경계를 담는32768로 바로잡은 후 집중2검사가 모두 통과했다. 제품 알고리즘의 기대값을 바꾸거나 실패를 숨기지 않았다.

Release 전체 빌드는 경고0·오류0이고, 최종 전체 CTest는 **1418개 중1416통과·기존2실패, 203.75초, 종료8**이다. 실패는 데모1의145프레임/3.625초 TYPE148 stage5 애니메이션과 데모3의113프레임/2.825초 TYPE128 effect11 사전 검사이며 새 실패는 없다. 색 띠48행·사정선4040입력·필요 에너지2352행과 새 프레임65입력의 SHA/고유 입력 감사도 통과했다. 필요 에너지의 공유 CMake2개 유효 해시는 변경 전후 이력과 함께 갱신했으며 기존 제품/원본2352행은 바꾸지 않았다.

## 인접 메모리와 실제 연결 경계

원본 색 조회는 `min(life,maximum) × float(count) × float(1/maximum)`을 절삭한다. 수명==최댓값이면11색의 **배열 다음 DWORD**를 읽는다. 독립 검증은 읽을 수 있는 인접64개 DWORD를 명시 입력으로 공급하고12번째에0xabcdef01을 넣어 실제 색 번호/선 요청을 대조했다. 이 값은 실제 게임 heap 관찰 결과가 아니다. 제품도 읽을 수 있는 span을 명시로 받고,11색만 공급되면 예외를 낸다. 마지막 색으로 clamp하거나 가짜12번째 색을 만들지 않는다.

따라서 이번 완료는 Frame/Draw 몸체와 출력 요청 수준이다. 재개 후 작업은 다음과 같다.

1. 실제 생성자/공통 등록·120입자 zero·공유11색 할당/소멸을 현재 Host/Kernel과 연결한다.
2. 정상 첫 Draw에서 읽는 인접 DWORD의 실제 allocator/실행 근거를 확보한다.
3. 같은 공통 표시 목록·수집/정렬·dirty 큐·실제 VFX 선 래스터에 연결하고 픽셀을 검증한다.
4. 생성 순서(표시 Pop→effect11→Missile 부착)를 보존한 Session에서 데모3의113프레임 이후를 검증한다.

이번에는 Session의 `flightEffect`를 채우지 않았다. 효과 등록/표시·실제 데모 진행·사용자 자연 완주를 완료로 세지 않는다. [전체 연결 인수인계](cpp-fierytail-notes-20261016.md)를 따른다.

원본 보고서는 `cpppj/fierytail-frame.json`, 기대값은 `cpppj/tests/fixtures/fierytail-frame-x86.tsv`다. `python tools/decomp_fierytail_frame.py --verify`로 보호 PE·정밀 범위표·도구/호출 균형 검사·기대값의 SHA와 고유 입력을 확인한다. 로그 접두사는 `extracted/goal-fierytail-frame-20261016-`이다. 보호 원본·AGENTS.md·dotnetpj는 수정하지 않았다.

사용자가 이번 작업까지 끝내고 문서와 git 커밋을 마친 뒤 목표를 정지하도록 요청했다. 단위98 문서/인수인계와 `20261016-35 CP Fiery Tail 프레임과 선 요청 원본 대조` 로컬 커밋까지 마친 뒤 목표를 일시정지하며 다음 연결 단위는 시작하지 않는다. 목표 달성/자연 완주 완료로 처리하지 않는다.
