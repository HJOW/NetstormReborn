## 확인한 차이와 수정

실제 UberGump는 F6을 별도로 처리해 `ShowTechnology`를 예약하고 반환했다. 이 위치는 `UserInput`의 공통 정지 조회보다 앞이어서 정지 중에도 F6이 지식 창을 열 수 있었다. 원문 `004d96b6`은 먼저 `00460de0`의 현재 정지를 검사하고, 그 뒤 `004d9a00..004d9a22`에서 F6의 Shift/Control을 거부한 다음 현재 `00542974`를 두 인자0/0으로 예약한다. Alt는 별도 거부하지 않는다.

F6를 기존 `DispatchSelectionKeyInput`에 추가하고 UberGump의 앞선 예약 분기를 제거했다. 실제 UserInput이 사용하는 같은 공통 정지/명령 조회/입력 큐에 연결하므로 Home/F4/F5와 같은 부모 경계를 따른다. 이미 예약된 일반 `ShowTechnology` 명령과 메뉴의 창 열기는 유지한다. F9/ShiftF9는 원문 `004d95d1..004d960c`에서 정지 검사 **앞**에 예약하므로 함께 옮기지 않았다. 정지 해제에 쓰는 기존 ShiftF9의 수명도 유지한다.
