## 도구와 빌드

| 도구 | 확인한 버전 / 위치 |
| --- | --- |
| CMake | 4.4.4 |
| 빌드 생성기 | Visual Studio 17 2022 / Build Tools, MSBuild 17.14.60 |
| Ghidra | 12.1.4 PUBLIC, `C:/Tools/ghidra_12.1.4_PUBLIC` |
| Java | Temurin OpenJDK 21.0.12.1 |
| Python | 3.12.4 |
| 분석용 Python 의존성 | `extracted/oracle-python`의 pefile 2024.8.26·Capstone 5.0.7·Unicorn 2.1.4 |
| 이미지 처리 | Pillow 12.3.0 |

기존 관찰 도구는 `extracted/oracle-python`을 Python 검색 경로 맨 앞에 넣는다. 기본 Python에서 바로 `import unicorn`하면 모듈을 찾지 못하지만, 기존 도구와 같은 경로에서는 실제 모듈 가져오기가 성공한다. 버전은 설치 메타데이터 대신 실제 가져온 모듈의 `__version__`과 `__file__`을 기록했다. 기본 경로의 Capstone과 격리 경로의 버전이 다르므로 후속 분석도 기존 도구의 경로 설정을 유지한다.

다음 명령의 **Release 증분 빌드가 종료 코드 0, 경고·오류 출력 0**으로 완료됐다. `NetstormCpp.exe`를 만드는 대상만 지정했다.

```powershell
cmake --build cpppj/build --config Release --target NetstormCpp --parallel
```

실행 파일은 `cpppj/build/bin/Release/NetstormCpp.exe`다. 이번에는 테스트 추가·실행, 격리 PE 실행, 원본/클론 게임 및 GUI 실행을 하지 않았다. 기존 단위31의 테스트 결과를 이번 작업의 새 실행으로 세지 않는다.

현재 PC의 정적 확인 자료는 Git 제외 경로인 `extracted/cpp-prep-20261015-audit.py`, `extracted/cpp-prep-20261015-audit.json`, 빌드 로그 `extracted/cpp-prep-20261015-build.log`에 있다. 원본, AGENTS.md 및 사용자 수정 `TODO.md`는 보존했다.

## 다음 cpppj 분석에서 사용할 근거

현재 실제 클라이언트의 `UberGump::BeginMission`은 Battle 미션에서 `NotImplemented`로 반환한다. 단위29의 `MakeCampaignClientServices` 생성부도 아직 이 경로에서 소비하지 않는다. 사전준비 완료는 Battle 플레이나 Early Missions/1-1~1-2 완주 동일성의 완료를 뜻하지 않는다.

1. 내용물 부모 가상 `+0x24`는 실제 VT별로 분배한다. PATCH의 `0041c100`, CD의 `00401c20`은 빈 몸체지만 워커·다이스·워크샾·Player의 파생 통지는 별도로 복원해야 한다. 초기 캠페인의 레인/윈드 신전은 실제 빈 기본 몸체를 사용한다([단위30](cpp-run30-20261015.md)).
2. PATCH 사제 피해의 소유자 통지 `00416760`은 challenge 모드·owner 번호·현재 Player 기록의 `+0xb0` AI 포인터를 확인하고 `00415460`을 호출한다. 현재 세션과 같은 실제 Player 저장소에 연결해야 한다.
3. **`00416760 ↔ CD 004aaa20` 자동 대응은 채택하지 않는다.** 대응 점수는 `callers/medium 0.458`이지만 CD `004aaa20`은 두 인자를 최근 삭제 표식 전역 `005395d4/005395d8`에 쓰는 별개 함수다. CD 사제 피해 `0040cb10`의 실제 호출 대상은 `004d89b0(owner, victimSid, attackerSid)`이며, 이 함수는 `004d81f0(owner)`로 AI를 조회한 뒤 자체 피해 반응을 수행한다. PATCH의 래퍼와 AI 몸체가 CD에서 같은 함수 경계로 나뉜다고 가정하면 안 된다. 이번 확인은 기존 최종 C의 정적 호출 관계를 읽은 것으로, 해당 피해 경로를 새로 실행·대조한 결과가 아니다.
4. fencemark 표적 코너, Ready/login, 생산·건설·경제·AI·승패 및 실제 UI 연결의 미완료 항목은 `LEFT_JOBS.md`에 유지한다. Battle 차단 해제는 이 실제 하위 경계를 연결하면서 진행한다.

다른 PC에서 다시 시작하거나 이 PC의 정밀 산출물이 없어지면 [재생성 절차](decompile-vmw11-20261015.md)를 따른다. 일부 함수만 추가로 내보낼 때는 현재 정밀 프로젝트를 지정한다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/ghidra/export_functions.ps1 -Name <함수목록이름> -Refined
```

생성 소스를 바꾸면 작업 문서와 LEFT_JOBS.md에 마지막 디컴파일 PC를 갱신한다. 현재 마지막 정밀 디컴파일 기록은 **VM-W11-Codex, 2026-10-15**를 유지한다.
