## 문맥과 배치

TextContext는 `flags,font,color,style,extra,shadowColor,shadowX,shadowY` 순서다. 정상(+`104`)·눌림(+`124`)은 플래그 2, 기본 글꼴/스타일 0, 흰 글자와 검정 그림자 (1,1)를 쓴다. 비활성(+`144`)은 플래그 0과 검정 글자를 쓴다. 원본은 extra와 비활성 그림자 필드를 모두 초기화하지 않는다. **안전 C++ API는 읽지 않는 필드를 0으로 준비하며 원본에서 항상 0이라는 주장이 아니다.**

두 상태 +`a0`/+`a4` 중 하나라도 0이 아니면 눌림 배치다. 플래그는 +`ac`의 낮은 바이트이며 비트 8은 외곽선 생략, 비트 1은 비활성 문맥 우선이다. 비활성이어도 상태가 설정되면 위치 계산은 눌림이다. 일반 UI 입력에서는 비활성 버튼이 누름을 받지 않는다.

사각형 `(L,T,R,B)`의 외곽선은 끝점을 포함해 다음 순서로 그린다.

1. `(L+1,T)` → `(R-2,T)`
2. `(L+1,B-2)` → `(R-2,B-2)`
3. `(L,T+1)` → `(L,B-3)`
4. `(R-1,T+1)` → `(R-1,B-3)`

이후 `(L+1,T+1,R-1,B-2)` 사각형에서 글자 폭/높이를 뺀 크기를 2로 나누고 정상은 `(2,1)`, 눌림은 `(3,2)`를 더한 상대 위치를 쓴다. 중간 정수 덧셈/뺄셈은 DWORD 감김, 음수 나눗셈은 0 방향 절삭을 유지한다. [`DrawGumpLines`](../../cpppj/src/client/GumpVisual.cpp)는 역방향·끝점·화면 밖 클리핑을 처리하고 출력 때만 DWORD 색을 8비트로 좁힌다.

## 독립 원본 관찰과 검사

[`decomp_gumpvisual_oracle.py`](../../tools/decomp_gumpvisual_oracle.py)는 세 실제 PE의 **전체 정상 생성자와 Draw 몸체**를 제한 x86으로 실행한다. 새 독립 입력 **192개**(64×3), 두 x87 정밀도에서 생성 **384회**·그리기 **384회**, 전체 정상 반환 **768회**다. 상태 둘, 낮은/높은 플래그, 외곽선 생략, 음수/홀수 크기, DWORD 감김과 임의 DWORD 색을 조합해 문맥 바이트·선 순서/끝점·글자 위치/선택 문맥을 관찰한다.

GUI 기반/자식 생성·할당·가상 부착·부모 사각형·선/글자 래스터만 명시 경계다. 생성 입력은 **75×19, 라벨 null, 기본 문맥**이고 Draw의 글자 크기/사각형/상태는 별도 공급이다. strncpy·사용자 문맥·할당 실패·SEH 예외, 전체 좌표 변환·배경 자식·실제 원본 OS 창은 범위 밖이다. 0으로 준비한 객체의 비사용 필드를 원본 고정값으로 해석하지 않는다. 게임/OS 호출 0이다.

스택·보존 레지스터·SEH·x87 균형, 실행/쓰기 범위, 진입/정상 반환·경계 수·입력 순서·SHA를 감사했다. 기존 84종과 새 근거 **85종 모두 통과**, 저장 입력 누적 **455,578개**다. [`GumpVisualTests.cpp`](../../cpppj/tests/GumpVisualTests.cpp)의 새 검사 **4개**는 192개 원본 관찰, 두 판본의 파일 색 표/동률·일시 적용 유지/다음 파일 변경, 선 클리핑/끝점/겹침과 잘못된 입력 거부를 검증한다. 기본 CTest에는 원본 파일·Unicorn·Ghidra가 필요 없다.

[`cpp_gumpvisual_smoke.py`](../../tools/cpp_gumpvisual_smoke.py)는 보존 원본 자료와 검사 사본 두 팔레트로 클론 창을 순차 실행한다. 같은 프레임 **14상태·14화면**, 버튼 계획 **81개**, 선/글자 **32,220픽셀**을 실제 10.78 몸체와 독립 `.chfnt`/SHP 해독에 대조했다. 외곽선 번호 15와 사본 번호 37/73을 확인했고 사본의 비활성 누름은 화면 바이트를 바꾸지 않았다. 81개 화면 계획은 저장 입력 192개에 합산하지 않는다. 질감/안쪽 명암·원본 게임 전체 화면 일치를 증명하는 검사가 아니다.

UI 스크립트는 사건만 주입하고 후속 폴링이 바탕 화면 커서를 읽어 눌림 그림이 취소되는 문제가 있었다. `Client::inspectPoll`과 `--ui-script`의 마지막 마우스 입력으로 사건·폴링 좌표/왼쪽 버튼 상태를 맞췄다. 실제 커서를 움직이지 않으며 공급자가 없는 일반 실행은 Win32 폴링을 따른다. 누름/취소/비활성 창 시나리오와 기존 메뉴/월드 회귀에서 검증했다.
