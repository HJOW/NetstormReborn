# 실제 Edit의 손상 파일 정리와 재선택 (단위665)

원본10.78의004b5ca0은 잘못된 파일 뒤 즉시 종료하지 않는다. 현재 Template의+8 저장 억제DWORD를1로 쓴 뒤004bf690으로 반납하고, 다시 현재 owner의+8을0으로 쓴다.29번 진단을 기록한 뒤00460bf0으로 현재 기본 이름과 비교한다. 같으면 현재 경로를 다시 읽어 제거하고,00460c20으로 전체 기본 이름을 선택한 뒤 최초 존재 검사로 되돌아간다. 이 반복을 실제 Edit에 연결했다.

## 구현과 경계

`InstallEditorFortFile`은 기존 부재 파일의 NewFort child와 유효 파일의 State/Subscriber/config/title 꼬리를 공유한다. 손상 분기만 실제 헤더/반납·Client29번 로그·현재 newFort 조회 뒤 CRT 비교·작업본 삭제·전체 이름 선택을 사용한다. 반복 상한이나 임의 정상 반환은 넣지 않았다. 반납 예외는 이미 쓴+8=1을 보존하고 후속 로그/이름 선택을 실행하지 않는다.

Session의 파일 callback은 최초 보조 사본이 반납된 뒤에도 현재 파일의 raw 섹션을 같은 loader로 읽는다. 새 파일을 미리 전체 파싱하지 않는다. 최종 정상 파일의 현재 manager와 이름은 World/저장 꼬리에 그대로 이어진다. 실제 호스트 삭제는 기존 EditorFiles 작업 namespace만 사용하며 보호 원본을 수정하지 않는다.

기존 `InstallExistingEditorFile`/`InstallPresentEditorFile`의 한정 관측 API는 유지한다.004bd340의 정상0과 해당 진단 계약을 다른 헤더의 demo flag로 바꾸지 않는다. 일반 전투/MP의 이 부모 소비자, 전체 FILE/예외 ABI, 실제 GUI 전환 전체가 완료된 것은 아니다.10.72의 반복 부모는 이번 추가 대조 범위가 아니다.
