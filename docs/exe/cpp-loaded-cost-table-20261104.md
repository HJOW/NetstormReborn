## 원문 근거와 구현

PATCH 공통 후처리 `004b0d30`의 기계어 `004b0e72..004b0e97`은 현재 raw TYPE로 `0059ab50[type]`을 읽고 번호*23을 뺀 정수에 현재 누적값 `0059508c`를 더해 저장한다. 현재 TYPE+c4 float를 다시 인코딩하지 않는다. 별도 비용표는 `0049c2e0`의 로딩 종료 루프가 `ftol(cost+번호*23)`으로 채운다. `004b4900`의 TYPE+c4 float 쓰기와는 다른 저장소다.

기존 `SquidPostPop::TotalCost`는 현재 TYPE 대여 뒤에도 float 비용을 다시 읽어, 필드 변경이 별도 캐시까지 바뀐 것처럼 동작했다. PATCH는 생성 시 비용 사본 또는 명시 최초 로딩 표를 읽도록 바꿨다. 현재 등록 플래그·genus·발자국 조회는 기존 현재 TYPE를 유지한다. CD float 비용 경로·기존 ftol/비유한·물리 범위·거대 비용곡선 한계는 그대로다.

`SquidPostPop`과 `SquidReward`에 `BindLoadedCosts`를 추가했다. 실제 World는 `RawSurfaceStorage::Source()->TypeTable().Types()`, 실제 Session 보상은 `assets.game.TypeTable().Types()`를 비용 전용으로 빌린다. 이 불변 GameAssets 표는 현재 World TYPE와 별개이므로, 같은 장기 TYPE를 변경한 뒤 World/Session을 교체해도 변경값으로 비용 캐시를 다시 만들지 않는다. HP·플래그는 계속 실제 현재 표를 읽는다. 다른 판본/길이는 기존 대여를 바꾸기 전에 거부하며 빈 span은 생성 시 비용 사본으로 복귀한다. GameAssets 없는 독립 구성에서 별도 최초 표를 원하면 명시 대여한다. 대여 표는 처리기보다 오래 살아야 하고 변경/재할당할 수 없다.
