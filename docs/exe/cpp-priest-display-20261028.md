# 사제 보호막 기준점과 제단 내 포획 사제 색상 (단위541)

사용자는 다른 PC에서 캠페인1-1을 완주하고 다음 스테이지 안내창을 확인했다. 그 과정에서 적 사제가 원형 보호막 안의 왼쪽에 치우치며, 포획한 적 사제를 **제단에 넣은 뒤** 파랑 플레이어의 사제처럼 보인다고 제보했다. 해당 실행의 PC·커밋·실행파일 SHA는 제공되지 않았다.

이번 작업은 정적 분석·Release 빌드·장치 없는 C++/픽셀 검사다. 실제 게임 실행이나 스테이지 완주는 하지 않으며, 수정 후 실제 플레이 검증은 사용자가 추후 담당한다. 현재 PC와 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**으로 일치하고 디컴파일 산출물은 변경하지 않았다.

## 원인과 수정

- 원본10.78 공통 Draw `00498220`은 TYPE의 `+1dc/+1e0` 발 기준점을 뺀다. `priest.type`과 `forceField.type`의 발 크기는1×1, 비율은0.5/0.2여서 두 그림 모두8/2픽셀 보정이 필요하다. 사제158은 공통 경로를 사용했지만 보호막167은 임시 경로에서 보정을 생략했다. 보호막이 오른쪽8/아래2픽셀로 어긋나 안의 사제가 왼쪽에 보일 수 있었다.
- 원본은 제단164에 한하여 현재 소유자 `BYTE+34` 대신 원래 사제 소유자 `WORD+12`로 색표를 선택한다. `RawDaisContentNotice`는 내용물의 원래 소유자를 이미 제단 WORD에 기록했다. 임시 표시 경로가 제단의 현재 소유자를 사용해 포획자 색을 표시했다.
- `RawPlainAssetDraw`에 실제 TYPE/VT 쌍 **164/005076b8, 167/00507770**을 등록해 기존 공통 Draw로 연결했다. 제단 소유권·HP 전환·포획·희생 규칙과 좌표를 임의로 바꾸지 않았다. 썬 바리케이드 사이의 보호막170과 사제 원형 보호막167을 구별한다.

## 검사와 인계

신규 두 검사는 실제 Session에서 HP50%미만 전환으로 보호막을 생성하고, 다이스 Pop과 포획 사제 내용물 알림으로 제단을 생성한다. 현재 GameWorld가 제출한 같은 SID의 본체를 별도로 렌더링해 독립 SHP 해독 픽셀과 대조한다. 보호막은 모든 프레임에서8/2 기준점과 이전 미보정 결과의 차이를, 제단은 모든 O방향 프레임에서 파랑/빨강을 교환하며 원래 사제 색과 포획자 색의 차이를 확인한다.

최종 빌드·집중 검사 결과와 SHA는 [보고서](../../cpppj/priest-display-20261028.json)에 기록한다. 최초 검사 준비의 권한/지도 위치 오류, 초기 잘못된 기본 VT 가정, C4244 경고와 수정 내역도 원시 로그에 보존한다. 현재 제품의 자연 완주·전체 게임 동일성·Windows11 실기 검증 완료로 세지 않는다.
