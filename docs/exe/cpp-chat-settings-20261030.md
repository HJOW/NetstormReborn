## 입력줄 요청

기존573의 `ClientMain`은 설정을 해석할 때 `inputLineOff`를 같은 장기 전역으로 읽는다. 그리기 뒤 `ConsumeChatInputToggle`이 비영 요청을 한 번 실행하고 전역에0을 쓴다. 저장된 설정값 자체를0으로 바꾸는 동작은 아니다. 따라서 설정이 다시 해석되면 저장된 비영 값이 새 요청이 된다.

새 배포 사본의 캠페인1-1 브리핑에 **원문 Config 명령 버튼5개만** 추가했다. `Request One`, `Request Zero`, `Request Minus`, `Reparse Config`는 각각 `inputLineOff=1`, `inputLineOff=0`, `inputLineOff=-1`, `tracelevel=4`를 실행한다. `Startup Green`은 `-1chatFormat2=~g`를 저장한다. Header/Fort/AI/시작돈·게임 규칙은 그대로이며 이 언어 파일은 ZIP에 넣지 않았다.

실제 ESC→Game→Review Briefing→Config 버튼과 Enter/F3/문자 입력만 사용했다. 입력줄 플래그나 manager 상태를 검사 장치에서 직접 쓰지 않았다.

| 실제 단계 | 입력줄 | 확인한 동작 |
| --- | --- | --- |
| Enter | 표시 | 같은 Chat root/Console 생성 상태 |
| 요청1 | 숨김 | 프레임말 요청0 |
| Enter→요청0 | 표시 유지 | 전환 없음·요청0 |
| 요청-1 | 숨김 | 비영 값의 전환·요청0 |
| Enter→다른 설정 재해석 | 다시 숨김 | 저장된 -1을 재조회한 새 요청·소비0 |
| Enter→요청0 | 표시 유지 | 저장값0과 실제 표시 상태 |

각 관측에서 같은 root387/Console391, phase4·Session1·정지0을 확인했다. 기존 [573 입력 검사](cpp-chat-input-20261029.md)와 별개로, 이번에는 실제 실행 중 Config 변경을 확인했다. Chat 전체 드래그·팔레트/모드 조합의 완료를 뜻하지 않는다.

## 시작 ID와 서식 키

처음에는 미션에서 `.front ~g`를 저장하면 다음 실행도 녹색일 것으로 기대했다. 실제 첫 재실행은 기본색246이었다. 제품 수정 전에 원문과 현재 소유자를 확인했다.

- 원본 PE의 `00540c74 MySubscriber` 초기값은 `0xffffffff`(-1), `0054265c LoginSubscriber`는1이다.
- `0042e050` 초기화는 **그때의 signed My**로 `chatFormat`/`chatFormat2` 키를 만들고 현재 manager에 복사한다. 시작 때는 `-1chatFormat2`를 읽는다.
- 미션 Init의 `004c3355/004c335b/004c335c`는 Login 값을 My에 복사한다. 이 세 명령은 이미 초기화한 manager를 바꾸지 않는다.
- 미션에서 `.front`를 실행하면 현재 My1로 `1chatFormat2`에 저장한다.
- 싱글플레이 로그인 `004b63d0`의 직접 호출 목록에는 Chat 초기화가 없다. 다른 로그인 경로 `004b4480`의 재초기화를 싱글 경로에 넣지 않았다.

`tools/decomp_chat_settings_startup.py`는 기존 관측 장치에서 실제 `0042e050/0042e000`과 위 ID 복사3명령을 **Unicorn 격리 x86**으로 실행한다. Config/할당/명령 등록/CRT는 명시 경계다. 두 현재 ID와 네 독립 저장표의8사례를 각각 x87 제어어 `0x27f/0x37f`로 관측했다. 총16관측의 재관측 차이는0이고, 보강 전후 원시4파일도 같다.

| 저장표의 front 키 | 초기화할 때 My=-1 | 초기화할 때 My=1 |
| --- | --- | --- |
| 없음 | 빈 서식 | 빈 서식 |
| `1=~g`만 | 빈 서식 | `~g` |
| `-1=~g`만 | `~g` | 빈 서식 |

각 사례에서 미션 ID 복사 뒤 My1·같은 manager·기존 서식을 확인했다. 이는 **원본 전체 startup/게임 GUI의 실행이나613의 실제 CPU 도우미 관측과 다르다.** 8사례의 C++ 신규 fixture 비교도 아니다. 실제 제품의 대응 결과는 아래 세 GUI 실행으로 확인했다. 10.72는 이번 관측 대상이 아니다.
