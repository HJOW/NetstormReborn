# 실제 Client 단일 Kernel과 호스트 월드 수명 — 단위393

실제 Client와 Session이 같은 Kernel을 사용하도록 연결했다. 임의 호스트 `GameWorld` 자체는 등록표에서 빼고 UberGump가 소유한다. 전역 Clear 중 월드를 중복 소멸하거나 Kernel 프레임을 중첩 실행하지 않는다. 전체 State/Gump/Core 공유나 Editor 완료를 뜻하지 않는다.

## 근거와 실제 수명

기준 HEAD는 `a6f12d98 / 20261024-15 CP`이며 현재/마지막 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**으로 같다. 이번에 기존 정밀 C를 다시 읽었으며 디컴파일 소스·원본/CD·기존 Native fixture는 바꾸지 않았다.

- 10.78의00471a30은 같은 전역 표0056b80c부터00592908 직전까지 현재 슬롯을 증가 순서로 읽고 가상+18을 호출한다. 현재 GameWorld는 이 프로젝트의 표시/입력/Session 소유 호스트 어댑터이며, 그 전체 소유권을 원문 프로세스 슬롯 하나로 대응시킬 근거는 없었다.
- 00471af0도 같은 표를 한 번 순회하며 각 가상 소멸자가 복귀한 뒤에만 현재 슬롯을0으로 쓴다. 지난 빈 슬롯에 새로 등록된 항목은 그 호출에서 남는다.
- Client 루프의004662b0→00464170 뒤에00471a30이 한 번 있으며 게임 시계 정지로 Kernel 전체를 생략하지 않는다. 기존 GUI의 별도 raw Kernel 정지 관문을 전역 Kernel에 추가하지 않는다.
- CD10.72 대응 주소는004ed5d0/004ed4d0이고 슬롯 수 차이가 있다. 새 CD 실행/전체 CD 복원은 이번 범위가 아니다.

`CampaignClientServices`가 Client Kernel의 실제 주소를 Session에 전달하고, RawSurfaceWorld의 모든 Form·경로·Regular·소리·효과가 그 참조를 직접 빌린다. 실제 Client 경로에는 두 번째 Kernel을 생성하지 않는다. 외부 Kernel이 없는 독립 월드/검사는 기존 자체 소유자를 사용한다.

호스트 월드는 UberGump의 unique_ptr다. 실제 소멸을 시작하기 전에 현재 월드 슬롯을NULL로 옮겨 반납 중의 subscriber 조회가 이전 월드를 따라가지 않게 한다. 실제 Client는 현재 시각/연결/기존 AI 준비→같은 전역 Kernel 한 번→표시용 현재 객체 수집을 호출한다. 이 준비 분리는 기존 호스트 준비 몸체의 이동이며 원문 pre-Kernel 자식 전체의 순서를 새로 완성했다는 주장이 아니다. 독립 `RunFrame`/`Step` API는 기존 준비+단일 실행 계약을 유지한다.

원문 `ClearProcesses()`와 `Kernel.Clear()`는 여전히 단일 순회다. Session의 C++ 최종 소멸은 [단위392](cpp-session-player-links-20261024.md)의 실제 PlayerLinks 정리 뒤 `DrainProcesses()`로 지난 슬롯의 후속 등록까지 반납한다. 이 추가 순회는 실제 장치/Player/서비스가 살아 있을 때 끝내기 위한 호스트 소멸 정책이며 Native State 자식으로 공급하지 않는다. 자체 Kernel은 RawSurfaceWorld의 마지막 소유 멤버로서 다른 월드 모듈보다 먼저 반납된다. 빌린 Kernel은 같은 실제 Session이 모듈 해제 전에 명시 Drain하며 RawSurfaceWorld 자체의 소멸에서는 외부 Kernel을 파괴하거나 자동 정리하지 않는다.

전역 Kernel에는 이미 다른 프로세스가 존재할 수 있다. 최초 구현의 빈 전역 Kernel 거부는 원문보다 좁은 계약이어서 검토 중 제거했다. 모드/Runtime/삭제 바인딩의 최초 설치 검사는 같은 월드의 실제 Pool/할당 슬롯과 설치 상태로 판정하고, 전역 Kernel 개수를 자기 월드의 첫 등록 여부로 오인하지 않는다. 첫 실제 객체 전 부분 생성 실패는 외부 Kernel의 기존 프로세스를 반납하지 않으며, 정상 Session은 그 프로세스를 보존한 채 설치한 뒤 최종 전역 정리에서 같은 순서로 반납한다.
