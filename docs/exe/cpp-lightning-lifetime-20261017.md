## 실제 생성과 소멸

`RawLightningLifetime`은 실제 `00471d10`과 `00471e10/00471df0`의 필드 쓰기와 순서를 구현한다. 먼저 공통 `00488190→00487fd0`의 표시 등록/부착을 수행한 뒤120개×24BYTE 입자를0으로 초기화한다. 최초 공유 색 객체를 구성하고 깊이−25를 저장한 뒤64BYTE 경로를 확보한다. 부착 콜백 뒤 **현재 부모**를 다시 읽어 head를 검사하고 실제 경로 생성자를 호출한다. 생성 시 최초 부모 SID를 계속 쓰는 구현과 구별한다.

경로의 거리×원본 binary32 `0x3ccccccd`가 jitter다. 마지막에 선택 파일명을 저장한다. 부모0의 공통 등록은 부착을 생략하며, raw 수명 대조는 유효한0번 head를 명시 공급해 이 경로도 관찰한다. 실제 Host 관리자는 비영 부모로만 생성한다. 공통 생성자가 쓰지 않는 delta/scaledDelta, 경로 생성자가 쓰지 않는 바이트는 덮어쓰지 않는다.

공유 색 객체는 Fiery Tail의 `0055a750`과 다른 **`0055a758`**이다. 실제 `00458480`은 RGB(0,0,1)→(1,1,1)8개, (1,1,1)→(128/255,128/255,128/255)3개를 폭2.4로 만든다.0.5 회색으로 바꾸지 않는다. 기존 실제 색 띠/CRT 정렬/병합을 사용하는 `BuildLightningPalette`를 추가했다. Draw는 이 공유 표를 조회하지 않고 원본 리터럴195/85를 그대로 사용한다.

소멸은 **경로 반납→입자 반납→공통 목록 제거/base 소멸→flags bit0이면 객체 반납**이다. 공유 팔레트는 개별 빔의 소유가 아니다. 원본 free가 지우지 않는 개수/포인터 의미 필드는 보존하며 호스트 입자 vector만 반납한다. 반납 경계에서 아직 공통 등록이 있는지, 객체 반납 때 이미 제거됐는지도 원문과 대조한다.

## 실제 Host/Kernel 연결

`LightningVisualSystem`은 기존 `RenderProcessSystem` 하나를 다른 표시와 공유한다. 원본 process19·flags0x10의 실제 client Form을 `SquidProcessHost`에 부착하며 Kernel이 소유한다. 별도 프레임 목록/난수/시계를 만들지 않는다. 공통 토큰 조회·kind3 수집·깊이/부모 좌표도 같은 경로다.

생성 중에는 ready가 프레임/Draw/수집/파생 삭제 통지의 재진입을 차단한다. 실패한 확보는 실제 Form/Kernel/등록도 정리한다. 초기화 완료 뒤에는 단위105의 실제 `RawLightningFrame`을 실행한다. 소진 요청은 **실제 Host.Kill(flags0)**로 이어진다. 부모 종속 삭제와 시스템 정리도 같은 공통 수명을 사용한다. 실제 Form 삭제 통지는 기존 원본 대조를 마친 `RenderProcessRemovalBounds`를 거쳐 먼저 dirty를 보낸다.
