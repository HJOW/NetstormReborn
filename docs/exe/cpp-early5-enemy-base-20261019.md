# Early5의 적 훨리기그 베이스 선택과 자연 D안내

2026-10-19 단위211, 기준 `dd93980a`다. AGENTS 최신 cpppj 목표/오타와 양 LEFT를 재확인했다. 현재·마지막 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-19**로 같으며 새 디컴파일·제품 코드 변경·빌드·원본 게임 실행은 없다.

앞선 단위210의 A→B→추가 워크샾/네 생산 지식→C 실제 입력을 그대로 이어 사용했다. C의 MORE로 C1을 읽고 OK로 닫은 다음 아래쪽 방향키 누름/해제로 적 섬을 화면에 넣었다. 첫 ui1의 `cell:137,125`는 비행 중인 훨리기그(TYPE73)를 선택했고 C가 계속 유지됐다. 게임은 종료0이며 원본 전체 스냅샷도 동일했다. 이 결과를 실패 사례로 남겼다.

ui2에서는 `cell:138,127`의 베이스 본체를 눌러 **SID15013/TYPE72/owner2/139,129/HP200**을 선택했다. 원본 `RawTutorialLater::Five`의 C는 첫 선택의 TYPE72를 읽으면 현재 게임 시각+4를 예약하고, 기한 뒤 공통 Advance와 ClearSelection으로 D에 진입한다. 이 몸체와 독립 원본 fixture는 앞선 단위에서 이미 복원/검증됐다. 이번에는 실제 카메라·선택·시계·안내 연결을 확인했으며 타이머나 단계를 직접 쓰지 않았다.

추적 재현 도구로 다시 실행한 최종 ui3은 선택 후 **1.131초에도 C/같은 선택을 유지**, 이후 **5.465초 지점에서 D안내/선택0/정지/MORE**를 확인했다. 이 시간은 보고 지점 사이의 관측 간격이며 정확한 전환 시각 측정은 아니다. 공통 안내 예약/잠금도 있으므로 “정확히4초 뒤 화면이 표시됐다”고 주장하지 않는다. 카메라는1504,518→1504,818, 최종SP2800이다. 적 베이스HP200과 썬더 캐논HP1000이 모두 남아 있어 건물 파괴 조건으로 C가 넘어간 것이 아니다. 같은 실제 A/B/C/D 순서, 종료0, 보호 원본 전체 불변·자동 설정 복구를 확인했다.
