# 단위867 — Missile 현재 checking과 Baseprocess 진단 복귀

10.78 `00482340`의 두 checking 소비자를 현재 Client에 연결했다. 전체 게임·모든 투사체·공격 플레이의 동일성 완료 기록은 아니다. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-11-03**, 현재 작업 호스트도 HJOW-Athlon이며 디컴파일 산출물은 변경하지 않았다.

## 원문과 구현

첫 관문은 `00482340` 시작에서 표시/발사/표적 SID와 게임 시각을 저장하기 전이다. 두 번째는 충돌 효과·반사·충돌 입력 큐 다음, `+78/+7c` 이전 좌표 저장과 비충돌·사거리 미종료 반환보다 앞이다. 두 관문 모두 현재 `005e4794` DWORD를 다시 읽으며 `0041be80(this, firingSid)`를 호출한다.

이 함수는 `004ac140`의 일반 SID robust 검사가 아니다. 실제 `0041be80`은 현재 `this+4` Form 및 `this+8` 부착 SID의 범위를 각각 `\Ns\O\Baseprocess.cpp:0x69/0x6c`에서 진단하고 **항상1**을 반환한다. `firingSid` 인자는 이 본체에서 사용하지 않는다. 따라서 바깥 `Missile.cpp:0x1ee/0x2a0`의 `isRobust(firingSid)` false 진단은 정적으로 미도달이다. 이를 별도 실패 입력이나 성공한 진단 관측으로 만들지 않는다.

공통 도착에서 이미 복원한 `RunPathBaseRobust`를 그대로 공유한다. Form/부착 SID는 하위 WORD로 줄이지 않고 raw DWORD를 읽는다. 첫 진단이 돌아오면 현재 부착 SID를 읽고, 첫 관문이 끝난 뒤 현재 필드·시각을 사용한다. 장치는 실제로 진단이 선택됐을 때만 요구하며 앞선 이동/빗나감 요청 소비를 되돌리지 않는다.

두 번째 관문 뒤 `00482992`는 발사 SID를 다시 풀로 해석한다. 따라서 종료 처리의 group/DPS/특수 피해는 새 발사 슬롯을 읽는다. 표시 자산은 첫 관문 뒤 저장한 포인터를 계속 쓰므로, 후반 진단에서 raw `+8`이 바뀌어도 처음 저장한 표시 SID를 이동/삭제한다. 원문 포인터를 현재 raw SID로 잘못 다시 조회하던 부분을 함께 고쳤다.

`MissileState::checking`은 실제 Session에서 같은 `ClientGameplayGlobals::AiDebug().Checking()`을 빌린다. 진단 callable도 현재 Client의 `services.ai.assertion`에 연결했다. 기존 expression API 경계이므로 전체 원문 파일/행을 실제 진단 UI에 표시한 증거로 확대하지 않는다.

실제 `Missile`은 Host 삭제를 독립 수명 토큰에 알린다. 진단 중 자기 삭제가 정상 복귀해도 helper의 남은 raw 조회·프레임의 다음 필드 접근을 중단한다. 이는 해제된 C++ 객체 접근을 막는 호스트 경계이며 원문 해제 메모리 배치/값을 재현했다는 뜻이 아니다. 모든 임의 효과 콜백의 Session 자체 삭제까지 검증한 것으로 확대하지 않는다.

CD 대응은 `0044b260`, 공통 Baseprocess 대응은 `0048f710`이다. CD Handle에는 이 두 checking/robust 호출이 없으므로 이번 관문과 발사자 재조회 변경은 PATCH에만 적용한다. 원문 CD의 기존 계산/외부 장치 경계를 유지한다.
