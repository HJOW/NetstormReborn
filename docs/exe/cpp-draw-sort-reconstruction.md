# cpppj 원본 CRT 표시 정렬·동률 순서 복원

2026-10-11, **HJOW-Athlon**. 원본 표시 목록을 정렬하는 CRT qsort와 작은 구간 정렬을 판본별로 복원했다. 같은 깊이/y/x도 비교 결과가 1인 원본 규칙과 피벗/교환 순서를 그대로 사용한다. 실제 `Renderer::SetScene`과 건설 표시 제출에 연결했으며 Client의 초기화와 화면 크기 변경도 선택한 판본을 전달한다.

## 원본과 판본 차이

AGENTS.md·LEFT_JOBS.md·LEFT_JOBS.dotnetpj.md를 먼저 확인했다. 착수 시 깨끗한 작업 트리였고 현재 PC와 마지막 디컴파일 PC가 같았다. 새 `drawsort` 목록 **3/5/5개**를 읽기 전용으로 내보냈다. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-11.**

| 몸체 | originals 10.78 | originalCD / original1037 |
|---|---|---|
| CRT qsort | `004e6010` | `004f1c00` |
| 작은 구간 정렬 | `004e5fa0` | `004f1d60` |
| 별도 byte swap | qsort/shortsort 안의 실제 명령 | `004f1dc0` |
| 표시 비교 | `00497900` | `00458240` |
| 정렬 옵션 wrapper | Renderer `004994b0` 안의 호출 조건 | `004582b0` |

두 판본 모두 **8항목 이하**에서는 최대 항목을 뒤로 보내는 선택 정렬을 사용한다. 패치판의 작은 구간 몸체는 마지막 포인터를 EAX로 받는다. 실제 실행기는 이 호출 규약도 직접 공급하여 정상 반환을 확인한다.

큰 구간에서는 패치판이 앞/가운데/뒤 세 지점을 비교·교환하여 중앙값 피벗을 고른다. 피벗 항목이 이동하면 위치도 갱신한다. CD판은 가운데 항목을 첫 칸으로 옮긴 뒤 첫 칸을 피벗으로 유지한다. 양쪽 커서의 비교 부호·구간 끝 조건과 큰 구간을 30칸 스택에 보관하는 순서까지 보존했다. CD의 구간 크기 비교는 왼쪽 주소 거리에서 **1바이트**를 빼는 원본 표현도 유지한다.

정렬 키는 signed WORD 깊이 내림차순, y/x 오름차순이다. 완전 동률도 원본 비교 함수는 **0 대신 1**을 반환한다. 이를 표준 정렬기의 `<0` 비교나 안정 정렬로 바꾸면 원본 동률 순서를 재현할 수 없다. 유한 좌표의 키만 받는 복원 API에서 실제 CRT 분할/교환 몸체를 사용한다.

같은 깊이·좌표 9개를 1~9 토큰 순서로 제출한 실제 원본 결과는 다음과 같다. 종류와 tail은 서로 다른 입력이며 비교 키에는 참여하지 않는다.

| 판본 | 정렬 뒤 토큰 순서 | 같은 픽셀의 마지막 색/객체 |
|---|---|---|
| 10.78 | 9, 5, 3, 4, 2, 6, 7, 8, 1 | 1 |
| CD / 추가 판본 | 5, 2, 3, 4, 1, 6, 7, 8, 9 | 9 |

이 표는 Python 정렬로 계산하지 않았다. 각 PE의 qsort/비교/교환 전체를 실행한 저장 관찰이다. C++ 검사도 이 관찰의 토큰 순서와 실제 Renderer 픽셀을 비교한다.

## 연결 범위

- `client::SortDrawEntries`: 원본의 **전체 16바이트 항목**을 제자리 정렬한다. x/y·토큰·signed 깊이·종류·tail이 함께 이동한다. 8/9 경계와 판본별 분할을 구별한다.
- `client::SortRenderSprites`: 원래 인덱스를 토큰으로 둔 16바이트 키 목록을 정렬하고 자산/프레임/좌표/클립/색 변환/그림자를 함께 이동한다. `Renderer::SetScene`의 안정 정렬을 이 경로로 교체했다. `SceneImage`와 변경 영역 `Draw`가 같은 순서를 사용한다.
- `Renderer(width,height,edition)`: 기본 판본은 10.78이며 실제 Client 초기화/Resize는 `options_.edition`을 전달한다. 정렬 끔은 기존 제출 순서를 그대로 사용한다.
- `DrawVisibleConstruction`: 현재 풀의 판본을 같은 CRT 정렬에 전달한다. 실제 host/Kernel의 같은 부모 표시 9개도 원본 토큰 순서로 제출하는지 검사했다.

유한 x/y와 원본 signed 바이트 거리 범위의 항목 수만 받는다. 잘못된 키는 교환 전에 거부한다. 이는 호스트 계약이다. **NaN/무한대 정렬 키, 16바이트 이외의 항목 크기를 쓰는 CRT 정렬, 손상 포인터/개수는 복원 범위 밖**이다. 앞 단계의 가시 영역 교차 NaN 판본 차이는 그대로 유지한다.

**전체 Renderer/Client 프레임의 복원이 아니다.** 현재 GameWorld가 제출하는 SHP 목록과 건설 표시 전용 목록에 원본 정렬을 적용했다. 자산/구름/다른 효과의 공통 수집/병합·종류별 분배와 건설 SHP 캡처/팔레트/실제 프레임 출력 연결은 남았다. 기존 GameWorld의 클릭 선택은 중심점 거리 방식이며 원본 표시 순서/종류에 따른 선택 복원도 후속이다.

## 독립 관찰과 검증

`tools/decomp_drawsort_oracle.py`는 세 PE의 Ghidra 내보내기 함수 범위만 격리 x86으로 실행한다. 응답/계산/효과 대체가 **없다**. 실제 비교 대상 두 항목의 바이트 순서를 SHA로 관찰하고, 두 x87 정밀도에서 전체 출력·보호 구간·진입 횟수·비교 순서가 같은지 확인한다. 쓰기는 배열 안·스택·SEH에만 허용한다.

| 관찰 | 10.78 | CD | 추가 판본 | 합계 |
|---|---:|---:|---:|---:|
| 전체 qsort | 253 | 253 | 253 | 759 |
| 작은 구간 몸체 | 72 | 72 | 72 | 216 |
| CD 옵션 wrapper 끔/켬 | 0 | 90 | 90 | 180 |
| 합계 | 325 | 415 | 415 | **1,155** |

두 x87 정밀도(0x027f/0x037f)의 **정상 루트 반환 2,310회**. 원본 독립 관찰 누적은 **502,965 → 504,120개**다. 0/1/2/7/8/9/15/16/17/31/32/33/63/64/65/127/256항목·전체 동률/정순/역순/격자 중복/임의 입력·signed 깊이 양 끝·signed zero/최소 subnormal/큰 유한 좌표·종류 0~4·서로 다른 tail을 입력했다. 전 범위 동치 증명이 아니라 이 유한 입력 계획의 실제 대조다.

fixture는 완성 입력·전체 출력·앞뒤 보호 바이트·실제 함수 진입·비교 대상 순서 SHA를 저장한다. C++는 기대 피벗/정렬 순서를 재생성하지 않고 입력을 읽어 전체 출력 바이트와 보호 항목을 비교한다. 저장 감사는 PE/도구/내보내기/fixture SHA·입력 순서/폭·진입/정상 반환 총계를 확인한다. 원본 게임/복사본·analyzeManager·OS·assert는 실행하지 않았다.

새 C++ 검사 **7개**는 세 판본 재생, 잘못된 키의 변경 전 거부, 전체 스프라이트 필드 이동, 실제 Renderer 동률 픽셀/정렬 끔, 실제 건설 표시 동률 제출이다. Release 빌드 경고/오류 **0**, CTest 내부 **703개·실패 0**(검사 165.87초·전체 165.92초), 근거 감사 **107종 모두 통과**. 기존 클론 창 스모크도 통과했다: 18개 글꼴/4,608글자/302,480글꼴화소·786,432화면화소 일치, 변경 없는 4프레임 출력 생략, 패치/CD 커서 18개, 원본 1,394파일/CD snapshot 불변. 인수인계에도 이 결과를 [LEFT_JOBS.md](../../LEFT_JOBS.md)에 기록했다.
