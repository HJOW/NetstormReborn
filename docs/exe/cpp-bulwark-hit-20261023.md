# 불워크·윈드타워의 특수 피해 조건

10.78의 보호 PE와 현재 정밀 소스에서 두 특수 방어를 다시 확인했다. 현재 PC와 마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-22**로 일치한다. 이번에는 전체 디컴파일이나 게임 GUI 실행 없이 함수별 x86 관측·C++ 복원과 실제 세션 Kernel 검사를 수행한다. 원본/CD/AGENTS는 수정하지 않는다.

## 원본 조건과 실제 연결

|대상|원본 가상 진입|조건과 예외|
|---|---|---|
|불워크79/VT50ea08|+98=48ef20|공격자 SID가 0이 아니고 현재 TYPE+ec의 `0x100000` 비행체 속성이 있으면 0을 반환한다. 그 외에는 기존 일반 피해44c8e0을 원래 인수로 호출하고 전체 DWORD 반환을 보존한다. SID0은 TYPE을 읽지 않고 일반 피해로 간다. free/dead/extra/owner 필터는 추가하지 않는다.|
|윈드타워142/VT50ead0|+98=44c8e0, +9c=48ef70|공격자의 `0x100000` 비행체, `0x100` 폭탄 속성 또는 TYPE149 아크 스파이어면 방향 방어를 적용하지 않는다. 그 외 실제 발자국 중심 사이의 방향을 구해 현재 프레임 코드 L/M/N/O가 각각 북0/동2/남4/서6과 일치하면 방어한다. 동률은 원본처럼 세로 우선이다.|

불워크의48ef20은 구현 파일이 없어 실제 일반 피해 분배에서 빠져 있었다. `RawBulwarkHit`을 추가하고 `RawCampaignHitBindings::DamageHooks`의 실제 +98 및 Session의6699 예약 피해에 연결했다. 불워크의+5c도 일반44b900이므로 전용 +98을 보존하는 별도 Regular 경로를 추가했다. 기존83행 표/생성기는 옛 두 일반 HP 진입 조건의 원문이므로 수정하지 않는다.

윈드타워의48ef70과 우클릭 회전은 기존에 연결되어 있었다. 다만 C++ 공통 SID 검사가 공격자0을 먼저 예외로 거부하는 오류가 있었다. 원본은 이 함수에서0도 `POOL + SID*50`으로 읽으므로 해당 조회만 수정했다. 피해자0을 허용하도록 공통 슬롯 검사를 완화하지 않는다.
