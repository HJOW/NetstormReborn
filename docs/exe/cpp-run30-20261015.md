## 원인과 변경

`RawCampaignSession`은 `themes/elements` 벡터를 크기만 확보해0으로 유지했다. 지역 소유권과 레지던스가 신전 원소를 읽어도 항상 윈드0을 받았다. 총 보충 자료는 문자열 전체를 비교하고 속성 누락/미지정 값을 썬3으로 정했으므로 원본 TYPE+98과 달랐다.

`RiftTypeRecord.theme`과 실제 TYPE 파서 연결을 추가했다. 전체 TYPE의 초기값은 **PATCH5/CD4**다. 명시 `theme` 속성은 원본처럼 문자열의 **첫 BYTE 하나**만 조회하며 속성 이름의 대소문자 비교와 속성 적용 순서는 기존 파서대로다. 원소 문자열 전체를 비교하거나 소문자로 바꾸지 않는다.

현재 같은 TYPE의 값을 세션 전체 번호순 `gunTypes.theme`, `themes`, `elements`에 전달한다. 빈/내장 타입의 기본값도 같은 표를 사용한다. 기존 난수/지형 프레임 선택 알고리즘을 새로 바꾸지는 않았다.

레지던스 사건3은 같은 소유자의 첫 신전을 찾고 TYPE+98을 읽은 **뒤** 현재 `theammode`를 조회한다. 새 `AssetRegularHooks.themeMode`를 실제 세션의 같은 설정 조회에 연결했다. 독립 호출의 기존 고정 `state.themeMode` 입력은 훅이 없을 때 유지한다. 첫 일치가 없으면 옵션도 읽지 않는다. 지역 투표의 마지막 워크샾 원소 규칙과 레지던스의 첫 신전 규칙을 합치지 않았다.
