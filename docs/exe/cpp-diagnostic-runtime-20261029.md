# 실제 선택 진단·Ctrl Shift F7와 유니코드 설치 경로

2026-10-29 단위560, 작업 PC와 마지막 전체 디컴파일 PC는 HJOW-Athlon이다. 전체 정밀 디컴파일 기준일은 2026-10-23이며 이번에 원본 PE·CD·디컴파일 산출물을 수정하지 않았다.

553~558의 프로세스 요약·객체 재귀·가상 서식·공유 로그·덤프/디스크 부품을 실제 Client에 연결했다. 559에서 연결한 번개도 같은 실제 Form/부모를 가진다. 사용자의 모델 용량 오류 보고 뒤 변경 파일과 남은 실행을 다시 확인하고, 아래 최종 근거를 정리했다.

## 연결한 동작

- 선택의 임시 SID/TYPE 한 줄을 실제 가상+70/내장 Form 재귀 로그로 교체했다. 스크린샷 저장 완료 로그도 같은 FILE·필터·들여쓰기를 사용한다.
- `ClientTraceGlobals`는 로그1024바이트·현재 FILE·level·재귀 깊이·suppress를 Client 수명으로 보유한다. `tracelevel` 설정 변경은 같은 현재 level에 반영되며 미션 전환으로 상태를 재생성하지 않는다.
- Pool count는 `SidPool::CapacityValue()`의 실제 현재 주소다. 검사/메타맵은 DWORD 또는 제품 bool의 현재 주소를 빌리는 `ObjectTraceFlag`로 연결했다. 지역 정수 사본으로 고정하지 않는다.
- 지면97/가장자리 농장121은 장기 보조 owner로 옮겨 Session의 지면 조회와 덤프가 같은 현재 값을 사용한다. fringe102는 기존 `TerrainBitmapState`를 사용한다.
- Ctrl Shift F7 누름은 원문과 같이 Guide/Gump 뒤, console/정지/일반 F7 전에 처리한다. `004437f0`은 실제 단일 RET이며, 이어 객체 `004d6020`→프로세스 `00471890` 순서로 출력한다. 뗌은 출력하지 않으며 Alt를 추가 금지하지 않는다.
- `squids.txt`는 설치 기본 폴더의 두 단계 파일/마크업 제거 경로다. `procSumm.txt`는 원문 CRT와 같이 현재 작업 폴더의 고정 상대 이름으로 연다. 현재 Kernel에서 실제 SquidProcess의 Form·부모를 읽으며 가짜 타입0/부모0을 넣지 않는다.

## 한글 경로에서 발견한 시작 오류

실제 한글 설치 사본은 시작 시 `Invalid UTF-8 text`로 종료했다. 설치 경로를 시스템 ANSI 문자열로 설정에 넣고 원문 Windows-1252 인코더로 저장하던 경계가 원인이었다.

Client에만 호환 저장을 추가했다. 원문 `ConfigInterface::SaveFile`과 `EncodeConfigFile`의 엄격한 규칙은 유지한다. 기존 영어/서유럽 값은 같은 Windows-1252/XOR 바이트다. 유효 UTF-8이지만 그 인코딩으로 표현할 수 없는 값만 원래 `mQdsT` 서명 뒤에 UTF-8 BOM을 넣고 XOR한다. 기존 두 설정 로더가 이 서명/BOM 조합을 이미 읽는다. 잘못된 UTF-8은 그대로 거부하며 쓰기 실패 때 재시도하거나 changed를 지우지 않는다.

설치 경로는 `u8string`으로 전달하고 설정 파일 열기·전체화면 표식 제거는 wide CRT를 사용한다. 원본 ANSI와 다른 Windows10/11 호환 처리임을 각 코드에 명시했다. 실행 파일에는 프로세스 UTF-8 manifest를 포함했다. 이 선언은 Windows10 1903부터 지원되며, 이번 실제 확인 환경은 Windows10 19045다. Windows11 실기를 확인한 것은 아니다. [Microsoft의 manifest 문서](https://learn.microsoft.com/en-us/windows/win32/sbscs/application-manifests)

일반 미션에서는 실제 레인 신전 선택의 재귀 로그, 수동 정지 중 덤프, 뗌 뒤 두 파일의 바이트/수정 시각 불변, Alt 추가 누름의 재쓰기, 재개·ESC 이탈·메뉴 덤프를 확인했다. level0에서는 선택 stdout 로그가 걸러지고 덤프의 임시30이 끝나면0으로 돌아온다. 모든 덤프 후 depth/suppress/indent가0이다. 프로세스 파일 행 수는 실제 같은 Kernel 개수와 같다.

Edit에서는 TEST01.fort/english를 격리 사본의 `AAA560` 이름으로 동일 바이트 복사했다. 이 드라이브는 파일 시각이2초 단위이고 디렉터리 열거가 생성 순서다. 원문은 정렬 전에 수락한50개만 보유하므로 이 사본을 먼저 생성한 뒤 나머지 자료를 복사했다. 433개 원래 파일 뒤에 단순 추가했을 때 목록에 나타나지 않았던 이유도 확인했다. 원본50개 상한이나 사용자 원본 파일은 바꾸지 않았다. 뗌/재누름의 수정 시각 비교도 이 해상도에서 구별되도록 누름 사이5초 이상을 확보했다.

게임 SHA-256: `e779165698483c4cae6d3bf0a3e7e02410b3dfed86e30a9a7c60d3e28f94ade2`.

근거는 [보고서](../../cpppj/diagnostic-runtime-20261029.json), 원시는 `extracted/cpp-trace-runtime-560-20261029/`다. 최종 두 일반/한글 사례는 `gui-v4`, 최종 Edit는 `gui-v5`이며 같은 게임 SHA다. 도구는 [cpp_diagnostic_runtime_smoke.py](../../tools/cpp_diagnostic_runtime_smoke.py)다. HJOW-Athlon은 AGENTS.md의 실제 게임/별도 창 확인 예외 시스템이다.

중간 실패도 보존했다. 최초 도구의 sunVortex 대상 가정은 실제 rainVortex로 정정했다. 한글 시작 실패는 위 실제 호환 경계에서 고쳤다. Edit의 보이지 않는 캠페인 이름과 뒤에 추가한 사본은 실제 목록/열거 순서에 맞춰 정정했다. 호환 검사 최초 추가 시 Config의 registry 생성 인자 누락은 수정했고 `build-v4`가 최종 빌드다.

## 다음 작업과 판정 한계

사용자 요청대로 이전 작업 파일을 점검하고 문서·커밋을 먼저 정리했다. **현재 게임의 일반31/Demo3 전체34 짧은 진입은 커밋 뒤 다음 작업**이다. 직전 전체34 기준은552다. 현재 제품의 전체 C++ 통과·자연 완주·Windows11 실기를 주장하지 않는다. 기존 자동 전술1개 실패/보류와 입력6개 정정/집중 통과 이력도 유지한다.

traceToChat0의 정상 관문은 연결했으나 비영의 `0042f190` 스타일 전달, 메타맵 번개의 `00479650` 실제 기록 경로는 명시 미복원이다. 남은 UI/Edit·시나리오·전체 수명·호환성을 이어간다. 자연 완주/스펠 도움말 그림/연녹색 직사각형/언어 파일 부재 개선의 보류, 공중3종의 정적 분석 제한, 멀티플레이 사전 구현의 신규 검사 금지를 유지한다. 전체 목표는 진행 중이다.
