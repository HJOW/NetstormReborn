## 실제 동일 월드 조립

`RawCampaignHitBindings`는 기존 실제 RawGunImpact/RawDudeNotice/RawGunHit/RawPriestDamage/RawDamageableBurning을 같은 RawSurfaceWorld/Core/Pool/Host/HP/난수/감시 저장소에 조립한다. 기존 숫자 계산과 원본 함수 몸체를 새 계산으로 대신하지 않는다.

- Missile의 정상 충돌이 실제 Ground→Around finder/현재 Dude 반응→공유 난수100→anim160 생성/Pop/Regular로 이어진다. barrier 충돌도 기존 실제 Visual 생성기에 연결한다. 이 검사에서 barrier corner helper를 완전히 복원했다고 주장하지 않는다.
- 총의 실제 Q16 압축 시각/DPS 계산과 현재 가상 피해 전달을 실제 사제 body에 연결한다. 회복 조회/취소는 동일 Host이고 HP 쓰기/공간 경계 전환은 기존 RawPriestWorldBindings다. 현재 boss/server의 HP1 의존 감시 통지는 동일 DependFormHost/GunProcess에 도달한다.
- 사제 회복 caller도 동일 DamageableBurning 판정을 읽는다. 실제 보호 TYPE158의 damageEffect는0이며 자연 반환이다. 이를 검사에서0으로 덮어쓰지 않았다. nonzero 효과와 Dude Burning0/대피 경로 생성은 선택 시 요구되는 실제 외부 경계로 남아 있다.
- 보호 PE의 썬 디스크83/anim160은 가상10/14/18이 공통 Destroy/Pre/Post다. PATCH는4af780/4b0950/4b0840, CD는4ab7e0/4add20/4adbe0이다. 실제 가상표를 확인하여 해당 자산만 Core의 기존 공통 삭제/장부/공간/부착 프로세스 제거 경로로 연결한다. 다른 파생 자산의 삭제를 묵시적으로 공통 처리하지 않는다.
- 사제158의 가상98은 PATCH494380/CD40cb10이다. 현재 동일 HP를 읽고 쓰며 저장된 사제 사본이나 가짜 표적을 만들지 않는다.

## HP1 보호막과 소리 경계

처음 반복 피격은 HP1 경계의 `priestForceField.wav` 조회에서 멈췄다. 기존 RawPriestShield/RawPriestPostPopTail/ForcefieldPostPop/Regular의 실제 생성·소유자·공간·조회/예약은 이미 연결되어 있었다. 이제 실제 SoundList 이름 조회와 SoundProcessSystem47 부착을 같은 Host/Kernel에 연결했다. HP1 후 실제 보호막과 사건1/2 및 sound47 수명이 유지되는 것을 검사한다.

소리 장치의 재생/정지는 명시 토큰 관찰 입력이다. game/wall 시각은 동일한 명시 검사 입력을 사용한다. 보호막 안내음/번역키 `PriestImmobile`/tell과 owner 피해 통지도 외부 요청으로 관찰한다. 실제 WAV 출력, 번역 문자열, UI 안내 및 그에 따른 게임 정지·AI 통지 구현을 완료했다고 세지 않는다. 실제 GameWorld 연결에서는 기존 실제 SoundPlayer/장치·UI 소비자를 공급해야 한다.

## 새 독립 원본 호출 사슬

새 입력96개(PATCH48/CD48)가 정상반환/assert0이다. WORD3×현재시각4×DPS2×회복예약2의 입력이다. 초기 HP100, owner2→1, 미션 레벨보정 차단, damageEffect0, 비어 있는 감시 체인 및 x87=027f를 명시한다. 기존 개별 GunHit/사제 피해/HP/공통 setter의 입력 수는 재합산하지 않는다.

실제 GunHit→Time/SetTime→가상Apply→**실제 표적98 PriestHit**→HPsetter/burning을 실행한다. 피해가 충분하지 않은 자연 반환 입력도 포함한다. PATCH48 C++ 검사는 실제 보호 캠페인을 매 입력 새로 설치하고 같은 조립기를 사용하여 HP·발사 WORD·owner 피해 통지 수를 원본 결과와 비교한다. CD48은 독립 PE 관찰이며 이 새 조립기를 CD 캠페인에서48개 직접 재생한 것으로 주장하지 않는다.

발사 group/genus/type 및 공간통지는 명시 query 입력이다. PATCH DPS getter는 실제4바이트 PE thunk를 실행하고 CD DPS 반환은 입력 thunk다. 회복 조회/취소·프레임·소유자통지·가상 공간은 기존 DamageOracle의 관찰 경계다. 입력 준비의 actual Adjust(0) 한 번은 준비용 실행으로 사슬 정상반환 수에 재합산하지 않는다. 비어 있지 않은 실제 감시 해제는 아래 C++ 전체 Kernel 검사가 담당한다.
