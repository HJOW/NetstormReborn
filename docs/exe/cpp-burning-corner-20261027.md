[원문 관측](../../cpppj/burning-sources-corner-native-20261027.json), [통합 보고서](../../cpppj/burning-corner-runtime-20261027.json)를 함께 본다.

## 원문 관측과 수정

`decomp_burning_sources_corner.py`는 실제424110/CD4a5d30과 현재 HP·난수·하위 몸체를 실행한다. 작은2×7~9×5의 투명 캡처와 기존16×12 대조 입력, 두 난수 시드, 두 x87 정밀도를 사용했다. 최종36입력/72정상 반환의 selected/전체150입자/행/난수 결과를 기록했다. 명령 위치별300후보 픽셀 읽기와 실제 행 읽기 주소도 관측했다. 기존326×2 Source gold는 변경하지 않았다.

10.78은 투명 픽셀에서 rowTaken 읽기가0회다. CD는 각300후보에서 행을 먼저 읽는다. 작은 폭에서는 후보 row가 논리 행 개수와 같을 수 있다. CD 관측 입력은 이 추가 위치의 접근 가능한0BYTE1개를 명시해 제공했다. 이는 Source의 현재 메모리 입력이며 실제 caller의 힙 패딩/안전성 복원이 아니다. 제품의 배열 크기를 늘리지 않았다.

처음 두 실행기는 두 판본이 같은 픽셀 우선 순서라고 가정해 CD의 실제300행 읽기에서 관찰 조건에 실패했다. 원시 native1/2를 보존하고 판본 차이에 맞춰 입력/관찰을 정정했다. 그 전에는 새 fixture/보고서가 없었으며, 최종 성공 뒤 최초 gold를 생성했다. 원본 게임/OS 실행이나 Source 하위 함수 대체는 없다.

`RawBurningSources::Select`는10.78에서 아래 픽셀을 먼저 확인한다. 불투명해서 실제 행에 도달한 경우에만 같은 범위 보호를 적용한다. CD는 범위 보호→행 표식→필요하면 픽셀 순서다. 선택된 잘못된 행의 예외는 유지했다. 같은 Source 배열/용량/300시도/7점 폴백/난수·selected의 원본 의미는 바꾸지 않았다.
