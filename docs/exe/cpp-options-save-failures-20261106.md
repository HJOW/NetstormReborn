## 제품 변경

`ClientOptionsDisk.cpp`의 기존 `FinishOptionsStream`과 교체 실패 후 이름 복구를 `options_detail` 내부 함수로 추출했다. 실제 일반 저장과 매핑1224 교체가 이 함수를 호출하며 검사는 같은 제품 라이브러리에 링크한다. 별도 모형 writer로 대체하지 않는다. 쓰기→flush→선택적 commit→close 순서와 실패 시 예외·changed 보존은 유지했다.

기존에도 백업 이름 복원은 있었다. 이번에는 목표 속성 조회의 모든 실패를 파일 부재로 취급하던 조건을 실제 FILE_NOT_FOUND/PATH_NOT_FOUND로 한정했다. 복원은 기존과 같이 덮어쓰기 없는 `MoveFileExW`다. 복원 실패 코드는 별도 진단에 더하고 원래 `ReplaceFileW` 오류 코드는 보존한다. 실패 복구 자료를 성공 저장의 지연 정리 목록에 넣지 않는 정책도 유지한다.

백업 경로가 지정된1176에서는 기존/새 파일이 각 이름을 유지할 수 있고,1177에서는 기존 파일이 백업 이름으로 옮겨졌을 수 있다. 이 상태 구분은 [Microsoft ReplaceFileW 문서](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)에 따른다. 파일 내용 복구와 새 설정 저장 성공은 별개이며, 이름 복원에 성공해도 최초 저장 실패 예외를 전달한다.
