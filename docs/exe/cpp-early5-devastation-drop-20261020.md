# Early5 Devastation 이후 포획과 사제 내려놓기 — 단위238

시작 HEAD는 `0fee047a`다. 사용자 요청으로 cpppj의 다음 작업을 재개했다. 현재 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon**, 마지막 정밀 디컴파일 날짜는 **2026-10-19**다. 새 디컴파일은 하지 않았다. AGENTS.md와 두 인수인계 문서를 읽었으며 dotnetpj는 수정하지 않는다.

## 발견한 문제와 수정

기존 단위236/237은 빈 장면의 Devastation과 요청·수신을 검증했다. 이번에는 실제 Tutorial5 스크립트가 지정한 `SubtleDefense`를 로드하고 원래 적 사제를 대상으로 시전했다. 검사 입력은 골렘·주문 내용물·잔액이며, 적 HP/좌표·대상 목록·검색 결과·진행 단계는 직접 쓰지 않는다. 예약 시계와 실제 프레임을 진행하여 원래 검색·피해·시전 종료를 실행한다.

실제 Devastation으로 적 사제 HP가 **100→1**이 됐다. 시전 비용은 한 번 차감되고 주문 내용물과 시전자는 유지된다. 실제 경로 도착과 0x4f 로컬 전송으로 포획한 뒤 0x50으로 내려놓는 검사에서, 포로 내용물은 삭제되지만 원래 소유자2의 살아 있는 사제를 찾지 못하는 문제가 드러났다.

`RawCampaignConstructionBindings`가 배치의 소유자 처리를 공통 `SquidOwner`로 고정한 것이 원인이다. 보호10.78 PE의 `00442c80` 안 **00442f8d: ff5274**는 가상 **+74**를 호출한다. 사제 표 **0050f210+74=0050f284**의 DWORD는 **00491790**, 곧 기존에 독립 복원한 사제 소유자 몸체다. 정적 읽기 기록은 `extracted/goal-early5-devastation-20261020-owner-static.json`이다. 정적 관측이며 새 원본 실행/정상 반환 횟수로 합산하지 않는다.

`RawCampaignConstructionGameplay::setOwner`를 통해 Session의 기존 `RawPriestWorldBindings::SetOwner`를 연결한다. 이 분배기는 사제에 원래 소유자·로컬 표식을 처리하고 다른 타입에는 공통 소유자를 사용한다. 별도의 소유자/참여 상태를 덧쓰지 않는다. 공통 생성·배치·HP·공간·포획 내용물 수명은 기존 복원 몸체를 그대로 사용한다.

## 검사 입력의 교정과 보존

초기 검사는 `World.Objects()`에서 원래 섬의 표면까지 반환한다고 잘못 가정해 지형 삭제를 요구했다. 비자산 슬롯을 포함하지 않는 이 표시 목록으로 지형 삭제를 증명할 수 없어 해당 주장을 제거하고 적 사제 흐름으로 범위를 한정했다. 초기 실패 원문은 `focused1`에 남긴다. 지형 효과를 검증했다고 주장하지 않는다.

다음 포획 실패는 기존 한 지점용 도착 도우미를 이동 경로에 사용한 검사 입력 오류였다. 경로는 마지막 시각에서도 한 호출에 한 꼭짓점만 소비한다. 실제 도착 좌표가 시작점에 머문 진단을 `focused4.stdout`에 보존했다. 새 검사는 실제 경로 프레임을 끝까지 호출하며 좌표·완료 상태를 직접 쓰지 않는다. 이를 수정한 `focused5`는 내려놓은 사제의 참여 조회에서만 실패해 위 연결 누락을 드러냈다. 제품 수정 전 실패와 수정 후 결과를 구별한다.

첫 전체 빌드 시도는 실행 중인 클론 EXE 재링크가 Windows 파일 잠금으로 실패했다(`build1`, LNK1104). 검사 대상만 빌드하는 방식으로 변경했고, 게임 창 종료 후 최종 전체 Release 빌드(`build8`)는 종료0으로 완료했다. 검사기/기대값을 바꾸어 제품 실패를 숨기지 않는다.

## 실제 화면 관측과 남은 작업

이 PC에는 단위226의 다른 PC 원시 입력이 없어, 커밋된 A→D 입력에 전진 조작을 붙여 새 실행을 보관한다. UI 입력은 같은 실제 InputQueue를 사용한다. HP/SP/단계/승리 주입 동작은 사용하지 않는다. 허용된 설정 두 파일은 실행 후 원래 바이트와 존재 상태로 복구하고 보호 원본 전체 파일 해시를 비교한다.

`ui1`은 자연 A→D, 윈드 제네레이터·발사기·다리·썬 캐논의 실제 생성과 적 썬더 캐논 피해를 관측했다. `ui2`는 방어 보충 부족으로 신전 파괴 안내에서 멈췄다. 정상 프로세스 종료0은 미션 성공이 아니다. `ui3`도 신전 파괴 안내를 화면으로 관측했으며 사용자 중단 요청으로 종료했다. 강제 종료 때문에 메모리의 `states.tsv`는 저장되지 않았고, 남은 BMP·입력·종료 로그만 보존한다. 세 UI 실행은 모두 **수정 전 앱 cb5aea89…**이므로 사제 내려놓기 수정의 실제 화면 검증으로 세지 않는다.

## 사용자 지시 변경과 최종 검증 범위

사용자가 **“실제 cpppj 실행 테스트는 다 뒤로 … 나중에 실제 플레이 테스트를 통해 한꺼번에 … 이번 테스트는 미뤄줘”**라고 지시했다. 실행 중인 이 작업의 클론 창과 전체 회귀만 프로세스 경로/명령줄/부모를 확인한 뒤 중단했다. 원본 게임과 다른 사용자 프로세스는 실행·종료하지 않았다. 이후 게임 실행이나 추가 검사를 시작하지 않았다. 실제 실행/플레이 검증은 매 작업의 선행 조건으로 삼지 않고, 구현을 모은 뒤 별도 통합 플레이 검증으로 이월한다.

중단 요청 전에 최종 검사 바이너리 **5e9afa21…**의 Devastation 집중 **4개/0실패**, Cast/Drop 집중 **2개/0실패**가 통과했다. 새 검사는 HP100→1, 실제 경로 도착, 0x50→0x4f→0x50의 세 전송, 포획 내용물 변환/삭제, 원래 소유자2 사제 복귀·참여 조회, 주문 내용물 보존과 일반 Drop의 SP 보존을 확인한다. 전체 회귀는 **31.64초에서 사용자 요청으로 중단**되어 완료 개수와 실패 개수를 확정할 수 없다. 전체1773개 통과로 주장하지 않는다.

현재 소스 핀 **98보고서·181항목**을 갱신했고, 새 이력과 핀을 역변환하면 시작 HEAD의 JSON과 의미가 같음을 확인했다. 과거 실행·바이너리·원본 기대값·기존 이력은 보존한다. 최종 결과·중단·출처는 `cpppj/early5-devastation-runtime.json`, 읽기 전용 감사는 `tools/cpp_early5_devastation_runtime.py --verify`다. 입력 계획은 `cpppj/tests/fixtures/tutorial-five-devastation-ui-input.tsv`에 남기되 후속 통합 플레이 검증 전까지 재실행하지 않는다.
