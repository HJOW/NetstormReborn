## 실제로 빠져 있던 연결

사용자가 갱신한 TEST02에는 owner1의 Bulf135가 이미 있다. 타입 선택기 `00488fe0`은 이 부모에 **41**을 돌려주지만, 실제 Session의 `StartMotion`, PathStart, 경로 생성/부모 검증은 이 파생 종류를 지원하지 않았다. 따라서 기존 포획/희생의 골렘 명시 입력 검사가 통과해도 TEST02의 Bulf를 사용자가 움직이는 경로는 완료되지 않은 상태였다.

원본 `0042afb0`은 부모 VT **00503e50**을 설치한다. 이 표의 +38/+3c/+40/+44/+c8은 각각 **0042a5f0/00429800/004437f0/00427750/004287d0**다. 골렘133의 해당 다섯 슬롯과 같음을 보호 PE에서 직접 확인했다. 그래서 부모의 기존 공통 Halt·Carrier 도착·시작 통지는 공유하되, 실제 이동 프레임을 골렘40으로 대체하지 않는다.

## 복원한 동작

`RawBulfFrame`은 immobile004287a0→기존 finished→Halt→Step 순서를 따른다. 첫 각도는 Step 이전에 보관하며, 각도가 변하면 E/F 회전 구간을 선택한다. 새 각도가 작거나 차이가180도를 넘으면 F, 나머지는 E다. 각도×원본 float1/360×(구간 개수−1)을 **float로 저장한 뒤 +0.5/signed64 절삭**하는 원본43fa50을 보존했다.

각도가 그대로이고90도의 배수일 때만 SHP의 보행 간격과 실제 이동 거리의 제곱을 비교한다. 이동 거리가 보행 간격과 **같아도 프레임을 진행**한다(`간격 제곱 <= 이동 제곱`). 첫 C++ 대조에서 이 동일 경계의 두 입력이 실패해, 원본 기대값을 유지한 채 제품 비교 조건을 바로잡았다. E/F에서 A~D로 복귀하는 중간 프레임은 원본 **3/9/17/30**이다. 다음 프레임은 `(현재 절대 프레임+1)%count+first`로 계산한다. 사제/골렘의 상대 프레임 계산으로 바꾸지 않는다. 정밀 C 출력의 일부 float형 프레임 표기 대신 실제 EBX 정수 연산도 대조했다.

프레임이 바뀌었을 때만 Unpop0→프레임 DWORD→Step 위치 Pop40을 수행한다. `(다음 프레임+1)%4==0`이면 공용004558f0(1000,6000)을 소비해 `bulfWalk1.wav`~`bulfWalk5.wav`를 선택한다. Pop 뒤의 현재 부모 좌표를 다시 읽어 위치 음향을 요청한다. 새 난수 생성기를 두지 않고 같은 Session의 게임 난수를 사용한다.

`RawPathRuntime`에41의 실제 VT를 추가했고, 기존 `RawPathProcess`는41 전용 프레임 처리기를 사용한다. Init은 기존 실제 지면/BFS에 cardinal 인자1을 전달한다. 도착은41의 원래 일반0048b340을 사용하므로 사제/골렘의 정지 애니메이션 접두를 추가하지 않았다. 기존 시작·현재 경로 조회·재탐색·서버 연결도135/503e50/41의 일치를 검사한다. 모든 게임/공간/시계/현재 부모는 같은 세션 저장소다.

## 독립 원본 관측

`tools/decomp_bulf_path.py`는 보호 PE의 생성자/전체 프레임/회전 helper와 실제 CRT를 실행한다. **314개 고유 입력, 두 x87 정밀도628회 정상 복귀, 167464개 명령**, 각 정밀도의 저장 결과가 같다. 합성 A~F 각8프레임과 실제 Bulf처럼 **보행8/회전24**인 두 메타 입력을 사용했다. 생성자 할당/미초기화 heap, 회전/180도 경계, 직각/비직각, A~F 현재 프레임, 보행 간격의 동일/초과, immobile/finished/Halt/Step 완료, 발소리 번호, Pop 뒤 위치 변경, helper의 Inf/NaN/음수0을 구분한다.
