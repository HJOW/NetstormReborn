## 동일 월드 연결

`RawSurfaceWorld`가 기존 실제 `DependFormHost`를 소유하고 같은 Pool/삭제기/`SquidFormDispatch`에 타입1을 등록한다. 현재 Core는 이 인스턴스의 참조를 제공한다. 새 감시 생성기나 별도 표적 목록을 만들지 않는다.

`RawCampaignAssetBindings`의 Gun addDependency는 현재 Fields가 실제 Host의 같은 GunProcess인지 확인하고 `Create(watched,process.Form())`를 호출한다. removeDependency는 동일 감시 호스트의 `Remove(watcher,watched,0)`다. 표적 교체/삭제가 실제 raw Form 체인과 같은 삭제 깊이를 사용한다.

`SquidProcessHost::NotifyDependency`는 원본처럼 server0에서 PID조차 읽지 않는다. server가 비영점이면 현재 Form의 DWORD PID로 현재 Kernel 객체를 다시 찾고 가상 notify에 `(2,dependForm,watched)`를 전달한다. 원본은 실제 슬롯 포인터를 바로 호출하며 새 구현의 손상/빈 PID는 명시 예외다. `SquidProcessState.server`는 실제 DAT00540bc0/CD00540a28이며 기존 boss 전역과 각 주소를 구분한다. 캠페인 자산 Prepare는 같은 Gun server 모드를 이 통지 경계에도 공급한다.

`GunProcess::Notify`는 기존 실제 상태 기계를 override한다. 아직 몸체를 연결하지 않은 다른 파생 notify는 명시 예외이며 기본 성공으로 통지를 버리지 않는다. 현재 월드의 감시 통지 경계는 ProcessForm watcher를 지원한다. 다른 자산 watcher의 파생34는 이번 연결 범위 밖이다. 서버 DependForm Pop은 현재 runtime의 `formTransmit`에 실제 Form/flags를 전달하며 누락이면 명시 거부한다. 캠페인 검사의 소비자는 현재 타입1/정규화flags0x108 요청을 관찰하는 외부 경계다. 이는 실제 직렬화/네트워크 완료를 뜻하지 않는다.

## 독립 원본 관찰

새 `gun-depend-x86.tsv`/`gun-depend.json`에는 **138고유 입력**, 각판본69개의 정상 반환을 기록한다. 원본 assert는0이다. 기존 Form 수명/감시 생성·삭제·재진입 관찰은 재합산하지 않는다.

- 각판본9개는 실제 Gun 감시 wrapper가 요청한 watched/currentForm 인자다. 큰 pair 생성은 명시 관찰 경계다.
- 각판본60개는 실제 ProcessForm34와 실제 PID getter를 실행한다. server0/1/상위bit 비영점, PID1/5/255, 서로 다른 watched/form WORD와 server0의 잘못된PID 입력을 포함한다. 파생 notify는 PID별 명시 관찰 객체에 요청을 기록하는 경계다.
- C++ 독립 소비자는 notify120개를 같은 실제 Host/Kernel/Form 슬롯으로 비교한다. wrapper18개는 원본 인자 관찰 근거이며 이18개 자체를 C++ 완전 pair 재생으로 주장하지 않는다. 기존 실제 pair 몸체를 캠페인 검사에서 소비한다.

## 캠페인 및 빌드 검사

실제 설치한1-1의 같은 GunProcess와 저장 사제 두 부모를 사용해 표적 A→B→없음의 생성/제거를 검사한다. 각 선택에서 raw Pool의 감시 쌍2개, 현재 Form 조회, 같은 장부 깊이0을 확인한다.

삭제 통지 검사는 실제 저장 표적에 ReleaseDependent 시점의 dead 조건만 명시 입력하고 같은 감시 Notify 경로를 실행한다. Gun 표적0/상태1/현재 Form 전송을 검사한 뒤 두 감시 Form을 같은 삭제기로 반납한다. 전체 사제 사망/피해 사슬을 실행했다는 근거로 확대하지 않는다.

최초 빌드는 새 실제 server 전역을 기존 프로세스 상태에 선언하기 전에 호출하여 실패했다. 실패 당시 전체 process/world/검사 원문과 로그를 `cpppj/hist/run21-fail1`에 보존했다. 필수 server 필드를 원본 주소와 함께 추가했다. 첫 집중 검사는 실제 서버 Form Pop 송신 경계 누락으로2개 실패했다. 해당 전체 소스/로그는 `run21-fail2`에 보존하고 필수 요청 경계를 연결했다. 다음 검사의 flags0 기대 가정은 기존 실제 Form Attach의0x100 및 서버 Pop의8 정규화 결과0x108로 교정했으며 실패 원문/로그는 `run21-fail3`에 보존했다. 최종 집중4개는 모두 통과했다. 최종 전체 회귀 및 Release 결과는 실행 완료 후 기록한다.
