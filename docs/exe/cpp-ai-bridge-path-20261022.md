## 보존한 동작

상태0은 signed `available >= wanted - 1`에서 상태1만 쓴다. 상태1은 초기화가 변경한 **현재 상태**를 증가시키며, 상태2·3도 하위 완료 시 현재 상태를 증가시킨다. 상태4는 signed `available >= wanted`에서 상태5만 쓴다. 상태5만 출력 좌표를 복사하고 상태0/true로 반환한다. 한 호출에서 다음 단계까지 실행하지 않는다. 뺄셈과 증가의 DWORD 감김도 보존했다.

조각 소비는 pending 조각을 제외하고 첫 일치만 삭제한다. 패턴 DWORD를 WORD로 자르지 않으며, 추가 소유자·kind·dead 필터를 넣지 않는다. 기한은 삭제 후의 **현재 float rate + 현재 double now**다. 디컴파일 C본문의 now를 float로 축소한 식과 달리 원본 명령은 `fld DWORD [this+10] / fadd QWORD [0055b4d0] / fstp QWORD`다. 이번 구현과 검사는 QWORD 시각의 소수 부분을 보존한다.

연장 결과는 완료 직후 선택한 좌표의 사본을 유지한다. 배치 뒤에는 현재 owner와 패턴을 읽어 소비하고, 삭제 뒤 다시 현재 owner의 기술 부모를 조회해 재고를 갱신한다. 로그 종류29에서만 끝점·목표점 디버그 표식을 기존 배치 경계로 요청한다. 두 번째 표식 TYPE도 첫 표식 효과 뒤 현재 값을 읽는다.

시작점을 아직 찾지 못했을 때에도 `Advance`는 true이며 기존 타임아웃을 변경하지 않는다. 기존 연결점이 유효한 채 탐색을 기다리는 경우도 타임아웃1/true다. 연장 결과가 무효일 때만 타임아웃을 DWORD 감소한 뒤 signed로 판정한다. 실패하면 타임아웃1을 쓰고 본체 `b00` 출력 관문 뒤 원본 `Bridge timeout` 로그를 낸다. 도달한 하위 누락은 명시 오류이며 앞선 효과를 취소하지 않는다.

## 검증 범위

[독립 실행 도구](../../tools/decomp_ai_bridge_step.py)는 보호 PE의 `004167a0` 실제 x86 명령을 Unicorn 격리 메모리에서 실행한다. 초기화·후보 준비·경로 검색은 명시 하위 입력이며 OS나 게임 창을 실행하지 않는다. signed 경계·0~5/범위 밖 상태·하위 false/true/현재 상태 변경 조합 **600개 입력이 모두 정상 반환**했다. [보고서](../../cpppj/ai-bridge-step-20261022.json)와 [fixture](../../cpppj/tests/fixtures/ai-bridge-step-x86.tsv)에 호스트·보호 PE/도구/fixture SHA와 관찰값을 보존했다. 기존 Python3.12 환경에 없던 격리 검사 의존성 `unicorn 2.1.4`를 사용자 패키지에 설치했다.

[C++ 검사](../../cpppj/tests/AiBridgePathTests.cpp) 13개는 위600개 출력을 재생하고 첫 조각 소비·DWORD 패턴·삭제 뒤 기한·미완료 보존·배치 뒤 현재 필드 재조회·무효/NaN 좌표·표식 순서·타임아웃·누락 경계의 부분 효과를 확인했다. 첫 Release 빌드와 focused13개 검사는 종료0이다. 전체 CTest는 **종료8·173.39초·내부2,212개·실패 check72개**다. [실패 기록](../../cpppj/ai-bridge-regression-20261022.json)에 검사명과 로그 SHA를 보존했다. 새13개는 통과했으며 기존 큐/Player/AI 초기화 실패는 각각 개별 필터에서도 재현했다. 시작 HEAD를 별도 빌드하여 대조하지는 않았다. 전체 통과로 보고하지 않는다.

REA의 보호 PE 열기는 SHA와 x86 PE를 확인했으나 Ghidra 분석은 H: 루트의 Windows 경로 속성 조회 `Win32 87`로 시작하지 못했다. 같은 요청을 반복하지 않고 세션을 닫았다. 이후 근거는 이 PC에서 재생성한 정밀 결과, 원본 PE의 Capstone 명령 및 격리 원본 실행이다. 새 Ghidra 디컴파일이나 원본/AGENTS 수정은 없다.
