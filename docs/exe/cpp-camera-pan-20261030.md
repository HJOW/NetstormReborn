## 원문 판정과 계산

큰 입력 부모 `004d62b0`의 **004d6b54..004d6cda**와 일반 큐 진입 **004d6da2**를 구분했다. 실제 가운데 폴링은 `446b50` 커서 갱신 뒤다. 기존 별도 화살표 Scroll과 임시 키 보관/시계도 제거했다. 앞단의 실제 건설 커서 키 처리는 유지했다. 원문 큰 부모의 두 `497e00` 호출은 가장자리 `004d679a`와 이번 pan `004d6cd5`다.

1. 가운데 버튼을 조회한 뒤 `scrollWhileMouseOut`, 포인터 밖 비트, Alt/가운데 누름, 현재 모달로 일반/이동 큐를 고른다. 설정의 PE 초기값은1이며 누락 때 현재값을 유지한다.
2. 이동 경로는 팝업 Kill 요청을 먼저 실행한다. 좌표가-1이거나 창이 비활성이어도 이미 선택한 이동 큐 경로는 유지한다.
3. 현재 지도 원점과 signed 폭/높이로 중심을 계산한다. 포인터를 같은 영역으로 제한하고 `(client크기 / 지도크기) × 중심거리`를 원문 FTOL로 절삭한다.
4. Shift를 새로 조회한다. `/8` 이전 두 이동량의 절댓값을 비교하며 같으면 X를 지운다. 각 signed `/8` 결과를 현재 Renderer 기준 목표에 쓴다.
5. 목표 적용은 기존 프레임 말미의 Present/Commit이 수행한다. pan 계산에서 snapshot/현재 view를 즉시 바꾸지 않는다.

새 `RawCameraPan`은 폴링/팝업 콜백 뒤 현재 전역을 재조회한다. `UberGump`는 같은 HUD의 네 지도 필드·Client의 WM_SIZE 값·현재 활성/모달을 공급한다. 기존 UserInput의 임시 키 상태가 사라져 `Cancel` API와 세 남은 호출도 제거했다.

이동 중 일반 키는 원문 전용 큐처럼 소비한다. **Windows10/11 호환 Alt+Enter는 기존 WM_SYSKEYDOWN에서 모드를 직접 전환하므로** 같은 사건을 일반 Enter/건설로 다시 전달하지 않는다. 원본과 다른 호스트 처리와 이유를 코드 주석에 명시했다. 실제 Alt+Enter·확대 전체화면/DPI 입력 단위의 새 검증은 이번에 하지 않았다.

10.72의 기존 정밀표는 큰 입력 부모의 대응을 `0041ae80`으로 기록한다. 이번 세부 구간/관측/복원은10.78이며10.72의 동일 동작 완료를 뜻하지 않는다. 초기 조사에서 찾은 조기 희생 안내는 실제 `missionPost=0` 일반 전투용임을 확인해 후순위 범위로 남겼다.
