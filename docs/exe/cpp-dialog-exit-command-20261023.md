# HTML 부모 OnExit 해석과 반납 예약

기준은 `VM-W11-Codex / 2026-10-23`의 기존 정밀 `Netstorm.c`와 보호10.78 PE다. 새 디컴파일/게임/GUI/OS 실행과 기존 제품 파일/CMake 수정은 하지 않았다. 이 절은 독립 구성요소 작성 당시의 관측 범위다. 단위370에서 실제 페이지 수명/Client 프레임에 등록·연결했으며 제품 빌드/전체 검사와 실제 해상도 확인 결과는 [수명 연결 상세](cpp-dialog-exit-lifetime-20261023.md)에 기록한다.

## 실제 원문 계약

`004c83b0`은 종류별 regex 검색 우선순위를 유지한다. OnExit 정규식은 `\$OnExit[ \t]*=[ \t]*([^,]+),([^,]+),([^$ ]+)`이며 캡처1은 라벨, 캡처2는 명령 이름, 캡처3은 인자다. 여러 OnExit가 발견되면 같은 두 필드에 마지막 결과가 남는다. 조건 평가는 이 메타 단계보다 먼저 기존 두 번 HTML 순회의 첫 단계가 처리한다.

`004c85d2..004c863c`의 실제 명령은 다음 순서를 가진다.

1. 캡처2를 `004d52c0`의 실제 이름 표에 조회한다. 결과0만 `004c2630`으로 진단하며, `ffffffff`를 별도로 거부하거나 진단하지 않는다.
2. 캡처3의 첫 BYTE를 signed 확장해 원본 C로케일 isdigit에 전달한다. 첫 BYTE가 숫자인 경우만 `004e66de` atol을 호출한다. `-1`, `+2`, 선행 공백 숫자, 인용 문자열, 빈 인자는 숫자로 변환하지 않는다.
3. 숫자가 아니면 그 즉시 `004c7910`의 기존80칸 문자열 고리를 진행한다. 쉼표/세미콜론/따옴표를 다시 토큰화하거나 벗기지 않는다. 지역 `param` Config의 참조를 종료 때까지 저장하는 대신, 이때 해석된 숫자/고리 토큰을 보관한다.
4. `004c8a58/004c8a5e`가 HTML 부모 `+21e0=command`, `+21e4=parameter`에 기록한다.

`004cf1c0` 전체 HTML 부모 소멸은 종류 가상표/인스턴스 수를 갱신한 다음, `+21e0!=0`인 경우 `00452f90(command,parameter,parameter)`를 한 번 예약한다. 직접 명령을 실행하지 않는다. 그 뒤 관련 Gump serial 조회/Kill, 벽 시각, 기본 Gump 소멸을 수행한다. 원본 객체는 한 수명에서 한 번만 소멸한다. `004c79b0`의 버튼/메뉴 선택은 선택 명령을 먼저 예약하고 부모를 Kill하며, MenuJustClosed 수신도 부모 Kill로 간다.

보호 `netstorm.tarc`의 `\d\tell.english`에서 OnExit는 세 곳이다. `SetSize2`의253행은 `QuitApp,99`, 1950/1953행의 조건 분기는 `Tell,Blank`를 사용한다. 해상도 Yes는 Config SCREENW/H 두 명령, OnExit QuitApp99, MenuJustClosed의 실제 수명을 거쳐야 한다.

## 새 모듈

`DialogExitCommandState`는 두 해석된 DWORD만 보관한다. `ResolveDialogExitCommand`는 이미 얻은 regex 캡처 원문을 받아 위 해석 순서로 값을 저장한다. `MakeDialogExitResolveHooks`는 기존 `ScriptStringRing`과 현재 이름 조회/진단을 빌린다. 숫자는 기존 `ConfigParseLong`을 재사용한다.

`DisposeDialogExitCommand`는 보유값을 먼저 비운 뒤 같은 `InputQueue`에 `code,param,param`을 예약한다. 재진입/반복 반납이 같은 소멸을 두 번 예약하지 않도록 하는 호스트 수명 관문이다. 이는 원본 소멸자가 살아 있는 객체 필드를0으로 썼다는 주장이 아니다. 선택된 queue가 없으면 명시 거부하고 보유 상태를 유지한다. command0은 큐를 호출하지 않는다.

기존 `QueueScriptCommand`는 즉시 큐에 넣고 첫/둘째 필드를 토큰화하므로 메타 해석에 그대로 사용할 수 없다. 특히 그 helper의 `ffffffff` 진단/거부 정책은 OnExit 메타 원문과 다르다. `DialogMetadataHooks.resolveAction`은 현재 void 관찰 API여서 해석 결과를 페이지에 반환할 수 없고, 현재 `ExtractRuntimeMetadata`는 캡처에 Trim을 적용한다. 단위370은 별도 resolveOnExit raw 캡처 훅과 현재 페이지별 resolved 두 DWORD로 이 경계를 연결했다.

원문 캡처 지역 버퍼는80/256바이트다. `00495a10`은 최대 폭만큼 복사한 뒤 종료NUL을 붙여 정확한 상한에서 한 바이트를 넘겨 쓸 수 있다. 새 모듈은 첫NUL 앞의 명령80바이트 이상/인자256바이트 이상을 명시 거부한다. 원본의 잘못된 메모리 쓰기를 호스트에서 재현하지 않는다. regex 전체, 비정상 과대 캡처, 모든 메타 파생 컨트롤의 복원을 주장하지 않는다.

## 독립 원문 관측과 검증 상태

`decomp_dialog_exit_command.py`는 제품 코드 작성 전에204개 입력을 x87 `027f/037f`에서 독립 실행했다. 두 정밀도 결과가 같았으며 실제 HTML 부모 소멸은408회 정상 반환했다. 실제 명령 수는5,266,842개다. c83b0의 캡처 후 해석/OnExit 저장 명령 구간, 원본 d52c0 명령표, C로케일 isdigit/atol,80칸 고리,40칸 큐, cf1c0 전체를 실행했다. 스택/SEH/비휘발 레지스터/x87 정상 복구도 확인했다.

거대한 regex 엔진/HTML 조건/부모 생성은 실행하지 않았고 이미 얻은 캡처를 명시 입력으로 주었다. heap 할당·반납/TLS/진단/직계 자식 조회/벽 시각/기본 Gump 소멸은 명시 경계다. 따라서 전체 c83b0 함수 또는 실제 UI 페이지 수명을 실행했다고 확대하지 않는다. 초기 관측기에서 EAX→EDI 저장 전을 종료점으로 잡았던 오류를 바로잡아 실제 `004c863c`까지 포함한 뒤 최종 fixture를 동결했다. 최종 기대 데이터는 제품 구현을 보지 않고 실제 PE 출력에서 생성했다.

새 C++ 검사는204행의 해석 필드/고리 진행/외부 순서/소멸 큐, 기존 실제 문자열 고리/입력큐, 여러 OnExit의 마지막 값, 반납 재진입/중복 방지, 미연결/물리 상한을 다룬다. 독립 작성 단계에서는 컴파일/빌드/검사를 수행하지 않았고, 이후 단위370에서 제품에 등록하여 관련39/전체2408검사 실패0을 확인했다. 해당 CMake fixture 매크로는 `NETSTORM_DIALOG_EXIT_COMMAND_FIXTURE`다.

단위370은 현재 논리 페이지 반납과 Rebuild/Resize를 구별하고, 설정 저장 뒤 지연 소멸/큐 예약을 Client에 연결하여 실제 해상도Yes의800×600저장·정상종료를 검증했다. 전체 공통HTML부모/Gump 수명/모든Tell·메뉴·HUD·게임 전체 동일성은 별도 후속이며, 이 독립 모듈이나 해상도 경로 통과로 전체 완료를 주장하지 않는다.
