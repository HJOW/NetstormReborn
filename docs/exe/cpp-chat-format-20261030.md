## 원문 해석과 부분효과

PE00504a00의 패턴은 아래와 같다. 공백 문자는 실제 CR/TAB/LF/space 바이트다.

```text
(~[^~\r\t\n ]+)+
```

부분 검색의 첫 스타일 구간을 취하며 따옴표 해석이나 전체 문자열 검증을 추가하지 않는다. VT/FF·비ASCII는 해당 부정 문자 클래스에서 허용된다. 그룹0은 최대80BYTE와 NUL을 공통0059a830에 쓰며, 그 뒤 미작성 바이트는 보존한다.0042d160은 `~0`~`~6`의 두 바이트를 제자리에서 지우고 NUL까지 앞으로 복사한다. 새 NUL 뒤 꼬리를0으로 채우지 않는다.

검색 실패는 level29의 `Illegal format` 진단을 거쳐0을 반환한다. 현재 manager0의 진단 후 복귀하면 원문처럼 현재 전역을 사용해 계속한다. 실제 물리 밖 접근은 명시 오류로 남긴다.

검색 성공 뒤 현재 manager 토큰을 고정하고 back은+0x14/60BYTE, front는+0x50/500BYTE를 복사한다. 다음 강제 NUL은 그 고정 manager의+0x4f/+0x243에 쓴다. 복사 callback이 현재 manager를 바꿔도 NUL 대상을 바꾸지 않는다. 설정 키는 이후의 현재 subscriber를 signed 십진수로 다시 읽어 `chatFormat` 또는 `chatFormat2`를 붙인다. 설정 값 역시 같은 공통 캡처를 다시 읽는다. 복사 중 ID/캡처가 변경되면 manager의 복사 내용과 Config 값이 달라질 수 있는 원문 효과를 보존했다.

`RawChatFormat`은 이 고정 패턴과 슬롯 제거를 구현한다. `ClientChatManagerGlobals`는 현재 서식 명령이 접근하는 공통 캡처의 **앞81BYTE**를 Client 수명으로 소유한다. 이 메모리는 manager 재생성 때 지우지 않는다. 공통 Regexp 버퍼 전체와 모든 소비자를 복원한 것으로 확대하지 않는다.

`ApplyClientChatFormat`은 기존 실제 strncpy·진단과 Config.Set에 연결한다. 원본 Windows-1252 바이트는 기존 UTF8 Config 경계에서 변환하고, Config 변경 알림과 디스크 저장은 기존 Client 프레임의 시점을 따른다. 명령 callback에서 저장 시점을 앞당기는 별도 SaveOptions 호출은 넣지 않았다.
