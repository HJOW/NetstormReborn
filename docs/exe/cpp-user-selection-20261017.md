# 세 인자 선택과 사제·Carrier·Archer 메뉴 입구

작업 단위142. 기준 커밋은 `c09f7a0`이며 현재 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. AGENTS와 두 LEFT 문서를 다시 읽었다. 새 디컴파일, 원본 게임/OS 창 실행, 전체화면 DirectDraw 수정은 하지 않았다. 기존 원본 파일과 기존 fixture를 보존했다.

## 실제 인자와 복원 범위

실제 Client의 임시 우클릭 메뉴를 교체하려고 VT를 조사하던 중, 사제와 Carrier의 가상+ac가 공통 메뉴보다 먼저 `4d5c90`을 호출함을 확인했다. 이를 현재 `GameWorld::Select`로 대체하면 기존 선택의 프로세스 종료, 가상 통지, 생산/운반 처리와 소리가 빠진다.

정밀 C는 `4d5c90(sid, param_2)`로 표시하지만 실제 함수는 **세 인자**를 읽는다. `4d5eb4`의 현재 ESP+28은 둘째 인자, `4d5fa6`의 ESP+2c는 셋째 인자다. 둘째는 flags1 `08000000`인 대상의 선택 허용, 셋째는 운반/이동 조건에서 강조 모드5를 활성화하는 데 사용된다. Carrier `4268c0`와 사제 thunk `492080`은 `(sid,0,0)`, Archer `41e660`은 `(sid,0,1)`을 넘긴다. extra bit1이면 선택을 건너뛰지만 공통 `4adb30`은 호출한다. 공통 메뉴의 반환 DWORD도 그대로 보존한다.

[`RawUserSelection`](../../cpppj/src/client/RawUserSelection.h)은 다음을 구현한다.

- `Select`: 시계/입력 관문, 다중 선택 정리, 기존 선택의 ProcessFinder 50/51 통지와 +7c(0)→+88→selected0, 대상 진단/생산/운반, 제단으로 되돌아가는 전체 반복, 선택 허용, +7c(1)/+88, float 기억 좌표 비교, 이동 강조/Regular/소리와 원본 반환 순서.
- `ClearMultiple`: signed 개수와 현재 배열을 매 반복에서 읽고 물리 범위 및 state&3만 검사한다. 가상 통지 뒤 개수가 줄거나 늘어나는 입력도 보존한다.
- `Remember`: flags2&30000일 때만 두 float 비트와 TYPE를 기억한다. float== 비교는 부호0/NaN/Infinity를 정수 비트 비교로 바꾸지 않는다.
- `CarrierMenu`, `ArcherMenu`: 위 세 인자 차이와 공통 +ac 호출을 보존한다. 사제 thunk는 Carrier 입구와 같다.

선택·마우스 TYPE·기억 좌표·다중 선택 저장소는 caller의 현재 참조이며 별도 게임 상태를 만들지 않는다. 기존 [`RawUserHighlight`](../../cpppj/src/client/RawUserHighlight.h)에 같은 참조를 공급할 수 있다. free/dead/contained를 원본에 없는 추가 선택 필터로 사용하지 않는다. 배열 범위 손상/종속 순환은 호스트에서 오류로 거부한다.

**큰 진단, 파생 가상+7c/+88, 프로세스+1c, 생산/운반/이동/Regular, 현재 관문, 강조와 장치는 명시 연결 경계다.** ProcessFinder의 선택 경로는 checkingDead=0·내장 상한70의 관찰 입력을 사용한다. 현재 Session/Client 소비자와 이 새 몸체를 연결하지 않았고 자연 우클릭 화면도 교체하지 않았다. 전체 목표나 모든 사용자 선택의 동일성 완료를 주장하지 않는다.

## 독립 원본 검증

[`decomp_user_selection.py`](../../tools/decomp_user_selection.py)는 보호 PE를 Unicorn에서 격리 실행한다. 선택/다중 정리/기억/세 메뉴 입구, 실제 ProcessFinder와 필터·flags 조회, float 비교/물리 범위, 강조/마우스 초기화를 포함한 **17개 몸체**를 실제 명령으로 실행한다. 정밀 함수표에 없는 `425e80`은 보호 PE의 `call 4b1bf0; ret 4` 8바이트를 별도 범위로 제한했다. C++/테스트를 읽거나 실행하여 기대 분기를 만들지 않는다.

고유 입력 **1,074개**, 두 정밀도에서 정상 반환 **2,148회**, 실제 명령 **1,129,680개**, 53/64비트 정밀도 차이 **0**이다. 실제 진입은 선택2,042·다중 정리2,048·기억984·Carrier88·Archer44·사제 thunk44회다. ProcessFinder의 next 캡처, 자산/내장 Form 필터, callback이 바꾼 타입/현재 선택/개수/좌표/extra, 제단의 재진입과 다음 관문, 둘째/셋째 인자의 독립 효과를 포함한다. 정상 반환마다 보존 GP·스택·canary·x87 제어/스택 계약을 확인했다.

초기 도구 작성 중 결과 BYTE/WORD 읽기 API와 `4971e0`의 cdecl 스택 정리를 바로잡았다. 이 오류들은 새 fixture가 처음 기록되기 전에 발견했다. 기존 기대값을 수정하거나 제품 분기를 관측 오류에 맞추지 않았다. C++ 재생의 첫 실행부터1,074행의 반환·외부 효과·현재 전역이 모두 일치했다. 예약 슬롯1/마지막23999 등 물리 입력은 검사에서 명시 주입하며 실제 게임 생성/할당 성공으로 가장하지 않는다.

## 현재 검증 상태

Release 빌드1·최종 주석 정리 빌드2는 모두 종료0·경고0·오류0이다. 집중 `UserSelection_` 3개와 최종 재생3개가 통과했다. 전체 CTest는 **1,577개·실패0·종료0·197.42초**다. 최종 빌드의 변경은 주석의 글자 교정뿐이며 동작 수정은 없다. 로그 접두부는 `extracted/goal-user-selection-20261017-`다.

원본 근거 감사는 새 도구를 포함한60종 중 **49종 성공·기존11종 실패·새 실패0**이다. 기존 실패는 단위138의 오래된 해시/누락된 추출 산출물과 같다. CMake/속성의 직전 HEAD와 같던 현재 핀만 **기존35보고서·49개** 갱신했고 이전 값을 integration_updates에 남겼다. 과거 이력/fixture를 고쳐 감사 성공을 만들지 않았다.

실제 Client 입구가 바뀌지 않아 이 단위에서 클론창 진입을 반복하지 않는다. 단위141의1-1/1-2 월드 및 tutorial1/2/3 브리핑5회 성공을 새 선택/자연 우클릭/사용자 완주 검증으로 확대하지 않는다.

CD10.72의 정밀 C 대응은 선택 `41eda0`, 기억 `41ea70`, 강조 `41ad10`, Carrier 메뉴 입구 `4e43e0`다. 이번 새 몸체와 CPU 검증은10.78 전용이고 CD를 거부한다. 다중 선택 정리/Archer 입구는 현재 정밀 대응이 없으며 CD 복원 완료로 표시하지 않는다.
