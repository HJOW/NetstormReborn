# cpppj Gump 삭제 큐·등록 해제·기본 소멸자 복원

작업 PC: **HJOW-Athlon**, 기록일: **2026-10-12**. AGENTS.md와 두 LEFT_JOBS를 먼저 읽었고 착수 시 작업 트리는 깨끗했다. 현재 PC와 마지막 디컴파일 PC가 같았다. `gumplifetime` **9/11/11개**를 Ghidra 읽기 전용으로 내보냈다. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-12.**

`GumpLifetime`은 같은 `GumpCreateNode`와 등록 표를 사용한다. 부모·자식의 삭제 요청을 큐에 넣고, 정리 단계에서 등록 해제와 가상 소멸자를 실행한다. 실제 기본 소멸자까지 연결하면 뒤의 중복 큐 항목을 비워 이미 해제한 객체를 다시 조회하지 않는다. 파생 소멸자·Form 삭제의 실제 몸체와 전체 메뉴/게임 프레임 연결은 후속이다.

## 복원한 순서

`Kill`은 각 자식의 `next`를 호출 전에 보관하고 자식을 먼저 처리한다. 현재 idle/overlay 플래그를 보고 등록을 해제한 다음, Form 플래그 `0x40`이면 현재 Form SID의 가상 삭제(0)를 호출한다. 그 뒤 현재 void 비트 `8`을 다시 읽고 필요할 때 가상 Push를 호출한다. 큐 추가 → focus/수집 override의 일치 포인터 제거 → 첫 dialog 일치 제거 → 현재 flags에 dead `0x10000` 설정 순서다. 이미 dead인 노드의 반복 요청도 큐에 넣는다.

`SetIdle`은 첫 빈 칸/첫 일치 칸을 선택한다. `SetOverlay`는 표를 끝까지 검색해 마지막 빈 칸/마지막 일치 칸을 선택한다. overlay disable의 대상이 없으면 플래그를 그대로 보존한다. 10.78의 진단 전역이 켜진 경우에만 이 부재를 원본 assert 계약으로 거부한다. `RemoveDialog`는 첫 일치 뒤의 항목을 앞으로 복사하고 마지막 칸을 0으로 만든다. 현재 dialog는 새 마지막 항목이다.

`Destroy`도 자식 우선이며 호출 전에 `next`를 보관한다. 미등록 `0x100000`이면 등록 표/개수를 그대로 둔다. 그 외에는 현재 id의 등록 칸을 비우고 개수를 감소시킨다. 10.78은 칸 제거 → 감소, CD는 감소 → 칸 제거 순서다. dead를 지우고 destroying `4`를 세운 다음 가상 scalar 소멸자(1)를 호출한다.

`Cleanup`은 현재 큐의 null 항목을 건너뛴다. 비어 있지 않은 항목은 dead를 검사한 후 실제 `Destroy`를 호출하고, **그 직후 현재 큐 개수를 다시 읽는다**. null을 건너뛸 때에는 로컬 개수를 갱신하지 않는다. 마지막에 그 로컬 개수만큼 앞쪽 큐를 비우고 개수를 0으로 만든다. 소멸자가 큐를 늘리거나 줄이는 입력도 대조했다.

`DestructBase`는 기본 가상 표를 먼저 복원한다. 10.78에서 진단이 켜졌으면 destroying을 검사한다. 현재 `+0x78` 텍스트 포인터를 free에 전달한 **뒤** 0으로 쓴다. 다음 `+0x7c` 포인터는 그 시점의 현재 값을 읽어 같은 순서로 해제한다. 이어 overlay 전체 → 실제 idle 구간 전체 → 삭제 큐 1,000칸 전체에서 자기 토큰의 모든 일치를 지운다. 기본 소멸자 자체는 등록 개수/flags/dialog/큐 개수를 변경하지 않는다.

`DeleteScalar`는 기본 소멸자를 실제 호출한 뒤 flags의 **bit 0(값 1)**일 때 객체를 free에 전달한다. 해제 뒤 객체 필드를 다시 읽지 않고 원래 this 토큰을 반환한다.

## 실제 저장소 연결과 계약

검사는 실제 `GumpCreate`로 생성하고 `GumpTree`로 부착한다. 수명 가상 Push를 실제 `GumpTree.Push`에, 가상 소멸자를 실제 `GumpLifetime.DeleteScalar`에 바인딩했다. 최종 객체 free는 노드 저장소에서 객체를 제거한다. 자식 우선 큐/분리/idle·overlay·dialog 해제/수집 결과 0/중복 요청의 한 번만 해제/등록 칸 재사용과 serial 증가까지 확인했다.

트리의 `0x4000` 교체 부착도 실제 Kill에 바인딩했다. 기존 형제는 표시 트리에서 분리되고 큐에 쌓이며 정리 전까지 등록은 유지된다. 이것은 복원 모듈 사이의 실제 연결 검사이며 전체 Client/GameWorld 메뉴가 새 저장소로 전환됐다는 뜻은 아니다.

노드 주소는 처리 중 안정되어 있어야 한다. 객체 자체의 해제는 자기 가상 소멸자/free 경계에서만 수행한다. 텍스트 free는 객체를 해제하지 않는다. 잘못된 토큰/링크 순환/표 범위/idle·overlay 플래그 불일치/등록 개수 음수/누락 경계는 호스트 예외로 거부한다. 원본 assert에 도달하는 큐 추가 한도는 호스트에서 위험한 쓰기 전에 거부한다. 이미 수행한 정상 쓰기는 콜백 예외 때 그대로 남긴다. 손상 입력의 원본 assert 실행이나 실제 PE 예외 전파는 이번 근거에 포함하지 않는다.
