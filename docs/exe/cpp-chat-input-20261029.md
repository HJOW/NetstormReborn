# 실제 채팅 입력줄 표시와 키 입력 — 단위573

Enter로 실제 Console을 열고 일반 문자·Backspace를 편집하는 경로를 연결했다. `inputLineOff`의 프레임말 전환도 원본 순서로 복원했다. 원문 378개 사례의 두 정밀도 관측·재관측 차이는 0이며, 집중 검사 49개가 모두 통과했다. Release 검사·게임 빌드의 경고와 오류는 0이다. [원문 관측](../../cpppj/chat-input-native-20261029.json)과 [검증 집계](../../cpppj/chat-input-runtime-20261029.json)를 따른다.

## 복원한 동작

- 원본 `004d8c60`의 Enter는 Guide/Gump의 선행 소비와 `00565dd4` 모달 관문 뒤, 게임 정지 관문 앞에 있다. 문자 코드13을 사용하며 가상 키 `000d0000`과 구별한다. 뗌은 거부하고 Ctrl/Shift/Alt를 추가로 거부하지 않는다. 입력줄이 숨겨져 있을 때 `0042f270(1)`로 표시하고 `0042e410`의 `ToggleBottomGump(0,1)`을 현재 Chat 부모에 Bubble한다. 같은 사건을 새 Console에 다시 보내 즉시 제출하지 않는다.
- `0042f310`은 현재 Chat이 없으면 0, 있으면 현재 Console의 표시 비트만 반환한다. `0042f210`은 Console만 Push한 뒤 현재 Chat/Console을 다시 읽고 표시 비트1을 반전한다. Console 자체의 좌표로 parent0/mode0 Attach를 호출한다. root Push·전체 자식 크기 갱신·입력 초기화를 추가하지 않는다.
- `0054db18`은 BSS0으로 시작하는 전환 요청이다. `inputLineOff`를 옵션 해석 때 읽고, 원본 `00439b96`처럼 양쪽 프레임 갱신 가지의 그리기 뒤·커서/Sleep 앞에서 전환 후0으로 소비한다. callback이 실패하면 요청을 남긴다. 설정값 자체는 남으므로 다른 옵션의 재해석에서 요청이 다시 읽히는 것도 보존했다.
- `RawMenuControls`의 보고서는 현재 Chat 포인터·요청·Console flags·실제 입력 BYTE를 읽기만 한다. `--ui-script`의 `enter`, `tab`, `backspace` 이름은 WM_CHAR와 같은 하위 코드13/9/8로 큐에 넣는다. Tab 자동완성은 이번 실행에서 사용하지 않았다.
