# cpppj 단위720 — 원본 저장 맵의 전체 표면·Graph 대조와 분석기 재실행

2026-11-02 / HJOW-Athlon / Windows 10. 마지막 전체 정밀 디컴파일은 HJOW-Athlon·2026-10-23이다. 이번에는 다시 디컴파일하지 않았다. 게임 제품은 **719 / 11.01**을 유지하며 C++ 게임 소스를 바꾸거나 재빌드하지 않았다. 분석 도구와 원본 관측을 보완했다. 전체 목표는 미완료이고, 사용자가 요청한 대로 이 단위의 문서 반영·커밋 후 목표를 일시 중지한다.

## 확인한 결과

원본과 현재 제품의 **전체674개 surface 타입·상태·소유자·float32 좌표**가 다중집합으로 일치한다. 누락/추가 모두0이다. 원본 TYPE188개의 실제 `flags1 & 0x800`로 surface 타입82·97·98·157·162를 판정하므로 이 맵에 있던97만 고른 비교가 아니다. 해당 Fort의 SHA-256은 `545c0f12ad4db7f3dc3ebe3ff8565abf9d0114d967d1973a5548b203ed8715e0`이다.

그림 frame은206개 일치하고468개 다르다. 이를 Graph 합계 통과에 포함하지 않으며 원인·난수 상태·지면 frame 재생성 시점은 확인하지 않았다. 전체 화면/원시 Pool/개별 Graph 소속 동일성의 성공으로 확대하지 않는다. Graph 번호1→2와 할당 SID는 각 수명의 값이고 세 번째 Graph WORD는 미정 바이트일 수 있어 판정하지 않는다. 원본 배치 직후의 **장부678과 실제 소속670의 차이8**도 그대로 보존했으며 임의로 정규화하지 않았다.

과거493~494의 “배치 직후1/694 → 재적재0”과 같은 입력을 재실행한 결과는 아니다. 현재 `RawSurfaceWorld::BeginLoad`의 `graphsEnabled=true`는 이미 `cb4137c5324c951ddf6cb7790302f52f17e2370f`(20261028-31)에서 반영됐다. 원본 AddIsland의 Generate → Populate → Graph(0) → WriteTerritory와 현재 호출 연결도 확인했다. 이번 한 맵에서0이 재현되지 않았다는 사실과 과거 수정의 원인을 구별한다. 새 Graph 규칙 수정은 없다.

## 원본 관측의 경계

`tools/cpp_editor_graph_original.py`는 기존 analyzeManager CLI의 명시 세션을 사용한다. 메모리 관측은 소유 복사본의 정확한 경로·PID 생성시각·원본 EXE SHA·MZ를 검증한 뒤 `QUERY_LIMITED_INFORMATION | VM_READ`만 요청한다. 게임 메모리 쓰기·시계 주입·중단·디버거 API는 없다.

실제 원본 Pool은 **120000슬롯 × 50BYTE**다. 16비트 SID 범위로 자르지 않고 전체6000000BYTE와 TYPE188×500BYTE, Graph255×6BYTE를 읽었다. 관련 Pool 필드와 Graph 표를 다시 읽어 일관성을 확인했다. 최종 surface 플래그는 `0x800`이다. 초기 진단 snapshot의 파생 histogram은 그림/장식 비트`0x08000000`을 잘못 썼으므로 원시 파일은 보존하고 정확한 플래그로 별도 고정 표를 만들었다. 잘못된 파생 histogram을 정답으로 사용하지 않는다.

원본 전용 실행은4수명(PID1516·4364·1464·11128)이다. 첫 수명은 시작 안내 단계에서 끝났고, PID4364에서 실제 맵 생성/배치/저장, PID11128에서 최종 재적재를 확인했다. 큰 원시 Pool·TYPE·Graph와 화면·입력·CLI 실패 로그는 `extracted/cpp-editor-graph-720/` 및 같은 analyzeManager 세션에 남아 있다.

- 사용자는 앞서 실행 중이던 게임을 실수로 직접 종료했다고 설명했다. **그 중간 종료는 사용자 종료로 기록하며 비정상 종료/게임 결함으로 보지 않는다.** 발언에 PID는 없어 개별 PID에 단정해 배정하지 않는다. CLI45초 응답 대기 만료는 별도 관측이고, 게임 종료의 원인으로 확정하지 않는다.
- 최초 analyzeManager 자동 녹화는 기본 출력 오디오 캡처 `0x80070490 / 요소 없음`으로 실패했다. AV 녹화 성공/소리 검증으로 세지 않는다. 최종 재실행은 명시 녹화 생략 상태다.
- 최초 WGC는 `FrameArrived timed out`, 창 재선택 후 `window capture timed out`이었다. 동일 WGC 캡처를 반복하지 않고 기존 analyzeManager의 화면 복사 캡처와 Computer Use 입력을 사용했다. 물리 사용자 키 입력 검증은 아니다.
- 저장 뒤 첫 메인 메뉴 대기 중 의도하지 않은 Auto-Demo가 시작됐다. 화면을 확인하고 소유 세션을 종료했으며, 전투 관측·특정 적 공격/승리 재현의 성공 근거로 사용하지 않는다. 후속 실행은 복사본 설정에서 autoDemo0을 확인했다.
- 목록을 한 맵으로 제한하기 위해 다른 Fort433개를 **분석 복사본 안에서** 별도 보관했다. originals/CD는 바꾸지 않았다. 재실행을 위한 options/setup 변경도 분석 복사본 전용이다.

## 분석기 변경

`restart_session`은 종료 상태·최초 EXE SHA·다른 살아 있는 소유 세션을 확인한 뒤 **같은 작업 복사본**을 새 PID/생성시각으로 실행한다. 기존 맵·설정·이벤트를 유지한다. 새 세션을 복사해 원본이 만든 맵을 잃는 문제를 피한다. 실제 실행 전 확인 조건은 기존 start_session과 같다.

start/restart의 `automaticRecording` 기본값은true다. 화면/상태만 비교할 때 false를 명시할 수 있다. 이 경우 녹화 장치를 열지 않고 `automatic_recording_skipped` 이벤트와 `automaticRecordingRequested=false`, 현재 녹화 상태null을 반환한다. 종료 응답도 같은 규칙을 쓴다. 이전 실행의 오디오 실패 파일을 삭제하거나 성공으로 바꾸지 않는다. 사용법은 [analyzeManager 문서](../analyze-manager.md)를 따른다.
