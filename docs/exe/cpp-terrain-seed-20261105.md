# 군도 첫 청크 시드와 공유 지형 흩뿌리기

단위892는 패치 `004c0e20/004c13f0`과 CD `0049de40/0049e4e0`의 공유 지형 부품을 복원한다. 전체 군도 생성 상위 `004c1510`의 연결은 다음 단위로 이월하며, 일반 생성에 첫 시드 조회를 삽입하지 않았다. **전체 cpppj 목표는 미완료**다. 마지막 전체 정밀 디컴파일과 현재 분석 호스트는 **HJOW-Athlon / 2026-11-03**으로 같다. 정밀 산출물과 보호 원본은 수정하지 않았다.

## 원문과 제품 변경

`RawTerrainGrowth::FirstChunkSeed`는 현재 청크 bounds를 Y외부/X내부로 순회한다. signed island BYTE를 전체 signed noRegion DWORD와 비교하고, 첫 불일치 청크의 raw+5, 즉 `record[3]`를 반환한다. 섬 번호나 영역 번호를 시드로 대체하지 않는다. 실패하면 패치만 현재 checking DWORD가 비영인 경우 `0 / \Ns\O\Terrainbuilder.cpp / 0x25f`를 보고하며, 정상 복귀 후 `0x2333`을 반환한다. CD는 같은 실패를 보고하지 않고 noRegion을 조회 진입 때 캐시한다.

패치의 실제 청크 getter `00432180`도 실행 경계에 포함했다. mode0이면 `isValid()`/`0xb7`, 좌표 범위 오류면 원문 combined 표현식/`0xb8`을 `\Ns\O\Chunkmap.cpp`로 보고한 뒤 현재 청크를 clamp 조회한다. 이 두 getter 진단은 checking으로 막지 않는다. 진단 효과가 mode/noRegion/청크/경계를 바꾼 뒤의 현재 값과 패치·CD 차이를 보존한다. C++는 선택된 진단의 장치가 없을 때 명시적 오류를 내며, 정상 입력의 진입 단계에서 미사용 장치를 요구하지 않는다.

`RawTerrainGrowth::Scatter`는 count0이어도 첫 시드를 한 번 구하고, 시드×93의 로컬 PRNG로 두 좌표를 뽑는다. 각 칸 bounds의 +2/−2 반열린 범위이며, 비양수 폭에서는 그 최솟값을 반환하고 난수를 소비하지 않는다. 섬이 없거나 섬0인 칸만 `x/region0`으로 쓰고 count를 줄인다. 기존 문자/지역과 중복 여부를 성공 조건에 추가하지 않는다. 패치의 float32 저장→ftol 하위DWORD→0방향/16과 CD의 직접 정수/x87 변환 차이도 구분한다. 게임 전역 난수는 소비하지 않는다.

성공 가능한 칸이 없는 입력에서는 원문에도 재시도 한계가 없다. 제품에 종료 횟수나 성공을 합성하지 않았다. 실제 배열 밖 손상 쓰기는 기존 C++ `Index`의 호스트 오류 경계를 유지한다. 음수 count/손상 주소의 임의 메모리 실행 전체를 지원했다는 뜻은 아니다.

## 검사 범위

새 `tools/decomp_terrain_seed.py`는 현재 양판본 전체 `functions.tsv`의 불연속 주소 범위와 보호 PE만 읽는다. 첫 조회/흩뿌리기·실제 청크 getter/섬 조회·로컬 PRNG·실제 ftol을 실행하고, 진단 표시만 명시 외부 경계로 둔다. 원본이나 게임 창, OS API를 구동하지 않는다.

- 판본별189행, 합계 **378개 고유 입력**을 관찰했다. 첫 조회222행/흩뿌리기156행이며, x87 `0x027f/0x037f` 반복은 고유 입력 수에 더하지 않는다. 생성 뒤 `--verify`로 전체를 재관측했으며 fixture를 다시 쓰지 않았다.
- 반환 스택·비휘발 레지스터·x87 스택·스택 canary와 청크/게임 난수의 불변을 확인했다. 진단의 표현식/파일/행, 실제 getter 방문 순서/PRNG 횟수, 전체 code/region 각각65,536BYTE를 기록했다. C++는 원문 기대 배열 전체와 진단 목록을 대조한다.
- 첫 fixture 생성 중 profile10/noRegion−1/count54가 2,000,000명령 후 반환하지 않는 것을 확인했다. 성공 칸이 없는 입력을 정상 반환 목록에서 제외하고, 판본별20,000명령의 **반환 없음·쓰기0** 증거로 분리했다. 이 증거는 fixture 행 수에 포함하지 않으며 C++ 무한 반복 검사는 하지 않는다. 원본 range 호출은 패치160/CD192회였다.
- 새4사례는 원문 첫 조회·흩뿌리기, 같은 checking owner의 현재 값/선택 장치 누락, 일반 분기가 첫 시드를 조회하지 않는 경계를 확인한다. 기존 일반 성장108행/초기 context224행/실제 일반 월드 바인딩3사례를 같은 집중 대상에 포함했다.

Release 제품/집중 대상 빌드301.294초와 검사 전용 재빌드11.103초가 성공했다. 최초 검사 입력의 int→BYTE 변환 경고2개를 명시적 BYTE값으로 교정했으며 마지막 빌드의 경고/오류는0이다. 최초11개와 교정 후 새4개를 실행해 **고유11사례/새4·2명령/15실행·실패0**이다. 검사 전용 교정 뒤 제품SHA가 같은 것도 확인했다.
