# C++ 공간 해시·발자국 점유 비트 복원

2026-10-06. [표면 이웃/재귀 복원](cpp-surface-reconstruction.md)의 다음 기반으로 **4단계 해시 배열, 버킷 주소, 객체의 해시 단계, 발자국의 유효 genus**를 복원했다. 패치판 10.78과 CD판 10.72의 실제 기계어를 격리 메모리에서 실행했고 원본/복사본/클론 GUI는 실행하지 않았다.

소스는 새 [SquidHash.h](../../cpppj/src/o/SquidHash.h)·[SquidHash.cpp](../../cpppj/src/o/SquidHash.cpp)와 [Squid.cpp](../../cpppj/src/o/Squid.cpp)의 `EffectiveGenus`다. **현재는 지도 저장/주소 계산과 점유 비트 계산의 복원이다. 실제 공간 체인의 등록·해제, SID 할당/반납, spot 등록/제거, GameWorld 연결은 남았다.** 다리 배치 UI·전체 붕괴·건설/경제/전투/AI/승패는 아직 없으며 미션 완주는 불가능하다.

## 2. 표면 배열과 발자국의 관계

원본 단계별 버킷 크기는 패치 `005424f8`, CD `0052d598`의 **1·2·4·16**이다. 보드 한 변 256에서 배열 한 변은 **256·128·64·16**, 전체 머리 수는 **86,272개**다. 초기화는 선택 단계와 관계없이 네 배열을 모두 0으로 지운 뒤 선택 상태를 복구한다.

**표면 조회 전역 `005c84bc`/CD `0052d590`는 별도로 발자국을 채운 배열이 아니라 0단계 해시 배열의 주소다.** 버킷에는 객체 번호 체인의 머리가 있다. `Squid`의 등록 함수 `004b02d0`는 `004ace40`→`004b2a90`로 기준점의 버킷을 고르고 기존 머리를 객체의 next 필드로 연결한 뒤 새 번호를 머리에 쓴다. spot 바이트는 별도의 발자국 반복에서 보정한다. 이 등록 함수 전체는 아직 C++로 옮기지 않았다.

앞선 SurfaceFinder 테스트에서 번호를 여러 셀에 배치한 입력은 실제 탐색기의 중복 제거를 검증하는 합성 입력이었다. 그것을 **원본 등록 함수가 객체의 전체 발자국에 같은 번호를 쓰는 근거로 해석하지 않는다.** 큰 표면과 `noIsland` 등 실제 객체의 생성/등록 순서를 추가로 복원해야 한다.

버킷 좌표 변환은 plain `_ftol` 후 단계 크기로 나누는 계산이다. 예를 들어 월드 x=20.25는 0단계 x=20, 1단계 x=10이다. `Cell`/`At`의 정수 좌표는 이미 변환한 버킷 칸이며 월드 칸을 다시 나누지 않는다. 기존 표면 조회나 spot에서 쓰는 `+0.9999f`는 **해시 주소 변환에 넣지 않는다.**

객체의 해시 단계는 발자국 대신 **현재 SHP 헤더의 크기**를 사용한다. 섬/다리 genus 비트 2/4가 있으면 0이다. 그 외에는 가로/세로의 최댓값이 2 이하이면 1, 4 이하이면 2, 더 크면 3이다. C++ 인터페이스는 확인한 헤더 크기를 명시적으로 받는다.

## 3. 유효 genus와 좌표 정밀도

`Squid::EffectiveGenus`는 타입 플래그 2 전체를 보존하고 발자국 칸의 안쪽 비트 8만 보정한다. 실제 건물군 마스크는 두 판본 모두 **`0x50444200`**이다. 기준점에는 float 비트 `3f7ff972`의 `0.9999f`를 더한 뒤 0 방향으로 절삭한다. 원본의 x87 중간 합을 C++에서 다시 float로 좁히지 않는다.

오른쪽 아래 기준점과 폭/높이로 발자국 네 변을 정한다. 칸이 네 변 중 하나에 있으면 안쪽 비트를 추가하지 않는다. 건물군이면서 네 변에 해당하지 않으면 비트 8을 붙이되, **roof 비트 `0x400000`의 정확한 중심 열에서 위쪽 절반/중앙은 제외**한다. 최종 uint를 spot byte에 저장하는 것은 이후 등록 함수의 범위다.

이 함수는 호출자가 전달한 칸을 검사하며, 자체적으로 모든 칸을 방문하거나 지도에 쓰지 않는다. C++ 입력 검사는 보드 안의 정상 좌표·양수 발자국으로 제한한다. 원본 객체의 void/contained/dead 상태나 pop/unpop 효과를 대신 판단하지 않는다.

## 4. x87 실행 상태를 명시한 기계어 검증

새 [decomp_hash_oracle.py](../../tools/decomp_hash_oracle.py)는 실제 함수/보조 함수와 CRT float 변환을 실행한다. assert 보고만 대체했으며 **두 판본 모두 호출 0회**다. 허용 몸체·200,000명령 상한·복귀 EIP/ESP/`ret N`·메모리 쓰기 범위를 검사한다. 입력 타입·프레임·객체의 다른 필드에는 쓰기를 허용하지 않는다.

Unicorn의 초기 x87 제어 워드는 0이었다. 이를 그대로 쓰면 소수 좌표 점유 입력 363개에서 두 CRT 변환의 결과가 달랐다. 이것은 이번 원본 함수의 판본 차이로 채택하지 않았다. **반올림 nearest·예외 마스크를 명시한 제어 워드 `0x027f`(53비트)와 `0x037f`(64비트)**에서 float 버킷·단계·genus 입력을 두 판본 모두 실행했더니 결과가 같았다. 매 호출 후 제어 워드 보존과 x87 TOP 복구도 검사한다. 원본 프로그램의 전체 시작 함수가 설정하는 부동소수 환경을 동적 확인한 것은 아니다.

| 새 x86 기대값 | 입력 사례 | 검사 |
|---|---:|---|
| 기존 배열 초기화 | 4 | 모든 86,272머리 0·선택 보존·표면 포인터 |
| 현재 단계의 칸 주소 | 100 | 시작/가운데/끝, 단계별 한 변 |
| 지정 단계의 칸 주소 | 100 | 월드 좌표와 구별한 버킷 좌표 |
| float 버킷 주소 | 607 | 정수/버킷 경계 앞뒤·월드 끝·plain 절삭 |
| 객체 해시 단계 | 605 | 섬/다리 우선·2/4 경계·가로/세로 독립 |
| 유효 genus | 3,216 | 1×1~7×7·직사각형·지붕·소수 좌표·상위 비트 |
| 합계 | **4,632** | 두 판본 결과 일치. float 경로는 53/64비트 모두 대조 |

[HashTests.cpp](../../cpppj/tests/HashTests.cpp)의 새 6개 검사가 저장된 [hash-x86.tsv](../../cpppj/tests/fixtures/hash-x86.tsv)와 C++를 대조한다. Windows Release 빌드 경고·오류 0, **CTest 내부 87개 검사** 통과. 기존 26,868개와 합쳐 **31,500개 제한 x86 입력 사례**다. 이 중 수명 480개는 접두 구간, 이번 초기화 4개는 할당 없는 경로이며 게임 전체 일치/완성도 수치가 아니다.

[recovery-hash-evidence.json](../../cpppj/recovery-hash-evidence.json)에 바이너리·기대값·생성/공통 도구 SHA-256, 제어 워드·실행 범위·함수 대응을 저장했다. [decomp_refine.py](../../tools/decomp_refine.py)는 이 해시·x87 상태·assert 0·함수 존재/`ret N`을 확인한 뒤 **5개** 검토 앵커를 적용한다. 초기화는 malloc 분기 제외 때문에 검토 앵커에서 제외했다. 현재 전체 대응 **2,496쌍·검토 24쌍**, strong 1,738/medium 707/weak 51이다.

```powershell
python tools/decomp_hash_oracle.py
python tools/decomp_refine.py
python tools/cpp_source_map.py
cmake --build cpppj/build --config Release

```

기대값 생성에는 기존 Python/Unicorn/PE 분석 환경과 원본 EXE가 필요하다. C++ 빌드/CTest는 저장한 기대값만 읽으므로 원본 실행 파일·Python·Ghidra가 필요 없다. SOURCE_MAP 파일 존재는 29/136이며 모듈 전체 완료 수가 아니다. AGENTS.md·원본 자료·C#은 수정하지 않았고 커밋하지 않았다.

## 5. 다음 연결 순서
