# 실제 Edit State1 진입 전 cleanup·Client 수명 공백

작성일은 **2026-10-25**, 현재 PC와 마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon**, 마지막 디컴파일 날짜는 **2026-10-23**이다. 대상은 originals의 **PATCH 10.78**이다. CD 10.72의 대응 주소가 있는 것과 같은 제품 경로가 복원된 것은 구별한다.

이 문서는 단위428 최종 검증 중인 소스를 **읽기 전용으로 조사한 인계**다. 새 게임/GUI 실행, 빌드, Native oracle 실행, CPP/CMake/LEFT 변경과 커밋을 하지 않았다. 이 문서 한 개만 추가했다. `CleanupStateWorld` 전체 부모가 존재하는 것과 자연 `UberGump::Tick`에서 같은 Client 저장소로 호출되는 것은 별개이며, 후자는 아직 미연결이다. 단위426의 준비 대여/UI tail·공통 확정과427~428의 Editor 전송/Session 요청 접합을 전체 State1 완료로 합산하지 않는다.

## 판정 방법과 근거

- **A — 실제 현재 호출 API/저장소가 이미 존재:** 선언뿐 아니라 본문과 현재 소유자를 확인했다. 공개 wrapper가 없거나 조립이 남으면 그 경계를 함께 적었다.
- **B — 본문 미이식:** 해당 원문 전체 leaf의 대응 제품 본문이 없거나 일부만 있다. 주소 문자열 검색 실패만으로 판정하지 않고, 유사 모듈의 본문이 실제로 무엇을 하는지 대조했다.
- **C — Session 밖 장기 소유자 없음:** 필요한 현재 원문 물리가 Session/World 안에만 있거나, 아직 Client/Uber 수명에 배치되지 않았다. 기존 본문이 있는 **A+C**는 재구현보다 소유권 접합이 우선이다.

분류는 중복될 수 있다. A는 자연 메뉴 연결/전체 동일성 검증 완료를 뜻하지 않는다. 원문 부모와 작은 leaf의 호출을 기록한 기존 fixture도 실제 장치·실제 Client binding의 증거로 확대하지 않는다.

주 근거는 [원문 C](../../extracted/refined/originals/Netstorm.c)의 `FUN_004b2df0`·`FUN_004b6dd0` 및 각 leaf 본문, [함수 목록](../../extracted/refined/originals/functions.tsv), [현재 부모](../../cpppj/src/o/RawStateWorldCleanup.cpp), [34개 Effect 선언](../../cpppj/src/o/RawStateWorldCleanup.h)이다. `004b2df0`은 **1256BYTE**, `004b6dd0`은 **6521BYTE**다. 기존 [정리 재사용 조사](cpp-state-world-cleanup-reuse-20261024.md)는 당시 미확인 상태를 보존한 과거 문서이며, 아래의 새 본문 확인으로 일부 미확인을 좁혔다. 기존 [Native294 보고서](../../extracted/cpp-state-world-cleanup-20261024-native.json)는 부모의 순서/직접 쓰기 근거이며 모든 자식의 실제 제품 연결 증거는 아니다.

### 새 World 이전 HUD 생성과 설치 뒤 재통지를 분리한다

[ProductionControlContext](../../cpppj/src/client/ProductionControlContext.h)는 이미 **같은 ClientGameplayGlobals/RawSurfaceStorage/ClientPlayerRecords/장기87BYTE옵션**을 받아 Session 없이 전체 생산 패널을 만든다. 현재 `UberHud.inc::InstallHud()`의 선두 `if (!world_) return`을 없애기만 하면 createProduction의 `world_->Session().ProductionContext()`, createMinimap의 BindWorld/카메라 콜백, 마지막 BindMapView에서 실패한다. **이 함수를 그대로 앞당겨서는 안 된다.** 같은 기존 네 공장/공통 트리를 보존하면서 다음 두 단계를 연결한다.

- **cleanup/초기 prefix:** ProductionControlContext를 Client/Uber의 현재 owner에서 직접 구성해 `ConstructProduction`에 준다. 미니맵도 이미 `ConstructMinimap(storage,hooks)`를 제공하므로 같은 실제 storage로 생성하고 아직 Pop/Unpop을 빌리지 않는다. root Replace/자식/등록/초기 도킹·현재 전역·초기 HUD 통지를 실제로 수행한다. 생성 시점에 필요한 카메라/지도 전역은 장기 HUD/Client owner를 제공하고, 나중에 사용될 실제 월드 효과는 그 도달 위치에서 Session을 요구한다. 생성할 필요가 없는 효과를 빈 성공으로 실행하는 방식은 피한다.
- **checkpoint 후 tail:** 같은 패널/미니맵을 새로 만들지 않고 현재 Runtime에 미니맵 BindWorld/MapView를 연결한 뒤, 단위426의 UI scope에서 기존 실제 Form/Sync와 원문 HUD 재통지를 실행한다. scope 밖에서 `RequireSession()`을 호출하거나 첫 prefix 통지를 후반 한 번으로 합치지 않는다. 실패하면 부분 Gump/표 상태를 보존한 채 loaded를 공개하지 않는다.

## 실제 제품 연결까지 권고하는 다섯 작업 단위

각 단위의 정확 범위/검증 후 인계와 로컬 커밋은 root 작업에서 수행한다. 이 문서 작성자는 코드/인계/커밋을 하지 않았다.

1. **Client cleanup 전역과 작은 누락 leaf.** 현재 long owner를 먼저 주소별로 연결하고, clock-sync/MetaZone flag·기록/Zone/255DWORD/20 pool-header/Pool wrapper의 두40DWORD·위치값 등 미소유 필드의 실제 초기화와 공유 소비자를 정리한다. 연결22칸/보조표도 기존 두 로컬 전송의 수명과 연결한다. 기존 Chat/SP/Template/Clock/Sound 본문을 새로 만들지 않는다. 첫reset1과 각 폭/순서·반복 재조회 검사를 둔다.
2. **Session 내부 물리의 장기 수명 접합.** Graph 기록·stack, Island3204BYTE, Chunk mode·크기·셀, TotalMade 세표, 사제 ownerState, cursor lifecycle/선택의 현재 데이터를 실제 Client/Storage 수명으로 옮기거나 대여하도록 한다. 기존 Raw 본문을 같은 저장소에 바인딩하고 준비 Session에서 ctor reset을 반복하지 않게 한다. 신규 지역 graph 생성과 Native reset을 구별하는 검사, padding/255번째 경계 보존을 확인한다.
3. **34개 Effect와 비enum hook의 실제 adapter.** 같은 owner로 CleanupStateWorld(0)을 실행한다. Kernel 단일Clear, Gump 제외타입/Kill/Cleanup/Replace, 현재 budget SP표시와 Core0→Player재할당→Core1을 순서대로 연결한다. 처음 MainMenu에서 자연 생략되는 하위와 도달 시 오류인 미지원 재진입을 구별하고, 이전 Session의 C++ 소멸이 부모 효과를 중복하지 않게 반납 계약을 만든다.
4. **Session 없는 초기 HUD와 State1 prefix.** 기존 InstallHud의 네 공장/트리를 초기 문맥으로 재사용하고, 위 prefix의 로컬 전송/모드/Core1/renderer/Chunk/옵션/HUD 통지를 실제 순서로 조립한다. 같은 owner 정체성을 고정한 뒤 준비 대여 Session을 만든다. prefix에서 실제 HUD가 생성됐는지와 후반 재통지가 분리됐는지 검사한다.
5. **자연 Tick State1→기존 checkpoint→tail→공통 확정 접합.** 기존 파일 선택의 전체144BYTE 요청/old/phase를 유지하며 checkpoint와 한정 UI scope/Commit을 연결한다. 실제 Edit 진입·기존 맵 편집·저장/재열기의 집중 검증으로 이어가고, 같은 최종 제품에서 root의 통합 CTest/자연 플레이 묶음을 수행한다. 도달하지 않은 신규 맵/시나리오·다른 재진입·전체 미션 완주를 완료로 세지 않는다.

현재 조사로 새 전체 cleanup 모듈을 또 만들 근거는 없다. **이미 있는 작은 본문을 같은 실제 owner와 원문 위치에 연결하는 작업**과, B/C로 명시한 누락 본문·장기 물리를 채우는 작업이 남아 있다.
