# 다리 저장 프레임과 지면 생성

> 2026-09-28 · 원본 실행 파일·타입 정의 분석, 개발용 렌더링 구현

## 다리: 저장 값은 각 칸의 프레임 번호

`Template` 저장 `004bd940`은 bridge 플래그가 켜져 있을 때 오브젝트의 `+0x24` 값을
1바이트로 저장하고, 읽기 `004bdc60`은 같은 위치에 복원한다. 이 필드는 애니메이션 프레임이다.
따라서 `.fort`의 `bridge` 값은 이웃 방향 비트나 생산 창 다리 조각 번호가 아니라
**이미 배치된 각 칸의 bridge 클러스터 번호**다.

| 저장 값 | bridge.type 클러스터 | 모습 |
|---|---|---|
| 0 | A01 | 기본 연결 |
| 35 | J01 | 세로 판자 |
| 41 | K01 | 가로 판자 |

손상·강화 프레임도 클러스터에 있으므로 저장 값을 그대로 사용한다.
원본 463개 파일의 모든 저장 다리 값이 실제 클러스터 범위에 들어간다.
`MapSpriteFrames.BodyFrame`은 타입의 레이어 수를 적용하여 셰이프 본체 프레임을 구한다.

VA `0x52f998`의 복합 패턴은 **새 다리 조각을 생성·배치할 때** 쓰는 별도 데이터다.
배치된 다리의 정적 렌더링에는 이 표를 적용하지 않는다. 이전 인수인계의
"저장된 bridge 값이 복합 패턴 번호" 추정은 정정했다.

## 지면 생성의 확인된 흐름

`Terrainbuilder`의 `004c10a0`은 각 영역 청크에 중심부와 연결 통로를 만든 뒤,
청크별 시드로 지면을 성장시키고 빈 틈을 두 차례 보정한다.

* 패턴의 방향 문자 A~P는 청크 연결 비트로 대응한다. VA `0x52f910`:
  `15,7,14,13,11,6,12,9,3,5,10,4,8,1,2,0` (북=1, 동=2, 남=4, 서=8).
* `Territory` 오프셋 3은 단순 외관 번호가 아니라 **청크 중심 위치와 성장 시드에 참여하는 값**이다.
* 중심 좌표는 청크 시작에 `(4 + (seed & 7), 4 + ((9999 - seed) & 7))`를 더한다.
* 중심 주변 4×4칸과 폭 2칸 연결 통로를 만든다. 각 영역의 두 번째 청크는 추가 10×10칸을 채운다.
* `004c0ec0`은 영역별 청크 카운터에 `0x10e3`을 곱하고 저장 시드를 더하여 성장 시드를 만든다.
* `004c0800`은 기존 지면에 접하는 3×3칸을 추가한다. 새 지면이 생기면 최대 실패 횟수 1,000을 초기화한다.
* 정수 난수 `004bca20`: 시드 0이면 `0x0bad0bad`, 다음 상태는 `state * 0x10003 + 3`의
  32비트 오버플로 결과, 출력은 상위 16비트의 나머지다.

## 지면 타일 선택

`004c04b0`은 직선 네 이웃과 대각선 네 이웃을 검사하여 두 방향 문자를 만든다.
비트→문자 표 VA `0x52f8fc`는 `PNOILJFBMHKEGDCA`다.
`isle.type`의 `AA`, `AB`, `BF`, `CG` 같은 클러스터 이름 앞 두 글자에 대응한다.

직접 대응되는 타일이 없으면 `0041cd20`은 양쪽 직선 이웃이 지지하는 대각선만 남기고
연결을 정규화한다. 원본 타일의 그림 참조에는 네 원소별 이미지가 있으며
`RA*`=비, `TH*`=천둥, `WI*`=바람, 나머지=태양으로 구별할 수 있다.

## 현재 구현의 검증 범위와 제한

`FortTerrainPreview`는 위 연결·시드 성장 흐름을 바탕으로 지면 미리보기를 생성한다.
Save the Island!, The War Begins! 두 맵의 반복 생성 결과가 같고 모든 타일 좌표·클러스터가 유효하다.
비 테마 타일이 다른 원소의 이미지로 바뀌지 않는 회귀 검사도 추가했다.
Windows에서 Save the Island!, The War Begins!, 느슨한 b0.fort를 각각 실행하여 PNG 캡처를 저장했다.
검증 이미지는 `extracted/screens/fort-map-terrain-*.png`에 있으며 추출 결과이므로 저장소에는 포함하지 않는다.

**원본 지면을 픽셀 단위로 재현했다고 확정한 구현은 아니다.** 현재 다음 차이가 있다.

* 원소는 해당 영역의 신전에서 추정한다. 건물 받침은 소유자의 신전 테마로 그린다.
  원본의 플레이어 원소 선택 및 중립 영역 규칙을 직접 옮긴 것은 아니다.
* 시각적 타일 변형은 좌표로 고정한다. 원본의 전역 난수·프레임 선택 및 3×3 큰 타일 선택은 미구현이다.
* 작은 받침 섬은 `noIsland` 셀과 `createsisland` 건물 발자국으로 미리보기한다.
  원본 받침 생성 과정, 지면 하단 절벽·그림자·장식은 아직 재현하지 않는다.
* 게임 모드별 특수 섬 생성, 일반 전투 섬 재배치, 패턴 셀의 세부 변형을 검증해야 한다.

후속 작업은 원본 캡처와 좌표를 맞춰 지면 마스크·타일 선택·하단 절벽을 순서대로 대조하는 것이다.
