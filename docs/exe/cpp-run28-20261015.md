# 단위28: 실제 초기 카메라 선택·중심 이동과 캠페인 설치 연결

기준은 `b4113da`다. 작업 전에 AGENTS와 두 LEFT를 다시 읽었다. 현재 및 마지막 정밀 디컴파일 PC는 **VM-W11-Codex, 2026-10-15**다. 사용자 `TODO.md` 수정은 보존한다.

## 복원한 동작

원본 초기 시야는 신전 우선 선택과 다르다. PATCH `004340d0`/CD `00488f50`은 SID 2부터 사용 중인 슬롯을 순서대로 읽고, 요새/전투 모드에서 현재 로컬 플레이어의 사제 genus `0x200000`을 만날 때마다 대상을 갱신한다. free만 건너뛰므로 마지막 후보가 dead이면 `CenterOn`이 자연 반환하고 이전 살아 있는 사제로 다시 돌아가지 않는다. void 후보는 중심 이동 대상이다.

`CameraHome`에 초기 선택, 실제 `CenterOn`과 중심 좌표 변환을 연결했다. `CenterOn`은 현재 raw 좌표에서 TYPE의 **전체 footX/footY**를 뺀 후 float에 저장한다. 발자국 절반이나 `(크기-1)/2`를 사용하지 않는다. 중심 변환은 원본처럼 음수 16/11 배율과 실제 ftol 결과의 하위 DWORD를 사용한 뒤 화면 폭/높이의 정수 절반을 차감한다. `+0.5` 반올림 보정이나 월드 범위 clamp는 없다.

초기화의 Carrier 표시 억제 깊이와 카메라 요청/변환 갱신 카운터를 보존한다. 원본 Carrier `00426080`/CD `004e36f0`은 reset의 깊이가 비영점인 동안 실제 조건에서 표시 프로세스를 만들지 않는다. 화면 적용이 C++ 예외를 던지면 억제 깊이를 복구하며 앞서 증가한 요청/변환 번호를 취소하지 않는다.

Challenge에서 대상 좌표를 실제로 얻는 경로와 빈 목록의 월드 중심 경로도 보존했다. 원본의 좌표 미초기화 스택을 읽는 Challenge 경로와 억제 깊이 UINT_MAX 감김은 명시 거부한다. 현재 목표의 일반 캠페인은 이 두 경로를 사용하지 않는다.

## 실제 세션 연결

실제 캠페인용 `GameWorld` 생성자는 이제 로더 실행 전에 실제 `viewport` 크기를 받는다. 같은 로더의 Graph 재구성 뒤 `install.resetCamera`를 월드가 직접 공급한다. 외부 카메라 관찰 콜백은 필요하지 않다. `RawCampaignSession::ResetCamera`가 같은 Pool/TYPE와 실제 로컬 소유자·모드를 읽고 원점을 현재 raw 표시·음향 영역에 전달한다.

설치 후 첫 Resize에서 이전 신전 우선 Home이 다시 실행되지 않게 실제 화면 크기를 먼저 보관한다. 두 실제 미션 데이터 검사에서는 외부 resetCamera를 비워도 생성이 성공하고, 사제 좌표에서 전체 footX/footY를 뺀 지점이 1024×768 화면의 (512,384)에 놓이는지 확인했다.

이전 Tutorial 어댑터의 수동 Home/F4/F5·Scroll과 가변 패널 배치는 별도다. 이번 연결은 실제 raw 캠페인의 초기 시야다. 원본 Renderer의 거대한 commit 내부 전체 복원이나 실제 Battle GUI 진입 검증을 완료한 것으로 해석하지 않는다.

## 원본과 C++ 대조

현재 호스트의 정밀 프로젝트에서 판본별 10함수, 고유 **20함수**를 읽기 전용 내보냈다. `tools/ghidra/camera-home-functions.json`에 초기 선택/반복자/CenterOn/중심 요청/TYPE getter/Carrier 표시 억제/실제 ftol 몸체를 기록한다. 최초 PATCH 9함수 목록에는 TYPE 인덱스 하위 `0049a840`이 빠져 격리 실행이 허용되지 않은 주소에서 중단됐다. 실제 원문을 읽어 이 몸체를 추가했고 최종 실행은 하위 대체 없이 완료했다. 실패 로그는 `extracted/run28-native-first.log`이며 당시 fixture/report는 생성하지 않았다.

`tools/decomp_camera_home.py`는 실제 PE 명령을 실행하며 Renderer commit만 관찰 경계로 둔다. 원본의 최종 원점과 호출 시점 억제 깊이/요청/변환 번호, 반환 뒤 카운터를 기록한다. x87 제어워드 `0x027f`와 스택 깊이, Carrier의 SEH 머리 복구도 확인한다.

새 고유 입력은 판본별 **1,182개**, 총 **2,364개 정상 반환·assert 0**이다. 빈 목록/단일·복수 사제/신전·다른 walker/다른 owner/마지막 free·dead·void/전체 DWORD 로컬 번호 257/분수·음수·NaN·무한대 좌표/다른 발자국/홀수 화면 크기/갱신 번호 감김/정의된 Challenge 경로를 포함한다. 원본 판단으로 기대값을 계산하지 않고 실제 요청만 fixture로 기록했다.

C++은 같은 물리 슬롯 입력을 fixture에서 읽어 두 판본의 전체 원점·카운터를 대조했다. 원본 격리 풀은 128슬롯, C++은 기존 SID 풀 계약에 따라 24,000슬롯을 사용하며 128 이상은 전부 free다. 같은 사용 중인 번호와 선택 결과를 비교한다. 실제 게임의 전체 Pool/Renderer 수명 동일성 검증과는 구별한다.

근거는 `cpppj/camera-home.json`, `cpppj/tests/fixtures/camera-home-x86.tsv`, `extracted/camera-home/` 및 `extracted/run28-native-final.log`다. 원본 두 PE/정밀 내보내기/도구/공용 격리 실행기/fixture SHA를 기록했다. 같은 입력 재실행은 새 고유 입력으로 합산하지 않는다.

## 빌드와 후속

최종 Release 빌드는 경고·오류 없이 성공했다. 새 집중 **3개**, 실제 캠페인 세션 **5개**가 통과했다. 실제 교전 결과는 첫 피해 frame173·HP1 frame178·종료 frame898이다. 최종 전체 CTest는 **1/1 통과·내부1,145개·실패 체크0**(110.36초)다. 로그는 `extracted/run28-build-final.log`, `run28-camera.log`, `run28-session.log`, `run28-all.log`이며 내부 개수는 `cpppj/build/Testing/Temporary/LastTest.log`에서 확인했다.

다음은 실제 `install.translateYou/setConfig`·음향/UI/owner 통지·Ready/login과 미션 규칙 연결이다. Battle 진입 차단과 Early Missions 및 캠페인 1-1~1-2 진행·완주 동일성은 **미완료**다. 목표는 active로 유지하며 DirectDraw 전체화면 오류 수정은 제외한다. 원본 두 PE의 최종 SHA-256은 정밀 재생성 및 `cpppj/camera-home.json`의 기준값과 같다. AGENTS·dotnetpj·보호 원본 파일을 편집하지 않았다. 인수인계 뒤 로컬 `20261015-14 실제 초기 카메라 복원과 캠페인 설치 시야 연결 검증`으로 커밋하며 원격 push는 하지 않는다.
