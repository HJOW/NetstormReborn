## 실제 오류와 다음 복원

`bc5walkers76`은148프레임/game9.812초까지 플레이 장면/진단6을 관측한 뒤 `Burning sources 새 행 인덱스 오류`로 종료1이다. 현재 C++ 선택기는 아래 픽셀의 불투명 여부보다 row 경계를 먼저 검사한다. 읽기 전용 정밀 원문의424110은 픽셀이 불투명할 때에만 rowTaken을 읽으므로 조회 순서 차이가 있다. 작은 캡처에서 투명한 모서리의 후보 row가 배열 끝일 수 있다. 실제 실패의 폭/높이를 아직 계측하지 않았으므로 같은 원인으로 단정하지 않는다. 다음에는 이 입력을 실제 보호 명령에 대조하고 선택된 경계만 검사하도록 복원한 뒤 같은 미션을 재생한다. rows를 임의로 늘리거나 guard를 삭제해 숨기지 않는다.

`bc8fury76`은 `ProcessFinder의 isProcess assert 경계`로 종료1이다. 현재 `RemoveAttachedProcesses`가 종속 후보의 type<10을 만났다는 의미다. 다음에는 부모/현재/다음 SID·타입과 삭제 중 Form 수명을 계측하고 실제4b22d0/4b1b80/4b27a0을 대조한다. 후보를 무조건 건너뛰어 성공으로 만들지 않는다. 두 미션의 최초 로그/미완료 상태/입력 계획은 그대로 보존했다.

첫 데모3시도는 frame3에 `UI control not found: Demo`로 목록 선택 전 종료했다. 현재 State3/4의 메인 표시 준비보다 이른 검사 입력이었다. 최초3기록을 유지하고 frame10 main 관측→12 Demo→16 목록 관측→18 선택으로 도구를 수정했다. 같은 제품으로 재실행한 데모3개는 모두 통과했다. 실제 실행은37회이며, 기준선34경로와 도구 타이밍 실패3회를 구별한다.
