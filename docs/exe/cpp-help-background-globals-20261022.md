# 도움말 질감 배경의 원본 전역 연결

2026-10-22 작업 단위306. 현재 PC와 마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-22**다. 실제 Help 트리의 텍스트/그림 출력에서 발생한 `배경 자산 타입 없음` 예외를 추적했다.

원본 Help 생성자 `004c5380`의 명령은 그림 배경과 본문 배경을 만들 때 현재 `005ca920` TYPE와 `005ca924` 프레임을 각각 읽는다. 실제 전달은 `004c5505..004c551e`, `004c5574..004c558d`에 있다. 내부 단색 배경만 TYPE0/프레임0을 전달한다.

공유 전역의 초기화 부모 `004c7160`은 `005ca920 = 005411c8`, `005ca924 = 0`을 기록한다. 보호 PE의 파일 초기값 `005411c8`은92이며 원본 자산 로딩 표의 `fortGump`다. 기존 복원은 두 질감 배경도 TYPE0/프레임0으로 고정해 생성하므로 실제 자산 조회가 실패했다.

`QuickHelpWindowState`에 이 두 현재 전역을 추가하고 자식 생성마다 다시 읽도록 연결했다. 실제 `RawMenuControls`는 같은 자산 로더의 `fortGump`와 프레임0을 공급한다. TYPE0을 임의 자산으로 대체하는 폴백은 추가하지 않았으며, 원래 단색 배경의 TYPE0은 유지한다.

독립 원본98행 재생과 별도로, 첫 질감 자식 생성 뒤 전역이 바뀌면 두 번째 자식이 새 TYPE/프레임을 읽는 검사를 추가했다. 실제 Help 트리 검사는 두 자식의 TYPE92/프레임0과 보호 자산·글꼴·팔레트를 사용한 픽셀 출력·클립 밖 행 padding 보존을 확인한다. 기존 독립 fixture의 입력 및 기대값은 변경하지 않았다.

지식 메뉴의 독립 Session 서비스에는 실제 Deck 조회가 요구하는 할당 바이트 입력이 누락되어 있었다. 현재 다른 Session 검사와 같은 명시 패턴0x71을 공급했다. 게임 규칙이나 생산 결과를 외부 서비스로 대신 쓰지 않는다.
