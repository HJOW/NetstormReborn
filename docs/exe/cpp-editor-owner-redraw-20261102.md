# Edit 소유자 추적의 실제 월드 갱신 연결 (단위747)

2026-11-02 / HJOW-Athlon / Windows 10. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 산출물은 바꾸지 않았다. 이전746의 화면 모드 부모 복원·집중 검사·실제 메뉴 검증·커밋은 완료한 진척으로 유지한다. 현재 실행 제품은 **747 / 표시11.01**이고 전체 목표는 진행 중이다.

## 원문과 결함

`004d5290`은 같은 객체의 현재 owner BYTE를 `MOVZX`로 읽고, 비영이면 `0048f3b0(owner,1)` 뒤 **월드 재그리기 `0059a8b0`을 증가**시킨다. 중립0은 Core 선택과 증가를 모두 생략한다. 일반 SetOwner 부모 `004d817e..004d81cb`는 보관한 SID에 가상+74를 실행하고 현재 Editor가 비영이면 위 추적을 호출한 뒤, `004d81c5`에서 같은 월드 값을 한 번 더 증가시킨다.

기존 독립256입력 검사는 이 산술/효과 순서를 원문과 일치시켰지만, 실제 Client/World 연결에서 `MapRevision()`의 **다른 주소 `005949d4`**를 전달했다. 편집 우클릭과 SetOwner 일반 입력이 모두 이 잘못된 연결을 사용했다. 단순한 변수 이름 차이가 아니라, 실제 미니맵 갱신을 바꾸고 원문 월드 갱신을 누락하는 문제다.

현재 디컴파일의 `char` 표기만으로 owner를 signed로 바꾸지 않는다. 실제 `004d529d`는 MOVZX이며 기존 unsigned BYTE 동작을 유지했다.10.72 대응은 `0041a6f0`로 기록하되 이번 재관측/실제 접합 검사는10.78 범위다.

## 수정

- `RawCampaignSession::FollowObjectOwner`가 기존 원문 추적 몸체를 같은 Pool, Player/Core 저장소, **Session과 Client가 공유하는 worldRedraw 참조**에 연결한다. 전역 상태를 복사하지 않는다.
- 편집 우클릭은 기존 `Select(id,0,0)` 후 현재 Editor 관문을 유지하고 위 공통 Session 부모를 호출한다. 선택이 정지로 거부되어도 원문처럼 원래 클릭 객체의 소유자를 읽는다.
- SetOwner 일반 입력의 뒤쪽 증가에는 `UberGump::worldRedraw_`를 전달하고, 중간 소유자 추적도 같은 Session 부모를 사용한다. 실제 SetOwner 가상 효과가 정당하게 일으키는 지형/미니맵 변경까지 차단하지 않는다.
- 헤더의 두 `revision` 참조 인자가 원문 `0059a8b0`임을 명시했다. 다른 주소의 이름이 같다는 이유로 재연결하지 않는다.
- 남은 `++MapRevision()` 직접 소비자인 섬 추가 `0047fb90`은 원문에서도 `005949d4++`임을 정적으로 확인했으므로 유지했다. 이를 이번 소유자 결함과 묶어 월드 갱신으로 바꾸지 않았다.

## 검증

새 검사는 창 없는 실제 GameWorld/Session, Client와 같은 `ClientGameplayGlobals`/`ClientKencloudGlobals` 저장소와 실제 보호 자산을 사용한다. 선택을 정지 상태로 거부해 불필요한 선택 효과를 실행하지 않은 뒤 편집 우클릭 부모를 호출한다. 월드 값`ffffffff→0`, 미니맵`12345678` 유지, 현재 Core1 선택, owner0의 무동작, Editor0의 조기 반환을 확인한다. 중립 상태는 검사 RAM의 명시 BYTE 입력이며 실제 사제 포획/희생/소유자 변경 플레이가 아니다.

수정 전 같은 입력에서 **1검사/4단언 실패**를 검출했다(`tests-before.log`). 기대값은 바꾸지 않았으며 수정 후 **집중55개/실패0**이다. 새1개, 기존 메뉴/Session·비용 Form·수집/부착·카메라와 기존 소유자256행/경계 검사가 포함된다. 새 테스트 실행 대상은 없고 실행66개/전체71대상을 유지한다.

기존 관측기 `decomp_object_owner_command.OwnerOracle`로256입력을 다시 실행해 보호 fixture의 trace/현재 상태와 모두 일치했다. 새 fixture는 없고 기존 관측 파일을 덮어쓰지 않았다. 가상+74와 Core 선택은 기존 명시 경계이며,256회를 전체 UserInput이나 실제 게임/네트워크 실행으로 세지 않는다. 최초 C++ 실제 연결의 실패가 독립 산술 검사만으로는 잡히지 않았다는 점을 구별한다.

Release 제품/집중 대상 빌드는 경고·오류0이다. EXE SHA-256은 `cfe3a71f07e65a18e3034d8e8cd0f44a1a369816f537863272c69a2db60fa8c6`이다. 기존 보호 **2656개(AGENTS1·원본1394·CD425·fixture836)**가 모두 불변이며 다음 기준은 `extracted/cpp-editor-owner-redraw-747/protected-after.json`이다.

이번 새 게임/독립CLI/GUI/fixture/MP 검사는0이다. 마지막 실제 GUI는746제품의 화면 조정·재시작이며747의 GUI 검증으로 합산하지 않는다. 전체34/ZIP645는644제품의 별도 근거다. 전체C++·전체34·새ZIP·물리 입력/PCM·자연 완주·포획/희생/특정 적 공격/승리·공중3종 전용 행동은 실행하지 않았다.
