## 변경한 동작

시나리오 안내의 `ToggleBottomGump,2` 버튼이 원래 하단 채팅 창을 전환하게 했다. 이전에는 이름 조회가 빠져 있었고, 숫자 명령을 연결해도 HUD가 효과 뒤 기본 반환0을 돌려주는 것을 호스트가 미구현 명령으로 처리했다.

보호PE의 이름표 `542fc8` → 문자열 `51884c` → 명령 전역 `542914` → `02000088`을 확인해 `GameMenuScriptCode`에 연결했다. `UberGump::Event`는 이미 일반 Gump Route가 실행한 명령을 다시 실행하지 않고 끝낸다. HUD의 원래 반환0, 인자0/1/2 처리와 기존 루트·자식 수명은 유지한다. 일반 캠페인의 View에서 채팅을 숨기는 `594fa4` 조건도 유지한다. 기본 메뉴에 항목을 추가하지 않았다.

구분선의 원본 알고리즘은 수정하지 않았다. `4c49f0`은 누른 화면 위치를 로컬 좌표로 바꿔 anchor에 저장하고 통지/캡처를 설정한다. `4c4b00`은 포인터Y-2를25~화면높이-25로 제한한 다음, 공통 Move `464d10`이 저장된 anchor를 뺀다. 5픽셀 구분선 중앙을 누르면 anchor2이므로 최종 상단23·하단높이-27이며, 예를 들어 포인터220은216이 된다. 검사 기대값에서 마지막 anchor 보정을 빠뜨렸던 부분을 바로잡았다.

검사 스크립트도 최초 down 뒤 `pointer`로 누른 상태의 위치만 바꾸도록 수정했다. 이전의 두번째 down은 로컬 anchor를 다시 쓰고, 캡처된 처리기가 성공을 반환한 뒤 공통 Route가 capture를 지우는 다른 입력이었다. 정상 드래그 중에는 같은 divider 토큰을 캡처하고 실제 up 뒤 해제되는 것을 확인한다.
