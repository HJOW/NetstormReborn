# Shift 다중 선택·그룹 이동·이동점 통지 — 단위701

2026-11-02, HJOW-Athlon. 마지막 전체 정밀 디컴파일은 같은 PC의 2026-10-23 자료다. 기존 다중 선택 저장소/정리는 유지하고 빠져 있던 추가·제외·기본 선택 승격·그룹 이동을 같은 실제 입력/Client owner에 연결했다.

## 차이와 복원

기존 `ClientUserSelectionGlobals`에는 기본 선택과30칸 보조 목록이 있고 `RawUserSelection::ClearMultiple`은 있었지만, 목록을 추가/토글하는 writer와 다중 이동 부모는 없었다. `UserInput`의 이동 모드 좌클릭은 항상 기본 선택 하나만 이동시켰다. 이제 원문 **Shift+좌클릭**으로 보조 유닛을 추가/제외하고, 일반 좌클릭 이동은 보조 목록을 먼저 전송한 뒤 기본 선택을 마지막에 전송한다.

원문 `004da35c..004da476`의85명령을 정적으로 읽어 입력 비트를 확인했다. `0x20000000`(현재 InputCode::kShift)이 다중 선택 분기이고 `0x10000000`(Ctrl)과 special 값은 강제 후보 조회에 쓰인다. 최초 진행 안내의 Ctrl 가정은 이 확인 뒤 Shift로 바로잡았고 제품에는 Shift로 구현했다. [정적 도구](../../tools/cpp_multiple_selection_input_audit.py)·[보고서](../../cpppj/multiple-selection-input-native-20261102.json)는 실제 입력 부모 전체를 실행한 관측이 아니다.

`RawUserSelection`이 기존 같은 선택/가상 통지 장치로 다음을 처리한다.

- **ToggleMultiple /004da6b0:** 물리 범위·state&3 관문, ffffffff 토글, 현재 선택 비트와 비교, +7c 통지, 기본 선택 해제 시 보조 첫 원소 승격, 추가/삭제·선택 음향·현재 +88 순서를 보존한다. 비정규 DWORD2도 bool로 바꾸지 않는다. 기본 선택 승격 뒤 +88은 처음 클릭한 대상이다.
- **ExtendSelection /004da39a..40e:** 현재 정지와 이동 플래그를 읽고, 기존 기본 선택이 없거나 free/비이동이면 실제 세 인자 Select를 사용한다. 나머지는 ToggleMultiple이다. 원문에 없는 소유자 제한을 추가하지 않는다.
- **MoveMultiple /004d5500:** 같은 enabled 전역에0 → 현재 목록의 유효/비free·비dead 원소에 이동 전송 → enabled1 → 실제 ClearMultiple이다. 각 전송 뒤 현재 개수/배열을 다시 읽는다. 전송 실패 때 enabled0을 임의 복구하지 않는다. 기본 선택의 전송은 뒤의 원래 caller가 한다.

보조 목록의 실제 writer는 `00414450`처럼 **고정 용량·중복 제외**이고, `0040ea00`처럼 모든 같은 값을 안정된 순서로 제거한다. 기존 Native 정적 생성 근거의 보조30칸을 유지하며 기본 선택은 별도다([455](cpp-state-sid-lists-runtime-20261026.md)). 가득 찬 목록을 자동 확장하거나 삭제 뒤 꼬리 바이트를0으로 바꾸지 않는다.

`GameWorld`의 같은 Input/Session에 추가·제거/enabled 장치를 연결했다. `Pick`은 기존 기본값0을 유지하면서 원문 Ctrl+special의 force도 받는다. 실제 일반 이동점은 원문 역투영/정수 절삭 뒤 `WorldDestSelected`의 x/y로 일반 큐에 쓰고, 그룹 이동 뒤 현재 기본 선택을 다시 읽는다. 이름표 `00542da8`→전역`00542808`→`0x02000044`는 보호 PE에서 확인했다. minimap처럼 별도 caller는 이 사용자 입력 전용 통지를 합성하지 않는다.

## 원문과 집중 검사

[원문 도구](../../tools/decomp_multiple_selection.py)는 보호 PE의 실제004da6b0/004d5500과 목록 추가·제거·다중 정리/ProcessFinder·기본 Mark helper를 **601개 입력**으로 실행했다. [fixture](../../cpppj/tests/fixtures/multiple-selection-x86.tsv)의 호출 순서와 selected/mode/enabled/count·다섯 선택 비트·전체30원소39DWORD를 제품과 대조했다. [원문 보고서](../../cpppj/multiple-selection-native-20261102.json)를 따른다.

표시 +88·콘솔 관문·강조·음향·운반체 전송은 명시 경계다. 통지/표시/음향/전송이 현재 선택·배열·개수를 바꾸는 입력을 포함한다. 기본 Mark22BYTE는 실제 기계어를 실행했고 파생 Mark 전체/실제 음향·전송·OS 입력의 근거로 확대하지 않는다. 최초 도구는 정밀 함수 표에 없는 기본 Mark를 일반 helper로 찾다 초기화에서 실패했다. 기존 `decomp_squid_selection.py`와 같은 실제 ret4까지22BYTE를 별도 허용해 해결했다. 전체 디컴파일 자료는 변경하지 않았다.

새 C++3개는601행 전체 대조, 단일 선택→추가/제외→기본 선택 승격/고정 용량·중복·제거, 이동 중 선택 해제 차단과 전송 실패의 부분 효과다. 기존 단일 선택/Client owner12개(기존 원문1074행·Clear87행 재생 포함)와 함께 **최종15개 통과, 실패0**이다. 새 게임 실행·전체 C++ 검사는 없다.

최초 집중 검사는 기본 선택 승격 후 새 선택을 +88로 갱신하던 제 구현 때문에 trace 두 건과 SID0 예외 한 건이 실패했다. 실제 원문은 처음 보관한 대상 piVar5를 갱신한다. 원래 대상 sid로 고치고 같은601행을 모두 재생해 통과했다. 기대 fixture를 수정하지 않았고 `focused-v1`/`focused-v2`를 보존했다. Release `build-v1`/최종 `build-v2`는 모두 경고·오류0이다.
