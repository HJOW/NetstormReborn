# cpppj 삭제/해체 보상(SP)·SP 저장소·샘 풀 복원

2026-10-07. **1차 기준은 10.78**이다. [공통 삭제 장부](cpp-destroylifecycle-reconstruction.md)가 사건으로만 내보내던 보상을 실제 계산으로 복원했다. 호스트 **DESKTOP-HJOW에서 원본/복사본 게임·업데이터/설치 도구·클론 창을 실행하지 않았다.** CD/추가 10.37은 비교 판본이다.

소스: [SquidReward](../../cpppj/src/o/SquidReward.cpp), [SpStore](../../cpppj/src/o/SpStore.cpp), 연결: [SquidDestroyLifecycle](../../cpppj/src/o/SquidDestroyLifecycle.cpp). 검사: [RewardTests.cpp](../../cpppj/tests/RewardTests.cpp). 독립 원본 출력: [reward-x86.tsv](../../cpppj/tests/fixtures/reward-x86.tsv), [근거 기록](../../cpppj/recovery-reward-evidence.json), [생성/감사 도구](../../tools/decomp_reward_oracle.py).

## 의미 정정

- 보상은 **처치한 쪽에 SP를 주는 계산**이다. `sid, (flags>>16)&15, 0`에서 수신자는 flags 16..19비트다. 삭제 비용의 `DAT_005424bc`%(전투 초기화가 25로 정함)를 수신자에게 지급한다. 세 번째 인자가 0이 아닌 호출(해체/환불)은 남은 HP 비례 환불을 쓴다.
- 지급하지 않은 가치(`비용 − 지급액`)는 전역 정수(패치 `00595088`, CD `00512110`)에 쌓인다. 이 값은 샘(geyser) 생성 코드에서 샘 타입의 비용과 비교되므로 **샘 풀**로 부른다(사용처 추정).
- 타입 번호 전역은 PE의 초기값을 읽어 확인했다. 164 altar(보상 제외, 개수 곡선 −1), 165 dais(개수 곡선 −1), 147 rainBlocker(삭제 보상 제외·해체 포함), 150 growingRainBlocker(비용을 rainBlocker로 대체, 해체 환불 0), 154 nugget(해체 환불에 ¼ 배율 없음), 158 priest(디버그 전역이 켜지면 최대 HP ¼).
- vtable +0x80은 base에서 객체 **상태 바이트의 상위 3비트**를 돌려준다(`004ad0a0`의 조건은 항상 참이다). 파생 구현 두 개(`0044a480`/`004478f0`, CD `00483670`/`00481310`)는 다른 객체 전달/프레임 문자 기반이며 호출자 계약으로 둔다.

## 판본 차이

| 항목 | 10.78 | CD / 10.37 |
|---|---|---|
| SP 저장 | 소유자별 **32비트 값을 32개의 9칸 DWORD 배열에 비트 단위로 흩뿌려** 저장(난수 잡음 포함) | 로컬 SP만 전역 float, 다른 소유자는 AI 지갑만 |
| 비용 단가 | 로더가 `ftol(cost + 번호×23)`을 정수 표에 저장, 읽을 때 `번호×23`을 뺌 | float `cost`를 그대로 사용 |
| 비용 곡선 | 같은 float 단가를 (개수+1)번 x87로 더함 | `(개수+1)`과 단가를 곱해 float로 저장 |
| HP 필드 | raw `+0x1a` **DWORD** | raw `+0x1a` **WORD**(부호 확장) |
| 환불 산술 | `float(HP×비용) ÷ 최대HP` | `float((HP÷최대HP) × 비용)` |
| SP 고정 모드 | SP를 194162로 만드는 차이를 지급액으로 사용(지갑은 이 차이를 받음) | SP를 100000으로 덮어쓰고 지갑은 입력 지급액을 받음 |
| 소유자 SP | 모든 소유자가 같은 저장소 | 로컬 외에는 지갑 정수 가산만 |

패치판 SP 저장소의 `0040eba0`은 시각 기반으로 **게임 전역 난수를 재시드**하고 offset(0..99)을 고른 뒤 32번의 순열 교환을 하지만 곧바로 항등 순열로 덮어쓴다. 읽기/쓰기마다 난수를 쓴다: 쓰기 한 번에 **160회**(비트당 5개의 잡음)다. 즉 **SP가 바뀔 때마다 전역 난수 상태가 전진**한다. 재시드의 시각 값은 입력으로 주입한다.

## 독립 원본 대조와 검증 한계

| 입력 | 세 실제 PE (각 입력을 x87 53/64비트로 모두 실행) |
|---|---:|
| 10.78 패치 | 2,400 |
| CD 10.72 배포본 | 2,400 |
| 추가 10.37 | 2,400 |
| 합계 | **7,200** |

두 정밀도의 결과가 다른 입력은 제외하도록 만들었지만 **제외는 0건**이었다. 입력은 시드 고정 합성이다: 객체 타입(altar/dais/rainBlocker/growingRainBlocker/nugget/priest/일반), 단가 float(0·소수·음수·`2^24` 초과·CD는 ±3e9까지), 최대 HP·플래그, 상태 바이트 상위 비트(개수 0..7)와 파생 개수 대체(−2..1000), HP(음수/16비트 초과 포함), 수신자 0..8과 로컬 소유자(같음/다름), 삭제 비율(0·25·150·`INT_MAX`·`UINT_MAX`), 샘 풀 초기값(경계 근처), SP 고정 두 전역·절반 HP·지갑 끄기·지갑 하한 객체(없음/값 0/값 있음)·priest ¼·디버그 assert 전역(위반 입력 제외), AI 부착 마스크와 지갑 초기값, SP 초기값, 재시드 상태(0 포함)와 힙 채움값이다.

비교하는 관찰값은 **샘 풀·소유자 0..8의 AI 지갑 DWORD·SP(패치는 실제 읽기 함수로 소유자 0..8, CD는 전역 float)·전역 난수 상태·32개 SP 배열 전체의 Adler-32·offset·UI 갱신 횟수·가상 개수 질의 횟수**다. 패치판은 같은 재시드/채움 입력으로 소유자 0..8의 초기 SP를 쓰는 실제 `0040edb0` 구간의 난수 상태와 배열 체크섬도 C++와 따로 대조한다(초기화 + 아홉 번의 쓰기가 같은 난수 소비를 한다).

각 PE의 정밀도별 실제 내부 도달은 보상 2,400회, 패치 기준 비용 곡선 2,397·해체 환불 500·로컬 가산 909·소유자 가산 708·AI 지갑 1,617·샘 풀 1,617·SP 쓰기 23,217·SP 읽기 23,217·난수 3,793,920회이며 CD/10.37은 보상 2,400·비용 곡선 2,394·환불 599·지갑 가산 1,779·로컬 가산 991이다([기록](../../cpppj/recovery-reward-evidence.json)의 `native_hits`는 두 정밀도를 합한 값이다). 분기 도달은 패치 기준 적용 1,617, 해체 500, SP 고정 1,200, 절반 HP 해체 238, 지갑 하한 도달 68, 수신자 0 지급 178이다. 최대 HP 0은 기계어로 확인한 결과 두 판본 모두 환불 0이다(x87 무한대/NaN → 절삭 변환의 하위 DWORD 0). 원본 assert 도달 0·정상 반환/ESP/x87 제어 워드/TOP·허용 밖 쓰기 0을 확인했다.

**명시적 대체**는 SP 표시 갱신(`0043dad0`/CD `004ee9d0`, 호출만 센다), 시각 기반 재시드(`004559d0`, 입력 상태 주입), 0x24바이트 힙 할당(`004e4391`, 입력 채움값), 패치 assert 보고, 파생 vtable +0x80의 개수(base가 아닌 입력은 호출 순서대로 값을 돌려주는 스텁)뿐이다. 나머지 보상/비용/환불/SP 저장소/지갑/샘 풀/난수는 원본 명령이다. 정수 비용 표는 실제 로더의 `ftol(cost+번호×23)` 접두 구간(`0049c338`~)을 실행해 채웠다.

C++의 `SquidReward::Plan`은 쓰기 전에 수신자 0..8·타입 번호·풀 범위·SP 저장소 연결을 검사한다. SP 저장값이 유한하지 않거나 절삭 변환 범위를 넘는 경우는 저장소 쓰기 전에 거부하지만, **저장소 초기화(Initialize)는 이미 일어났을 수 있다**(원본도 첫 접근에서 초기화한다). 삭제 장부에 연결하면 `PreDestroy`는 보상 계획을 먼저 검사한 뒤 선택 해제/Graph 분할 이후에 실제 지급한다. 상위 Destroy의 전체 롤백은 여전히 없다.

최종 x64 Release 경고/오류 0·CTest 실행 파일 1개 안의 내부 **191개·실패 0**(61.41초), 누적 제한 x86은 **96,240개**(89,040 + 7,200)다. 새 검사 9개는 세 PE fixture 재생, 난수가 지형 생성기와 같은 식인지, SP 저장소 왕복/보호, 보상 입력 거부, 삭제 장부의 수신자 지급·샘 풀, 보상 없음/수신자 0, 풀·장부 불일치 거부다. 이전 `--verify` 감사(공통 삭제 장부/Graph/destroy/일반 탐색/다리 효과/삭제 준비)가 모두 통과했고 원본 여섯 디렉터리 **2,782개 파일의 SHA/목록이 이전 기록과 동일**하다(`extracted/reward/protected-before.json`은 직전 작업의 기준 기록 사본이다).

## 재현

```powershell
$env:PYTHONPATH = 'extracted/oracle-python'
python -X utf8 tools/decomp_reward_oracle.py
python -X utf8 tools/decomp_reward_oracle.py --verify
cmake --build cpppj/build --config Release
ctest --test-dir cpppj/build -C Release --output-on-failure
```

기대값 생성에는 원본 PE/읽기 전용 내보내기/Python 의존성이 필요하다. `--verify`는 SHA/행 수를 감사한다. C++ 콘솔 검사에는 저장 fixture만 필요하다. 최신 빌드/회귀와 보호 파일 결과는 [LEFT_JOBS.md](../../LEFT_JOBS.md)를 따른다.

## 남은 연결

종속 ProcessForm의 release/destroy와 `0x2692`의 예약/조회·실행 틀은 [후속](cpp-process-reconstruction.md)에서 복원했다. AI 부착 통지(`004166e0` 등)·다른 form 종류의 파생 release/destroy·참조 수명·Flyingshrapnel 파편·walker 낙하·0x2692 처리기 몸체·끝 칸 변환·파생 vtable +0x80(dais 전달/프레임 기반 개수)과 raw GameWorld는 남았다. 샘 풀을 읽는 샘 생성 코드와 SP 표시/UI(`0043dad0`)도 아직 없다. 건설/경제/전투/승패와 미션 완주는 검사하지 않았다.

원본/복사본·업데이터/설치 도구 실행과 모든 창 검사는 호스트 **DESKTOP-HJOW에서 금지**되어 있다. 다른 허용 PC에서 raw 월드 연결 후 삭제→SP 지급→재진입을 확인한다. 해당 PC의 AGENTS.md/사용자 지시를 먼저 확인한다.
