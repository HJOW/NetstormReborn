# 1059 — R 연결 번호·모드와 State37 검색 부모

State37의 원문 검색 부모를 실제 Client의 파일 장치에 연결하고, 새 R 런타임이 사용할 전용 연결 번호/종료/모드 부품을 제품 라이브러리에 추가했다. **실행 제품은1059 / 11.01**이다. **새 R 실행 파일과 OS launch 장치, Root/CS 관리자는 아직 미구현**이며 이 작업을 서버 실행/로그인 성공으로 계산하지 않는다. 직전 CP 커밋은 `eb680d67 / 20261107-84 CP`다.

## 실제 State37 부모

`InstallNativeLocalServerLaunch`는 실제 current37을 받고 안내→현재UDP12/IPX13 닫기→`ReadString(rootServerExe)`→여섯 후보 순서를 실행한다. 원문00542624의 순서는 `.\debug\`, `..\r\debug\`, `..\..\r\debug\`, `.\r\debug\`, `.\`, `..\`다. 현재 루트/접두/이름을 기존 `RawFileName.Format`의 -2/-2/-3으로 조합하고, 실제 `Files.Probe`의 모든 비영 출처를 채택한다. 원문처럼 복사한 후보를 조회하므로 파일명 고리의 후속 덮어쓰기가 실행 후보를 바꾸지 않는다.

각 실패마다 next34를 쓰고 첫 성공에서는 program/`lan`/wait0의 실제 실행 장치를 호출한 뒤 next38을 쓴다. 공통144BYTE 확정은 기존 상태 분배기에 남긴다. **실제 실행 장치는 아직 비어 있다.** 후보가 존재하면 해당 미연결 경계에서 명시 오류가 나고, 전부 없으면 원문처럼 다음34다. 원본 R.exe를 대신 실행하지 않았다. 실행 장치가 연결된 뒤에도 OS 시작 실패를 로그인 성공으로 판정하는 코드는 추가하지 않는다.

0054d988은 실행 위치/명시 경로 루트이며 옵션 문자열이 아니다. 현재 Client의 GameDirectory로 같은 시작 루트 경계를 빌린다. rootServerExe는 PathSpec이 아닌 ReadString이다. 원본 지역 미작성 스택/누락 키의 임의 바이트와 CreateProcessA의 인용·핸들 누수 자체는 현대 장치와 별개 한계다. 새 장치는 Unicode 경로·핸들 반납·설치 배치를 함께 복원해야 하며 이번에는 만들지 않았다.

## 제공된 R과10.78의 차이

R 시작 코드에 `Fleet's Server Build version 1.0` 문구가 있고,00475660의 Root 응답 버전 필드는10/0x47(71)이다. 이 문구나 응답 필드를 새 제품의 표시 버전11.01로 혼동하지 않는다.10.78의004b4160 메타 버전 검사는 같은 major10의 minor71 차이를 로그한 뒤 허용한다. 별도 게임 버전 검사004b41e0은 minor78 이상 조건이 있으므로 두 경계를 구분한다. 이 좁은 버전 검사 관측으로 전체 패킷 호환을 주장하지 않는다.

R0044d550의 참가자 접근은+0xd78/stride0xbc, 전투는+8/stride0x158이다.10.78 클라이언트의+0xb70/stride0x1cc와stride0x124 물리를 그대로 R 객체로 재해석할 수 없다. 실제 wire 서식과 R 전용 객체 수명을 따로 옮겨야 한다. 이번에는 이 물리들을 섞은 CS 버퍼나 가짜 응답을 만들지 않았다.

LAN 인자의 R은 콘솔 제목/최소화·우선순위 설정 뒤 `NETSTORMOOGABOOGA` 등록 메시지의0x500을 알리고 나서477e10 초기화를 시작한다. 이는 서버 준비 완료 패킷이 아니다. 원문 클라이언트00436550은 fullscreen 비트가 있을 때0x500에서 `ShowWindow(...,9)`를 호출한다. 현재 ClientMain의 등록 메시지는 미이식 주석 상태다.0x100 설정 재적재/0x200·300 표식도 함께 원문대로 후속 연결한다.004b9230의 수동 선택/재시도 UI와 구별한다.
