# Fiery Tail 생성·공통 표시 등록·공유 색 표·삭제 복원

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 단위99는10.78의 `00457ea0`과 `004882c0`을 `RawFieryTailLifetime`으로 복원했다. 실제 게임·GUI와 새 디컴파일은 실행하지 않았다. CD10.72의 파생 생성자는 이번 실행 대조 범위가 아니다.

## 제품 동작과 소유권

이미 확보한 객체의 생성은 기존 `RawRenderRegistry::Construct`로 시작한다. 표시 목록의 첫 빈 칸/40칸 확장을 처리한 뒤 **process11·flags0x10의 부모 부착**을 수행한다. 이후 System의 입자 개수·시계·최초 프레임 표식을 초기화하고, 직전 좌표를0으로 만든 뒤 **120×24바이트 입자 전체를0으로 초기화**한다. 생성자는 `+40/+44`의 시간 간격 float를 쓰지 않으므로 이미 주어진 비트를 보존한다.

공유 색 표 `0055a750`이 비어 있을 때만8바이트 객체를 만들고 실제 RGB 두 색 띠·CRT 정렬·8+3색 병합을 수행한다. 채워진 표는 다른 효과에서 재사용한다. 파생 생성자의 마지막 쓰기는 최대 수명4, 공유 표 토큰, offset0, 표시 깊이-25다. 초기 공통 등록의 부모 깊이와 마지막 파생 깊이를 구별한다.

`FieryTailFrameFields::palette`는 이 공유 표의 토큰이다. 첫 실제 색 표의 내용은 기존 `BuildFieryTailPalette`가 만든11개 DWORD이며, 원본44바이트 할당 뒤의 값을 임의로 추가하지 않는다. 최초 프레임/Draw의 현재 색 span은 별도 계약을 그대로 유지한다.

삭제는 `004882c0 → 0044fd70 → 00423aa0 → 0040f1b0 → 00487880 → 0041bd00` 순서를 따른다. 입자 저장소를 먼저 반납하고 표시 목록 슬롯을 비운 뒤 base 부모/form을-12345로 바꾼다. flags의 bit0이 있으면 객체 자체를 반납한다. 공유 색 표는 개별 효과의 소유물이 아니므로 반납하지 않는다. 원본이 반납한 포인터/용량을 다시 쓰지 않는 것과 달리 호스트의 vector 저장소는 해제해 재사용을 막는다. 검사 직렬화의 삭제 후 용량은 할당 시점에 보존한 원본 의미값이다.

## 원본 관찰과 검증

`tools/decomp_fierytail_lifetime.py`는 현재 PC 전체 정밀 함수표의 실제 범위와 기존 색 띠 Oracle의 명시 callback 범위만 실행한다. 파생/공통 생성자·표시 슬롯 검색/확장·입자 초기화·색 띠 생성·실제 CRT 정렬·병합·스택 확보 helper·소멸자는 실제 PE 몸체다. **new/free의 성공/주소와 BaseProcess 부착은 외부 경계**다. 실제 게임 heap이나 Host/Kernel을 실행한 것이 아니다.

입력은 실제3개 COL의 cold/warm 공유 표, 빈/가득 찬/빈 칸 목록, 부모0/50, signed 깊이, 부착 중 부모·깊이 변경과 flags의 하위/상위 bit를 포함한다. warm의31..41색은 이미 있는 공유 표를 나타내는 명시 입력이며, 실제 게임이 그 색을 생성했다고 주장하지 않는다. 두 x87 정밀도를 보존하고 C++는 기본53비트 결과를 대조한다.

각 입력에서 생성/삭제 반환 포인터·ESP·비휘발 레지스터·x87 제어/TOP/tag·스택 sentinel·SEH 복구를 확인한다. 실제 객체의 의미88바이트, 전체2880바이트 입자,44바이트 색 표, 목록 슬롯과 확보/부착/반납 사건을 기록한다. 시간 간격과 미사용 DWORD의 sentinel, 공유 표와 원본 RGBX 입력 불변도 검사한다. 입자 반납 시 등록이 살아 있고 객체 반납 시 슬롯이 비어 있는지 확인한다.

최초 관찰기에서 목록 확장 중 이전 목록 반납까지 입자/객체용 slot 검사를 적용해 미초기화 slot을 읽는 오류가 있었다. 목록 반납을 그 검사에서 분리하고 최종 전체 관찰을 다시 실행했다. 제품의 원본 기대값을 조정한 것은 아니다.

**고유31입력·두 정밀도에서 생성62회/삭제62회 정상 반환·결과 차이0**이다. C++ 생성/삭제 의미88바이트,120입자 전체, 등록/반납 사건은 첫 대조부터 일치했다. 공유 색 표는 cold12행이 기존 제품과 달라 아래 원인을 수정했다. 수정 후 기본53비트31행의 전체 필드·입자·색·사건이 일치하고 `FieryTail` 집중4검사가 통과했다. Release 전체 빌드는 경고0·오류0이다.

실제 생성자의 첫 색 띠는 **어두운 빨강→주황8색**이다. 기존 `BuildFieryTailPalette`의 끝점 순서가 반대였다. 단위97의 helper 실험은 직접 지정한 RGB 입력을 실행했기 때문에 그 하위 호출/결과는 정확했지만 실제 생성자의 호출 방향을 입증하지 못했다. 제품 호출을 고치고 `ParticleGradient_FieryTailPeConstants`는 실제 생성자의3개 COL 결과를 읽도록 바꿨다. 기존 색 띠 fixture의 원본 바이트와 일반 helper 대조를 변경하지 않았다.3팔레트 검사는 이번31입력의 재사용이며 새 원본 입력으로 합산하지 않는다.

## 다음 연결 경계

이번 작업은 생성/삭제 몸체다. 같은 Host/Kernel과 다른 효과가 공유하는 표시 registry로의 수명 연결, 생성 중 프레임/Draw 재진입 차단, 공통 수집/정렬/dirty 큐/VFX 선 래스터는 남아 있다. 최초 최대 수명 색 조회의 배열 뒤 DWORD는 실제 allocator/게임 관찰 근거가 필요하다. 가짜12번째 색, 마지막 색 clamp 또는 빈 효과로 데모 경계를 넘기지 않는다.

이후 실제 Session의 **표시 Pop→effect11 생성/부착→Missile 부착** 순서를 보존하고 데모3의113프레임 이후를 검사한다. 데모1 TYPE148 stage5와 전체 사용자 플레이·자연 완주·원본 동일성은 별도 미완료 항목이다. 이번 요청의 전체화면 DirectDraw 오류 수정 제외도 유지한다. [전체 연결 인수인계](cpp-fierytail-notes-20261016.md)를 따른다.
