# 배치 통지 전의 로컬 예측 조각 정리

2026-10-10, **HJOW-Athlon**. [건설 배치 실행](cpp-construction-place-reconstruction.md), [서버의 건설 확정](cpp-construction-confirm-reconstruction.md)에 이어 같은 세션에서 진행했다. 현재 PC와 마지막 디컴파일 PC가 같다. 새 `constructionclear` 목록 **23/19/19개**를 읽기 전용 Ghidra로 내보냈다. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-10.** 원본 게임·복사본·analyzeManager·클론 창을 실행하지 않았다.

배치 통지 처리기(`004441b0`)가 조각을 놓기 직전에 부르는 함수다. 로컬 배치는 서버의 답을 기다리지 않고 클라이언트 영역 번호로 abstract 조각을 먼저 놓아 둔다(예측). 통지가 도착하면 이 함수가 통지의 칸마다 그 자리의 예측 조각을 지워 서버가 정한 번호의 조각이 들어갈 자리를 비운다. **통지 처리기 본체와 실제 삭제 연결은 아직 없다.**

## 순서

인자는 타입, x, y, decoder 인자, 방향, 플레이어다. `(타입, 인자, 방향, x, y, 0)`으로 decoder를 만들고 유효 칸마다 아래를 한다.

1. **칸 범위를 구한다.** 칸 좌표 `(x, y)`에서 타입 발자국만큼 물린 점 `(x - (폭 - 1), y - (높이 - 1))`을 각 좌표마다 1~255로 자른다. 칸 좌표가 유효하면(둘 다 0 초과 256 미만) 범위는 자른 점과 칸 좌표를 잇는 사각형이고, 유효하지 않으면 두 모서리 모두 자른 점이다. 작은 쪽 모서리는 0방향으로 절삭하고 큰 쪽 모서리는 0.99999를 더해 절삭해 네 정수를 만든다.
2. 그 범위로 일반 탐색기를 시작해(플래그 0, 기본 필터) 객체를 차례로 본다. 탐색기가 돌려준 번호가 0이거나 풀 크기 이상이면 이 칸을 끝낸다.
3. 객체가 **abstract이고, 번호가 5 이상 서버 영역 첫 번호(패치 15000, CD 6000) 미만이고, 타입이 통지의 타입과 같으면** 후보다. **권한이 없으면 타입이 달라도 후보다.** 후보가 아니면 탐색기의 다음 객체로 넘어간다.
4. 후보의 삭제 플래그를 정한다. 타입이 통지와 같고, 프레임이 decoder의 현재 프레임과 같거나(패치 DWORD 비교, CD는 BYTE를 0 확장해 비교) 다리 타입이면서 방향 글자가 같고, 소유자 바이트가 플레이어 인자(DWORD)와 같으면 **`0x2000000`**, 아니면 0이다.
5. 후보의 가상 `+0x10`을 그 플래그로 부르고 **이 칸을 끝낸다.** 한 칸에서 후보를 둘 이상 지우지 않는다.

플레이어 인자는 DWORD로 비교하므로 상위 비트가 있는 값(`0x103` 등)은 어떤 소유자와도 같지 않다. 다리는 로컬 예측이 고른 조각 프레임이 통지와 달라도 방향 글자가 같으면 같은 조각으로 취급한다.

## 판본 차이

정상 입력(유한 좌표)에서 두 판본의 결과는 같다. 코드는 다르다.

- 패치판은 칸 범위를 `00425af0`이 두 helper(`0040e880`, `0040e8f0`)를 불러 만들고 CD판은 `00420140` 안에 펼쳐져 있다. CD판의 유효성 검사는 좌표의 비트를 정수로 0과 비교하는 부분이 섞여 있다.
- 비교할 수 없는 값(NaN)의 처리(자르기와 모서리 넓히기에서 어느 쪽을 고르는지)가 두 판본에서 다르다. C++ decoder가 유한하지 않은 시작 좌표를 거부하므로 이 차이는 재현하지 않았고 fixture에도 없다.
- 프레임 필드는 패치 `+0x24` DWORD, CD `+0x22` BYTE이고 소유자는 패치 `+0x22`, CD `+0x20`이다.

## 독립 원본 관찰과 C++ 연결

[`decomp_constructionclear_oracle.py`](../../tools/decomp_constructionclear_oracle.py)는 세 PE를 두 x87 제어 워드로 실행했다. 새 독립 저장 입력 **1,020개**: 10.78 **420개**, CD와 10.37 각 **300개**. 정상 반환 **2,040회**, 두 정밀도의 관찰이 모두 같았다. 칸은 10.78 1,484개, CD·10.37 각 872개이고 칸마다 실제 탐색기 Begin에 한 번씩 진입했다. 저장 입력 누적은 앞 단계 460,737개에 더해 **461,757개**다.

입력은 시작 좌표 10가지(소수·정수·가장자리·지도 밖·음수) × 발자국 4가지 × 권한 × 다른 타입의 발자국, 플레이어 인자의 폭, noIsland 아홉 칸 × 방향, 다리 패턴 26개 × 방향 × 프레임 표를 교차한다. 후보 조각은 실제 decoder로 읽은 칸 주변에 고정 시드로 놓는다: 칸에서의 어긋남, abstract 비트(매장 비트 포함), 클라이언트/서버 영역 번호, 같은/다른 타입, 같은 프레임·다른 프레임·방향 글자만 같은 프레임, 같은/다른 소유자, 해시 단계 0~3. 어떤 후보가 지워지는지는 Python에서 계산하지 않는다.

정리 몸체와 decoder·칸 범위·자르기/유효성·절삭/올림·탐색기·방향 글자 조회는 원본 명령이다. **가상 삭제만 명시 경계**이며 삭제 뒤에도 후보는 해시에 남는다(실제 삭제의 공간 해제는 실행하지 않는다). 탐색기 Begin의 네 정수 인자는 대체하지 않고 관찰해 칸 범위 계산을 따로 대조한다. 스택·보존 레지스터·x87·허용 실행 범위·쓰기(스택 밖 쓰기 없음, 해시 불변)·입력 순서·진입/반환 수·탐색/삭제 사건 수·SHA를 감사한다. 원본 assert와 게임/OS 호출은 0이다. 후보 좌표는 1 이상 255 이하로 두었다(CD 탐색기는 그 밖의 좌표에서 assert한다).

[`ConstructionClearTests.cpp`](../../cpppj/tests/ConstructionClearTests.cpp)의 새 검사 **6개**: 세 PE 관찰 전체 재생(칸마다의 탐색 범위와 지운 후보·삭제 플래그의 순서 일치), 칸 범위의 자르기/유효성 경계, 한 칸에서 하나만 지우고 서버 영역·abstract 아님·다른 타입을 건드리지 않는 것과 권한 없음의 동작·거부 경로, 그리고 **세 모듈을 한 흐름으로 잇는 통합 검사**다. 통합 검사는 실제 factory·소유자 지정으로 클라이언트 영역 SID 아홉 개에 noIsland를 abstract로 놓고(로컬 예측), 확정이 만든 서버 SID의 통지를 처리기 자리에서 받아 정리 → 배치 실행을 부른다. 예측 아홉 개가 칸 순서대로 모두 같은 조각 플래그로 지워지고 칸마다 서버 영역 번호의 확정 조각 하나만 남는 것을 탐색기로 확인한다. 이 검사의 Pop과 삭제는 해시 등록/해제만 하는 경계이고 처리기의 abstract 판정은 0으로 두었다. [fixture](../../cpppj/tests/fixtures/constructionclear-x86.tsv)와 [근거 JSON](../../cpppj/recovery-constructionclear-evidence.json)은 UTF-8/LF다.

Release 경고/오류 **0**, CTest 내부 **572개·실패 0**(136.53초), 원본 근거 감사 **89종 모두 통과**. 새 변이 9개 **모두 검출**(기대 검사만 돌리는 `--focused` 실행. 변이 전 사본은 전체 검사 통과). 원본 보호 파일·AGENTS.md·dotnetpj는 바꾸지 않았다. 로그는 Git 제외 `extracted/constructionclear-*.log`에 있다.
