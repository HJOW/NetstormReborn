## 발견한 차이와 수정

1. 첫 빌드는 새 검사에서 vector를 shared_ptr에 잘못 대입해 실패했다. 검사 입력 수명을 shared_ptr로 바로잡은 뒤 빌드가 성공했다.
2. 첫 실행26불일치 중19개는 로그인에서 보호 `d/TEST02.fort`를 다시 읽던 검사 입력 문제였다. 같은 원본 작업본 VFS로 고쳤다. fixture의 기대값을 다시 계산해 바꾸지 않았다.
3. 남은7개 중4개는 Go 뒤 초기 Regular를 아직 실행하지 않은 시점 차이였다. 실제 `.Step(.025)`로 현재 Kernel을 한 번 진행하니 거주 구역의 QA와 소유자가 원본과 맞았다. 결과를 직접 쓰지 않았다.
4. 간헐천3개는 제품 결함이었다. 원본004852e0→004ac550→현재 TYPE+0xc4→004e49c0→QA WORD와 달리 `RawAssetPostPop`이 생성 당시 TYPE 사본을 유지해 전투 옵션 적용 뒤에도2000을 썼다. 이를 장기 수명의 현재 TYPE span으로 교체했다. 현재 타입 조회는 각 효과 뒤 다시 읽고 범위를 검사한다. 실제 전투 옵션/TYPE 쓰기나 저장 QA를 검사에서 주입하지 않았다.
