# 장면별 배경음악 감독: 곡 요청·다음 곡·프레임 확인·시작·날씨 효과

2026-10-10, 마지막 디컴파일 수행 PC **HJOW-Athlon**(192.168.0.94). [scenemusic 목록](../../tools/ghidra/scenemusic-functions.json) **10/9/9개**를 같은 PC의 세 Ghidra 프로젝트에서 읽기 전용으로 내보냈다. 현재 호스트와 마지막 디컴파일 PC가 같아 정밀 디컴파일은 다시 하지 않았다. 10.78 싱글플레이 우선, Windows 안정 구동 2차, outpost/LAN 3차, 한국어/요구사항/MCP 4차를 유지했다. 원본 게임/복사본·클론 창·소리 장치는 실행하지 않았다.

[`SceneMusic`](../../cpppj/src/client/SoundSceneMusic.h)은 "지금 어떤 곡을 틀어야 하는가"를 정하는 감독이다. 곡을 실제로 열고 멈추는 일은 [상위 곡 선택](cpp-music-selection-reconstruction.md)과 [음악 채널](cpp-music-control-reconstruction.md)이, 효과음은 [재생 계층](cpp-sound-play-reconstruction.md)이 맡고, 감독은 그 앞에서 **언제 어떤 이름을 요청하는지**, 그 곡이 **언제 끝나는지**(실시간 시계), **곡에 딸린 날씨 효과**를 처리한다. [앞선 분석 문서](music.md)의 정적 분석을 기계어 관찰로 확정한 단계다.

## 동작 (기계어로 확정한 것)

**곡 요청 `Request(이름)`** — 아래 순서다.
1. 지금 곡과 이름이 같으면(ASCII 대소문자 무시) 끝낸다.
2. 결과 곡이 재생 중이면(아래 잠금) `anticipation.mus` 말고는 끝낸다.
3. `fanfare.mus`는 결과 상태가 **정확히 1**일 때만 진행한다.
4. 곡을 고른다(상위 곡 선택).
5. `fanfare`면 `fanfareEnd = 곡 길이 + 지금`, `defeat`면 `defeatEnd = 곡 길이 + 지금`.
6. 곡 길이가 **30초보다 길면**(엄격, NaN은 아님) `songEnd = 곡 길이 + 지금`, 아니면 `songEnd = 지금 + 180초`.

시계 읽기 횟수가 판본 공통으로 정해져 있다: fanfare와 defeat는 두 번(끝 시각, `songEnd`), 나머지는 한 번이다. 곡 길이는 사용할 때마다 다시 읽는다. 곡 선택이 실패해도(파일 없음) 이름은 바뀌고, 이어지는 `songEnd`는 **그때 채널에 남아 있는 곡의 길이**로 계산한다(열려 있던 이전 곡이 계속 재생된다).

**결과 곡 잠금** — 현재 곡이 `fanfare.mus`이고 `지금 < fanfareEnd`, 또는 현재 곡이 `defeat.mus`이고 `지금 < defeatEnd`이면 참이다. 이 `<`는 x87 `fcomp` + `test ah,1`이어서 **비교 불가(NaN)도 참**으로 취급한다(C의 `<`와 다르다). C++은 `!(왼쪽 >= 오른쪽)`으로 같은 결과를 낸다.

**프레임 확인 `Frame()`** — 지금 ≥ `songEnd`일 때만(NaN이면 건너뜀) 진행한다: 전투 중이면 다음 곡, 아니면 대기실이면 `anticipation.mus`, 아니면 `ser22.mus`. 전투 여부는 DWORD가 0이 아닌지만 본다.

**다음 곡 `Next()`** — 색인을 32비트로 하나 올려 **C의 `% 4`**를 취한다(오버플로는 감기고, 음수는 −3~0이 된다). 색인을 **먼저 저장**한 뒤, 플레이어 표가 준비돼 있고 로컬 플레이어의 희생 의식이 진행 중이면 `sacrifice.mus`를 요청하고 **날씨 효과 없이 끝낸다**. 아니면 그 색인의 원소 곡을 요청하고 날씨 효과를 적용한다. 그래서 의식으로 끊긴 원소 곡은 이어 틀지 않고 의식 뒤에 다음 곡부터 시작한다([music.md 5절](music.md)와 일치).

**시작 `Start()`** — 전투 밖이면 색인 3과 메뉴 곡을 요청한다. 전투 중이면 `난수(0~3999) / 1000`을 색인으로 두고 `Next()`를 부른다(그래서 첫 곡은 난수 색인의 **다음** 곡이다). 이어 `Frame()`을 한 번 부르고 마지막에 `tint = 색 표[색인]`을 쓴다. 요청이 같은 이름이라 무시되면 `songEnd`가 예전 값 그대로여서 이 `Frame()`이 곧바로 다음 곡으로 넘어갈 수도 있다(대조 입력에 포함).

**날씨 효과 `ApplyWeather()`** — 화면 갱신 → (설정 `ascendancyPalette`가 **1**이면 `tint = 색 표[색인]` → 팔레트 파일 적재 → 갱신 카운터 `= 1`) → (효과음 표가 비어 있지 않으면, 색인이 2일 때 번개 효과를 먼저 시작하고 효과음 재생). 색은 팔레트 적재보다 먼저 쓰고, 효과음 색인은 팔레트 단계 뒤에 다시 읽는다. 효과음은 `반복·음량·좌우·우선·한도`가 모두 0인 이름 기반 전역 재생이다.

### 범위 밖 색인

색인이 0~3을 벗어나면 원본은 표 앞뒤 메모리를 읽는다. C++은 `std::out_of_range`로 막는다. 정상 흐름에서는 일어나지 않는다: `Start`가 3 또는 0~3으로 정하고 `Next`가 `% 4`를 취하기 때문이다(`Start`는 전투 밖에서 색인을 3으로 되돌리므로 처음 색인이 범위 밖이어도 읽지 않는다). 대조 입력에서도 음수 색인은 뺐다.

## C++ 검사

[`SoundSceneMusicTests.cpp`](../../cpppj/tests/SoundSceneMusicTests.cpp)의 새 검사 5개.

1. **세 PE 관찰 재생(3개).** 연산 목록을 실제 `SceneMusic`에 같은 순서로 적용하고 호출별 사건·반환과 마지막 전역 열 개를 비교한다. 같은 C++이 세 판본을 모두 통과한다.
2. **실제 스택 위의 수명.** 실제 `MusicSelection`·기본 채널·`SoundMusic`·`SoundPlayer`에 이어(파일 열기, 버퍼 생성, 장치 호출만 모의) 전투 시작 → 곡 길이가 파일 헤더에서 계산된 값(214초 안팎)과 `songEnd = 길이 + 지금` → 곡 끝마다 다음 곡으로 넘어가고 이전 파일이 닫힘 → 한 바퀴 돌며 천둥 곡에서 번개와 `thunderCrack.wav`가 적재됨 → 희생 의식 중에는 희생 곡이 열리고 번개가 없음 → 의식 뒤 다음 원소 곡 → 결과 상태 1에서 승리 곡이 열리고 끝나기 전에 메뉴 곡 요청은 막히고 대기실 곡은 허용됨 → 끝난 뒤 메뉴 곡으로 복귀 → 찾을 수 없는 곡은 이름만 바뀌고 열린 곡이 유지됨 → 설정이 켜지면 색과 갱신 카운터가 쓰임.
3. **거부와 원본 경계.** 빠진 경계, 범위 밖 색인(`Next`·`ApplyWeather`는 예외, `Start`는 색인을 3으로 되돌려 읽지 않음), 32비트로 감기는 큰 색인, 비교 불가 시계의 `Frame`/잠금.
