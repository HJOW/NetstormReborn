# cpppj 단위24: 실제 세션 경계 감사와 원본 재시드 전제

## 기준과 현재 경계

기준 커밋은 `9ecedb6`(단위23)다. AGENTS와 양 LEFT를 다시 읽었다. 현재 및 마지막 정밀 디컴파일 PC는 **HJOW-Athlon, 2026-10-15**다. 보호 PE·AGENTS·dotnetpj는 불변이며 게임/GUI/OS 소리 장치를 실행하지 않았다.

실제 `UberGump::BeginMission`은 MissionType Battle을 `NotImplemented`로 거부한다. 실제 GameWorld는 저장 객체를 별도 `objects_`에 생성하고 관찰 기반 이동/지형 어댑터를 사용한다. 복원된 캠페인 설치/전투/경로 모듈은 production library에 있으나 현재 그 소유·조립은 검사 장면에서 수행된다. **이번 단위에서 이 세션/화면/입력 연결을 완료하지 않았다.**

production 세션으로 옮길 때 검사 장면의 고정 reseed 반환1, UI/소리/전송 관찰 콜백 및 일부 명시 원본 입력을 실제 동작으로 복사하면 안 된다. 먼저 발견한 실제 재시드 경로를 복원했다. 다음 작업은 실제 서비스를 공급하는 세션 소유자를 구성하고 같은 raw 슬롯을 게임 화면/입력에 연결한다. Early Missions/1-1~1-2 진행·완주 동일성 목표를 이 준비 작업으로 축소하지 않는다.

## 실제 재시드

원본 PATCH00455970은 randomMode005c89a8이0이면 CRT srand(0x38d535), 그 밖이면 `__time32(NULL)`의 Unix 초를 srand에 넘긴다. 실제 CRT rand100회를 버린 뒤 추가3회 반환값을32비트 곱으로 게임 난수00532710에 저장한다. CRT 상태와 GameRandom 상태는 별개이며, 그 뒤에도 CRT의103번째 소비 후 상태를 유지한다.

PATCH004559d0은 mode DWORD를1로 임시 변경하여 같은 초기화를 실행한 뒤 원래 mode를 복원한다. SP 초기화의 재시드 입력은 이 helper의 게임 난수 상태다. 임의 seed1이나 밀리초를 직접 반환하는 경로로 대신하지 않는다.

`RawGameRandomSeed`는 기존 GameRandom, 같은 CRT 상태, 현재 mode 및 signed32 Unix 초 공급자를 받는다. 실제 MSVC srand/rand의32비트 상태 감김/15비트 반환/100+3 소비/곱/모드 복원을 수행한다. OS 시각 공급자는 caller 경계이며, 공급자 예외 시 임시 mode가 남지 않도록 복원한다. 이 예외 보호 자체를 원본 정상 입력 관찰로 합산하지 않는다.

## 정밀 자료와 실패 보존

첫 `campaign-seed` plan의 PATCH helper1은 export됐으나 빈 CD 목록 때문에 wrapper가 실패했다. 원래 plan/log/export를 덮어쓰지 않았다. 별도 `campaign-seed2`는 PATCH helper/하위 초기화2개를, `campaign-seed3`는 동일2개 및 실제 CRT srand004e649e/rand004e64ab를 읽었다. **고유 정밀 함수는4개**이며 반복 export를 다시 합산하지 않는다. CD10.72의 재시드 진입은 이번 비교 범위 밖으로 기록한다.

직접 영향 원문8개를 먼저 `run24-base`에 보존했고, 무편집 상태의 공용 CMake/SpStore 헤더/소스3개를 추가하여 총11개 기준을 유지한다. GameWorld/UberGump/검사 조립의 보존본은 세션 연결 대비 기준이며 이번 단위의 동작 변경으로 주장하지 않는다.

## 독립 원본과 C++ 검증

새 입력은 temporary2×mode4×Unix초6×이전CRT2의 **고유96개**다. mode0/1/7/ffffffff, Unix초0/1/−1/2000년 시작/INT_MAX/INT_MIN을 교차한다. 실제 초기화/helper/srand/rand 몸체를 격리 x86에서 실행한다. `__time32(NULL)`의 signed 초와 CRT thread data 포인터만 외부 입력이며 난수 산술을 대체하지 않는다.

각 입력에서 mode/game/CRT 전체 DWORD 및 시각/TLS 요청 수를 관찰한다. 정상반환96/assert0이다. 각 호출은 actual srand1/rand103/TLS104를 수행한다. 고정 mode의 직접 초기화에서는 시각을 호출하지 않으며 임시 재시드는 원래 mode0이어도 시각을 한 번 요청한다. 실제 CRT 계산과 게임 시드 곱을 C++96입력이 허용오차 없이 직접 비교한다.

추가 검사는 같은 GameRandom/CRT/mode에 RawGameRandomSeed::Reseed를 기존 ScrambledSpStore::Initialize 콜백으로 연결한다. SP의 초기화/재시드 상태 수명, 같은 시각의 반복 재시드, 누락 공급자 및 공급자 예외 후 mode 복원을 확인한다. 이 연결 검사와 기존 SP 입력을 새 Native96 입력으로 합산하지 않는다.

현재 실제 세션에서의 Unix 시각/CRT 스레드/초기 전역 공유와 전체 SP caller·Ready/login/9 Player 초기화는 추가 연결이 필요하다. 기존 검사 장면의 고정 seed 입력을 임의로 바꾸어 이전 성공 근거를 덮어쓰지 않았다. 이번 독립 fixture/report는 `campaign-seed-x86.tsv`, `campaign-seed.json`이며 현재 source/log/history/실행 SHA는 `run24.json`에 고정한다.

최종 Release 경고/오류0, 새 집중2개 및 전체 CTest **1/1·내부1,131개·실패체크0**(174.43초)다. 로그는 `run24-build-final.log`, `run24-seed-final.log`, `run24-all.log`다. 로컬 커밋 메시지는 `20261015-09 실제 세션 경계 감사와 게임 재시드 전제 복원 검증`이다.
