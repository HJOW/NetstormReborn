# 1046 — 접속 완료 통지와 별도 송신버퍼

1045에서 남긴 bootstrap1/004e2f00과 접속 전 별도22송신버퍼를 실제 Registry/각 backend에 연결했다. 마지막 전체 정밀 디컴파일은 **2026-11-03 / HJOW-Athlon**이다.004e2270/004e2620/004dece0/004e2f00의 정밀 C와 보호 PE를 읽기 전용으로 대조했으며 산출물은 변경하지 않았다.

004e2620 직접 호출은 **4곳/2함수**다.4b3f8c의 ID10/11 경로와4b77b2/4b857e/4b85c6의 ID9 경로는 모두 네 번째 초기 패킷 인자가NULL이다. 정밀 C가 뒤 세 호출을3인자로 표시하므로 PE의 push0/EBP0/검사 뒤EAX0을 확인했다.4b6dd0의 EBP는 prologue의 frame 포인터를 저장한 뒤4b6df5에서0으로 만들며4b77b2까지 다시 쓰지 않는다. 이 정적 직접 호출 범위를 모든 간접/임의 외부 호출의 부재 증명으로 확대하지 않는다. 현재 기본 게임이 새 초기 패킷을 보내도록 바꾸지 않았다.

공통 몸체는 비제로 초기 패킷도 복원한다. 실제 TCP 노드 공개 뒤 해당 ID의 기존 버퍼를 반납하고 칸0을 쓴다. 새 입력이 비NULL이면004dece0처럼 **현재 packet의 observer(1)→현재 선언 길이WORD 재조회→그 길이만 전체 복제→현재 칸에 공개**한다. observer가 실제 입력 바이트를 바꿀 수 있고 copy는 바뀐 길이를 사용한다. 뒤 observer/할당 실패에서 앞선 접속/기존 버퍼 반납을 되돌리지 않는다. 문자열/20BYTE 주소 두 Connect와 현재 포트 문자열 경로가 같은 선택적 초기 패킷을 전달한다. 기본 빈 span은 원문NULL이다.

원문005e4a70의22칸은 전송의 aggregate/partial wire 큐와 별개다. 동일 Registry가 이 칸과 복제 물리를 소유한다. 노드와 겹치지 않는 같은opaque발급기를 쓰고 노드용 Owns/Node는 복제 버퍼를 노드로 보지 않는다. 실제 free 장치인 Release는 두 물리를 구별하며 기존 DisconnectTransceiver도 같은 복제를 반납한다. CloseAllTransceivers가 별도 버퍼를 임의로 지우지 않는 기존 순서는 유지한다.

bootstrap1은 실제 TCP/내부 미션/Editor 등록표에서 한 번 설치한다. 기존 수신기/버전/정책/observer를 덮지 않고 공유 표에 중복 설치하지 않는다. 비음수 ID의 현재 버퍼가 비영이면 **현재 transceiver의 가상+4**로 직접 보내며 Player/대상 송신 관문을 반복하지 않는다. 송신 callback이 칸을 바꿀 수 있으므로 정상 복귀 뒤의 **현재** 버퍼를 다시 읽어 free→칸0한다. 송신 실패에서는 원문처럼 free/0을 수행하지 않는다. C++ 호출 동안의 공유 물리 pin은 callback 중 해제된 원문 메모리 접근의 호스트 안전 경계이며 원문32비트 주소/해제 메모리 자체 동일성 주장은 아니다.

현재 TCP API의 빈 현재칸 접속 계약과 로컬IPv4 정책은 유지한다. 원문004e2620의 기존 연결 재사용/실패 교체·endpoint/server/boss/리슨·수락 전체 감사는 후속이다.1번 통지/별도22송신버퍼를 그 잔여와 합쳐 반복 미구현으로 세지 않는다.
