## 원문과 제품 연결

원문`004dea00`은 German3→English1→Portuguese6의 세 파일을 한 번 읽는다. French/Spanish 파일도 TARC에 있지만 시작 함수는 읽지 않는다. 새`RawXlat`과`InitializeRawXlat`은 같은 순서를 사용하며, Client의 실제 BaseFile 존재 조회→읽기와9번 부재 로그를 빌린다. 일부 파일이 없으면 다음 파일로 가고, 읽기 예외 때 앞서 완료한 언어를 되돌리지 않는다.

`004de710`은 읽은 파일의 **마지막BYTE를 NUL로 바꾼다**. CR은 첫NUL 전까지만 제거하고 원래 파일 크기로`memmove`하며, 이동 뒤 같은 위치를 다시 검사한다. 파일 크기는 줄이지 않는다. `004de260`은 줄 첫BYTE의`*`/`-`/`=`를 사용하고 구분자와 그 앞BYTE에 NUL을 쓴다. 마지막 불완전한 레코드는 저장하지 않는다. 코드와 실제 전체 버퍼 대조는 이 부분 쓰기를 포함한다. 닫는`=`가 파일의 마지막BYTE라면 NUL로 사라져 레코드가 완성되지 않는 경우도 유지한다.

같은 원문 키를 다시 읽으면 **해당 언어 칸만** 바꾼다. 다른 언어를 지우지 않으며 NULL 칸과 등록된 빈 번역을 구별한다. `004de9a0`처럼 영어0/1은 조회를 생략하고, 나머지는 정확한 C문자열 키와 현재 언어 칸을 사용한다. 없는 키/NULL 칸만 원문으로 돌아간다. 제품의 C++ 장부는 논리 키/언어 값을 소유하며 원문32비트 노드 주소·할당 배치 자체가 같다는 주장은 하지 않는다.

`Client::InitializeNativeTranslations`를 최초 번역된 창 제목보다 앞에 연결했다. 이후 언어 선택은 현재 번호`005435b4`에 해당하는 기존 칸을 읽으며, 아직 갱신되지 않았을 수 있는 공개 번호`00542384`로 번역하지 않는다. Config 변경 때10.78의 Xlat 파일을 다시 읽거나 장부를 비우지 않는다. 기존 단일`XlatTable`과 CD 어댑터는 유지했다. CD10.72의 전체 Xlat 부모를 새로 대조한 것은 아니다.

원문1252 바이트와 Client 내부 UTF-8 표시 변환은 구별한다. **원본과 다른 Windows10/11 표시 경계:** 1252로 표현할 수 없는 사용자 이름은 기존 UTF-8 문자열로 유지해 잘못 디코딩하지 않는다. 이 차이는 코드에도 명시했다. 한국어 표/글꼴·언어 메뉴 전체를 구현했다는 뜻은 아니다.
