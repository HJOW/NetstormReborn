## 본체와 기존 Tell 연결

[TellFileMenus](../../cpppj/src/client/TellFileMenus.cpp)는 실제 디스크 열거 순서로 파일을 수집한다. 파일명은 마지막 경로 구분자 뒤에서 첫 점부터 제거한다. 이름 Config가 이미 등록되어 있으면 **첫 등록 객체를 재사용**하고, 없으면 같은 Registry에 등록하여 `path`, `fileName`, `index`를 원문 Append 순서로 쓴 뒤 현재 실제 파일 읽기로 본문을 적재한다. 최초 메타는 파일 본문의 같은 이름 키보다 우선한다. 새 객체는 페이지 교체 후에도 같은 Client 목록 수명에 남는다.

중복은 경로 문자열이 아닌 같은 Config의 고정 prefix 정체성으로 제거한다. index는 **고유 이름을 수집한 순서**이고, 표시 순서는 원문 두 겹 비교/교환에 따른 **대소문자 무시 prefix 순서**다. 제목으로 정렬하지 않는다. 기존 Config의 path/index를 다시 쓰거나 같은 기본 이름의 다른 경로를 새로 적재하지 않는다.

각 행에서 실제 지역 `cur` Config를 등록하여 `cur.file`을 쓰고 `{{local.1}.title}`을 현재 Config로 치환한다. @는 빈 제목을 파일명으로 바꾸고 #는 빈 제목을 보존한다. `--`로 시작하는 제목은 구분선이며 인자 치환/고리를 소비하지 않는다. 일반 행은 원문 인자를 한 번 치환하여 **숫자로 시작하더라도 문자열 고리**에 쓴다. 지역 cur는 실제 메뉴 작성 콜백이 반환한 뒤 반납된다. 원문 지역256/80/1024BYTE와40개 prefix 밖의 오버런 입력은 호스트에서 명시 거부하고 앞선 정상 효과를 보존한다.

[UberGump](../../cpppj/src/client/UberGump.cpp)의 기존 Tell은 메타를 추출하는 시점에 이 본체를 호출한다. 이전의 전체 파싱 후 파일명 정렬/Script 적재에 의존하던 @ 목록 대신 같은 등록부/cur/고리의 현재 값을 사용하며 #도 같은 원문 본체에 연결했다. [RawMenuHtml](../../cpppj/src/client/RawMenuHtml.inc)의 실제 전체 HTML은 같은 목록 소유자를 빌려 실제 `MenuGumpControls.AddText/AddSeparator`로 작성한다. 명시 하위 콜백이 있는 기존 검사/호출은 그 콜백을 유지하며, 목록 소유자/고리가 없는 선택 분기는 계속 명시 실패한다.

기존 Tell 부모의 표시 어댑터는 남아 있다. 따라서 그 어댑터의 행 높이/구분선 외관이나 페이지 전체 배치가 원본과 같다고 주장하지 않는다. 실제 공통 메뉴 작성·반납과 기존 표시의 목록 내용/명령 연결을 구별한다. `%` 목록은 별도 함수이며 이번 @/# 복원에 합치지 않았다.

## 독립 원문과 검사
