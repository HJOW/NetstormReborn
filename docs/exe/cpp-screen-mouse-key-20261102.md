# Guide 앞 F12와 전체화면 마우스 모드 (단위744)

2026-11-02 / HJOW-Athlon / Windows10. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 기존 산출물은 바꾸지 않았다. AGENTS.md와 현재 cpppj/dotnetpj 인계를 다시 읽었다.743의 현재 demo 선택 관문 수정·검사·커밋은 완료한 진척이다. 실행 제품은 **744 / 표시11.01**이며 전체1~8차 목표는 진행 중이다.

## 실제 누락과 원문

남은 DD 조정 UI를 확인하면서 원본 `AdjustDirectDraw` 안내가 제시하는 F12 기능의 실제 입력 연결이 없음을 찾았다. 기존495는 조정 버튼·확인/취소·15초 복구를 이미 확인했으므로 이를 새 미구현으로 되돌리지 않았다.

원문 `004d6e34..004d6e60`은 전체 사건 마스크가 `007b0000`이고 뗌이 아니며 현재 `005c78d4&1`이 참이면 현재 모드에 `0x40`을 XOR하여 `00435ba0`을 즉시 호출한다. 수정키/폴링 상위 표시는 추가 거부하지 않는다. 그 뒤 `004d6e61`의 Guide 처리와 Gump/콘솔·정지 검사를 계속한다. 일반 `ScreenModeChange`의 확인 Tell을 예약하는 기능이 아니며 `workingFullScreenFlags` 승인도 별개다. 뒤쪽 Ctrl+Shift+F12 개발자 분기/특수 허용값은 켜지 않았다.

새 격리 도구 `tools/decomp_screen_mouse_key.py`는 실제 기계어552입력을 두 x87 정밀도에서 **1,104회** 실행했다. Shift/Control/Alt/폴링 상위 표시32조합·뗌·화면 DWORD8종과 다른 사건을 교차했다. 모드 읽기와 실제 화면 장치의 단일 DWORD 인자만 관측하며 Guide 직전에 멈춘다. 스택0복구·바깥 canary·비휘발/x87·코드 불변을 확인했다. 장치/Guide 전체 동작이나 OS는 에뮬레이션하지 않았다. 새 fixture는 `screen-mouse-key-x86.tsv` 한 개다.

## 제품 연결

`DispatchScreenMouseKey`는 대상 사건일 때만 현재 모드를 읽고 전체화면이면 같은 장치를 즉시 호출한다. `UberGump::Event`의 영화/Guide/모달 앞에 연결하며 원문처럼 같은 사건의 후속 처리를 계속한다. 전환 장치는 기존 `Client::ChangeScreenMode`를 사용한다. **원본 DirectDraw 대신 Windows10/11 borderless/DIB 호환 장치를 사용하는 차이**를 호출 위치에도 한국어 주석으로 명시했다. 원본 법적 모드 계산과 기존 출력/설정 정책은 바꾸지 않았다.

검사용 UI 스크립트의 키 이름표에도 F12를 추가했다. 이것은 검사 입력 이름을 실제 Win32 가상 키 값으로 보내는 추가이며 물리 `Client::KeyEvent`의 키 생성 규칙 변경이 아니다. 모드 전환을 일반 입력 큐의 후속 명령으로 미루거나 모달 뒤에 연결하지 않는다.
