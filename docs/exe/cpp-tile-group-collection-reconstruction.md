# cpppj 지면·다리 행별 표시 묶음 복원

2026-10-11, `HJOW-Athlon`. AGENTS.md와 두 인계 문서를 확인했고 마지막 디컴파일 PC가 현재 PC와 같았다. `tilegroup` 목록으로 패치 5개·CD/추가판 각 4개를 읽기 전용 내보냈다. 마지막 디컴파일 수행 PC는 **HJOW-Athlon, 2026-10-11**이다.

`TileGroupCollection`으로 실제 `SquidHash` 0단계의 머리 SID와 `SidPool` raw 슬롯을 읽어 행별 묶음을 만든다. `BindTileGroupCollection`은 공통 수집과 kind 1 분배를 같은 저장소에 연결한다. 카메라 투영·실제 SHP 출력·Client 자동 프레임은 후속이다.

## 원본 근거와 수집 동작

| 내용 | 10.78 | CD/추가판 |
|---|---|---|
| 행별 묶음 수집 | `00433410` | `004884a0` |
| 두 좌표의 셀 환산 | `00432580` | 수집기에 인라인 |
| float 좌표 +0.5, CRT 절삭 | `0043fa50`→`004e49c0` | `0048ee10`→`004f161c` |
| 현재 해시 칸 주소 | `004b29a0` | `00479be0` |
| SID 슬롯 크기/깊이 | 50바이트 / `+35` | 36바이트 / `+33` |
| 행 개수 assert | `count < height/11+6` | `count < 49` |

좌표 보조 함수의 Ghidra 의사코드는 float 인수 읽기와 `+0.5`를 누락한다. 실제 `fld [esp+4]`·상수 `fadd`·CRT 점프를 확인했고, 재생 검사에서 발견한 차이를 고친 뒤 반올림 경계 양쪽 입력을 추가했다. float으로 합을 먼저 저장하지 않는다. CRT 64비트 정수의 하위 DWORD를 signed 셀 좌표로 사용하고 우선 최대 255로 제한한다. 왼쪽/위는 1을 빼고 오른쪽/아래는 1을 더한 뒤 각 끝을 독립적으로 0~255로 제한한다. 확장 DWORD의 넘침도 보존한다.

수집 때 해시를 0단계로 바꾸고 **y 바깥·x 안쪽 순서**로 방문한다. 각 칸의 첫 SID만 읽으며 next 체인은 따라가지 않는다. type/state/dead/실제 프레임 크기를 검사하지 않고 같은 SID가 여러 칸에 있으면 그대로 중복 제출한다. raw `+14/+18` x/y, 객체 토큰, **signed BYTE→signed WORD 깊이**, `kind=1`, `tail=0`을 16바이트 멤버에 쓴다. 빈 칸은 배경 덮음 결과를 false로 만든다.

빈 행은 헤더를 만들지 않는다. 각 유효 행의 헤더는 첫 멤버와 양수 개수를 가리킨다. 행 사이 빈 칸을 위해 멤버 배열을 띄우지 않고 연속으로 기록한다. 방문 칸이 없으면 배경 덮음은 true로 남는다. 정상 종료는 이전 선택과 관계없이 해시를 **2단계**로 바꾸고 배경 결과를 기록한다.

## 제한·토큰·실제 연결

기존 `DrawCollectionRequest.groupTime`을 **`groupRowLimit`**으로 바로잡았다. 원본 인수는 시각이 아니라 각 행의 `count < drawListSize` assert 값이다. 패치 Renderer는 `((width/16)*(height+10))/11`, CD Renderer는 `0x6f5`를 공급한다. 새 API도 호출자가 값을 공급한다. 기존 상위 Renderer fixture의 인자 관찰은 유지했고 표시 병합 재생 검사는 변경된 이름을 사용한다.

이 제한은 전체 멤버 개수가 아니다. 예를 들어 두 행 각각 2개·limit 3은 정상이며 전체 4개를 제출한다. 원본은 멤버 기록 뒤 strict 제한을 검사한다. 행 헤더도 기록 뒤 판본별 strict 상한을 검사하므로 CD는 최대 48개, 패치는 화면 높이 768에서 최대 74개가 유효하다. 새 C++는 bounded 256×256 해시만 방문하고 전체 월드만큼 멤버 저장소를 예약한다. 실패 전의 부분 멤버/헤더와 0단계 선택은 남을 수 있으며 배경 반환 인수는 정상 종료에서만 바뀐다.

32비트 원본 포인터를 64비트 호스트 포인터로 해석하지 않는다. 상태의 `objectTokenBase + SID*stride`, `groupTokenBase + headerIndex*8`을 사용한다. 두 전체 토큰 영역의 겹침/넘침을 생성 때 거부한다. `Object`는 실제 SID로, `Group`은 현재 수집의 헤더/span으로 되돌린다. pool/hash는 수집기보다 오래 살아야 한다. 반환 목록은 다음 수집/소멸까지 유효하며 같은 수집기의 재진입은 지원하지 않는다.

공통 목록은 각 행의 **첫 멤버 키**로 정렬하고 상위 항목 tail을 보존한다. kind 1 분배는 행 내부를 다시 정렬하지 않고 모두 sprite 경계에 보낸다. 실제 SID 5·6의 첫 행과 SID 7의 뒤 행을 연결한 검사에서 높은 깊이의 뒤 행을 먼저 그린 뒤 첫 행의 SID 5→6 순서를 유지했다. 묶음 숨김과 UI 전용 dirty의 수집 생략도 검사한다. 실제 SHP sprite 경계와 GUI 프레임은 아직 연결하지 않았다.

## 독립 원본 대조와 검증

`tools/decomp_tilegroup_oracle.py`는 세 실제 PE의 전체 수집기/좌표 보조/해시 주소/CRT 명령을 실행한다. **응답 대체 경계가 없다.** 완성 raw 슬롯과 희소 칸 입력만 생성하고 기대 방문 범위나 목록은 계산하지 않는다. fixture에는 전체 96개 멤버·64개 헤더의 바이트, 배경 결과, 현재 해시 상태, 실제 함수 진입 수와 보호 바이트를 저장한다.
