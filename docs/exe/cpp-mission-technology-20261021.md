# Early Missions의 실제 기술 허용 목록 연결

단위252는 `2054e074`에서 시작했다. 현재 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-20**로 일치한다. AGENTS와 양 인수인계를 다시 읽었으며 새 디컴파일·원본/CD·AGENTS 변경은 없다. 전체11미션의 자연 플레이/원본 동일성 목표는 진행 중이다.

## 빠진 초기화와 실제 허용 표

보호 Early Missions1~6은 모두 `techAllowed=deny;all;allow;...`를 가진다. 기존 Client 단계1은 이 목록을 적용하지 않아 실제 Session의 허용 표가 처음의 전부 허용 상태로 남았다. 사제 건설 메뉴와 생산은 같은 `RawTotalMade`를 이미 사용하므로,설정을 실제 표에 적용해야 원래 제한이 작동한다.

`MissionTechnology`는 원본 `00482eb0`의 전체 목록 처리다. 모드는1(허용)에서 시작한다. 대소문자와 무관한 deny/allow는 모드만 바꾸고 all은 `004c23c0` 상당의 첫255DWORD를 갱신한다. 다른 이름은 실제 `RiftTypeTable::Find` 뒤 `RawTotalMade::Allow`에 현재 모드를 전달한다. 256번째 물리 칸은 all의 대상이 아니다. 목록을 한 번 나눈 사본으로 캐시하지 않고 매 인덱스마다 현재 `mission.techAllowed`를 다시 읽는다. **첫 빈 항목에서 끝나며 공백은 다듬지 않는다.**

원본 `00482d50`의 항목 선택은 C 문자열의 첫NUL을 따르고 세미콜론만 구분한다. 기존 ConfigListItem을 사용하되 호출 경계에서 첫NUL 뒤를 제외한다. 내부 UTF-8 설정은 원본 Windows-1252로 바꾼다. 원본512BYTE 임시 버퍼를 넘는 입력은 예외로 거부한다. 실제 미등록 이름은 원본에서-1을 반환해 허용 표 앞 DWORD를 덮어쓴다. 이 원본 결함은 격리 관측에 보존하고 제품의 기존 RawTotalMade 물리 범위 검사에서는 예외로 드러낸다. 미등록 항목을 건너뛰어 성공시키지 않는다.

Client는 Tutorial 단계1의 현재 월드/로그인 설치 뒤,사용자 입력과 단계3 Start 전에 같은 `world_->Session().TotalMade()`에 목록을 적용한다. 새 허용 표나 메뉴 전용 사본은 없다. 원본의 loadFort는 State7을 예약한 뒤 이 목록을 적용한다. 현재 Client는 기존 동기 설치 어댑터 뒤 적용하므로 **전체 비동기 State의 복원 근거는 아니다.** 외부 입력/후속 AI Start 전에 같은 최종 제한을 설치한다.

원본 Tutorial 소멸 `004c3210`은 `AllowAll(1)`로 제한을 해제한다. 현재 어댑터는 Session의 실제 표를 반납하고 새 Session을0으로 생성한다. 따라서 목록이 없는 캠페인/데모5개는 이전 Early 제한을 승계하지 않는다. 전체 가상 소멸을 구현했다는 뜻은 아니다.

## 제품 변경 전 관측과 검사

`decomp_mission_technology.py`는 실제 `00482eb0/00482d50/0049a860/004c23c0/004c23e0`와 CRT를 **55고유 입력·55정상 반환·665852실제 명령**으로 실행했다. Config 조회/512임시 버퍼/키 서식/TLS만 명시 경계다. 원본 자산 로딩 순서의 타입 이름을 독립 입력으로 공급한다. 첫 빈 값/대소문자/모드 반복/빈 중간 항목/공백/미등록/NUL·조회 중 설정 변경·보호11목록을 교차하며 같은 입력은 중복 제거했다.

전체257DWORD(표 앞 한 칸+물리256칸)와 실제 조회/쓰기 호출 순서를 보존한다. 제품 코드로 기대값을 만들지 않았다. 정상 반환/스택/보존 레지스터와 x87 제어어를 확인했고 게임/OS/창은 없다. 첫 성공 도구/fixture/JSON은 제품 변경 전에 `extracted/mission-technology-20261021-first-capture/`에 동결했다. 기존 원문/실행 결과를 덮어쓰지 않는다.

fixture SHA-256은 `19c5c321acdac977b365eb61d928ba7616387f51f92c3ac4b8add7b18298ee00`다. 첫 캡처의 도구/JSON/fixture는 현재 독립 원문과 바이트가 같다.

## 다음 작업의 주의점

초기화의 약화 체력 전역 `005ca8f0`은 `004c3290`에서 tutorialNumber가 비제로일 때1로 되지만 **후속 State7이 부르는 `004b2df0`에서0으로 다시 초기화된다.** 앞 쓰기만 보고 실제 세션의 사제 체력을1/4로 바꾸면 실행 순서와 어긋난다. 이번에는 체력 계산/원본 파일을 바꾸지 않았다.

Review Knowledge와 사제의 View Netstorm Knowledge는 실제 `ShowTechnology=020000a0`·`00492b60`을 사용한다. 전체 기술 카드/정렬·원소별 배치/입력·현재 팝업 상태 연결은 아직 필요하다. 전체 Init의 이름 정규화/+b0/전역·비동기 State/원본 공장·가상 소멸,중첩 창/다른 키·전략AI·지형 효과/자연 포획·희생·대피,11미션 자연 완주와 외관/음향 동일성의 통합 검증도 남는다.
