# 단위325: 원본 저장 부모와 실제 편집 작업본 저장

시작 HEAD는 `5916e84f`이며 깨끗한 트리에서 시작했다. 작업 PC와 마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-22**로 같다. AGENTS와 양 인수인계를 다시 읽었다. 직전 단위는 실제 Fort 목록 연결/전체2,255개 통과/커밋을 완료한 진행 턴이었다. 전체 캠페인으로 확대된 현재 목표를 유지한다.

## 원본 저장 순서

편집 진입의 State dirty/Notify가 실제 파일 저장을 요청하므로, UI 활성화에 앞서 저장 경로를 연결했다. `RawDataManagerFileSave`는 보호 PE의 **0044d8d0**을 옮긴다.

1. MarkStream20의 네 DWORD를0, mark를-1로 시작하고 0044d640 이미지 생성을 먼저 수행한다.
2. 생성 효과 뒤의 `readOnlyForts`0054db30과 로컬 번호00540c70/숨김 표0052f81e를 읽는다. 저장 억제 중에도 이미지 생성은 수행한다.
3. 이미지 포인터는 생성 직후 보관한다. 실제 가상 파일명 getter004bcca0을 조회하여 CRT chmod에 모드0x180을 전달한다.
4. 권한 효과 뒤의 이미지 길이를 보관하고 파일명 getter를 다시 조회하여0041bb90에 이름/앞서 보관한 포인터/길이를 전달한다. 둘째 이름 조회가 source.end를 바꿔도 이미 보관한 길이는 바뀌지 않는다. 저장 관문은 권한 효과 뒤에 다시 검사하지 않는다.
5. 보관한 포인터가 비영이면 한 번 반납한다. 호스트 예외에서도 이미지 할당 반납을 한 번 시도한다. 이 예외 정책이 원본 SEH의 모든 변이를 복원했다는 뜻은 아니다.

새 격리 도구는 실제 저장 부모와 실제 파일명 getter를 실행한다. 이미지 생성/CRT chmod/OS 파일 쓰기/할당 반납만 명시 외부 경계다. **144입력×두 x87 정밀도=288회 저장 부모**, 실제 이름 getter108회를 관측했다. 전역 저장 억제0/1/-1, 소유자0/1/8, 숨김0/1과 이미지 생성/권한/둘째 이름 조회의 명시 메모리 효과를 포함한다. 실제 source20/manager64/현재 전역/요청 순서를 C++와 비교한다. 이 효과 입력은 관측 장치가 삽입한 것으로 전체 원본 게임에서 자연 발생한 사건을 뜻하지 않는다.

새 fixture의 최초 TSV 헤더를 공용 로더의 주석 형식으로 맞췄다. 헤더를 제외한 원본 관측 데이터의 SHA가 그대로임을 확인했다. 기존 fixture는 바꾸지 않았다. 새 관측 범위와 SHA는 [출처](../../cpppj/datamanager-file-save-20261022.json)에 기록한다.

## 실제 Template/State 연결

`RawPlayerTemplateState::BindFileSave`는 PATCH Notify의 기존 isMine/미션 진단/Template 존재/preventSave 관문 뒤에만 실제 저장 소비자를 호출한다. 미연결 상태의 명시 실패와 CD 미확정 경계는 유지한다.

`CampaignTemplateStorage::SaveFile`은 같은 manager/원시 섹션과 기존 `RawFortImage`를 실제 저장 부모에 연결한다. 가상 서명은 manager+10c에F를 쓰고 +110의-1 기본값을0으로 정규화한다. 과거 `fort.flag` 사본을 쓰지 않는다. 각 섹션은 원본처럼 같은 이름 목록에서 검색하여 manager.current를 갱신하고 source stream의 pos를 초기화하지 않는다. 정상 전체 이미지 뒤 current는Terr19다.

기존 값형 이미지 API는 같은 기본 동작을 유지하며 실제 manager 공급자가 있을 때만 서명/섹션 조회를 위임한다. 004bcd8f의 실제 **signed JL**을 확인하여 현재 타입 개수의 음수 DWORD가 불필요한 진단을 내지 않도록 비교를 맞췄다. 고정32768BYTE 할당/35섹션/길이WORD와 물리 범위 보호는 유지한다.

## 편집 작업본과 원본 보존

`EditorFiles`는 명시된 작업 루트와 원본/CD 보호 루트들을 사용한다. 작업본은 없을 때만 원문으로 준비하고 기존 사용자 파일은 유지한다. 실제 경로를 권한 변경과 쓰기 직전에 각각 확인하여 작업 루트 밖/보호 루트 안의 요청을 거부한다. 포맷 저장 관문은 원본 부모가 결정하고 이 장치는 chmod와w+b 파일 쓰기만 수행한다. 실제 작업 루트/부모 폴더 준비는 호스트 초기화이며 원본 게임 규칙을 대체하지 않는다.

검사는 보호 TEST01을 새 빌드 산출물 아래 작업본으로 준비하고 현재 State 원문을 수정한 뒤 빌린 헤더의 **Notify→같은 manager 이미지→실제 권한/파일 쓰기→Fort 재읽기**를 수행한다. 저장된 모든 raw 섹션이 현재 Template과 같고, 다음 Prepare가 사용자 저장 내용을 되돌리지 않는지 확인한다. 원본/CD 직접 쓰기, 권한 변경, 작업 폴더 이탈은 거부하고 보호 원문을 다시 읽어 같음을 확인한다. 생성물은 검사 전용 새 디렉터리에만 남긴다.

전체 파일 저장 억제와 숨김 관문은 직렬화까지 수행하되 작업 파일을 바꾸지 않는다. Template isMine/preventSave는 Notify 단계에서 저장 부모를 부르지 않는다. 신규 manager의 서명 정규화, 현재 검색, 음수 타입 개수도 검사한다.

첫 빌드의 namespace 닫는 중괄호 누락과 다음 빌드의 검사 상수 이름 충돌은 수정했다. 최종 빌드/집중 검사/전체 회귀 결과는 출처 JSON과 `extracted/cpp-editor-file-save-20261022-*` 로그에 보존한다.

첫 전체 회귀의 PlayerRegular 두 판본 검사에서는 미연결 진단 문구를 기존 경계 대조 코드가 인식하지 못했다. 저장 장치를 주지 않은 장면은 여전히 같은 원본 저장 호출 지점에서 멈추므로 새 문구도 그 경계로 인식하도록 고쳤다. 원본 fixture와 비교 조건은 유지했다.

최종 Release 빌드4는 **종료0·경고0·오류0**다. 새 검사6개, 기존 이미지4개·PlayerRegular3개가 실패check0이며, 전체 **2,261개·실패check0·exit0**, 실제176.65초/CTest전체176.66초로 통과했다. 보호 PE 두 개·TEST01·TAFF의 작업 전 SHA와 같고, 저장 검사는 보호 원문을 다시 읽어 같은지 대조했다. 실제 Client/편집 월드의 검증으로 확대해서 해석하지 않는다.
