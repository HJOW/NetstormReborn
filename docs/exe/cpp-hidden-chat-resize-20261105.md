# 숨긴 Chat의 화면 전환 뒤 복원 위치 수정 (단위921)

Chat을 숨긴 채 해상도를 바꾸면 다시 열 때 이전 화면의 위치로 복원되는 결함을 수정했다. 제품921/11.01을 빌드했으며 관련 고유10사례가 통과했다.

## 결함과 수정

640×480의 실제 전체 Uber/Chat 구분선은 표시 위치384로 하단96픽셀을 남긴다. 숨김 입력은 구분선을480으로 옮기고384를 savedChatY에 보관한다. 기존 RawUberRootControls::Reflow는 숨긴 구분선을 새 화면 끝으로 옮겼지만 savedChatY는 바꾸지 않았다. 따라서800×600에서 다시 열 때504 대신384로 돌아갔다. 새 검사의 네 해상도 전환 모두 이 결함을 검출해 처음4단언이 실패했다.

Reflow는 기존 Chat 구분선이 이전 화면 끝 이상에 있을 때 savedChatY에도 같은 높이 차이를 더한다. 실제 구분선·슬레이브·지도 갱신은 기존 경로를 사용한다. 원본의 고정 해상도 몸체는 바꾸지 않았다. 이 변경은 Windows 화면 장치 전환을 지원하기 위한 호환 확장이며 코드 주석에 이유를 적었다. 실제 제품 호출은 UberHud.inc의 InstallHud→Reflow다.

## 확인 결과

- 실제 전체 공장/자식과 같은 루트에서 숨김→SetControls→Reflow→재표시를800×600·1280×720·1024×768·640×480으로 왕복했다. 복원 위치504/624/672/384와 하단96픽셀을 유지하고 루트/Chat/생산/전체 등록 수가 보존됐다.
- 기존 전체 Uber 생성·교체·표시 중 재배치3사례, 실제 드래그 후 Chat 토글1, 현재 덱 표시1,1024 HUD 모드1, Chat 입력 전환1·실제 스타일/클립 표면1과 원문 도킹2,150입력1사례가 통과했다.
- 최종8명령/고유10사례·실패0이다. 최초4단언 실패는 제품 수정으로 해소했으며 검사 기대값은 바꾸지 않았다. 초기/수정 빌드2명령(MSBuild3호출)은 모두 종료0·경고/오류0이다. 빌드 중 소스 편집·동시 빌드는 없었다.

마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-11-03**이며 현재 호스트와 같다. 기존 원문 HudDock fixture와 코드 경계에만 의존하고 정밀 산출물은 수정하지 않았다. 보호2,787개/fixture967개 불변·새 Native/fixture0·checking8·활성74프로젝트다. 새 대상 대신 기존 issue_commands 집중 대상에 전체 HUD와 도킹 검사를 연결했다.

제품921의 파일/제품 버전은11.01, EXE는10,787,840바이트, SHA-256 `fca9945c0f858e6d9088680ad359fd948ab4106d6dba0ce31ad2d47b5620dcd0`다. 실제 게임/GUI·포획/희생/공격/승리·공중3종 전용·신규MP/패킷/통신·물리입력/PCM/CD·전체검사/34미션/ZIP은 실행하지 않았다. 실제 화면 장치/물리 관측을 완료했다고 쓰지 않는다.
