## 비패턴 생성과 진행

패턴이 없는 타입은 타입 footX/footY와 별개로 반복 개수가 **1×1**이다. 방향은 signed int의 `/2`이며 0..3 회전을 지원한다. 패치는 홀수 방향과 DWORD 0xffffffff(-1→회전 0)를 실제로 처리한다. CD 생성자는 홀수 방향을 assert하며 C++는 별도 예외로 진단한다.

기본 모드는 타입 `+0x118`의 **기본 프레임**을 사용한다. 명시 모드(`+0x50` 비영)는 첫 인자를 프레임 번호로 사용하고 타입 프레임 개수 `+0x114`로 검사한다. 일반 배치는 `(type,type,flags,x,y,0)`이므로 기본 모드다. 비패턴 한 칸의 좌표는 원래 x/y이며 첫 Advance에서 프레임을 고른다. 기본 프레임 **-1**이면 유효 칸이 없어 Valid=false가 된다. 다음 Advance에서 끝나며 마지막 frame/좌표를 유지한다.

기본 프레임의 개수 범위 검사는 원본 기본 경로에 없으므로 임의로 추가하지 않았다. 원본 프레임 코드 디버그 검사 전역은 이번 관찰에서 0이다. 유효 SHP/프레임 자료 공급과 픽셀 조회는 별도 경계이며, 잘못된 메타 자료를 실제 자산으로 해석하지 않는다.

## 서로 다른 두 범위 계산

미리보기 범위 조회는 Valid=false여도 현재 좌표와 순회 개수를 사용한다. 비패턴에서는 다음과 같다.

```text
right = trunc(currentX), bottom = trunc(currentY)
left = right - footX, top = bottom - footY
```

**한 칸 발자국이면 좌표 21,22의 미리보기 범위는 20,21..21,22**다. 기존 주변 한 칸 표시까지 포함하면 4×4, 즉 16칸을 검사한다. 이 차이를 기존 미리보기 훅에서 공급했던 합성 사각형과 구분한다.

충돌 finder 인자는 유효 칸만 대상으로 현재 발자국을 읽어 계산한다.

```text
snappedX = float(trunc(currentX)), snappedY = float(trunc(currentY))
left = trunc(snappedX - (footX - 1))
top = trunc(snappedY - (footY - 1))
right = trunc(wide(currentX) + float(0.99999))
bottom = trunc(wide(currentY) + float(0.99999))
```

올림 보정은 원본 단정도 상수를 넓은 덧셈에서 사용한다. 미리 float로 저장하여 경계가 달라지게 하지 않는다. 원본 finder의 이후 지도 클램프는 기존 실제 `RawSquidFinder`가 수행한다. `Bounds`/`CollisionArea`의 산술·비유한 입력 진단은 원본의 미정의/범위 밖 입력과 별도 C++ 계약이다. 큰 발자국의 범위 대조는 전체 12×12 미리보기 배열의 안전성을 증명하지 않는다.

## 실제 연결과 경계 순서

`MakePriestGeometryPreviewHooks`는 미리보기 범위만 실제 decoder에 연결한다. `MakePriestGeometryCollisionHooks`는 후보 검사기의 모양 순회를 연결하고 후보별 지형 경계를 유지한다. 연결은 같은 풀/판본만 허용한다. 호출자는 현재 특수 패턴 타입 번호와 프레임 코드/기본 프레임 메타 자료를 공급해야 한다.

지역 초기화는 decoder 생성 뒤 호출한다. 유효 칸마다 실제 사각형 계산→실제 finder/후보 검사→모양별 지형/주변 관계 경계→Advance 순서다. 후보 거부 뒤에는 모양 후처리/최종 지역 처리를 호출하지 않는다. 기본 프레임 -1이면 초기화/최종 지역 처리는 수행하고 finder/모양 후처리는 호출하지 않는다. 초기화 중 메타 기본 프레임이 변해도 이미 고른 frame을 유지하고, 발자국은 사각형 계산 시 현재 값을 읽는다. 요청 값 인자는 복사하여 외부 호출자 변경이 섞이지 않는다.

두 판본 생성 통합은 **실제 decoder 범위/순회·접두·미리보기·finder·충돌 후보·사제 생성자/postCreate**를 연결한다. 첫 **21,22** 충돌 거부→다음 **21,21** 생성, 새 SID **15001/6001**, WORD **0x8101**이다. 지역 초기화 2회·모양 후처리 1회·최종 지역 처리 1회·Pop 요청 1회와 실제 미리보기 표시 **16칸**을 확인한다.

**초기 픽셀 모양 조회/SHP 연결(`0043cbd0`/CD `004ed7c0`), 후보별 bridge/표면/지형/지역/관계 몸체와 최종 지형 판정, 일반 Pop/가상 Carrier 검사 몸체는 남은 경계다.** 내보내기에는 픽셀 모양 조회도 포함하지만 이 함수는 이번 기계어 실행 대상이 아니다. 특수 패턴 타입으로 바뀐 입력도 미지원 계약으로 진단한다.

## 독립 기계어 관찰

[`decomp_priestgeometry_oracle.py`](../../tools/decomp_priestgeometry_oracle.py)은 세 PE에서 패치 **2,304개**, CD/10.37 각각 **1,024개**, 총 **4,352개**를 독립 실행한다. signed 방향·CD 짝수 제한·기본/누락/명시 프레임·기본 프레임 개수 검사 생략·여러 발자국·음수/소수/절삭 경계·지도 끝 좌표를 포함한다. x87 FPCW **0x027f/0x037f** 관찰이 모두 일치한다.

생성/Advance/정수 Bounds는 실제 thiscall 호출과 정상 반환/ESP·보존 레지스터·x87를 검사한다. **충돌 사각형은 MayPlace의 중간 구간에 현재 좌표/타입 지역 변수를 공급하고 finder 함수 진입에서 인자를 관찰해 종료한다. 전체 MayPlace/finder/후보/지형을 원본 실행했다고 해석하지 않는다.** 생성/진행/추가 패턴 타입 조회/발자국/snap/CRT 명령은 대체하지 않는다. 원본 패턴 전역은 0, 사제 타입은 158, 패치 프레임 디버그 전역은 0이다. CD 홀수/잘못된 명시 프레임 assert는 정상 fixture에서 제외하고 C++ 진단으로 검사한다.

패치·두 정밀도 합산 실제 생성/추가 패턴 타입 조회 **4,608회**, Advance/Bounds/발자국 **9,216회**, 타입 getter **15,552회**, snap/사각형 진입/finder 인자 관찰 **3,456회**, CRT **39,168회**다. CD/10.37 각각 생성/추가 패턴 조회 **2,048회**, Advance/Bounds/발자국 **4,096회**, snap/사각형 진입/finder 경계 **1,536회**, CRT **17,408회**다. finder 몸체와 assert/OS 실행은 **0회**다.
