# 장치 경로 실패 뒤 BaseFile 재조회 복원 — 단위644

## 결과

현재 VFS가 미구현으로 표시했던 장치 경로의 재조회를 실제 읽기 부모0041b4c0에 맞춰 연결했다. 예를 들어 `C:\game\d\a`가 디스크에는 없고 현재 TAFF에만 있으면 직접 열기 실패 뒤 기본 아카이브에서 읽는다. 드라이브 기준 상대 경로 `C:d\a`도 원본 FileSpec의 장치 경로에 포함한다.

일반 상대 입력은 기본 디스크→기본 TAFF→보조 디스크→보조 TAFF 순서다. 장치 경로는 먼저 원래 이름을 직접 연다. 실패하면 현재 이름과 기본 root의 **대소문자를 구분하는 공통 BYTE 접두 부분**만 제거한 뒤 기본 TAFF→보조 디스크→보조 TAFF로 이어진다. 전체 root가 일치하는지, 디렉터리 경계에서 끝나는지는 새로 검사하지 않는다. 첫 NUL 뒤의 데이터도 이름으로 쓰지 않는다.

조회 정책은 새 공통 `RawBaseFileReadPolicy`가 소유한다. 이미 Native28관측으로 고정한459c60 경로 조합도 같은 모듈로 이동하고 기존 Technical Help는 이 몸체를 호출한다. 빈 파일은 성공이며, 아카이브를 찾은 뒤 열기가 실패한 예외를 다른 경로의 성공으로 대체하지 않는다. 미발견의 nullopt/기존 Read의 예외 계약은 유지한다. 원본 FILE/예외 객체 ABI와 모드0 외의 쓰기를 합성하지 않는다.

## 현대 Windows 경로 어댑터

원본은 게임 폴더로chdir하지만 cpppj는 전체 프로세스CWD를 바꾸지 않는다. 같은 드라이브의 상대 경로는 가상 게임CWD에서 직접 읽어 디스크가 TAFF보다 먼저 선택되도록 연결했다. 다른 드라이브의 현재 디렉터리는 OS 해석에 남긴다.

UTF-8의 공통 접두 BYTE가 글자 중간에서 끝나면 나머지 이름은 W 경로로 변환되지 않을 수 있다. 이 경우 디스크 실패를 반환하고 다음 TAFF의 원시 BYTE 이름 조회를 계속한다. 정상 UTF-8 입력을 Windows10/11 W 경로로 읽는 차이와 가상CWD 처리는 코드에 한국어 주석으로 설명했다.
