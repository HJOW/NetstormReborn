# 현대 Windows 전체화면 — 단위495

현재 PC는 HJOW-Athlon/Windows10 10.0.19045다. 마지막 전체 정밀 디컴파일은 같은 PC의2026-10-23이며 산출물은 변경하지 않았다. 최종 기계 판독 결과는 [실행 보고서](../../cpppj/modern-fullscreen-runtime-20261027.json)에 기록한다.

## 구현과 원본 차이

원본 `004a4fe0`의 독점8비트 DirectDraw/페이지 flip 대신 현재 데스크톱 모드를 유지하는 borderless 창에 기존8비트 DIB를 출력한다. Windows10/11에서 사라진 DirectDraw 표면/팔레트에 의존해 종료 후 다음 실행이 실패하지 않도록 하는 호환성 변경이다. 해당 차이를 코드에 한국어로 명시했다. 원본 `ScreenModeIsLegal`의 계산/기존 검사는 그대로다.

- 원본 논리 화면, Renderer, 인덱스/팔레트, dirty 갱신은 유지한다. 현재 모니터에 비율을 맞추고 남는 띠는 검정으로 출력한다. 전체화면은 Renderer의 dirty 소비 뒤 프레임당 한 번 출력한다. 창 모드는 기존 BitBlt/dirty 경로다.
- 최종 전체화면 확대는 `ScaleScreenPresentation`의 정수 픽셀 중심 최근접 복사이며 `SetDIBitsToDevice`로 실제 RGBQUAD256색을1:1 출력한다. 표시 DC의 비정수 GDI 확대와 별도 메모리 DC의 표본이1366폭에서 달라졌기 때문에 장치의 확대 반올림에 맡기지 않는다. 초기의 ‘dirty clip만 제거하면 해결’ 가정은 실제 build3에서 반증됐고 그 결과도 보존했다. 로딩의 별도32비트 그림/문자는 논리 배치 후 GDI 확대다.
- 팔레트 변경은 이미 RGB로 출력한 전체 화면도 다시 칠한다.1366폭은 원본의 폭=행 간격 가정 대신 실제 DWORD 정렬1368을 사용한다. 확대 임시8비트 버퍼는 출력 프레임 수명으로만 소유하며 원본/게임 월드의 픽셀을 변경하지 않는다.
- 실제 클라이언트 좌표를 동일한 출력 사각형으로 역변환한다. Win32 마우스 메시지, 키/글자 사건, Poll이 같은 변환을 사용한다. 음수 마우스 메시지는 signed16비트로 해석한다.
- 모니터 전체 사각형/현재 DPI 픽셀을 사용한다. 활성 전체화면에서만 출력 영역으로 커서를 제한하고 포커스 상실·창 복귀·종료 때 반납한다. Alt-Enter/Options/Window Mode는 같은 장치를 사용한다. 해상도 변경은 현재 전체화면 모드를 보존한다.
- 원본 실패 표식 `fullscreenStateFile.dat`를 생성하지 않으며 남아 있던 표식은 새 호환 시작을 차단하지 않는다. `--window`는 저장된 사용자 시작 선택을 덮어쓰지 않는다.
- 원본 Tell `DirectDrawManager`와 `ScreenModeAbsChange`를 실제 장치에 연결했다. `ScreenModeChange`는 조정 비트/15초 확인/Cancel의 원본 Tell을 사용하고 `AcceptScreenModeChange` 뒤 기억한다. 현대 경로의 실제 모드는 항상DIB/비flip이므로 옛 DIB/flip 옵션을 독점 하드웨어 기능으로 구현했다고 주장하지 않는다. Parallax는 기존 실제 FourPage0 관문으로 비활성이다. 이 메뉴의 전체 원본 동일성은 별도 잔여다.
- 논리 캡처와 실제 OS 클라이언트 출력 캡처를 구별한다. `snapshot-output`은 실제 창 DC를 읽으며 논리 DIB를 다시 확대해 증거를 합성하지 않는다.

Microsoft 근거: [StretchBlt의 다른 모니터 DC 제약과 StretchDIBits 안내](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-stretchblt), [ClipCursor의 공유 자원/다른 앱 전환 전 해제](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-clipcursor).

## 검증 경계

새 호환 계산/실제 GDI 행 간격 검사5개와 실제 클론의 메뉴 전환/짧은 스테이지/저장 후 재실행을 확인했다. 원본 게임은 실행하지 않았다. 원본/CD/AGENTS 및 기존 검사/fixture의 바이트를 감사하며 최초 실패/첫 빌드/첫 실행도 `extracted/cpp-modern-fullscreen-495/`에 보존한다.

- 같은 최종 실행 파일에서 창→전체화면→800×600 해상도 변경→창→전체화면→Quit과 다른 프로세스 재실행을 확인했다. 남은 옛 실패 표식은 시작을 차단하지 않았고 새 표식도 남기지 않았다. `--window`는 실제 창 모드로 시작했다.
- 실제 읽기 전용 원본 설정은 workingFullScreenFlags=11/startInFullScreen=1/windowScreenFlags=10이다. 검사 프로세스의 `--set111`은 기억된 확인 모드를 덮어쓰지 않는다. 따라서 새 사본의 재시작은139(11+128), 확인한171을 저장한 뒤 재시작은171이다. 이전 사본 재사용의171과 처음 읽은11을235로 가정한 감사 실패도 보존하고 실제 시작 입력에 맞춰 구별했다.
- TheWarBegins의 브리핑→Play Mission→잠시 진행은 종료0이다. 이전 관측은 잘못된 선택적 Go! 클릭으로 브리핑에 머물렀으므로 새 분리 사본에서 필수 Play Mission/`page=mission` 관문으로 다시 실행했다.1366×768(실제 DIB 행1368)·정확16:9의1280×720·16:10의1280×800도 메인 메뉴 표시/종료0이다. 현재 모니터1920×1080에서4:3 출력은좌우240,16:10은좌우96의 검은 띠를 쓴다.
- 조정64의 실제235→171 미리보기→Cancel235, 다시 미리보기→OK171→AdjustDirectDraw와 별도 프로세스171 재진입을 확인했다. 확인하지 않은 별도 실행에서는 실제15초 타이머가235로 되돌렸다.
- 확대된 실제 클라이언트 위치에 보낸 Win32 마우스 메시지로 Options/Window Mode/Quit을 선택했고 Alt-Enter로 전체화면에 돌아왔다. 활성/비활성 메시지 주입에서 커서 제한/반납을 확인했고 종료 후 제한은 데스크톱 전체로 풀렸다. **활성 메시지는 명시 주입이며 실제 다른 앱 포커스 이동을 검증한 것은 아니다.**
- 논리/실제 출력 캡처의 메뉴·스테이지·1366폭·16:9·16:10 총9,121,920픽셀은 별도 Windows 메모리 DC에8비트 좌표 입력을 확대해 얻은 표본과 차이0, 모든 여백 검정이다. 이는 **표시 변환** 대조이며 원본 게임 화면/월드 전체의 동일성 판정은 아니다. [픽셀 도구](../../tools/cpp_fullscreen_pixel_audit.py)는 제품의 출력 보고값 대신 두 이미지 크기로 비율을 독립 계산한다.
- [원문 명령 관측](../../cpppj/screen-mode-commands-native-20261027.json)은 실제3입력/두 정밀도6정상 반환이다. 실제 조정 인자171/복구 인자10·`DirectDrawVerify(235)`·확인 후235 기억/AdjustDirectDraw를 관찰했다. 하위 실제 DirectDraw 장치 실행은 명시 경계이며 클론 기대값으로 만든 fixture가 아니다.

첫 행 간격 검사의 모드 미설정 Screen.Lock 진단, 첫 메뉴 전환의 남은 Options 입력 상태, 잘못된 War 약칭 입력, Win32 도구의 시작 안내 처리 누락,1366폭의5,160픽셀 차이와 build3에서도 남은 결과를 모두 보존했다. 행 간격 검사는 실제 독립 ScreenSurface로 준비를 수정했으며1368 기대값은 유지했다. 최종 픽셀 표본의 기대도 약화하지 않았다.

최종 Release build4는 경고/오류0, 신규5개 포함 집중72고유/84관측·실패0이다. 전체C++3,308/실패0·CTest1/실패0(371.98초)을 같은 최종 바이너리에서 통과했다. 기존3,303 등록을 모두 보존했고 검사/원본/CD3,210파일과 AGENTS, 기존 검사 CMake의165,029BYTE 접두부·최종 소스/검사2,873파일도 감사했다. 게임 SHA256은 `1b61d810cd94be10902b937b712054e8b533416e2516608b853a22488eb1148b`이다. 커밋 전 원격 pull은 추가 변경이 없었으며 push하지 않았다.

Windows11 실기, 다른 DPI/음수 좌표 모니터/디스플레이 변경 실기, 전체화면 가장자리 스크롤, 전체 스테이지 완주·픽셀/음향 동일성은 이번 짧은 검사로 완료 처리하지 않는다. 와이드 논리 크기는 명시 설정 입력으로 확인하며 원본 세 해상도 메뉴를 와이드 해상도 메뉴 구현 완료로 합산하지 않는다. `.english` 부재 개선과 사용자 개입 검증은 계속 보류한다.
