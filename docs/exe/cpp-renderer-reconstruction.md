# cpppj 표시 기반 복원 — Renderer·글꼴·커서

> 2026-10-05. [실제 플레이 복원 계획](../cpp-playable-plan.md)의 1단계. 원본 게임 프로세스는 실행하지 않았다. 원본 파일은 읽기만 하며 창 스모크의 허용 설정 변경은 보관·복구한다.

`client/Renderer`는 8비트 버퍼에 장면을 합성한다. 프레임을 한 번 압축 해제해 재사용하고 불투명 색 0·255와 투명을 구분한다. 소스 변환표는 스프라이트 팔레트 번호를 치환하고 그림자는 불투명 영역 아래의 **대상 화면 색**을 치환한다. 실제 소유자/그림자 표 생성·선택은 Squid/타입 런타임 복원 뒤 연결한다.

`Client::Frame`은 Renderer의 변경 영역을 그려 `Screen::Update`에 내보낸다. `Client::draw`를 제거했고 `InspectView`는 시작/카메라 이동 때 장면 목록만 제출한다. `WM_PAINT`는 BeginPaint/EndPaint로 창 영역을 검증한 뒤 전체 다시 그리기를 요청한다. 변화가 없으면 화면 버퍼를 다시 합성하거나 BitBlt로 내보내지 않는다.

## 글꼴 형식의 추가 확정

기존 [chfnt 분석](../formats/chfnt.md)의 미확정 뒤쪽을 두 판본 읽기/쓰기 함수와 실제 캐시로 확정했다.

| 파일 오프셋 | 내용 |
|---|---|
| `0x00` | `BitmapFontData`·`1A 00`, 16바이트 |
| `0x10` | 버전 1, 높이, 어센트, 디센트, 문자 수 256 |
| `0x24` | i32×256 측정 폭(ABC B+C) |
| `0x424` | i32×256 ABC A |
| `0x824` | i32×256 그리기 진행 폭(ABC B+C) |
| `0xC24` | u32×256 글리프 블록 바이트 수 |
| `0x1024` | 256개 독립 VFX `1.10` 블록. 각 블록은 한 프레임 |

메모리에는 256포인터 표가 더 있지만 파일에는 저장하지 않는다. 공백은 좌표 `7FFFFFFF/80000001`의 특수 빈 프레임이며 폭은 그대로 진행한다. 측정은 첫 표, 실제 출력은 세 번째 표를 쓴다. 저장된 ABC A를 다시 x에 더하지 않는다. 원본 캐시의 글자 불투명 픽셀은 색 100이고 글자 출력 표의 항목 100만 요청 색으로 바꾼다.

원본 슬롯은 0=14/700, 1=Courier New 13/0, 2=미사용, 3=20/700, 4=48/0, 5=14/0, 6=12/0이다. 문맥 스타일 번호는 normal/italic/bold/strikeout/underline이다. 글자 크기는 포인트가 아니라 **CreateFontA의 양수 픽셀 높이**다. 캐시가 없거나 손상되면 같은 GDI 글꼴로 메모리 캐시를 만든다. 생성 결과는 기존 원본 파일에 쓰지 않는다. OS 글꼴/래스터화 차이 때문에 생성 결과가 원본에 저장된 캐시와 같다고 주장하지 않는다.

## 커서

패치 `005423a8`·CD `00516c60`의 표는 같다. 번호 1~18은 리소스 113, 110, 111, 108, 107, 109, 115, 116, 131, 117, 130, 129, 132, 133, 134, 136, 141, 148이다. 번호 0은 미설정이다. 원본 실행 파일을 자료로 연 모듈에서 읽으며 게임 프로세스를 실행하지 않는다. 리소스 없는 폴더에는 시스템 화살표를 사용한다.

하드웨어 커서는 LoadCursor/SetCursor/창 클래스와 `WM_SETCURSOR`로 유지한다. 소프트웨어 커서는 원본과 같이 32×32 8비트 DIB의 배경 103 위에 DrawIconEx로 그려 핫스팟과 픽셀을 얻는다. 원본 VFX 캡처 규칙처럼 왼쪽 위 픽셀과 같은 색을 투명하게 만든다. Renderer는 이전/새 커서 영역을 무효화하여 이동 흔적을 지운다. 어떤 게임 상황에서 어떤 번호를 선택하는지는 UserInput/Cursor 로직을 옮길 때 연결한다.

## 검증

- `decomp_renderer_oracle.py`: 두 판본 정렬 비교 261개·변경 표 시퀀스 133개 일치. 원본 기계어와 두 사각형 보조 함수만 허용하며 Win32·CRT 대체가 없다. [기록](../../cpppj/recovery-renderer-evidence.json).
- 단위 검사: 기계어 기대값, 깊이/이동 흔적/출력 없음, 불투명 0/255·클리핑·소스/대상 변환, 소프트웨어 커서 이동/삭제, GDI 글꼴 생성·원본 없는 커서 생성을 확인한다.
- `cpp_renderer_smoke.py`: 원본 캐시 18개·4,608글리프·302,480픽셀을 Python VFX 판독기와 전수 대조한다. 실제 글꼴 창의 모든 786,432픽셀이 일치하며 5프레임 중 그리기/출력 각 1회다. 두 판본의 커서 표·리소스와 실제 소프트웨어 커서 18개 생성/검사 창을 확인한다. 패치판 폴더 전체 1,394파일 및 CD 커서 검사 전후의 목록·해시가 같다.
- 기존 `cpp_window_smoke.py`: 두 판본 타입 격자 픽셀과 미션 검사 화면·영역 전수 비교를 유지한다. 이 화면은 실제 원본 게임 화면과의 비교가 아니다.

```powershell
cmake --build cpppj/build --config Release
ctest --test-dir cpppj/build --build-config Release --output-on-failure
python tools/decomp_renderer_oracle.py
python tools/cpp_renderer_smoke.py
python tools/cpp_window_smoke.py
cpppj/build/bin/Release/NetstormCpp.exe --run originals --view fonts --window
```

수동 `--run`은 원본과 공유하는 옵션을 저장한다. 스모크는 보관·복구하므로 검사용으로는 스모크를 우선 사용한다. 결과는 `extracted/cpp-renderer-smoke/`의 report.json·fonts.png·fonts-expected.png다.

## 후속 연결과 제한

- 원본 `004994b0` 전체 및 `00498220`의 Squid 객체별 분기는 아직 옮기지 않았다. Squid·지형·Gump·효과의 목록 수집과 실제 깊이·방향/상태 프레임·소유자/그림자 변환표 선택이 필요하다.
- 구름·시차·카메라 버퍼 복사·DirectDraw/플리핑은 후속이다. 이 단계는 기존 창 모드 출력만 사용한다.
- 원본 qsort 동률 순서는 미확정이다. 현재 유한 좌표를 검증하고 동률에는 입력 순서를 유지한다.
- 글자 변경은 보수적인 전체 무효화다. Gump의 원본 변경 알림·깊이와 결합할 때 좁힌다. 프레임 캐시의 참조 자산은 Renderer보다 오래 살아야 한다.
- 커서 번호에 따른 실게임 상황 선택·숨김 중첩·GDI 생성 캐시의 원본 OS별 픽셀 동일성은 검증하지 않았다.
- 메인 메뉴·실제 월드·플레이는 완료하지 않았다. 다음은 [현재 계획 2단계](../cpp-playable-plan.md#2단계--바로-다음-작업)의 메뉴·미션 진입이다.
