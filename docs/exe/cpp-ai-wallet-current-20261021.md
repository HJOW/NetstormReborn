# 실제 Player·AI 본체를 공유하는 지갑 가산 연결

후속: [일반 AI 생성·삭제 사건 연결](cpp-ai-object-notices-20261021.md)을 진행했다. 아래 남은 경계와 정적 보고서는 이 지갑 단위를 마친 당시의 범위이며, 초기 전체 월드 등록/전략은 후속 단위에서도 별도 미완료다.

2026-10-21, 시작 HEAD `2f1d7880`. 현재/마지막 전체 정밀 디컴파일 PC는 **VM-W11-CODEX / 2026-10-21**로 같다. 직전 검토/문서화 턴은 새 원본 자료를 확인하고 문서·인수인계를 커밋한 진행 턴이다. 이후 자동 goal 계속 요청으로 원본 경제 연결을 복원했다. 사용자가 요청한 **테스트용 AI/SP 옵션은 구현하거나 활성화하지 않았으며 게임·집중 검사·희생 검증도 재개하지 않았다.**

## 문제와 변경

기존 `RawAiCreate`는 실제 Player+b0에 `RawAiBrainMemory`의 본체 토큰을 부착한다. 그러나 `SquidReward`의 지갑 가산은 별도 `SquidPostPopState::aiAttached`와 `SquidRewardState::aiWallet` 배열을 사용했다. 따라서 실제 AI를 생성해도 비용/보상의 가산이 그 본체+0x2d8에 도달하지 않았다. 두 자료를 프레임마다 복사하는 대신 원본처럼 현재 Player의 포인터를 읽도록 바꿨다.

[`RawAiWallet`](../../cpppj/src/o/RawAiWallet.cpp)은 원본 **00413bb0**의 순서다.

1. 현재00594fc8이 비영이거나 signed owner가1 미만이면 반환한다.
2. 같은 Player9에서 해당 owner의+b0를 읽고0이면 반환한다. flags20이나 별도 부착 bool로 대신하지 않는다.
3. 그 토큰의 실제 본체+0x2d8에 정수 금액을 DWORD 감김으로 더한다.
4. 그다음00463b50에 해당하는 현재 미션 포인터/+0x68의 데모 여부를 조회한다.
5. 데모이면 **처음 저장한 같은 본체 포인터**의 현재 지갑을 다시 읽고 signed 하한1190을 적용한다. 미션 조회가 Player의 포인터를 바꾸더라도 새 포인터로 갈아타지 않는다.

`RawCampaignSession::ConnectAi`는 같은 `aiMemory`/Player9를 사용한다. 비활성 모드는 `core.ownerMode.challenge`의 현재00594fc8, 데모는 기존 UI가 제공하는 같은 `missionOutcome.demo`를 읽는다. `missionPost`나 에디터 모드로 데모 여부를 추정하지 않는다.

`SquidReward::BindPatchWallet`은 PATCH만 허용하며 이후 `AddSp`/`CreditWallet`/환불의 모든 지갑 가산을 위 몸체에 보낸다. 기존 독립 값형 대조와 CD/10.37용 배열 경로는 바인딩하지 않으면 그대로 유지한다. 실제 Session은 그 배열의 초기값·부착값·클램프값을 읽거나 동기화하지 않는다.

기존 SP 부모는 **SP 저장→정수 지갑 가산→화면 갱신** 순서를 유지한다. 금액의 float/정수 변환이나 SP 난수 소비를 이번 변경으로 바꾸지 않았다. 너겟 내용물 수명의 별도 선가산과 이어지는 `AddSp`도 기존 원본 호출 순서를 유지하며 임의로 중복이라고 합치지 않는다.

## 원본 근거와 확인 범위

기존 정밀 `Netstorm.c`/`functions.tsv`와 보호된10.78 PE의 실제 명령을 정적으로 대조했다.00413bb0의 현재 Player+b0, 저장 ESI, 가산 뒤00463b50, 재조회와 signed `cmp 0x4a6`/`jg`,00463b50의 현재 포인터/+68,0040eec0/0041df80의 SP 저장→지갑→표시 호출을 확인했다. 새 디컴파일이나 native/OS 실행은 없다.

원본의 포인터 산술이 유효 저장소 밖을 가리키는 입력은 실제 Player9/0xb08 계약으로 호스트 예외 처리한다. 해제 토큰·본체 크기 부족·현재 조회 누락도 성공으로 바꾸지 않는다. 이 안전 계약은 원본의 잘못된 주소 접근/OS 예외 재현을 주장하는 것이 아니다.

새 검사6개는 **작성·컴파일만** 한다. 현재 상태를 다음 기준으로 확인하도록 작성했다.

- 비활성·signed 비양수·NULL brain에서 후속 조회 생략, 표 밖/해제/폭 부족 거부.
- 독립 기대값8행의 감김·데모 하한과 전체 나머지 바이트 보존.
- 데모 경계에서 Player/지갑이 변해도 저장 토큰 유지와 현재 값 재조회.
- `AddSp`가 같은 실제 SP/brain을 갱신하고 값형 사본을 사용하지 않는 연결, 직접 `CreditWallet`의 SP/난수/표시 무변경, CD 값형 경로 보존.
- 실제 Session의 원본 서버 환불이 같은 본체를 갱신하고00594fc8/AI 제거 뒤에는 지갑 조회를 생략하는 경로.

첫 Release 빌드의 `kPlayerCount`가 기존 공용 상수와 충돌한 오류를 `kPlayerSlots`로 고쳤다. 최초 실패 로그/종료1 결과는 `extracted/cpp-ai-wallet-20261021-build1*`에 보존했다. 수정 후 `build2.log`와 별도 종료 코드 JSON은 **Release 종료0·경고0·오류0**이다. 같은 빌드 세션의 실제 종료를 확인했으며 관측 타임아웃을 이유로 재시작하지 않았다.

`tools/cpp_ai_wallet_audit.py`와 `cpppj/ai-wallet-static-20261021.json`은 원본 네 함수의 정적 명령·작업 트리 입력·바이너리 SHA와 새6검사 등록을 확인한다. **C++검사/CTest/게임/native 명령 실행0**이며 컴파일 등록을 통과 수로 세지 않는다. 기존 원본 보상 fixture와 과거 실행 보고서는 덮어쓰지 않는다.

## 남은 경계

이번 변경은 **기존 가산이 같은 실제 지갑으로 전달되도록 한 원본 복원**이다. 시작 SP와 지갑을 임의로 같은 값으로 만들거나 추가 자금을 지급하지 않는다. 원본00416eb0의 전략 준비/로컬 SP 조정,00417de0/00417d30의 전체 전략 프레임, 다리/유닛 배치와 생성·삭제 목록 통지는 후속이다.

`SquidPostPopState::aiAttached`를 켜지 않았고 해당 통지의 미복원 거부를 지우지 않았다. 이것만으로 전략 AI/자동 클리어/데모 자연 완주가 가능해진 것은 아니다. 실제 GUI의 포획·희생과 전체11미션 플레이/표시·음향·동작 동일성도 미완료다.
