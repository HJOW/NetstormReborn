# 대상 색 변환 복원과 간헐천 그림자 — 단위678

현재/마지막 전체 정밀 디컴파일 호스트는 **HJOW-Athlon / 2026-10-23**이다. 새 디컴파일은 하지 않았다. 사용자 제보의 그림자 농도와 다리 정렬 순서를 따로 대조했다.

## 원문과 실제 결함

10.78의 `00498220`은 그림자 프레임에 `004dab90`을 호출하고 색표 `00557738`을 전달한다. 이 래퍼는 실제 `0040351d`로 간다. 커널의 압축 해제 임시 표면은255로 채워지고, 소스가255가 아닐 때 **현재 대상 픽셀을 색표로 변환**한다. 기계어와 전체 디컴파일의 `pcVar23`(소스 마스크)·`pbVar25`(대상)을 구별해 확인했다.

현재 `SpritePixelTarget`은 이 경로를 소스 색 치환으로 처리했다. 간헐천 그림자 이미지의 어두운 색이 아래 다리·배경을 덮는 원인이었다. 2026-10-12 Sprite Draw 문서의 ‘translated이므로 소스 치환’이라는 해석과 그에 맞춘 픽셀 기대도 잘못이었다. 과거 문서에 정정 근거를 연결했다. 당시 전체 Draw의 프레임/인자 명령열 관측과 이 잘못된 픽셀 기대는 별개다.

`DrawTranslatedVfxImage`를 추가하고 Shadow·Dead·Abstract의 같은 원문 경로에 연결했다. 소유자 색 치환과 일반 배율 출력은 기존 경로를 유지한다. 대상 변환은 단위 배율에서도 꼭짓점 순회를 거치고, y 꼭짓점이 같으면 출력하지 않는다. 소스255는 마스크 투명이고, 색표 결과255는 대상에 그대로 저장한다. 현재 화면의 원문 색표(그림자0.6 계수)는 바꾸지 않았다. Windows 호환성 변경이 아닌 원문 동작 복원이다.

## 그리기 순서

원문 `00433660`은 그림자의 y에서 float0.1을 빼고 같은 signed 깊이를 제출한다. 기존 `ObjectCollection`이 이를 보존한다. 정렬은 `004e6010` 계열의 깊이→y→x 비교와 기존 실제 CRT 순서를 따른다. 이번에는 정렬·다리 깊이·농도 상수를 변경하지 않았다. 수집7개·정렬6개의 기존 원문 검사도 통과했다. ‘모든 다리를 그림자 뒤로 다시 그리기’ 같은 별도 정책은 넣지 않았다.
