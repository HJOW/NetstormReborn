# 서버의 건설 확정과 배치 통지

2026-10-10, **HJOW-Athlon**. [건설 배치 실행](cpp-construction-place-reconstruction.md)에 이어 같은 세션에서 진행했다. 현재 PC와 마지막 디컴파일 PC가 같다. 새 `constructionconfirm` 목록 **11/11/11개**를 읽기 전용 Ghidra로 내보냈다. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-10.** 원본 게임·복사본·analyzeManager·클론 창을 실행하지 않았다.

배치 가능 판정을 통과한 건설 요청을 서버가 확정하는 함수다. 조각마다 서버 SID를 확보하고, 그 목록을 담은 배치 통지(메시지 `0x3f`)를 보낸 뒤 같은 통지를 자기 쪽 처리기에 직접 넘긴다. 통지를 받은 쪽이 [배치 실행](cpp-construction-place-reconstruction.md)으로 조각을 놓는다. **요청 함수·통지 처리기·건설 UI는 아직 없으므로 게임에서 건물을 지을 수 있게 된 것은 아니다.**

## 순서

인자는 타입, x, y, 플레이어, decoder 인자, 방향, 플래그, 시각(double을 이루는 두 DWORD), 품질이다.

1. 타입 flags1에 **`0x8000`(사제가 지어야 함)**이 있고, 플래그 bit 0이 꺼져 있고, 생략 전역이 0이면 `(플레이어, 타입, x, y)`로 지을 사제를 찾는다. **결과가 0이면 아무 효과 없이 0을 돌려준다.**
2. 스택에 0x200바이트를 확보해 메시지를 만든다.
3. `(타입, 인자, 방향, x, y, 0)`으로 decoder를 만들고 유효 칸마다 `(타입, 0)`으로 SID를 만들어 그 번호를 메시지 항목에 차례로 적는다. 20번째를 적으면 assert(`sidCount < MAX_SIDS`)다. 패턴은 최대 15칸이라 정상 입력에서는 닿지 않는다.
4. 메시지 필드를 쓴다: `+4` 타입(바이트), `+5` x, `+9` y(비트 그대로), `+0xd` 인자·`+0xe` 방향·`+0xf` 플레이어·`+0x10` 플래그·`+0x11` 품질(각각 하위 바이트), `+0x12` 시각 8바이트, `+0x1a` SID 개수.
5. 전송 → 처리기 직접 호출 `(9, 0, 메시지)` → 기록기가 켜져 있고 활성이면 첫 SID를 기록 → 1을 돌려준다.

조각이 하나도 없어도(decoder에 유효 칸이 없음) 개수 0인 통지를 보내고 1을 돌려준다. 이때 기록기에 넘기는 "첫 SID"는 원본에서 초기화되지 않은 지역 값이다. C++는 0을 넘기며 이 값을 원본과 같다고 주장하지 않는다.

두 판본의 순서와 필드 위치는 같다. CD판은 좌표 지역 배열 20칸의 빈 생성자(`0041f9d0`)를 더 부를 뿐이다. 조각마다 새 객체의 좌표를 지역 배열에 복사하는 코드가 두 판본에 있지만 그 배열은 이 함수 안에서 다시 읽히지 않는다.

## 독립 원본 관찰과 C++ 연결

[`decomp_constructionconfirm_oracle.py`](../../tools/decomp_constructionconfirm_oracle.py)는 세 PE를 두 x87 제어 워드로 실행했다. 새 독립 저장 입력 **1,300개**: 10.78 **508개**, CD와 10.37 각 **396개**. 정상 반환 **2,600회**, 두 정밀도의 관찰이 모두 같았다. 만든 SID는 10.78 1,370개, CD·10.37 각 862개다. 저장 입력 누적은 앞 단계 459,437개에 더해 **460,737개**다.

입력은 타입 비트 × 호출 플래그 × 생략 전역 × 사제 조회 결과, 바이트로 잘리는 인자(플레이어·decoder 인자·품질의 상위 비트)와 좌표/시각 비트, 조각 수(없음·한 칸·island·noIsland 9칸·다리 패턴 26개 × 방향), 기록기 켜짐 × 활성을 교차한다. 사건 순서와 통지 필드 전체, 반환값을 저장한다. 확정 몸체와 decoder·스택 확보·항목 주소 계산은 원본 명령이고 위 표의 경계만 인자를 기록하고 반환한다. 스택·보존 레지스터·x87·허용 실행 범위·쓰기(스택 밖 쓰기 없음)·입력 순서·진입/반환 수·경계 사건 수·SHA를 감사한다. 원본 assert와 게임/OS 호출은 0이다. 조각이 없으면서 기록기가 켜진 조합은 위 이유로 입력에서 뺐다.

[`ConstructionConfirmTests.cpp`](../../cpppj/tests/ConstructionConfirmTests.cpp)의 새 검사 **5개**: 세 PE 관찰 전체 재생, 실제 factory가 만든 서버 SID 아홉 개가 통지에 담기고 처리기 자리에 둔 배치 실행이 그 SID에 noIsland를 놓는 통합 검사(사제를 못 찾으면 SID를 만들지 않음 포함), 누락 경계·다른 풀·범위 밖 타입·잘못된 생성 결과 거부와 기록기 인자. 통합 검사의 처리기는 abstract 0으로 배치 실행만 부르며 **실제 처리기 `004441b0`의 abstract 판정·예측 정리·사제 이동은 복원 전**이다. [fixture](../../cpppj/tests/fixtures/constructionconfirm-x86.tsv)와 [근거 JSON](../../cpppj/recovery-constructionconfirm-evidence.json)은 UTF-8/LF다.

Release 경고/오류 **0**, CTest 내부 **566개·실패 0**(144.12초), 원본 근거 감사 **88종 모두 통과**. 새 변이 7개 **모두 검출**(기대 검사만 돌리는 `--focused` 실행. 변이 전 사본은 전체 검사 통과). 원본 보호 파일·AGENTS.md·dotnetpj는 바꾸지 않았다. 로그는 Git 제외 `extracted/constructionconfirm-*.log`에 있다.
