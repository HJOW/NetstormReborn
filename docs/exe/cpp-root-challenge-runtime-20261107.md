# 1069 — 실제 CCh 로그인과 참가자 종료

`root::ChallengeRuntime`이0044e940/0044e0d0의 전체 부모와 현재 참가자·전투/명단·메시지 작성기를 같은 ChallengeStore/TransceiverTransport/옵션에 연결한다. 제품 기준은1069 / 11.01, 게임 EXE 12,365,824바이트, SHA-256 `9e6c176fdd69f9b227622aaebcbeef5db5fd0843fde0c53c980637c57c9496e7`다. 직전 CP는 `26b21de6 / 20261107-106 CP`다. **상위 공유 표/파일·주소/Root 라우터와 새 R.exe의 실제 호출은 아직 없다.** CCh 본체 작성을 서버 접속/플레이 검증으로 계산하지 않는다. 실제 장치가 선택됐는데 미연결이면 명시 오류다.

## 로그인 본체

요청 이름은0044bb00처럼 ASCII 금지 구간을X로 치환한다. 현재 CCh flags2면1Ch의 내부 소켓 토큰을 한 번 소비하고 실제 sender0/4096/flags444→별도peer/IPv4flags54 노드를 구성한다. counter/이름/현재 subscriber 중복→자동 blacklist 삽입·저장/현재 subscriber·주소 표→낮은 버전 관문→첫 빈1..39 슬롯 순서다. 실패 코드는0(표/버전),3(중복),4(이름),5(가득 참),6(counter)이며 원문처럼1dh 응답/flush/close 공통 꼬리로 간다.

선택한 슬롯은 현재 노드 공개→복합 sender `(zone&ff)<<8|participant`→실제 buffered 모드→0044c7b0/후속 데이터 순서다. 참가자 id/subscriber/이름 제거 문자 집합·CRT clock/+70·74/6BYTE·10BYTE Core/flags mask·좌표/소속0과 실제 버전·언어·주소·레벨을 지정 폭으로 쓴다. 현재marked 표는+74에 반영한다. 원본 `_clock` 경계는 호스트 CRT로 연결했다.

기계어에서 누락 인자를 확인한 결과 **성공 응답의 상태는1, DWORD는 요청 subscriber**다. Root17h 가입 통지→1dh10.71/성공1→26h 현재 MOD/좌표·반경→낮은 버전 안내→유효 전투 생성23h/설명71h→기존 참가자20h/주소7bh→새 참가자 전체 통지/주소→로그→뉴스41h/객체8BYTE→길드 이름88h 순서를 구현했다. 내부 wire10.71과 제품 표시11.01을 구분한다. 낮은 버전의 기본 안내는 폐기된 HQ URL 대신 현재 로컬11.01 빌드를 안내한다. 별도 외부 등록/클라이언트 검증 소비자를 추가하지 않는다.

## 현재 바이트와 패킷

004cf220에서 다음 알려진 전역004d05a8까지5000BYTE의 PE 로더 초기 값은 전부0이었다. 이를 호스트 공유 scratch 물리 한계로 잡고, Root 재초기화/각 패킷마다 지우지 않는다. 디버그 심벌로 원문 배열 선언 크기를 증명한 것은 아니다. capacity0 allocator처럼 header만 쓴다. 특히23h는 기존 본문+5에 bit2를 OR하므로 현재 바이트를 보존한다. 동적 allocator 패킷은 원문처럼ff로 채운다. 별칭으로 추정했던88h는 실제 **guild.txt 길드 이름**이었다. 0045cda0/0045da40은 각각guild.txt/guildreq.txt이므로1066 설명/주석도 정정했다.

20h 전체 참가자,22h 변경,23h 전투,71h 설명,1dh 응답,17h Root 통지,7bh 주소,41h version3 메시지/객체·수신 subscriber,88h 길드 이름과 실제 관찰기를 작성했다.41h의 bufferLen 진단은004461a1의 MOVZX WORD/CMP -1상 항상 거짓인 원문을 보존한다. 문자열은 실제 첫NUL로 제한한다. 고정88h의 미작성 tail/뉴스 객체 padding은 현재 CRT 할당 입력을 사용하며 원본 스택 바이트 자체 일치를 주장하지 않는다.

원문00451df0는 순회자의 subscriber 대신 **0번 참가자의 subscriber**로 길드를 조회하고 새로 배정한 참가자 번호 대신 원래 source에 보낸다. 이 특이동작을 그대로 구현했다. 주소 대체 옵션도 기존 참가자마다 원문 parse 호출/현재 주소 비교 뒤 적용한다. 실제 주소/표 로더는 caller 장치로 남는다.
