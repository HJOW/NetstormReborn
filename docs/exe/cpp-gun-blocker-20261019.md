# 스톤 타워 배치의 기존 Gun 통지와 Early5 자연 피격

2026-10-19 단위208. 기준 `e963f23f`, 현재·마지막 정밀 디컴파일 PC **VM-W11-Codex / 2026-10-19**다. AGENTS/양 LEFT를 다시 읽었다. 직전 턴은 피격 사건 생산자 커밋과 실제 실패 지점 확인으로 진척했다. 원본 게임·OS 실행이나 새 디컴파일은 없다. 이전 REA의 H: 경로 속성 조회 실패는 반복하지 않았으며 같은 PC 정밀 본문과 보호 PE를 재사용했다.

## 실제 원본 동작

기존 `startBlocker` 훅의 실제 `0046ae80`은 새 프로세스를 만들지 않는다. boss `00540bc4`가 참일 때 20DWORD 목록을 확보하고, 현재 타워의 소유자·원점으로 `00469590`을 실행한다. 목록의 각 기존 Gun을 Form/Kernel에서 다시 찾아 `0046a960`으로 표적을 타워로 바꾼다. 이 마지막 몸체는 기존 `RawGunProcess::SetTarget`을 재사용한다.

`00469590`은 스톤 타워의 실제 발자국으로 사각형을 만든다. 먼저 최대 발사기 사거리 안의 일반 finder를 순회해 group0·비추상·비동맹 조건을 검사한다. 새 사각형 중심의 제곱거리와 기존 표적의 경계점 점수를 비교하고, 실제 SHP/TYPE 포구에서 기존 표적으로 가는 사선이 타워와 교차할 때 목록에 넣는다. 지상 표적에는 기존 점수에 1000이 더해진다.

다음에는 새 사각형에서 0/2/4/6 방향으로 최대 캐논 사거리까지 뻗는 영역을 각각 순회한다. group1·비추상·비동맹·반대쪽을 향한 현재 공격 모드를 확인하고, 새 타워가 기존 표적보다 엄격히 가까운 총만 넣는다. 목록 용량을 넘기지 않으며 원본 finder 순서와 중복을 유지한다. 후보 raw의 free/dead 비트를 임의로 추가 배제하지 않는다. 최대 사거리는 TYPE 초기화가 원본처럼 전체 번호를 순회해 group1에10, group0에3 여유를 더해 계산한다.

`RawGunBlocker`는 기존 해시/일반 finder/발자국 중심/교차점 몸체를 공유한다. Session은 같은 `RawContainedLookup`, `SquidProcessHost::FromForm`, `RawGunMode`, `RawFenceTarget::Muzzle`, 기존 Gun 처리기를 연결한다. 별도 성공값이나 튜토리얼 단계를 쓰지 않는다. 현재 구현 범위는10.78이며 CD10.72에 같은 알고리즘을 합성하지 않는다.

## 독립 원본 검증과 수정 이력

새 `decomp_gun_blocker.py`는 실제 보호 PE의 수집·목록 쓰기·네 finder·점수·포구·교차·통지 래퍼를 실행한다. 기존 Form/Kernel 조회·현재 공격 모드·할당/해제·SetTarget은 명시 외부 경계다. **690고유 입력/두 x87 정밀도/1380정상 반환/차이0**를 새 `gun-blocker-x86.tsv`에 고정했다. 실제 Session 완주나 원본 게임 실행의 증거로 합산하지 않는다.

첫 표본 v1은 발사기가 선택되는 양성 경우가 없어 사선 위 발사기 표본을 보강했다. v2와 첫 C++ 비교에서는 원본 포구가 NaN인 것을 발견했다. 새 관측기에 실제 픽셀 배율16/11이 누락되어0으로 남은 문제였다. 두 미완성 표본의 도구/전체 결과/해시를 `coverage-v1.*`, `scale-v2.*`로 보존한 뒤 입력 전역만 바로잡아 v3를 생성했다. 현재 기대값은 v3이며 C++ 결과를 기대값으로 사용하지 않았다. 중간 `native-smoke1~4`의 미공급 getter/비Gun 후보 입력 경계 오류도 그대로 보존한다.

최종 원본 비교는 높이 한 칸인 사각형의 접촉을 C++가 잘못 제외한 차이를 잡았다. 사각형 경계를 포함하도록 고치되 기존 `RawFenceTarget::Intersection`의 별도 끝점 규칙은 유지했다. 추가 정밀 검토에서는 발사기 최대 반경과 정확히 같은 거리도 원본은 포함하는 것을 확인했다. 기존690행을 그대로 두고 별도 `decomp_gun_blocker_boundary.py`로 반경 바로 아래/동일/바로 위의 수집·통지 **6행/12정상 반환**을 고정해 이 조건도 포함했다. 원본 기대값은 바꾸지 않았고 최종 집중 **2검사**는 696개 목록·통지 모두 일치한다. 경계 검사 추가 빌드의 문자열 인자 형식 오류는 기존 `LoadFixture(const char*)`에 맞춰 고쳤고 실패 로그를 보존했다. 기존422개 fixture·기존 검사 본문은 수정하지 않고 새 원본 fixture 두 개와 실제 UI 입력 fixture를 추가했다.
