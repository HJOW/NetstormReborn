# 다이스의 별도 TYPE 추가 그림·파편 캡처 — 단위242

작업일은 **2026-10-20**, 시작 커밋은 `249c3a3d`다. 현재/마지막 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-20**이다. 기존 정밀 산출물·보호 PE를 읽었고 새 디컴파일·원본/CD 변경은 없다.

## 원본 근거

10.78 다이스165의 가상 표 `00507950`에서 `+78=004acfe0`은 TYPE의 baseFrame, `+a0=0041c0f0`은 빈 캡처 기본 그림, `+a4=004484b0`은 별도 그림이다. `004484b0`은 현재 프레임 DWORD를 **별도 TYPE169(`daisExtraFrames`)의 전체 프레임 수**로 signed 나눗셈하고 나머지 프레임을 `00497280`에 제출한다. 현재 TYPE165의 프레임 수나 현재 그림만 출력하는 방법으로 대체하지 않는다.

`tools/decomp_dais_draw.py`는 제품 C++를 작성하기 전에 원본 `004484b0`·`0049a840` 기계어만 격리 실행했다. 프레임/프레임 수/상태/좌표/그림 토큰 **768입력**, 두 독립 정밀도 **1,536정상 반환·59,904명령**에서 전체 요청이 일치했다. 실제 원본 함수 내부에는 dead/추상/owner 필터가 없다. `00497280`의 this·네 인자를 효과 경계로 기록하며 일반 RLE·추상/로컬 관문·전체 픽셀까지 원본과 대조한 것은 아니다. 게임/OS/창은 실행하지 않았다.

원문은 `dais-draw-x86.tsv`와 `dais-draw-native.json`에 최초 동결했다. 재실행으로 기존 기대값을 덮어쓰지 않는다. CD10.72 대응 `00482e70`은 현재 프레임을 **BYTE(+22)**로 읽고 별도 TYPE 전역 `0051cbe8`과 같은 나머지 계산을 사용한다. 이번 제품은 10.78만 구현한다.

## 제품 연결

`RawDaisDraw`는 확인한165/507950 쌍과 TYPE169 번호를 사용해 원본 요청을 계산한다. 자체 상태 필터를 새로 만들지 않는다. `RawCampaignFactoryDisplay`의 실제 수집/일반 SpriteDraw 경로에 다이스를 등록하고, 별도169TYPE의 프레임을 원래 기준점에 제출한다. 일반 `00497280`의 현재 추상/로컬 소유자 관문은 기존 표시 규칙과 같은 위치에서 처리한다. GameWorld의 기존 표시/선택 영역 분배도 이 실제 처리기를 사용한다.

Session의 파괴 파편 캡처는 다이스를 지원하는 기존 `RawShapeToBuffer`로 연결했다. 추가 그림 상태에서 기본 캡처는 원본의 빈+a0대로 `-1`, 추가 캡처는 TYPE169의 평문 RLE다. 기존 버퍼 크기·핫스폿·원본 난수·파편 수명은 유지한다. 추상 다이스의 캡처 색상은 명시 미연결로 남긴다.

## 빌드·검증 범위

원본768행 C++ 대조, 미연결 문맥 거부, 실제 Session의 다이스 추가 표시/파괴 캡처 연결을 위한 **새 검사3개**를 작성했다. 마지막 검사는 의식의 frame47/extra2를 명시 표시 입력으로 사용하며 자연 의식 진행·원본 전체 픽셀 관측의 증거가 아니다. 첫 빌드의 검사 초안은 존재하지 않는 `RenderProcessSystem::Fields`를 참조해 컴파일 오류가 났고, 기존 `Slots`→`Lookup` 경로로 수정했다. 실제 깊이 필드35와 추가 그림 입력도 명시했다. 오류/최종 빌드 원문은 `extracted/cpp-dais-draw-20261020-build*.log`에 보존한다.
