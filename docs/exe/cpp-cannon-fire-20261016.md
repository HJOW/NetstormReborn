# 썬·썬더 캐논 실제 공통 발사와 세션 연결

2026-10-16 단위90, 현재/마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-16**이다. AGENTS.md와 양 LEFT를 다시 읽고 `3451096`의 깨끗한 트리에서 시작했다. 직전 단위89는 크로스보우 원본2638입력 대조·세션 연결과 데모3의3→5프레임 진행을 남긴 작업이다. 목표는 실제 사용자 플레이/자연 완주와 원본 동일성이며 미달성이다. 사용자가 이번 단위 완료·문서화·커밋 후 중지를 요청했으므로 이 상태를 남기고 목표를 일시정지한다.

## TYPE131 명칭 정정

직전 기록은 TYPE131을 아이스 캐논으로 잘못 표시했다. 실제 로딩 순서 `TypeLoadOrder.cpp`·공유 대응표·보호 PE의0054125c=129/00541264=131을 대조했다. **TYPE129 `rainCannon`=Ice Cannon/아이스 캐논, TYPE131 `thunderCannon`=Thunder Cannon/썬더 캐논**이다. 실제 보호 자원을 읽는 CampaignFire 검사도 thunderCannon 블록+70=131, group1/theme2를 확인한다.

직전 작업 문서·현재 README·인수인계와 `crossbow-animation.json`의 표시 이름을 정정했다. 보고서에는 이전 이름과 정정 근거를 별도 남긴다. 당시 TYPE131·프레임5·시각0.125 및 원본 관찰·fixture·통과 수는 바뀌지 않았다. 공유 명칭 표와 소스명 대응표는 이미 정확해 변경하지 않았다.

## 실제 공통 몸체와 연결

`RawCannonFire.*`는 원본 **00467330**의64BYTE 공통 Fire를 복원한다. 썬 캐논은00468460/0050b318 및004684b0의24프레임 앞뒤 변환, 썬더 캐논은004684d0/0050b370 및00468520의 현재 문자별 프레임 구간을 사용한다. 현재 물리 프레임에서 읽는 TYPE+124의 문자 코드와 TYPE+130/+170의 첫 프레임/개수는 기존 실제 프레임 자료를 그대로 공급한다.

표적 위치/중심은 due 검사 전에 추적한다. 가상 단계 효과 뒤 현재 부모를 다시 조회해 Unpop→프레임 쓰기→Repop(0x40)을 수행한다. **처음 추적한 표적이 살아 있었는데 launch가 실패하면 완료와 시각 갱신을 보류**한다. 이후 현재 표적이 바뀌거나 죽는 경우와 이 최초 생존 snapshot을 구별한다. 완료는 같은 GunProcess에 event1/info6/value7을 보내고 flags0x10으로 실제 CannonFire를 해제한다.

썬더 단계표는 현재 문자 구간의 마지막 프레임에서 발사하고 구간 끝을 넘으면 첫 프레임으로 돌아가며 완료한다. 마지막 프레임에서5칸/1칸 앞의 `thunderCannonGrowl.wav`/`thunderCannonRoar.wav`를 순서대로 호출한다. 같은 단계에 두 전역 차이가 겹치면 두 소리 모두 호출하며 첫 소리 효과가 부모/두 번째 차이/시각을 바꾸는 경우도 원문과 같다. 일반 지연은 float0.5이며 TYPE131의 발사 단계에서는 실제00501550=0.25를 곱해0.125가 된다. 썬 발사의 지연은 float0.07이다.

일반 launch00466f50은 살아 있는 HP 표적에서 코너를 구한 뒤 현재 부모/표적/속도/표시/효과를 다시 읽는다. 썬은 표시80/효과11, 썬더는 **표시132 `thunderCannonMissile`/효과0**, 둘 다 속도20/반사0이다. 원본004af170의 실제 초기화 접미부004af182~004af196이 쓰는 무효 좌표-10000을 생성 인수에 사용한다. 준비 접미부2회는 아래 고유 입력/반환 수에 더하지 않는다.

같은 `RawCampaignArcherBindings`에 실제 프레임 표와 두 파생 상태를 연결했다. TYPE128의 stage5는 새 공통 Fire를 사용하고 회전/원위치는 기존 몸체를 유지한다. TYPE131 stage5도 새 공통 Fire를 쓰며 group1 stage2는 같은 실제 회전 함수를 사용한다. 동일 Pool/World/Host/Missile과 PrepareFrame 시계, 별도 실제 클래스의 notify/kill을 사용한다. 나머지 미복원 TYPE/단계는 명시 오류를 유지한다.

## 원문 대조와 첫 실패

보호10.78의 **고유5534입력, x87 두 정밀도(027f/037f)의11068정상 반환·차이0**이다. 썬847/썬더4687이며 공통 프레임2956·생성자2·가상 단계2560·launch16이다. 프레임에는 외부 재진입140입력이 포함된다. 연속/단일/교차/불균등 문자 구간, 별도 단계 인수, due/free/dead/HP, 중첩 소리, 중심/공간/코너/Missile/음향 효과 뒤의 현재 필드/전역을 확인한다. 전체64BYTE 객체·네 슬롯200BYTE·반환·효과 인수/순서·스택·비휘발·x87/SEH·쓰기 guard를 대조한다.

공간·중심·HP·Host·난수/format·Missile ctor는 명시 외부 입력이다. 공통 Frame·파생 단계/생성자·launch·타입 코드/가상 getter는 원문을 실행한다. 따라서 이 수치는 전체 투사체나 실제 미션 완주 관찰 수가 아니다. 새 게임/GUI 창 실행·디컴파일은0이며 CD10.72의 새 공통 발사는 이번에 대조하지 않았다.

첫 원문 실행 뒤 보고서 작성은 `Path` import 누락으로 실패했고 이를 보완했다. 음향 재진입으로 부모가 바뀌는 경우의 공간 관찰도 고정 SID50 대신 실제 ECX의 부모 SID를 기록하도록 수정했다. 초기 fixture는 로컬 `...-first.tsv`로 보존했다. 첫 C++ 대조는 디컴파일 출력의 임시변수를 현재 프레임으로 오해해 Sun/Thunder 프레임 검사에서 실패했다. 기계어의0046736a/00467397과00467411~00467417이 **스택에 보존한 최초 표적 dead 플래그**를 읽음을 확인해 구현만 고쳤다. 최종 원본 fixture와 기대값은 이 C++ 수정 때 바뀌지 않았다.

## 최종 검사와 정지 시점
