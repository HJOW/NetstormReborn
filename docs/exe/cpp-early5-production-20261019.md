# Early5 추가 워크샾의 본체 클릭과 자연 C안내

2026-10-19 단위210. 기준은 `0a5995fc`다. AGENTS와 양 LEFT를 다시 읽었고 현재/마지막 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-19**로 같다. 단위209에서 최신 cpppj 목표와 “멀티플레이/Outpust는 2차보다 후순위” 오타 수정까지 반영한 뒤 진행했다. 보호 원본이나 AGENTS, dotnetpj는 수정하지 않는다.

## 실제 실패와 수정

실제 Early5의 MORE/OK→스톤 타워 지식/생산/배치→썬더 피격으로 B에 진입한 뒤 사제의 Construct→Workshop→Sun Workshop 건설을 수행했다. 새 워크샾은130,90에 생성되고 HP0에서3000까지 자연 건설됐다. SP는4000→3600→2800이다. 기존 워크샾에는 스톤 타워와 썬 디스크 발사기 두 지식이 등록됐다.

새 워크샾을 본체 중심 `cell:127,86`으로 우클릭해도 메뉴가 열리지 않았다. 실제 raw 프레임1의 SHP 영역은 `(-25,-65,-13,-48)`인 작은 추가 애니메이션 조각이다. 기존 `GameWorld::Bounds`가 이 조각의 범위만 사용한 것이 원인이었다. 보호 SHP의 본체 프레임0 영역은 `(-111,-114,0,0)`으로 훨씬 넓다. 작업 전 ui4에서 건물HP3000/현재프레임1인데 실제 생산 메뉴가 열리지 않는 실패를 보존했다.

같은 PC 정밀 본문 `454cd0`은 가상+80의 Level로 TYPE+A..H 첫 프레임을 읽는다. `454cf0`은 현재 프레임이 본체 프레임과 다르면 추가 그림을 그린다. 이미 원본 픽셀 fixture로 검증된 `RawFactoryDraw::MainFrame`을 재사용해 두 실제 Factory/아웃포스트 가상 표의 클릭 영역을 **본체 프레임과 같은 SquidDisplay SHP 헤더/카메라/배율**로 계산했다. 게임 단계·HP·SP·지식 목록을 직접 변경하지 않는다. 이 수정은 전체 원본 픽셀 선택 알고리즘 복원의 완료를 뜻하지 않는다. 일반 객체의 간이 클릭 영역과 모바일 여유 등은 기존 경계로 남는다. CD10.72에 이10.78 연결을 추정 적용하지 않는다.

## 검증과 보존한 실패

- ui1은 B 이후 워크샾 건설을 관측했다. `completedWorkshop`이라는 첫 보고 이름은 고정 frame1000의 이름일 뿐, 당시HP1567로 아직 건설 중이었다. 새 검증기는 `workshopReady`에서 실제HP3000을 별개로 확인한다.
- ui2는 불필요한 ESC가 게임 메뉴를 열어 후속 생산 입력이 실패했다. ui3은 건물 기준점의 빈 영역을 눌렀다. ui4는 실제 본체 중심을 눌렀으나 작은 추가 프레임 영역만 사용해 실패했다. 종료코드와 로그를 모두 보존했고 각 실행 뒤 보호 원본 전체 스냅샷은 동일했다.
- 수정 후 ui5는 기존에도 관측된 `Unable to open d/options.cfg`로 초반 중단됐다. 원본은 복구됐으며 원인은 미확인이다. PC/파일시스템 또는 사용자가 본 Codex 용량 오류 때문이라고 결론 내리지 않는다.
- ui6은 ui4와 같은 입력으로 성공했다. 새 워크샾을 대상으로 원본 생산 메뉴가 열리고 썬 캐논·윈드 제네레이터가 등록됐다. 기존 워크샾의78/71, 새 워크샾의128/75 네 실제 Form/부모 관계를 확인했다. 자연 A→B→C, C안내/정지/MORE, SP2800, 종료0, 보호 원본 전체 불변이다. 게임 시각은23.504초다.
- 첫 집중 실행은 대소문자가 다른 `shapeToBuffer` 필터여서0검사/실패1이었다. 올바른 `ShapeToBuffer` 필터의 원본 평면·Factory 픽셀 대조 **5검사 실패0**를 별도 보존했다. 기존 원본 fixture나 기대값은 수정하지 않았다.

실제 입력은 `tutorial-five-production-ui-input.tsv`, 재현/저장 검증기는 `cpp_tutorial_five_production_smoke.py`다. 최종 빌드·전체 회귀·추가 재현·현재 핀 갱신 수치는 `cpppj/tutorial-five-production-runtime.json`과 LEFT 단위210 기록을 따른다. 산출물 접두는 `extracted/goal-early5-production-20261019-`다. 이전 보고서의 현재 핀은 기준과 일치하는 항목만 바꾸고 이전 값/관측/이력을 보존한다.
