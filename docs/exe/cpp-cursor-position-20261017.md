작업 PC와 마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**으로 일치한다. 단위119는 깨끗한 `db8969d`에서 시작했다. 직전 미리보기522행/전체1,477검사와 커밋은 완료된 진행이다. 원본/클론 게임을 별도로 실행하거나 GUI 플레이를 검증하지 않았다. 새 Ghidra 내보내기·추출 소스·보호 원본·AGENTS.md·dotnetpj 변경은 없다.

## 실제 마우스 갱신 몸체

`RawCursorPosition`은 PATCH00446b50을 같은 Drop/Placement 상태 및 현재 카메라/snap 참조에 연결한다. 기존 MetadisplayDirtyView.camera와 같은 두 float 비트를 빌리며 카메라/위치 사본을 소유하지 않는다. 현재 갱신 몸체의 CD 대응은 미확인이고 생성자는CD를 거부한다. 두 수학 helper의 CD 대응은4971e0→455c40,41d770→440a50으로 기록한다.

- 446b55/446b7a는 **int 마우스 x/y**를 읽는다. C 출력의 float 매개변수 캐스트를 옮기지 않는다. 화면점은 현재 hotspot에서 signed 크기/2를 빼고16/11을 뺀 값이며 DWORD 감김을 유지한다.
- 4971e0은 int 감김 뒤 x에16/y에11을 더한다. 정수를 float로 먼저 좁히지 않는 실제 fild32와 단정도 역배율**3d800000/3dba2e8c** 및 현재 카메라를 사용한다. double1/11로 바꾸지 않는다.
- 55a2d8이 켜졌을 때41d770은 `_ftol` signed64 결과의 **하위signed DWORD**를 다시 float로 저장한다. floor/반올림이 아니다. NaN/비유한 절삭의 indefinite 하위0도 보존한다. 스냅 초기값은0이며 teleporter 진단5e4794와 다른 전역이다.

화면점은 잠금/위치 불변 경로에서도 먼저 갱신한다. 월드 좌표가 같으면 정리/생성을 생략하되 NaN은 원본처럼 변경으로 판단한다. 잠금0일 때 Activate(0)을 실행하고 계산된 목표점을 쓴 뒤 **현재 잠금을 다시 읽는다**. 그 뒤 실제 생성과 현재 legalGump에 따른 커서2/3 선택을 수행한다. 생성이 바꾼 좌표/잠금을 뒤에서 덮어쓰지 않는다.

`MakeCursorPositionHooks`는 같은 풀의 실제 Lifecycle.Activate/Previews.Create를 연결하고, `BindCursorPosition`은 Take의 마지막 정수 마우스 인자를 같은 Update에 전달한다. 하드웨어 커서 선택은 실제 공급자가 필요하다. 실제 Client 세션 활성은 별도다.

## 실제 사슬에서 확인한 기존 전역 매핑 오류

단위117/118의 독립 입력 대조만으로는 모듈 사이의 상태 필드가 같은 원본 전역을 뜻하는지 증명되지 않았다. 실제 Activate와 위치 판정을 함께 연결하면서 다음 불일치를 발견했다.

|원본 전역|교정한 단일 의미|
|---|---|
|0055a2ac|Drop.inputFlags: 취득 전 Form의 저장 WORD|
|0055a2e0|Drop.costFlags: Take 두 번째 인자의 전체 커서 플래그;20 지역 검사/40 비용 표시/200 임시 삭제 포함|
|0055a2dc|Placement.placementFlags: 별도의 배치 경고 조건 DWORD|

기존 위치 모듈은20/40을 저장 WORD에, 배치 경고 조건을 호출 플래그에 연결했다. 이를 원래 주소대로 교정했다. 단위117의573행과 단위118의522행 fixture는 **변경하지 않았고**, 검사 어댑터의 입력 연결만 같은 주소의 필드로 바꿨다. 저장 WORD의20이 지역 검사를 켜지 않는 것도 guard로 확인한다.

연속 이동의 다리 입력에는 원본 Take가 추가하는200을 **55a2e0**에 넣어 실제 Activate가 기존 임시 목록을 삭제하도록 했다.55a2dc와 섞지 않는다. 추가로 첫 GUI 사슬 실패에서 상태/슬롯은 같고 수신 이벤트 인자만0/33554495로 달랐다. PE의5427f4 기본값이 **0200003f**임을 확인해 Placement.acceptEvent 기본값을 교정했다. 기존573행은 명시 이벤트123456 입력을 그대로 사용한다.

## 독립 원문과 각 이동 직후 바이트 대조

`decomp_cursor_position.py`는 **623개 단독 입력 +64개 사슬 =687고유 입력**을 관찰한다. 단독 입력은 실제446b50/4971e0/41d770 및 CRT를 실행한다. 사슬은 실제 위치 갱신→Activate→미리보기→Query→Prepare를 **두 번 연속** 실행한다. 첫 Query가 바꾼 그림 크기와 목록을 두 번째 이동이 그대로 사용한다.
