# 음악 채널 제어와 공유 음소거 복원

2026-10-10, 마지막 디컴파일 수행 PC **HJOW-Athlon**(192.168.0.94). 같은 PC의 10.78·CD·추가 10.37 Ghidra 프로젝트에서 [musiccontrol 목록](../../tools/ghidra/musiccontrol-functions.json) **11/13/13개**를 읽기 전용으로 내보냈다. 게임·창·실제 오디오 장치·작업 스레드를 실행하지 않았다.

[SoundMusic.h](../../cpppj/src/client/SoundMusic.h)·[SoundMusic.cpp](../../cpppj/src/client/SoundMusic.cpp)는 음악 채널의 읽기·되감기·시작·닫기·정지·음량과 효과음/음악의 공유 음소거를 복원한다. 기존 `SoundPlayer::SetMasterVolume`을 직접 사용한다. **버퍼 생성/스트리밍 갱신과 실제 COM 경계는 후속 [musicstream](cpp-music-stream-reconstruction.md)에서 완료했다.** 음악 파일 열기·스레드 초기화/종료·실제 장치/클라이언트 연결은 아직 남아 있다. `Start`는 상태만 활성화하고 실제 버퍼 `Play`는 호출하지 않는다.

## 주소와 상태

| 되감기 | `004a9fe0` | 읽기/시작 내부, seek helper `004377d0` |

| 파일 닫기 | `004aa410` | `0043a130` |
| 상태 시작 | `004aaa40` | 파일 열기 `004393b0` 끝의 인라인 구간 |
| 채널 정지 | `004aa9c0` | `00439ea0` |
| 전체 음악 음량 | `004aa5d0` | `00439dd0` |

| 공개 음악 정지 | `004aad70` | `00439910` |

기본 채널은 `005c7b60` / CD `005650b8`, 크기는 `0x60`바이트다. 버퍼/파일은 C++에서 호스트 포인터 대신 32비트 토큰으로 보관하고 외부 경계가 실제 자원을 관리한다. 채널은 `std::recursive_mutex`를 소유하며 원본 잠금 바이트를 호스트 잠금으로 해석하지 않는다.

| 오프셋 | 의미 |
|---|---|
| `+0x00` / `+0x04` | 버퍼 토큰 / 버퍼 바이트 수 |
| `+0x08` | flags: 비트 1=활성, 비트 2=파일 반복 |
| `+0x0c` / `+0x10` | 파일 토큰 / 표본 바이트 수 |

| `+0x20` / `+0x24` | 파일 읽기 위치 / 버퍼 쓰기 위치 |
| `+0x28` | WAVEFORMATEX(18바이트), `+0x3a` 패딩 WORD |
| `+0x3c` / `+0x40` | data 시작 위치 / 중첩 정지 깊이 |
| `+0x44` | 원본 CRITICAL_SECTION 바이트(호스트 잠금과 분리) |

공유 전역은 음악 준비 `005c7b5c` / CD `0051a764`, 음악 음량 `005c7b24` / CD `0051a724`, 예약 음악 음량 `005c7b30` / CD `0051a730`이다. 효과음과 같은 `SoundState`의 기존 보류 깊이/예약 효과음 음량을 사용한다.

## 원본 계약

`Read`는 0바이트 요청에서도 잠금/해제를 수행한다. 파일 끝 이전 요청은 정확히 요청 크기를 읽어야 성공이다. 한 번 재생은 남은 표본을 읽고 목적 버퍼의 끝을 **0으로 채우며 실제 읽은 크기**를 반환한다. 반복 재생은 파일 끝에서 **한 번만 되감아** 나머지를 읽는다. 요청이 여러 바퀴 길이여도 반복해서 채우지 않는다. 정확히 끝에 맞는 요청도 반복 플래그가 있으면 되감는다. 되감기 반환을 검사하지 않는 원본 흐름을 유지한다.

부분 읽기나 IO 실패는 파일을 닫고 0을 반환한다. 이미 출력한 바이트와 앞 구간에서 갱신한 위치는 남는다. 되감기 실패는 파일을 닫은 뒤 잠금을 풀고 `Failed to rewind music file.`을 기록한다. **실패 경로는 File 토큰을 지우지 않으므로 다음 읽기/닫기에서 같은 토큰이 다시 전달될 수 있다.** 후속 실제 파일 경계는 토큰의 수명을 관리해야 한다. 손상된 음수 길이/범위 밖 읽기 위치는 C++에서 예외로 거부하며 native 관찰에 포함하지 않았다.

`Start`는 길이/버퍼가 0이면 원본 assert를 보고한 뒤 계속한다. 보고 줄은 패치 `0x509`/`0x50a`, CD `0x504`/`0x505`다. 외부 잠금 안에서 중첩 되감기를 수행하고 성공하면 flags를 loop=0일 때 1, 그 외 3으로 대체하며 쓰기 위치를 0으로 만든다. 실패하면 기존 flags/쓰기 위치를 유지한다. **CD 시작은 파일 열기 함수 안에 있으므로 C++ 구간은 정적 소스와 비교했고 독립 native 시작 입력은 10.78에만 있다.** CD 읽기의 내부 되감기는 실제 기계어로 실행한다.

`Close`는 파일을 닫고 파일 토큰·길이·data 위치·읽기 위치·duration·WAVEFORMATEX만 지운다. 버퍼·flags·쓰기 위치·정지 깊이·예약 바이트는 보존한다. `Stop`은 외부 잠금 안에서 중첩 정지→버퍼 해제→파일 닫기를 수행한다. 정지 깊이가 0일 때만 실제 버퍼 정지를 요청하고, 활성 비트만 제거한다. 버퍼/버퍼 크기를 지우고 최종 깊이를 0으로 만든다. 파일 반복 비트는 남는다. 음량 적용/버퍼 해제의 음수 반환은 원본 문장을 채널 9에 기록한다.

**두 판본의 공개 정지도 `+0x3a` 패딩 WORD를 보존한다.** CD 디컴파일의 `DAT_005650f0 = 0` 표기만으로 DWORD 초기화로 읽으면 틀린다. 실제 `004399f4`는 `mov word ptr [eax + 0x10], bx`이고 이때 eax는 `005650e0`이므로 WAVEFORMATEX 마지막 WORD만 지운다. 전체 `0x60` 상태 관찰로 이를 확인했다.

음악 음량은 범위를 자르지 않는다. 보류 깊이가 0 이외이면 예약 음악 음량만 바꾼다. 그 외에는 현재 음량을 저장하고 음악이 준비됐으면 채널 버퍼에 적용한다. 버퍼가 없어도 채널의 잠금/해제는 수행한다.

첫 `PushMute`는 효과음/음악 음량을 예약하고 두 음량을 `-10000`으로 바꾼 뒤 DWORD 깊이를 증가시킨다. 음수 깊이도 그대로 증가한다. `PopMute`는 양수만 감소시키고 마지막 해제에서 최신 예약 효과음/음악 음량을 복원한다. 중첩 중 음량 변경은 예약값만 갱신한다. 효과음 복원 COM 콜백이 깊이를 바꾸면 패치판은 깊이를 다시 검사해 음악 즉시 복원을 건너뛴다. CD는 음악 setter를 호출해 변경된 보류 상태를 따른다. 두 판본의 재진입 입력을 대조했다.

## 독립 대조와 검증

[실행기](../../tools/decomp_musiccontrol_oracle.py)가 세 원본 PE의 실제 음악/공유 음소거와 기존 효과음 제어/조회 몸체를 실행했다. **10.78 1,780개·CD 1,756개·추가 10.37 1,756개, 총 5,292개**다. 두 x87 제어값 `0x027f`·`0x037f`에서 스크립트 10,584회, 음악 직접 함수 호출 **44,244회**(기존 Lookup/효과음 음량까지 포함한 root 호출 **66,132회**)가 정상 반환했다. 직접 시작/되감기 입력은 10.78 24개에만 포함한다.

COM 음량/정지/참조 해제, Winmm read/seek/close, 잠금 관찰, 기록/예정 assert/패치 CRT 로캘, 초기 표/채널/파일/버퍼 배치와 명시 COM 재진입만 대체한다. 파일 읽기 출력은 독립 메모리 파일을 실제 원본 요청에 따라 공급하며 음악 상태 전이를 Python으로 계산하지 않는다. 원본 잠금 호출은 사건/중첩/균형으로 검사한다. 실제 OS 호출은 0이다.

[musiccontrol-x86.tsv](../../cpppj/tests/fixtures/musiccontrol-x86.tsv)는 호출별 사건/반환, 전체 채널 96바이트와 출력 128바이트, 효과음 표 Adler-32, 파일 위치/열림 상태와 공유 음량/깊이 전역을 보관한다. [근거 기록](../../cpppj/recovery-musiccontrol-evidence.json)은 PE/실행기/내보내기/관찰 SHA, 전체 입력/행, 직접 정상 반환/실제 몸체 진입, 허용 쓰기·스택/보존 레지스터/SEH/x87·예기치 않은 assert/OS 0·잠금 균형을 감사한다. 기존 fixture/감사 도구는 수정하지 않았다.

[SoundMusicTests.cpp](../../cpppj/tests/SoundMusicTests.cpp)의 새 검사 6개는 판본별 모든 관찰과 실제 시작→파일 끝 통과→부분 IO 실패→정지, 중첩 음소거 중 예약 음량 갱신→마지막 복원, 잘못된 길이/경계 누락 및 IO 예외 뒤 잠금 해제를 확인한다. 일반 CTest는 원본 PE/Python/장치/실제 파일/작업 스레드를 실행하지 않는다.

```powershell
powershell -ExecutionPolicy Bypass -File tools/ghidra/export_functions.ps1 -Name musiccontrol
python -X utf8 tools/decomp_musiccontrol_oracle.py
python -X utf8 tools/decomp_musiccontrol_oracle.py --verify
cmake --build cpppj/build --config Release --parallel 4
cpppj/build/bin/Release/netstorm_tests.exe --filter SoundMusic_
ctest --test-dir cpppj/build -C Release --output-on-failure
```

누적 독립 관찰은 **430,645개**다. 최종 회귀 결과와 기록은 [LEFT_JOBS.md](../../LEFT_JOBS.md)의 최신 인계를 따른다.
