# 영역 청크 배치 분석

> 2026-09-28 · 보유 패치판 `Netstorm.exe` 정적 분석 및 원본 463개 `.fort` 검증

`Territory`의 모양에서 빈 칸을 제외하면 `TerrNN` 청크의 수와 위치를 결정할 수 있다.
청크 순서는 생성 패턴의 순회 순서가 아니라 **최종 월드 y·x 순서**다.

## 레코드와 패턴

섹션은 6바이트 × 20개다 (`Template` 읽기 `004bd660`, 쓰기 `004bd600`).

| 오프셋 | 확인된 의미 |
|---|---|
| 0 | 하위 6비트: 모양 번호, 상위 2비트: 방향 값 |
| 1 | 플래그: bit 0이 켜지고 bit 1이 꺼져야 섬 생성 대상 |
| 2 | 청크 위치: **하위 니블 x, 상위 니블 y** (오브젝트 위치 바이트와 반대) |
| 3 | 청크 중심 위치·성장 시드에 참여하는 값 ([추가 분석](terrain-and-bridges.md)), 나머지 역할 미확정 |
| 4~5 | 미확정, 로더는 원본 값 보존 |

`Islandbuilder`의 `0046dba0`는 위치 바이트를 기준 사각형의 시작점에 더하고
`Canondecoder`의 `00425c20`에 타입 `DAT_00541204`, 모양 번호, 방향, 위치를 넘긴다.
`0046dd70`은 플래그 bit 0/1을 검사한다. 나머지 비트 의미는 아직 확정하지 않았다.

패턴은 VA `0x5300f0 + 모양 × 72`에 있다. 첫 12바이트는 정수 3개
(첫 값 미확정, 폭, 높이)이며 나머지는 최대 15개의 4바이트 셀이다.
셀의 둘째 바이트가 `.`이면 빈 칸이고 `A`~`P`이면 유효 청크다 (`00425700`).
그 밖의 셀 정보는 지형 생성 분석에서 사용해야 하며 현재 JSON은 청크 위치 계산에 필요한 문자만 보존한다.

`tools/territory_patterns.py`가 선택 가능한 64개 패턴을 `TerritoryPatterns.json`으로 추출한다.
게임은 이 JSON을 내장 리소스로 읽으므로 실행 시 원본 exe는 필요하지 않다.

## 방향 처리의 주의점

생성 호출 `0046dc7e`는 저장된 상위 2비트를 그대로 전달하고,
`00425c20`의 `00425c3f`는 이 값을 2로 나눈다. 따라서 실제 청크 생성은
저장 값 0·1에서 회전 0, 2·3에서 시계 방향 90도를 사용한다.
회전 배열 VA `0x531530`~`0x53158f`도 함께 확인했다.

반면 크기 계산 `004bfd70`과 청크 수 계산 `004bfde0`은 방향 값을 두 배하여 전달한다.
두 경로의 차이는 그대로 문서에 남긴다. **원본 463개 파일의 활성 영역 2,053개는 방향이 모두 0**이라
회전된 저장 파일의 실제 플레이 결과는 아직 검증하지 못했다.

## 원점과 저장 순서

저장 좌표를 유지하는 미션 경로 `00432050`은 기준 사각형 시작점을
`(위치 x + 1, 위치 y + 1)`로 정한다. `FortMap`은 이 원점 (1,1)을 기본값으로 사용한다.
요새 편집 경로 `00431ff0`의 시작점은 (6,6)이다. 일반 전투는 플레이어별 위치 재배치가 있으므로
저장된 미션 맵을 읽는 경로와 분리해 구현해야 한다.

`0046dba0`가 패턴의 유효 셀을 월드 청크에 등록한다. 저장 `004be230`과
읽기 `004be2c0`은 전체 월드를 y·x 순서로 훑고 해당 영역의 청크만 골라 처리한다.
청크 좌표를 정렬한 뒤 `TerrNN`의 순번과 대응시키면 된다.

## 검증 결과

* 원본 463개 파일의 모든 비어 있지 않은 `TerrNN`에서 패턴의 유효 셀 수와 저장 청크 수가 일치한다.
* `Save the Island!`의 Terr07: 모양 7, 위치 `0x59` → (10,6), (11,6), (10,7), (11,7).
* 같은 맵의 rainVortex (187,108), priest (185,118), Chaff rainBattery (193,106)가 캡처의 템플릿 매칭 좌표와 일치한다.

다음 분석 대상은 패턴 셀의 지형 방향·변형 값, 영역 외관 값, 원소별 지면 생성과 다리의 복합 모양이다.

## C++ 복원 (2026-10-05)

이 경로를 cpppj에 원본 구조대로 옮겼다: `o/CanonDecoder`(`00425c20`·`00425860`·`00425700`), `o/ChunkMap`(`00432180`·`00432210`), `o/Islandbuilder`(`0046dba0`·`0046dd70`)와 영역 청크 순회(`004be2c0`). 패턴 표는 실행 파일의 68개를 그대로 쓴다(이 문서의 JSON은 선택 가능한 64개다). 두 판본의 모든 `.fort`(패치판 폴더 465개·영역 2,060개, CD판 23개·영역 59개)에서 C++의 결과가 이 문서의 규칙으로 Python에서 따로 계산한 청크 좌표·방향 글자·순서와 같다. 실제 파일의 영역은 여전히 모두 방향 0이다. 근거와 범위: [cpp-screen-reconstruction.md](cpp-screen-reconstruction.md) 9절, 검사 `tools/cpp_window_smoke.py`.
