# 4차 와이드 해상도 — 16:9 최대 1920×1080 (단위937)

2026-11-06, HJOW-Athlon. AGENTS.md 4차 요구("와이드 해상도는 16:9, 최대 1920×1080, 이 단계는 해상도 지원만이며 그래픽 크기 스케일 조정 불필요")의 구현이다.

## 조사 결과

- 논리 화면은 `SCREENW/SCREENH` 설정으로 정해지며 시작 때 **크기 검증이 없다**. 원본의 세 4:3 크기뿐 아니라 임의 크기로 이미 시작·렌더링된다(DIB 논리 화면). 그래서 `--set "SCREENW=1920;SCREENH=1080"`만으로 1920×1080에서 메인 메뉴와 미션이 열렸다. 메인 메뉴 배경(구름)은 전체 화면을 채우고 640×480 로고 그림은 크기 변경 없이 가운데에 놓인다(요구와 일치). 미션은 좌측 80px HUD 덱과 나머지 전체 맵 뷰로 배치된다.
- 선택 목록은 `client/ScreenResolutions.h`의 `kScreenResolutionChoices` 하나를 옵션 팝업(`resolution`)과 게임 안 ESC Options 메뉴(`RawGameMenus`)가 공유한다. 이미 호환 항목 1280×720·1280×800·1366×768이 있었다.

## 변경

1. 목록에 **1600×900, 1920×1080**을 추가했다(원본 3 + 호환 5). `IsSupportedScreenResolution`으로 허용 판정을 한 곳에 두고 `Client::ChangeResolution`의 하드코딩된 세 크기 검사를 이 목록 기반으로 바꿨다. 폭만 받는 옛 `resolution` 명령의 높이도 목록에서 찾는다.
2. **메인 메뉴 버튼 y 보정(높이 800 초과):** 원문은 `y=SCREENH/3+55`(둘째 줄 +78)이며 1024×768에서 로고 그림 위 기준 167이다. 같은 식은 1080에서 버튼을 로고 위로(그림 기준 115) 올려 겹치므로, 높이 800 초과에서만 그림 기준 같은 위치(`(H-480)/2+112+55`)를 쓴다. 800 이하(원문 3개, 1280×720·1280×800·1366×768)의 값은 그대로다. 코드 주석에 원본과 다른 Windows 10/11 와이드 호환 처리임을 적었다.
3. 검사: 새 `netstorm_screen_resolution_tests`(목록/허용 판정 계약 2개)와 기존 메인 버튼 배치 검사(`RawMenuControls_MainLayoutMeasuredWidthAndSixResolutions`)에 두 해상도 사례(1600×900 → x644,y377 / 1920×1080 → x804,y467)를 추가했다. 두 검사 모두 통과했고 빌드 경고/오류는 0이다. `netstorm_main_popup_tests`의 실패 1개는 단위933에서 기록한 기존 실패(`CampaignSaveGoMain_ActualManagerGateAndSelectedBattleStop`)와 같다.

## 실제 실행 확인(창 모드, 논리 화면 캡처)

- 1920×1080 메인 메뉴: 버튼이 로고 아래 정상 위치. 옵션→Resolution 하위 메뉴에 8개 해상도가 나오고 현재 1920 by 1080이 표시된다.
- 1024×768과 1920×1080의 Tutorial1 미션 화면을 비교해 같은 HUD 구성과 전체 맵 뷰 확장을 확인했다. 프레임 시간은 두 해상도에서 같았다(310프레임 12초, 프레임 제한 지배).
- 해상도 변경 흐름: `Tell SETSIZE(1600,900)`→Yes→설정 저장·종료 뒤 `--set` 없이 다시 실행하면 1600×900으로 올라온다.
- MCP 화면 PNG/녹화도 화면 크기를 그대로 따른다(1920×1080에서 PNG 인코딩 정상).

## 알려진 한계

- **좌측 덱에 y=774..798의 80×25 검은 직사각형**이 높이 774를 넘는 해상도(1280×800 기존 호환 항목 포함, 900·1080)에서 보인다. 위치가 화면 높이와 무관한 고정값이라 768 기준 좌표의 숨은 요소가 원래는 화면 밖이던 것으로 추정하나 어느 Gump인지 아직 확정하지 못했다(리포트에 해당 좌표의 항목 없음). 해상도 지원 자체는 막지 않는 표시 결함이며 후속 조사 대상이다.
- 높이 1080 이상(16:10 1920×1200 등)과 4K는 이번 단계의 지원 범위가 아니다(4K는 7차 FSR 요구).
- 실제 전체화면(모니터 1920×1080)과 창이 바탕화면보다 큰 경우의 물리 출력은 확인하지 못했다. 기존 전체화면 호환 표시(`FitScreenPresentation`)가 같은 논리 화면을 사용한다.
- 와이드에서 월드 카메라 이동/가장자리 스크롤/미니맵의 세부 동작과 모든 UI 창의 배치는 사용자 플레이 확인 대상이다.
