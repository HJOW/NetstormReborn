# cpppj1328 — 방향키 카메라 이동

2026-11-23, HJOW-Athlon. 마지막 디컴파일 PC도 HJOW-Athlon이며 원문/디컴파일은 변경하지 않았다. 방향키 화면 이동은 원본에 없는 사용자 추가 요구다.

## 입력 계약

게임 화면에서 ↑↓←→ 누름 사건마다 논리 화면 기준 32픽셀을 이동한다. 누르고 있을 때는 기존 Win32 키 자동 반복을 사용하며 별도 프레임 타이머·키 보관을 추가하지 않았다. 같은 프레임의 여러 사건도 현재 목표에 누적하고 기존 Present의 지도 경계 제한을 따른다. 따라서 FPS/출력 배율은 사건당 이동량에 영향을 주지 않는다. Shift/Ctrl/Alt 자체로 새 속도 배율은 적용하지 않으며 기존 Alt 폴링 이동은 그대로 우선한다.

Guide 뒤에서 현재 대화창·도움말·메뉴·Gump 캡처·채팅 입력줄 표시 여부를 확인한다. 아무 입력 UI도 없는 게임 화면에서만 `UserInput::Event`로 먼저 보내고, 활성 조각의 좌/우 회전은 기존 `RawCampaignCursor::HandleInput`가 먼저 소비한다. 위/아래는 조각을 든 상태에서도 카메라 이동이다. 정지·키 뗌은 기존 세계 입력 관문에서 거부한다. 입력 UI에 전달한 방향키는 카메라 꼬리로 다시 보내지 않는다.

원본 ChatWindow는 입력줄을 숨겨도 위/아래를 로그 스크롤로 소비했다. 최초 실행에서 좌/우만 움직여 이를 발견하고, 입력줄이 숨겨진 일반 게임 화면의 네 방향키를 앞서 분배하도록 고쳤다. 두 번째 실행에서는 열린 메뉴의 미소비 좌/우가 세계 꼬리로 흘러 카메라가 움직이는 문제를 확인했고, UI 관문에서 거부된 방향키의 세계 재진입을 차단했다. 두 실패 보고·실행 파일 SHA를 `extracted/cpp-followups-1328/`에 보존했다.
