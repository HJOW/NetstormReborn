# C++ 표면 이웃·다리 연결·붕괴 방문 목록 복원

2026-10-05. [다리 계산 복원](cpp-bridge-reconstruction.md)에 이어 원본의 **연결 검사, 정수 발자국의 표면 이웃 탐색, 붕괴 방문 목록 재귀**를 옮겼다. 패치판 10.78과 CD판 10.72의 실제 함수/보조 함수를 Unicorn에서 정상 반환까지 실행했다. 원본 게임과 클론 GUI는 실행하지 않았다.

소스는 새 [SquidFinder.h](../../cpppj/src/o/SquidFinder.h)·[SquidFinder.cpp](../../cpppj/src/o/SquidFinder.cpp), 확장한 [Bridge.h](../../cpppj/src/o/Bridge.h)·[Bridge.cpp](../../cpppj/src/o/Bridge.cpp)다. **현재는 읽기 전용 표면 스냅샷을 받는 계산 계층이다. GameWorld의 실제 표면 배열·spot 생성, 배치 UI, 수명 타이머·금/낙하/삭제는 아직 연결하지 않았다.** 미션 완주는 여전히 불가능하다.

## 1. 확인한 함수와 호출 범위

| 계산 | 패치판 | CD판 | 실행 범위 |
|---|---|---|---|
| 양쪽 타입/프레임의 연결 | `00441e40` | `004d2e00` | 스택 인자 5개, `ret 0` |
| 이웃 탐색기 생성 | `004b23e0` | `004ebad0` | ECX 객체, 번호·flag 8, `ret 8` |
| 초기 범위/spot 검사 | `004b1d70` | `004ebf30` | flag 8 경로, `ret 0` |
| 표면 지도 순회/중복 | `004b1c20` | `004ebdd0` | 실제 지도·가상 필터, `ret 0` |
| 가상 후보 필터 | `004b1e80` | `004ec040` | 실제 타입/기하/연결 함수, `ret 4` |
| 다음 이웃 | `004b1e70` | `004ec030` | flag 8 경로, `ret 0` |
| 다리 이웃 수 | `004b2660` | `004ec150` | 재귀에서 호출하는 출력 목록 NULL 경로, `ret 0` |
| 붕괴 방문 목록 | `004218b0` | `00449f10` | 깊이 0/부모 0에서 전체 재귀, `ret 8` |

전체 프로그램의 모든 입력을 검사한 것은 아니다. 표면 탐색은 정수 기준점·지도 안에 놓인 정상 발자국·flag 8에 한정한다. 일반 공간 해시, 이동 중 소수 좌표, 이웃 수 함수의 출력 목록 쓰기 경로는 후속이다. 구조체는 원본 포인터/바이트 오프셋을 C++로 복제하지 않고 이름 있는 필드로 바꿨다.

## 2. 옮긴 규칙

`Bridge::Connects`는 짝수 방향에서 프레임의 `side`, 홀수 방향에서 `variant` 글자를 읽는다. 양쪽에 현재/반대 방향의 연결 비트가 있어야 한다. 타입 플래그 2의 `0x40000`은 글자를 P로 만들고, 다리/폭탄 마스크 `0x104`와 섬/건물군 마스크 `0x1044202`가 만나는 경우 섬/건물 쪽을 A로 바꾼다. **이 보정의 순서와 if/else 우선순위도 보존했다.** 소유자·동맹·놓을 수 있는 위치를 판단하는 함수와는 범위가 다르다.

`SurfaceFinder::Neighbors`의 지도는 **칸마다 표면 객체 번호를 담은 256×256 ushort 배열**이며 spot은 같은 크기의 byte 배열이다. 기준점은 발자국의 오른쪽 아래 칸이다.

1. 자기 사각형의 각 좌표를 원본처럼 1..255로 제한하고 spot을 모두 AND한다. 공통 비트 8이면 탐색하지 않는다. 가장자리 0을 1로 제한하는 규칙도 그대로다.
2. 사각형을 한 칸 넓히고 네 모서리를 제외하여 y 바깥·x 안쪽 순서로 읽는다. 1×1이면 북→서→자기→동→남 순서다. 지도 밖/번호 0은 건너뛴다.
3. 후보의 기준점이 자기 사각형 안이면 제외한다. 타입의 `surface`(플래그 1 `0x800`), 양방향 연결, 죽음 비트, 후보 기준점의 spot 비트 8을 확인한다. flag 8 경로는 buried 비트를 추가로 제외하지 않는다.
4. 후보 중심→자기 중심의 네 방향을 고른다. 중심은 `(x-width×0.5, y-height×0.5)`이며 절댓값 동률이면 세로 방향이 먼저다. 같은 객체 번호는 여러 지도 칸에서 발견해도 한 번만 반환한다.

표면 객체 번호 지도의 주소는 패치 `DAT_005c84bc`, CD `DAT_0052d590`이다. 기존 열린 방향 시험에서 설정한 별도 조회 전역을 이 배열 주소로 간주하면 안 된다. 실제 CD 순회 명령의 포인터 읽기로 확인했다.

**2026-10-06 후속 확인:** 이 전역은 [SquidHash 0단계의 버킷 머리 배열](cpp-hash-reconstruction.md)이다. 앞선 중복 테스트의 여러 셀에 같은 번호를 적은 합성 입력은 탐색기 규칙의 근거이며, 원본 등록이 객체 발자국 전체에 번호를 채운다는 뜻이 아니다. 실제 기준점/공간 체인과 spot 등록은 별도로 복원한다.

`Bridge::CollectDecay`는 원본의 방문 목록 [시작 다리]와 두 전역 플래그를 이름 있는 결과로 반환한다. 이 함수 자체는 실제 수명을 줄이거나 객체를 삭제하지 않는다.

- 다리/섬인 이웃을 순서대로 읽고 바로 전 부모만 제외한다. 다리는 용량이 남을 때 방문 목록에 추가한다. 기본 용량은 원본 초기화의 100이며, **목록이 차도 재귀/경계 처리는 계속한다.**
- A~I 접합 칸이고 섬이 아니면 재귀한다. 깊이 0에서 그 이웃의 이웃 수가 3 미만이면 `shortJunction`을 켠다. 이 플래그는 뒤의 분기에도 유지된다.
- 판자·끝 칸·P·섬은 경계다. 깊이 0 또는 깊이 1의 짧은 접합이면 `canDecay`를 켜고 그 번호의 **모든 목록 항목**을 제거한다. 그 외에는 다리 이웃 수가 2 미만이면 진행, 2 이상이면 해당 번호를 제거한다. 섬의 이웃 수는 이 분기에서 0으로 취급한다.
- 전체 목록을 방문 집합으로 바꾸지 않는다. 원본은 부모만 제외하여 접합 고리에서 무한 재귀할 수 있다. 새 C++는 현재 재귀 경로의 고리 또는 안전 깊이 256에서 `complete=false`, `canDecay=false`로 중단한다. 이 한계는 새 코드의 안전 처리이며 원본 상수가 아니다. 불완전 결과로 수명 갱신을 진행하면 안 된다.

## 3. 검증 결과와 재현

[decomp_surface_oracle.py](../../tools/decomp_surface_oracle.py)는 실제 PE 기계어·프레임/타입·기하 함수·이웃 필터·재귀를 실행하여 [surface-x86.tsv](../../cpppj/tests/fixtures/surface-x86.tsv)를 만든다. 이웃 탐색이나 재귀를 Python 계산으로 대체하지 않았다. assert 보고만 대체했고 **두 판본 모두 호출 0회**였다. 허용 함수 몸체·명령 수 200,000·복귀 EIP/ESP/`ret N`과 메모리 쓰기 범위를 검사했다. 입력 객체/타입/지도는 네이티브 쓰기를 허용하지 않았다.

| 새 기대값 | 입력 사례 | 내용 |
|---|---:|---|
| 연결 | 3,016 | A~P 모든 쌍/8방향, 별도 축 글자, 타입 마스크/보정 순서 |
| 이웃 | 125 | 지도 가장자리·1×1/3×3·큰 이웃 중복·표면/죽음/내부 비트·목록 순서 |
| 재귀 | 309 | 직선/분기·긴 접합 사슬·판자/끝/섬 경계·용량 1/3/100 |
| 합계 | **3,450** | 두 판본 결과 모두 일치 |

[SurfaceTests.cpp](../../cpppj/tests/SurfaceTests.cpp)의 세 x86 검사와 스냅샷 수명·접합 고리·입력 오류 검사 세 개를 추가했다. Windows Release 빌드 경고·오류 0, **CTest 내부 81개 검사** 통과. 기존 23,418개와 합쳐 **26,868개 x86 기대값 입력 사례**이며 기존 수명 480개는 접두 구간 검사다. 게임 전체의 완성도나 전체 붕괴/실제 플레이 검사 수로 해석하지 않는다.

[recovery-surface-evidence.json](../../cpppj/recovery-surface-evidence.json)에 원본 두 판본·기대값·생성/공통 실행 도구의 SHA-256, 실제 쓰기 대상 주소/크기 수, 적용/거부한 함수 대응과 한계를 기록했다. [decomp_refine.py](../../tools/decomp_refine.py)는 이 해시와 두 판본의 함수 존재/`ret N`을 확인한 뒤 7개 검토 대응을 적용한다. 새로 확인한 필터·표면 순회 함수도 포함한다. 재생성한 전체 대응은 2,496쌍·검토 19쌍(strong 1,735/medium 710/weak 51)이다.

추가 오대응 `004b1810`↔CD `004eae20`을 금지했다. 전자는 일반 공간 해시의 다음 함수(`ret 0`), 후자는 생성자(`ret 16`)다. 일반 공간 해시 경로의 동작은 이번에 검증하지 않았으므로 새로운 완전 함수 대응으로 추정해 넣지 않았다.

```powershell
python tools/decomp_surface_oracle.py
python tools/decomp_refine.py
python tools/cpp_source_map.py
cmake --build cpppj/build --config Release
ctest --test-dir cpppj/build -C Release --output-on-failure
```

기대값 생성에는 기존 Python/Unicorn/PE 분석 환경이 필요하다. 저장된 기대값을 사용하는 C++ 빌드/CTest에는 원본 실행 파일·Python·Ghidra가 필요 없다. 원본 게임 실행·원본 자료/AGENTS.md 수정·C# 변경은 없었다. SOURCE_MAP의 파일 존재 표시는 28/136이며 전체 모듈 완료 수가 아니다.

## 4. 다음 작업과 계획의 주소 정정

이전 계획의 **`004215d0`를 배치 판정으로 적은 부분을 정정했다.** 이 함수는 폭발 가장자리의 J/K 판자를 L~O 끝 칸으로 바꾸는 함수이며, [기존 분석](bridge-pieces.md#81-exe-로-확인한-것)에도 기록되어 있다. 실제 배치 판정은 RiftType의 **`0049b510`↔CD `00445200`**, 실제 조각 생성/품질 적용은 Construction의 `00442c80`에서 확인한다.

1. 실제 표면 객체/SID·표면 번호 지도·spot 생성과 변경 순서를 복원한다. 현재 GroundGrid의 bridge bool을 원본 연결망으로 간주하지 않는다. 지금의 SurfaceFinder는 새 입력 스냅샷이 필요하므로 이동/생성/삭제 시점에도 재구성해야 한다.
2. `0049b510`의 다리 배치 경로에서 겹침·초목·영역/소유자·이어짐과 법적 위치 마스크를 좁혀 복원한다. `00421240`/`004213b0` 소유자 전파, Construction의 실제 생성도 이어서 연결한다.
3. `004227e0` 한 칸 처리·`00422bc0` 스캔에 방문 목록을 연결하고, 수명 함수의 나머지·금 프레임/소리·낙하·삭제를 복원한다. 그래프 크기와 원본 번호별 처리 순서를 확인한다.
4. 다리 생산 칸·커서 조각·회전·배치 클릭을 GameWorld/UI에 연결한 뒤 Construct·덱·에너지·채집/SP→전투·AI·승패/결과·소리로 진행한다. [전체 계획](../cpp-playable-plan.md)과 [LEFT_JOBS.md](../../LEFT_JOBS.md)에 완료/남은 범위를 함께 기록한다.
