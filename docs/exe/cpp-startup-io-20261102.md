# cpppj 단위737 — 생성자의 선행 TAFF 읽기 제거

2026-11-02 / HJOW-Athlon / Windows 10. 마지막 전체 정밀 디컴파일은 HJOW-Athlon·2026-10-23이며 새 디컴파일은 없다. 733의5차 전체 자동 파일/reader·일반 권한 설치와 Windows10/11 AMD64·Windows11 ARM 고려 요구는 유지한다. 이관 구현과 ARM 검증은 미착수다.

## 문제와 변경

기존10.78 Client 생성자는 Run의 setup 탐색 전에 입력 폴더의 모든 TAFF를 읽었다. 따라서 하위 launcher의 setup 대신 부모 d/setup.cfg를 찾아 부모 자료를 쓰는 원문 경로에서도, 선택하지 않을 하위 폴더의 손상 아카이브 때문에 먼저 실패할 수 있었다.736이 실제 시작 두 목록/핸들 수명을 연결했어도 생성자의 이 선행 I/O는 남아 있었다.

10.78 생성자에서 파일/디렉터리 열거를 제거했다. 실제 Run은 `InitializeNativeStartupFiles`를 통해735의6후보 setup 탐색→CD 탐색→부모 기본 루트→736의 같은 FileSpec 기본/CD 등록을 실행한다. 성공한 선택 루트는 같은 Client의 GameDirectory/VFS/설정 reader로 이어지고 마지막 검색 핸들은 기존처럼 설정 Load/두Set 뒤 반납한다. 10.72는 이번10.78 복원으로 바꾸지 않고 기존 생성자 등록을 유지한다.

원본 Run을 호출하지 않는 독립 Client API는 이전의 자동 아카이브 조회 계약을 유지한다. 생성자에서는 기본 등록을 예약만 하고, 실제 TAFF 내용/메타데이터/목록이 처음 필요할 때 기존 값형 등록을 한 번 수행한다. 직접 디스크 읽기·절대 Probe·MatchDisk·소유자 조회는 이 예약을 실행하지 않는다. 실제 시작은 예약된 옛 VFS를 선택 루트의 새 VFS로 교체하므로 이 독립 API 호환 처리가 원문 등록 앞에 들어가지 않는다.

등록 캐시는 mutable 목록으로 구현해 const 조회와 const 복사에서도 정의된 C++ 객체 변경으로 준비한다. 공개 명시 등록 API/등록 순서·중복 관문은 유지하고 같은 등록 몸체를 공유한다. 매 조회마다 아카이브를 다시 읽거나 손상 오류를 성공으로 삼지 않는다. 독립 예약은 원본 게임의 별도 기능이 아니라 cpppj의 창 없는 조회 API 호환이며 실제 Run의 Native 초기화 순서와 구별한다.
