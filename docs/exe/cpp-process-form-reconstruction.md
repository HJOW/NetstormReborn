이 단계는 [건설 상태 전송·수신](cpp-construction-data-reconstruction.md)의 새 수신 객체 부착 경계를 실제 SID 풀/Kernel에 연결한다. `SquidProcessHost::Attach`의 선택적 `form` 인자와 `RawConstructionData(pool,state,logic,host)` 생성자, `RawPacketDispatch` 및 `RegisterConstructionData`를 더했다. 서버와 client 월드가 같은 서버 form 번호를 유지하며 전체 상태를 수신하고, 부분 갱신 뒤 실제 프레임에서 HP를 진행한다. client는 서버 삭제 권한을 기다리고, 삭제 통지의 기존 하위 몸체를 직접 호출해 완료 처리/반납까지 검사한다. 부모 abstract는 비권한 client에서 유지되며 서버의 후속 상태 전파를 기다린다. 게임 내 건설 GUI는 아직 연결하지 않았다.

## 지정 free form

원본은 먼저 Kernel 번호를 받고 지정 서버 슬롯을 Take한다. Take는 free/dead 비트만 끄고 ProcessForm의 가상 표/타입/void를 쓴다. 생성자는 슬롯을 지우지 않고 postTake는 빈 함수다. 자산 Take의 zOrder 후처리를 적용하면 원본 바이트가 달라진다. 이후 실제 프로세스 타입과 DWORD Kernel 번호를 쓰고 부모에 부착한 뒤 `OnAttached`를 호출한다.

부착 순서는 부모 WORD `+16` → 다음 WORD `+4`에 기존 머리 → 기존 머리의 이전 번호(form `+14`, 자산 `+16`) → 부모 머리 WORD `+6` → 이전 WORD `+14=0` → contained 설정/void 해제다. 풀 freeCount·예측 커서·free 머리/꼬리는 Take 때문에 바뀌지 않는다. 패치판 실제 Kernel 등록의 타입 순환만 기존 규칙대로 진행한다.

C++는 번호 0이면 기존 Allocate 경로를 사용한다. 지정 번호는 서버 영역(패치 15000/CD 6000) 안의 free 슬롯만 받는다. 사용 중인 form 재부착·예측 예약 머리·잘못된 체인/genus는 Kernel 등록 전에 예외로 거부한다. 패치 free/dead 부모는 기존처럼 null로 건너뛰며 CD의 assert 뒤 진행은 지원하지 않는다.

## 단일 패킷 분배

원본 세 등록 함수는 각각 처리기, observer, 버전/정책 표 하나만 바꾼다. C++ 등록 API는 타입 0/최대 밖 번호를 쓰기 전에 예외로 거부한다. 이 입력들의 원본 패킷 거부 결과는 대조하되 원본의 범위 밖 등록 메모리 쓰기는 C++로 재현하지 않는다. 초기 최대 타입은 패치 137/CD 126이다. 실제 WORD 선언 길이 표를 `RawPacketLengths.h`에 그대로 저장하며 감사 도구가 PE와 직접 대조한다. 0xffff이면 가변 길이이며, 타입 10 이상은 처리기가 있어야 검증을 통과한다. 실제 span 폭과 선언 길이를 같게 강제하지 않는다. 처리기가 필요한 필드 폭을 별도로 확인한다.

단일 분배 순서는 닫힌 연결 거부 → 검증 → 버전 정책 → 현재 시각 기록 → 타입 10 이상 기록 경계 → 현재 처리기 재조회 → 깊이 증가/콜백/감소 → depth 0에서 종료 비트가 켜지면 close/release다. 타입 6은 별도 heartbeat 시각을 기록한다. 단일 경로는 observer를 호출하지 않는다. 기록 경계나 콜백의 재등록·중첩 때도 처리기 선택과 저장소 수명을 보존한다. C++ 콜백 예외에서 깊이를 복구하는 동작은 별도 호스트 계약이다.

incoming은 bit 0x80을 가린다. 낮은 버전은 정책 8 종료/2 무시, 높은 버전은 4 종료/1 무시이며 종료가 우선한다. 정책 0이면 버전이 달라도 계속 처리한다. 원본 초기화처럼 건설 **0x37은 observer=null, version=1, 정책=0**이다.

새 소유 수신은 실제 ConstructionProcess를 만들고 전체 FF 상태를 읽은 뒤 캡처한 서버 form/부모 DWORD/현재 타입으로 부착한다. 수신 생성자의 원본 미초기화 소리/추가 영역과 C++ 기본 0 저장소 계약을 구분한다. 추가 바이트는 전체 상태에서 복원하고 소리는 전송하지 않는다. 잘못된 부모 DWORD나 잘린 패킷은 살아 있는 Kernel 객체를 남기지 않는다.

## 독립 근거와 검사 범위

`tools/decomp_processform_oracle.py`는 세 PE 각각 **612개**(Attach 288·Dispatch 324), 합계 **1,836개**를 두 x87 정밀도에서 실행한다. 기존 누적 489,939개에 더하면 **491,775개**다. 주 부착/분배 루트 정상 반환 **3,672회**, 별도 세 등록 루트 정상 반환 **5,832회**를 구분한다.
