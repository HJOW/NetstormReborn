## 제품 변경과 의미

암호 읽기의 `fread`는 `(data,size,1,file)`이며 반환값으로 반복 길이를 줄이지 않는다. 짧게 읽혀도 **요청한 묶음 전체**를 XOR/복사한다. 따라서 미작성 작업 BYTE와 앞 묶음에서 이미 해독한 BYTE도 다음 결과에 영향을 준다. 호출자가 명시한 현재 작업 버퍼를 사용하며 각 묶음/실패 때0으로 채우지 않는다. 버퍼 물리/키 부족은 명시 예외로 남긴다. 원본의 실제 미정 스택 값 자체를 복원했다는 주장이 아니다.

PE의0052f454에서 실제 fopen 모드는 세 개뿐이다. 네 번째 DWORD는 이웃 함수 주소라 append 모드를 추가하지 않았다. NULL/빈 키는 새로 할당하지 않는다. 키 할당 중 입력이 바뀌면 복사는 원문처럼 그 시점의 첫 NUL에서 멈춘다. NULL 할당이나 손상 포인터가 정상 동작한다고 가장하지 않는다.

일반 파일은 이제 기존 VFS 조회 정책 뒤에서 공통 열기→길이→읽기→소멸을 사용한다. Windows10/11의 원본 ANSI와 다른 wide CRT 경로는 주석으로 명시했다. 전체 바이트 vector는 음수 길이 또는 읽는 중 줄어든 파일의 짧은 전체 읽기를 거부한다. 원문의 미정 tail을0으로 만들어 정상 자산으로 반환하지 않는 호스트 물리 경계다. 전체 원문 FILE/예외 객체 ABI의 복원과 구별한다.

TAFF는 기존처럼 불변 파일 바이트를 소유하며, 내용물의 메모리 부분 파일을 같은 읽기/키 수명에 연결했다. 엔트리마다 새 상태와 `mydoghasfleas` 키를 적용한다. 메모리 핸들 반납은 별도 OS fclose가 아니고, 실제 아카이브 디스크 FILE은 앞선 전체 읽기에서 이미 닫힌다. 기존 XOR 유틸리티/TAFF 헤더·조회 순서·부재 작업본 격리는 유지한다. 객체 덤프 Writer 생성도 같은 원문 세 필드0 몸체를 사용한다.
