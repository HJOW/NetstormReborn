# 공통 미션 안내 검사의 실제 로그인 수명

2026-10-22 작업 단위307. 현재 PC와 마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-22**다. 단위306 전체 회귀의 공통 미션/Guide/Early1 실패를 조사했다. 제품 계산이나 독립 원본 fixture는 바꾸지 않았다.

임시 관측에서 `TheWarBegins`·`MasterOfWhirligigs`는 Start 뒤 로컬 Player+50이0, 적 Player+50이32였다. 첫 공통 프레임에 실제 승패 몸체가 `Failed` 섹션을 열어 안내 잠금10을 계속 유지했다. 데모 세 개는 로컬도 AI로 등록되어32이므로 같은 실패가 없었다. 원인은 `.Load()`로 설치만 하고 실제 로그인/Ready/Player 패킷 절차를 생략한 독립 검사였다.

두 공통 미션 검사와 실제 Guide 수명 검사는 장치 경계만 공급한 뒤 기존 `LoadLocalConnection()`을 사용하도록 수정했다. 같은 처리기가 상태8→9→10→13→14와 Player 플래그를 기록하며 검사에서 플래그를 직접 쓰지 않는다. 실제 phase14·로컬 활성0x43·사제 생존을 확인한 뒤 원래10호출 안내·7호출 재개·F8 재표시·데모 종료 큐를 그대로 검증한다. 실제 Guide는 원래 단계1 초기화 시점에 로그인하고 진입 정지를 보유한 뒤 Start한다. 제품 생성자에 임의 활성값을 추가하지 않았다.

Early1의 다른 실패는 이미 열린 안내에서 F8/명시 First로 다시 표시할 때도 `closeTransient`가 자기 정지 전이어야 한다고 가정한 검사였다. 기존 `TellMissionStage`의 Tell→정리→Pause 호출은 그대로이며, 재표시에서는 이미 보유한 자기 정지를 유지한다. 정리 시점의 실제 정지 상태를 네 번 관측하여 A/B 최초 표시 `false,false`, 두 번 재표시 `true,true`를 함께 확인한다. 최종 정지 깊이는1을 유지한다.

Release 빌드는 **종료0**이고 실제 공통5미션1개·Guide1개·Early1 수명1개 모두 **실패check0**이다. 로그는 `extracted/cpp-mission-login-lifecycle-20261022-{build,common,guide,early1}.log`다. 원인 확인용 출력은 제거했다. 전체 CTest는 이 단위에서 반복하지 않았으며 최신 전체 결과는 단위306의 **2,214개·10개 검사 실패·24check 실패**로 유지한다. 세 집중 검사의 해결을 전체 통과로 계산하지 않는다.

새 디컴파일·보호 원본/CD·AGENTS/dotnetpj 변경이나 게임/창 실행은 없다. 15개 미션 자연 플레이와 Edit/custom Fort·언어별 시나리오 전체 목표는 계속 미완료다. 인수인계 후 **20261022-32 CP**로 로컬 커밋하며 원격 push하지 않는다.
