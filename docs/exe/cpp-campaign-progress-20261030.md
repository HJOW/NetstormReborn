# 캠페인 진행상황 저장과 초기 잠금 점검 — 단위578

캠페인의 완료/잠금 해제 상태는 **게임 자료 폴더의 `d/options.cfg`**에 설정과 함께 저장된다. 현재 저장소에서는 [originals/d/options.cfg](../../originals/d/options.cfg)다. cpppj도 `--run`에 지정한 자료 폴더의 같은 상대 경로를 사용한다. 배포판은 `<압축 해제 위치>/game/d/options.cfg`다. 실행파일을 다시 빌드해도 자료 폴더의 이 파일이 유지되면 진행상황이 유지된다. 자료 폴더가 다르면 각자의 설정을 읽는다.

현재 보호 원본 파일에는 Early Missions의 `DoneTutorial1..6=1`과 캠페인 **1-1~1-6, 2-1~2-3의 완료 표시9개**가 들어 있다. 이 상태에서는2-4 **Guard My Back**까지 선택 가능하다. 해당 값의 작성 시점이나 작성자는 이번 점검에서 판정하지 않았다. 원본 파일을 초기화하거나 수정하지 않았다.

## 원본 동작과 cpppj 경로

`options.cfg`는 `mQdsT` 서명과 `mydoghasfleas` 키의 단순 XOR 인코딩을 사용한다. 별도의 사용자 프로필/레지스트리에 캠페인 잠금을 쓰는 경로를 이번 대상에서 사용하지 않는다. 저장 경로의 원본 부모는00441d10이며,00440f30은 options 섹션과 현재 END 섹션을 같은 파일에 쓴다. cpppj의 `Client::SaveOptions`도 같은 자료 폴더의 `d/options.cfg`를 연다. 원본ANSI와 다른 유니코드 파일 열기는 기존 Windows10/11 호환 수정이다.

완료한 미션의 원본 본문에는 다음 효과가 들어 있다. 캠페인16개 모두 같은 완료 키 쓰기가 있음을 정적으로 확인했다.

```text
<$Config,Done{mission.fileName}=1>
```

예를 들어1-1은 `DoneTheWarBegins=1`을 쓴다. cpppj는 이 Config 효과를 실제 입력 큐로 전달하고 `Config::Set`의 changed 표시를 세운다. 현재 Client 루프는 changed 상태를 확인해 `SaveOptions`를 호출한다. 시작 시에도 같은 파일을 읽고 저장한다. 이번 점검은 실제 승리/포획/희생/특정 적 공격을 재현하지 않았다.

메뉴의 원본 데이터 `offical3.english`, `offical4.english`, `offical5.english`가 다음 조건을 직접 지정한다. 파일명은 원본의 `offical` 철자 그대로다.

| 항목 | 활성화 조건 |
| --- | --- |
| 1-1 The War Begins | 항상1 |
| 1-2 Master of Whirligigs | DoneTheWarBegins |
| 이후 각 미션 | 바로 앞 미션의 Done 키 |
| 2-1 The Noose | DoneDissolvedAlliance, 즉1-6 완료 |
| 3-1 Breaking Through | DoneSurrounded, 즉2-5 완료 |

완료 키가 없는 `setup.cfg` 기본값에서는1-1만 활성화된다. 다른 장의 목록은 열 수 있어도 내부 미션은 비활성 상태다. 일반 모드의 이 규칙을 검사했으며, 원문이 허용하는 userCheat/특수 모드의 강제 활성화 예외는 바꾸지 않았다.

## 배포와 후속 작업

`cpppj/package-cpppj.ps1`은 이미 `d/options.cfg`를 제외 목록에 넣고 ZIP 검사에서도 혼입을 거부한다. 따라서 현재 원본의 완료 표시를 새 사용자 배포판에 넣지 않는 기존 정책이 맞다. 이번에 새 ZIP을 만들거나 배포 동작을 변경하지 않았다. 새 설정의 실제 메뉴 결과도1-1만 해제되는 기본 동작과 일치하여 제품 수정은 필요하지 않았다.

사용자 요청의 저장 위치/포함 상태/초기 잠금 점검은 완료했다. 실제 승리 재현은 사용자 확인으로 남긴다. 기존 전체 목표와577 이후의 Chat0042da00 제출 해석·실제 명령/송신 연결, 남은 UI/Edit·시나리오·수명·호환성은 계속 진행 대상이다.
