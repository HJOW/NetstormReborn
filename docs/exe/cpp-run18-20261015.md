# 단위18: 실제 캠페인 초기 월드 설치 연결

## 결과와 범위

기준 커밋은 `637ad76`, 작업 PC는 `HJOW-Athlon`이다. 마지막 디컴파일 PC도 `HJOW-Athlon`(2026-10-15)이다. 보호 실행 파일과 AGENTS는 변경하지 않았다. 새 독립 Native 입력은 **0**이며 이전 모듈의 관찰 수를 다시 합산하지 않는다.

`RawCampaignWorldRuntime`은 기존 복원 몸체를 같은 Pool/TYPE/프레임/장부/해시/지도/Player 기록에 연결한다. 별도 모형 월드를 만들지 않는다.

| 단계 | 실제 소비자 |
| --- | --- |
| 로그인·Template header·현재 이름·Player152 | `RawCampaignWorldLoad` / `RawPlayerWorld` |
| Territory120BYTE·PlaceAll | `RawFortWorldLoad::ReadTerritory` / `RawIslandBuilder` |

Player 생성, 신전 Owner/PostPop, IslandRuntime과 FinishOwner는 같은9 기록을 읽고 쓴다. HP 처리기는 같은 Pool뿐 아니라 같은 장부인지도 확인한다. 잘못된 Template 배열은 최초 쓰기 전에 거부한다. 부분 설치 실패 뒤 재실행을 허용하지 않으며 실패를 로드 완료로 표시하지 않는다.

## 보호 자료를 사용한 설치 검사

`CampaignWorldRuntimeTests.cpp`는 보호 `d/thewarbegins.fort`, 타입·Run·SHP를 사용한다. 초기 게임 난수는 명시 입력 `0x12345678`, CRT는7이고 실제 SP 초기화도 같은 게임 난수를 소비한다. 이는 원본 게임의 실시간 시작 seed와 같다고 주장하는 값이 아니다.

- 저장 **172 객체**의 타입별 수가 설치 후 일치한다. 생성 지면/받침/Player를 이172에 합산하지 않는다.
- 사제2·신전2·간헐천14, Player152 하나와 공유 Player 첫 지역을 확인했다.
- 저장 워커 내용물은 살아 있는 워커 자산으로 생성하지 않는다. 실제 **Form6 두 개**의 타입WORD133 및 살아 있는 부모 연결을 확인했다.
- 생성 지형과 받침을 포함한 활성 자산은 **1875개**, Kernel은 **34개**, 명시 외부 요청은 **33개**였다.
- Territory 부족은 실제 Player 생성 뒤 보고하며 부분 설치 재실행을 거부한다. Template8 배열은 실제 생성 전에 거부한다.
- 집중3개 검사 실패0. 전체 CTest는 내부1105개·실패 체크0이며 실행 시간은174.90초다.

### 검사 경계

config/번역/카메라/생산 Gump/사제 Owner 통지/내용물 부모 통지/발사기 입력 큐/소리/전송은 외부 요청 관찰이다. 특히 사운드 토큰은 검사에서 TYPE 번호로 명시 매핑하고 실제 `impactSound` 파일명을 조회했다. 이 토큰을 PE의 런타임 포인터나 실제 재생으로 주장하지 않는다. theme/element 표의0 입력 또한 이 설치 검사의 명시 입력이다. 기존 `DudeSpawnSupport`가 초기74를 빈 타입으로 준비하는 부분은 이 미션에서 선택되지 않는다.

전투 프레임을 실행하지 않았으며 검사에서 실행하지 않은 사제 Damageable/Placement 및 전투 하위는 명시 거부 상태다. 따라서 이 결과는 원본 전체 초기 메모리의 독립 Native 전수 대조나 실제 게임 플레이 성공을 의미하지 않는다. GameWorld의 실제 미션 설치로 전환하고 Ready/login, 입력, 생산, 전투, 경제, 운반, AI/Guide, UI/음향, 승패와 Early Missions/1-1~1-2 완주를 연결해야 한다. 전체화면 DirectDraw 오류는 현재 목표에서 제외한다.

## 오류와 보존

직접 영향4파일 전체를 `cpppj/hist/run18-base`에 보존했다. 기존 fixture/보고서를 수정하지 않았다. 테스트 초기 컴파일에서 자산 삭제 callback 인자와 private ProcessForm 부착 접근을 교정했다. 내용물은 기존 `ContentFormHost::BindCreate`의 실제 정렬 부착을 사용한다. 다리 타입 전역/PlayerKnown 입력과 신전의 실제 청크 BYTE getter 연결을 교정했다. `std::span`의 잘못된 `at` 호출도 교정했다. 실패 당시 테스트 원문과 로그는 명시한 `run18-fail`, `run18-fail5`, `run18-run1..4` 보존본에 남았다.

현재 소스/의존 모듈/보존본/로그/빌드 바이너리의 전체 SHA와 편집 원문은 `cpppj/run18.json`에 기록한다. 이 보고서는 이전 단위의 SHA 기준을 덮지 않는다. 이전 최종 경로/참조/과거SHA 감사는 별도 미완료 작업이다.
