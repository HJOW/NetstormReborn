## 변경과 원문 보존

`UberGump::PollCameraPan`의 현재 전역 조회에서 호환 전체화면은 `Screen`의 논리 폭/높이, 창 모드는 이전과 같은 실제 client 크기를 공급한다. Windows10/11에서는 원본의 디스플레이 해상도 전환 대신 borderless DIB 확대를 사용하기 때문에 이 구분이 필요하다. 원본과 달라지는 호환성 처리와 이유를 한국어 코드 주석에 명시했다.

`RawCameraPan`의 관문·중심거리·FTOL/8·Shift 축 선택·팝업 효과 뒤 현재값 재조회와 실제 목표 요청 순서는 변경하지 않았다. 원문259행 fixture와 기존 검사도 그대로다. 속도 상수나 프레임 delta를 추가하지 않았다. 새 원문 관측·fixture·디컴파일 산출물 변경은 없다.

## 같은 새 배포본의 실제 여섯 실행

새617 ZIP을 별도 한글 경로에 풀고 캠페인1-1의 안내 버튼을 클릭했다. 각 화면비에서 같은 시점의 논리 Alt 포인터·가운데 포인터·F2를 공급해 창/전체화면을 순차 비교했다. 물리 키 누름을 재현한 것이 아니라 기존 `--ui-script`의 명시 검사 폴링이다.

| 논리 화면 | Alt 10회 가로 이동: 창/전체 | 가운데 10회 이동 `(X,Y)`: 창/전체 |
| --- | --- | --- |
| 1024×768 / 4:3 | 290 / 290px | (-50,-240) / (-50,-240)px |
| 1280×720 / 16:9 | 370 / 370px | (-50,-220) / (-50,-220)px |
| 1280×800 / 16:10 | 370 / 370px | (-50,-250) / (-50,-250)px |

가운데 입력의 X=-50은 실제 지도 중심과 화면 중심이 다른 원문 거리 계산의 결과다. 창/전체화면 양쪽에서 같은 전체 이동 벡터를 확인했으며 임의로0으로 맞추지 않았다.

실제 창 client는 각각 논리 크기와 같고 전체화면 client는1920×1080이다. 세 전체화면의 출력 범위는4:3 `(240,0)~(1680,1080)`,16:9 `(0,0)~(1920,1080)`,16:10 `(96,0)~(1824,1080)`이다. 요청 카운터는 각 이동 구간10회이며 해제 후 위치/목표가 유지된다. 이동 중 F2는 소비되고 해제 후 정상 반전·복귀했다.

여섯 실행 모두 같은 실제 미션/로컬owner·PlayerKnown·비정지 시각 증가·활성 창·종료0을 확인했다. 실제 창 전체RGB도 각 논리 프레임의 최종 확대 출력과 같고16:10 전체화면 캡처를 육안 확인했다. 이 출력 비교는 원본 게임 화면의 전체 픽셀 동일성 판정과 구별한다.
