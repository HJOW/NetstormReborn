# cpppj 공통 미션 프레임·안내 예약 게이트 복원

2026-10-15, 현재 PC와 마지막 정밀 디컴파일 PC는 **VM-W11-Codex**다. AGENTS와 양 LEFT를 확인했다. 기존 최신 정밀 `extracted/refined/originals/Netstorm.c`와 보호 10.78 PE의 실제 바이트를 사용했으며 새 디컴파일 전체 출력 변경·원본 파일 수정·원본/클론 게임·GUI 실행은 없다. DirectDraw 전체화면 오류는 범위 밖이다.

`RawMissionFrameGate`는 원본 공통 프레임의 순서와 안내 잠금/정지 소유권을 복원했다. `MissionFrameGateState`는 단계·임시 타이머를 한 번만 소유하므로 Tutorial1~6 판정기는 같은 참조를 읽어야 한다. 이번 모듈 자체를 실제 클라이언트의 미션 프로세스에 연결했다고 주장하지 않는다.

## 상태·시각·조회 계약

- `stage`는 전역 `005ca8e8`, `tutorialNumber`는 `005ca8e4`이며 캠페인 번호와 다르다. 후속 단계 증가의 `004c3409 mov al,[005ca8e8] → inc al → movsx ecx,al`을 그대로 보존한다. 127 다음은 -128이고 255 다음은0이다.
- `nextStageSeconds/delaySeconds/lockFrames`는 `+78 double/+80 float/+84 signed DWORD`다. 첫 기한0에서도 연속10번의 빈 다이얼로그 조회 뒤 안내를 요청한다. 미래 기한이라도 실제 정지 상태면 카운터를 판정한다. 다이얼로그가 있으면10으로 되돌리며, 후속 예약은 실행 중이고 잠금<1일 때만 가능하다.
- 원본 `004c3423 fld DWORD[esi+80] → 004c3429 fadd QWORD[0055b4d0] → fstp QWORD`를 사용한다. 디컴파일 C의 현재 게임 시각 float 축소를 적용하지 않는다. 16,777,216.25초 입력으로 그 차이를 독립 검사한다.
- 시작된 프레임은 `stageDirty=0`을 먼저 쓰고 승패 훅을 부른다. `tellAtSeconds`는0이 아니며 **경과보다 작을 때만** 실행한다. 경과와 같으면 실행하지 않는다. 데모 기한은 **현재 시각과 같아도** 실행한다.
- `scriptPaused/clearFrames`는 `+b8 DWORD/+c8 signed DWORD`다. 자기 정지 표식이 있고 잠금이 정확히0일 때만 안내창 없음→다이얼로그 없음→0x4000 자식 없음 순서로 조회한다. 세 조건이7번 연속 참이면 실제 Resume를 한 번 요청한 뒤 자기 표식과 카운터를0으로 쓴다. 다른 경우 카운터를0으로 쓰며, 잠금 중에는 기존 카운터를 보존한다.
- `PauseForDialog`는 다른 보유자로 이미 정지했어도 자기 표식이0이면 별도 깊이를 잡는다. 이미 자기 표식이 있더라도 실제 시계가 실행 중이면 다시 정지를 요청한다. 정지/재개 깊이의 실제 구현은 caller가 공급한다.
- `RunFrame(event)`는 전달받은 현재 사건을 튜토리얼 훅에 그대로 넘기며 그 DWORD 반환도 보존한다. `Advance()`의 bool은 caller 편의용 성공 여부이고 원본 함수의 반환값을 새로 해석한 것이 아니다. 각 훅 뒤에는 현재 공유 상태를 다시 읽어, Tell/승패/창 수명 효과가 바꾼 필드를 다음 분기에 반영한다.

## 독립 검증

`tools/decomp_missionframe_oracle.py`는 보호 PE를 읽기 전용으로 가상 메모리에 넣어 위 네 **실제 기계어 몸체만** 실행한다. 함수 바이트 수정은 없으며 미허용 함수/OS 진입·객체/단계/스택 밖 쓰기를 거부한다. 외부 승패/Tell/list/demo/Tutorial/UI/정지 깊이는 명시 입력/관찰 경계다.

새 관찰은 중복을 제거한 **328개**다: Frame265/Advance48/Pause9/Postpone6. 전부 정상 반환했고 반환 EIP·인자 정리 뒤 ESP·비휘발 EBX/ESI/EDI/EBP·x87 제어어 `027f`와 TOP0을 확인했다. 기한 포함/초과, 시작 전, 잠금 음수/0/1/2/10, 정지 소유권, 세 UI 조회의 단락 순서, signed 카운터 감김, char 감김,1~6/범위 밖 분배, 효과가 상태를 바꾼 뒤의 재조회/최종 쓰기를 포함한다. `--verify`는 원본/도구/fixture/실제 어셈블리/정밀 C의 SHA와 입력 계획·고유 수·정상 반환 수를 다시 확인하며 새 원본 관찰로 더하지 않는다.

`MissionFrameGateTests.cpp`는 같은328행의 **14필드 전체 비트·정지 깊이·외부 조회/효과 순서·반환값**을 C++와 직접 대조한다. 별도 한 검사는 필수 경계 누락 거부와 공유 상태 identity를 확인한다. 공용 CMake와 분리한 `extracted/missionframe/standalone`의 MSVC19.44 Release `/W4 /utf-8 /permissive-` 빌드는 경고/오류0, 새 검사 **2개·실패 체크0**이다. 루트의 NetstormCpp/netstorm_tests 통합 Release 빌드도 경고/오류0이며 새 게이트2개와 TutorialOne/TotalMade3개 집중 검사가 모두 실패0이다. 전체 CTest 결과는 상위 작업 기록을 따른다.

최초 C++ 대조의3실패는 관찰 경계에서 정지 깊이를 Python의 `-1`로 기록한 입력과 C++ DWORD의 `0xffffffff` 차이였다. 외부 깊이 observer를32비트로 교정한 뒤 동일328개를 재실행해 모두 일치했다. 이 교정은 원본 기계어·C++ 게이트 몸체를 바꾸지 않았으며 최초 오류 내용은 `extracted/missionframe/initial-comparison.txt`에 보존했다.

## 후속 연결과 제한

실제 Ready/login·미션 헤더와 시작 시각/started 설정·승패 사건·현재 Gump 등록/지연 삭제·F4/다리 제작 집계·수확/SP 저장소·상위 입력/프레임 호출 지점과 연결해야 한다. 초기 브리핑을 즉시 표시하고 닫자마자 재개하는 이전 adapter 흐름은 이 모듈만 추가해도 자동으로 바뀌지 않는다. 일반 비동기 Tell의 버튼 트리 수정과도 별도다.

이 모듈의 시험은 PATCH10.78에 한정한다. CD10.72 대응, 실제 Early Missions/캠페인1-1~1-2 진행/완주/그래픽·소리 동일성, 진행 저장과 승리 UI는 미완료다. 보호 PE SHA-256은 `a305414cfe0b94494bb32fef2b359e920e9daba225e0821b76aea1f9f8e7d236`이며 전체 근거 해시는 `cpppj/missionframe.json`에 있다.
