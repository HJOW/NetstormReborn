# 제단 우클릭 레벨 조회와 실제 메뉴·삭제

2026-10-28 단위518. 현재 PC와 마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-23**이다. 디컴파일 산출물은 수정하지 않았다.

## 결함과 수정

원래 `BreakingThrough`의 제단 본체를 우클릭하면 `객체 메뉴 파생 가상80 미연결`로 종료1이었다. 제단 가운데에 있는 적 사제의 메뉴가 열린 관측과 구별했다. 외곽 `cell:163,123`을 클릭한 실패가 실제 제단 경로의 재현이다.

`MakeObjectMenus`는 제단·다이스의 가상 `+80`을 외부 UI callback으로 남겨 두었지만 실제 Client는 그 callback을 제공하지 않았다. 메뉴 요약과 회수는 이미 같은 count 분배기를 공유했다. 두 경우를 Session의 기존 실제 몸체에 연결했다.

| 대상 | 보호 PE의 실제 VT/+80 | 연결한 기존 몸체 |
| --- | --- | --- |
| 제단 TYPE164 | `5076b8 / 44a480` | `RawAltarSacrifice::Count`: 현재 좌표의 typed 다이스 조회 → 유효하면 다이스 count, 없으면0 |
| 다이스 TYPE165 | `507950 / 4478f0` | `RawTempleRitual::Count`: 현재 프레임과 방향에 따른 레벨 조회 |

나머지81개 생성 VT는 기존 `RawSquidLevel::Get`을 유지한다. 별도 레벨 캐시나 상수, 메뉴 전용 소유자/HP/다이스는 만들지 않았다. 두 하위 몸체는 기존 독립 x86 fixture의 검사에 포함돼 있으며 이번에는 새 원문 실행·fixture 생성 없이 해당 회귀를 다시 실행했다.

## 현재 제품 검증

최종 Release 빌드는 경고/오류0, 실제 등록 **3345개**다. 현재 제품의 집중 검사는 **36고유/36관측·실패0**이다. 범위는 SquidRetype1, ObjectConversion2, GemReward2, ObjectMenu20, ObjectCommand3, TempleRitual2, AltarSacrifice1, EditorSaveGoMain2, EditorTestBattle3이다. 전체3345개 실행으로 확대하지 않는다.

같은 최종 제품으로 원래 맵의 다음 **4실행을 수락**했다.

| 모드 | 화면 크기 | 실제 확인 |
| --- | --- | --- |
| 캠페인 | 1280×720·1024×768 | 적 소유 제단 SID15017/TYPE164/owner2 → `Altar Level I` → About(TYPE164)·Player → Altar 도움말 → 바깥 클릭으로 반납, 활성1/비정지 |

편집 사례마다 원래 아카이브의 `\d\breakingthrough.fort` 3355BYTE/SHA `cff7def3cde57387e2ba1dbff582a86a3e2f3db539fa3b0db0ec81f21313c098`를 담은 새 실행 사본을 사용했다. 저장 결과는 별도 `data-editor`에 생긴다. 앞선 실행의 편집 저장 경로를 재사용한 관측은 최종 수락에서 제외했다. 원본·입력 사본·설정은 보존됐다. 실제 포획/희생이나 자연 완주는 실행하지 않았다.

모든 중간 관측을 포함하면 **11게임 실행 중7종료0/4종료1**이다. 덱에 직접 없는 TYPE164를 요청한 도구 실패, 다단 브리핑을 건너뛴 도구 실패, 사제를 고른 중간 성공, 수정 전 제단의 제품 실패와 이전 편집 입력 재사용 실패를 최종4개와 구별했다. 원시는 `extracted/cpp-building-menus-518/`다. 회귀 도구는 [cpp_altar_menu_smoke.py](../../tools/cpp_altar_menu_smoke.py), 해시/명령/보호 결과는 [보고서](../../cpppj/altar-menu-runtime-20261028.json)를 본다.

## 단위517 재빌드 마감과 빌드 충돌 기록

진행 중이던 exec72073/wrapper14416의 전체 CMake 재빌드는 정상 종료0했다. 그 결과의 검사 프로그램은 등록3345/SHA `161b3132…`이며 신규3개와 GemReward2개를 실제 통과했다. 이는 앞 단위의 별도 링크 probe4개와 구별한다.

그 재빌드의 검사 링크가 끝나기 전에 제단 수정 게임 빌드를 별도로 실행한 것은 작업 순서 오류였다. 정적 라이브러리 접근 충돌로 해당 시도는 LNK1104/종료1이었다. 두 프로세스의 종료를 확인한 후 **순차 전체 CMake 증분 빌드**를 실행해 경고/오류0으로 게임·검사·보조 제품을 다시 링크했다. 이후에 위 최종 제품 검사와 실제4사례를 실행했다. 실패 로그를 삭제하지 않았다. 더 이상 진행 중인 재빌드는 없다.

## 남은 범위

자기 소유 제단의 회수/소유자 변경, 다른 레벨·포획 상태, 전체 일반 건물형의 소유자/상태별 메뉴·효과, 원본 전체 선택기004d5840은 남는다. `CHEAT Set Owner`는 이번에 표시만 확인했고 실제 대화/변경은 미검증이다. 제단 메뉴 수정만으로 해당 전체 범위를 완료 처리하지 않는다.

Meltdown은 원문 입력41c290 → 생성자40b1a0의 76h/6BYTE 요청 → 수신4207a0 경로를 정적으로 찾았다. 현재 제품의 요청/수신 연결은 아직 미복원이다. 특히 수신은4203a0/4205f0 등의 별도 폭발 경로를 사용하므로 회수/일반 삭제로 대신하지 않는다. Detonate와 Dig Up의 실제 special 클릭, 비석 전환 뒤 frame2 후속 표시도 계속 잔여다.

훨리기그·맨오워·더스트 데빌은 요청대로 정적 분석/코드 작업만 허용하며 이 세 타입을 위한 생산·생성·우클릭 재현을 하지 않았다. 연녹색 직사각형 분석 보류도 유지한다. 전체화면·Windows10/11 전체 호환성·전체 플레이 동일성의 완료 증거는 아니다.
