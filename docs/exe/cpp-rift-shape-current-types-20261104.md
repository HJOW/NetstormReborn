단위844 기록이다. 현재 호스트와 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-11-03**으로 일치한다. 디컴파일 산출물은 변경하지 않았다. 직전 C++ 커밋은 `bd36f6e6 / 20261104-27 CP`다. 제품844/11.01이며 집중97개를 최종 통과했다. 전체 목표는 미완료다.

10.78 `00419850`을 실제 `SquidDisplay::FrameSize`에 연결했다. 처음 선택한 TYPE와 저장된 frame/abstract를 유지하며, `0x440000` 프레임 마스크가 있으면 count를 두 배로 만든 뒤 낮은 DWORD를 signed로 비교한다. 기존 int64 계산은 감김 입력에서 원문과 달랐다. 프레임 범위가 잘못되면 선택 TYPE 번호와 저장된 frame/abstract로 기존 `00436d40` 상세 writer를 호출하고, 그 뒤 `frameCheck( abstract, frame, false ) / ..\o\rifttype.h:0xe1`을 진단한다. 이 경로는 checking과 무관하다.

범위가 정상이지만 SHP가 null이거나 TYPE 첫 DWORD가 두 CRT 해제/미초기화 표식이면 상세 없이 e1을 진단한다. 진단이 정상 반환하면 처음 선택한 TYPE의 현재 SHP에서 저장된 frame을 읽는다. 상세/진단 중 raw TYPE나 raw frame이 바뀌어도 다른 TYPE나 정상 frame으로 교체하지 않는다. 범위 진단이 선택된 뒤 callback이 count를 고쳐도 e1은 실행한다. 반대로 해제 표식만 남아 있어도 진단 뒤 같은 SHP의 물리 접근을 진행한다. 실제 null/배열 밖 접근은 그 소비 지점의 명시적 호스트 오류로 남긴다.

해시 단계의 원문 caller `004ace40`은 abstract 인자로0을 넘긴다. raw의 abstract 비트가 켜져 있어도 이 고정 인자를 상세에 전달한다. 기존 Client 상세 소유자와 Storage 진단을 사용하며, 앞서 Pop이 수행한 좌표·점유 변경을 되돌리지 않는다. callback이 SHP 치수를 바꾸면 그 현재 치수로 해시 단계를 계산한다. CD10.72의 기존 별도 프레임 크기 경계는 유지했다.

후처리·Graph·이웃 탐색은 생성 때 TYPE를 복사하던 기존 독립 계약을 갖고 있었다. 실제 World에는 주소가 고정된 같은 현재 TYPE 배열을 명시 대여한다. `SquidPostPop`의 비용/등록 플래그, Graph의 검증/실제 실행/임시 이웃 탐색, World의 이웃 발자국/표면 플래그와 finder가 같은 배열을 읽는다. 독립 fixture/명시 snapshot은 계속 자체 사본을 소유한다. 잘못된 판본/길이의 대여는 기존 대여를 바꾸기 전에 거부하며, 빈 span으로 소유 사본으로 복귀할 수 있다. 배열/필드 참조는 실행기보다 오래 살아야 하며 재할당하지 않는다.
