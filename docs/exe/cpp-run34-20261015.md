# 단위34: 실제 레인 신전 Draw와 본체 합성

2026-10-15, **VM-W11-Codex**. 기준 `eeb751d`에서 사용자 제보의 레인 신전 기본 그림 누락을 수정했다. AGENTS와 양 LEFT를 재독했고 작업 트리는 깨끗했다. 이전 점검은 원인·원본 근거를 확인하고 기록한 진척이다. 현재/마지막 정밀 디컴파일 PC는 **VM-W11-Codex, 2026-10-15**다.

## 원본 몸체와 실제 연결

- 새 정밀 `rain-draw` export는 PATCH5/CD4함수다. PATCH의 `004dcd00`, CD의 `0044fe00`은 기본0번 → 현재 프레임을 그린다. WORD+0c가 비영이고 현재 프레임이 C구간 개수보다 작으면 현재 방향의 첫 프레임에서 상승음을 호출하고 C구간 첫 번호+현재 프레임을 추가로 그린다. CD의 프레임 BYTE와 PATCH DWORD를 구별한다.
- `RawRainVortexDraw`는 이 호출 순서와 콜백 뒤 raw 재조회를 복원한다. `RawCampaignSession::DrawRainTemple`은 같은 풀/프레임 표를 읽고 실제 SoundList와 SoundProcessHooks의 `templeAscend.wav` 재생 경계를 사용한다.
- 실제 `GameWorld::Sprites()`의 살아 있는 일반 색 레인 신전은 이 가상 Draw를 실행한다. Renderer의 한 `RenderSprite`에 기본 그림과 `followingFrames`를 보관하여 CRT 정렬이 신전 내부 그리기 순서를 뒤집지 않게 한다. Renderer의 화면 범위/부분 갱신/SceneImage와 실제 출력은 모두 같은 프레임 순서를 사용한다.
- 현재 물결의 압축 픽셀 영역으로만 신전의 선택 범위를 계산하던 부분을 원본 Squid 표시 헤더의 전체 범위로 연결했다. 실제1-1의 돌 테두리 쪽 클릭이 SID15002를 고르는 것을 기존 세션 검사에 추가했다. 픽셀 적중/다른 객체와의 선택 우선순위 전체가 원본과 같다는 판정은 아니다.

## Native와 C++ 검사

`tools/decomp_rain_draw.py`는 실제 PE의 Draw·TYPE·방향 조회를 실행한다. **그림 제출 helper와 음향 제출 함수는 인자/순서 관찰로 대체한다.** 픽셀 출력/장치 실행 또는 원본 프로그램 전체 실행을 뜻하지 않는다. 불연속 명령 허용 범위를 현재 Ghidra 함수표로 제한하고 실행 중 스택 밖 쓰기를 거부한다.

- 판본당29프레임×WORD상태0/1/2/65535 = **116개**, 두 판본 합계 **232고유 입력**이다. 정상 반환/EIP/ESP, EBX·ESI·EDI·EBP 보존과 raw 슬롯 불변을 확인했다. 출력 경계의 x/y/shape/this와 음향의 나머지0 인자를 검사한다.
- 새 C++ 원본 순서 대조2개와 Renderer 전체 픽셀/부분 갱신/이동 뒤 지우기/SceneImage/후속 그림만 보이는 클립2개, 합계 **4개 통과**다. 기존 Renderer 필터11개도 실패0이며 이 중2개는 위 새 검사와 중복된다.
- 기존 실제 CampaignSession **5개 통과**다. 사제 이동과 교전의 최초 피해173/HP1 178/종료898프레임을 유지한다. 새 물결/기본 그림 제출과 테두리 선택 검사는 기존1-1 검사 안에 추가했다.
- 전체 CTest 결과는 아래 최종 검사 절에 기록한다.

최초 빌드는 새 검사에서 기존 raw 쓰기 helper 이름을 잘못 사용해 컴파일 오류3개가 났다. 검사 입력 쓰기를 명시한 뒤 빌드했다. 첫 집중 실행에서는 후속 그림 전용 클립의 선택 영역에 불투명 픽셀이 없어서 비영 픽셀 단언1개가 실패했다. 독립 기대 합성과 실제 출력은 그때도 같았다. 실제 기본 그림의 불투명 픽셀(-48,-98)을 화면(0,0)에 놓도록 **검사 입력**을 교정했으며 Renderer 동작/Native 기대값은 바꾸지 않았다. 첫 검사 원문은 `extracted/run34-first/RainDrawTests.cpp`, 로그는 `run34-build.log`, `run34-rain-tests.log`에 보존한다.

첫 CD export 목록에는 추정한 TYPE 조회 주소00444200이 들어갔으나 실제 CD 래퍼004abf50은 TYPE를 직접 계산한다. 해당 주소는 다른 함수의 말미이므로 목록에서 제거하고 CD4개를 재export했다. 잘못된 주소를 원본 관찰에서 실행하지 않았다. 최초 목록/출력은 `extracted/rain-draw-draft/`에 보존한다.

## 실제 창의 독립 픽셀 대조

`tools/check_rain_scene.py`는 실제1-1을 실행하고 같은 루프의 raw 보고와 BMP를 기록한다. Python의 기존 독립 SHP 판독기로 기본0과 현재 물결을 합성하고 불투명 픽셀을 실제 화면 RGB와 대조한다. 다른 지형/UI/그림자 전체 화면의 픽셀 일치를 주장하지 않는다.

- 수정 전 단위33 캡처는 신전 영역 **9,809픽셀 중8,130개 불일치**를 검출했다. 물결에 가리지 않는 기본 그림 픽셀은8,136개였다. 자료: `extracted/run34-before-pixels.json`.
- 수정 후 실제 창의 프레임3/5/7/9를 각각 대조했다. **각9,809픽셀, 총39,236픽셀 불일치0**이다. 각 시점에서 기본 그림만 차지한 픽셀도7,714개 이상 포함한다. 캡처에서 돌 테두리·장식과 물결 합성을 직접 확인했다.
- 자료: `extracted/run34-rain-scene/{states.tsv,pixels.json,rain12.bmp,rain22.bmp,rain32.bmp,rain42.bmp}`. 실행 종료0·originals 전체 파일명/해시 불변·설정 복구다. 무음 검사이며 상승 상태/실제 음향 장치의 GUI 관찰은 아니다.
