## 3. 추첨 (FUN_004257c0)

```text
r = 난수 % 287
누적 = 0
표 순서로: 누적 += 가중치; r <= 누적 이면 그 모양
```

비교가 "이하"라서 **r = 0이면 가중치 0인 0번(한 칸)** 이 뽑힌다. 가중치 0인 11·12·24번은 누적값이 앞 모양과 같아 사실상 뽑히지 않는다(11·12번은 앞의 10번, 24번은 앞의 23번이 먼저 걸린다). 난수는 `FUN_004558c0(10000)` 또는 `FUN_004558f0(0, 10000)`이다.

게임 전역 난수(`DAT_00532710`): `상태 = (상태 == 0 ? 0x0BAD0BAD : 상태) × 0x10003 + 3`, 결과 `(상태 >> 16) % 상한`. 지형 생성의 `004bca20`과 같은 식이다.

## 4. 회전

`FUN_00425c20`의 회전 번호 0~3은 `param_4 / 2`다. 회전 1은 **연결을 시계 방향으로 90°** 돌린다. 방향 글자 표 VA 0x531590(회전 번호 × 16 + 글자, 32비트 글자 코드):

| 회전 | A B C D E F G H I J K L M N O P → |
|---:|---|
| 0 | A B C D E F G H I J K L M N O P |
| 1 | A C D E B G H I F K J M N O L P |
| 2 | A D E B C H I F G J K N O L M P |
| 3 | A E B C D I F G H K J O L M N P |

칸 위치는 시작 칸 표(0x531570 `{0,0,1,1}`·0x531580 `{0,1,1,0}`)와 이동 표(0x531550 `{1,0,−1,0}`·0x531560 `{0,−1,0,1}`)로 순회하며, 결과는 다음 식과 같다(폭 w, 높이 h, 원래 칸 (x, y)).

| 회전 | 회전 뒤 칸 | 회전 뒤 크기 |
|---:|---|---|
| 0 | (x, y) | w × h |
| 1 | (h − 1 − y, x) | h × w |
| 2 | (w − 1 − x, h − 1 − y) | w × h |
| 3 | (y, w − 1 − x) | h × w |

회전 뒤 칸의 월드 위치는 조각 원점(`param_5`, `param_6`) + (열, 행)이다.

### 원본 실행으로 확인한 조작 (2026-09-29)

- **조각을 든 채 오른쪽 클릭 → 90° 회전.** 기본은 **시계 방향**(회전 번호 +1)이다.
- **C 키는 조각을 돌리지 않고 "반대 회전"(옵션 Counterclockwise Piece Rotation, 설정 `rotmode`)을 켜고 끈다.** 켜진 동안 오른쪽 클릭은 반시계 방향(−1)이다.
  - `help.english`: "To rotate a bridge 90 degrees simply right-click with the mouse and to activate reverse bridge rotation, press the C key."
  - 튜토리얼 `tutorial1.english`의 "Rotating Bridges"도 오른쪽 클릭 회전을 안내한다.
- 확인 경과: 원본에서 든 조각은 5번(`J1`/`B1 K1`/`J1`/`J1`)이었다.
  - C를 켠 뒤 오른쪽 클릭 → 가로 4칸 위로 가지(회전 3)
  - C를 끈 뒤 오른쪽 클릭 → 원래 모양(회전 0)
  - 한 번 더 → 가로 4칸 아래로 가지(회전 1)
  - 모두 위 표의 회전 식과 같다.
- **들고 있는 조각의 위치:** 조각의 **왼쪽 위 칸이 커서로만 정해지고**, 조각 크기·회전과 관계없다(2×4 ↔ 4×2 회전 전후와 커서 이동에서 왼쪽 위 기준점이 같았다).
  - 칸 (cx, cy)의 기준점(스프라이트 오른쪽 아래 끝)을 월드 픽셀 (16·cx, 11·cy)로 두면, 커서가 x 기준점 −7 ~ +8, y 기준점 ~ +10 범위에 있을 때 그 칸이 왼쪽 위가 된다.
  - 1픽셀 단위 측정: x 793~808 → 기준점 800, 792 → 784, 809 → 816. y 151~161 → 기준점 151, 150 → 140, 162 → 162.
  - 클론: `BridgeCursor.TopLeftCell` = (⌊(x + 7) / 16⌋, ⌊y / 11⌋).
- 붙일 수 없는 곳에서는 조각 전체가 **순수 빨강**으로 칠해진다. 구름 위와 초목이 늘어진 섬 왼쪽 가장자리 옆에서 확인했다.
- 튜토리얼 "Bridges" 안내: 다리는 **섬 가장자리** 또는 **다른 다리의 열린 끝**에 붙여야 하고, 붙지 않았거나 아래에 무언가가 막고 있으면 전체가 빨강이다. **초목이 가장자리 밖으로 늘어진 곳에는 붙일 수 없다.** 배치 판정 분석(8절)의 기준으로 쓴다.
- 원본 사이드바는 칸의 조각을 **절반 크기**(칸당 약 8×5.5px)로 그린다.

## 6. 생산 창 다리 칸 채우기 (플레이어)

`Combatgump.cpp`가 매 프레임 다음 순서로 처리한다.

1. 생산 칸의 다리 조각 수(`iVar13`)와 그중 한 칸 조각 수(`iVar9`)를 센다.
2. **템플이 사라진 순간**(직전 +0xdc ≠ 0, 지금 플레이어 +0x7c = 0, 편집기 아님) 칸의 다리 조각을 모두 없앤다. 사용자 확인 규칙 "템플이 파괴되면 다리 조각이 덱에서 사라진다"와 일치한다([workshop-deck.md](../gameplay/workshop-deck.md)).
3. 다음 조건이 모두 참이면 새 조각을 검토한다.
   - 플레이어 +0xb0 = 0 (의미 미확인)
   - 편집기이거나 템플이 있다
   - 간격 시각이 지났다(`generatortimer` 콘솔 명령으로 끄면 매 프레임)
4. 조건이 참이면 **다음 시각 = 지금 + 1초**로 예약하고(`_DAT_00531b2c = 1`), 칸 수가 상한(전투 옵션 Bridge Slots 2/4/6) 미만이면 새 조각을 만든다.
   - 칸이 가득 차 있어도 시각은 다시 예약하므로, 칸이 비면 최대 1초 뒤에 채워진다.
5. 새 조각의 모양은 `FUN_004257c0(FUN_004558c0(10000))`로 고른다.

스캔(`FUN_00422bc0`)은 10초에 한 번 오브젝트 번호 15000~23001 을 나누어 훑으며 **다리 칸마다 이 처리를 한 번** 한다(번호 순). **2026-10-07 정정(세 PE의 기계어 대조, [cpp-bridgedecay-reconstruction.md](cpp-bridgedecay-reconstruction.md) 2절):** 프레임당 처리할 번호 수는 반올림이 아니라 **절삭** `trunc(프레임 시간(게임 시계) ÷ 10 × 8001)`이다(14ms 프레임에서 11개). 주기의 남은 시간이 0 이하가 된 프레임에는 **남은 번호를 한꺼번에** 처리하고 커서를 되돌리며, 다음 주기의 끝을 그 프레임의 시각 + 10초로 잡는다. 그래서 한 주기는 10초를 넘긴 첫 프레임까지이고(14ms 프레임에서 10.010초), 칸마다 스캔 시각이 번호에 따라 0~10초 어긋난다(2026-10-09 클론도 공유 SID 구간을 고정 24Hz 틱으로 나눠 처리). 칸 C 에 대해:

1. **그래프 검사**: C 가 속한 표면 연결 그래프의 `numSurface`(`Graph.cpp` 기록 `DAT_00562c18 + 그래프 × 6`의 첫 short, 로그 문자열 "graph index / numSurface / inUse")가 **5 미만**이면 C 를 곧바로 제거한다. `FUN_00462f10`은 아래 이웃 규칙으로 표면 객체를 범람 채우며 **객체마다 1 증가**시킨다. 여러 칸짜리 섬 발자국을 모든 칸으로 세는 설명은 2026-10-06 [Graph의 실제 기계어 대조](cpp-graph-reconstruction.md)로 정정했다. **다리 객체만 4개 이하인 분리 조각은 다음 스캔에서 무너진다.**
2. 프레임이 **단단함**(플래그 0x40)이면 끝.
3. **이웃**(`FUN_004b2660`)이 하나도 없으면 수명을 1 줄이고(`FUN_00421c30(1)`) 끝.
4. **구동자 검사**(`FUN_004217f0`): C 에 "열린 쪽"이 없으면 끝. 열린 쪽 = C 의 연결 글자에 있는 북·동·남·서 방향 중 그쪽 칸의 오브젝트가 이웃 목록에 없는 것(`FUN_00421770`). 글자별 조건: **A·P 는 늘 아님, B~E(세 갈래)는 열린 쪽 2개 이상, F~K(모퉁이·판자)는 1개 이상, L~O(끝 칸)는 늘 참**. 즉 양쪽이 이어진 판자는 수명이 줄지 않고, 섬·다리 **끝에 있는 칸만** 구동자가 된다.
5. **방문 목록 만들기**(`FUN_004218b0`): 목록을 [C]로 시작해 깊이 0 에서 재귀한다(목록 용량 100 — 정적 초기화 `0x4fc640`이 `push 0x64`로 생성. 이웃 목록은 10).

   - n 이 **접합 칸**(글자 A~I, 섬 아님)이면: 깊이 0 이고 n 의 이웃이 3개 미만이면 `DAT_005453a0`(짧은 접합)을 켜고, n 에서 깊이 + 1 로 재귀한다.

6. **수명 맞추기**: 목록 칸들의 **0 이 아닌 수명의 최소값**을 구해(없으면 7, 7 초과는 7) 1 을 뺀 값으로 목록의 모든 칸을 맞춘다(`FUN_00421c30(현재 − 목표)`, 목록의 단단한 접합 칸도 수명은 바뀌고 프레임은 그대로다). 결과 0 이면 그 칸을 제거한다. **금은 이전 수명이 5 이상이고 새 수명이 5 미만일 때만** 간다(`bridgeCrack.wav`는 목표 < 5 ≤ 최소값일 때). 수명 0 이던 새 칸이 4 로 바로 맞춰지면 금이 가지 않는다. 새 수명 ≤ 5 이면 칸 위 이동체가 떨어지는지 검사한다(`FUN_004202f0`~`FUN_00426120`, 미구현).

### 8.3 원본 관찰과의 차이 (남은 확인)

- **칸 단위 처리로 바꾼 결과 (2026-09-30)**
  - 이전 구현(열린 끝이 하나라도 있는 **연결망 전체**가 함께 줄어듦)은 원본 맵에 저장된 다리(336개 맵, 90,290칸)의 **57%를 5분 안에 없앴다**(단단한 칸 제외). 원본 칸 단위 처리로 옮긴 뒤 같은 조건에서 **3.2%**(2,927칸)만 사라진다. 사라지는 칸은 대부분 섬에서 떨어진 5~6칸짜리 접합 무리(끝 칸 포함)와 그 끝 판자로, 원본 규칙대로라면 실제로 무너질 조각이다. 회귀 테스트 `OriginalMaps_StoredBridgesMostlySurviveFiveMinutes`.
  - 관찰 "두 칸짜리는 **끝 칸이 먼저** 사라진다"(1.5절)와 "서쪽 칸은 동쪽 칸을 이어 붙이면 멈췄다가 동쪽 칸이 사라진 뒤 다시 줄어든다"는 새 모델이 설명한다: 양쪽이 이어진 안쪽 칸은 구동자가 아니라 수명이 그대로이고, 끝 칸이 사라진 다음 스캔부터 안쪽 칸이 끝 칸이 되어 자기 수명대로 다시 줄어든다(`Decay_PlankChainCollapsesFromTheTip`). 서쪽 칸이 끝 칸이 사라진 뒤 14~29초 만에 사라진 것은 멈추기 전 수명이 이미 2~3 이었다고 보면 ±1 스캔 안에서 맞는다.
- **T자 조각 재측정 (2026-09-30, 사용자 직접 조작 영상 → 모델과 일치)**
  - 측정: 놓은 뒤 줄기 끝 칸이 **+36.9초에 금 → +77.1초에 낙하**(금 간 기간 40.2초). 모델은 "첫 스캔에서 수명 7 → 스캔마다 −1, 금은 4가 될 때(4번째 스캔, 30~40초), 0에서 제거(8번째 스캔, 70~80초)"이고 금 간 기간은 정확히 스캔 4번(40초)이다.
  - **두 측정에서 같은 스캔 위상이 나온다:** 금 시각 − 30초 = 6.9초, 낙하 시각 − 70초 = 7.1초(프레임 간격 ±0.1초). 즉 스캔 주기 10초, 금이 4번째·제거가 8번째 스캔이라는 수명 순서가 이 칸에서는 0.2초 안에서 맞는다. (캡처 시각은 OS 벽시계이고 게임 시계와 미세하게 다를 수 있다.)
  - **어느 칸이 줄었는가:** 줄기 **끝 칸만** 금이 가고 떨어졌다. 가로 막대 동쪽 끝은 97초 동안 그대로였다. 8.1의 방문 목록 규칙을 손으로 따라가면 같은 결과다 — 줄기 끝 칸의 이웃(줄기 판자)은 깊이 0 경계라 붕괴 진행이 켜지고, 막대 동쪽 끝에서 출발하면 접합 칸(이웃 3개)을 지나 만나는 판자가 모두 이웃 2개라 붕괴 진행이 켜지지 않는다. **클론 시뮬레이션으로 이 T자 조각을 돌려 본 것은 아니다**(정확한 조각 모양을 칸 단위로 확정하지 않았다). 같은 구조의 클론 테스트 `Decay_JunctionClusterDecaysTogetherButAttachedPlankWaits`는 접합 칸 무리가 함께 줄어드는 다른 모양을 검사한다.

### 8.4 초목 가장자리 판별 (2026-09-30 exe 확인 + 구현)

- 섬 가장자리의 초목은 지면 생성 뒤 `Islandbuilder.cpp` `0040e560`이 영역 청크당 20개를 목표로 놓는 **`edgeFarm`** 오브젝트다(이전 문서의 "흰 가장자리 장식"과 같은 것). `edgefarm.type`: `typeflags edgefarm matchframe dropBlocking walkBlocking mayDropOnRim`.
