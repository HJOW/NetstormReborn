# cpppj 단위22: 실제 썬 디스크 발사기 Fire와 썬 디스크 첫 비행

## 기준과 원본 자료

기준 커밋은 `55c6f9e`(단위21)다. 작업 전 AGENTS와 양 LEFT를 다시 읽었다. 현재 및 마지막 정밀 디컴파일 PC는 **HJOW-Athlon, 2026-10-15**다. 두 보호 PE/AGENTS/dotnetpj는 수정하지 않았다. 게임이나 GUI는 실행하지 않았고, 격리 x86 분석과 콘솔 빌드/검사를 수행했다.

직접 영향 기존6파일의 전체 원문은 `cpppj/hist/run22-base/`와 `capture.json`에 보존했다. 새 함수 export는 `extracted/projectile-geom/`, `projectile-help/`, `projectile-disc/`에 판본별 원문/범위를 기록한다. PATCH13/CD11의 고유 export는 준비 자료를 포함하며, 전부를 독립 실행했다고 합산하지 않는다. 이전 전체 디컴파일 및 SP/Archer/Missile/공통 setter의 기존 입력은 재합산하지 않는다.

## 연결한 실제 몸체

- `RawCampaignArcherBindings`는 기존 실제 `RawArcherAnimation`/`RawMissile`을 같은 RawSurfaceWorld/Core/Pool/Host에 조립한다. 공유 난수, 현재 게임 시각/경과, 실제 생성/소유자/Unpop/Pop, 완료 GunNotify와 Host Kill을 연결한다. 다른 총의 미공급 효과는 선택 시 오류로 남긴다.
- 보호 TYPE71은 `orientations=0`, 클러스터35다. 실제 Gun의 단계2가 방향0인 썬 디스크 발사기 회전을 생략하며 단계5가 실제 Fire를 선택한다. 회전을 인위적으로 실행하지 않는다.
- `RawProjectileGeometry`는 가상 포구 PATCH0046a780/CD00437390과 그 하위 SHP/BoardCoord 계산을 복원한다. 기본 및 현재 SHP 추가 헤더의 마지막 signed WORD 두 개를 각각 더하고, 현재 픽셀 배율로 나눈 뒤 위치에 더한다. 표시 hotspot을 다시 빼거나 abstract 레이어를 더하지 않는다.
- 표적 ctor의 치수는 TYPE footX/footY다. 충돌 상자는 위치에서 full footX와 footY+heightExtension을 빼고 원본 Clamp/min/max helper를 적용한다. NaN/정수 overflow 등 검증 밖 입력은 이번 동일성 범위에 포함하지 않는다.
- 첫 실제 생성 후 선택된 썬 디스크83의 Regular event0가 미연결이었다. 그 실제 Handle PATCH00469540/CD00437290은 글자별 프레임 진행과 다르게 `stride=clusters/directions`, `((current+1)%stride-current%stride)+current`를 지정하고 payload를 반환한다. 새 `RawDiscRegular`가 실제 가상표50b570/CD501440으로 분배하며 같은 Core.frame을 사용한다.

## 독립 원본 비교

|새 고유 입력|PATCH|CD10.72|합계|관찰 경계|
|---|---:|---:|---:|---|
|포구/치수/충돌 상자|120|120|240|가상78 기본프레임1만 외부 입력. 실제 SHP lookup/좌표/치수/상자 실행|
|썬 디스크 Handle|96|96|192|실제 Handle/TYPE getter 실행. 공통 setter는 요청 관찰|
|합계|216|216|432|정상반환432/assert0, x87=027f|

포구는 위치4×현재프레임4×extra2×배율3의96입력/판본이다. 상자21입력은 소수 양수/경계/invalid 좌표와 치수/높이3가지, 치수3입력은 확장 플래그0이다. C++ 두 검사는 좌표의 binary32 전체 DWORD를 허용오차 없이 비교한다.

디스크는 현재frame4×클러스터3×방향2×event/count쌍2×payload2의96입력/판본이다. C++은 실제 요청 nextFrame/flags, 현재 raw frame 폭 및 반환 payload 전체 비트를 비교한다. 공통 setter의 외부 SHP 크기1×1/표시 요청은 명시 검사 경계다. 실제 캠페인 검사에서는 보호 SHP와 실제 표시/공간 지정기를 사용한다.

새 결과는 `projectile-geom.json`, `disc-regular.json`과 두 신규 fixture에 고정한다. `run22.json`은 기존 전체 소스/fixture, 신규 전체 원문, 직접 전후 diff, 원문 보존본, 새 export, 모든 실행 로그/바이너리의 SHA를 참조한다. 기존 단위21 보고서를 새 성공으로 덮어쓰지 않는다.

stage 검사에서 원문 보존본/새 소스/fixture/export/로그84파일은 전체 Git blob 바이트와 같다. 기존 공통 LEFT만 Windows 작업파일CRLF→GitLF 정규화가 있으므로 두 SHA를 `gitTextNormalization`에 따로 기록한다. 이를 전체바이트 동일 자료로 주장하지 않는다.

## 실제 캠페인 입력과 범위

보호 1-1 저장 객체를 실제 설치한다. 내 사제158/SID15000은94/108, 적 썬 디스크 발사기는132~152/116~138 구역에 있다. 검사는 실제 저장 사제를 실제 World.Unpop/Pop으로130/114에 재배치하는 **명시 입력**이다. 접근 경로/플레이어 마우스 조작의 복원 완료를 의미하지 않는다.

선택 프로세스만 실행하지 않고 현재 전체 Kernel을 실행한다. 같은 FrameTime을 AssetBindings와 ArcherBindings에 먼저 공급한다. 실제 finder/Gun→Fire35→Missile28/썬 디스크83 생성→같은 표시 부모 SID67의 첫 위치 변경을 확인했다. 표적/발사 TYPE/소유자/실제 Host/PID를 현재 raw 슬롯에서 확인한다. 첫 이동에서 종료하므로 충돌·피해·사망·발사 완료 반복 성공으로 주장하지 않는다.

배리어 코너의 외부 검사 입력은 현재 live fencemark90가 없음을 전수 확인한 뒤 원본 invalid corner를 제공한다. 전체 교차 corner helper 복원은 아니다. 실제 음향/전송도 TYPE 이름/토큰을 관찰하는 외부 경계다. 원본 함수보다 팬게임 근거를 우선하지 않는다.

## 실패 보존과 교정

- 첫 토큰 size_t→DWORD 경고의 전체 Scene 원문/로그를 `run22-warn1`에 보존하고 명시 TYPE 폭으로 교정했다.
- 처음 사제를Dude70으로 잘못 고른 위치 입력은 실제 현재 priest158 전역으로 교정했다. `positions.log`는 빌드 중 옛 실행 파일의 필터 미등록 결과여서 현재 구현 검증으로 세지 않는다. `positions2.log`는 잘못된70 입력 실패, `positions3.log`는158 위치 검사 성공이다. 이 초기 위치 입력 원문의 완전한 각 버전 보존은 없어 후속 실패 소스처럼 주장하지 않는다.
- 첫 포구 abstract 레이어 해석의 전체 신규 소스를 `run22-geom1`에 보존하고 실제419850의 반환식을 확인해 물리 프레임 직접 조회로 교정했다.
- 첫 독립 비교는 CD 상자6체크 실패, 첫 발사는 TYPE83 event0 미연결이었다. 전체 직접 source/log를 `run22-fail1`에 보존했다. 진단 추가 검사와 기계어 출력은 `run22-fail2`에 따로 보존했다.
- **CD 유효점 판정의 디컴파일 C는 정수 좌표 변환으로 읽으면 틀린다.** 기계어 `cmp DWORD [point],0`은 float 비트의 signed 비교이며 ftol 호출이 없다. 유한 양수에서는PATCH float>0과 같다. 생산식만 교정했고 독립 Native240입력/기대값은 바꾸지 않았다.
- 첫 RawDiscRegular 빌드의 SquidFrame 직접 include 누락은 `run22-buildfail`에 원문/로그를 보존하고 include만 추가했다. 그 뒤 Release7 및 신규6검사가 통과했다.

## 최종 검증과 남은 작업

최종 Release 빌드는 경고/오류0이다. 집중 검사는 새6개 모두 성공이며 전체 CTest **1/1·내부1,126개·실패체크0**(181.29초)이다. 원본432개 비교의 실패 체크0이며 기존 프레임 setter/Archer/Missile 입력을 새 원본 수로 합산하지 않는다. 실행 로그는 `run22-build-final.log`, `run22-geometry-final.log`, `run22-disc-final.log`, `run22-fire-final.log`, `run22-all.log`다.

현재 GameWorld의 실제 세션/입력과 Ready/login/9 Player/RNG, 전체 전투/생산/경제/운반/AI/Guide/UI/음향/승패·진행 저장 및 Early Missions/캠페인1-1~1-2 완주 동일성은 미완료다. 다음은 실제 충돌 효과/주변Dude 반응/GunHit/사제 피해·사망 및 자산 삭제 수명을 같은 월드에 연결한다. fencemark 교차 corner helper도 남았다. DirectDraw 전체화면 오류는 현재 목표에서 제외한다.

경로 감사는 최장178자이며, 이전 ignored 이력의 `run10-NormalTerrainWorldBinding_first.log`(파일명41자) 한 건이 남는다. 기존 이력 원문을 임의 변경하지 않았다. 로컬 커밋 메시지는 `20261015-07 실제 썬 디스크 발사기 발사와 썬 디스크 첫 비행 연결 검증`이며 원격 push는 하지 않는다.
