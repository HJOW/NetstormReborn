# CD 공간 Unpop의 현재 진단·부분 쓰기와 실제 연결 (단위909)

CD `004ad0b0`도 void 기록 이후의 현재 TYPE/상태를 사용해 원문 순서대로 지도·해시·종속 분리·표시를 처리한다. 기존 CD 경로의 선행 전수 검사/거부를 제거하고 PATCH `004afe50`과 같은 실제 부모에 판본 차이를 명시했다. 전체 Factory/Pop 복원은 진행 중이다.

## 원문 근거와 구현

- 마지막 전체 정밀 디컴파일과 현재 작업 호스트는 HJOW-Athlon / 2026-11-03이다. `extracted/refined/originalCD/NETSTORM.c`의 `004ad0b0`, `004acfc0`, `00479d20`, `004abf50` 및 보호 PE의 실제 명령/문자열을 대조했다. 정밀 산출물은 수정하지 않았다.
- CD 접두 진단은 `!isForm()/!isContained()/isValid()`의 `5bf/5c0/5c7`이다. 정상 복귀 뒤 현재 상태를 다시 읽고 free/void이면 반환한다. 그 외에는 void를 먼저 쓴다.
- 초기 TYPE 포인터/그 genus를 저장하지만 미니맵/옆면 통지/진단 이후 현재 TYPE·위치를 각 원문 위치에서 다시 읽는다. CD extra는35이며 PATCH는40이다. 저장한 발자국 범위와 현재 EffectiveGenus의 입력을 구별한다.
- CD에는 PATCH의 spot/GridSid/found 진단이 없다. 해시 미발견도 진단 없이 현재 VT의 `+88/+8c` 표시 갱신으로 이어진다. 기존처럼 표시·건물 연결과 전체 체인을 먼저 검증해 부분 쓰기를 없애지 않는다.
- 이전 항목에 next를 쓰는 실제 SetNext 진단을 양판본에 연결했다. `previous==next`이면 PATCH `c:\ns\o\squid.h:123`, CD `\ns\o\squid.h:10c`를 호출하고 정상 복귀 뒤 저장한 next WORD를 쓴다. 머리 직접 저장은 next를 추가 역참조하거나 self-next를 임의 거부하지 않는다.
- CD 일반 Unpop의 contained 분기는 기존 실제 공통 분리와 자신의 내용물 UI 검색으로 이어진다. World/Session의 현재 종단 연결을 재사용한다. 공통 분리의 CD 진단 파일 문자열도 보호 PE의 `\ns\o\Squid.cpp`로 고쳤다.

## 독립 CPU 관측

새 관측기는 CD 부모·실제 TYPE/EffectiveGenus/HashBucket/CRT와 inline spot/side/hash 명령만 호출한다. 게임 시작·GUI·OS 게임 초기화·통신은 실행하지 않는다. 미니맵·옆면 통지·가상 표시·진단·종속 분리/UI는 명시 장치이며 실제 자식 완료를 주장하지 않는다.

기존 명시 입력1,300개에 이전 next=self·머리 self-next·범위 밖 next·비균일 초기 지도를 더해 최초 유효1,402행을 동결했다. 전역/요청 순서와 전체 raw4,644BYTE·네 해시172,544BYTE·지도65,536BYTE의 Adler-32를 대조한다. 원문 진단은 `5bf:108`, `5c7:108`, `5c0:48`, `10c:18`회다. 다음 번호를 직접 머리에 쓰는 경우는 그 번호의 슬롯을 읽는 관측이 아니다.

관측기 빌드는2회다. 첫 빌드 도구의 세션 ID/종료 코드 출력이 누락됐으며 EXE/map 생성과 실행 중 cl/link/cmd 부재로 terminal을 확인했다. 첫 관측은 정적 CRT가 payload를 `443000`에서 시작하게 해 `410000` 범위 guard에서 종료1로 중단됐다. 원문 함수에는 들어가지 않았다. `/MD` 링크 설정으로 재빌드한 종료0 EXE에서 첫 유효 관측을 얻었다. 첫 EXE/map/실패 로그를 보존했고 원본 PE나 기존 fixture를 변경하지 않았다.
