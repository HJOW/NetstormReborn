2026-10-26 **HJOW-Athlon**에서 원본 10.78을 기준으로 작업했다. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 산출물을 변경하지 않았다.

## 원문의 소비 순서와 수정

원문 `00469fc0`은 전투 밖에서 곡 색인3과 `ser22.mus`를 선택한다. 전투 중에는 `004558f0(0,4000)` → `004558c0(4000)`으로 **공통00532710**을 한 번 소비하고, 결과를1000으로 나눈 뒤 다음 곡 처리를 실행한다. 메뉴 장면에는 이 난수 호출이 없다. State 정리 `004b2df0`도 fort/battle 전역을0으로 쓰기 **앞**에서 이 음악 부모를 호출하므로 현재 전투의 공통 난수를 사용해야 한다.

기존 `SceneMusic` 계산은 독립 원본 fixture와 일치했지만, 실제 `ClientAudio`는 `timeGetTime()`으로 시드한 별도 `GameRandom`을 만들었다. 따라서 음악 선택 결과와 그 뒤 SP·AI·지형 등이 소비하는 공통 스트림이 원문과 달랐다.

`ClientAudio`에 외부 `GameRandom&`를 빌리는 생성자를 추가했다. 실제 Client의 일반 음향과 `noAudio` 모두 `ClientRandomGlobals::Game()`의 같은 객체를 빌린다. 생성·음향 종료·소멸은 해당 시드를 쓰거나 난수를 소비하지 않는다. 기존 정수 시드 생성자는 독립 음향 검사의 지역 난수 경로를 유지한다. 두 생성자는 같은 음향 계층 조립을 사용하며 활성 난수 참조만 다르다.

Client는 공통 난수 owner를 음향보다 먼저 만들고 나중에 반납한다. 음향이 빌린 참조를 전투마다 새 사본으로 동기화하거나, 음악 스레드에서 난수를 따로 소비하는 경로를 추가하지 않았다.
