# Early3~6 실제 프레임과 세 DWORD 사건 연결

2026-10-19 단위206. 기준 커밋은 `5afa207a`다. 현재 PC와 마지막 정밀 디컴파일 PC는 **VM-W11-Codex**, 마지막 디컴파일 날짜는 **2026-10-19**다. 이번 단위에서 새 디컴파일이나 원본 게임 실행은 하지 않았다.

## 연결한 동작

기존 `RawTutorialLater`는 원본 Early3~6의 조건을 구현하고 독립 PE 입력 533개로 검증했으나 실제 Client에는 연결되지 않았다. 기존 공개 이름 `RawCampaignTutorialOneBindings`를 유지하면서 같은 `RawMissionFrameGate`의 1~6 분배에 연결했다. 기존 Early1/2 판정 몸체와 fixture는 바꾸지 않았다.

Session은 현재 로그인 옵션 87BYTE, 실제 Player 9개, 누적 제작 장부, 생산 Deck, 기술 알림, 사제 목록, 연결 Graph, 지역 getter와 일반 finder를 빌려준다. 지역 조회는 기존 `RawCampaignOwnership::IslandNumber`, 부류 검색은 기존 `RawDamageablePostDestroy::GenusAt`을 사용한다. 별도 성공값이나 관찰용 월드를 만들지 않는다.

원본 `00493c00`은 포획 완료 여부가 아니라 **현재 사제 HP가 최대 HP의 절반 미만**인지 signed 비교한다. 기존 훅 이름 `priestCaptured`를 유지하되 실제 현재 raw HP와 `SquidReward::MaxHitPoints`를 연결했다. 사제 부류가 아닌 입력은 원본 진단 위치를 표시하는 예외로 거부한다.

Early3~6은 명령 외에 사건의 두 DWORD도 읽는다. 기존 공통 gate의 독립 몸체를 변경하지 않고, 실제 `InputEvent`의 code/x/y를 한 호출 동안 유지한다. 프레임 호출은 0/0/0을 쓰며, 중첩 호출이나 예외 뒤 이전 호출의 인자를 복원한다. 특히 Early5의 `020000b5(132,78)`은 썬더 투사체가 스톤 타워에 맞았다는 사건이다. 원본 `00482340`의 해당 큐 생산 분기를 정밀 소스와 대조했으며, 이 단위에서 사건 생산자 자체를 새로 구현한 것은 아니다.

10호출 안내와 7호출 자기 정지 해제가 Early3~6에도 적용되므로 11단계 진입 도구의 관측 시점을 이에 맞췄다. 네 미션을 프레임 4의 안내 전 빈 화면에서 이미 진입한 것으로 세지 않는다.

## 근거와 검증

보호 PE의 타입/명령 DWORD 20개와 현재 호스트의 원본 몸체 5개를 `extracted/goal-early-later-runtime-20261019-static.json` 및 `original-bodies.c`에 보존한다. REA 6.5.0/Ghidra 12.1.4는 H: 루트의 Windows 경로 속성 조회에서 Win32 87로 분석을 시작하지 못했다. 동일 요청을 재시도하지 않았고 세션을 닫은 뒤 진단을 보존했다. 실제 구현 대조에는 이 PC에서 사전 재생성한 `extracted/refined/originals/Netstorm.c`를 사용했다.

새 실제 Session 회귀는 네 미션의 로그인/Start/원문 A안내/초기 SP/옵션/자기 정지를 검사한다. Early3의 수입 사건을 실제 전용 판정에 전달하며, Early5는 첫째/둘째 TYPE 각각의 오입력과 중첩 사건 뒤 올바른 두 인자가 보존되는 경우를 검사한다. 이 회귀의 명시 사건 입력을 실제 플레이의 자연 수확이나 피격 관측으로 세지 않는다.

초기 전체 Release 빌드와 후속 증분 빌드는 컴파일 오류/경고 없이 완료했다. 첫 집중 검사는 새 검사에서 `aiOff`를 AI 설정 할당 자체가 없는 것으로 잘못 가정해 실패했다. 실제 Start 사슬에 맞춰 할당/참여 경계를 공급한 다음에는 생산 Deck 할당 경계 누락을 발견했다. 두 누락 모두 기존 실제 Start/생산 검사가 쓰는 명시 할당 입력으로 고쳤고 게임 판정이나 기존 기대값은 바꾸지 않았다. 중간 실패 `focused1/2`와 최종 집중 `focused3`의 stdout/stderr/실행 파일 해시를 모두 보존한다. 최종 집중 3검사는 실패 0이다.

첫 실제 창 검사에서 목표 11개 모두 안내 버튼을 거쳐 플레이 상태로 진입했다. 같은 제품의 Early2 자연 완주 재검증도 **A~I / 윈드 신전 1개 / 썬 워크샾 1개 / 발사기 최대 4개→회수 후 3개 / 환불 75SP / 최종 3075SP / 완료 0→1 / Tutorial3의 2000SP·첫 안내**를 통과했다. 마지막 게임 시각은 80.67초이고 원본 폴더 전후 스냅샷은 같다. 이 결과를 Early3의 자연 완주로 합산하지 않는다.

최종 전체 **1726검사 실패 0 / 172.022초**다. 최종 실행 파일의 직렬 11개 진입도 모두 통과했다. 각 마지막 실제 프레임을 원문 초기 SP/기술·살아 있는 사제·정지 깊이·Early A단계와 읽기 전용으로 다시 대조했다. 자동 검사 종료와 저장된 실제 플레이 관측을 구분한다. 모든 산출물 접두는 `extracted/goal-early-later-runtime-20261019-`다.

## H: 설정 파일 열기 오류와 복구

전체 회귀와 병행한 진입 재검사에서 Tutorial2/GuardMyBack이 각각 한 번 `Unable to open d/options.cfg`로 종료했다. 두 실패와 원본 스냅샷 동일 결과는 `entry-final/`에 보존했다. 전체 회귀 종료 후 `entry-serial/`에서 11개 진입은 모두 통과했으나, 마지막 `preserve_game_settings`의 설정 복구에서 Python `OSError: [Errno 22] Invalid argument`가 발생해 최종 `results.json` 작성 전에 종료했다. **자동 정리까지 성공한 실행으로 기록하지 않는다.**

실제 H: 파일 시스템은 **exFAT**다. 설정 파일의 작업 전 Git 상태는 깨끗했고 `options.cfg`는 `-text`이므로 Git 기준 바이트를 그대로 복구할 수 있었다. 실패 당시 바이트와 기준 바이트를 별도 `.bin`으로 보존한 뒤 재쓰기 첫 시도에서 성공했고, **기준 SHA-256 `7c986d379a533456fb34d19f7937d1a028812c4560389d43cb663f1bd10cd7d4`** 일치와 `originals/`·`originalCD/` Git 변경 없음을 확인했다. 비어 있는 원래 `fullscreenStateFile.dat`도 동일하다. 복구 관측은 `options-restore.json`에 있다.

직렬 관측은 삭제하거나 다시 성공값으로 덮지 않았다. 새 읽기 전용 도구 `tools/cpp_tutorial_later_runtime.py --inspect <entry-serial 경로>`가 저장된 각 마지막 실제 프레임과 입력을 보호 Header에 대조한다. 원래 도구가 남기지 못한 마지막 요약을 보완할 뿐 게임을 실행하거나 상태를 쓰지 않는다. 간헐적 파일 열기/복구 오류의 원인과 NTFS 비교·재시도 필요성은 미확정으로 남긴다. 게임의 파일 쓰기 구현은 이번 단위에서 바꾸지 않았다.

사용자는 같은 작업 중 Codex의 `Selected model is at capacity. Please try a different model.` 메시지를 보았으며 에이전트 작업이 중단됐을 가능성을 알렸다. 해당 서비스 오류가 파일 열기/복구 오류에 영향을 주었는지는 확인되지 않았다. 프로젝트·PC·파일 시스템의 결함으로 단정하지 않으며 실제 오류 로그와 설정 복구 검증을 그대로 보존한다.

기준 커밋과 일치하는 현재 핀 **77보고서/213항목**만 갱신했다. 이전 해시와 `integration_updates` 이력을 보존했고, 기준과 이미 달랐던 역사 핀은 바꾸지 않았다. 다른 PC의 과거 실행 산출물이 이 PC에 모두 없으므로 이전 140종 감사의 재실행 성공을 주장하지 않는다.

## 남은 범위

이 연결만으로 Early3~6 자연 완주가 입증되지는 않는다. Early3의 실제 수확/다리 연결/생산/사제 약화/골렘 포획/운반, Early4~6의 자연 사건/완주, F8 Guide와 키 분배, 캠페인 1-1/1-2 및 데모 3개의 공통 프레임/전략 AI/승패/후속 미션과 전체 외관·음향 동일성 검증을 이어가야 한다. Early5의 썬더 투사체→스톤 타워 피격 사건 생산자와 H: 설정 파일 열기/복구 오류도 후속 확인 대상이다. 전체 목표는 미완료다.
