# Gump 기본 생성·등록·루트 초기화 복원

작업 PC: **HJOW-Athlon**, 기록일: **2026-10-12**. AGENTS.md와 두 LEFT_JOBS를 확인했고 착수 시 Git 트리는 깨끗했다. 현재 PC와 마지막 디컴파일 수행 PC가 일치했다. `gumpcreate` **2/2/2개**를 Ghidra 읽기 전용으로 내보냈다. 원본/복사본 게임·analyzeManager·클론 창은 실행하지 않았다.

## 완료 범위

패치 10.78 기본 생성자 **004642c0**, 루트 초기화 **004663d0**, CD/추가판의 **00492da0/00492b30** 전체 정상 몸체를 `GumpCreate`로 복원했다. 등록 표 1000칸·현재 개수·serial·화면 크기를 `GumpCreateState`가 보유하고, 호출자가 제공하는 안정된 토큰 저장소에 기본 객체를 초기화한다.

`GumpCreateNode`는 기존 `GumpCollectionNode`를 상속한다. `CollectionHooks`가 같은 기본 클래스 주소를 반환하여 생성된 객체의 플래그·링크·좌표·캐시를 수집과 Draw에서 공유한다. 호스트 구조체 메모리 배치는 PE의 0xa0바이트 배치와 별개다. 검사 직렬화는 원본 40개 DWORD 위치에 각 필드를 명시적으로 대응시킨다. raw 가상 표 주소는 판본별 근거 식별자이며 호스트에서 역참조하지 않는다.

반환한 수집 연결은 생성기를 참조하므로 `GumpCreate`·상태·노드 저장소를 연결 사용 기간 동안 유지해야 한다. 외부에서 등록 표 +0을 직접 바꾸는 경우 `collection.root`도 같은 토큰으로 맞춘다.

## 기본 필드와 첫 빈 칸 등록

생성자는 입력 command·width·height·flags를 사용한다. flags에는 void 비트 **8**, scale에는 **1**, 기본 깊이에는 **-40**, 글자 문맥 마지막 두 DWORD에는 **1**을 넣는다. width/height는 각각 기본 크기와 현재 크기의 두 위치에 비트 그대로 복사한다. 인자가 NaN·무한대·음수 0이어도 생성자에서 크기 계산은 하지 않는다.

실제 원본이 쓰지 않는 **+0x28 form과 +0x74**는 생성 전 값을 보존한다. 부모/자식/다음/이전 링크·위치/속도·캐시·텍스트 포인터 등 나머지 기본 필드는 원본대로 초기화한다. 독립 관찰의 전체 바이트 대조로 미작성 필드까지 확인했다.

serial은 모든 생성에서 DWORD로 증가한다. **bit 0x100000**이면 등록 표와 개수를 건드리지 않고 id 0으로 반환한다. 그 외에는 증가할 개수의 signed 값이 1000보다 작은지 검사한 뒤 앞에서부터 첫 빈 칸에 토큰을 기록하고 그 위치를 id로 쓴다. 마지막 칸 999도 검사한다.

원본은 개수 조건이 정상인데 등록 표만 가득 찬 불일치 입력에서도 정상 반환한다. 이 경우 표는 그대로이고 id는 0이며 개수는 증가한다. 이 동작을 보존했다. signed 음수 개수와 DWORD 넘침도 원본 정상 반환 입력으로 관찰했다. 원본 assert에 도달하는 개수 입력은 PE에서 실행하지 않았으며, 호스트 구현은 객체/전역 변경 전에 예외로 거부한다.

## 루트 초기화와 할당 경계

루트 초기화는 먼저 등록 표를 비우고 **new(0xa0)**를 요청한다. 성공하면 **할당 후의 현재 signed 화면 크기**를 float로 변환하여 command 0·flags 1의 기본 생성자를 호출하고 등록 표 +0/수집 루트에 토큰을 넣는다. 할당 경계가 개수·serial·화면 크기를 바꾼 경우에도 현재 값을 사용한다.

할당 실패 0이면 생성자를 호출하지 않으며 비운 표/루트 0을 유지한다. 기존 개수·serial·overrideHead·이전 노드 저장소는 초기화하지 않는다. 반복 루트 초기화 역시 개수·serial을 이어서 사용한다. 이전 객체를 반납하는 수명 경로는 이번 몸체에 없으므로 호출자가 별도로 처리해야 한다.

## 기존 수집·Draw 연결

통합 검사는 루트와 일반 Gump 생성→같은 저장소의 수집→원본 CRT 정렬→공통 kind 2→클립 보호→선 픽셀 출력을 연결한다. 수집 캐시가 원래 생성 저장소에 기록되고 이후 flags 변경도 바로 반영되는 것을 확인했다.

이 검사에서는 부모/자식 링크를 **명시 입력으로 공급**한다. 기본 생성자는 부모 트리에 부착하지 않는다. 실제 부착 함수·파생 생성자·가상 Draw 처리기·텍스트 공급·Client/GameWorld 자동 프레임은 후속이다. 현재 메뉴 전체나 건설 GUI를 이 경로로 전환한 상태는 아니다.
