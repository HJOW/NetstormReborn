# 실제 캠페인 썬 캐논 애니메이션 연결과 미복원 총 분류

2026-10-16 단위88, 현재/마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-16**이다. AGENTS.md와 양 LEFT를 다시 읽고 깨끗한 `1801496`에서 시작했다. [직전 비행 표적 선택](cpp-flyer-target-20261016.md) 뒤의 실제 미복원 부모와 이미 복원한 애니메이션 본체의 세션 연결을 확인했다. 목표는 사용자 플레이/자연 완주·원본 동일성이며 아직 미달성이다.

## 이번 실제 연결

`RawCampaignArcherBindings`는 기존에 썬 디스크 발사기 TYPE71만 생성 분배에 연결했다. 같은 풀에 이미 복원한 [썬 캐논 GunAnimation](cpp-gun-animation-20261013.md)을 추가로 소유하고, **TYPE128일 때만** 원본 `CreateGunAnimation`의 stage2/5/8을 선택한다. 기존 실제 부모/표적의 TYPE와 Host를 조회하며, 나머지는 원래 fallback 또는 TYPE/단계를 명시하는 오류를 유지한다.

캐논과 발사기는 같은 World·공간·Kernel·Missile 본체를 공유하지만 **완료 notify/kill의 실제 C++ 타입과 원본 애니메이션 필드는 구별**한다. 공통 공간/음향/중심/난수 경계를 복사한 뒤 각 클래스에 맞는 Host 완료 어댑터를 설치한다. 썬 캐논의 게임 시각은 같은 PrepareFrame 입력으로 갱신한다. 기존 디스크 발사기 본체·투사체/피해 수치·원본 fixture는 변경하지 않았다.

새 통합 검사는 실제 보호 캠페인 자원과 같은 Core에서 만든 TYPE128 부모에 실제 GunProcess를 붙인다. 회전/발사/원위치 생성기를 각각 실행해 **TYPE36/35/36 Form, 실제 GunAnimation 클래스, 현재 부모/표적/GunForm과 각 생성 시각**을 확인하고 같은 Host로 정리한다. 이 부모는 void 상태이며 **생성 분배와 현재 시계만 검증**한다. 이 검사를 새 건물의 공간 Pop이나 사용자 건설 완료의 증거로 삼지 않는다.

최초 검사 시도는 새 썬 캐논을 소유자 변경·Pop까지 진행하다 원본 서버/로딩 관문에서 거부됐다. 그 관문을 완화하지 않았다. 최종 검사는 생성 분배/시계 범위로 명확히 한정했으며 **실제 건설 완료·소유자/Pop 경로의 관문은 후속 검증**으로 남긴다. 최초 실패는 `extracted/goal-campaign-cannon-20261016-fire-tests.log`에 보존한다.

세션의 현재 `RawProjectileGeometry::ArcherMuzzle`도 TYPE71만 지원하므로 **썬 캐논의 실제 투사체 생성/포구 연결은 아직 완료되지 않았다**. 이번 생성 분배 검사는 launch를 실행하지 않는다. 해당 포구·비행 효과 경계를 후속 복원한 뒤 실제 발사부터 충돌/피해까지 검증해야 한다.

## 검증의 범위와 이력

새 생성/시계1개와 기존 실제 디스크 발사/첫 비행2개, 합계 **CampaignFire3개가 통과**했다. 기존 GunAnimation4개와 ArcherAnimation4개도 통과했다. 기존 프레임/launch fixture를 C++에서 다시 대조했으며 **이번에 원본 입력을 새로 재생하거나2560개를 새 관찰 수로 더하지 않았다**.

기존 GunAnimation/Missile/ArcherMissile의 Python `--verify`3개는 현재 fixture SHA 또는 baseline lineage 불일치로 실패한다. 해당 fixture/보고서/도구는 이번 단위에서 수정하지 않았고 단위 시작 Git 바이트와 동일함을 새 보고서에 기록한다. 이를 새 코드의 통과 검증으로 표기하거나 과거 보고서 SHA를 현재 값으로 덮어쓰지 않는다. C++ 회귀 통과와 과거 SHA 감사 실패를 별개로 남긴다.

이전 명칭 전용 snapshot의 감사도 현재 소스에서는 실패한다. 당시 보고서가 고정한200파일 중 후속 기능 수정4경로가 달라졌으며, 그 경로와 역사/단위 시작/현재 SHA를 새 보고서에 기록했다. 이는 현재 공유 JSON의 반더 타워 표기 검사와 구분한다. 과거 명칭 교정만 허용하는 감사를 통과시키기 위해 이후 기능 변경을 지우거나 당시 보고서를 덮어쓰지 않는다.
