# 캠페인 1-1 레인 신전 표시 점검

2026-10-15, **VM-W11-Codex**. 사용자에게서 플레이어 측 Rain Temple의 모습이 이상하다는 제보를 받아 점검했다. 기준 커밋은 `aa2ce74`이며 AGENTS와 두 LEFT 문서를 확인했다. 현재 PC와 마지막 정밀 디컴파일 PC는 **VM-W11-Codex, 2026-10-15**로 일치한다. 현재 `extracted/refined/originals/Netstorm.c`를 읽었으며 새 디컴파일은 수행하지 않았다.

## 결론

**미완성된 표시 경로가 원인이다.** 현재 실제 캠페인의 `GameWorld::Sprites()`는 각 raw 객체의 현재 프레임 한 장만 제출한다. 레인 신전의 일반 물결 프레임은 신전 전체 그림이 아니므로, 돌 테두리와 장식이 사라지고 물결만 지면에 남는다. 이번 작업은 점검과 인수인계이며 게임 소스 수정은 하지 않았다.

## 확인 근거

1. 기존 클론 캡처 `extracted/run33-final/thewarbegins/mission.bmp`에서 플레이어 섬에 작은 청록색 물결만 보인다. 같은 실행의 `states.tsv`는 SID15002, `rainVortex`, owner1, 좌표89/116, HP5000을 기록한다. 브리핑과 미션의 현재 프레임은 각각1/2다. 따라서 물결의 프레임 진행은 연결되어 있다. 이번 점검에서 새 게임 창을 실행한 것은 아니다.
2. 원본 `screenShots/The War Begins! - Briefing.png`의 대화상자 왼쪽에는 큰 돌 테두리와 장식이 보인다. 대화상자가 신전 일부를 가리므로 이 화면으로 전체 픽셀 일치를 주장하지 않는다.
3. 보호 원본 `d/rainVortex.type`에는 `A00 : default baseframe`와 물결 `B01`~`B14`가 별도로 있다. 일반 프레임 번호는 A00=0, B01~B14=1~14다. SHP 블록54를 기존 Python 판독기로 내보내 확인했다. `A00_L0.png`에는 실제 돌 테두리·장식·물 바닥이 모두 존재한다. 관련 자산은 누락되지 않았다.
4. 10.78의 레인 신전 가상표는 `005196f0`, Draw 슬롯+`a4`는 **`004dcd00`**이다. 이 몸체는 `00497280(this,x,y,shape,0)` 다음에 `00497280(this,x,y,shape,currentFrame)`을 호출한다. 즉 기본 신전과 현재 물결을 같은 위치에 순서대로 그린다. WORD+`0c`가 비영일 때의 추가 상태 표시 분기도 별도로 존재한다. 일반 표시를 고칠 때 이 분기와 그림자를 혼동하지 않아야 한다.
5. `GameWorld.cpp`의 실제 raw 제출 루프는 현재 `object.frame`만 `add(...)`에 전달한다. 레인 신전의 위 가상 Draw 경로를 소비하지 않는다. 같은 함수에 그림자 제출도 연결되어 있지 않다. 물결의 현재 프레임만으로 수행하는 화면 밖 판정과 `GameWorld::Bounds()`의 선택 범위도 함께 검토해야 한다.

신전과 별개로 플레이어 섬의 원소 지형도 현재 캡처에서는 초록색이고 원본 브리핑에서는 눈/얼음 계열이다. 이 차이는 함께 관찰했지만 이번 점검으로 원인을 확정하거나 수정한 것은 아니다.

## 검사와 보존

- `python -X utf8 tools/shp.py export --orig originals --out extracted/rain-temple-check --type rainVortex`: 종료0. 출력은 Git 제외 경로의 `054_rainVortex/`에 있다.
- `netstorm_tests.exe --filter VortexDisplay`: **2개 통과, 실패 체크0**. 이 검사는 `SquidDisplay`의 갱신 사각형/inset/선택·그림자 영역을 비교한다. 신전 그림의 레이어 합성을 검사하지 않으므로 통과를 외형 복원 완료로 해석하면 안 된다.
- 새 테스트 추가, 빌드, 실제 원본/클론 게임 실행은 없다. 이번에 본 클론 실행 자료는 단위33의 기존 자료다.
- 두 보호 PE의 SHA-256은 기존 기준과 같다. 원본 자산과 AGENTS, 사용자 TODO, dotnetpj를 변경하지 않았다.

## 필요한 수정

- 실제 캠페인 표시에서 레인 신전 Draw의 **기본0 → 현재 물결** 순서를 연결한다. 같은 정렬 키의 독립 스프라이트로 나눈 뒤 CRT 정렬이 순서를 바꾸는 구현은 피하고, 원본의 한 객체 Draw 순서를 보존한다.
- 전체 그림의 화면 밖 판정/부분 갱신/선택 범위와 그림자, WORD+0c의 상태별 추가 표시를 각각 원본 경로에 맞춰 연결한다.
- 원본 자산으로 합성한 기대 그림과 실제 Renderer 출력의 픽셀 비교, 실제1-1 창의 전후 비교를 추가한다. 현재 기존 세션 검사는 `Sprites()`의 비어 있지 않음만 확인하므로 레인 신전의 기본 그림 누락을 검출하지 못한다.
- 플레이어 섬의 원소 지형 차이를 별도로 추적한다. 앞 단위의 Warning 안내, 건설/생산/수확 및 캠페인 완주 미완료 항목도 유지한다.

점검 단위는 인수인계 후 `20261015-21 캠페인 레인 신전 기본 그림 누락 점검과 인수인계`로 로컬 커밋한다. 원격 push는 하지 않는다.
