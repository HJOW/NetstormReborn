# 실제 중단의 사용자 저장 상태 삭제 — 단위949

일반 중단의 공통 abort가 사용자 Saves 경로를 빠뜨려 설치 폴더의 옛 `d/!state.dat`를 삭제하던 오류를 수정했다. 같은 실제 Early1 중단 메뉴에서 **수정 전 제품939의 잘못된 삭제를 재현**했고, 새 제품949는 **사용자 파일 삭제2회·설치 파일 보존·메인 복귀·정상 종료0**을 확인했다. [완료 JSON](../../cpppj/abort-user-saved-state-20261106.json)을 따른다.

2026-11-06, HJOW-Athlon. 마지막 전체 정밀 디컴파일은 같은 PC/2026-11-03이다. AGENTS.md의 실행 확인 면제 호스트에서 클론의 실제 창·무음·격리 자료를 사용했다. 원본/CD·AGENTS.md·기존 fixture·디컴파일 원시는 변경하지 않았다.

## 원인과 변경

원문10.78 `004b6350`은 AbortPending·모드별 다음3/6·세 블록+84를 쓴 뒤 `004b5470`으로 계산한 상태 파일을 삭제한다. 현재 [일반 입력의 공통 abort](../../cpppj/src/client/UberGump.cpp)는 그 순서를 보존하지만, 삭제 callback만 `DeleteSavedStateFile(gameDirectory, formatter)`의 옛 설치 위치를 사용했다. 같은 입력의 이유3/9 선행 삭제와 Native State3 삭제는 이미 사용자 경로를 전달하고 있었다.

공통 callback에도 `client_.UserSavedStateFile()`을 전달했다. 원문 이름 고리 소비·파일 삭제 실패 반환 무시·중복 삭제·예약/정리 순서는 바꾸지 않았다. 사용자 홈 정책에서는 현재 Saves 파일을 삭제하고 설치 자료를 보존하며, 정책이 없는 기존 장치에는 빈 override를 전달해 옛 동작을 유지한다. 제품 표기/파일 버전은11.01이다.

## 실제 수정 전후 대조

[기존 실제 중단 도구](../../tools/mcp_cpp_mission_abort_smoke.py)에 `--check-saved-state-delete` 선택 검사를 추가했다. 이 모드는 보호 원본 아래의 실행/출력 경로를 거부한다. 없는 설치 상태 파일만 검사 사본에 새로 만들고, 기존 파일이 있으면 읽기만 한다. 사용자 삭제 표식은 초기 Startup reader와 실제 Replay 진입을 마친 뒤 ABORT 창에서 Main Menu를 누르기 직전에 준비한다. 원본/사용자 실사용 Saves에는 쓰지 않는다.

전후 실행은 같은 도구 SHA와 서로 다른 전체 자료 사본을 사용했다. 제품939는 실행 파일과 필요한 DLL을 별도 폴더에 고정한 뒤 사용했고, 소스 수정/빌드는 그 프로세스가 종료한 뒤 진행했다. 검사 표식은 삭제 대상 식별용이며 유효 저장 게임이나 저장 상태 reader 복구의 증거가 아니다.

수정 제품 한 프로세스에서 새 Early1 진입2회+Replay2회=총4진입, Continue/Abort/Main Menu 왕복을 확인했다. 앱 입력35개·실제 보고24개·논리1024×768 PNG3개이며 시작 미션/최종 메인을 육안 확인했다. `saved-state-audit.json`의 두 사용자 삭제와 설치 SHA `0eff9279a4f5aff283c8df168284e52ac58f946e985178c9027de4db02965439`를 최종 원시와 대조했다. 코드·설정·승패 값을 주입해 중단 성공을 만들지 않았다.
