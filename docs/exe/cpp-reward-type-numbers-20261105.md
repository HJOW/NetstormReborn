# 단위869 — 보상·일반 삭제의 현재 TYPE 번호

보상 계산과 일반 삭제에서 제단·다이스·너겟·일반/성장 레인 바리케이드의 현재 타입 번호를 같은 Client의 장기 owner에 연결했다. 전체 의식/운반 소비자나 공통 Pop 완료는 아니다. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-11-03**, 현재 호스트도 일치하며 디컴파일 산출물은 변경하지 않았다.

## 현재 번호와 별도 비용표

보호 10.78 PE의 초기 DWORD는 `005412e8=164` 제단, `005412ec=165` 다이스, `005412a4=147` 레인 바리케이드, `005412b0=150` 성장형, `005412c0=154` 너겟이다. `RawGameAuxState`가 한 번 소유하고 일반 월드 준비/Session 교체에서 이 값들을 다시 쓰지 않는다.

`SquidRewardState`에 실제 주소 대여와 현재 getter를 추가했다. 실제 Session은 위 다섯 owner를 연결한다. 독립/CD 재생은 별도 연결이 없으면 기존 `types` 입력을 유지한다. 이 번호 표는 현재 World TYPE 기록과 별개이며 865의 최초 정수 비용표도 그대로다. 현재 float 비용이 바뀌어도 번호 대여 때문에 비용 캐시를 다시 만들지 않는다.

`0049fce0` HP 예외와 `004adcb0` 다이스 최대HP, `0044b220/0043cb30` 비용 개수−1·너겟 전액 배율, `0044c2f0/0044c240`의 보상 제외·성장형 별칭/환불0을 현재 번호로 판정한다. HP 진단 자체의 기존 호스트 예외 경계는 이번 단위에서 바꾸지 않는다. 일반 삭제 `0044b9e0`의 섬 정리 제외도 `DamageablePostDestroyState`가 같은 `005412a4`를 빌리게 했다.

## 가상 Count 전후 순서

원문 `0044c2f0`과 CD `004626d0`을 실제 기계어와 함께 읽어 C++ 인자 평가 순서에 의존하던 부분을 명시했다. 양판본 모두 첫 TYPE는 첫 가상Count 전에 저장하고, 첫 비용 계산 뒤 현재 슬롯 TYPE와 성장형 번호를 비교한다. 별칭 가지는 **두 번째 Count 뒤** 현재 레인 바리케이드 번호를 읽어 비용을 다시 계산한다. PATCH `0044c355→0044c35c`, CD `0046273c→00462743` 순서다.

해체 환불은 서로 다르다. PATCH `0044c37f`는 현재 TYPE를 저장한 뒤 `0044c385`의 Count를 호출하고 그 저장값을 넘긴다. CD는 `00462777`의 Count 뒤 `00462784`에서 TYPE를 읽는다. 따라서 Count 중 슬롯 TYPE가 바뀌는 명시 입력에서 전달 타입이 다르다. 기존 fixture 기대값을 바꾸는 대신 해당 두 순서를 본체와 새 합성 검사에 명시한다. 새 PE 실행 관측으로 주장하지 않으며 기계어 정적 대조 근거다.
