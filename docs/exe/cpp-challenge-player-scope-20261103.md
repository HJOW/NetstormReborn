# Challenge 플레이어 삭제의 후순위 분류

단위799는 checking 잔여의0042bc10을 원본 Ch.cpp의 Challenge 플레이어 삭제로 분류했다. 제품 코드/빌드/단위 검사/Native 관측/게임 실행/통신은 모두0이다. 구현을 완료한 것이 아니며 전체 잔여43은 그대로다. 분류만 부모35·부분6·MP2에서 **부모34·부분6·MP3**으로 정정한다.

원문은 플레이어 번호1..39를 허용하고 CL_NUM_CHAL_PLAYERS를40으로 비교한다. 1미만/40 이상은 checking과 무관한 Ch.cpp499 진단·로그9 뒤 반환이다. 유효 번호는 this+b70+번호×1cc의 플레이어를 고르고, 현재 checking에서 유효 비트가 없으면4a1을 진단한다. 복귀 뒤 현재 비트를 다시 읽어 여전히 무효이면 로그 뒤 반환한다. 배치된 방/슬롯이 있으면 해당 슬롯을0으로 쓰고 방 상태 갱신/후처리를 거쳐 플레이어 상태를 정리한다. 상수의40을 싱글플레이 참가자 수로 취급하지 않는다.

정밀 C 출력의 직접 호출 표현을 검색하면0042c2a0 한 부모가 byte 목록의 플레이어 번호를 반복 전달하고 목록 갱신을 호출한다. 이는 텍스트 직접 호출 검색이며 vtable/별칭/간접 호출 전체 부재를 증명하지 않는다. 현재 SquidOwner의 challenge 모드도 같은1..39 범위를 별도로 사용한다. checking 공백 색인의 현재 제품 직접 주소 언급 부재는 구현 완료 근거가 아니다.

이 부모는 싱글플레이/UI/호환성 뒤의 로컬 TCP/IP Challenge/Outpust 정적 사전 구현 범위로 이월한다. 그 단계에서 기존 방/플레이어/구독/삭제 메시지 순서를 디컴파일에 따라 연결하되 신규 단위 검사·게임·실제 통신 검사를 만들거나 실행하지 않는다. 일반 미션의 플레이어 삭제와 섞지 않고, 공식 서버/외부 검증 기능은684의 비활성 정책을 유지한다.
