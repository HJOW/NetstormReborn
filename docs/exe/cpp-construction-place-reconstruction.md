## 배치 순서

인자는 타입, 시작 좌표, decoder 인자(패턴 번호 또는 프레임 인자), 방향, 플레이어, SID 개수와 목록, abstract 인자, 다리 품질이다.

1. 플레이어가 서버 번호 9이면 assert다. 이어 `(타입, 인자, 방향, x, y, 0)`으로 CanonDecoder를 만든다.
2. **패치판만** 비용을 판정한다(아래 절). CD판과 10.37에는 이 구간이 없다.
3. decoder의 유효 칸마다 조각 하나를 놓는다. 한 조각의 순서는 다음과 같다.
   - SID 목록에서 번호를 읽는다. 서버 플래그가 꺼져 있고 번호가 5 미만이거나 서버 영역(패치 15000 이상, CD 6000 이상)이면 수신 함수가 돌려준 객체를 쓰고, 아니면 그 번호의 슬롯을 그대로 쓴다.
   - 슬롯이 void가 아니면 assert다.
   - abstract 비트(패치 `+0x28`, CD `+0x23`의 bit 0)를 abstract 인자의 bit 0으로 바꾼다. 다른 비트는 그대로다.
   - HP가 있는 객체이면 HP를 쓴다. abstract 인자가 0이 아니면 0, 0이면 최대 HP다. HP 유무는 **방금 쓴 abstract 비트**를 읽으므로 dais 부류(flags2 `0x400000`)는 abstract 인자의 bit 0이 켜졌을 때만 HP 0을 받는다.
   - 프레임 필드(패치 `+0x24` DWORD, CD `+0x22` BYTE)에 decoder의 현재 프레임을 쓴다.
   - `+0xc` 단어에 decoder 인자의 하위 단어를 쓴다. 타입이 noIsland이고 칸의 좌표가 시작 좌표와 같으면 대신 **`0x5d4`**를 쓴다(3×3 가운데 첫 칸 하나). 단어 쓰기 함수는 객체 타입이 다리이면 표면 알림을 부른다.
   - 타입이 다리이면 품질을 정한다(아래).
   - 가상 소유자 지정(플레이어) → 가상 Pop(칸 좌표, 플래그) → decoder 진행.
4. **패치판만** 끝에서 놓은 조각 수가 SID 개수 인자와 같은지 assert한다.

**Pop 플래그는 abstract 인자가 0이면 `0x41`, 0이 아니면 `2`다.** Ghidra 디컴파일은 이 값을 반복 횟수와 OR하는 것처럼 보여 주지만 기계어는 `(abstract != 0) + 1`을 미리 구해 두고 abstract가 0일 때만 `0x40`을 더한다.

호출자가 넘기는 abstract 인자(디컴파일 판독, 이번에 기계어로 대조하지 않았다): 로컬 배치 `004433b0`은 항상 1이다. 배치 통지 처리기 `004441b0`(CD `004d1d00`)은 **HP가 있는 타입(flags1 `0x10`)이거나 dais이면 1**, 그 밖이거나 통지의 플래그 bit 0이 켜져 있으면 0이다. 그래서 HP가 있는 건물은 HP 0의 abstract 상태(건설 중)로 놓이고, 다리처럼 HP가 없는 조각은 곧바로 확정(Pop `0x41`)된다.

### 다리 품질

품질 인자가 1이면 프레임 플래그 `0x20`과 수명 `상수 - 1`, 3이면 플래그 `0x40`과 수명 0, 그 밖에는 플래그 0과 수명 0이다. decoder가 고른 프레임 코드의 방향 글자가 `K`보다 뒤이면(signed char 비교) 품질과 무관하게 수명이 `상수 - 1`이 된다. 그 프레임 코드의 방향 글자·변형 글자와 `부호 확장한 플래그 | 품질 플래그`가 정확히 같은 첫 프레임을 타입에서 찾아 프레임 필드를 다시 쓴다. **맞는 프레임이 없으면 원본은 assert(Rifttype.cpp 362행)다.** 이어 `+0xc` 단어의 bit 3~6만 수명으로 바꾸고 표면 알림을 한 번 더 부른다. 그래서 다리 조각 하나는 알림을 두 번 받는다.

## 비용 판정과 비용 부족 처리 (패치판)

배치의 비용 판정은 **다른 플레이어의 배치에만** 적용된다. 플레이어가 로컬 플레이어이거나, 차단 전역이 켜져 있거나, 번호가 1~8 밖이거나, 타입 비용이 0(±0)이거나, 타입이 nugget이면 건너뛴다. 그 밖에는 SP 조회(`0040ef30`) 결과가 비용 이상이면 그 플레이어의 SP에서 비용을 빼고, 모자라거나 비교할 수 없으면(NaN) 비용 부족 처리를 부른다. **두 경우 모두 조각은 그대로 놓는다.** 로컬 플레이어의 비용은 이 함수가 아니라 조각을 내려놓는 커서 처리(Cursor.cpp `004473e0`)에서 빠진다: `droppiece.wav` → 로컬 배치 `004433b0` → 커서 플래그 `0x40`이면 `0040eec0(-비용)`과 SP 표시 갱신 순서다(디컴파일 판독이며 이번에 기계어로 대조하지 않았다).

비용 부족 처리(`00442b50`)는 그 플레이어의 표시 비트(Player `+0x54`의 `0x400`)를 읽어 둔 뒤 켠다.

- **권한이 있으면**(`00540bc4`): 표시가 처음이면 `ClientCheated(%s)`에 플레이어 이름을 넣은 문구를 다른 모두에게 보내고, 당사자에게 `ServerThinksYouCheated`를 보낸다. 좌표가 유효하면(둘 다 0 초과 256 미만) 취소 통지 함수를 부른다.
- **권한이 없으면**: 잔액과 무관하게 비용을 뺀다(로컬이면 로컬 가산, 아니면 플레이어 가산). 표시가 처음이면 `ServerCheated(%s)` 문구를 로컬 안내 창에 띄운다.

취소 통지(`00442af0`)는 환불을 부른 뒤 메시지 `0x2f`(15바이트)를 그 플레이어에게 보낸다. 본문은 좌표 두 개의 비트, 타입 바이트, decoder 인자와 방향의 하위 바이트다.

환불(`00442a40`)은 nugget이면 아무것도 하지 않는다. 타입 비용을 `__ftol`로 0방향 절삭한 정수를 float로 되돌려 SP에 더하고(전투 표시 중의 로컬 플레이어는 건너뜀), 정수가 양수이면 메시지 `0x6c`(11바이트: 플레이어 바이트 둘, 1, 정수 금액)를 보낸다. `__ftol`은 64비트 정수의 하위 DWORD를 쓰므로 NaN·무한대 비용은 0, 2³¹ 이상은 감긴 음수가 된다(관찰로 확인). CD판 `004d1bc0`은 SP를 건드리지 않고 통지만 보낸다.

SP 조회(`0040ef30`)는 전투 표시 중의 로컬 플레이어이면 번호 검사 없이 저장소를 읽고, 그 밖에는 번호가 1~8일 때만 읽으며 아니면 0이다.

## 독립 원본 관찰과 C++ 연결

[`decomp_constructionplace_oracle.py`](../../tools/decomp_constructionplace_oracle.py)는 세 PE를 두 x87 제어 워드 `0x027f`/`0x037f`로 실행했다. 새 독립 저장 입력 **3,682개**: 10.78 **1,778개**(배치 1,246·비용 부족 292·환불 144·SP 조회 48·취소 통지 24·가산 분배 24), CD와 10.37 각 **952개**(배치 916·환불 36). 정상 반환은 10.78 **3,556회**, CD·10.37 각 **1,904회**(합계 7,364회)이고 두 정밀도의 관찰이 모두 같았다. 놓인 조각은 10.78 **3,510개**, CD·10.37 각 **2,812개**다. 저장 입력 누적은 앞 단계 455,755개에 더해 **459,437개**다.

입력은 비용 판정을 건너뛰는 조건 여덟, 잔액 충분/부족 × 권한 × 기존 표시 × 좌표 유효성 × 전투 표시, 타입 부류(HP 있음/없음·dais 부류·noIsland·island·nugget) × 서버 플래그 × SID 영역 × abstract 인자 0~3 × 슬롯 초기 내용 세 가지, 좌표와 없는 기본 프레임, 다리 패턴 26개 × 방향 × 품질 0~3 × 프레임 표 네 가지(기본·역순·부호 있는 플래그·품질 프레임 없음) × 수명 상수 세 가지(5·1·16)를 교차하고, 수명 값이 단어의 bit 7 위로 넘치는 수명 상수 17·33도 따로 넣는다. 조각 수는 실제 decoder를 한 번 더 돌려 센 값을 SID 개수로 공급하며 Python에서 계산하지 않는다. 슬롯 전체 바이트·사건 순서·Player 표시 비트·SP 조회 반환 비트를 저장한다.

배치·비용 처리 몸체와 decoder/HP/단어/프레임 helper는 원본 명령이다. 위 표의 명시 경계만 인자를 기록하고 반환한다. 소유자 경계는 소유자 바이트만 쓰고 수신 경계는 요청한 번호의 슬롯을 돌려준다. 스택·보존 레지스터·x87 제어/깊이·허용 실행 범위·허용 쓰기 범위(조각 슬롯과 Player 표시 필드)·입력 순서·진입/반환 수·경계 사건 수·SHA를 감사한다. 원본 assert와 게임/OS 호출은 0이다.

관찰에서 뺀 것: 서버 번호 9·void가 아닌 슬롯·개수 불일치·없는 품질 프레임(모두 원본 assert), 번호 5 미만 SID, NaN/무한대 시작 좌표(C++ decoder가 거부한다). 그래서 noIsland 시작 칸 비교의 NaN 차이는 기계어 판독이며 fixture로 대조하지 않았다.

### 다음 단계를 위한 판독 메모

아래는 호출자 쪽을 읽은 메모다. `00444590`은 기계어를, 나머지는 디컴파일을 읽었고 **원본 실행 대조는 하지 않았다.**

- **서버 확정 `00444590(타입, x, y, 플레이어, decoder 인자, 방향, 플래그, 시각 double, 품질)`**(이 메모를 쓴 뒤 같은 세션에서 [복원·대조를 마쳤다](cpp-construction-confirm-reconstruction.md)): 타입 flags1에 `0x8000`이 있고 플래그 bit 0이 꺼져 있으며 전역 `0054db14`가 0이면 먼저 `0048fdb0(플레이어, 타입, x, y)`로 지을 사제를 찾고, 없으면 0을 돌려준다. 이어 메시지 `0x3f`(가변 길이, 최대 0x200)를 만들고 decoder의 칸마다 `004af530(타입, 0)`으로 SID를 확보해 메시지의 항목(`0040a840`)에 적는다(20개 이상이면 `sidCount < MAX_SIDS` assert). 메시지 필드는 `+4` 타입, `+5` x, `+9` y, `+0xd` decoder 인자, `+0xe` 방향, `+0xf` 플레이어, `+0x10` 플래그, `+0x11` 품질, `+0x12` 시각(double), `+0x1a` SID 개수다. `004e2e30`으로 보낸 뒤 처리기 `004441b0(9, 0, 메시지)`를 직접 부르고 1을 돌려준다.
- **로컬 예측 정리 `00441fd0`**: decoder의 칸마다 그 칸 범위의 객체를 훑어 abstract이면서 번호가 클라이언트 영역(5~14999)인 것을 찾는다(타입이 같거나 권한이 없을 때). 타입·프레임(다리는 방향 글자)·소유자가 통지와 같으면 가상 `+0x10`을 플래그 `0x2000000`으로, 아니면 0으로 불러 지운다.
- **배치 통지 처리기 `004441b0`**: 메시지의 타입이 HP가 있거나 dais이고 플래그 bit 0이 꺼져 있으면 abstract 1로 배치 실행을 부른다. 통지의 플레이어가 로컬이면 최근 배치 좌표 네 개를 밀어 넣는 기록(`00558ea4`~)도 갱신한다.

실제 Pop은 타입별 가상 함수라 지원하는 타입부터 연결해야 한다. 월드 난수·효과음 호출자·raw 비표면 객체·경제·전투·AI·승패도 남아 **미션 완주는 아직 불가능하다.** 현행 목표는 한국어 3차, outpost/LAN 4차, 화면 요구사항/MCP 5차다. [최신 인계](../../LEFT_JOBS.md).
