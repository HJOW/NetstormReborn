# 단위33: 실제 fencemark 표적 계산과 UI 교전

작업일 **2026-10-15**, 현재 및 마지막 정밀 디컴파일 PC **VM-W11-Codex**. AGENTS와 양 LEFT를 재독하고 `68ca4e3`에서 이어갔다. 직전 턴은 실제 미션 진입·이동 구현/검사/커밋으로 진척했다. 도중 사용자가 커밋한 `2e05f3d`의 TODO 변경을 보존한다.

## 실제 표적 계산

`RawFenceTarget`에 PATCH10.78의 다음 몸체를 연결했다.

- `004571b0`: 현재 발사 시야/포구와 표적 발자국을 합치고 현재 해시 단계 경계에 도장한다. 실제 finder1을 순회해 fencemark만 검사한다. x87 53비트 거리와 현재 float 최솟값을 엄격히 비교하고, 선택 뒤 최솟값을 float로 저장하는 순서를 보존한다.
- `004568b0`: 마크의 WORD 끝점과 high24/low8 압축 끝점을 읽고, 현재 소유자·9×9 동맹·발자국·양쪽 분류·선분 교차·픽셀 보정을 적용한다.
- `004818d0/004819b0`: 현재 물리 SHP의 signed 포구 WORD를 더하고 TYPE 핫스폿을 빼는 일반 시야/포구다. 아처 전용 기본프레임 포구 getter와 구분한다.
- `00462800/00462710/00462650`: 수직/비수직 선분의 교차와 범위 검사다. 사각형의 min/min·max/max 대각 끝점 제외, 실제 float 절편/결과 저장 지점을 보존한다.

같은 raw Pool·Hash·TYPE·현재 배율·GunProcess 동맹·기존 foot/2 중심 getter를 빌린다. `RawCampaignSession`의 기본 `targetPoint`를 실제 계산에 연결하고 세션 검사에서 상수 `(-10000,-10000)` 모의를 제거했다. 배리어가 없을 때의 무효 좌표도 실제 시야/후보 탐색을 마친 결과다.

이번 구현은 **PATCH10.78 전용**이며 CD 입력은 명시적으로 거부한다. CD 대응 근거는 외부 선택 `004793d0`, 마크 계산 `00479860`, 선분 `0044d5e0`이며 CD 몸체의 이식·실행 대조는 아직 하지 않았다. 유효한 finite 좌표/TYPE/프레임/server SID·정상 크기의 발자국이 범위다. 손상 슬롯·범위 밖 프레임·정수 overflow·NaN을 정상 호출로 취급하지 않는다.

## 원본 관찰과 C++ 대조

현재 정밀 프로젝트에서 `fence-target` **46함수**를 읽기 전용으로 내보냈다. 마지막 디컴파일 수행 PC는 **VM-W11-Codex, 2026-10-15**다. `tools/decomp_fence_target.py`는 현재 지원 몸체 범위만 허용하며 **외부 함수 대체 없이** 실제 PE의 표적·선분·SHP·finder·가상 기본 필터·각도·CRT를 실행한다. 합성 TYPE/SHP·끝점·체인/해시·배율은 명시 입력이다. 실제 게임의 배리어 생성/Pop 전체를 관찰한 것으로 확대하지 않는다.

## 실제 창에서의 교전과 발견한 UI 결함

같은 실제 클라이언트에서 사제를 선택하고 화면 안의 칸을 클릭했다. 위치·HP·피격·스크립트 섹션을 직접 주입하지 않았다.

1. `(120,114)`에는 도착했으나 HP100을 유지했다. 실제 `sunArcher.type`의 사거리는9이며 이 지점은 적의 사거리 밖이다. `extracted/run33-ui-first/`에 보존했다.
2. `(124,114)` 클릭에서는 이동 프로세스가 시작되지 않았고94,108에 남았다. 원인을 단정하지 않는다. `extracted/run33-ui-combat/`의 입력·상태·이미지를 보존했다.
3. `(122,114)`에 도착한 뒤 실제 적 총의 공격으로 **같은 SID15000의 HP100→1**, 보호막/현재 안내 키가 발생했다. 탐색용 최초 자료는 `extracted/run33-ui-reachable/`다.

`tools/cpp_campaign_entry_smoke.py`에 `--combat`과 기존 자료를 보존할 `--output`을 추가했다. 최종 재현 명령은 다음과 같다.

```powershell
python -X utf8 tools/cpp_campaign_entry_smoke.py --combat --output extracted/run33-final
```

최종 **6회 모두 종료0·단언 통과**다. 1-1/1-2 미션 진입, Early1~3 raw 브리핑, 실제1-1 교전을 검사한다. 실제 좌표94,108→122,114·HP100→1·현재 충돌 자산160을 확인했다. 최종 게임 시계는0.191→28.032초다. 이전 `--movement --combat --output extracted/run33-entry`의7회에서도 이동과 교전을 확인했으며 당시에는 탄체83과 충돌160을 모두 관찰했다. 모든 묶음에서 허용 설정을 복구한 뒤 **originals 전체 파일 이름·내용 해시 불변**이다. 음향 장치는 사용하지 않았고 원본 게임 프로세스는 시작하지 않았다.

**안내 UI는 미완료다.** 스크린샷을 보면 HP1 보호막은 표시되지만 안내 창에는 이전 `Game` 버튼 글자만 남는다. 원본 `tell.english [PriestImmobile]`는 `<$Warning,"~B~E~yOur Priest has been Immobilized">`를 실행한다. 현재 UI는 이 명령을 처리하지 못하며, Kernel 도중 Tell 뒤 `Compose(false)`가 이전 버튼 라벨/입력 트리를 재사용하는 문제도 있다. 최종 검사는 잘못된 창/정지 상태를 정답으로 단언하지 않고, `warning_ui_verified=false`와 관찰한 phase/page/paused만 기록한다. **HP1 모델 교전의 성공과 원본 안내 표시·재개 규칙의 완료를 구분한다.**

다음 원본 근거: `Warning` 문자열 `00518124`의 등록 참조는 `00543398`, 명령 ID 저장소는 `00542afc`다. 실제 `004d62b0`의 해당 명령 분기는 **`004d3090(0x11,0)`**을 호출한다. `extracted/run33-warning-evidence.json`에 정적 문자열/등록 참조를 남겼다. 정확한 Warning 생성·텍스트/지속 시간·정지·닫기 규칙을 원본에서 확인하여 연결해야 한다. 일반 Tell 모달을 새로 만들어 우회하지 않는다.
