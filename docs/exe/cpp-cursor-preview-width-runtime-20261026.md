# 단일 커서 미리보기 DWORD와 실제 소비 경계 (단위452)

현재 PC와 마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon**, 마지막 수행일은 **2026-10-23**이다. 기준 HEAD는 `1ecdfa2a`다. 같은 호스트의 정밀 C·보호 PE를 읽기 전용으로 사용하고 디컴파일 산출물과 원본/CD 파일을 바꾸지 않았다.

## 재개와 완료 상태

2026-10-26 사용자 재개 요청으로 미완료 보존 커밋 `46e65408`에서 이어서 작업했다. **Source6/build6은 경고·오류0, 집중444개와 실제 단축키·회전·Drop·보충 GUI를 통과했다.** [실행 보고서](../../cpppj/cursor-preview-width-runtime-20261026.json)에 같은 제품과 원시 증거 SHA를 기록했다. 이전 중단 및 실패 로그는 그대로 보존한다.

## 실제 전역과 원문 순서

단일 `CursorDropState::preview`는 PATCH `0055a2a8`(CD `0051b658`)의 **4BYTE 전역**이다. 이미 DWORD가 된30칸 임시 목록과 별개로 이 필드만 호스트 `Sid`(16비트)였으므로 높은WORD를 보관할 수 없었다. 이를 실제 `uint32_t`로 바꿨다. Session·Client·준비 대여·Cancel·배치·품질 조회와 현재 보고는 같은 저장소를 사용한다.

원본 Drop `004473e0`(CD `0043d660`)은 잠금 → 위치 조회 → legal → 현재 미리보기 포인터 계산 → 준비/반올림/준비 → 강조/소리 → 실제 소비 순서다. 포인터 정수 계산만으로 자료를 읽지 않는다. 기존 호스트의 준비 전 미리보기 범위 검사를 실제 가상/로컬 배치/GUI 소비 위치로 옮겼다. 캡처한 DWORD는 준비가 현재 전역을 바꾸어도 유지한다.

실제 호스트 Pool에서 쓰는 SID16으로 바꾸기 직전에 전체 값을 검사한다. 높은WORD를 잘라 다른 유효 객체로 만들지 않는다. Lifecycle의 현재 번호, SourceAllowed와 생성 중 품질 조회도 실제 소비 위치에서 변환한다. 이 범위 검사는 지원되는 호스트 물리의 계약이며 원본의 임의32비트 포인터 감김·잘못된 Pool 역참조까지 복원했다고 설명하지 않는다.

## 제품 전에 고정한 Native 증거

[관측 도구](../../tools/decomp_cursor_preview_width.py)는 두 판본 × 두 x87 상태에서 **280관측**을 고정했다. 잠금/불법 위치 조기 반환, 첫 준비 경계에서 명시 중단, 유효50 캡처 뒤 현재 전역을0·65535·큰DWORD로 변경하는 입력을 포함한다. 정상240/명시 준비 중단40이며 정밀도 차이는0이다.

전체 Drop·반올림·잠금은 실제 원문 CPU다. 위치/준비·가상·로컬 배치 등 기존 큰 효과는 명시 장치를 재사용한다. 큰 번호를 실제 Pool에서 역참조하는 입력은 포함하지 않는다. [최초 fixture](../../cpppj/tests/fixtures/cursor-preview-width-x86.tsv)에 입력·사건·최종14필드를 고정했고 [Native 보고서](../../cpppj/cursor-preview-width-native-20261026.json)에 원문·도구·기존 함수 범위와 실제 SHA를 기록했다. 원본 게임 창·OS 호출은 실행하지 않았다.

## 검증 상태

기존 Native fixture를 유지하고 기존 검사의 입력형·출력형을 같은 숫자의 DWORD로 대응했다. **신규 6개를 모두 실제 실행했다.** 280관측 재생, 호스트 소비 실패의 선행 효과와 하위 WORD 비별칭, 실제 장기 주소·준비 보존, Cancel의 선행 효과와 실제 Client 첫 메뉴의 4BYTE 정리, 내용물 커서 비교가 통과했다.

제품 소비자 변경 전에 실제 PATCH `00447390` / CD `0043d4c0`의 내용물 커서 비교 leaf **56관측**을 추가 고정했다. 신규 C++ 검사는 값형·getter 두 경로로 112회 재생하도록 작성했다. 부모 번호 가상+0·Cancel은 명시 경계이며 전체 삭제·Cancel 검증으로 합산하지 않는다. 최초 관측의 가상표 입력 누락(unmapped read) 실패와 교정 성공 로그를 모두 보존했다.

## 실제 생산 UI 검증

`tools/cpp_production_shortcuts_smoke.py`에 선택형 `--data-root`를 추가해 원본 파일의 실제 복사본에서 기존 입력열을 실행했다. 실제 게임 SHA는 `471ec293a520bc3c519a5fd7d07ef3d9b09a3755a1f82cbc2af687e2527f2c92`이며 원본/CD 등 보호1,821파일은 동일했다. QWASZX 여섯 슬롯과 Y/E, 존재하지 않는 초기 슬롯, ESC 취소, 회전/반대 회전, 실제 합법 위치의 Drop, 새 서버 다리15211과 보충을 확인했다. 회전·배치 BMP도 육안 확인했다.

이 GUI는 기존 `useProductTimers=0` 설정과 WM_CHAR 이후의 실제 큐 입력을 사용했다. 미션 완주·원본 타이머 자연 완주·원본 픽셀/음향 동일성으로 확대하지 않는다. 다리 패턴·HP·SP·미션 단계의 직접 주입은 사용하지 않았다.
