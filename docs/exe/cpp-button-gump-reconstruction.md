## 상태와 생성

| 원본 위치 | 호스트 필드 | 용도 |
| --- | --- | --- |
| `+0x1c` | `GumpCreateNode.id` | 등록표 칸, 생성 이후 보존 |
| `+0x20` | `GumpCreateNode.command` | 기본 버튼 생성자가 쓰는 색 BYTE의 부호 확장 값 |
| `+0x2c` | `GumpCreateNode.serial` | 값 명령 대상 및 부모 통지의 버튼 식별자 |
| `+0xa0` / `+0xa4` | `value` / `pressed` | 저장 값과 임시 누름 상태, 전체 DWORD |
| `+0xa8` / `+0xac` | `blink` / `buttonFlags` | 점멸 상태와 버튼 플래그 |
| `+0xb0` / `+0xb8` | `firstDeadline` / `repeatDeadline` | 벽 시계의 double 초 예약 |
| `+0x100` | `background` | 돌 버튼 배경 토큰, 돌 버튼 전체 생성은 후속 |

기본 생성은 실제 `GumpCreate::Construct(token,0,0,0,1)`로 등록·serial·void를 준비한다. 기본 버튼 가상 표 `00503848`/`005017d8`, Gump 플래그 `0xa00`, 버튼 플래그, 두 상태/점멸/예약 0과 정수 크기를 설정한다. 저장소의 `form`/미작성 기본 필드 및 기본 생성자가 쓰지 않는 배경 필드는 보존한다. `ButtonGumpNode`는 의미별 호스트 저장소이며 원본 메모리 배치로 직접 캐스팅하는 타입이 아니다.

실행 중 사건 ID 네 개와 기본 색은 `ButtonGumpState`로 공급한다. `valueEvent/clickEvent/rightEvent/repeatEvent`는 각각 패치판 `005428b8/005427a8/00542740/005427b4`, CD `00512a40/00512930/005128c8/0051293c`다. 색 BYTE는 패치 `00540453`/CD `00535f88`이다. **초기화된 실제 전역을 공급해야 하며 기본값 0을 원본 사건 ID로 간주하지 않는다.**

## 입력과 상태 변화

| 입력 | 처리 |
| --- | --- |
| 비활성 버튼 입력 | 즉시 0, 다른 효과 없음 |
| 일치한 값 명령 | 전체 DWORD 값 지정→재그리기→현재 serial/값의 부모 click 통지, 이후 사건 분기 계속 |
| 일반 왼쪽 누름 | 필요하면 팝업 Kill→두 예약→첫 캡처→통지 플래그→idle 등록→pressed(1)→button.wav→재그리기 |
| 즉시 버튼 누름 | 토글이면 값 반전/통지, 일반 즉시면 기존 값 0일 때만 값 1/통지. 소리/재그리기는 매번 수행 |
| 일반 버튼 내부 뗌 | 토글이면 값 반전/통지, 일반이면 현재 pressed가 비영일 때 통지→통지/idle 해제→pressed(0)→재그리기 |
| 일반 버튼 외부 뗌 | 통지/idle 해제→pressed(0). 부모 click 통지와 마지막 추가 재그리기는 없음 |
| 도움말 포인터 없는 오른쪽 누름 | 필요하면 팝업 Kill→현재 serial/값의 부모 right 통지→1 |
| 그 외 입력 | 기존 기본 Gump 도움말 처리 경계로 위임, 반환 DWORD 보존 |

버튼 플래그는 비활성 `1`, 토글 `2`, 즉시 `4`, pulse `0x10`, 팝업 유지 `0x20`이다. 팝업 삭제는 등록표 0번의 직계 자식에서 `0x4000`·비 dead만 검사한다. visible/void는 필터가 아니며 next를 Kill 전에 보관한다. 실제 파괴는 `GumpLifetime`의 지연 Cleanup 단계가 담당한다.

돌 버튼의 두 상태 중 하나가 비영인지 쓰기 전에 저장하고 **부모 redraw 콜백 이후의 현재 두 상태**를 다시 읽는다. OR가 달라진 때만 현재 배경 `+0xb4`의 `0x40000`을 바꾸고 배경 redraw를 호출한다. 같은 값 쓰기도 부모 redraw는 생략하지 않는다. `VisualState`는 같은 트리의 경계와 전체 DWORD 상태를 기존 돌 버튼 출력 계획에 전달한다. 점멸 setter의 상태 변화 자체를 실제 화면 점멸 구현 완료로 해석하지 않는다.

## 통지와 idle

등록표 통지는 전달 사건과 별개로 왼쪽 버튼을 폴링한다. release이면 Gump 통지 플래그만 지운 뒤 전달 좌표로 상태를 계산한다. 일반 버튼은 내부 1/외부 0, 토글 버튼은 내부 `(value==0)`/외부 현재 value를 사용한다. 계산 값이 pressed와 다를 때만 가상 pressed 지정→두 예약 재설정→추가 재그리기를 한다. 비활성 여부는 여기서 제외 조건이 아니다. 즉시 버튼 통지는 원본 assert 계약 밖의 호출로 거부한다.

idle는 pulse 비트가 있으면 두 상태 비영 때 가상 pulse(0)를 호출하고, 두 상태 0·첫 예약 만료 때 점멸 반전 후 첫 예약을 **현재 벽 시계 +1초**로 잡는다. 이후 현재 플래그/pressed를 다시 읽어 비즉시·pressed 비영·두 예약 만료일 때 부모 repeat 통지 `(serial,1)`를 한 번 보낸다. 반복 예약은 통지 후 다시 조회한 시계 **+0.05초**다. 첫 눌림/통지 상태 변경의 첫 예약은 **+0.4초**다. 과거 프레임의 누락 횟수를 한 호출에서 보충하지 않는다.

시계 조회마다 원본과 같이 다시 호출하며 콜백 뒤 현재 필드를 읽는다. `SetPulse(false)`가 idle 표에서 제거해도 이미 진행 중인 이번 idle 몸체의 후반은 계속한다. C++ double/x87의 모든 극단 입력 반올림 일치는 아직 실행 대조로 확인하지 않았다.

## 화면→로컬 좌표

`GumpCollection::ScreenToLocal`은 `Position`의 정수 결과를 빼는 방식이 아니다. 화면 정수를 float32로 저장하고 부모가 있는 현재 노드의 float 위치를 뺀 뒤 매 단계 float32로 저장한다. 루트 자신의 위치는 빼지 않는다.

부모가 월드 부착이면 실제 기존 투영→부모 로컬 위치의 CRT 절삭→DWORD 덧셈으로 기준점을 만든다. 그 기준점을 빼고 이후 일반 부모의 로컬 위치를 생략한다. 이 단계에서는 자식 자신의 로컬 위치도 별도로 빼지 않는 원본 순서를 유지했다. 위치 캐시는 갱신하지 않는다. 잘못된 토큰·순환·월드 부착 부모의 루트 계약 위반은 호스트 예외로 거부한다.

## 연결 방법과 이름 충돌 수정

`BindButtonGump`은 사건/캡처 처리기의 handle와 프레임 idle/broadcast 훅을 감싼다. 호출 시 `resolve(token)`이 반환한 버튼 처리기를 쓰며, 그 외 토큰에는 기존 가상 처리를 유지한다. **훅을 처리기 객체 생성 전에 묶고**, 같은 상태/저장소로 GumpEvents→GumpInput→GumpFrame→ButtonGump를 만든 뒤 resolver가 참조하는 버튼 포인터를 설정한다. 도달할 수 있는 벽 시계·폴링·재그리기·소리·기본 도움말 경계와 돌 버튼 배경 플래그 저장소를 공급한다. 처리 도중 노드 주소는 안정되어야 하며 실제 해제는 지연한다.

기존 `Gump.h`의 메뉴 어댑터와 `GumpInput.h`의 복원된 트리 처리기가 같은 namespace/class 이름을 정의하는 C++ ODR 충돌을 발견했다. 메뉴 어댑터만 **`GumpControlInput`**으로 바꾸고 `Gump.cpp`·UberGump의 사용처·기존 MenuTests 두 선언을 갱신했다. 입력/메뉴 동작 본문은 유지했다. 새 테스트는 추가하지 않았다.
