작업일 **2026-10-15**, 현재 및 마지막 정밀 디컴파일 PC **VM-W11-Codex**. `AGENTS.md`와 양 LEFT를 재독하고 `a0e520e`에서 시작했다. 직전 사전준비 턴은 도구·산출물의 사용 가능성과 잘못된 CD 대응이라는 새 근거를 남긴 진척이다. 이번에는 실제 미션 진입 경로를 변경했다. 사용자 `TODO.md` 수정은 보존한다.

## 실제 클라이언트 연결과 스크립트 종류 교정

`UberGump::BeginMission`에서 `MakeCampaignClientServices`를 실제로 소비하고, 현재 화면 크기·보호 요새·실제 파일 시스템을 받는 raw `GameWorld` 생성자를 사용한다. 설정·번역·창 제목·음향·입력·Gump 갱신은 같은 Client에 연결한다. 기존 Battle의 `NotImplemented` 반환을 제거했다.

실제 창을 처음 실행했을 때 **1-1 `thewarbegins`와 1-2 `masterofwhirligigs`의 원본 `missionType`은 `Tutorial`**임을 확인했다. Battle 분기만 연결한 최초 변경에서는 1-1이 기존 관찰 어댑터에 남았고, 초기 검사 도구의 Battle 예상도 틀렸다. 당시 실행/도구/보고서/이미지는 `extracted/run32-entry-first/`에 보존했다. 지원하는 Tutorial·Battle 두 종류의 월드 생성 경로를 공통 raw 세션으로 교정했다. 튜토리얼 단계 판단 몸체의 복원을 완료했다는 의미는 아니다.

## 내용물 부모 가상 통지

`tools/decomp_content_notice_table.py`는 현재 `DerivedConstructors.inc`의 최종 VT와 기본 Squid VT를 수집하여 **두 보호 PE의 실제 VT+0x24 DWORD**를 읽는다. 자동 함수 대응표를 사용하지 않는다. 생성된 `ContentNoticeVtables.inc`의 범위는 다음과 같다.

| 판본 | 지원 고유 VT | 실제 빈 몸체 | 워커 | 다이스 | 워크샾 | Player |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 10.78 | 83 | 71 (`0041c100`) | 8 | 1 | 2 | 1 |
| 10.72 | 68 | 57 (`00401c20`) | 7 | 1 | 2 | 1 |

`RawContentParentNotice`는 부모의 현재 raw VT를 읽는다. 실제 기본 빈 몸체는 상태·owner·내용물 인자를 추가 조회하지 않고 반환한다. 파생 몸체는 실제 외부 소비자에 그대로 분배하며, 없으면 해당 진입점을 포함한 오류를 낸다. 알려지지 않은 VT도 명시적으로 거부한다. 모든 클래스에 빈 통지를 공급하지 않는다.

같은 세션의 `ContentFormHost`를 이 분배기에 연결했다. 초기 1-1/1-2 내용물을 가진 레인·윈드 신전은 실제 기본 몸체로 통과한다. 워커·다이스·워크샾·Player의 전체 파생 통지는 아직 세션에 연결하지 않았다. 기존 `RawDaisContentNotice` 등의 같은 월드 연결은 후속이다.

## 현재 Player의 실제 피해 통지

`RawPlayerDamageNotice`에 PATCH `00416760`의 challenge → signed owner<1 → 현재 Player `owner*0xb4+0xb0` AI 조회 → AI 피해 몸체 요청 순서를 복원했다. Player 바이트와 모드는 같은 세션의 저장소를 빌린다. AI가 NULL인 실제 자연 반환을 공급하며, 비영 AI에 실제 `00415460` 소비자가 없으면 오류를 유지한다. 호스트 경계로 잘못된 Player 저장 크기와 owner≥9를 거부한다. 유효 Player9의 원본 주소 산술이 0으로 감기는 비정상 포인터 배치는 지원하지 않는다.

원본 기계어에서 AI 호출은 **ECX=AI, 스택=(victimSid, attackerSid)**의 `__thiscall`이다. 디컴파일 C의 추정 인자형을 ABI로 그대로 사용하지 않았다. CD의 `004aaa20`은 삭제 표식 setter이므로 이 래퍼의 CD 대응으로 사용하지 않는다([사전준비 기록](cpp-prep-vmw11-20261015.md)). 이번 클래스는 PATCH 전용이다. CD 사제 피해의 AI 경로와 실제 AI 판단 자체는 미복원이다.

캠페인 세션의 기본 피격 서비스를 실제 래퍼로 연결했다. 기존 캠페인 검사에서 내용물 통지와 owner 피해 통지 모의를 제거했다. 실제 Player AI가 아직 생성되지 않은 현재 상태를 읽으며, AI의 부재를 영구 게임 규칙으로 고정하지 않는다. Ready/login과 AI 생성이 이어져야 한다.

## 원본 관찰과 C++ 검사

현재 정밀 프로젝트에서 읽기 전용 `campaign-notices`를 **PATCH2/CD1함수** 내보냈다. 마지막 디컴파일 PC는 **VM-W11-Codex, 2026-10-15**다.

`tools/decomp_campaign_notices.py`가 새로 관찰한 고유 루트 입력은 **156개**다.

- PATCH 피해 래퍼 144개: owner 음수/0/1~8·challenge·현재 NULL/비영 AI·두 SID 조합. 실제 AI 호출 요청 24개를 ECX/스택에서 관찰한다.
- 실제 기본 빈 통지 12개: 두 판본 각6개. 부모 raw 전체 불변을 확인한다.
- 정상 EIP·ESP 반환, EBX/ESI/EDI/EBP 보존, Player 전체 바이트 불변, assert 도달0을 확인했다. 게임 규칙 AI 몸체 `00415460`은 실행하지 않았으며, 이 진입점의 호출 인자 관찰만 명시 외부 경계로 삼았다. 복원/관찰 범위는 래퍼다.

최초 Native 결과의 TSV 머리말을 C++ fixture 공통 로더의 `#` 주석 형식으로 교정했다. 교정 전 자료는 `extracted/run32-native-first/`에 보존했다. 재실행은 같은156개 입력이며 새 고유 입력으로 중복 합산하지 않는다. `campaign-notices.json`은 최종 보호 PE·정밀 범위·도구/helper·fixture SHA를, `content-notice-table.json`은 생성자 표·도구·실제 VT 분배 표 SHA를 기록한다.

새 `CampaignNotice` **4개**와 실제 `CampaignSession` **5개**가 통과했다. 기존 실제 교전의 최초 피해173/HP1 178/종료898프레임도 유지한다. 이 교전 검사는 fencemark 코너를 여전히 명시 외부 입력으로 공급하며, 실제 UI 전투 전체의 증거로 확대하지 않는다.

Release 게임/검사 빌드 성공이다. 최초 검사 소스의 `std::fill` int→BYTE 경고를 `std::uint8_t` 입력으로 교정했으며 최종 증분 빌드는 경고·오류0이다. 최종 전체 CTest는 **1/1 통과, 내부1,152개·실패 체크0**, 검사118.65초/전체118.73초다.

두 캠페인은 브리핑 정지→실행 상태와 같은 raw 객체/Kernel을 확인했다. Early1~3은 실제 raw 세션의 최초 브리핑까지 확인했다. 1-1/1-2 실제 화면을 열어 그림·지형·초기 카메라를 시각적으로 확인했다. 원본 화면과의 독립 전수 픽셀 대조는 이번 범위에 포함하지 않는다.

1-1의 추가 이동은 실제 사제 클릭과 `cell:90,108` 클릭을 사용한다. 같은 SID15000이 94,108에서 목표90,108에 도착하고, 실제 원본 세션 시계와 Kernel이 2,000번의 화면 루프 동안 진행한다. 공통 장부/PreDestroy/PostDestroy 깊이0과 정상 종료를 확인한다. 긴 실행 stderr에는 실제 PlayerRegular 진단 `[29] SORE LOSER TEST ... STARTING.`이 출력되므로, 오류와 구별하여 로그에 보존한다.

최초 별도 이동 관찰은 원본 게임 시계0.193→36.914초였고 `extracted/run32-movement/`에 보존했다. 재현 가능한 최종 도구는 `extracted/run32-entry/thewarbegins-movement/`에 별도 저장한다. 창 입력은 경로/HP 결과를 직접 바꾸지 않는다. 보호 설정은 허용 파일만 복구하고, 실행 전후 **originals 전체 파일 이름·내용 해시 불변**을 확인한다.

통합 이동 도구의 최초 단언은 객체 보고 열을 y/프레임으로 잘못 지정했다. 실제 캡처 상태에는 목표 도착이 있었으나 단언이 실패했으며, `extracted/run32-entry-movement-first/`에 도구·실행 결과를 보존했다. 객체 필드의 실제 x/y인 `[5:7]`로 교정해 재실행했다. 원래 별도 도구도 같은 잘못된 열 조각을 비교했으므로, 그 도구의 이동 단언을 최종 증거로 사용하지 않고 저장된 전체 상태와 교정한 통합 검사를 사용한다.

교정한 최종 **6회 모두 정상 종료·단언 통과**, originals 전체 불변이다. 최종 이동의 실제 게임 시계는 **0.197→40.369초**, 좌표는 **94,108→90,108**이다. 최종 로그는 `extracted/run32-entry-verified.log`, 전체 결과는 `extracted/run32-entry/results.json`이다.

## 재개 지점과 한계

실제 진입과 사제 이동을 같은 raw 세션에 연결했다. **Early Missions/1-1~1-2 완주 동일성은 계속 미완료**이며 목표active와 원본 DirectDraw 전체화면 오류 제외를 유지한다.

- 다음은 실제 fencemark 표적 코너 및 경계 기하를 연결하여 UI 전투를 진행한다. 상수 무효 좌표를 실제 구현의 기본값으로 공급하지 않는다.
- Ready/login·Player SP/색/기술/현재 UI의 저장소 통합, 실제 AI 생성과 피해 반응이 남는다.
- 내용물 파생 통지, 운반·수확·생산·건설·다리 입력/배치, 튜토리얼 단계 판단·안내·승패·진행 저장을 실제 미션에서 이어간다. 현재 객체 메뉴의 Construct는 여전히 비활성이다.
- 오디오 장치·원본 라이브 플레이·전체 화면/입력/원본 그림 전수 동일성을 이번 짧은 진입 검사로 주장하지 않는다. 이번 초기 이동은 적 총의 피격 상황을 만들지 않았다.
