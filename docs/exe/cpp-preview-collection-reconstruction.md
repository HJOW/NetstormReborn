`PreviewCollection`은 실제 `SidPool` raw 조각 목록·선택 타입·부모 깊이·spot 표에서 kind 4 두 레이어를 수집한다. `BindPreviewCollection`은 공통 목록의 마지막 수집 슬롯에 연결한다. 준비된 실제 `ScrambledSpStore` 읽기도 연결했다. 커서 조각 생성/입력, preview Draw와 Client 자동 프레임은 후속이다.

## 원본 근거와 부분 출력

| 내용 | 10.78 | CD/추가판 |

잠금이 있거나 signed 목록 count가 0 이하이면 출력/피드백에 접근하지 않고 0을 반환한다. 각 반복의 시작에서 **현재 count와 limit**을 읽고 `limit < 1`일 때만 멈춘다. viewport 인수 네 개는 원본 몸체에서 사용하지 않는다. type/state/프레임/SHP 교차에 의한 일반 자산 수집의 필터도 적용하지 않는다.

각 후보는 현재 작업 칸에 raw XY·객체 토큰·깊이 **14바이트를 먼저 기록**한다. 뒤의 배치 판정에서 건너뛰어도 이 기록을 되돌리지 않는다. kind/tail 두 바이트와 반환 count는 그대로이며 다음 후보가 같은 칸을 덮어쓴다. 마지막 후보가 실패하면 반환 수 뒤의 미사용 칸에도 이 부분 기록이 남는다.

깊이는 선택 타입의 DWORD zOrder 하위 WORD, 부모 Gump가 있으면 그 깊이-9다. 선택 타입 flags2의 surface bit 4가 -1로, island bit `0x400000`이 -20으로 덮어쓰며 **island가 우선**한다. raw 조각 자신의 깊이 BYTE를 쓰지 않는다. 모든 결과는 WORD 넘침과 signed 해석을 보존한다.

## 배치 칸과 두 레이어

raw 타입이 두 특수 타입 전역 중 하나와 같으면 legal이 0일 때 건너뛴다. legal이 있으면 별도 커서 배치 XY에 **단정도 0.9999**(`0x3f7ff972`)를 x87에서 더하고 CRT 64비트 절삭 하위 DWORD로 칸 주소를 만든다. +0.5나 합의 float 저장을 사용하지 않는다. spot 주소는 DWORD `x + (y << 8)`이며 양 축을 독립적으로 클램프하지 않는다. `spot & 2`이면 건너뛴다. 나머지는 본체 깊이만 **20**으로 바꾼다.

제출되는 본체는 kind 4/tail 0이고 보조 레이어는 kind 4/tail 2다. 보조 깊이는 **원래 기준 깊이-1**이므로 본체가 20이 된 경우에도 19로 바꾸지 않는다. XY는 판정 전에 저장한 raw 값을 사용하고 보조 토큰은 현재 목록 SID를 다시 읽는다. 다음 반복도 현재 count를 재조회한다.

한 쌍을 기록한 뒤 count를 2 늘리고 limit를 2 줄인다. 따라서 limit 1에서도 **2개를 반환**한다. 이는 행/일반 자산 수집의 strict assert와 다른 동작이다. C++는 실제 span에 두 칸이 없으면 이미 쓴 후보 14바이트를 남긴 채 예외로 거부한다. 이 경우 패치 피드백과 완성 kind/tail을 쓰기 전에 멈춰 원본의 배열 밖 쓰기를 막는다. 공통 호출자는 실제 남은 span을 전달한다.

## 패치 피드백과 실제 연결

실제로 제출하는 쌍마다 다음 순서로 상태를 갱신한다. 건너뛴 후보/잠금/제한 종료에서는 갱신하지 않는다.

1. SP 저장소 offset과 복사 offset이 다르면 강조 시각에 현재 시각 비트를 쓴다.
2. countdown이 비영이면 querySp가 비영인 경우 현재 플레이어의 SP DWORD를 읽는다. 이를 float 비트로 해석한 **ordered >7000**일 때 강조한다. NaN/정확히 7000은 강조하지 않는다. 이후 countdown을 DWORD로 한 번 감소시킨다.
3. 첫 SP 배열 포인터가 없거나 첫 순열 WORD가 -1이면 강조한다.

CD/추가판은 이 상태를 바꾸거나 SP를 읽지 않는다. `MakePreviewSpHooks`는 **초기화한 실제 저장소**만 받는다. 상위 계층은 그 offset/첫 표 상태를 수집 상태에 공급한다. lazy 초기화의 전역 변경과 Cursor 전체 상태 연결은 이번 범위가 아니다. 저장한 원본 관찰도 초기화를 마친 SP 저장소의 getter 전체를 실행한 결과다.

부모 Gump 깊이와 SP 읽기는 사용하는 분기에서만 필요하며 누락하면 예외로 거부한다. 0/풀 밖 SID, 짧은 현재 목록, 없는 타입, 표 밖 spot 주소, 출력 부족과 대리 토큰의 32비트 범위·정렬·유효 SID도 검사한다. 상태/풀/타입/spot은 수집기보다 오래 살아야 한다. 공유 상태를 바꾸므로 동시 호출은 지원하지 않는다.

실제 UI 트리·지면 0단계·일반 자산 3단계·미리보기 목록을 같은 공통 수집과 CRT 정렬/종류 분배에 연결했다. 높은 깊이 UI→미리보기 두 레이어→그림자/본체→지면 순서와 tail을 확인한다. 화면 밖 raw 미리보기도 수집하며 UI 전용 dirty에서는 목록과 countdown을 건드리지 않는다. SP 경계가 목록/타입을 바꾸는 별도 host 계약 검사에서는 보조 토큰의 현재 조회와 저장 XY/깊이를 확인했다. 이것은 native getter가 실제로 목록을 변경했다는 관찰이 아니다.
