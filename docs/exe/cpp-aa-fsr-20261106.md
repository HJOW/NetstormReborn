# 7차 안티앨리어싱 / FSR 1.0 선택 옵션과 2560×1440·3840×2160 해상도 (단위939)

2026-11-06, HJOW-Athlon. AGENTS.md 7차 요구의 구현이다: 메인 메뉴 Options에서 **안티앨리어싱**과 **FSR 1.0**을 각각 선택(기본 꺼짐)하고 게임 화면에 적용하며, FSR을 쓸 수 있는 환경에서는 해상도 목록에 **2560×1440과 3840×2160**이 나타나고 이 해상도를 고르면 FSR이 자동으로 켜져 **실질 해상도 1920×1080을 FSR로 업스케일**한다. 마지막 정밀 디컴파일 호스트는 변하지 않았다(HJOW-Athlon, 2026-11-03). 원본 10.78에는 없는 **전부 클론 추가 기능**이며 옵션이 꺼져 있으면(기본) 기존 GDI 경로가 그대로다.

## 구조

| 구성 | 내용 |
| --- | --- |
| 서드파티 | `third_party/fsr1/`에 AMD FidelityFX FSR 1(공식 `ffx_a.h`, `ffx_fsr1.h`, MIT 라이선스)을 **수정 없이** 보관한다. 출처 커밋/SHA-256은 `README.ko.md`. 배포판은 `third-party\fsr1\`로 동봉한다. |
| 상수 | `client/FsrConstants`: 공식 헤더의 CPU 경로(`A_CPU`)로 `FsrEasuCon`/`FsrRcasCon` 상수를 계산한다(GPU/게임 없이 검사 가능). |
| 출력기 | `client/GpuPresenter`: Direct3D 11(하드웨어, 안 되면 WARP 소프트웨어). 8비트 팔레트 논리 프레임을 올려 **팔레트 변환 → (선택)안티앨리어싱 → (선택)EASU → RCAS → 레터박스 출력** 패스를 그리고 스왑 체인(flip discard)에 표시한다. 셰이더는 런타임 `D3DCompile`이며 AMD 헤더 바이트는 빌드 때 CMake가 C++ 배열(`build/src/generated/FsrShaderHeaders.cpp`)로 만들어 실행 파일에 넣는다. EASU/RCAS 본체는 AMD 원본 `FsrEasuF`/`FsrRcasF`를 그대로 호출한다. |
| 안티앨리어싱 | 논리 해상도에서 휘도 대비가 큰 가장자리를 수직 방향 이웃과 섞는 FXAA 3.11식(부분 화소 섞기만 단순화) 후처리다. |
| 화면 | `Screen::SetPostProcess(fsr, aa)`가 출력기를 만들거나 없앤다. 켜져 있으면 `Update`가 GDI 대신 완성 프레임 전체를 GPU로 표시하고(실패하면 이유를 stderr에 남기고 GDI로 복귀) `PresentationRect`/`ToLogicalPoint`가 창 모드에서도 비율 맞춤/입력 역변환을 한다. `SetPresentSize`로 표시(창 클라이언트) 목표 크기를 받아 테두리 없는 창 판정/크기를 그 기준으로 정한다. |
| Client | 설정 `antiAliasing`, `fsr1`(없으면 0=꺼짐). `SCREENW/SCREENH`는 **표시(목표) 크기**이고 FSR 해상도는 논리 1920×1080(`LogicalScreenSize`)으로 그려 FSR이 늘린다. 후처리 장치가 없으면 FSR 해상도 설정은 1920×1080으로 낮춘다. `ApplyPresentationOptions()`가 시작/해상도 변경/옵션 메뉴 토글 직후 적용한다. `NETSTORM_NO_GPU=1`이면 후처리를 쓸 수 없다고 본다. |
| 메뉴 | 옵션 팝업(메인·게임 중)에 **Anti-Aliasing**, **FSR 1.0 Upscaling** 토글과 해상도 목록의 FSR 두 행을 후처리 장치가 있을 때만 추가한다(원문 구성/918 관측은 훅이 꺼진 기본에서 불변). 현재 해상도 체크는 표시 크기를 기준으로 한다. 한국어 번역표에 두 항목을 추가했다. |
| MCP | `netstorm_screenshot`에 `presented=true`를 추가했다. GPU 후처리가 실제 표시한 클라이언트 영역 전체를 RGBA PNG로 돌려준다(꺼져 있으면 논리 화면). |

## 확인

- **단위 검사:** `netstorm_fsr_tests` 5/0(EASU/RCAS 상수가 공식 정의와 일치, 숨은 창에서 장치 생성→셰이더 컴파일→4가지 AA/FSR 조합 표시→읽기, 균일색 보존·레터박스 검정·창 크기 변경 추적·잘못된 인자 거부), `netstorm_screen_resolution_tests` 3/0(FSR 해상도는 허용 여부가 있을 때만 지원·논리 1920×1080·기존 8개 불변), `GameMenus_OptionsPostProcessEntriesOnlyWhenEnabled`(기본은 원문 구성, 켜면 FSR 두 행·두 토글이 현재 표시 크기/설정으로 체크), 기존 `GameMenus_Native918`/`netstorm_mcp_parts_tests`/`korean_text`/`user_data_root` 불변. `main_popup`·`renderer_presentation`의 실패 1개는 기존 `CampaignSaveGoMain_*`(HEAD 기준선에서도 같음)다. 빌드 경고/오류 0.
- **실제 실행(창 모드, MCP 화면 PNG):** (1) 옵션 꺼짐 기본에서는 논리 화면 PNG 그대로이고 `presented=true`도 논리 화면으로 돌아온다(GDI 경로 유지). (2) `--set SCREENW=2560;SCREENH=1440`에서 논리 1920×1080, 창 클라이언트 정확히 2560×1440, `presented` 캡처가 RGBA 2560×1440이며 FSR 업스케일(EASU+RCAS) 결과를 육안으로 확인했다(디더링된 팔레트 그림이 매끈하게 늘어남). (3) 옵션 팝업에 Anti-Aliasing / FSR 1.0 Upscaling이 보이고 각각 눌러 켜면 체크 표시가 생기며 출력이 GDI에서 GPU 경로(RGBA)로 바뀌고 FSR은 1:1에서도 EASU/RCAS를 거쳐 화소가 달라진다. (4) 하드웨어/소프트웨어(WARP) 중 어느 장치였는지는 이번 실행에서 기록하지 않았다(`GpuPresenter::AdapterName`으로 확인할 수 있다).
- 배포: `package-cpppj.ps1`이 `third-party\fsr1\`(MIT 라이선스·출처·헤더)를 동봉하고 안내문에 옵션을 적는다(DryRun 확인).

## 알려진 한계·후속

- **미션/월드 화면의 후처리 확인은 하지 못했다.** 메인 메뉴·옵션 화면에서만 확인했고 미션 HUD/맵 화면, 전체화면 모드(비율 레터박스·가장자리 스크롤·커서 제한), 실제 4K 모니터의 3840×2160 표시, 창 모드 입력 좌표 역변환(`ToLogicalPoint`)은 사용자 플레이 확인 대상이다.
- 후처리가 켜진 동안 `Screen::Update`는 변경 영역과 무관하게 매번 완성 프레임 전체를 GPU로 올린다(1920×1080 8비트 한 장+팔레트). 프레임당 `Update`가 여러 번 불리면 낭비이며 필요하면 프레임 끝 한 번 표시로 합치는 최적화가 후속이다. 소프트웨어(WARP) 장치에서 3840×2160 FSR은 느릴 수 있다.
- 안티앨리어싱은 FXAA 3.11 정확 구현이 아니라 단순화한 윤곽선 섞기이며 효과가 약하다(디더링된 팔레트 그림 특성). 세기/알고리즘은 사용자 취향 조정 대상이다.
- 로딩 화면(`PaintLoading`)과 일부 GDI 직접 그리기는 후처리 장치 이전/바깥 경로라 후처리가 켜진 뒤에는 보이지 않을 수 있다(첫 프레임 이후 GPU가 덮는다).
- FSR 해상도는 `SETSIZE` 흐름(설정 저장·종료 뒤 재실행)으로 적용되며, 후처리 장치가 없는 환경에서 설정이 남아 있으면 1920×1080으로 낮춰 시작한다. 선택 목록에서는 장치가 없으면 보이지 않는다.
- ARM64 Windows 11에서 Direct3D 11 후처리는 같은 코드로 가능하나 이번에 빌드/실행하지 않았다.
