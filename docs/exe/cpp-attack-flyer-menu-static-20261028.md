## 원문 조건과 현재 연결

1. 공통 Open004adb30은 raw+40의 건설 중 비트1에서 거부한다. 그 외에는 Fancy 시작→현재 객체 정보004ada70→실제 가상+a8 순서다. 현재 `RawObjectMenuOpen::Open`과 Client의 `Dispatch/Populate`가 같은 순서로 연결된다.
2. 세 타입은 공통 Damageable0044cbd0이다. 소유자가 현재 로컬일 때 TYPE를 먼저 보관하고 실제 가상+80의 count를 읽어 회수 작성0044ca00에 전달한다. 현재 Session은 이 VT들의 공통 level getter를 사용한다. 이어서 공통 Object004b1270을 작성한다.
3. 회수 항목은 소유자 일치만으로 항상 나타나지 않는다. 현재 TYPE의 flags2 0x200·성장 레인 블로커 여부·cost, 크리스탈 제외 및 Editor 여부, DenySalvage·회수 종류·억제 TYPE 등 원문 조건을 거친다. 현재 `RawObjectMenu::AddSalvage`가 이를 처리한다. 이번 정적 대조로 세 타입의 모든 실제 자산/모드 조합에서 회수 항목이 보인다고 단정하지 않는다.
4. 공통 Object는 일반 모드의 Help, 소유자가 있으면 Player 하위 메뉴를 작성한다. Editor에서는 Destroy, 특수 모드/missionPost에서는 원문의 CHEAT 항목, Editor/특수 모드에서는 Set Owner 조건이 추가된다. 현재 공통 작성기에 연결되어 있다. 공중 공격형만을 위한 Move/Attack 항목은 이 원문 체인에서 발견되지 않았다.
5. Open의 위치 분기는 작성 후 현재 TYPE.flags2의 0x30100 마스크다. 기존 정적 자산 기록의 세 타입 flags2는 0x00100000이므로 이 분기에서는 사건의 클릭 좌표에 붙인다. 이동 운반체 전용 선택/위치 조정을 대신 적용하지 않는다.

기존 `RawPlainUnitCapture`에도 세 TYPE/VT 쌍이 있고 `RawCampaignFactoryDisplay`의 일반 표시 경로로 연결된다. 이 사실은 표시 분배의 정적 존재만 뜻하며 생산·공격·우클릭 픽셀 재현을 입증하지 않는다. 이번 단위의 코드 변경은 슬롯 표에 대상과 검증 한계를 설명하는 한국어 주석을 추가한 것이다. 동작 차이가 확인되지 않은 공통 메뉴 몸체는 유지했다.
