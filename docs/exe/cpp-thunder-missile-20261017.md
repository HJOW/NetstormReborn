# 썬더 캐논 실제 포구·종점·투사체 — 단위103

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 단위102의 데모3 `DissolvedAlliance`는145프레임/3.625초의 TYPE131 생성 제한에서 멈췄다. 이번에는 같은 원본 생성/이동 몸체에 실제 썬더 경로를 연결한다. 새 디컴파일·실제 원본 게임/GUI 실행은 없다.

## 원본의 방향과 포구

TYPE131의 생성자 `0046ae50`은 vtable `0050bad0`을 기록한다. 보호 PE의 `0050bad0 + 0xb4`는 **`0041c110`**이며 원시 `+0x0e/+0x12` 좌표 두 DWORD를 복사한다. 썬 캐논128·크로스보우140과 같은 getter이고, 썬 디스크 발사기71의 SHP 포구 두 개 합산과 다르다. Missile 생성자는 그 뒤 현재 SHP hotspot을 더하고 TYPE hotspot을 빼는 기존 두 단계 float 저장을 그대로 수행한다.

실제 `00481750`은 썬 캐논에서 허용 프레임 표를 사용한다. 다른 총에서는 `0045ae60 → 004d4d00 → 004ad680`으로 현재 프레임 문자를 읽는다. signed 문자값×2−152가0..7 밖이면0으로 바꾼다. L/M/N/O는 각각0/2/4/6이다. 조준 방향과 다르면 절삭한 현재 사거리·원본 방향 표·정수 곱 감김·1..255 clamp로 종점을 보정하고 현재 방향의 축에 고정한다. 같은 방향이면 현재 표적 축을 유지한다.

`RawProjectileGeometry`는 같은 풀의 기존 `RawGunMode`를 참조한다. 별도 프레임 방향 캐시나 팬게임 규칙을 추가하지 않았다. 다른 풀의 모듈은 거부하며 썬더 방향 getter 누락도 오류로 보고한다. Session은 이미 소유하는 현재 getter를 전달한다. `RawMissile`은10.78의 두 group1 부모128/131을 같은 생성/충돌/만료 경로로 분배한다. 반사·직접 지정 포구·빗나감 등 미복원 분기는 기존 명시 오류를 유지한다. CD10.72에 새 썬더 분기를 합성하지 않는다.

첫 C++ 대조는 생성/포구/종점은 일치했지만 비행의 사거리 만료 일부에서 달랐다. 실제 원본 `00540bb4/00540bb8`은 **일반4/썬더10**이다. 기존 제품은 썬더에도4를 적용해 조기 갱신/삭제와 충돌음 누락이 발생했다. 원본처럼 Pop 전에 현재 정수 여유를 float에 저장하고 일반/코너의 해당 분기에 사용하도록 고쳤다. 기대값은 바꾸지 않았다.

자연 데모는 생성145프레임을 통과한 뒤159프레임의 삭제에서 멈췄다. 최초에132로 추정했던 설명은 **타입/SID 진단으로 TYPE80·SID160임을 확인해 정정**했다. 선행 썬 미사일80의 기본 가상 표 `00501dd0`를 같은81의 실제 공통 삭제에 한정해 연결했고 부모가 부착한 Fiery Tail도 정리한다.

또한 실제132는83과 같은 `0046a6c0/0050b570`을 사용한다. 그 가상 `+10/+14/+18/+24`는 각각 `004af780/004b0950/004b0840/0041c100`이다. 같은 타입/가상 표가 일치할 때 기존 실제 공통 삭제로 분배하도록 연결했다. 다른 타입 전체를 공통 삭제로 넓히지 않았다. 자연 검사는80의159프레임 종료와132 자신의 후속 종료를 구별한다.

## 실제 보호 자원과 독립 관찰

`originals/netstorm.tarc`의 `thundercannon.type`은 group cannon·사거리42, L/M/N/O 각각9프레임이다. 각 구간 마지막 물리 번호는8/17/26/35다. `thundercannonmissile.type`은 **orientations4·실제 클러스터12개**, 따라서 방향당3프레임이며 표시 TYPE132다. 일반 launch의 비행 효과는0이다. 썬 캐논의 process11을 썬더에 잘못 붙이지 않는다.

실제 RiftType 원본 loader도 **`fireSound`**를 읽는다. Session이 존재하지 않는 `firingSound`를 조회해 발사음을 놓치던 오류를 고쳤다. 원본/보호 자원에 별칭은 없다. 실제 데모에서 무기131의 `thunderCannon.wav` 토큰이 전달되는지도 확인한다. 생성자의 무기 사운드 우선·표시 사운드 fallback 순서는 기존 원본 대조 몸체를 유지한다.

새 `tools/decomp_thunder_missile.py`는 기존 썬/크로스보우 fixture를 바꾸지 않고 별도 원문을 만든다. 실제 `00481a50` 생성자·`00482340` 프레임과 포구·사정선·타입/group·문자 방향·치수/중심·좌표·거리·방향 프레임·rectangle·CRT helper를 실행한다. SHP hotspot 자료/자산 가상 생성·소유자·공간/소리·피해·갱신/일반 충돌 상자는 명시 외부 경계다. 기대 결과를 Python으로 계산하지 않는다.

`ThunderMissileTests`는 같은 입력을 실제 `RawGunMode`·`RawProjectileGeometry`·`RawMissile`로 실행해 전체 원문이 일치했다. 보호 데모 자원의 자연 생성 검사는 총/표적/HP/난수를 바꾸지 않고145프레임을 진행한 뒤 같은 Kernel의 TYPE132·28 Form과 효과11 미부착·실제 발사음 전달을 확인했다. 썬80/Fiery Tail은159프레임/3.975초, 썬더132는244프레임/6.1초에 자연 삭제되고 원래 Kernel/표시 토큰이 정리된다. 두 종료를 혼동하지 않는다.
