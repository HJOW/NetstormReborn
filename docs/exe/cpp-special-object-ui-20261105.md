# 특수 대상 메뉴·전환과 선택된 스펠 삭제의 UI 수명 (단위913)

선택된 스펠을 삭제하면 이미 반납된 사정거리 ProcessForm을 다시 조회해 오류가 나는 문제를 수정했다. 삭제 효과를 일반 선택 함수 Select(0)에서 원문 별도 선택 해제 ClearSelection으로 바꿨다. 요청된 UI1번의 크리스탈/비석·스펠 메뉴를 제품의 같은 Client·Session·controlled 트리에서 확인한다.

## 원인과 원문

- 현재/마지막 전체 정밀 디컴파일 호스트는 HJOW-Athlon / 2026-11-03이며 정밀 산출물은 수정하지 않았다.
- PATCH004af780은 종속 release/destroy 뒤 현재 선택과 자신을 비교하고 **004af9c2에서004d5c60**을 호출한다. CD004ab7e0도 **004ab9e1→0041ed70**이다. 보호 PE 실제 call 명령을 읽어 확인했다. 일반 선택004d5c90/CD0041eda0을 호출하지 않는다.
- 별도 Clear는 enabled 관문 뒤 다중 선택 정리→현재 선택0→강조0이며 이전 선택의 종속 프로세스를 다시 훑지 않는다. 일반 Select(0)는 이전 마나/사정거리 프로세스에 통지하므로 삭제 후 이 경로를 호출하면 반납된 PID를 조회한다.
- 제품 GameWorld의 ClearSelection 효과 callback만 올바른 별도 ClearSelection으로 수정했다. 일반 선택/ESC/초기화의 Select(0) 경로는 유지한다.

## UI 검증 범위

창이나 Netstorm.exe 프로세스를 실행하지 않고 같은 보호 자산과 실제 CampaignObjectMenuClient·현재 VT+a8/+ac·Gump/StyleText·선택/사정거리/입력 큐·Session 가상6c를 사용했다. dump만 현재 SID를 기록하는 명시 장치이며 실제 진단 창/파일은 만들지 않는다.

- 크리스탈154: 일반/편집2 × raw owner0/1/2/8의8입력에서 About/Player/Destroy 조건, Dig Up/Turn To Spell 부재와 About 클릭의 TYPE154 인자를 확인했다. 실제 GumpForm/부모 참조·원래 head/전체 대상 바이트/풀 수량과 팝업 반납도 확인했다.
- Devastation114↔비석112: 네 소유자의 편집 메뉴 클릭8회에서 명령030000ce와 대상 SID를 실제 입력 큐로 받고 같은 가상6c를 실행했다. SID·좌표·소유자·HP, 비석 QA114/frame0을 보존하고 같은 메뉴를 다시 열었다. 정상 모드의 Detonate 소유자 조건과 개발자 Dig Up 부재를 확인했다. 명령의 freeCount는 선택 UI의 합법적 사정거리 할당 이후·명령 직전에 저장한다.
- 비선택 크리스탈과 선택된 스펠의 대상 삭제에서 실제 Form 통지→팝업 Kill→지연 Cleanup을 확인했다. 선택된 스펠의 Range51/Kernel과 실제 단일·다중·강조 상태가 정상 정리된다.
- 최종 새4사례의 실제 메뉴 작성은22회·controlled 클릭16회·전환8회다. 명시 대상/모드 입력이며 자연 도달·픽셀 선택기/물리 마우스·OS 창/픽셀 동일성을 증명하지 않는다. 기본 GUI 메뉴/Help와 Edit 전환·저장 이력은515/517/525의 당시 증거로 유지한다.
- special55a480을 켜거나 CHEAT Dig Up을 강제로 노출/클릭하지 않았다. 합법적 special 진입의 실제 Dig Up 효과는 여전히 별도 잔여다.

## 실패 기록과 최종 결과

첫 새3사례 중 크리스탈/비선택 대상 삭제2개는 통과했고 전환은 선택 장치 부재로 실패했다. 제품 선택 연결을 보충한 두 번째 검사는 독립 Client dump의 미초기화 물리 조회로 실패해 dump만 명시 관측 장치로 분리했다. 세 번째와 단계 기록을 추가한 네 번째 실행은 실제 제품의 삭제 후 ProcessForm/PID 오류를 재현했다. 원문 call을 확인해 제품을 수정하고 선택된 스펠 삭제 회귀1개를 추가했다. 이전4명령/10사례 실행/실패 단언4를 보존했다.
