# Early5 썬더 투사체의 실제 피격 명령 생산자

2026-10-19 단위207. 기준 `dc362a77`, 현재·마지막 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-19**다. 원본 게임이나 OS 코드는 실행하지 않았다. 앞 단위에서 확인한 REA의 H: 경로 속성 조회 실패를 반복하지 않고, 같은 PC에서 재생성한 정밀 본문과 보호 PE를 사용했다.

## 원본과 구현

10.78 `00482340`은 실제 충돌이 확인되면 효과·소리 처리 뒤, 이전 위치 저장과 직접 피해·표시 삭제 전에 표시 타입 `00541268=132`와 표적 타입 `00541190=78`을 비교한다. 일치하면 `00452fe0(005429c8=020000b5,132,78)`를 호출한다. 인자는 SID가 아니라 타입이다. 코너 충돌도 이 분기를 지난다. 기존 `RawTutorialLater`의 Early5 A단계는 이 명령과 두 타입을 읽지만, `RawMissile`에는 생산자가 빠져 있었다.

`MissileState`에 원본 스톤 타워 타입·피격 토큰, `MissileHooks`에 실제 입력 큐 경계를 추가했다. 원본과 같은 위치에서 명령을 보낸다. 큐가 없으면 명시 오류로 거부한다. Session은 기존 튜토리얼 토큰과 `services.assets.queueCommand`를 연결한다. 기존 Early3~6의 세 DWORD 소비와 단일 입력 큐를 사용하며 튜토리얼 단계를 직접 쓰지 않는다. CD10.72에 이 새 10.78 분기를 적용하지 않는다.

## 독립 원본 관측과 회귀

제품 수정 전에 새 도구 `decomp_thunder_hit_event.py`로 **688개 고유 입력을 x87 027f/037f 각각 정상 반환**, 정밀도 차이 0, 명령 발생 24행을 고정했다. 기존 `thunder-missile-x86.tsv`는 그대로 두고 `thunder-hit-event-x86.tsv`에 전체 사건 순서·128BYTE 객체·150BYTE 슬롯·8BYTE 좌표를 저장했다. 외부 SHP·공간 효과·소리·피해·명령 큐는 명시 경계다. 원본의 수치·타입 조회·충돌 판정은 실제 PE 명령이다.

기존 네 원본 검사 본문을 유지하고, 새 검사 하나가 688행의 전체 이미지와 순서를 비교한다. 누락 큐 거부도 확인한다. Release 빌드의 컴파일 오류·경고0, 썬더 관련 필터 **6검사 실패0**, 전체 Release **1727검사 실패0 / 155.759초**다. 결과와 실행 파일 해시는 `cpppj/tutorial-five-hit-event.json`에 고정한다. 산출물 접두는 `extracted/goal-thunder-hit-event-20261019-`다.

첫 원본 관측 `native1.log`는 발사자의 free 비트가 켜진 입력에서 미공급 가상 `+98`에 도달해 거부됐다. 원본 본문은 그 경우 별도 피해 경로를 사용한다. 현재 단위는 free 발사자를 제외한 상태0/2만 고정했고, 이 미복원 경로를 후속 작업으로 남긴다. 실패 로그는 보존한다. 새 기대값을 C++ 결과에 맞춰 바꾸지 않았다.

## 실제 Early5 플레이 시도와 남은 지점

`ui1`은 첫 안내 MORE/OK 후 신전의 객체 메뉴를 열다가 실제 파생 `+a8` 미연결로 실패했다. `ui2`는 워크샾의 **Put Knowledge into Production → Stone Tower → 생산78 → 실제 배치(135,93)**를 수행했다. 실제 SP는 **4000→3600**, 현재 월드에 로컬 스톤 타워가 생겼다. 건설 후 `startBlocker` 미연결 오류로 종료해 피격이나 B단계는 관측하지 못했다. 두 실행은 원본 전체 스냅샷 동일과 설정 복구를 확인했다. 이 실패를 자연 피격/완주 성공으로 세지 않는다.

`startBlocker`라는 기존 훅 이름과 오류 문구는 “프로세스”라고 부르지만, 원본 `0046ae80` 본문은 옵션 `00540bc4`를 확인하고 현재 소유자·좌표로 목록을 모아 기존 Gun 프로세스를 찾아 `0046a960`으로 새 장애물을 통지한다. 이 본문에서 새 프로세스를 생성하는 것은 아니다. 다음 단위는 이 실제 목록 수집·기존 Gun 통지를 연결하고, 같은 배치 입력으로 자연 피격 명령과 Early5 B단계를 검증한다.

최종 실행 파일의 11개 진입 재검사는 **5진입 통과/6실패**이며 마지막 자동 설정 복구도 `OSError22`로 실패했다. Tutorial1/3/4/5와 GuardMyBack의 진입은 저장된 실제 프레임으로 확인했고, 다른 6개는 `Unable to open d/options.cfg`로 실패했다. 최종 자동 요약은 생성되지 않았고 원문 `entry.log`와 개별 산출물을 그대로 보존했다. 실패 당시 설정을 별도 보존하고 작업 전 바이트를 수동 복구해 SHA-256 `7c986d379a533456fb34d19f7937d1a028812c4560389d43cb663f1bd10cd7d4` 일치 및 원본/CD Git 변경 없음을 확인했다. 이전 단위의 11진입 성공을 이번 실행 결과로 합산하지 않는다.

기준과 일치했던 현재 핀 **89보고서/154항목**만 갱신하고 이전 핀과 원본 관측은 보존했다. 기존421fixture는 그대로이며 새 독립 fixture 하나를 추가했다. 다른 PC의 과거 산출물까지 새로 검증했다고 주장하지 않는다.

Codex 용량 오류와 파일 오류의 관계는 계속 미확인이다. 프로젝트·PC·파일 시스템의 결함으로 단정하지 않는다. 이번 두 Early5 실행의 종료 원인은 로그에 명시된 하위 연결 누락이다. 전체 목표는 active/미완료이며 Early3~6·캠페인1-1/1-2·데모3의 자연 완주와 전체 동일성은 별도다.
