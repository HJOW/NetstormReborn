# 맨 오 워 수명·프레임과 공통 비행 제어 복원

2026-10-16 단위86, 현재/마지막 전체 정련 PC는 **VM-W11-Codex / 2026-10-16**이다. [최초 후처리·프로세스 생성](cpp-flyer-postpop-20261016.md)에 이어 `RawFlyerFrame.*`을 실제 Session의 동일 Pool·Host·Kernel·프로세스 원문 필드에 연결했다. 목표 지정 미션의 자연 완주와 원본 동일성은 미달성이다. 사용자 요청에 따라 이 단위의 문서·검증·로컬 커밋 후 작업을 중단하고 목표를 일시정지한다.

## 수명과 종료를 종류별로 구별한다

사용자가 알려 준 동작은 **훨리기그(Whirligig, TYPE73·sunFlyer)는 수명이 다하면 소속 훨리베이스(Whirlibase, TYPE72·sunAviary)로 돌아와 충전 후 재출격하고, 맨 오 워(Man o'War, TYPE144·rainFlyer)는 소멸한다**는 것이다. 맨 오 워의 수명 종료 그래픽·효과음은 전투 파괴와도 다르다. [명칭 대응표](../unit-source-name-map.md)에 이 요구와 확인 범위를 함께 기록했다. 두 종류에 같은 수명 종료 동작을 적용하지 않는다.

실제 맨 오 워 wrapper `0045d630`은 처음에 `0045bf00`을 호출하여 outer+68에 현재 시각+60초를 쓴다. boss 권한이면 부모 extra의20 비트 또는 수명 만료를 검사하고 **부모의 가상 Destroy에 `0x200000`을 전달한 뒤 즉시 반환**한다. 서버 여부와 boss는 서로 다른 전역이다. 이 플래그를 일반 `Destroy(0)`로 바꾸지 않는다. 공통 `0045c9d0`의 extra20 종료도 같은 플래그를 사용한다.

파생 비행 PreDestroy `0045e7e0`은 부모QB에 든 그림자가 있으면 **그림자를 flags0으로 먼저 삭제하고**, 원래 flags를 공통 `0044b4b0`으로 전달한다. 기존 `RawDamageablePreDestroy`의 공통 몸체는 `0x200000`일 때 collapse/Collapse 음향, `0x100000`일 때 explosion/Explosion 음향을 독립적으로 선택한다. 그러나 **비행 파생 PreDestroy와 실제 종료 그래픽·음향 소비자 연결은 이번 단위에서 완성하지 않았다.** 플래그·정적 호출 확인을 실제 효과 재현 완료로 해석하지 않는다. 전투 파괴 경로의 실제 flags와 끝까지 비교해야 한다.

훨리기그 전용 생성/프레임/귀환 타이머와 충전·재출격 전체 연결도 남아 있다. 이번 공통 제어 비교에는 홈으로 향하는 이동, 착륙 단계9, 훨리베이스의 실제 프로세스32 원문 변경, 충전 단계 종료 뒤 의존 해제·복귀 기한·명령2를 포함하지만, 훨리기그의 완전한 실제 순환을 실행한 증거는 아니다. Session의 아직 미복원인 전용 명령·종료·홈 통지는 명시 오류를 유지한다.

## 복원한 제어와 실제 필드

- `0045bf00`/`0045b800`: 맨 오 워/기본 첫 초기화의 쓰기 순서를 보존한다. 공격+50·착륙+58을0으로, 초기화+54를1로 쓰고 **outer+48에 현재 시각+20초**를 기록한다. +48은16진수로72BYTE이며 아래 표적 검색 타이머와 다르다.
- `0045c9d0`: dead/free·진단·홈/부모 SID·extra 관문, 실제 경과 double/float, 복귀 타이머와 홈QA, 표적 중심/가상 offset/포위 위치/클램프, 속도·반경·거리·이동, 공격 시작/유지/해제, 착륙, 현재 프레임/좌표를 반영한 Unpop→frame DWORD→Pop(flags40), 정수 칸 변경 통지, dirty/현재 시각, 서버 표적 검증·자리 경쟁·거리 및 재검색을 원문 순서로 실행한다. **포위 위치의 두 번째 인수는 현재 비행체 부모 SID이며 Form SID와 다르다.**
- 표적 검색은 **outer+40(64BYTE, inner+10)** 타이머를 검사한다. 검색 결과가 없으면 현재 시각+5초를 같은 위치에 쓴다. 초기화의 outer+48(72BYTE) 20초 타이머로 대신하지 않는다. 실제 생성자의 검색 타이머 초기값은0이므로 첫 공통 Frame부터 검색에 도달할 수 있다.
- `0045bf50`: 맨 오 워 애니메이션 기한에 실제 double `0.10000000149011612`를 더한다. 현재 frame6·표적 존재·공격 상태가 맞을 때만 실제 무기 생성 경계를 호출하고 TYPE+1f0과 현재 프레임 번호로 중복 소리를 억제한다. 발사 뒤 현재 타입·현재 부모·현재 프레임을 원문 위치에서 다시 읽는다. 프레임은 현재 글자의 실제 run 개수에 대한 signed 나머지다.
- `0045b6f0`/`0045b760`: boss 진단, 의존 해제→dirty4→표적WORD0→원본 빈 사건1→현재 Form 전송 순서와 서버 사건2의 표적 검증을 유지한다. 다른 사건은 원본처럼 자연 반환한다.
- `0045b7a0`: 윈드 플라이어(TYPE138), 홈0/ffff, free/dead 홈의 통지 생략과 살아 있는 홈의 가상+34(0,0)를 유지한다. `004ad730`의 checkForms는 실제 종속 head/next의 타입과 free/void를 검사하며 dead 종속을 허용한다.

큰 하위인 표적 검색 `0045c4b0`, 포위 `0045bb80`, 가까운 경쟁 수 `0045b840`, 맨 오 워 무기 `00472690`, 비행 종료 `0045bc30→004605f0`, 전용 명령·홈 통지·다른 비행 종류의 프레임은 여전히 미복원이다. 원본 관찰에서는 선언한 외부 입력으로, 실제 Session에서는 선택 시 구체적인 오류로 구별한다. 맨 오 워 무기를 기존 썬 캐논의 다른 미사일로 대체하지 않는다.

실제 Session에는 같은 `RawGunHit::SetTime/Hit`, 표적 문맥/MayTarget, 일반 의존 저장소, 실제 공간 Pop/Unpop/Repop, 현재 TYPE/run, Form 전송, 훨리베이스 프로세스32, 단일 음향 장부를 연결했다. 이동 시 제거하는 **TYPE47은 soundProcessType**이며 무기 프로세스가 아니다. 타입별 소리 stamp도 기존 `SoundProcessState.typeFrames`를 공유한다. 같은 소리의 두 장부를 만들지 않는다.

## 독립 원본 대조와 정정 이력

`tools/decomp_flyer_frame.py`는 원본10.78의 검토한 실제 명령과 명시 외부 경계를 사용한다. **744고유 입력(I18/A122/C26/N74/D30/F474)**을 x87 027f/037f에서 각각 실행해 **1488정상 반환, 정밀도 차이0**을 확인했다. 전체112BYTE 프로세스·일곱 객체350BYTE·현재 전역20BYTE·다섯 TYPE의 소리 stamp·훨리베이스 프로세스48BYTE·반환·호출 순서와 스택/비휘발/SEH/FPU/쓰기guard를 비교한다. 두 정밀도 재생을 고유 입력 수에 중복 합산하지 않는다.

현재 산술 비교는 명시한 TYPE 발자국2×2·run 개수16 및 외부 반환/변경 입력을 사용한다. 중심/offset/거리/클램프/ftol/checkForms는 실제 명령이다. 큰 표적 선택·무기·공간·음향 몸체의 동등성까지 증명한 것은 아니다. 초기화·프레임·해제·통지·부모 사망·공통 제어의 C++ 비교6개와 선택된 누락 경계의 부분 쓰기 검사1개, **총7개는 실패0**이다.

최초 관찰 입력은 Parent getter `0041bfb0`이 요구하는 실제 부착 head를0으로 준비해 반복 진단을 발생시켰다. 두 부모 head70과 프로세스31/state8을 정상 입력으로 정정하고 원본을 다시 실행했다. checkForms의 void/dead/free 변이는 별도로 유지한다. 최초 자료는 `extracted/goal-flyer-frame-20261016-first-parent-input.{json,tsv}`와 `...-focused.log`에 보존한다.

대조 과정에서 제품의 포위 인수(Form 대신 부모)와 검색 타이머(72 대신64)를 고쳤다. 검색 기한 전/일치/후의 독립 입력도 실제64BYTE 위치로 옮겨 원본을 재실행했다. 이전 입력은 `...-before-search-input.{json,tsv}`와 `...-focused-corrected.log`에 보존했다.

마지막8개 호출 순서 차이는 원본 `004b15f0(target,process*)`의 두 번째 인수를 관찰기가 Form 번호로 기록하지 않은 데서 발생했다. 실제 현재 inner 포인터를 검증하고 **그 포인터+4의 Form**으로 경계를 정규화했다. 원본을 다시 실행하여 **8개 trace만 바뀌고 모든 상태·반환 바이트는 불변**임을 확인했다. `...-before-depend-pointer.{json,tsv}`와 `...-focused-search.log`를 보존한다. C++ 출력을 원본 기대값으로 사용하지 않았다.

최초 `FlyerPostPop_` 필터 시도는 등록된 검사명과 달라0개였으며, 실제 `Flyer_` 필터로 정정했다. 최종 빌드가 링크 중일 때 시도한 기존 회귀2회도 Windows의 실행 파일 잠금으로 시작하지 못했다. 해당 로그는 `...-{postpop,aviary}-link-lock-attempt.log`로 보존하고 통과 수에 포함하지 않는다. 빌드 정상 종료 후 기존 비행 생성5개·아비어리10개를 다시 실행해 모두 통과했다. 실제 자원 맨 오 워 최초 생성/Host/그림자 통합1개도 통과했다. 관련 소스는 빌드 중 변경하지 않았다.

## 실제 미션과 중단 지점

데모1은 실제 맨 오 워를 생성한 뒤 **103프레임/2.575초**에서 새 공통 Frame을 지나 미복원 표적 검색 `0045c4b0`에 도달한다. 기존과 같은 프레임이므로 생존 프레임 증가로 해석하지 않는다. 데모3은 다른 총 애니메이션의3프레임/0.075초 경계가 남는다. 400프레임 뒤에만 실행될 새 맨 오 워 상태 검사는 이 미복원 경계 때문에 도달할 수 없어 이번 변경에서 제거했으며 검증 수에 합산하지 않았다. 기존400프레임 목표나 실패 처리를 완화하지 않는다.

최종 Release 빌드는 경고0·오류0이며 전체 CTest는 **1379개 중1377통과·2실패, 검사133.14초/전체133.25초·종료8**이다. 실패는 위 두 미복원 경계뿐이다. 검증 실행 파일 SHA는 [보고서](../../cpppj/flyer-frame.json)의 `product_validation` 및 [공통 인수인계](../../LEFT_JOBS.md)를 따른다. 모든 빌드·검사는 콘솔에서 수행했으며 게임·GUI 실행은 없다. 현재 지정 미션 작업에서는 기존 DirectDraw 오류 수정을 제외하되 **cpppj2차 목표에서는 필수**다.

재개 시 우선 맨 오 워 표적 검색/포위/경쟁수와 실제 무기를 복원하고, 훨리기그 전용 수명·귀환·충전·재출격을 별도 비교한다. 파생 PreDestroy/그림자 삭제와 수명 소멸·전투 파괴의 flags·그래픽·효과음을 끝까지 대조해야 한다. 다른 총 애니메이션, 펜스 사건3의 잔류 x87/이웃 재Pop, GUI·Guide·사용자 조작·AI 전략·승패·저장·다음 미션·전체 그래픽/음향도 남는다.

원본/fixture/제품 SHA는 새 보고서에 고정한다. 기존 비행 생성 보고서의 Session·CMake2파일은 이번 통합으로 달라지므로 과거 SHA와 현재 SHA를 새 보고서의 `historical_source_drift`에 구별한다. 요구에너지2352개의 제품·원본 입력은 변경하지 않으며 CMake 등록 변경만 해당 보고서의 단위86 이력으로 남긴다. 보호 원본/AGENTS.md/dotnetpj는 수정하지 않고 push하지 않는다.

10.72 참고: 정련 자료의 대응 후보는 공통 Frame `0045c9d0→004987a0`(string0.67), 맨 오 워 Frame `0045d630→004997d0`(neighbor0.912)다. 이는 자동 대응 메타데이터이며 CD 원본 명령 재생이나 동등성을 확인한 결과가 아니다. 이번 단위에서는10.78만 복원했다.
