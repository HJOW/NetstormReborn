# 화면 모드 변경 부모의 복구·설정·공통 갱신 (단위746)

2026-11-02 / HJOW-Athlon / Windows 10. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 산출물은 수정하지 않았다. 사용자의 이번 `/goal` 재개 지시로 745 뒤 작업을 이어 갔다. 실행 제품은 **746 / 표시11.01**이고 전체1~8차 목표는 미완료다.

## 원문과 실제 차이

10.78의 `00435ba0`은 최초 화면 모드를 복구용으로 보관하고, 창 모드 요청에서는 `(requested & 0xffffffab) | 2`를 적용한다. 현재 모드와 다를 때만 `004a4fe0`을 호출한다. 첫 장치 변경이 실패하면 `00435c29`에서 채널29의 `screen mode change failed.` 진단을 남기고, 현재 `0054dbb4`가 비영일 때 최초 모드로 복구한다. 이후 실제 현재 모드의 bit0을 `startInFullScreen`에 저장하고 설정 callback 뒤의 `005c85d8`을 감김 증가한다. 복구/설정 저장 자체의 예외를 다시 성공으로 바꾸지 않는다.

기존 `Client::ChangeScreenMode`는 장치 거부를 바로 상위 예외로 보내고 공통 메타 갱신을 수행하지 않았다. 동일 모드에서도 호스트의 커서/출력 갱신을 반복했고 조정 미리보기만 시작 설정 저장에서 제외했다. 원문 조정·절대 변경은 모두 같은 부모를 호출한다.

`0054dbb4`는 HWND가 아니라 **화면 모드 초기화 완료 DWORD**다. 원문 `004a4fe0`의 끝에1을 쓰는 것을 확인하여 Client 수명으로 보유했다. 최초 모드/해상도 교체/실제 변경의 성공 경계에 연결하며 Screen 교체로0을 복제하지 않는다. 처음 작성한 연결의 HWND 해석은 최종 코드에 남기지 않았다.

10.72 대응 `00485620`도 같은 창 비트 정리·현재 화면 장치·시작 설정 저장·별도 갱신 증가를 갖는다. 이번 독립 CPU 관측은10.78만 실행했고 CD 전체 예외 수명/실기 검증은 하지 않았다.

## 변경

- `ScreenModeTransition`에 원문 부모를 옮기고 실제 Client의 현재 Screen/Config/진단/초기화 완료값과 `ClientLocalStateGlobals::MetaRefresh()`를 연결했다. 설정 callback이 갱신값을 바꾸는 경우도 현재값을 읽어 증가한다.
- 미리보기/취소/절대 변경/F12가 같은 부모를 사용한다. 마지막 확인 모드인 `workingFullScreenFlags`는 기존 Accept 명령에서만 저장한다.
- **원본과 다른 Windows 10/11 호환 동작:** 기존 DIB·비flip·화면비 유지 borderless 장치를 유지한다. 원문의 장치 요청은 부모에서 임의 정규화하지 않고 실제 Screen 장치에서 호환 플래그로 바꾼다. 해당 차이와 이유는 코드의 한국어 주석에 명시했다.
- 읽기 전용 `screen_transition` 진단에 실제 메타 갱신 DWORD를 공개했다. 제품 UI에는 별도 검사 표시를 추가하지 않는다.
- 기존 선택 키 집중 대상에 관련 검사 파일을 추가했다. 새 실행 대상은 없다.

## 검증과 최초 실패

보호 PE의 **전체 정상 부모 `00435ba0..00435c28`**를192입력×두 x87 정밀도=**384회** 실행했다. 화면 장치와 설정 쓰기 CALL만 명시하며 원시 요청·출력 모드·설정 인자·설정 후 갱신·스택/비휘발/SEH 체인 복구를 관측했다. 동일 모드, 창 비트 정리, 전체 DWORD, 설정 callback의 현재값 변경과 UINT32 감김을 포함한다. fixture는 `screen-mode-transition-x86.tsv`다. 원본 프로그램/OS 장치는 실행하지 않았다. 실제 C++ 예외 언와인딩/`00435c29` 실행을 이384회에 포함하지 않는다.

새 C++5개는192행 대조, 첫 변경 실패 뒤 실제 이전 모드 복구, 초기화 전 복구 생략, 복구/설정 실패의 전파와 갱신 보존, 동일 모드/누락 장치 경계를 확인한다. 예외 경로는 원문 정적 대조와 명시 실패 입력이며 원본 SEH 관측이 아니다. 최종 **집중33개 실패0**에는 기존 선택 키·F12·게임 메뉴/튜토리얼과 DIB/화면비/픽셀/실제1366폭 행 간격 검사가 포함된다.

첫 빌드는 읽기 전용 진단에서 비const Config getter를 호출해 실패했다(`build-v1.log`). 진단이 Config를 재해석하지 않고 현재 갱신 DWORD만 읽게 수정했다. 최종 `build-v3.log`는 제품/집중 대상 Release 경고·오류0이며 `tests-v3.log`의33개가 통과했다. 중간 산출물/사본을 현재 제품으로 세지 않는다.
