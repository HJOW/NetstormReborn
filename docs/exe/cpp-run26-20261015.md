# 단위26: 실제 Player9 송신 분배와 단독 캠페인 연결

## 기준과 정밀 분석

기준 `7cb5494`에서 AGENTS와 양 LEFT를 다시 읽었다. 현재 및 마지막 정밀 디컴파일 PC는 **HJOW-Athlon, 2026-10-15**다. 직접 영향8개 원문을 `cpppj/hist/run26-base`에 전체 보존했다.

PATCH `004e2e30/004e2e80`과 CD `004c0420/004c0480`을 정밀 내보냈다. 원본은 Player1..8의 접속 BYTE bit0과 NULL 아닌 연결 객체를 확인하고 로컬 플레이어를 제외한다. 지정 제외 송신은 서버를 확인하고 제외 번호도 적용한다. Player0은 보내지 않는다.

일반 송신은 후보마다 현재 로컬 번호를 다시 읽는다. 지정 제외 송신은 처음 로컬 번호를 보관한다. 접속/연결 표는 송신 callback 다음에도 현재 상태를 읽는다. CD Player 폭은0xac이며 접속 BYTE는 PATCH와 같은+50이다. 미빌드 초안의 CD+48 값은 정밀 본문을 읽은 뒤 교정했으며 초안 전체를 `run26-draft`에 보존했다.

## 구현과 검사

`RawBattleBroadcast`가 두 원본 분배 몸체를 복원한다. 단일 Player 표와 연결 객체 표를 빌리며, 실제 연결 객체의 송신 함수만 외부 경계다. 세션의 실제 Gun/Path writer 결과는 별도 송신 관찰 콜백이 없으면 이 분배기에 전달된다. 단독 캠페인의 NULL 연결은 원본의 조건에서 자연 반환한다.

새 독립 입력은 두 PE 합계 **1,356개**다. 접속 플래그의 다른 비트, Player0, NULL 연결, 로컬 번호, 제외 번호와 첫 송신 callback의 로컬/다음 접속/다음 연결 변경을 포함한다. 분배 함수와 조건/순회는 실제 PE다. 가상+4 송신 장치의 요청과 callback 변경은 명시 외부 입력이며 네트워크 I/O가 아니다. 표 포인터 자체의 교체는 입력 범위 밖이다.

첫 도구는 두 몸체 실행과 fixture 생성 후 보고서를 쓰는 `Path` 이름 오류로 종료했다. 최초 도구/로그/fixture를 보존하고 보고서 쓰기만 교정했다. fixture 전체 바이트가 전후 동일하다. 재실행을 새 고유 입력으로 합산하지 않았다.

C++ 검사는 두 판본의678개씩 정확한 요청 순서/packet 인자를 대조한다. NULL 연결/서버 계약 검사와 production1-1의 실제 Gun/Path 분배→선택/좌클릭→Host54→이동 검사도 추가했다. 이전 세션 교전·설치 검사도 유지했다.

최종 Release 경고/오류0, 집중8개 성공(신규4개), 전체CTest 1/1·내부1,139개·실패 체크0(188.54초)다. 전체 원문/입력/실행 SHA는 `cpppj/run26.json`, `extracted/run26-*.log` 및 `tools/check_campaign26.py finalize/verify`에 고정했다.
