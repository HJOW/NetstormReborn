# Depend 생성의 현재 번호·공통 Factory·가상 부착 순서 (단위910)

감시 Form 쌍 생성은 각 Create 직전의 현재 전체 타입 번호와 현재 공통 Factory 생성자를 사용한다. 원문 부모의 client 범위/서버 진단과 판본별 WORD/VT 순서, 실제 World의 장기 번호/클래스 수명을 함께 연결한다. 다른 Form 부착/Factory/Pop 부모와 전체 목표는 진행 중이다.

## 원문과 범위

- 마지막 전체 정밀 디컴파일과 현재 작업 호스트는 HJOW-Athlon / 2026-11-03이다. 정밀 산출물은 수정하지 않았다.
- 부모는 PATCH004b1510/CD004af940이다. client 범위는5~14999/5~5999이며 예약0~4는 포함하지 않는다. 어느 부모든 client이면 flags2이고 둘 다 아니면 현재 server를 읽어 진단한다. 정상 복귀 뒤에는 저장 flags0을 유지한다.
- 현재 번호는 PATCH00541074/CD0051c964이다. 두 보호 PE 초기 DWORD1을 확인했고 원문은 두 번의 Create 직전에 이를 다시 읽는다. 현재 생성자 선택과 다른 TYPE로의 대체를 부모에서 고정하지 않는다.
- PATCH는 첫 watched→첫 watcher0→두 번째 watcher→두 번째 watched0 뒤 첫 VT를 읽는다. CD는 첫 watcher0→두 번째 watched0→첫 watched 뒤 첫 VT를 저장하고 두 번째 watcher를 쓴다. 첫+74가 돌아온 뒤에는 두 번째의 현재 VT+74를 선택한다.
- 원문 반환은 void다. C++의 두 객체 반환은 기존 호스트 추적용 부가 결과이며 Native 반환값 일치를 주장하지 않는다.
- 조회는 실제453740 thunk→4b1bd0과 Remove의 같은 predicate에서 현재 전체 Depend 번호를 비교한다. 생성·검색은 같은 장기 주소를 읽고 가상 감시 수명 진입은 실제 클래스 VT를 사용한다.

## 실제 연결

RawGameAuxState에 장기 현재 번호를 추가하고 일반 World 준비에서 이를 다시1로 쓰지 않는다. 실제 World의 DependFormHost는 같은 공장/번호/진단을 빌린다. 독립 Host도 RawSquidDestroy의 기존 TYPE 입력으로 같은 공통 Factory를 구성한다. 실제 생성 경로에서 SquidForms의 고정 Create/Take를 우회해 사용하지 않는다.

공통 Form 조회/기본 부착은 현재 TYPE에서 VT를 추정하지 않고 생성자가 남긴 네 VT를 구분한다. 실제+74가 정렬 부착인 Content 클래스는 기본 부착과 별도로 취급한다. 실제 감시 클래스는 두 Create의 이전/현재 TYPE BYTE가 달라도 같은 가상 수명으로 들어간다.
