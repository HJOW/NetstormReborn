# Early2 실제 프레임·건설·생산·회수와 자연 완료 연결

2026-10-19 단위205. 기준 커밋은 `a254fab54fd2c7ab5ef643cc16b73c2da5e14216`이다. 현재 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon**, 마지막 디컴파일 날짜는 **2026-10-16**이다. 이번에는 새 디컴파일이나 원본 게임 실행을 하지 않았다.

## 변경 결과

기존 `RawTutorialTwo`가 실제 클라이언트의 프레임·입력에 연결되지 않아 Early2의 안내 뒤 건설·생산 진행을 판정하지 못했다. 기존 공개 이름 `RawCampaignTutorialOneBindings`를 유지하면서 같은 `RawMissionFrameGate`에서 Early1과 Early2만 실제 처리기로 분배했다. Early3~6은 아직 연결하지 않았다.

Early2는 로그인 때부터 공급 판정에 사용하던 동일한 87BYTE 옵션, `UpdateRange`, 실제 누적 제작 장부와 생산 목록, 회수 금지 저장소를 참조한다. 초기 안내 뒤 실제 옵션은 stock=2/range=0/공급 범위 제곱=196이다. 시계·선택·Tell·팝업 정리는 같은 월드와 UI에 연결하며 단계나 완료 결과를 합성하지 않는다. 부호형 회수 금지는 같은 4BYTE의 대응 unsigned 별칭으로 연결했다. Early1의 공통 프레임·안내·자기 정지 수명은 유지한다.

현재 선택 초기화 `004d5c90(0,0,0)`과 후속 `004d5c60`을 별개로 연결했다. 일반 선택의 셋째 인자 1을 재사용하지 않는다. 새 `RawUserSelection::Clear`는 enabled일 때 다중 선택 정리→현재 SID 0→강조 0의 원본 순서를 따른다. 정지/콘솔 검사를 추가하거나 기존 단일 선택의 가상 통지를 대신 호출하지 않는다. 대응 C++ 작성 전에 보호 PE의 `004d5c60`을 **87개 고유 입력/두 x87 정밀도/174회 정상 반환**으로 동결했다. 기존 선택 몸체와 기존 기대 자료는 유지했다.

실제 윈드 신전 배치에서 공통 자산 PostPop의 내용물 조회/Slot 생성 연결 누락을 발견했다. `FindContained(parent,0x10,type,0)`와 `Create(parent,type,0,0x10,0x10,0)`를 기존 실제 Carrier/Contained에 연결했다. 원본 `54126c`의 종류는 **133(Golem)**이고 생성되는 Form 클래스는 **6(내용물)**이다. 이 호출을 골렘 유닛 생성으로 바꾸지 않았다. 원본 AssetPostPop/Contained 생성 몸체는 변경하지 않았다.

## 실제 창에서 확인한 범위

최종 `gui9`는 새 검사 프로필의 `DoneTutorial2=0`, 원본 영어 시작 SP 10000, stock 타이머를 켠 상태에서 입력만 재생했다. 게임 창은 소리 없이 실행했으며 원본 설정을 실행 뒤 복원했다.

| 실제 진행 | 관측 결과 |
| --- | --- |
| A 안내와 자기 정지 해제 | MORE/MORE/OK 뒤 실제 입력 가능 |
| 사제 Construct/Temple | 합법 위치의 윈드 신전 1개, 5000SP 소비 |
| Construct/Workshop | 썬 워크샾 1개, 800SP 소비 |
| 지식과 생산 | Put Knowledge into Production→Sun Disc Thrower |
| D/E/G 생산과 F 신전 선택 | 썬 디스크 발사기 최대 4개, 원본 신전 선택 시간 판정 |
| H 실제 회수 | `Salvage gains 75` 클릭→54h 패킷 1회→발사기 3개 |
| I 자연 완료 | 완료 기록 0→1, SP 3075, 마지막 게임 시각 81.647초 |
| Next Tutorial | Tutorial3 영어 시작 안내, 원본 SP 2000 |

SP는 **10000→5000→4200→3900→3600→3300→3000→3075**였다. 보호 TARC의 신전/워크샾/발사기 비용은 5000/800/300이며, PE `501550`의 환불 배율은 **4BYTE float 0.25**이다. 발사기 1개 회수 금액은 75다. 총 4524프레임, 게임 종료 코드 0, 전체 originals 스냅샷 동일을 확인했다. 진행 단계·SP·HP·생성 결과를 실행 도중 쓰지 않았다.

재현 입력은 `cpppj/tests/fixtures/tutorial-two-runtime-ui-input.tsv`의 1098행, 검사 도구는 `tools/cpp_tutorial_two_smoke.py`, 현재 출처 보고서는 `cpppj/tutorial-two-runtime.json`이다. `--verify`와 `--inspect`는 저장된 자료를 읽으며 게임을 실행하지 않는다. `--output`은 새 창을 실행한다.

## 검증과 실패 기록

- 최종 Release build4 통과. 전체 **1725개 검사 실패 0 / 258.43초**, 새 선택 해제 2개 및 실제 Early2 로그인/A 안내 회귀 통과.
- 별도 **11개 스테이지 실제 플레이 진입 통과**, originals 스냅샷 동일. Early1/2에는 원본 10호출 안내와 7호출 재개를 기다리며 실제 gate를 검사한다.
- 출처 감사 **140종 중 125통과**, 기존 15문제 동일, 새 문제 0. 기존 420개 fixture 바이트는 그대로이며 새 native/수동 입력 2개를 더해 422개다.
- 현재 검증 소스 14개/두 실행파일과 보호 파일 2127개를 고정했다. 과거 78개 보고서의 현재 핀 223개는 이전 값과 단위205 갱신 이력을 함께 보존했다. 기존 검사 본문은 바꾸지 않고 새 3개만 추가했다.

중간 실패도 `extracted/goal-early-two-runtime-20261019-` 접두로 보존했다. gui2는 가격을 포함한 실제 건설 라벨 누락, gui3은 위 Slot 연결 누락, gui5~7은 raw_cursor 필드 해석과 입력 조건 오류였다. 실제 순서는 lockDepth/legal/type/previewSID이며, inactive의 캐시된 legal/type를 활성 미리보기로 보지 않도록 입력 조건만 교정했다. gui6/7은 해당 검사 창을 고유 식별해 정상 종료했고 이유를 기록했다. 제품의 배치 허용이나 단계 판정은 완화하지 않았다.

gui8은 자연 완료와 다음 미션에 도달했지만 B 단계 입력 반복으로 워크샾 3개를 지었다. 최종 계획에는 실제 객체 존재 조건을 넣어 gui9에서 1개만 지었다. 초기 225SP 회수 라벨 가정은 틀렸으며 실제 메뉴와 환불은 모두 75였다. gui9 게임은 정상 종료했지만 관측기의 PE 상수 읽기가 8BYTE double이라 후처리가 실패했다. 관측기만 4BYTE float로 고쳐 동일한 저장 관측을 다시 검사했다. 이전 관측기와 변경 사유는 `validator-width-correction.json`에 보존했다. 이는 게임 재실행이나 결과 자료 변경이 아니다.

연결 전 전체 검사 1725개/264.89초는 `tests-before-slot`로 따로 보존했다. 최종 전체 검사 자료는 `tests-final`, 최종 창 자료는 `gui9`, 11진입은 `entry/results.json`, 출처 감사는 `verify-final.json`이다. 현재 소스는 `sources.json`, 이전 핀 목록은 `pin-updates.json`으로 대조한다.

## 인수인계와 목표 일시중지

사용자 요청에 따라 이 단위의 문서화와 로컬 커밋을 마친 뒤 전체 목표를 **일시중지**한다. 새 작업 단위는 시작하지 않는다. 원격 push, AGENTS/originals/originalCD/dotnetpj/DirectDraw 변경은 없다.

전체 목표는 여전히 미완료다. F8 Guide와 원본 키 분배, Early3~6 실제 판정과 자연 완주, 캠페인1-1/1-2 및 데모 3개 공통 프레임·전략 AI·자연 포획/운반/희생/승리·후속 미션, 전체 그래픽·애니메이션·음향 동일성 검증과 기존 출처 15문제가 남는다. Early2 완주나 11개 진입을 전체 완료로 세지 않는다. 캠페인/튜토리얼의 멀티플레이 전용 희생 보상 선택창 생략과 임시 처리 주석은 유지한다. 캠페인1-1 썬 캐논 공격 관측에는 제네레이터로 공급 범위를 연장해야 하며 섬 경계의 불법 배치를 우회해서는 안 된다. 재개 시 AGENTS와 양 LEFT를 다시 읽고 현재 PC/마지막 디컴파일 PC를 확인한다.
