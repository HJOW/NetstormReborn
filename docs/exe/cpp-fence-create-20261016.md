# 썬 바리케이드의 실제 표식·포스 필드 생성과 연결 재생성

후속 단위85의 맨 오 워 최초 후처리/프로세스 생성과 현재 검증은 [비행 후처리 복원](cpp-flyer-postpop-20261016.md)을 참고한다. 아래 수치와 실패 위치는 단위84 당시 이력이다.

현재/마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-16**으로 일치한다. AGENTS.md와 양 인수인계를 다시 읽었다. 직전 단위83/da2b342의 실제 미션 실패(00457460 연결 재생성)에서 이어갔다. 보호 원본·AGENTS·dotnetpj 변경, 게임/GUI 실행은 없다. 목표는 active·미달성이다.

## 내부 표식90

실제004adea0의 두 중심으로 원본4방향을 선택한다. X/Y 절댓값이 같으면 세로를 우선한다. Rect는 들어오는 끝점만1..255로 clamp하며 원래 점이 invalid면 그 끝점으로 교체한다. 경계 동일점도 Rect 안에 포함한다.

단계2의4칸 해시 구간은 **이동 전 현재float+0.5f를 x87에서 더한 뒤 ftol→signed /4→상한63**으로 구한다. 한 걸음 이동 후 Rect를 벗어나면 생성하지 않는다. 직전 구간과 달라졌을 때만 **이동 후 현재float**에 표식을 생성한다. 좌표/이동 경로는 함수 로컬 입력이며 생성 효과가 부모 좌표를 바꿔도 이미 계산한 경로를 다시 만들지 않는다.

각 생성은 원본처럼 type/flags2로 새 SID를 얻고 **QA WORD=부모SID→004214a0 표면 통지→QB DWORD=(대상SID>>8)&255→graphBYTE=대상SID&255→현재 부모owner의 가상+74→가상+90(flags40) Pop** 순서다. 통지 뒤 owner를 다시 읽으며 QB/graph를 하나의 필드로 합치거나 지우지 않는다. 실제15001 등 높은 SID의 high8/low8도 독립 표본에서 대조했다.

## 화면 포스 필드170

원본 mode0과 같은 X/Y 보정을 쓰되 정수 절삭 전 float를 그대로 Pop에 넘긴다. 수직은 TYPE의 J 첫 프레임, 수평은 K 첫 프레임을 **raw frame DWORD에 직접** 쓴다. 실제 Frame 지정기의 표시/해시 갱신으로 바꾸지 않는다. 현재 생성 TYPE는 매번 다시 읽고, 새 슬롯의 현재 TYPE에서 첫 프레임을 조회한다.

새 객체의 extra bit20이 켜져 있으면 해당 객체를 생성한 상태에서 **전체 생성을 즉시 종료**한다. Frame/owner/Pop를 수행하거나 임의로 반납하지 않는다. 두 owner가 같거나 signed 두 번째SID가 첫 번째보다 작으면 첫 owner, 아니면 둘째 owner를 쓴다. 동일 SID와 signed 음수 인수도 대조했다.

끝점 동일점은 한 번 포함하며 최대100개다. 소수 끝점이1단위 증분으로 정확히 같아지지 않으면 원본처럼100개 상한까지 진행한다. 이 관찰의 Pop는 명시 경계이므로 임의의 보드 밖 시험 입력에서 실제 게임의 전체 공간/표시 동작까지 실행한 증거가 아니다.

## 실제 연결 재생성과 삭제

부모extra9는 진입 때만 검사한다. 방향0/2/4/6마다 실제 **동맹 최근접00455fb0→현재 사거리00455f00→대상 현재extra21**을 확인한다. 통과하면 내부 표식을 생성한 다음 그 효과 뒤 현재 두 좌표/owner와 끝점SID로 포스 필드를 생성한다. 거리 효과가 대상extra를 바꿨거나 생성 효과가 부모owner/좌표를 바꾸는 순서를 보존한다.

새 표식이 다시 삭제되면서 드러난 Session 분배 누락도 연결했다. 원본90/170의 실제 가상 표005092d0/00509388은 **+10=004af780, +14=004b0950, +18=004b0840**이다. 이미 복원한 같은 공통 삭제와 Pre/Post에만 연결한다. 다른 펜스 파생/보상/표면 접두를 이 표로 허용하지 않는다. 실제 dead·종속·Unpop·장부 깊이·반납이 수행되며 삭제를 빈 효과로 대체하지 않았다.

## 독립 관찰과 오류 교정

`tools/decomp_fence_create.py`는 현재 PC 정밀 함수표의 세 부모 및 중심/방향/Rect/스냅/CRT/태그 helper를 제한 x86으로 실행한다. **578고유 입력**은 표식106·포스필드306·재생성166개이며 각 입력을 두 x87 정밀도로 재생한 **1156정상 반환**을 확인한다. 비휘발 레지스터·스택·FPU 정밀도/스택 복원도 매번 검사한다. 생성/통지/가상owner/Pop는 명시 인수/현재 raw 변경 경계다. 재생성의 이웃/거리/하위 생성도 독립 제어 관찰에서는 명시 입력이고 실제 Session은 기존 실제 모듈과 새 생성기를 연결한다.

전체 부모100/250BYTE·선택한 모든 새 객체50BYTE·모든 효과 순서가 C++의 전수 비교3개와 일치한다. 누락/bit20 조기 종료/앞선 QA·Frame 쓰기 보존 검사1개도 통과했고 펜스 회귀21개는 실패0이다.

- 최초 oracle은 TYPE foot를14/18에 썼다. 실제0049a900의 **1d4/1d8**을 확인해 입력을 정정하고 다시 관찰했다. 최초 자료 `extracted/goal-fence-create-20261016-first-oracle.{json,tsv}`는 현재578개에 합산하지 않는다.
- 첫 C++ 표식 비교에서 역방향 구간이 달랐다. 실제0043fa50의 **+0.5f**를 어셈블리로 확인해 단순 절삭을 교정했다. 기존 원본 기대값을 C++ 출력으로 바꾸지 않았다.
- 높은 클라이언트 SID4660에 지정 Take를 사용한 검사는 원본의 서버 영역 전용 계약 때문에 거부됐다. 검사 입력은 명시 create 경계가 반환할60~159와 클라이언트 끝점을 미리 확보하고, 지정 Take는 서버 끝점15001에만 사용하도록 고쳤다. 실제 게임의 allocator/Take 계약을 완화하지 않았다. 원본 관찰에서도 allocator 자체는 외부 경계다.

## 실제 세션의 현재 검증 범위

보호 자원의 실제 Load→Start→같은 Kernel400프레임(25ms 외부 시각 간격,10초)은 **11개 중9개** 통과한다. Early Missions1~6, 캠페인1-1/1-2, 데모2 GuardMyBack이다. 남은 실제 연속 프레임 실패는 **DemoStormRages103프레임/2.575초의 rainFlyer(TYPE144) 파생 Pop**, **DissolvedAlliance3프레임/0.075초의 다른 총 animation**이다. 성공 예외·다른 미션·건너뜀으로 바꾸지 않는다. 보호bit20 없는 사건3의 잔류 x87 반환, 이웃 재Pop004578f0/004577f0, 전체 GUI/Guide·AI전략·사용자 명령·승패/저장/다음 미션·그래픽/음향 동일성도 아직 후속이다. 현재9개 성공은 자연 완주가 아니다.
