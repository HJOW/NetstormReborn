# ESC의 선택 정리와 커서/메뉴 순서 (단위742)

2026-11-02 / HJOW-Athlon / Windows10. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 기존 산출물은 바꾸지 않았다. 이전741의 F6 연결·검사·커밋은 진척으로 분류했다. 전체 목표 중 남은 비멀티 ESC 부모를 이어 진행했다. 현재 실행 제품은 **742 / 표시11.01**이다.

## 실제 차이와 원문 대조

741제품에서 사제 SID15000을 선택한 뒤 ESC를 누르면 메뉴는 열리지만 선택이 남았다. 정지 상태에서도 같았다. 기존 ESC는 활성 커서 취소 또는 메뉴 토글만 실행했다. 원문 `004d9494..004d9573`은 enabled/blocked 검사 뒤 다중 선택, 현재 단일 선택의 프로세스/가상 통지, 강조를 먼저 정리한다. 그 뒤 `004d9574`에서 현재 커서를 조회하여 취소/팝업 닫기 또는 메뉴 토글로 간다.

기존 `Select(0,0,0)`은 대상0일 때 정지 조회를 생략하고 같은 enabled/blocked·다중/단일/강조 정리를 수행한다. 새 도구 `tools/decomp_escape_selection.py`로 **154입력×두x87정밀도**에서 원문 ESC 부분과 실제 Select0를 각각308회 실행했다. 관문/선택/목록/강조와 콜백 변경 뒤의 전체 trace/최종 전역이 모두 일치했다. 이는 대조한 입력의 결과이며 모든 가능한 상태의 동등성 증명으로 확대하지 않는다.

부분 입구의 부모 ABI는 명시 트램펄린으로 EBX/ESI/EDI와0x120 지역 스택을 준비한다. 원문 몸체는 바꾸지 않고9574 직전에 부모 반환점으로 이동한다. 기존 스택 canary/비휘발/x87 검사를 유지하며 사용하지 않는 EAX는 비교하지 않는다. cursor/menu와 key-up/Guide/Gump/Console은 이 관측 범위 밖이다. 원본 게임 프로세스는 실행하지 않았다. 새 fixture는 `escape-selection-x86.tsv` 한 개다.

## 실제 연결

실제 ESC의 World 입력에서 기존 `ResetSelection()`을 먼저 실행한다. 이 함수는 같은 장기 선택 소유자의 `Select(0,0,0)`을 호출하므로 정지 중에도 선택/강조가 정리된다. 앞선 Gump가 소비한 ESC는 이 부모까지 다시 보내지 않는다.

이후 활성 조각이 있으면 기존 `CancelCursorForState()`의 원문446e70 몸체와 팝업 닫기를 한 번씩 호출한다. 기존 일반 UserInput 우회를 제거해 마우스/커서 설정 읽기와 팝업 닫기를 중복하지 않는다. 커서가 없으면 기존 serial 조회/메뉴 토글을 유지한다. `IsEscapeKeyPress`로 전체 사건 코드와 뗌을 확인하여 같은 하위BYTE를 가진 명령/마우스를 ESC로 오인하지 않는다.

## 검증

Release 게임/기존 `netstorm_priest_selection_shortcut_tests`를 빌드해 경고/오류0, **집중23개/실패0**을 확인했다. 새2개는 Native154행의 실제 기존 선택 몸체 재생과 ESC 사건 종류/뗌이다. 기존1074 선택/87 해제 및 다중·다음·사제 선택 회귀도 포함한다. 새 실행 파일은 추가하지 않아 테스트 실행66개/전체71대상을 유지한다. 전체 C++ 실행은 아니다.

`tools/cpp_escape_selection_smoke.py`의 실제 기록은 다음처럼 구별한다.

- **수정 전741제품:** 355프레임/18.288초/프로세스 종료0. 일반/정지 ESC 메뉴가 열린 뒤에도 선택15000이 남아 관측검사는 실패했다. 입력과 원시 관측/실패를 보존했다.
- **수정 후742제품:** 415프레임/19.259초/종료0. 일반/정지 ESC는 선택0 뒤 메뉴를 열고 다시 닫았다. 정지 시각도 유지했다. Q로 든 타입82 조각(미리보기73)은 첫 ESC에서 반납되어 깊이1/미리보기0이 됐고 메뉴는 닫혀 있었다. 다음 ESC에서 메뉴가 열리고 마지막 ESC로 닫혔다. 조각 배치/공격은 하지 않았다. 현재 창 출력의 메뉴 화면도 직접 확인했다.
- 두 실행 모두 허용 설정을 복원한 뒤 원본/자료가 일치했다. 후 실행에 Q 취소 구간을 추가했으므로 두 전체 입력/프레임 수가 같다고 주장하지 않는다. 시간은 성능 비교가 아니다.
