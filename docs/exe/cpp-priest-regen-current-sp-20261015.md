# 사제 회복의 현재 SP 저장소 연결

현재 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon, 2026-10-15**다. 같은 PC에서 다시 생성한 `extracted/refined/originals/Netstorm.c`의 `00494580`을 읽고 기존 SP/사제 회복 모듈을 연결했다. 정밀 디컴파일 산출물 변경과 새 선택 export는 없다. 원본 게임·GUI를 실행하지 않았다.

`RawCampaignSession`은 이미 `ScrambledSpStore`에 같은 `priestState.regen.patch.sequence` 주소를 연결하지만, 회복 처리에서는 audit 직후 실제 offset을 `observedSequence`에 복사하고 뒤의 배열/순열 조건에는 값형 필드를 사용했다. 중립 효과나 측정이 저장소를 바꾸면 원본의 현재 읽기와 달라질 수 있었다.

`BindPriestRegenSpStore`는 추적 주소가 같은지 확인하고 현재 실제 offset·첫 배열 주소·첫 순열 WORD를 읽는 세 조회기를 만든다. 회복 몸체가 호출할 때마다 같은 저장소를 읽으며 별도 복사/동기화를 하지 않는다. 실제 세션의 audit는 `Rotate()`만 실행하고, 세 조회기를 사제 회복에 설치한다. 기존 값형 필드는 독립 기계어 fixture의 명시 입력으로 유지한다. 일부 조회기만 설치한 입력은 생성 단계에서 거부한다.

원본 순서는 난수/추적 증가 → 조건부 HP 효과 → SP 회전 → 중립 효과 → 현재 offset 비교 → 조건부 측정/횟수 감소 → 현재 첫 배열 검사 → 현재 signed WORD 검사다. 마지막 두 검사는 원본의 독립된 `if`이므로 첫 배열이 NULL이어도 WORD를 반드시 읽는다. 기존 `||`를 두 검사로 분리했다. 측정 기준은 기존처럼 **7000 초과**이며 7000과 NaN은 초과로 처리하지 않는다.

새 집중 검사는 같은 저장소의 중립 효과 중 추가 회전, stale 값형 필드와 실제 저장소의 불일치, 측정 안의 lazy 초기화, `observed→measurement→pointer→WORD` 순서, NULL 배열 뒤 WORD 조회, 누락/다른 추적 주소/부분 조회기 거부를 확인한다. 저장 SP 비트와 추적 주소 보존도 검사한다.

기존 원본 회복 **4,539개(판본별 1,513개)**를 실제 PE의 격리 x86 실행으로 다시 생성했다. 기존 fixture와 동일한 관찰이며 새 고유입력으로 합산하지 않는다. 외부 공간/표시/중립 효과와 audit/측정은 기존 관찰기의 대체 경계를 유지한다. 실제 OS/게임 실행은 없다. 빌드·집중/전체 검사 결과는 이 단위의 LEFT_JOBS 최신 절에 기록한다.

이 변경은 Early Missions·캠페인 완주 완료를 뜻하지 않는다. AI 활성화/전략, 건설·생산·다리·수확·운반·희생, 로그인/Ready/Stage3와 미션 단계/정지/승패 저장 연결은 계속 남는다. DirectDraw 전체화면 오류는 요청대로 제외한다.

소스 고정 Release 빌드 경고0·오류0, 집중24개와 공통 전체 CTest **1,238개 실패0·195.14초**가 통과했다. 이 결과는 SP와 AI 현재 조회기 변경을 함께 반영한 작업트리 기준이다. 사용자 중지 요청으로 인수인계/로컬 커밋 뒤 후속 구현을 진행하지 않는다.
