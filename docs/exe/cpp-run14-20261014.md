## Git 보존 자료의 긴 경로와 줄바꿈

이번 보존에는 이전 `.gitattributes` 자체의 전체 원문도 포함된다. 중첩한 당시 규칙이 최상위 history 규칙보다 우선해 줄바꿈을 바꿀 수 있다. 현재 저장소는 `core.longpaths=true`와 로컬 `.git/info/attributes`의 아래 규칙으로 긴 경로와 보존 바이트를 처리했다. 기존 info 규칙은 유지했다. 실행 도구가 출력한 CRLF와 공백도 로그 원문 그대로 보존한다. 재개/다른 체크아웃에서도 history 변경을 stage하기 전에 이 규칙을 추가한다.

```text
cpppj/hist/** -text whitespace=cr-at-eol,-blank-at-eol,-blank-at-eof,-space-before-tab
extracted/run14*.log -text whitespace=cr-at-eol,-blank-at-eol,-blank-at-eof,-space-before-tab
```

커밋 직전에 모든 stage 파일의 Git blob SHA와 실제 전체 바이트를 비교했다. 보존 파일과 내부 `.gitattributes` 원문을 수정하지 않는다.
