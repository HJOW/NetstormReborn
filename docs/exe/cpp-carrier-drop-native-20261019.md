# Early5 Cast/Drop 원본 실행 기준 — 2026-10-19

Early5 자연F 이후 주문 시전을 복원하기 위해, 미연결 부분의 구현 전에 원본 요청·Cast 메뉴·서버 수신의 독립 기대값을 확보했다. 이번 단위는 실제 게임의 Cast 기능 연결 완료가 아니다.

현재 PC와 마지막 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-19**다. 기존 정밀 함수표와 보호PE를 사용했고 새 디컴파일, 게임 창 실행, C++ 제품 변경은 없다. 이전 단위227의 전체1753/0실패 결과는 이전 검사 결과로 유지한다.

## 확인한 호출 경로

원본 등록 표는 메시지 `0x50`을 `444bc0`에 등록한다. `427070`은 요청 헤더 `01500900` 뒤에 부모WORD·내용물WORD·상태BYTE를 붙인다. Cast 메뉴 `42aa50`과 일반 Drop이 이 요청을 공유한다.

서버의 주문 분기는 위치 검사/정수화·입력 큐·송신자/비용 확인·이동 경로 제거·Regular 예약·부모 공간 분리·주문 생성·소유자/QA 지정·Pop 순으로 실행된다. 그 뒤 새 주문SID를 담은 **`0x5c`/버전1/길이6** 패킷을 로컬 `41e860`에 전달하고 다른 수신자에게 배포한다. `0x50` 요청을 받았다는 사실만으로 주문 효과까지 실행됐다고 판단하면 안 된다.

Devastation168의 실제 생성자 `420e40`은 VT `502370`을 쓴다. 공통 Pop은 `4b02d0`, 고유 삭제 전처리는 `41e960`이다. `41e860`은 원격 소유자 비용 처리와 주문 대상의 Regular(event0, 지연0.1초)를 예약한다. 이 후속 함수/효과는 이번413입력의 실행 범위 밖이다. 정적 경로 자료는 `…-routing-static.json`에 실행 자료와 구분했다.

## 독립 실행

`tools/decomp_carrier_drop.py`가 보호PE의 다음16개 몸체를 직접 실행한다.

`427070`, `42aa50`, `444bc0`, `40a9e0`, `40ac60`, `4df230`, `49a840`, `40eb80`, `4b2270`, `4b1b20`, `44daa0`, `4e49c0`, `41df60`, `40e800`, `4ac200`, `4ac220`.

413개 고유 입력을 x87 제어어 `027f`/`037f`에서 각각 실행해 **826회 정상 반환·107,290명령**을 관측했다. 두 정밀도의 효과·패킷·전체7슬롯 결과는 전부 같았다. 비휘발 레지스터·retN/스택 canary·SEH·빈 x87 스택·실행/읽기/쓰기 범위를 확인했다.

지면 정지 판정, 비용 승인/돈 차감, 화면 투영/숫자 표시, Regular, 부착 프로세스 조회/통지, 선택, 전송, 큰 월드 생성/Owner/Pop, 일반 배치/삭제/회피 등은 명시 효과 경계다. 전체 미션 월드나 실제 폭발·피해·사제 포획을 이 격리 실행이 대신하지 않는다.

다음 특이 동작은 추측으로 고치지 않고 원문으로 보존했다.

- 일반 Drop의 선택0은 주문을 건너뛰고 첫 비주문 내용물을 보낸다.
- Cast 메뉴는 첫 내용물SID를 보관한 뒤 플래그를 검색한다. 뒤의 항목에 플래그가 있어도 실제 요청에는 처음 보관한 SID가 들어간다.
- 송신자257과 부모owner BYTE1은 같지 않다. 수신은 전체DWORD를 비교해 거부한다.
- 원격 소유자의 비용 부족 통지 뒤에도 원본은 주문 생성·`0x5c` 배포를 계속한다.
- 일반 내려놓기는 상태BYTE를0/1로 정규화하고, 지상/정지 조건에 따라 회피를 요청한다.
- 외부 효과 뒤 비용·소유자·호출자 패킷을 바꾼 입력으로, 처음 보관하는 값과 나중에 다시 읽는 값을 구분했다.

초기 검증 준비에서는 재사용한 호출기의 POOL 주소와 새 도구의 주소가 달랐고, 새 주문의 QA 쓰기를+16으로 잘못 제한했다. 첫 도구/실패 로그를 보존한 뒤 입력을 같은 POOL로 맞추고 실제 `4ac220`의+12 WORD 쓰기를 허용했다. 최초 탐색의8바이트 배포 버퍼 관측도 실제 헤더의6바이트로 줄여 스택 잔여2바이트를 패킷으로 세지 않았다. 이 수정들은 제품 구현 전에 수행했으며 C++ 결과를 기대값 생성에 사용하지 않았다.

고정 원문은 `cpppj/tests/fixtures/carrier-drop-x86.tsv`, 원본 실행 출처는 `cpppj/carrier-drop-native.json`이다. `cpppj/carrier-drop-analysis.json`과 `tools/cpp_carrier_drop_native_audit.py --verify`는 주요 분기와 현재 출처를 별도로 감사한다. 접두는 `extracted/goal-carrier-drop-20261019-`다.

## 다음 구현
