# 썬 캐논 Fiery Tail process11 정적 분석

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 생성/공통 등록·소멸은 단위99에서 실제 몸체를 고유31입력·두 정밀도의 생성62회/삭제62회 정상 반환과 C++로 대조했다([수명 기록](cpp-fierytail-lifetime-20261016.md)). 생성자의 실제 첫8색 방향이 기존 helper 실험의 명시 RGB 입력과 반대임을 찾아 수정했다. 선행 색 띠·병합 자체는 단위97에서 복원했다([색 띠 기록](cpp-particle-gradient-20261016.md)). 단위98 프레임/Draw는 고유65입력·두 정밀도 각각130회 정상 반환과 일치한다([프레임/선 요청 기록](cpp-fierytail-frame-20261016.md)). 이 대조를 실제 Host/Kernel·장치·Session 완료로 합산하지 않는다.

## 생성과 공통 등록

- TYPE11의 `+0x1d0`은 `00458700`이다. `new(0x68)` 뒤 실제 Fiery Tail 생성자 `00457ea0(parent)`를 호출한다. `00458680`은 TYPE12용 별도 생성자로, TYPE11과 혼동하지 않는다.
- `00457ea0 → 00488190 → 00487fd0` 순서로 System/RenderProcess를 만든다. 실제 공통 표시 목록은 `00595138` 포인터·`0059513c` 용량이며40칸씩 확장한다. 목록 등록 뒤 같은 부모에 process11/flags0x10을 부착하고 파생 초기화를 진행한다. 생성 중 프레임/그리기의 재진입을 허용해서는 안 된다.
- 용량은 디컴파일의 누락된 인자에 의존하지 않고 `00457ee7 push 0x78 → 00488100`으로 확인했다. 입자120개, 각24바이트이며 저장소 전체를0으로 지운다.
- Fiery Tail vtable은 `00509538`이다. `+0x18 → 004580f0`은 프레임, `+0x20 → 004583a0`은 그리기, `+0x0c → 00487960`은 공통 표시 변경, `+0 → 004882c0`은 공유 scalar 삭제 경로다.
- 파생 초기값은 `+0x50` 공유 색 표, `+0x54 = 4`(입자 수명의 기준 정수), `+0x58/+0x5c = 0`(직전 픽셀 좌표), `+0x60 = 0`(좌표 오프셋), `+0x20 = -25`(깊이)다. `00458680`의 수명2·오프셋-8·깊이-20은 TYPE12의 값이다.

## 프레임과 입자

이 몸체는 단위98 `RawFieryTailFrame`에서 구현했다. 초기/시간 조각별 방출과 전체 용량 입자·시계·난수·dirty 요청이 기본53비트의65원본 입력 전체와 일치했다. 단위100은 공통 Host에, 단위102는 Session과 실제 Renderer의 dirty 소비/픽셀에 연결했다.

- `004580f0`은 현재 부모의 raw 좌표에 `0059a924/28`(16/11) 배율을 곱한다. 최초 프레임에는 시계 `00418400`을 초기화하고 현재 표시 영역·직전 좌표를 맞춘 뒤10개를 만든다. 입자마다 Y 난수와 X 난수를 차례로 구한 뒤 슬롯을 요청한다. 초기 수명은4다.
- 다음 프레임은 `00418470(timer, 0.5)`로 시각을 나눈다. 이 함수의 실제 최대 간격은 `0.5 × double[00501960](0.1) = 0.05초`다. 저장하는 delta는 간격×float[00500fc8](10)이고, Fiery Tail은 `+0x40` delta로 수명을 감소시킨다. 나머지 간격이 있으면 반복한다.
- 조각마다 입자2개를 추가하고 용량 전체120개를 순회해 양수 수명만 감소시킨다. 살아 있던 입자의 좌표±10을 새 표시 영역에 포함한 뒤 `00487ba0`으로 이전/새 dirty 영역과 사각형을 갱신한다.
- `00487b40`은 사용 수가 용량보다 작으면 꼬리에 추가하고, 꽉 찼으면 첫 수명<=0 입자를 재사용한다. 자리가 없어도 앞서 수행한 난수 호출은 되돌리지 않는다.
- `00455930(-3,3)`은 공유 게임 난수 상태 `00532710`을 실제로 전진시킨다. 사정선 보정에서 호출하는 `004e49c0`과 다른 함수다.

## 색상표와 실제 그리기

- 공유 팔레트는 `0055a750`이며 처음 한 번 `00487cb0`(8바이트 객체), `0043ad20`(색 띠) 두 번, `00487d20`(병합)으로 만든다. 두 색 띠는8색과3색이다. double2.4는 후보 수와 거리 임계 항목을 고르는 배수다. 단위97의 `ParticleGradient`가 실제 색 축 투영·세 차례 CRT 정렬·선택과 요청 수 병합을 복원했다. 고유24입력·두 정밀도 색 띠96회/병합144회 정상 반환을 보존했다. 기존 건설/불타는 표시와 Session의 외부 경계에 연결하는 작업은 별도다.
- 첫 띠 RGB는 **`(185/255,0,0) → (1,195/255,6/255)`**, 둘째는 `(1,195/255,6/255) → (1,1,173/255)`다. 첫 띠를 반대로 기록했던 정적 메모와 제품 호출을 단위99 실제 생성자 관찰로 정정했다. 기존 helper fixture의 반대 방향 입력·결과는 그대로 보존한다. `BuildFieryTailPalette`는 실제 PE double 비트를 사용하며3팔레트의 실제 생성자11색과 일치한다. 원본 CRT 기본은53비트(실제 초기화023f, 관찰027f와 연산 설정 동일)이며 비교64비트037f를 임의로 사용하지 않는다.
- `004583a0`은 사용 수만큼 순회하며 양수 수명에 대해 `00487e50`으로 색을 읽고 **입자 화면 좌표→호출자가 준 부모 화면 끝점+offset의 선**을 `004dade0`에 요청한다. 단위98에서 카메라·정수화·끝점 감김·색의 전체 DWORD 요청이 원본과 일치했다. 수명==최댓값의 배열 뒤 DWORD도 명시 입력으로 관찰했고 없으면 제품은 거부한다. 단위101의 [실제 데모3 heap 관찰](cpp-fierytail-live-heap-20261017.md)은 이번 한 실행의 배열 뒤 DWORD가1임을 확인했다. 단위102는 실제 flags0·44바이트 할당과 OS 인접 메모리 읽기를 연결했으나, 클론64비트 heap의 값이 원본32비트 실행과 같다는 증거는 아니다. 고정1·임의12번째 색·마지막 색 clamp로 대체하지 않는다.
- 전역 `005318ec == 2`일 때 공유 색수 DWORD를0x17655, `+0x54` 최대 수명을0x315a로 바꾸는 별도 분기가 있다. 단위98은 이 쓰기와 출력도 관찰·복원했다. 전역의 의미·정상 도달 여부는 아직 미확정이며 임의의 화면 모드 의미를 붙이지 않는다.

## 클라이언트 연결과 다음 경계

단위100에서 생성/프레임/Draw/삭제 몸체를 **같은 공통 표시 registry와 실제 Host/Kernel**에 연결했고, 기존 건설 표시도 같은 목록/토큰을 공유하도록 옮겼다. [공통 표시 연결 기록](cpp-render-process-system-20261016.md)의 통합 검사와 실제 Form 삭제 통지48입력이 통과했다.

단위101은 실제 원본 복사본의 데모3에서11색/인접1과 heap mode1을 읽었다. 게임/녹화는 종료했다. 이 관찰은 [원문/범위](cpp-fierytail-live-heap-20261017.md)대로 한 실행의 근거다.

단위102는 `RawCampaignParticles`로 같은 Session의 Host/World/Kernel·공유11색·실제 할당/인접 읽기·카메라·dirty/VFX 래스터를 연결했다. GameWorld가 다른 SHP와 같은 Renderer 정렬/부분 갱신/SceneImage로 출력한다. 독립 원본 Draw→wrapper→VFX는 고유30입력·두 정밀도60정상 반환/차이0이며 C++ 전체 픽셀이 일치했다. 실제 데모 자연 발사도 **표시 Pop→effect11→Missile 부착**의 Kernel 순서와 화면196색을 확인했다. [연결·픽셀 근거와 한계](cpp-campaign-particles-20261017.md)를 따른다.

데모3은 기존113프레임/2.825초의 effect11을 통과했고 다음 경계는 **145프레임/3.625초 TYPE131 썬더 캐논의 미복원 투사체 생성**이다. 데모1 TYPE148 stage5·전체 GUI/입력·미션 자연 완주와 원본 전체 동일성은 별도로 남아 있다. 실제 할당 경계를 공급한 것과 원본32비트의 미정의 인접 메모리 값까지 동일하다는 주장은 구별한다.
