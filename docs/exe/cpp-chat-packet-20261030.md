## 원문 송신 순서

현재 이름 포인터를 먼저 고정한다. 이 시점에 이름이 비었으면 정적 `++Nameless++`를 선택한다. 대상 manager의 현재 count와 DWORD 배열에서 자기 subscriber를 탐색하고, 없으면 기존0042d1b0을 실행한다. 추가 callback 뒤에는 원문 위치에 따라 현재 subscriber·모드·manager 필드를 다시 읽지만 처음 선택한 이름 포인터는 바꾸지 않는다.

전투 모드에서는 this+0x10의 채널 비트에 this+0xc 비영일 때0x100을 합친다. 이를 **signed 십진 문자열**로 만들고 길이가3보다 짧으면 앞에 `0`을 삽입한다. 이어 본문의 첫NUL 앞까지 붙인다. 이 경로의 전송 본문 길이는 NUL을 제외한다. 비전투 경로는 호출자가 지정한 본문 물리 길이 전체를 복사하므로 NUL 뒤의 바이트도 길이 안에 있으면 보존한다. 이 차이를 임의로 통일하지 않았다.

패킷의 +5는 ASCII1, +6은 현재 subscriber DWORD, +10은 이름의 NUL 포함 길이 WORD, +12는 메시지 길이 WORD, +14는 수신자 수 BYTE다. +15부터 이름·본문·수신자 DWORD 배열을 놓는다. 미작성 +4는ff다. 수신자 수는 BYTE에 절단되지만 실제 복사는 원래 count의 전체 DWORD 배열을 사용한다.

원문의 builder004df590은 초기 길이 전역00544c5c를 최소4로 보정하며, 송신 직전 observer0040a8d0이 현재 이름/본문/수신자 필드로 +2 WORD를 확정한다. 이 단계를 건너뛴 패킷을 현재 길이4인 채로 전송에 넣으면 안 된다. 기존 전송의 observer 경계에 연결할 부품으로 별도 복원했다.

전송 채널 선택은 원문 순서대로00594fb8→1,00594fc8→11,00594fbc→9다. 모두0이면 원문 오류를 로그9에 쓰고 `0.0.0.0:0` 주소 장치 뒤0042f0e0 로컬 수신을 호출한다. 정상 종료의 반환값은 하위 송신 결과와 무관하게1이다. 이번에는 **단독9와 채널 없는 fallback만** 관측·검사했으며 MP1/11은 정적 분기만 작성했다.

## 길이 observer와 물리 범위

수신 인자0은 바이트를 바꾸지 않는다. 송신 비영은 nameLen==ffff이면 원문 assertion줄0x81d, addrLen==ff이면0x81f를 호출한 다음 길이를 WORD로 합산한다. bufferLen은 zero-extend 후DWORD -1과 비교하므로 원문0x81e assertion에는 도달하지 않는다. 디컴파일의 조건을 의도대로 고치는 대신 실제 명령을 유지했다.

호스트 구현은 원문 alloca 요청이 실제 복사 폭보다4BYTE 작은 부분에서 메모리 밖 쓰기를 하지 않도록 **전체 복사 물리를 소유**한다. 그 안의 패킷 바이트·길이 절단·observer 순서는 보존한다. 이름의 signed WORD 주소가 물리 밖으로 향하거나 실제 배열/본문이 부족한 입력은 명시 범위 오류다. 원문 손상 입력의 임의 주소 접근까지 재현한다고 세지 않는다.

`MakeClientChatPacketHooks`는 같은 장기 owner의 실제 manager/배열과 기존 AddChatRecipient를 사용한다. 현재 이름/전역과 실제 송신·주소·수신 장치는 호출자가 연결해야 한다. 도달한 장치가 없으면 그 위치에서 예외를 내고 앞선 자기 추가를 유지한다. 미선택 장치를 미리 요구하지 않는다.
