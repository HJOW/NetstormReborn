# cpppj 옵션 저장·전체화면 시작 표시 복원

> 2026-10-05. 패치판 10.78 기준, CD판 10.72 대조. 원본 게임 프로세스는 실행하지 않았다.
> `options.cfg`·`fullscreenStateFile.dat`는 cpppj 검사 동안만 변경한 뒤 원래 바이트와 존재 상태로 복구했다.

사용자가 정한 대로 cpppj는 `<게임 폴더>/d/options.cfg`를 원본과 같은 저장 시점·형식으로 읽고 쓴다. 시작 저장과 변경 후 저장, Windows-1252·XOR 형식, 전체화면 시작 표시의 조회·생성 경로를 복원했다. 메인 메뉴의 표시 파일 삭제 사건은 UberGump를 옮길 때 연결한다. DirectDraw 자체는 아직 없다.

## 저장 시점과 경로

| 역할 | 패치판 | CD판 | 확인한 동작 |
|---|---|---|---|
| 시작 저장 | `004359f0` → `00441d10(0)` (`00435a05`) | `00485410` → `004a9090(0)` | 설정 시작 직후, 설정 해석 전 무조건 한 번 저장 |
| 변경 검사 | `00441de0`, 호출 위치 `00439ad3` | `004a9c30`, 호출 위치 `00486767` | 전역 설정의 변경 표시가 켜졌을 때 저장 |
| 파일 저장 | `00440f30` | `004a9270` | 파일 이름 섹션 본문과 `[END]` 본문을 이어 쓰고 변경 표시 해제 |

패치판 저장 함수의 직접 호출은 `00441d53`·`00441d96`(시작 저장의 인자 분기)과 `00441e24`(변경 검사) 세 곳이다. `00441d10`의 실제 호출자는 시작 함수 한 곳이며 인자는 0이다. CD판은 시작 함수와 변경 검사에서 `004a9090(0)`을 부른다. 원본 게임 종료 시에 별도로 저장하는 직접 호출은 없다. 옵션 화면의 값 변경도 변경 표시를 통해 다음 메인 루프의 저장으로 이어진다.

디컴파일 출력에는 시작 함수·루프의 조각이 중복되어 호출 횟수가 더 많아 보이는 곳이 있다. 위 횟수는 실행 파일의 직접 `call` 명령으로 확인했다.

경로 조립의 `00540cec`는 `00503c8b`의 **빈 문자열**, `00540cf8`는 `00508ab4`의 **`d`**를 가리킨다. CD판의 `00510940`·`0051094c`도 같다. 설치 폴더 문자열 자체를 가리키는 포인터가 아니다. 원본은 게임 폴더를 작업 폴더로 삼아 `d\options.cfg`를 연다. cpppj는 작업 폴더를 바꾸지 않고 같은 파일을 게임 폴더 기준으로 연다. 설정 후보 경로 탐색은 기존처럼 미구현이다.

`Client::Run`은 시작 시 `SaveOptions()`를 부르고, 입력 처리 뒤 커널 갱신 전에 변경 표시를 검사한다. `global.dd…` 등 실행 중 설정 버퍼에 쓴 값도 이 저장에 포함된다. 따라서 일반 `--run`은 원본 게임의 다음 실행에 사용할 설정을 갱신한다.

## 저장 바이트

1. `[options.cfg]` 본문이 있고 `mQdsT`로 시작하지 않으면 서명 5바이트를 쓴다. 본문이 서명을 포함하면 그대로 쓴다.
2. 그 본문 뒤에 `[END]` 본문을 쓴다. 다른 섹션·섹션 이름 자체는 쓰지 않는다.
3. 문자 바이트는 Windows-1252이며, 파일 처음부터 `mydoghasfleas`를 반복 XOR한다. 쓰기 호출이나 4KB 블록마다 키 위치를 처음으로 돌리지 않는다.
4. 원본 `BaseFile` 모드 2는 `w+b`다. 기존 내용을 잘라 내고 저장한다.

cpppj가 붙이던 UTF-8 BOM을 제거했다. 내부 UTF-8은 `EncodeOriginalText`에서 원본 바이트로 역변환한다. Windows-1252의 모든 256개 바이트가 왕복한다. 원본 인코딩에 없는 문자와 잘못된 UTF-8은 파일 쓰기 전에 실패한다. 한국어 저장 형식은 요구사항 단계의 후속 작업이다. 이전 UTF-8 BOM 파일의 읽기 호환은 유지하지만 새 저장에는 BOM을 붙이지 않는다.

**빈 파일 섹션의 예외:** 파일 이름 섹션을 찾지 못하면 원본은 `[END]`만 XOR해 쓰며 서명을 새로 붙이지 않는다. 아무 본문도 없으면 빈 파일이다. 이 경우까지 기계어 기대값과 일치하도록 `EncodeConfigFile`은 서명을 임의로 추가하지 않는다.

`ConfigInterface::SaveFile`은 저장 내용과 인코딩을 만든 뒤 호출자가 제공한 파일 쓰기를 수행한다. 쓰기·인코딩 실패 시 이전 변경 표시를 보존하고 성공 뒤에 끈다. `o/`는 OS 파일 쓰기를 직접 호출하지 않는다.

## 전체화면 시작 표시와 디컴파일 정정

| 역할 | 패치판 | CD판 | 동작 |
|---|---|---|---|
| 존재 검사 | `00436dd0` → `004dd560` | `00487670` | 게임 폴더의 `fullscreenStateFile.dat`에 `GetFileAttributesA` 호출 |
| 표시 만들기 | `00436df0` | `004876a0` | `r+b`로 열고 없으면 `w+b`로 만든 뒤 데이터를 쓰지 않고 닫음 |
| 표시 삭제 | `00436e40` | `00487720` | CRT `remove`; UberGump 버튼 사건에서 호출 |

이 파일은 `d/` 밖에 있다. 파일 내부의 값을 읽는 동작은 없고, 존재 여부가 시작 판단에 쓰인다. cpppj는 존재 검사와 전체화면 시도 직전의 생성을 같은 자리에 넣었다. 삭제 함수 `Client::ClearFullScreenState`도 복원했지만, 아직 없는 UberGump의 버튼 사건에는 연결하지 않았다. 일반 종료에서 임의로 지우지 않는다.

**기존 분석 정정:** 디컴파일은 `004395df`를 WinMain에서 호출·반환하는 함수처럼 표현했다. 실제로는 WinMain 중간의 분기 목적지다.

- 패치판 `004395a4`에서 표시를 검사하고, 존재하면 `004395ad`에서 전체화면 플래그를 0으로 만든 뒤 `004395df`로 **점프**한다. 창 모드 초기화로 이어진다.
- 전체화면 초기화가 0을 반환해도 `004395cb`에서 플래그를 0으로 만든 뒤 같은 창 모드 경로로 간다.
- CD판 `00486253`~`004862ae`도 같은 구조다.

따라서 “원본은 전체화면 초기화 실패 시 그대로 종료하므로 창 모드 복구는 새 기능이다”라는 이전 설명은 잘못됐다. 현재 cpppj의 창 모드 복구는 원본 동작이다. 사용자가 겪은 전체화면 전환 뒤 재실행 오류의 전체 원인은 이 정적 분기만으로 확정하지 않는다. DirectDraw와 UberGump까지 복원한 뒤 검증할 일이다.

## 검증

```powershell
python tools/decomp_options_oracle.py
ctest --test-dir cpppj/build --build-config Release --output-on-failure
python tools/cpp_config_smoke.py
python tools/cpp_window_smoke.py
```

`decomp_options_oracle.py`는 두 판본의 저장·섹션 읽기·XOR 쓰기 기계어를 격리 실행한다. 파일 열기·닫기·`ftell`·`fwrite`·파일 이름 객체·`strncmp`는 명시적으로 대체한다. **XOR 계산은 원본 기계어가 수행**하고, 실제 OS API·원본 게임은 실행하지 않는다. `recovery-options-evidence.json`에 판본 해시, 대체 함수, 직접 호출 지점, 경로 포인터, 화면 모드 분기의 역어셈블을 기록한다.

- 두 판본이 같은 결과를 낸 **16개 입력**: 서명·빈 섹션·대소문자·파일 경로·중복 섹션·모든 비ASCII 바이트·4KB/8KB 경계·실제 설정 버퍼 2개. 기대값은 `tests/fixtures/options-x86.tsv`이며 C++ 단위 검사가 최종 XOR 바이트와 비교한다.
- 실제 설정 버퍼를 C++와 두 판본 저장 기계어에 넣은 결과도 바이트 단위로 같다. 이 PC에서는 패치판 **834바이트**, CD판 **114바이트**다. `InstallDir`에 따라 다른 PC에서는 길이가 달라질 수 있다.
- 설정 스모크는 게임 폴더의 `options.cfg` 저장 허용, 다른 파일의 저장 거부(대소문자·`..` 포함), 저장 왕복, 실패 시 설정 복구를 확인한다.
- 창 스모크는 타입 표 픽셀 대조·미션 화면에 더해 시작 표시 파일 생성과 기존 표시가 있을 때의 창 모드 재시작을 확인한다. 검사 전후 원본 파일 해시와 목록이 같다.

두 스모크는 `cpp_smoke_files.preserve_game_settings`로 설정과 시작 표시를 보관하고 `finally`에서 복구한다. 원래 없던 파일은 이 두 경로에 한해서 제거한다. `cpp_fort_smoke.py`는 파일 읽기 명령만 실행하므로 저장 예외를 추가할 필요가 없다.

원본 프로세스의 전체 시작·옵션 메뉴 조작은 검증하지 않았다. 저장 형식은 같은 버퍼의 원본 기계어와 대조한 결과이며, 아직 없는 모듈까지 포함한 설정 값 전체가 원본과 같다는 뜻은 아니다.
