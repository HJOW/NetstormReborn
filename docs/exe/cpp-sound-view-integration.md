# 위치 효과음의 화면·카메라 연결

> 후속 갱신(2026-10-10, HJOW-Athlon): [날씨 팔레트·화면 갱신 연결](cpp-weather-palette-integration.md)과 해상도 변경 시 색 보존을 완료했다. 아래 날씨 경계 미연결 항목은 화면·카메라 작업 당시의 인계이며 네 실제 COL 확보·번개·전체 원본 GUI는 남는다.

2026-10-10, 작업 PC **HJOW-Athlon**. AGENTS.md·LEFT_JOBS.md·LEFT_JOBS.dotnetpj.md의 최신 인계를 확인하고 클라이언트 소리 부착의 남은 `SoundView` 연결을 진행했다. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-10**(변동 없음). 기존 정밀 디컴파일을 읽었으며 디컴파일 산출물·원본 PE·관찰 fixture는 변경하지 않았다.

위치 재생 함수는 이미 복원됐지만, `ClientAudio`의 `SoundState::view`는 기본 640×480·카메라 원점 0으로 남아 있었다. 따라서 다른 해상도와 미션 카메라로 위치 효과음을 요청하면 화면 안 판정·좌우·거리 음량에 잘못된 기준이 사용될 수 있었다. 이제 실제 화면과 월드 카메라를 전달한다.

## 연결과 수명

| 연결 위치 | 전달하는 값 |
|---|---|
| `Client::Run`의 소리 초기화 | 카메라 0, 현재 화면 전체 영역 |
| `GameWorld::SurfaceView` | 실제 카메라와 raw 표시에도 전달하는 현재 월드 영역 |
| `GameWorld::Resize`·`Scroll`·`Home` | 크기/카메라가 바뀐 입력 단계에서 바로 갱신 |
| `UberGump::BeginMission` | 초기 홈 카메라를 브리핑 정지 전에 설정 |
| `Client::ChangeResolution` | 현재 카메라를 유지하면서 새 장치 크기를 반영 |
| `UberGump::ClearWorld` | 이전 카메라를 제거하고 전체 메뉴 영역으로 복귀 |

[`ClientAudio::SetView`·`View`](../../cpppj/src/client/ClientAudio.h)는 위치 재생 계층이 읽는 `SoundState::view`를 쓰고 읽는다. `GameWorld::soundViewChanged`가 주 스레드에서 이 값을 공급한다. 같은 크기로 `Resize`를 불러도 수신자를 갱신하며, 소리 옵션이 꺼져 있어도 최신 값을 전달한다. 장치 종료/재초기화는 화면 정보를 지우지 않는다. 반복 소리의 위치 음량·좌우 갱신과 화면 밖 정지는 기존 `SoundPlayer::PlayLoopAt`의 다음 요청이 처리한다.

원본의 카메라 전역 `0059a91c`·`0059a920`, 화면 영역 `005ca9cc`~`005ca9d8`을 읽는 좌표/화면/좌우/음량 계산 함수는 [소리 재생 계층](cpp-sound-play-reconstruction.md)의 기존 복원을 사용한다. 계산식·재생 순서·독립 원본 대조 자료는 바꾸지 않았다. 기존 정밀 디컴파일에서 원본 `Ubergump`의 패널 사건이 영역을 갱신하는 부분과 초기 화면 영역 설정도 읽었다.

**현재 월드 영역은 기존 어댑터의 `(0, 28, 화면 폭, 화면 높이)`이고 메뉴는 `(0, 0, 화면 폭, 화면 높이)`다.** raw 표시 경계와 같은 값을 그대로 공급한다. 원본의 가변 생산/상태 패널과 슬라이딩 사건에 따른 영역 계산은 복원하지 않았다. 이번 연결은 그 원본 GUI 전체 복원을 뜻하지 않는다.

검사 보고 `ClientAudio::Describe()`에는 `soundCameraX/Y`·`soundLeft/Top/Right/Bottom`을 더했다. `--ui-report`의 `audio_view`는 같은 프레임의 여섯 값을 기록하므로 월드의 `camera`·화면의 `size`와 직접 비교할 수 있다. `--no-audio`에서는 소리 보고 항목을 만들지 않는다.

`SceneFrame`의 헤더 주석도 실제 메인 루프와 원본 근거에 맞췄다. 게임 시계가 멈춰도 음악의 곡 끝 확인은 계속 호출한다.

## 검증

- Release 빌드 경고/오류 0. CTest 내부 **533개·실패 0**, 135.72초. 기본 CTest는 실제 장치를 열지 않는다.
- `--inspect-client-audio originals`의 **2회 실제 장치 검사** 통과. 기존 메뉴 스트림/장치 끄기·켜기/전투 곡 검사에 위치 반복 소리를 추가했다. 800×600 중심의 감쇠 0 → 카메라 x=200 이동 뒤 감쇠 -250 → 화면 밖 정지 → 재진입 재시작 → 장치 재초기화 뒤 영역 보존을 확인했다. 전 과정 음소거다.
- `cpp_audio_smoke.py`의 화면 연결 시나리오는 실제 UI 입력으로 **51개 관찰 프레임**을 비교한다. 브리핑 정지 중 초기 카메라, 스크롤/홈, 메뉴 복귀, 옵션에서 800×600·640×480·1024×768 변경, 소리 끄기/켜기, 각 해상도에서 미션 재진입을 확인했다. 현재 미션 UI에는 Options가 없어 크기 변경은 메뉴 복귀 후 수행한다.
- 기존 소리 재생/WAVE/장면 음악 원본 근거 감사 **3종 통과**(14,472·1,305·9,339개). 새 원본 입력은 없으며 누적 독립 입력은 **453,808개 그대로**다.
- 최종 `cpp_audio_smoke.py` 전체 통과(기존 메뉴/전투 곡·옵션·설정 끔 검사와 새 화면 시나리오). 보호 대상 원본 **1,392개**의 내용/존재 상태가 유지됐다. 기존 `cpp_world_smoke.py`·`cpp_menu_smoke.py` 회귀도 통과했으며 10.78/CD 자료 불변과 허용된 설정 파일의 보관/복원을 확인했다.

화면 시나리오의 첫 실행은 현재 미션에 없는 Options 버튼을 찾다가 실패했다. 검사 경로를 현재 UI에 맞게 메뉴 복귀 후 옵션 변경으로 고쳤고 화면 시나리오를 다시 실행해 통과했다. 클라이언트 코드는 이 실패 때문에 변경하지 않았다.

로그는 Git 제외 `extracted/soundview-{build,ctest,device,view-smoke,audio-smoke-final,world-smoke,menu-smoke}.log`와 `extracted/cpp-audio-smoke/`에 있다. 원본 게임·분석 프로그램은 실행하지 않았다. 실제 장치 검사는 모두 음소거이므로 사람이 들은 음질·좌우·끊김·음악/효과음 균형은 검증하지 않았다.

## 남은 일

원본 가변 GUI 영역, 월드의 게임 전역 난수 공유, 희생/결과/대기실 음악 요청, 날씨 팔레트·번개·화면 갱신 경계, 건설/전투/UI의 효과음 호출자와 월드 `SoundProcess` 부착이 남아 있다. 특히 이번 검사는 위치 효과음의 화면 정보 공급과 재생 경계를 확인한 것으로, 실제 게임 플레이에서 아직 복원되지 않은 효과음 호출자를 추가한 것은 아니다. 건설·경제·전투·AI·승패도 남아 미션 완주는 아직 불가능하다.
