### 항목 작성

40개 이상이면 문자열에 접근하기 전에 반환한다. 구분선은 자식이나 비어 있지 않은 문자열을 허용하지 않으며 선두·연속 구분선은 생략한다. 명령/인자는 각각 비트 `1`/`80`일 때만 쓴다. 쓰지 않은 라벨 외 필드는 보존한다.

자식이 있고 `800` 비트가 없으면 등록 ID를 기록하고 visible 비트를 내린 뒤 `Attach(0, 0, menu, 0)`를 호출한다. 패치는 ID 기록→숨김, CD는 숨김→ID 기록 순서다. `800`이면 ID만 기록한다. 자식 부착 후 현재 항목 수를 다시 읽어 플래그와 문자열을 쓰며, 문자열 콜백 후에도 현재 항목 수를 다시 읽어 증가시킨다. 콜백에서 수를 바꾸면 앞서 쓴 명령/인자/ID와 나중에 쓴 문자열의 칸이 다를 수 있다.

일반 라벨은 원본 `strncpy(..., 40)`처럼 NUL 뒤를 0으로 채운다. 40바이트 이상이면 별도 종료 문자를 쓰지 않는다. `MenuGumpItemBytes`는 뒤의 DWORD까지 원본 순서로 직렬화하므로 기존 `GumpText`가 해당 바이트를 포함해 측정할 수 있다. 전체 60바이트 안에도 NUL이 없으면 기존 범위 검사에서 거부한다.

스타일 라벨은 문맥 8 DWORD를 먼저 복사하고 font 슬롯을 0으로 만든다. `clearStyle` 호출 후 **현재** 비활성 비트 `200`을 다시 읽고 접두 `~*~x`를 붙인다. `parseStyle`에는 완성 문자열과 복사한 문맥을 전달한다. 소유 해제와 파서/측정 내부는 외부 경계다. `clearStyle`이 기존 토큰을 비우고 `parseStyle`이 새 토큰을 같은 항목 필드에 저장해야 한다.

원본의 256바이트 스타일 버퍼를 넘는 입력은 소유 해제 후 예외로 거부한다. 배열 밖 항목 접근·필수 경계 누락도 실제 도달 시 예외로 거부한다. 이미 수행한 원본 순서의 쓰기는 되돌리지 않는다. 원본의 assert 이후 진행이나 버퍼 넘침을 재현하지 않는다.

### 레이아웃

폭 여백은 세로 메뉴에서 좌우 각 15, 그 외 각 4다. 작은 여백 비트 `1000000`이면 각 3으로 바뀐다. 높이 여백은 위아래 각 1이다. 항목마다 **현재** 기본 문맥을 복사해 plain/styled 측정을 선택한다. 세로 메뉴의 자식 비트 `20` 또는 분리 비트 `800`에는 현재 문맥으로 `" >"`를 추가 측정한다.

측정 출력은 signed DWORD다. 폭 덧셈·총 높이·가로 메뉴의 항목 수×최대 폭은 x86 하위 32비트 감김을 보존한다. 여백 합계와 세로 offset은 CRT 절삭을 거친다. 저장한 float 항목 높이를 누적 offset 계산에서 다시 읽는다. 항목 수·플래그·여백은 해당 콜백 이후 필요한 시점에 재조회한다.

장식 메뉴는 현재 제목 Push→Fit(0)→Layout(0,0)→폭 비교/절삭→현재 좌표 Attach 순서다. 각 호출 후 제목 포인터를 다시 읽고, 제목 부착 후 현재 방향 비트로 크기 계산을 선택한다. 세로 메뉴는 최대 항목 폭/높이 합계와 누적 offset을 쓴다. 가로 메뉴는 항목 수×최대 폭/최대 높이와 공통 항목 높이·offset 0을 쓴다. 방향 비트가 둘 다 없으면 목표/기본 크기와 offset은 유지하되 측정 높이와 항목 폭은 갱신한다.

`BindMenuLayoutText`는 plain 라벨과 `" >"`를 실제 `GumpText`/`FontStore`에 연결한다. 장식/제목 Push·Attach에는 기존 메뉴 크기 처리와 같은 가상 분배를 공급해야 한다. StyleText의 Clear/Parse/측정과 제목 Fit/Layout은 별도로 공급한다. 객체 저장소와 처리기 수명은 훅보다 길어야 한다.

## 원본 분석 자료와 빌드

[decomp_menulayout_oracle.py](../../tools/decomp_menulayout_oracle.py)는 원본 게임 진입점·OS·assert를 실행하지 않고 추출한 메뉴/CRT/측정 위임의 실제 x86 명령만 격리 실행한다. plain/styled 측정값, StyleText 소유/파싱, 제목 Fit/Layout, 가상 Push/Attach는 입력으로 지정한 외부 응답이다. 해당 내부를 복원하거나 게임 화면을 실행한 것으로 간주하지 않는다.

두 실제 PE **각 130개, 합계 260개**의 원본 입력을 기록했다. 방향·여백·장식·항목 수 0/1/3/40·음수/큰 signed 측정값·구분선·자식·문자열 길이 0/1/39/40/50·비활성 스타일·콜백 뒤 상태 변경을 포함한다. 각 입력을 x87 제어 워드 027f/037f에서 실행해 전체 출력과 콜백 당시 상태 기록이 같았다. 최상위 정상 반환은 **548회**다. ABI·x87 제어/TOP·허용 코드/쓰기 범위·입력 문자열/문맥/가상 표 보호를 분석 도구에서 확인한다.

관찰 파일은 `cpppj/recovery-menulayout-observations.tsv`, 메타데이터/해시는 `cpppj/recovery-menulayout-evidence.json`에 있다. 최종 상태는 메뉴 전체 0xb90바이트와 자식 둘의 기본 160바이트씩을 기록하고, 콜백 직전에는 전체 저장소 CRC32와 인자를 기록한다. 근거를 재생성하려면 `tools/ghidra/menulayout-functions.json`의 판본별 함수 목록을 정밀 프로젝트의 `ExportCreation.java`에 넘긴 다음 아래 원본 분석 명령을 사용한다.

```powershell
python -X utf8 tools/decomp_menulayout_oracle.py
cmake --build cpppj/build --config Release --target netstorm NetstormCpp --parallel 2
```

게임 라이브러리와 `NetstormCpp`의 **Release 빌드 경고 0·오류 0**. 로그는 `extracted/menulayout-build.log`이다. **이번 단계의 C++ 테스트 추가/실행·전체 CTest·GUI 실행은 미수행**이다. 원본 관찰 누적은 **523,634개**이며 이번 260개에 대한 C++ 전수 재생 대조는 남아 있다. **854개 통과와 C++ 대조 누적 523,374개는 앞 단계 기록**이다.
