# RGB 입자 색 띠와 팔레트 병합 복원

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 단위97은 Fiery Tail TYPE11의 선행 의존인 색 띠 생성과 팔레트 병합을 복원했다. 실제 게임·GUI와 새 디컴파일은 실행하지 않았다. 기준은 보호10.78 PE이며 CD10.72는 이번 대조에 포함하지 않았다.

## 제품 동작

`cpppj/src/o/ParticleGradient.*`에 다음 원본 경로를 구현했다.

- `00439de0`의 RGBX 입력을 실제 double 상수로 정규화한다. 예약 BYTE는 색 계산에서 무시한다.
- `0043ad20/0043abe0`의 시작·끝 최근접 색, 시작색 평행 이동과 색 축 투영을 같은 연산·저장 순서로 계산한다.
- `0043a660`의 축 거리와 `0043a0c0/0043a300/0043a3d0`의 세 비교기를 원본 CRT의 qsort/shortsort 교환 순서로 실행한다. 동률과 선택하지 않은 항목의 비교0도 보존한다.
- 요청 수×폭2.4의 float 저장·반올림으로 거리 임계 항목을 찾고, double 절삭으로 후보 수를 정한다. **2.4는 후보 수와 거리 임계값에 쓰는 배수**다. 균일 RGB 보간이나 감마 보정으로 해석하지 않는다.
- 축 위의 선택 위치마다 엄격히 가까운 첫 후보를 표시한다. 중복 선택은 실제 선택 수를 늘리지 않는다. 마지막 선택 항목의 **색 번호만** 끝색 번호로 교체한다.
- `00487d20`의 병합은 실제 선택 수가 아니라 각 색 띠의 **요청 수**만큼 정렬 배열의 앞부분을 복사한다. 요청 수보다 선택 수가 적은 경우도 보존한다.

`BuildFieryTailPalette`는 PE의 RGB binary64 상수로8색+3색, 총11색을 만든다. 실제 세 COL 팔레트에서 이 전용 생성 경로도 독립 원본 병합 결과와 일치했다. 배열 뒤의 인접 할당 DWORD를 임의로 추가하지 않는다.

지원 입력 범위는 헤더에 명시했다. 양 끝이 같은 팔레트 색을 고르는 영길이 축과 원통 후보 수 범위 밖 입력은 거부한다. 원본의 NaN 경로까지 복원했다는 의미가 아니다.

## 독립 원본 검증

`tools/decomp_particle_gradient.py`가 실제 PE 함수 몸체를 격리 x86에서 실행했다. 실제 RGB 팔레트 생성·투영·선택·세 차례 CRT 정렬·정수 변환·팔레트 생성/병합을 대체하지 않았다. new/free의 성공과 주소만 명시적인 외부 입력이다.

- 실제 `GIFCLOUD.COL`·`BULF.COL`·`SUNCANNON.COL`, 합성 회색·중복 색·다색 팔레트의 **고유24입력**이다. 각 입력은 팔레트와 두 색 띠 매개변수의 조합이다.
- 기본53비트 `027f`와 비교64비트 `037f`에서 **색 띠96회·병합144회 정상 반환**했다. 같은 입력의 다른 정밀도를 고유 입력으로 중복 가산하지 않는다.
- 원본80바이트 항목 중 RGB 차·색 번호·거리·투영·선택 표식의 **의미48바이트×256항목** 전부와 헤더·1/2/3색 띠 병합을 보존했다. HSV와 패딩은 비교 범위에서 제외한다.
- 각 호출의 반환/ESP·비휘발 레지스터·x87 제어어/TOP/tag·스택 sentinel을 확인했다. 입력 RGBX와 기초 팔레트·병합 입력 객체가 변경되지 않았음을 검사하고 쓰기 영역을 제한했다.
- `0043a660`은 현재 정밀 함수표에 누락돼 있다. vtable `00506688`과 실제 PE 명령의 `ret4`로 확인한 **0043a660..0043a79e**만 별도로 허용했다. 전체 디컴파일을 변경하거나 이 함수가 내보내졌다고 기록하지 않았다.
- 두 차례 전체 생성의 fixture SHA는 동일한 `c918f485648298270e7cc2457474c176e2dd4042d3c5e7577839b4c0fc1f9f1a`다. 마지막 생성은 아래 정밀도 초기화 증거까지 포함한다.

원본 CRT 시작 경로는 `__cinit(1) → __fpmath → __setdefaultprecision`이다. 실제 `004e81da`와 하위 제어어 변환 함수를 별도로 실행해 초기 `037f`가 **023f**로 바뀌는 것을 확인했다. 이는 제어어 전체가027f라는 뜻이 아니다. 연산 정밀도53비트·반올림·예외 마스킹 비트가027f 관찰과 같다. 초기화1회는 색 띠 관찰 수에 합산하지 않는다.

두 정밀도는21입력에서 의미 필드가 달랐고, 그중7입력은 최종 색 번호도 달랐다: `GIFCLOUD.COL-2`, `BULF.COL-0/2`, `SUNCANNON.COL-2`, `duplicates-0/1/2`. C++는 기본53비트 결과와 비트 단위로 일치하며, 비교037f 결과는 fixture에 보존하되 지원 완료로 세지 않는다.

## 검증 결과와 남은 연결

Release 전체 빌드 경고0·오류0, `ParticleGradient` 집중2검사 모두 통과했다. 기본정밀도24입력/48색 띠와72병합의 모든 의미 필드·색 번호 및 실제 Fiery Tail 전용 생성자의3팔레트를 비교했다. 전용 생성자는 같은 원본 관찰을 재사용한 검사이며 새 원본 입력으로 세지 않는다.

전체 CTest는 **1416개 중1414통과·기존2실패, 195.70초**다. CTest는 하나의 실행 파일을 등록하므로 요약의 `1 tests failed`는 내부1416개 전체가 실패했다는 뜻이 아니다. 전체 종료 로그는 남았으나 도구 응답이 문맥 압축에서 생략돼 셸 종료 코드는 기록하지 않았다.

- 데모1:145프레임/3.625초, TYPE148 반더 타워 stage5 애니메이션 미복원.
- 데모3:113프레임/2.825초, TYPE128 비행 효과11 사전 검사 경계.

새 모듈은 아직 Session의 `flightEffect`에 연결하지 않았다. Fiery Tail의 생성/삭제·120입자·난수/시계·프레임·공통 표시 목록·dirty/픽셀 출력 및 사용자 자연 완주는 남았다. 특히 최대 수명의 색 조회가11색 배열 다음 DWORD를 읽는 원본 계약을 확인해야 한다. 빈 출력이나 임의 색을 넣어 이 경계를 넘기지 않는다. 다음 근거는 [Fiery Tail 인수인계](cpp-fierytail-notes-20261016.md)다.
