# Fort 원본 객체 로딩의 월드 효과·기본 소유자

2026-10-13, 현재 PC와 마지막 정밀 디컴파일 PC **VM-W11-CODEX**에서 현재 refined 두 판본, `Template.cpp`, `GameWorld.cpp`, 보호 `netstorm.tarc`의 1-1 파일을 읽었다. 이 단계는 읽기 전용 분석이다. 원본/클론 게임·GUI 실행이나 보호 파일 수정, 새 구현/커밋/푸시는 하지 않았다.

## 기본 소유자 전달

원본 `004be610/CD 00428d50`은 `Template::loadObjects`의 실제 진입이다. 로딩 깊이를 증가시키고 타입 이름 변환표를 만들며 지정한 Terr 범위를 순서대로 로드한다. 기본 소유자는 `this`가 원본 Template 전역 배열의 어느 칸인지를 계산한다.

- 패치 전역 배열 시작 `005c89f0`, 칸 크기 `0x14`다. `(this - 005c89f0) / 0x14`가1~8이면 해당 번호, 그 밖은0이다.
- `004be2c0/CD 00428a00`은 지도 청크를 y 바깥·x 안쪽으로 읽으며 `0046f200`의 지역/소유자 조건을 만족한 청크만 `004be160/CD 004288a0`에 넘긴다.
- `004be160`은 표지99와 WORD 개수를 읽고 각 객체에 기본 소유자를 `004bdc60/CD 00428320`의 param4로 전달한다.
- `Chaff`는 fort모드 `00594fb8` 또는 모드 `00594fa4`가 있을 때 읽는다. `004be3c0/CD 00428b20`이 전체 지도 청크를 같은 y/x 순서로 읽으며 동일한 Template 기본 소유자를 전달한다.
- 정상 종료 시 변환표를 해제하고 해당 Template 소유자의 후처리 `0040e1a0`을 부른 뒤 로딩 깊이를 감소시킨다.

현재 `GameWorld::Place`는 저장 소유자가 없으면 무조건1을 사용한다. 해당 값은 위 Template 인스턴스/현재 모드에서 계산한 기본 소유자를 대신할 수 없다. `FortObject::NormalizedOwner`도 저장 byte의 정규화만 표현하며 전체 월드 소유자 분배가 아니다.

## 객체 소유자 선택의 실제 분기

객체 body가 읽는 전역은 버전 `005c89c0/CD 005178dc`, 저장 소유자 마스크 `00542644/CD 005178c8`, 강제0 마스크 `00542648/CD 005178cc`, 특별/편집 `005c85a4/CD 00518904`, 미션 `00594fa0/CD 0052e16c`다.

1. 최초 후보는 전달받은 기본 소유자다. 저장 타입이0xf6 이상인 다리 약식이면 후보를 `255-storedType`으로 바꾼다.
2. 버전이0보다 크고 현재 genus가 ownerSaved 마스크에 포함되면 소유자 byte를 읽고0 또는9 이상을1로 바꾼다. 특별/편집 또는 미션이 참이면 이 정규화한 저장 소유자를 유지한다. 두 전역이 모두0이면 기본 소유자로 덮는다.
3. 버전0이면 위 저장 byte 분기를 거치지 않고 기본 소유자로 덮는다. 따라서 버전0 다리 약식의 owner도 기본 소유자가 된다.
4. 버전이0보다 크고 ownerSaved 마스크에 포함되지 않으면 후보를 그대로 유지한다. 이 경로의 다리 약식은 약식 소유자를 유지한다.
5. 현재 genus가 ownerCleared 마스크에 포함되면0이다. 현재 타입이 isle(`005411d0`,97) 또는 noIsland(`005412cc`,157)여도0이다. isleBig(`005411d4`,98)은 진단 경로다.
6. 해당 자산의 가상 +0x74를 호출한다. 사제는 원래 소유자/로컬 표식을 다루므로 owner byte를 직접 쓰는 것으로 대신할 수 없다.

미션 생성자 `00482bf0`는 `inMission=1`을 설정한다. 원본 State 경로의 `004b71c4`가 ESI를1로 설정하고 `004b71e7/004b71e8`에서1을 두 번 push하여 `0048f3b0(1,1)`을 호출한다. 이는 현재 플레이어/Template 소유자 모두1인 초기화이며 단순 한 인자 디컴파일 표기에 의존하지 않고 실제 명령을 확인했다. 1-1은 이 미션 조건에서 저장 owner1/2를 유지한다. 다른 Template/모드에도 무조건 이 값을 적용하지 않는다.

## 실제 객체 효과 순서

`004bdc60/CD 00428320`은 저장 필드를 읽는 동시에 실제 월드를 변경한다.

1. 위치/타입을 읽고 타입 변환 또는 다리 약식을 처리한다. 타입0은 뒤의0 byte를 검사하고 끝내며 isle는1 byte를 건너뛰고 실제 생성하지 않는다.
2. 실제 factory `(type,0)`로 초기화된 자산을 생성한다.
3. 현재 flags1에 따라 saveFrame byte를 raw 프레임에, saveQA byte를 WORD 낮은 byte에, saveQB signed WORD를 전체 WORD에 쓴다. 다리 genus면 저장 다리 프레임을 추가로 쓴다. 이 과정의 WORD 쓰기는 실제 가상 표면 알림 경로를 가진다.
4. 버전0의 legacyState 또는 버전2 이상 factoryState를 가상 +0x84에 전달한다.
5. 위 분기로 소유자를 선택하고 가상 +0x74를 호출한다.
6. 실제 HasHitPoints가 참이면 현재 최대 HP를 조회하여 가상 HP 지정 +공통 body로 쓴다. 단순 `.type maxHitPoints` 복사는 사제1/4 모드/dais 특수 경계를 우회한다.
7. flags1 `0x200000`이면 현재 좌표의 지형 객체를 원본 genus finder로 찾아 그 프레임을 전달한다. flags1 `0x100000`이면 원본 `0049aa90/CD 004444c0`의 P/P·wildcard 프레임 선택을 수행하고 -1을0으로 바꾼다. 이 선택에는 실제 전역 난수 소비와 최대256개 후보/대체 방향 분기가 있다.
8. 실제 가상 Pop +0x90에 flags9를 전달한다. 새 호스트의 일반 Pop0과 동일시하지 않는다. 원본 함수의 인자 좌표와 raw x/y 필드/호스트 경계를 일치시켜야 하며 디컴파일의 param2/param3 이름만으로 순서를 추정하지 않는다.
9. 현재 flags1 container `0x20000`이면 `004bd130/CD 00426dd0`이 Pop 후 실제 contained 자산/Form을 재귀 생성한다. 먼저 container를 Pop한 후 내용물을 붙이는 순서를 보존한다.
10. fort모드/편집 억제 전역/허용 genus 및 dais 개수 조건에 따라 가상 Destroy0를 요청하는 후처리가 있다. 미션에서는 초기화한 미션/보존 전역 조건을 같은 상태로 공급해야 한다.

내용물 body는 타입 변환→QA/QB→현재 내용물 listFlags→부모 containerListFlags→파일 byte 순으로 결정한다. listFlags0x10이면 전달 flags9의0x8을 끄고0x10을 켠 뒤 `004afa70`에 `listFlags & ~0x100`, quantity/WORD와 함께 생성 요청한다. 중첩 container는 생성한 해당 내용물 SID에서 재귀 처리한다. 값형 `object.contents` 복사로 원본 raw 체인을 대신하지 않는다.

## 1-1 보호 자료에서 확인한 값

보호 `originals/netstorm.tarc`의 `\d\thewarbegins.fort`를 기존 읽기 전용 파서로 확인했다. Chaff/Terr00/Terr01 모두 버전2이며 Chaff는256 청크, Terr00은6 청크, Terr01은3 청크다. 청크 내 순서의 상대 좌표만 아래에 기록하며 실제 월드 청크 위치는 지역 배치의 결과를 사용한다.

실제 priest.type에는 saveFrame이 없고 생성/이 body의 기본 프레임은0이다. `GameWorld::Place`는 `.type defaultFrame` C02를 선택하는 값형 어댑터이므로 이 값으로 raw 원본 프레임을 덮으면 초기 표시가 달라질 수 있다. 사제 QA129/2는 이후 실제 소유자 지정에서 원래 소유자 low7/로컬 표식과 상호작용한다. 거주 구역의 randframe 효과도 기존 단일 defaultFrame과 다르다.

실제1-1 월드 연결은 위 기본 소유자/모드/flags9·현재 최대 HP·사제 프레임0·randframe/지형 프레임·Pop 이후 contained 재귀·로딩 깊이/타입변환표 수명을 복원해야 한다. 이번 분석은 정적 근거와 보호 자료 입력을 확보한 단계이며, 해당 body의 독립 x86 실행 및 실제 캠페인 로딩 비교는 후속 작업이다.
