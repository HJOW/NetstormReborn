# 실제 캠페인 세션의 자동 AI 프레임 연결

현재 PC와 마지막 전체 정밀 디컴파일 PC는 **VM-W11-Codex / 2026-10-22**로 같다. 시작 HEAD는 `ebd0dedb / 20261022-45 CP`다. AGENTS와 두 인수인계를 확인했으며 보호 원본/CD·AGENTS·dotnetpj·기존 원본 fixture를 변경하지 않았다. 새 전체 디컴파일이나 게임·창 실행은 없다.

`RawCampaignSession::RunFrame`은 현재 게임 시각을 먼저 반영하고 일시정지가 아닐 때 `RawAiRuntime::Frame`을 실행한 뒤 같은 월드의 Kernel을 진행한다. 네 다리 전략과 Planning은 기존 후보 검색·공용 난수·실제 Player 기술부모·섬 그래프·지면 점유표를 공유한다. Runtime의 초기화·준비·목표 선택·수집자·시설·사제·건물 배치·다리·운반자·경제·SP·소멸/반납도 기존 세션의 실제 몸체에 연결했다. 현재 벽시각은 기존 건설 서비스와 같다. 원본 `00417c70/00417d30/00417de0`과 상위 비정지 AI→Kernel 호출 순서가 근거다.

GUI는 UberGump가 장기 GameWorld를 Client Kernel에 등록하고 `GameWorld::RunFrame`이 같은 Session을 호출한다. 따라서 별도 수동 AI API 없이 이 연결을 사용한다. 이 호출 경로 확인은 실제 화면·음향의 동일성 검증을 뜻하지 않는다.

AI의 자연 채집이 도달하는 원격 너겟 수입 통지도 원본 `004e2dc0`의 현재 Player 접속 비트와 NULL 연결 관문을 보존했다. 사람 접속 비트가 없는 AI나 연결 객체가 없는 대상은 송신이 자연 생략된다. 지갑/SP는 기존 `SquidReward`가 계속 계산한다. 실제로 연결된 원격 사람의5a 패킷은 기존 미복원 경계를 유지하며 멀티플레이 완료로 주장하지 않는다.

검색이 호출되는 시점에만 필요한 caller의 초기 8바이트는 `CampaignAiServices::bridgeScratchBytes`로 분리했다. 기존 본문/목록의 힙 할당 입력과 합치지 않는다. 실제 Windows 서비스는 초기화하지 않은 현재 로컬 8바이트를 자기 프로세스 읽기로 복사하며, C++ 미정값을 부동소수점 연산으로 직접 읽지 않는다. 검사에는 명시 패턴 `0x71`을 공급한다. 원본 x86과 호스트의 서로 다른 스택 잔여 바이트가 같다는 보장은 없으며, 검색 결과나 성공 좌표를 합성하지 않는다.

새 자동 세션 검사는 보호 `thewarbegins.fort`의 실제 로컬 로그인 후 명시 프로필로 AI를 생성한다. 수동 초기화·준비·전략·배치 API를 호출하지 않고 0.1초 간격 240프레임을 진행했다. 자연 결과는 초기화1·준비1·목표2·현재 재고3·owner2 실제 다리 칸 **15→25**·수집자 **3**·SP/지갑 **5000/5000**이다. HP·SP·배치·경로 결과를 직접 주입하지 않았다. 종료 프로필은 정지 프레임에서 유지되고 다음 비정지 프레임에 실제 본문을 소멸/반납하며 Player flags는 유지된다.

Early Missions6개·캠페인1-1~1-6·데모3개의 **15개 시작 경로**는 각각 원래 Fort/영어 스크립트→실제 로컬 로그인→공통 Start→자동 AI/같은 Kernel을25ms씩400프레임 진행했다. 새 캠페인1-3/1-4/1-5/1-6 검사4개를 추가했고, 일반 게임에서 로컬AI가 없고 데모에서만 있는 조건도 확인한다.
