# 1062 — R 서버 메인 통신 부모

제공된 R.exe의00476b80 통신 부모를 `root/NetworkPump`로 복원하고 netstorm 정적 라이브러리에 컴파일했다. 제품 기준은 **1062 / 11.01**, 게임 EXE 12,365,824바이트, SHA-256 `1399adc9232cf1c87429b3fcd45c43bc5178fa8e62038b75ce26933ed5834fb5`다. 직전 CP 커밋은 `f261f530 / 20261107-91 CP`다. **새 R.exe 대상·실제 소켓/분배/Root·CS 관리자는 아직 미구현이며 이 부모를 실행 중인 클라이언트에 호출 연결하지 않았다.** 라이브러리 컴파일을 서버 실행/통신 성공으로 계산하지 않는다.

## 원문 순회와 현재 조회

게임의22칸 전송표를 재사용하지 않고 기존 R ConnectionState의 일반256칸/대기32칸/Challenge51칸을 사용한다. Challenge마다 실제 +2ad8의40개 전송 토큰을 장치에서 읽는다. 세64칸 select 집합은 원문처럼 직접 추가하므로 중복을 제거하지 않고, 가득 찬 집합의 추가만 생략한다. 전체 소켓 개수는 따로 증가하며64번째부터 원문 진단을 요청한다. PE004cd860=1499에 분기별2e/40/65를 더한1545/1563/1600줄을 사용한다.

지역 FullTime4739b0은 처음 한 번 캡처한다. 같은 double의ftol64 하위 DWORD라는 장치 계약으로 순회 중 값을 유지하고, 마지막 수신 DWORD와의 SUB 감김 뒤 signed 비교를 적용한다. 옵션은 해당 수신 getter 복귀 뒤 현재값을 비교한다. 일반 timeout은+90이0이고 하위socket bit80이 꺼져야 종료한다. 대기 timeout은 실제 -index의858d0으로 보내며 슬롯0도 원문 집합 단계에 포함한다. Challenge 참가자 수는 timeout 전에 증가하므로 그 참가자가 종료돼도 이번 유휴 판단 개수에서 빼지 않는다.

일반 수신이나 Challenge 수신 콜백 뒤에는 원문처럼 같은 현재 슬롯을 다시 조회한다. 일반 슬롯이 지워졌으면 flush를 생략하고, Challenge 두 호출 사이에는 새 슬롯 값도 두 번째 장치에 전달한다. 임의0 슬롯 복구/서버 성공/준비 상태를 합성하지 않는다. 실제 장치가 선택됐는데 비어 있으면 명시 오류다. 로그는 원문의 level9/39와 전체 서식을 작성한 문자열을 넘겨 주소 문자열을%d의 정수 가변 인자로 잘못 전달하지 않게 했다. 원문 `Chal transciever` 철자도 보존한다.

## 호스트 경계와 확인

R004cd804의 PE초기1과004d2208의BSS0을 별도 NetworkState로 소유한다. timeout 네 DWORD는 BSS0이며 실제 서버 초기화/옵션 연결은 후속이다. OS 핸들과 최고값은 x64 포인터 폭을 보존한다. 이때 비교도 호스트 signed 포인터 폭이고32비트 원본 핸들 숫자/할당 배치 자체를 복원한 것은 아니다. Windows select는 nfds를 사용하지 않으며, 실제 WinSock 장치/시간 변환/보조 객체/Challenge 분배 접합은 아직 없다. 집합의 사용하지 않는 배열 바이트0도 원본 미정 스택 ABI 일치로 계산하지 않는다.

게임 Release/x64 빌드는 종료0·경고/오류0이다. 새 단위/MP/게임/통신/원본R 검사는 모두0이고 보호2800파일 불변·새fixture0이다. 전체 검사/34미션/ZIP은 반복하지 않았다. 원시 함수 사본/PE 값과 빌드 로그는 Git 제외 `extracted/cpp-resume-1062/`, 보고서는 `cpppj/root-network-pump-20261107.json`이다.
