# cpppj 1315 — 한국어 유닛 정보의 빈 본문 교정

2026-11-17, HJOW-Athlon. 사용자 제보인 **한국어 플레이 → 유닛 우클릭 → 정보의 빈 창**을 실제 미션에서 재현하고 교정했다. 마지막 디컴파일 호스트와 현재 PC가 일치하며, 원문 재디컴파일·원본/기존 fixture 수정은 없다. 제품 EXE 코드는 바뀌지 않고 한국어 번역 자산과 회귀 검사만 바뀐다.

## 원인과 번역 상태

`QuickHelpControl.cpp`의 `DispatchQuickHelpWindow`는 TYPE 요청의 내부 이름에 번역된 `Type`을 붙여 주제를 만든다. 한국어 용어표가 이를 `종류`로 번역해 `priest종류`를 요청했지만, `help.korean`의 실제 주제는 `priestType`이었다. 주제를 못 찾은 HTML 파서는 마지막 줄바꿈만 반환하므로 빈 문자열용 안내도 나오지 않고 그림만 보였다. 동적 능력치 표도 해당 주제 안의 `<info>`에서 생성되므로 함께 사라졌다.

한국어 도움말 파일 자체에는 **고유 128주제·앵커 138개**가 있으며, 유닛·건물·자원 정보용 `Type` 앵커는 **76개**다. 본문 미번역/파일 부재가 이번 빈 창의 원인은 아니다. 전체 문장의 번역 품질은 기존 사람 검수 대상으로 유지한다.

`assets/lang/korean/xlat.korean`의 `Type` 값을 원래 `Type`으로 보존하고, 내부 주제 접미사라는 설명을 더했다. 원본 사건 분배·주제 조회·도움말 본문·표시용 일반 단어의 번역을 변경하지 않는다. 저장소 C++의 해당 문자열 소비자는 유닛 정보 분배이며, 도움말 목록 생성기도 같은 `Type` 접미사를 사용한다. 번역표는 시작 때 적재하므로 현재 게임에는 **재시작 후** 반영된다. 독립 배포본에는 수정된 `lang/korean/xlat.korean`을 포함해야 한다.

## 검증

- 새 회귀 검사는 실제 한국어 용어표 → `DispatchQuickHelpWindow` → 실제 `help.korean`의 `QuickHelpHtml` 본문까지 연결한다. 모든 76개 정보 앵커의 요청 이름과 한글 본문 존재를 확인한다. 수정 전 **1검사·152단언 실패**, 수정 후 **1/1 통과**다. 기존 fixture 기대값은 바꾸지 않았다.
- Release `netstorm_korean_text_tests` 빌드 종료0, 관련 전체 **40/40 통과**다. 기존 한국어 128주제/큰 본문·영어 출력 동일성·언어 전환·일본어 검사가 포함된다. 제품 라이브러리 변경이 없어 불필요한 전체 제품 재빌드는 하지 않았다.
- 격리 데이터 사본과 별도 `NETSTORM_USER_DATA`로 `thewarbegins`에 진입해 실제 사제 우클릭 정보 메뉴를 눌렀다. 수정 전 본문 길이0·한글0, 수정 후 본문693자·한글314자이며 **능력치 표와 본문을 화면으로 확인**했다. F1 도움말도 표시된다. 영어 대조 실행은 본문1,130자이며 정상이다. 세 관측 실행 모두 종료0·게임 데이터 사본1,392파일 불변이다.
- 상태/승리 주입·공격·포획/희생·MP 실행은 하지 않았다. 최초 관찰 도구의 한국어 시작 버튼/보고서 제어문자 해독 보정 전 진입 실패3회는 별도 원시로 보존하며 제품 실패로 세지 않는다.
