# 생산 창 유닛 재충전 시간

> 분석일: 2026-09-29. 기준: 보유 `Netstorm.exe`의 정적 디컴파일과 `originals/d/setup.cfg`.
> 이 문서의 시간은 실행 파일에 기록된 예약 간격이다. 실제 화면 변화는 게임 루프의 다음 갱신 때 보인다.

## 모드와 설정

* 화면 왼쪽 생산 창은 플레이어가 부르는 **덱**이며, 원판 매뉴얼의 **Production window**다.
* 전투 옵션 `options[2]`인 Unit Rate는 0 Slow, 1 Medium, 2 Fast를 가리킨다. 옵션 화면 표의 선택 가능 범위는 1~2이고 기본값은 2다. 내부 시간표에는 인덱스 0도 있다 ([전투 옵션](battle-options.md)).
* `useProductTimers`는 `00441270`에서 등록되는 설정이다. 보유 `originals/d/setup.cfg`에는 `useProductTimers = 0`이며 `options.cfg`에는 이 키가 없다. 따라서 보유 설정에서는 아래의 기본 타이머 경로가 적용된다.
* `DAT_00594fb8`은 **`inFortMode`**다. `State.cpp` `004b2df0`의 모드 상호 배제 검사와 `Template.cpp` `004bf9a0`의 `inFortMode` 검사 문자열이 이를 직접 뒷받침한다. `004b6dd0`의 요새 모드 진입 경로 두 곳에서 1로, `004b2df0`의 모드 종료 경로에서 0으로 설정된다. `DAT_00594fbc`는 별도 `inBattleMode`다 (`Template.cpp` `004bf880`).

## 예약 간격

| `useProductTimers` | 경로 | Slow (0) | Medium (1) | Fast (2) | 요새 모드 처리 |
|---|---|---:|---:|---:|---|
| 0 | `Cursor.cpp` `004468b0` | 10초 | 5초 | 1초 | `inFortMode`이면 **0.0001초**로 대체 |
| 0이 아님 | `Combatgump.cpp` `0043f3xx` | 30초 | 15초 | 8초 | 해당 코드에 요새 모드 예외 없음 |

* 기본 경로에서 `004468b0`은 배치한 유닛에 플래그 `0x100`을 붙이고, `00496e80`으로 시간 제한 이벤트를 등록한다. `inFortMode`일 때 전달하는 상수 `0x38d1b717`은 약 0.0001초다. 따라서 보유 설정의 요새 모드에서는 대기 시간이 실질적으로 한 게임 갱신 수준이지만, 즉시 같은 호출 안에서 다시 채워진다고 단정하지 않는다.
* `useProductTimers`가 켜지면 `0043f3xx`는 타입별 예정 시각이 지났을 때 생산 수량을 1 올리고, 다음 예정 시각을 **현재 시각 + 표의 간격**으로 바꾼다. 수량 상한 `DAT_0054db74`는 초기화 코드에서 1로 설정된다. 이 경로는 게임 안에서 해당 설정을 켜서 확인하지 않았다.
* The War Begins! 영상 앞 15분에서 생산 아이콘 변화가 드문 것은 요새 모드의 짧은 예약 간격과 모순되지 않는다. 화면만으로 이벤트 실행 시점이나 배치 후 아이콘 복귀 간격을 프레임 단위로 확정할 수는 없다.

## 구현에 쓸 기준

보유 설정을 재현할 때는 요새 모드에서 Unit Rate와 무관하게 거의 즉시 재충전하고, 전투 모드에서는 Unit Rate에 따라 10/5/1초를 사용한다. 클론의 시간 처리는 고정 틱으로 구현하되, 원본과 대조할 때는 이벤트가 등록된 뒤 다음 갱신에서 실행될 수 있음을 고려한다. `useProductTimers`를 사용자 설정으로 제공한다면 별도의 30/15/8초 경로와 수량 상한 1을 적용한다.

남은 확인: 보유 게임에서 유닛 배치 직후 생산 아이콘 복귀를 프레임으로 측정하고, 일반 전투 화면에서는 같은 조작으로 Unit Rate별 간격을 재현한다. 원본과 클론의 실제 시각 차이는 이 동적 검증 뒤에 확정한다.
