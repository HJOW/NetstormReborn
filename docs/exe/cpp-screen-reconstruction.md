# cpppj 창·화면 장치·입력 큐·영역 배치 복원 (Win32)

> 2026-10-05. 기준은 패치판 `originals/Netstorm.exe`(10.78), 대조는 CD판 `originalCD/NETSTORM.EXE`(10.72).
> 원본 게임 프로세스는 실행하지 않았다. 처음 복원할 때 원본 파일은 읽기만 했고, 후속 [옵션 저장 복원](cpp-options-reconstruction.md)의 검사는 허용된 설정·시작 표시만 변경 후 복구했다. [후속 계획](../cpp-roadmap.md)의 2단계 나머지(영역 배치)와 3단계의 앞부분(플랫폼 결정, 창, 화면 장치)에 해당한다.
> **같은 날 후속:** 표시 기반과 [메뉴·브리핑·정적 미션 진입](cpp-menu-reconstruction.md)을 연결했다. [Renderer·글꼴·커서](cpp-renderer-reconstruction.md). 이 문서의 초기 검증 횟수/미완료 메모는 당시 범위이며 현재 전체 검사 수는 59개다. 실제 월드/플레이는 후속이다.

## 1. 원칙: 원본과 같은 방식으로 만든다

사용자(개발자)가 2026-10-05에 정한 cpppj의 방향이다. 같은 날 AGENTS.md에도 적혔다: "cpppj - C++ , 기존 게임을 디컴파일하여 C++ 코드로 최대한 복원하는 것이 1차 목표이다. 이후 윈도우10, 11에서 실행 가능한 수준으로 만들고, 요구사항 반영 및 MCP 추가한다. 윈도우용만 개발한다." / "dotnetpj - C# + MonoGame 기반으로 개발. cpppj 완성 후 이를 분석하여 개발."

목표의 순서는 **① 디컴파일한 코드를 C++로 최대한 복원(1차 목표) → ② Windows 10/11에서 실행 가능한 수준 → ③ 요구사항 반영과 MCP**다. 그래서 ①의 단계에서는 원본의 동작을 고치지 않고 그대로 옮기고, 원본에 없는 기능(와이드 화면, 60·120프레임, 한국어, 전체화면 재실행 오류 수정)은 ②·③에서 다룬다.

> **2026-10-10 갱신:** 위 인용과 ①②③은 2026-10-05 당시 AGENTS.md 문구다. 현재 AGENTS.md는 **1차 10.78 싱글플레이 복원 → 2차 Windows 10/11 오류 없는 실행 → 3차 TCP/IP 로컬 멀티플레이·outpost → 4차 요구사항 반영·MCP·한국어 지원**이다. 이 문서의 ②는 2차, ③은 4차에 해당하고 3차가 그 사이에 들어간다. 전체화면 재실행 오류 수정은 2차, 와이드 화면·60/120프레임·한국어는 4차에서 다룬다.

* cpppj는 **기존 게임 원본을 되살리는 것**이 목적이다. 기능 변경을 최소로 하고, **원본과 같은 방식**으로 만든다.
* 이후 **MCP를 붙여 원본 게임 분석에 쓴다.** 그래서 원본의 구조(초기화 순서, 전역 상태의 뜻, 화면·입력의 경로)가 코드에서 그대로 보여야 한다.
* cpppj는 **Windows 전용**이다(Linux 지원 없음). 한국어 지원은 cpppj에서는 후순위다.

이에 따라 플랫폼은 **Win32 API를 원본처럼 직접 부르는 방식**으로 정했다. SDL 같은 중간 라이브러리는 쓰지 않는다. 외부 라이브러리가 없으므로 빌드에 인터넷이 필요 없다는 점도 그대로다.

| 항목 | 결정 |
|---|---|
| 창·메시지 | `RegisterClassExA`·`CreateWindowExA`·`PeekMessageA` — 원본과 같은 호출, 같은 클래스 이름 `NetstormClient` |
| 그리기 | 8비트 DIB 섹션(`CreateDIBSection` + `DIB_PAL_COLORS`) → `SetDIBColorTable` → `BitBlt`. 원본 창 모드의 경로 그대로 |

| 입력 | 창 프로시저 → 40칸 사건 큐, `GetAsyncKeyState` 폴링 — 원본과 같다 |

## 4. 화면 장치

**화면 모드 플래그**(`DAT_005c78d4`). 설정 `windowScreenFlags`(기본 10)·`workingFullScreenFlags`(기본 11)의 값이다.

| 비트 | 뜻 | 정해진 뒤 적히는 설정 |
|---|---|---|
| `0x01` | DirectDraw 전체화면 | `global.ddFullScreen` |
| `0x02` | 그리기 표면이 DIB 섹션 | `global.ddBackBufferDib` |
| `0x04` | 페이지 플리핑 | `global.ddFlipping` |
| `0x08` | 구름 | |
| `0x10` | 구름 시차 | `global.ddParallax` |
| `0x20` | 구름 움직임 | |
| `0x40` | 커서를 직접 그림 | `global.ddSoftwareMouse` |
| `0x80` | 모드를 정할 때 항상 켬 | |

허용 조건(`004a13d0`)은 다섯 가지다: 전체화면은 DirectDraw가 있어야 하고, 플리핑은 전체화면에서만, 시차와 움직임은 구름이 있어야 하며, 전체화면도 DIB도 아니면 안 된다.

**창 모드의 그리기 경로.**

1. `Screen::Init`: 창 장치 문맥을 감싼 표면(종류 2), 메모리 장치 문맥, 빈 논리 팔레트(256색)를 만든다.
2. `Screen::InitDibSection`: 화면 크기의 8비트 위→아래 DIB 섹션(종류 1)을 메모리 장치 문맥에 고른다. 색 표는 `DIB_PAL_COLORS`(논리 팔레트 번호 0~255)다. 게임은 이 버퍼에 팔레트 번호로 그린다.
3. `Screen::SetMode`: 창 모양(바탕 화면이 게임 화면과 같은 크기면 테두리 없는 창)과 위치(`initWindowPos` 1~5 = 왼쪽 위·오른쪽 위·오른쪽 아래·왼쪽 아래·가운데)를 맞추고 팔레트를 적용한다.
4. `Screen::SetPalette`: 0번은 검정, 255번은 흰색으로 고정한다. `SetDIBColorTable`로 DIB 색 표를 바꾸고 논리 팔레트를 새로 만들어 고른다.
5. 프레임마다 `Lock` → 그리기 → `Unlock` → `Update`(`BitBlt`로 DIB에서 창으로).

원본 그대로 둔 세부: 표면의 줄 간격은 폭과 같다고 본다(화면 폭 640·800·1024는 4의 배수라 실제 DIB 줄 간격과 같다). 창 크기를 맞추는 `MoveWindow`는 높이 자리에도 폭을 넣는다(곧 `SetMode`가 바른 크기로 다시 옮긴다). 창은 한 가지 크기로만 둔다(`WM_GETMINMAXINFO`).

화면 크기는 설정 `SCREENW`·`SCREENH`에서 읽는다. **설정에 없으면 0 × 0이 되어 DIB를 만들지 못한다**(원본 assert `dibBuffer`와 같은 자리에서 멈춘다). 설치된 게임은 `options.cfg`에 이 값이 있다. `originalCD/`는 설치본이 아니라 CD 내용이어서 `options.cfg`가 없으므로 `--set "SCREENW=800;SCREENH=600"`처럼 명령줄 설정으로 준다.

## 5. 전체화면 (옮기지 않음)

원본은 `Screen` 초기화 때 `ddraw.dll`을 `LoadLibrary`로 열어 `DirectDrawCreate`를 찾고, 전체화면이면 DirectDraw 표면(종류 3·4·5)에 그린다. 이 경로는 아직 옮기지 않았다.

그래서 cpppj의 `Screen`은 **"DirectDraw 없음" 상태로 동작한다.** 원본 `004a4fe0`에는 DirectDraw가 없는데 전체화면을 요구하면 플래그를 10(창 모드: DIB + 구름)으로 바꾸는 규칙이 있고, cpppj는 그 규칙을 그대로 탄다. `originals/d/options.cfg`에 `startInFullScreen`이 켜져 있어도 창 모드로 뜬다.

AGENTS.md의 요구(전체화면, 16:9·16:10·4:3, 가장자리 스크롤, **전체화면 전환 뒤 재실행 오류가 없어야 함**)는 목표 순서의 ②·③ 단계(현재 AGENTS.md의 2차·4차 목표)에서 다룬다. 1차 목표 단계에서는 DirectDraw 경로를 원본대로 옮긴다. **이전 분석 정정:** `004395df`는 종료 함수가 아니라 WinMain의 분기 목적지다. 상태 파일이 있거나 전체화면 초기화가 실패하면 원본도 플래그를 0으로 만들고 창 모드로 이어 간다. [역어셈블 근거](cpp-options-reconstruction.md). 재실행 오류의 전체 원인은 아직 확정하지 않았다.

**주의:** 지금 `originals/d/options.cfg`는 `startInFullScreen = 1`이다(2026-10-05 읽기 전용 확인). cpppj는 DirectDraw가 없어 창 모드로 뜨지만, 원본 게임은 이 값 때문에 전체화면으로 시작하려 한다.

## 6. 입력

**사건 코드**(32비트). 글자는 아래 16비트에, 글자가 아닌 키는 가상 키 코드를 16비트 왼쪽으로 밀어 넣는다.

| 비트 | 뜻 |
|---|---|
| `0x80000000` | 뗌(키·버튼 올림) |
| `0x40000000` | 폴링: 지난 확인 뒤에 눌린 적 있음 |
| `0x20000000`·`0x10000000`·`0x08000000` | Shift·Ctrl·Alt |
| `0x04000000` | 폴링: 커서가 창 밖이거나 창이 비활성 |
| `0x02000000` | 프로그램이 넣은 명령 사건 |
| `0x00010000`·`0x00020000`·`0x00040000` | 왼쪽·오른쪽·가운데 버튼 |

**큐**(`DAT_0055a510`)는 40칸 고리다. 한 칸은 가득 참을 구분하는 데 쓰여 39개까지 담기고, 가득 차면 **새로 넣은 사건을 버린다**. 꺼낼 때 글자 `0x7f`(DEL)는 Ctrl+Backspace로 바뀐다. "뗌 사건 거르기"로 꺼내면 뗌 사건은 큐에서 빠지고 빈 사건이 돌아온다.

**창 프로시저**가 큐에 넣는 것: `WM_KEYDOWN`·`WM_KEYUP`(글자가 되는 키는 `WM_CHAR`에서 넣으므로 건너뛴다 — `ToAscii`로 판별), `WM_CHAR`, Alt와 함께 눌린 `WM_SYSKEYDOWN`·`WM_SYSKEYUP`, 마우스 버튼 여섯 메시지. 창을 활성화한 클릭은 게임 입력으로 넣지 않는다(제목 표시줄 클릭으로 활성화한 경우는 예외). `WM_SYSCOMMAND`의 `SC_KEYMENU`는 막아서 Alt가 메뉴를 열지 않는다. 좌표는 커서 위치에서 창 테두리 두께(`DAT_005c7904`·`DAT_005c7908`)를 뺀 화면 좌표다.

옮기지 않은 것: 등록 메시지 `NETSTORMOOGABOOGA`(설정 도구와의 통신), 메뉴 명령 `0x9c45`(소리), 커서 모양(`WM_SETCURSOR`), Esc가 글자가 되지 않는 자판의 처리(`DAT_0054db58 == 3`), 전체화면에서의 활성·비활성 처리.

## 7. 원본과 다르게 둔 것

기능을 바꾸려는 것이 아니라, 아직 옮기지 않았거나 원본 파일을 보호하려고 둔 차이다.

| 항목 | 원본 | cpppj | 이유 |
|---|---|---|---|
| 뮤텍스 | 만든다 | 만들지 않는다 | 원본과 함께 띄우기 |
| 아이콘·로딩 그림 | 자기 실행 파일의 리소스 | 게임 폴더의 원본 실행 파일을 자료로 열어 읽는다 | 리소스를 저장소에 복사하지 않는다 |
| 전체화면 | DirectDraw | 창 모드로 바뀐다 | 5절 |
| 창으로 내보내기 | 바뀐 사각형만 | 변경 영역만 | 후속 표시 기반 단계에서 연결했다 |
| `WM_PAINT` | Renderer가 있으면 "전체 다시 그리기" 표시 | BeginPaint/EndPaint·전체 무효화 | 후속 표시 기반 단계에서 연결했다 |
| 검사용 옵션 | 없음 | `--frames N`(그만큼 그린 뒤 닫기), `--screenshot`(화면 버퍼를 BMP로) | 자동 검사 |

## 8. 정한 것과 정하지 않은 것

* **`options.cfg`는 원본 게임과 동일하게 처리한다 (2026-10-05 사용자 결정).** AGENTS.md가 `options.cfg`와 `fullScreenStateFile.dat`의 수정·삭제를 예외로 허용한다. cpppj는 원본이 읽는 그 파일(`<게임 폴더>/d/options.cfg`)을 원본과 같은 시점에, 같은 형식으로 읽고 쓴다. 따로 둔 저장 위치는 만들지 않는다. 원본 게임과 설정을 함께 쓰게 되는 것은 의도한 결과다.
  * **구현 완료:** 설정 시작 직후 저장(`00441d10`)과 메인 루프의 변경 후 저장(`00441de0`)을 연결했다. Windows-1252·XOR 형식은 두 판본의 저장 기계어 16개 입력으로 확인했다. [옵션 저장 복원](cpp-options-reconstruction.md).
  * 저장 내용은 `[options.cfg]` 본문과 `[END]` 본문이다. 파일 이름 섹션이 없으면 서명을 추가하지 않는 원본 예외도 보존한다.
  * `fullScreenStateFile.dat`: 실행 파일의 이름은 `fullscreenStateFile.dat`다. 게임 폴더의 존재 검사·전체화면 시도 직전 생성과 **UberGump 메인 버튼 활성 사건 삭제**를 연결했다. 스모크는 두 파일의 바이트·존재 상태를 복구한다.
* **소리·글꼴·영상의 방식.** 원본은 DirectSound, 자체 비트맵 글꼴, Smacker 영상이다. 원칙에 따라 원본 방식으로 옮기는 것이 기본이다.
* **DirectDraw.** Windows 10/11에서 `ddraw.dll`의 8비트 전체화면은 호환성 계층을 거친다. 원본과 같은 호출로 옮길지, 같은 화면 장치 인터페이스 뒤에 다른 구현을 둘지는 전체화면을 옮길 때 정한다.

## 9. 영역 배치

`.fort`의 `Territory` 섹션(6바이트 × 20)은 영역마다 모양·방향·플래그·청크 위치를 담고, `TerrNN` 섹션은 그 영역이 차지한 청크의 오브젝트를 담는다. 형식과 분석은 [영역 청크 배치 분석](territory-layout.md)에 있다. 이번에 그 경로를 원본 구조대로 옮겼다.

1. `IslandBuilder::PlaceAll`(`0046dd70`): 플래그 bit 0이 켜지고 bit 1이 꺼진 레코드만 놓는다.
2. `IslandBuilder::Place`(`0046dba0`): 섬 목록에 (소유자, 영역 번호)를 등록하고, 놓을 범위의 시작점((1,1) — `00431fc0`)에 위치 바이트(하위 니블 x, 상위 니블 y)를 더한 자리에서 패턴을 푼다.
3. `CanonDecoder`(`00425c20`·`00425860`): 모양 번호의 패턴을 한 칸씩 내놓는다. 빈 칸(`.`)과 프레임을 찾지 못한 칸은 건너뛴다. 회전은 방향 값 ÷ 2이고, 회전하면 폭·높이가 바뀌며 방향 글자도 회전 표로 바뀐다. 프레임은 영역 패턴 타입(`puzzlePiece`, 타입 번호 107)의 프레임 코드 표에서 (방향 글자, 변형 `P`, 번호)로 찾는다.
4. 칸마다 청크 항목(12바이트: 섬 번호, 방향 글자, 레코드 6바이트, 영역 안의 순서)을 채운다.
5. `TerritoryChunks`(`004be2c0`): 지도를 y 바깥·x 안쪽으로 훑어 그 영역의 청크를 모은다. `TerrNN`의 청크 레코드는 이 순서다.

옮기지 않은 것: 다리·섬·그 밖의 타입의 패턴 표(`0052f998`, `00531410`, `005314a0`, `005314e8`)와 패턴 없는 타입의 경로, 섬 지형 만들기(`0046da70` 이후, Terrainbuilder), 전투의 플레이어별 섬 배치(`00432050`의 뒤쪽), 섬 목록의 나머지 필드, 섬 일치 검사에서 실행 상태에 따라 소유자 비교를 건너뛰는 경로.

## 10. 검사용 화면과 실행

`app/InspectView`는 **원본에 없는 검사 장면 공급 어댑터**다. 현재 화면 버퍼를 직접 그리지 않고 Renderer에 타입 표·기본 프레임·글자 목록을 제출한다. 실제 Squid·지형·메뉴가 연결되기 전까지 유지한다. 게임 화면의 복원 완료는 아니다(실제 목록/깊이·방향/상태 프레임·소유자/그림자 표 선택은 후속).

```powershell
# 원본의 로딩 화면만 (그리기 연결점 없음)
cpppj/build/bin/Release/NetstormCpp.exe --run originals
# 타입마다 기본 프레임을 격자로
cpppj/build/bin/Release/NetstormCpp.exe --run originals --view types
# 미션의 요새를 읽어 오브젝트를 월드 칸 좌표에 (화살표 키로 이동, Esc로 종료)
cpppj/build/bin/Release/NetstormCpp.exe --run originals --view TEST01
# CD 내용 폴더: 화면 크기를 명령줄 설정으로 준다. --cd 는 맨 끝에 둔다
cpppj/build/bin/Release/NetstormCpp.exe --run originalCD --view thewarbegins --set "SCREENW=800;SCREENH=600" --cd
# 영역 배치를 글로
cpppj/build/bin/Release/NetstormCpp.exe --dump-territories originals
```

`--run`의 옵션: `--view types|<미션>`, `--window`(원본 명령줄 `window`), `--set "키=값;키=값"`(원본 명령줄의 설정 글), `--frames N`, `--screenshot <out.bmp>`. 미션 화면은 한 칸을 16 × 11픽셀로 놓고([fort.md](../formats/fort.md) 4절) 레이어 0의 프레임(저장된 프레임, 다리는 저장된 클러스터 번호, 없으면 기본 프레임)을 그린다.

## 11. 검증

* **단위 테스트**(CTest 43개 가운데 새 13개): 화면 모드 조합, 사각형 자르기, 창 위치, 입력 큐(순서·넘침·뗌 거르기·DEL·명령), 패턴 표, 반복자(회전 0과 회전), 청크 지도, 섬 목록, 영역 놓기.
* **영역 배치 전수 대조**(`tools/cpp_window_smoke.py`): 두 판본의 모든 `.fort`에서 C++가 놓은 청크(좌표·방향 글자·순서)가, 기존 패턴 자료(`TerritoryPatterns.json`)로 Python에서 따로 계산한 결과와 줄 단위로 같다. 패치판 폴더 **465개 파일·영역 2,060개**, CD판 **23개 파일·영역 59개**. 영역마다 놓인 청크 수는 `TerrNN`의 청크 레코드 수와 같다.
* **창 화면 픽셀 대조**(같은 스크립트): 새 실행 파일을 5프레임 띄워 받은 타입 표 화면이, Python 해독기(`tools/shp.py`)와 팔레트 파일로 따로 그린 그림과 **모든 픽셀이 같다**(패치판 1024 × 768 = 786,432픽셀, CD판 800 × 600 = 480,000픽셀). DIB 버퍼 → 팔레트(0·255 고정 포함) → VFX 그리기·자르기 구간이 검사된다. 미션 화면(TEST01, CD판 `thewarbegins`)은 크기, 팔레트에 있는 색만 쓰였는지, 그려진 픽셀 수를 본다.
* **실제 창 확인**(수동, 1회): 창을 띄운 상태에서 바탕 화면을 캡처해 창 제목(`Activision and Titanic Entertainment Present: NetStorm`)·원본 아이콘·클라이언트 영역 1024 × 768에 DIB 내용이 표시되는 것을 눈으로 확인했다.
* 원본 파일은 검사 전후로 해시가 같다.

**확인하지 못한 것.**

* 이번에 옮긴 함수는 **x86 실행 대조를 하지 않았다.** Win32를 부르는 함수는 지금의 제한 실행 환경으로 돌릴 수 없고, 입력 큐·사각형 자르기·패턴 반복자는 돌릴 수 있지만 아직 기대값을 만들지 않았다. 근거는 두 판본의 디컴파일 대조와 위의 실제 자료 대조다.
* **회전된 영역**은 실제 파일에 없다(활성 영역 2,119개 모두 방향 0). 회전 경로는 표와 코드를 읽어 옮긴 것이고 단위 테스트도 같은 해석에 기대고 있다.
* 스크린샷은 DIB 버퍼와 현재 팔레트에서 만든다. 창으로의 `BitBlt` 결과는 자동으로 대조하지 않는다(위의 수동 확인 1회).
* 256색 화면 모드에서의 팔레트 동작(`WM_QUERYNEWPALETTE`·`WM_PALETTECHANGED`, `RealizePalette`)은 확인할 환경이 없다.
* 창 메시지 처리(활성화 클릭 삼키기, Alt 처리, 키 사건의 글자 판별)는 사람이 조작해 본 것이 아니다. 검사용 화면의 화살표·Esc 동작만 코드 경로로 쓰인다.
