## 원문 근거와 같은 실제 장치

원본10.78 PE의 **00439840→0042e050**은 공통 시작의 map mode 위치에서 Chatmanager를 생성한다. 뒤에는00422490과0047d860이 따르며, 현재 장부 count reset은 이 Chat 시작 뒤로 옮겼다. 원본 초기화는 Client 생성자/getter가 아니라 설정/자산/음향 준비 뒤, 메뉴/Session 생성 전 이 위치에서 한 번 실행한다. CD10.72에 확인되지 않은 이 PATCH 시작 연결을 적용하지 않는다.

새 `ClientChatRuntime`은 이미 복원한 `RawChatManagerPrefix` 본체를 그대로 사용한다. 같은 Client의 실제2712/128BYTE 할당·현재 manager 슬롯과 실제 점 명령표를 사용해 `format`/`back`/`front`를 원문 함수 식별자/표시flag1로 등록한다. signed 현재 Subscriber를 각 Config 키 생성 때 다시 읽고 실제 Config의 UTF8 문자열을 원문 ANSI 바이트로 변환한다. 원문60/500BYTE strncpy·강제NUL·같은 표 count 증가·재초기화 시 이전 할당 보존은 기존 본체가 수행한다. 이 등록은 콜백 본문의 실행이나 전체 Chat 전송/명령 실행 완료를 주장하지 않는다.

원문 **004c6c00**은 현재 icon TYPE+174의 B개수를 반환하고, **004c6c20**은 B개수를 캡처한 뒤 같은 TYPE을 다시 조회해 +178의 C개수와 곱하고1을 뺀다. 전체21/45BYTE를 실제 PE에서 확인했다. 최초 정적 도구의 짧은 범위/중간 시작 바이트는 `native-static-first.json`으로 보존하고 함수표의 실제 경계로 교정했다. 보호 `icon.type`은 B10/C14이므로 원문 최대랭크는139다. 제품 getter는 자산 사본의 고정 숫자를 쓰지 않고 같은 실제 `RawSurfaceStorage.frames`의 현재 B/C 개수를 조회한다.32비트 곱/감김과0 divisor의 실제 fault도 기존 formatter가 판정한다.

전체 Uber HUD와 `MakeCampaignClientServices.fortTechnologyUi`는 동일한 실제 갱신 함수를 호출한다. 현재 manager/active의 자연 관문은 원문0042f540 자체가 읽고, 선택된 경우에만 같은 Client CoreData getter의 현재 포인터/진단과 Core+4 rank·현재 icon TYPE을 읽는다. 임시 두256BYTE를 임의0채움하지 않는다. 원본 랭크 접두는 ChatWindow의 수신자 입력 접두와 별개다. 보고서의 `chat_manager` 행은 현재 manager/active/작성된 랭크 문자열/같은 실제 명령 count를 읽기만 한다.

## 집중 검사와 최초 실패

새6검사는 실제 Client 명령표와 현재 Config/원문 ANSI·60/500 절단·누락 padding, 재초기화와 이전 manager 유지, manager0/active0의 독립 자연 관문, 실제 Client Core 캐시의 rank255→139 제한과 rank15, 현재 전역 TYPE의 B3/C2 변경과0 divisor fault를 확인한다. 활성 Core/TYPE 변경은 명시 단위 입력이며 실제 GUI의 게임 상태를 주입하지 않는다.

새 checkpoint 검사는 실제 비영 Chat를 시작하고 같은 Client Gameplay/Subscriber/Player 및 실제 공통 월드 저장소를 사용한다. active0은 이번 새 Client의 실제 초기값과 Editor CoreData 로더의 자연 생략 관문이며 상수 반환 장치로 wrapper를 대체하지 않는다. 같은 작업 파일/Subscriber→World/Technology Chat→Deck→사제/카메라/생산→CoreWrite 자연 관문→전체 Fort snapshot→State &fe/Notify→startupStateCheck0 뒤 실제 EditorPlayers 번역 경계에 도달한다. 그 다음 번역은 검사가 명시 중단하며 checkpoint/loaded를 성공으로 공개하지 않는다. 카메라/생산 UI는 기존 관측 장치이며 실제 Editor GUI 설치 증거가 아니다.

빌드1/2의 새 checkpoint 기대는 생산 갱신을 외곽 직접 호출1회로 잘못 셌다. 실제 기존 World/저장 하위의 통지도 같은 장치에 도달해 **총5회**였다. 최초1/2 소스·제품·검사·실패 로그와 진단 `stopped1/chat1/camera1/production5/technology5`를 보존하고 검사 기대만 교정했다. 게임 관문/하위를 완화하지 않았다. 빌드2는 읽기 전용 보고 행을 추가했고 빌드3은 검사만 바꿨으므로 게임 제품2/3은 같다. 최종 집중은 신규 Chat6+checkpoint10+기존 Native Chat3+Chat/Core owner5+점 명령9=**33회·고유33·실패0**이다. 기존 Chat Native644관측 fixture와 원문 helper는 수정하지 않았다.
