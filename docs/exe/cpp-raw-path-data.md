# cpppj 실제 서버 Path 직렬화와 가상 Prepare

최종 디컴파일 PC는 **VM-W11-CODEX**, 날짜는 **2026-10-13**이다. 보호 원본은 수정하지 않았고 실제 게임/GUI는 실행하지 않았다. 패치10.78을 복원 기준으로 삼으며 CD10.72는 판본 차이를 별도로 기록한다.

## 실제 몸체와 공유 저장소

`RawPathData`는 가상 표의 +8인 패치 **004895b0** / CD **0047d630**을 복원한다. 공통 헤더 **004df590** / **00418b60**, payload 포인터 **0040a6a0** / **0040a240**, 부모 genus **004ac200** / **004abae0**와 CD의 헤더 WORD setter **00419090**도 native에서 직접 실행한다. 정확한 내보내기는 `tools/ghidra/pathdata-functions.json`의 판본별7개와 `pathdatahelpers-functions.json`의 패치1/CD2개다.

`MakePathFormTransmission`은 동일 SID 풀의 실제 `RawPathProcess::Runtime()`과 현재 base Form/Parent 번호를 조회한다. 서버 flags0 부착은 부모 체인 변경과 `OnAttached`보다 먼저 WriteData를 호출하므로 Runtime의 아직0인 부착 번호에 의존하지 않는다. 같은 공유 버퍼를 송신 효과에 공급한다. 다른 프로세스는 기존 실제 WriteData로 분배하며 미지정 효과를 빈 동작으로 채우지 않는다. 헤더·버퍼·타입 표·풀은 Host보다 오래 살아야 한다.

| 패킷 오프셋 | 실제 쓰기 |
|---|---|
| +0/+1/+2 | 하위7비트 flags / 패킷 번호 / 현재 헤더 WORD 길이(최소4) |
| +4/+6 | 실제 Form/Parent 번호의 하위 WORD |
| +8..+10 | 이전 공유 버퍼3바이트 보존 |
| +11/+13 | Path helper의 하위 WORD / payload BYTE 개수 |
| +15/+16 | 첫 float 좌표를0쪽 절삭한 하위 BYTE |
| +17 | 첫 double 시각×8을 `_ftol`한 DWORD |
| +21/+23 | 판본별 끝 필드의 하위 WORD/BYTE |
| +24 이후 | 압축 방향·거리 또는 직접 좌표 |

부모 genus의 **0x120000** 비트가 있으면 이후 꼭짓점마다 X/Y 절삭 BYTE를 쓴다. 그 외에는 절삭 좌표가 같으면 생략한다. 방향의 하위 비트가1이면 X 거리,0이면 X+Y 거리로 계산하고 **31칸씩 분할한 거리<<3 | 방향&7**을 기록한다. 방향은 경로 배열의 현재 값을 그대로 읽으며 새 경로나 방향을 추측하지 않는다. 반환 길이는 payload 개수+24이고 공통 헤더의 길이 전역을 새 반환 길이로 바꾸지 않는다. 부모 변경/force 가상 인자는 두 실제 몸체에서 읽지 않는다.

유효 float/double의 `_ftol` 결과가 signed32 범위 안인 원본 입력을 지원한다. 비정상 부동소수점·원본 배열 범위 밖·부족한 호스트 버퍼·signed32 거리 밖은 명시 예외 경계다. 원본의 메모리 손상 동작을 호스트에서 실행하지 않는다.

## Prepare의 판본 차이

가상 +0x30인 패치 **0048a200**은 nonzero speedOverride를 사용하며0일 때 타입 speed를 읽는다. CD **0047e710**은 첫 인자를 읽지 않고 항상 타입 speed를 사용한다. 실제 하위 시각 함수는 **00488e20** / **00402590**이다. `RawPathProcess::Prepare`가 이 판본 차이를 반영한다. 명시 타입 포인터를 사용한 native48개가 override0/양수/음수·타입 speed0.7/1.8·회전속도17.5/90·현재 시각을 교차한다.

이 가상 Prepare 계산의 x87 53/64비트 결과는 **16개** 입력에서1ULP 수준으로 다르다. fixture는 기존 원본 게임 계산 규약인 **0x027f(53비트)**를 사용한다. 64비트 결과와 차이 입력은 `pathprepare.json`에 보존했다. 정밀도 반복을 신규 입력 수에 더하지 않는다.

## 검증 범위와 남은 미션 연결

- `decomp_pathdata_oracle.py`: 고유 native **768개**(판본별384), 실제 반환 길이·전체2048바이트 공유 버퍼·기존 경로 이미지 불변 대조. 두 x87 정밀도 결과가 같다. 프로필에는0거리/중복·1/31/32/63칸·대각 방향·소수/음수/256 경계·하위3비트 밖 방향·직접/압축 genus·기존 버퍼/헤더/끝 필드·읽지 않는 인자가 있다. 진단 로그와 ctor 할당만 명시 관찰 경계다.
- `decomp_pathprepare_oracle.py`: 고유 native **48개**(판본별24), 실제 가상 Prepare→하위 시각 함수의 전체 QWORD 시각 표 대조. 정상 반환·assert0·정밀도 차이를 기록했다.
- C++ 검사3개: 전체 독립 패킷768개, 실제 서버 flags0 Host의 송신 전 체인/같은 버퍼와 이후 실제 체인·Pop·삭제, 가상 Prepare48개를 재생한다. 합성 부모의 Halt/Arrival·수명 cleanup과 서버 Form 삭제 Transmit 요청은 명시 검사 경계이며 실제 사제 몸체나 삭제 패킷 작성 복원 근거가 아니다. `pathdata-focused-host-final.log`에서 **종료0·3개/실패0**을 확인했다.

전체 Release 빌드/CTest 결과는 root의 최종 기록에서 확정한다. 최초 빌드의 잘못된 테스트 매크로/보호 getter 접근/Regular 생성자 인자와 최초 서버 검사의 SID 범위·삭제 관찰 경계 누락은 교정했고 실패 로그를 보존한다. 두 독립 도구의 `--verify`는 현재 SHA/정밀 범위/PE/fixture/고유 개수와 실제 entry 정상 반환을 확인한다. 서버 직렬화 경계는 닫혔지만 실제 사제 명령→BFS/Init/Prepare→flags0 부착의 상위 조립과 운반/의식/전투/승패·GameWorld 비표면 이관은 여전히 필수 후속이다. 이 검증을 캠페인1-1 실제 완주나 화면/소리 동일성의 증거로 세지 않는다.
