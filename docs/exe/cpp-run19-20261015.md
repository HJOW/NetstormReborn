# 단위19: 실제 사제 이동과 캠페인1-2 초기 설치

## 실행 연결

기준은 `2ed0b3e`, PC와 마지막 디컴파일 PC는 **HJOW-Athlon, 2026-10-15**다. AGENTS와 양 LEFT를 다시 읽었다. 보호 원본/AGENTS는 변경하지 않았다.

`RawCampaignMotionBindings`는 기존 Start/BFS/ProcessHost54/Halt/CarrierArrival/PriestArrival/cleanup을 동일 Pool/HP/spot/hash/현재 Path/Graph에 연결한다. 사제 모듈의 기존 CarrierPreDestroy와 CarrierCheck를 공유하고 Path 조회는 매번 현재 Form/Host에서 수행한다. 다른 월드/장부/시계 연결을 거부하며 외부 모듈을 해제하기 전에 같은 Kernel을 비운다.

보호 설치 장면은 `CampaignInstallSupport.h`로 옮겨 기존1-1 검사와 새로운1-2 검사에서 공유한다. 기존1-1 저장172개 검사를 유지한다. 새 이동 검사에서는 원본 `.type`의 speed/turningSpeed/defaultFrame, 실제 프레임/SHP, 실제 BFS와 공간/도착/삭제 몸체를 사용한다.

| 검사 | 관찰 |
| --- | --- |
| 1-1 실제 저장 적 사제의 저수준 이동 | 189프레임 후 도착·Path Form 반납, 송신 요청1 |
| 1-2 실제 내 사제의 저수준 이동 | 148프레임 후 도착·Path Form 반납, 송신 요청1 |
| 1-2 실제 초기 설치 | 보호 `MasterOfWhirligigs.fort`를 같은 부모/지형/저장객체/Graph 경로로 설치 |
| 상태 함수 | 새 독립 Native96입력의 has/level/진단 수/전체 슬롯BYTE 비교 |

이동은 실제 부모 SID에 명령을 주고 같은 Host clock을1/60초씩 진행한다. 목적지는 현재 Graph/spot/일반 finder의 가까운 빈 칸으로 선택하고 경로는 실제 BFS가 계산한다. 검사 입력을 특정 자유 칸으로 고르는 것은 UI 명령 허용/AI 동작을 복원한 것이 아니다.

보호 사제 `.type`에는 `stepSound`가 없고 `moveSound`는 별도 속성이다. 실제 기본 토큰0의 요청을 관찰했다. 1-1은 요청0회, 1-2는1회였으며 실제 음향 재생으로 주장하지 않는다.

## 실제 원본 전역과 Factory 상태

1-2 설치에서 저장 island94의 owner 필드가 없다는 오류를 발견했다. 파서는 원본처럼 이 타입의 바이트 하나를 읽고 객체를 생략했지만, 객체 로더의 기본값이 지면 번호97/98로 잘못 지정되어 있었다.

두 보호 PE의 실제 초기값은 다음과 같다.

| 전역 | 10.78 주소 | 10.72 주소 | 값 |
| --- | --- | --- | --- |
| island | 005411d0 | 0051cabc | 94 |
| islandStalag | 005411d4 | 0051cac0 | 95 |
| noIsland | 005412cc | 0051cbb8 | 157 |

`FortObjectLoadState` 기본값을94/95로 교정했다. 이전 Native fixture는 명시적으로97/98을 입력했으므로 C++ 소비자에서도 같은97/98을 직접 입력한다. 이 fixture/기대값/관찰 보고서를 수정하거나 재합산하지 않는다. 객체 로더의 필드 누락 진단에는 현재 요청 필드와 저장/생성 타입을 기록한다.

`RawSquidLevel`은 PATCH004ad0a0/004ad0f0/004ad110, CD004acdc0/004ace00/004ace20의 base 몸체다. `hasLevel`의 원래 OR 조건 때문에 정상 TYPE에서 항상 참인 결함도 보존한다. setter는 signed 범위 진단 뒤 하위5비트를 보존하고 현재 BYTE에 상위3비트를 쓴다. 진단 callback이 변경한 현재 BYTE도 다시 읽는다.

Factory의 실제 가상84는 PATCH00475290/CD0042b230이다. baseLevel 저장 다음 가상88의 상태 프레임 보정을 실행하므로 이를 단순 BYTE 저장으로 대체하지 않는다. 기존 `RawFactoryPostPop`의 실제 프레임 보정 몸체를 재사용하고 캠페인 자산 바인딩에도 Factory PostPop을 등록했다.

## 독립 Native와 회귀 검사

- 새 Native는 **96고유 입력/정상 반환96**이다. 판본별48, 범위 밖 입력의 예상 진단은 **각24**다. 이는 실패를 숨긴 값이 아니라 원본 진단 후 저장 동작의 검사다.
- 실제 setter/getter/hasLevel/TYPE 조회는 PE 명령을 실행한다. 원본 진단 함수만 명시 외부 관찰/반환 경계다. 첫 CD 실행의 미export TYPE getter는 실패 원문/로그를 보존하고 실제 getter를 추가 export하여 재실행했다. 반복 입력을 새 고유 입력으로 세지 않는다.
- 새 fixture/보고서는 `squid-level-x86.tsv` / `squid-level.json`으로 이전 원본 관찰과 분리했다.
- 집중5개 및 기존 FortObjectLoad4개 통과. 최종 Release 로그는 `extracted/run19-build8.log`, 집중 로그는 `run19-focused9.log` / `run19-fort.log`이다.
- 전체 CTest는 **1/1·내부1110개·실패 체크0**(183.54초), `extracted/run19-all.log`다. 최종 Release 경고/오류0이다.

직접 영향15파일의 전체 이전 원문은 `cpppj/hist/run19-base`에 있다. 최초 실행과 후속 잘못된 검사 가정/Native export 오류의 원문·로그는 `run19-fail1`, `run19-fail2`, `run19-fail8`, `run19-native1`에 보존했다. 소스/입력/로그/바이너리와 신규 C++ 전체 원문은 이번 `cpppj/run19.json`에 고정하며 과거 보고서의 SHA 기준을 덮지 않는다.

## 남은 실제 플레이 연결

GUI `GameWorld`는 아직 비표면 Squid 배열과 관찰 기반 이동을 사용한다. 이번 검사는 다른 Kernel 프로세스 전체/AI/게임 루프/GUI를 실행하지 않았다. 설치/이동 모듈의 실제 세션 소유자와 Ready/login, UI 입력, 생산, 전투, 경제, 운반, AI/Guide, 음향, 승패 및 Early Missions/1-1~1-2 완주를 연결해야 한다. 사제 Damageable/Placement와 선택되지 않은 큰 운반/의식/회피 하위는 명시 미연결 상태다. 실제 원본/클론 GUI 실행은0이며 전체화면 DirectDraw 오류는 제외한다. 전체 목표는 active다.
