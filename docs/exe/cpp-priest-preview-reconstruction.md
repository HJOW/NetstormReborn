[`RawPriestPlacementPreview`](../../cpppj/src/o/RawPriestPlacementPreview.h)는 기존 배치 접두의 `inspectGeometry`를 이어 받아 **실제 충돌 검사 전에 만드는 표시 배열**을 복원한다. `MakePriestPlacementPreviewHooks`로 같은 풀의 접두에 연결하고, 접두의 모양 조회와 생성의 다른 효과는 유지한다.

1. 접두가 캡처한 로컬 소유 여부가 false이면 배열 초기화/모양 조회를 생략하고 충돌 경계로 간다. 기존 배열의 144바이트를 보존한다. 접두의 강제 허용 경로도 미리보기에 진입하지 않는다.
2. 로컬이면 배열 전체를 0으로 지운 뒤 CanonDecoder의 생성/정수 사각형 조회 경계를 호출한다. 생성 인자는 `(type,type,flags,x,y,0)`다. C++ 훅은 두 하위 호출의 결과인 사각형을 반환한다. 이 단계에서는 사제의 패턴 없는 CanonDecoder 몸체를 복원하지 않았다.
3. 사각형 left/top을 각각 최소 1로 맞춘다. bottom+1부터 top-1까지 **y를 감소**시키며, 각 행에서 right+1부터 left-1까지 **x를 감소**시킨다. 양 끝을 포함한다. 빈 범위도 배열 초기화와 모양 조회는 수행한다.
4. 표시 위치는 `px=right-x+1`, `py=bottom-y+1`, 배열 오프셋은 **px×12+py**다. 화면 좌표처럼 y가 바깥 차원이라고 해석하지 않는다. 한 칸 모양에는 주변을 포함한 3×3 위치가 생긴다.
5. spot의 `0x10`이 있거나 고정 표면 SID가 0이면 1을 표시한다. 표면의 **현재 raw 타입/genus**를 읽고 genus `0x2`가 없으면 표시하지 않는다. genus가 있으면 현재 raw 소유자를 읽어 관계가 허용되지 않을 때 1을 표시한다. free/dead/void/contained 상태 비트나 extra로 표면을 추가 필터링하지 않는다. 점유 spot에서는 SID/raw를 읽지 않는다.
6. 관계는 편집기 전역이 켜짐→동일 소유자→관계 사용 전역이 켜져 있고 `표면 소유자×9+요청자` 항목이 0이 아님 순서로 허용한다. 요청자는 부호 확장한 low BYTE, 표면 소유자는 부호 없는 BYTE다. 전치된 관계나 중립 소유자의 특별 허용 규칙을 추가하지 않는다. 관계·타입·지도는 실제 사용 시점에 읽는다. 요청자 -1도 표면 소유자 1과 조합하면 최종 인덱스 8이므로 원본대로 그 항목을 조회한다. 개별 소유자를 0..8로 제한하지 않고 계산된 인덱스의 실제 표 범위만 검사한다.
7. 미리보기가 끝나면 원래 값 인자와 캡처한 로컬 비교를 실제 충돌/지역 처리 경계로 넘긴다. **표시된 1의 유무로 배치 반환을 결정하지 않는다.**

고정 표면 지도는 postPop 등에서 사용하는 현재 표면 지도(`00542514`/CD `005670cc`)와 구분한다. 이 경로는 고정 지도를 읽으며 next 체인을 탐색하지 않는다.

## 판본 차이와 입력 계약

패치는 각 미리보기 칸에서 **x<0, y<0, x≥256, y≥254이면 곧바로 false**다. 배열을 지운 효과와 앞선 모양 호출은 유지하며 이후 충돌 경계는 호출하지 않는다. 원본의 y 비교 값은 256이 아니라 254다. 미리보기 인덱스는 0..11의 원본 assert 대상이다.

CD에는 이 조기 거부가 없다. 먼저 `y×256+x`의 **linear spot을 읽고**, 표면 조회에만 x/y 지도 범위를 검사한다. 따라서 x=256이며 linear 주소가 할당 지도 안이면 다음 행의 첫 spot을 읽은 뒤 표면 없음으로 차단 표시하고 계속한다. y=254/255도 할당 지도 안에서 순회할 수 있다. 이 차이는 원본 정상 반환 fixture로 확인했다.

C++는 할당 지도 밖의 CD spot 읽기, 12×12 배열 밖 쓰기, 관계 표 밖 인덱스, 잘못된 SID/타입, 정수 사각형 산술 범위, 누락 자료/훅을 예외로 진단한다. 원본 assert/정의되지 않은 메모리 접근의 재현은 정상 대조 범위에 넣지 않는다. 편집기/동일 소유자/관계 비사용 등의 앞선 조건이 관계 조회를 생략하면 불필요한 관계 표 인덱스 검사를 추가하지 않는다.

## 생성 연결과 남은 경계

두 판본 통합은 사제 생성→배치 접두→미리보기→충돌 경계→**실제 서버 SID/사제 생성자·공통 postCreate**→WORD `0x8101` 쓰기→기록 소유자/일반 Pop/Carrier 검사 요청을 연결한다. spot=6·고정 표면 없음이므로 미리보기 9칸이 모두 1이지만, 충돌 경계가 true를 반환하면 첫 후보 `(21,22)`에 사제를 생성한다. 새 SID는 패치 15000/CD 6000이다.

**실제 충돌/지역 본체·CanonDecoder의 사제 모양 생성/범위 조회·일반 사제 Pop/가상 Carrier 상태 검사는 남은 경계다.** 이 통합은 지도 등록이나 전체 사제 생성 수명을 완성한 검사가 아니다. 다음은 `0049b825`/CD `0044550e` 이후 모양 순회와 충돌 후보 무시 조건 `0049ade0`/CD `00444900`을 분리해 실제 `RawSquidFinder`에 연결하는 것이다. 이어 실제 모양/관계 주변 처리와 일반 Pop/보호막·회복 예약·Carrier 상태 검사/낙하를 진행한다.

## 독립 기계어 대조

[`decomp_priestpreview_oracle.py`](../../tools/decomp_priestpreview_oracle.py)는 세 실제 PE에서 **각 1,620개, 총 4,860개**를 두 x87 정밀도로 실행한다. 사각형 12종×지도 5종×전역/소유자 9종×범위 조회 중 변화 3종이며, 두 정밀도 관찰이 같다.

C++는 전체 144바이트 배열·현재 편집기/동맹/관계/genus·표면 raw 전체·공간/고정 지도 Adler·반환/외부 사건 순서를 원본 관찰과 비교한다. 실행기는 thiscall EIP/ESP·보존 레지스터·x87·생성/범위 인자와 출력 포인터·전체 초기화·허용 코드/스택/배열·전역 쓰기, assert/OS 0회와 SHA/실제·대체 호출 수를 확인한다. 기존 배치 접두/나선 fixture와 감사 도구는 바꾸지 않았다.
