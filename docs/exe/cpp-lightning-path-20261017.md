# 공유 빔 경로·재귀 입자 생성 — 단위104

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 직전 단위103은 데모3의400프레임을 통과했고 현재 첫 미복원 경계는 데모1 TYPE148 stage5다. 이번에는 그 발사가 의존하는 공유 빔의 실제 경로 생성/입자 분기를 복원했다. 새 디컴파일·원본 게임/GUI 실행은 없다.

## 실제 경로의 저장과 계산

`RawLightningPath`는 원본 `00471b20`의64바이트 경로, `004720f0`의 시작점, `00472180`의 진행과 `00471fc0`의 재귀 가지를 구현한다. 기존 `GameRandom`을 공유한다. 죽은 입자 재사용 없이 꼬리만 늘리는 `00487b20`을 따르며 실제 빔의 용량120과 입자24바이트를 별도 저장소에 보관한다.

생성 시 같은 중심 조회와 현재16/11 배율로 양끝을 snapshot한다. source148은 y−76,149는 y−48,144는 x−5/y−48이다. target149/144는 y−48, 그 밖은 y−16이며 target148에 source의76을 적용하지 않는다. 이후 경로에는 표적 SID가 없으므로 움직이는 표적을 따라 끝점을 바꾸지 않는다.

경로는 원본 전체64바이트 이미지로 보관한다. 생성자가 쓰지 않는 `+24..+34`도 초기화로 덮지 않는다. 첫 점은 strength1·jitterWeight0·life2·이전NULL이며, 시작 step은 정확한 float0.15다. 입자 이전 포인터는 같은 고정 저장소의 **index+1**, 소유 빔 포인터는 **비영 토큰**으로 표현한다. 실제 호스트 주소로 원본32비트 포인터를 역참조하지 않는다. 다른 소유 빔의 저장소는 명시적으로 거부한다.

새 주점은 이전 주점에 연결하고 재귀 가지는 방금 추가한 점에서 시작한다. strength가 원본 float0.12보다 크고 정수 난수0..99가85 미만이면 길이/strength를 절반으로 줄여 재귀한다. 재귀의 끝을 다음 주점으로 잘못 바꾸지 않는다. sin/cos·atan2·sqrt의 넓은 계산과 float 저장 위치를 구별한다.

각 진행 단계는 누적 진행을 float로 저장한다. step 상한은 `step×float0.9`와 최소float0.08, 하한은 그 상한×원본 float1/3이다. 첫 난수로 조건을 검사하고 조건이 맞으면 **다시 뽑은 난수**를 step에 저장한다. 두 번째 값이0.08보다 작아질 수 있으므로 한 번 뽑아 clamp하는 구현은 다르다. 진행1에서는 끝점을 한 번 추가하고 완료 표식을 세운다. 진행 후퇴와 완료 후 재호출도 원본대로 처리한다.

## 독립 원본 대조
