# 단위27: 실제 창 제목 갱신 서비스 복원과 메뉴·미션 연결

기준 커밋은 `9eeef1e`다. 작업 전에 AGENTS와 두 LEFT 문서를 다시 읽었다. 현재 및 마지막 정밀 디컴파일 PC는 **VM-W11-Codex, 2026-10-15**다. 사용자가 수정 중인 `TODO.md`는 이 단위의 편집·커밋에 포함하지 않는다.

## 원본 근거와 구현

현재 호스트의 정밀 프로젝트에서 PATCH `00460730/00463a20/004639e0/00463a60`과 CD `004ca4e0/00417060/00417020/004170d0`을 읽기 전용으로 내보냈다. 순서대로 창 제목 갱신, 현재 미션의 demo/test 플래그 getter, 현재 title getter다.

`WindowTitle`은 다음 원본 선택과 조회 순서를 복원한다.

- 요새 이름 포인터가 NULL이거나 빈 문자열이면 `blankWindowName`에 NULL 인자를 준다.
- 편집 모드이면 `EditorWindowName`에 현재 요새 이름을 준다.
- 일반 요새이면 현재 Template의 +0과 +8이 모두 비영점인 경우 `readonly`를 별도 조회하고 공백 하나를 붙인 다음 `windowName`을 조회한다.
- 미션이면 demo가 testBattle보다 우선한다. 현재 미션 title을 읽은 뒤 `demoWindowName`, `testBattleWindowName`, `missionWindowName` 중 선택한 설정에 넣는다.
- 완성한 제목은 창 적용 소비자에 한 번 전달한다. 원본 256BYTE 버퍼 범위 밖이나 NUL이 포함된 새 문자열은 거부한다.

실제 `UberGump`의 메뉴 복귀와 일반 미션 진입에 이 함수를 연결했다. 메뉴의 고정 C 문자열과 미션 제목만 직접 표시하던 경로가 각각 실제 `blankWindowName`과 `missionWindowName` 설정을 사용한다. 현재 일반 미션 경로는 파일 이름을 빈 title의 대체값으로 넣지 않는다. 편집/Demo/테스트 미션 진입의 상위 모드 연결은 해당 기능과 함께 공급해야 한다.

## 독립 원본 대조

`tools/decomp_window_title.py`는 두 보호 PE를 격리 x86 메모리에 적재하여 실제 제목 분기·복사·미션 getter를 실행한다. 설정 함수의 반환 문자열, 미션의 title 문자열 조회, Win32 창 적용만 명시 외부 경계다. 원본 게임 프로세스는 실행하지 않는다.

판본마다 **576개**, 총 **1,152개 고유 입력**이 정상 반환했고 assert는 0이다. NULL/빈/일반 요새 이름, 편집·미션·Template 두 필드·demo·test의 모든 조합, 빈/일반/200글자 ASCII title을 포함한다. C++ 두 검사가 모든 입력의 설정 조회 키·NULL 인자·미션 title 조회 순서·최종 제목을 대조한다. 실제 `ConfigInterface` 치환을 사용하는 세 번째 검사도 추가했다.

최초 도구 실행은 명시 외부 미션 Get의 스택 정리를 cdecl로 처리하여 미션 분기에서 중단됐다. 원본 PATCH `00482c90` 끝의 `ret 4`와 CD의 정상 반환을 확인한 뒤 이 경계를 교정했다. 실패 실행에서는 fixture/report를 생성하지 않았다. 최종 1,152개만 고유 입력으로 기록하며 주석·근거 해시 보완 후 같은 입력의 재실행을 추가 관찰로 합산하지 않는다.

근거는 `cpppj/window-title.json`, `cpppj/tests/fixtures/window-title-x86.tsv`, `extracted/window-title/`와 `extracted/run27-native.log`다. 보고서에는 원본 두 PE, 정밀 내보내기, 생성 도구와 공용 격리 실행기, fixture의 SHA를 기록한다. 256BYTE 안의 ASCII 입력이며 초과·잘못된 포인터·실제 원본 설정/창 장치 자체의 재관찰은 포함하지 않는다.

## 실제 클라이언트 확인과 빌드

최종 Release 빌드가 경고·오류 없이 성공했다. 집중 검사 **3개·실패 체크 0개**가 통과했다.

`tools/cpp_title_smoke.py`로 최종 클론의 실제 창을 두 번 실행했다. 현재 실제 설정에서 얻은 기대값을 Win32 창 제목과 대조했다.

- 메뉴: `NetStorm Main Menu`
- 튜토리얼1 브리핑: `NetStorm Mission "Bridge the Gap!"`

두 자체 검사 창은 제목 일치 확인 뒤 WM_CLOSE로 정상 종료했다. 검사 도구는 허용된 `options.cfg`와 `fullscreenStateFile.dat`의 실행 전 바이트/존재 상태를 복구한다. 초기 짧은 PowerShell 관찰은 정지 브리핑의 180프레임이 빠르게 끝나 제목을 놓쳤다. 최종 도구는 프레임 상한을 충분히 두고 숨긴 창도 PID로 열거하여 확인한다. Win32 제목 확인을 전체 게임의 UI 동일성으로 확대하지 않는다.

최종 전체 CTest는 **1/1 통과·내부 1,142개·실패 체크 0개**(116.22초)다. 로그는 `extracted/run27-build-final.log`, `run27-focused.log`, `run27-ui.log`, `run27-title-ui.json`, `run27-all.log`이며 내부 개수는 `cpppj/build/Testing/Temporary/LastTest.log`에서도 확인했다.

## 후속

실제 세션의 `install.refreshWindowTitle`은 이번에 연결한 동일 `UberGump` 메서드를 재사용할 수 있다. `install.translateYou/setConfig/resetCamera`, 실제 음향·UI·owner 통지·Ready/login과 미션 게임 규칙의 연결은 계속 필요하다. Battle 미션의 `NotImplemented` 진입 차단과 Early Missions 및 캠페인 1-1~1-2의 실제 진행·완주 동일성은 **미완료**다. 목표는 active로 유지하며 DirectDraw 전체화면 오류 수정은 제외한다.

원본 두 PE의 최종 SHA-256은 정밀 재생성 및 `cpppj/window-title.json`의 기준값과 일치한다. AGENTS·dotnetpj·보호 실행 파일을 수정하지 않았다. 인수인계 완료 뒤 로컬 `20261015-13 실제 창 제목 갱신 복원과 메뉴 및 미션 연결 검증`으로 커밋하며 원격 push는 하지 않는다.
