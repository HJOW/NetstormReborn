# 1077 — CCh 41h 채팅 수신

`ChallengeRuntime`에 원문 00476880→004512b0의 전체41h 수신 몸체를 연결했다. 실제 전송 표의 nullable 직접 호출과 같은 패킷 수정/송신을 사용한다. 제품1077 / 11.01, EXE 12,366,336바이트, SHA-256 `ffa5e47e9a27601cfdd79be84d19f6e0e03853bbd0b44b0a9653ee5655ff5755`다. 직전 CP는 `3451978b / 20261107-137 CP`다. **새R.exe/최종 owner·실제 Install/Run 호출은 아직 없으며 수신 실행 검사는 하지 않았다.**

## 등록과 현재 물리

기존 `InstallPacketObservers`가41h 수신기도 등록한다. 원문00442950의 등록 버전은 **1/정책0**이며 작성기의 헤더 버전3과 별개다.1069에서41h 등록까지3으로 쓰던 부분을1로 교정했다. 길이는ffff/가변이고 실제 observer는 송신 시에만 같은 WORD를 쓴다.

수신 wrapper는 exitRequested 때 실제_exit0, CHAL 진단1439, sender의 **signed sar8** 존과lowBYTE를 읽는다. 양수/현재 개수/현재 CCh 토큰만 확인하며 별도local/active 필터를 추가하지 않는다. 연결 인자는 읽지 않으므로 Root의NULL 직접 호출을 지원한다.

공통 프레임 API의 기존 계약대로 입력은 **실제 쓰기 가능한 전송 버퍼**여야 한다. const 보기는 동일 mutable 물리로 복구하며 RootBroadcast도 실제 vector를 전달한다. 패킷 복사로 recipient/addrLen 변경을 숨기지 않는다. 임의 const 저장소에 수신을 호출하는 것은 지원 계약이 아니다.

## 명령과 전송 제한

첫NUL까지 소유 복사한 본문에서 .test/.test1을 대소문자 구분 부분 검색한다. 일치하면 특별 응답 `A COMMAND WAS FOUND WOOO`와원문LF/CR을 보낸 뒤 반환한다.450ff0은 **bufferLen=strlen**, 빈이름1BYTE·recipient0이며 그recipient의 첫0이 문자열 종결도 맡는다. 일반 Message의strlen+1 경로로 합치지 않았다.

그다음 LF 개수가 같은 Options.multiLineLimit보다 많고+75가1이 아니면 원문 차단 문구를 보낸다. 허용 본문의 모든 ~4는 제자리 두 공백으로 바꾼다.004be518의 CP1252 아포스트로피92를 명시 바이트로 보존하며 소스는UTF-8이다.

타이머는 게임 시계가 아니라 CRT clock이다.00451890은 현재+68 쓰기→DWORD차이→**signed idiv1000**→float 저장이다. penalty는signed(count-3)의음수를0으로 바꾼 값이며 기본 threshold2보다 elapsed-penalty가 작을 때만 count를 늘린다. **같은 값이면 새 clock을 별도로 읽어 기준을 재설정/count0**이다.451489 fcompp/test41/jp로 비교 방향·동등 경계를 확인했다. 기본 count3에 도달하고+75가1이 아니면 차단한다. 옵션은 현재참조여서 재해석 뒤 값도 사용한다.

## 전체·개별·감시자

nameLen은signed WORD, 수신자 시작의bufferLen은unsigned WORD다. addrLen1/첫recipient0이면addrLen을0으로 바꾸고 현재40연결 Broadcast만 호출한 뒤 반환한다. 이때 별도 감시자 꼬리는 없다.

개별 경로는 원수신자 수를 저장하고addrLen1로 바꾼다. 매회 현재 원래 목록에서 값을 읽어 **첫 recipient DWORD에 덮은 뒤** 같은 패킷을 전송한다. subscriber 조회는 활성 여부 없이0..39의 첫일치다. 연결 인덱스도 조회순번이 아니라 실제 레코드의id다. 대상+75가0이고 발신+74가0 또는 자기인 경우에만 보낸다. 마지막으로 현재 연결/+75비영인0..39 감시자에게 마지막recipient/addrLen1인 동일 패킷을 보낸다. 실제Send observer가 수정한 길이와 RootBroadcast의 다음CCh가 보는 현재 바이트도 보존한다.
