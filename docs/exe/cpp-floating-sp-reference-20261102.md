2026-11-02 / HJOW-Athlon / Windows10. 마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**이며 기존 산출물은 바꾸지 않았다.744의 F12 복원·검증·커밋은 완료한 진척으로 유지한다. 실행 제품은 **745 / 표시11.01**이다. 사용자의 최신 요청에 따라 **이 단위의 문서·로컬 커밋 완료 뒤 목표를 일시 정지**한다. 전체1~8차 목표는 미완료이며 다음 단위는 시작하지 않는다.

## 실제 차이와 원문

`RawMenuControls`의 SP 비용 표시에서 참조 객체가 비영이면 실제 객체 연결 대신 미연결 예외가 발생했다. 원문 `00464540`은 기존 `004644e0`의 Form 생성/소유 ID/객체 연결을 수행하고 Gump에 월드 투영 비트 `0x2000`을 추가한다. 원문 `00464740`의 위치 조회는 같은 Pool 객체의 `+0x0e/+0x12` float 좌표를 현재 카메라의 `00497220`으로 투영한다.

공통 `RawButtonControls`에서도 부착용 `GumpTree`와 출력용 `GumpCollection`의 투영 장치가 비어 있었다. 객체 Form 연결만 보완하면 다음 부착/그리기에서 다시 실패하므로 두 연결을 함께 복원했다. 일반 커서 배치/Carrier Drop의 기존 참조0은 유지했다. 모든 게임 상황에서 비영 참조가 발생하는지 또는 모든 동작이 같은 표시를 사용하는지는 이번 근거의 범위가 아니다.

## 변경

- 비용 표시가 기존 `MenuGumpWidgets::Reference`의 같은 Session Form/등록표를 사용한 뒤 원문의 `0x2000`을 추가한다. 객체 연결과 UI 표시 수명을 별도 저장소로 복제하지 않는다.
- 공통 버튼 장치에 현재 객체 투영 경계를 추가하고 부착과 수집기에 같은 콜백을 전달한다. 실제 Client는 미션/Editor 교체 후에도 현재 World의 Pool과 Client 카메라 snapshot을 조회한다.
- `ProjectGumpObject`는 10.78의 비정렬 raw float 두 칸과 기존 `ProjectCameraView`를 사용한다. 최초 위치/카메라를 저장하거나 넓은 DWORD를 SID16으로 접지 않는다.10.72의 다른 raw 배치는 명시 거부하며 이번에 구현했다고 주장하지 않는다.
- 기존 메뉴·Session 집중 대상에 기존 비용 표시/수집/부착/카메라 검사 파일을 추가했다. 새 테스트 실행 파일은 만들지 않았다.
