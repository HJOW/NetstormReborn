## 변경한 동작

`RawCampaignCarrierDrop.inc`의 `baseMenu`가 명시 미연결 처리기여서, Cast/Drop에서 처리하지 않은 명령은 원본의 공통 객체 처리기로 넘어가지 못하고 예외로 끝났다. 또한 공통 메뉴가 작성하는 소유자 변경·HP 감소·직접 삭제 항목을 `CampaignObjectMenuClient::Command`가 소비하지 않았다.

새 `RawObjectCommand`는 10.78의 `004ae010`과 Form 부모 `004ac9b0`의 분기를 복원한다. 상위 여섯 비트를 제거한 명령을 비교하며, 처리하면 `1`, 모르는 명령이면 `0`을 반환한다. 별도의 로컬 소유자·생존 상태 필터를 추가하지 않았다.

| 원본 명령 | 복원 동작 |
| --- | --- |
| `030000af` | 현재 로컬 소유자 DWORD를 가상 `+74`에 전달한다. |
| `030000e2` | 현재 편집 모드 또는 미션 모드에서만 HP DWORD−1을 가상 `+98`에 전달한다. 소유자/공격자는 0이며, 모드가 꺼져 있어도 처리 결과는 1이다. |
| `03000015` | Form 가상 `+10`에 flags 0으로 삭제를 요청한다. |
| `0300006e` | Form 가상 `+70` 진단 호출의 분기와 인자는 복원했다. Session의 실제 `004b0fb0` 진단 출력은 명시 미연결 경계로 남겼으며 GUI에 새 진단 메뉴를 추가하지 않았다. |
| 그 밖의 명령 | 외부 효과 없이 0을 반환한다. |

같은 Session의 `RawCampaignOwnership`으로 신전·사제·공통 소유자 분배를 연결하고, 기존 `RawCampaignHitBindings::DamageHooks`와 `RawSurfaceWorld::Destroy`를 피해·삭제에 사용한다. Cast/Drop의 미처리 명령도 이 처리기로 위임한다. 비캐리어의 공통 메뉴 명령은 새 `CommandObject`를 통해 같은 인스턴스를 사용한다. SP/네트워크 패킷이나 내용물 소비를 새로 만들지 않는다.

## 원본 근거와 CD판 차이

REA는 원본 EXE의 SHA-256을 확인하고 열었지만, `analyze_function`이 H: 루트의 Windows 경로 속성을 읽는 단계에서 `ERR_REA_WINDOWS_NATIVE` / Win32 87로 실패했다. `rea doctor --client codex --json`으로 등록 상태를 확인했고 세션은 닫았다. REA의 함수 분석 성공이나 Evidence를 주장하지 않는다. 복원 근거는 이 PC의 `extracted/refined/` 자료, PE의 원래 명령 토큰 DWORD와 Capstone 명령 해석, 아래 격리 x86 관측이다.

`tools/decomp_object_command.py`는 **제품 C++ 구현 전에** 원본 두 PE의 메모리 사본에서 공통 객체 명령과 Form 부모만 실행했다. 게임·Windows API·창은 실행하지 않는다. 원본의 가상 소유자/피해/삭제/진단 효과와 CD판의 소유자 getter는 명시 경계로 기록한다. 호출/복귀 스택, 비휘발 레지스터, 호출자 canary와 객체 바이트 보존을 확인한다.

| 판본 | 실제 함수 | 정상 반환 | 실행한 원본 명령 |
| --- | --- | ---: | ---: |
| 10.78 | `004ae010` / `004ac9b0` | 160 | 3,352 |
| CD10.72 | `004af0a0` / `004ac490` | 160 | 3,424 |

`cpppj/tests/fixtures/object-command-x86.tsv`와 `cpppj/object-command-native.json`에 상위 명령 비트·편집/미션 모드·HP 0/1/최솟값/최댓값의 결과를 보존했다. 이 관측은 제어 흐름과 가상 호출 인자의 근거이며 실제 가상 효과 전체나 플레이의 증거가 아니다. 최초 실행은 기본 Python에 Unicorn이 없어 중단됐고, 저장소의 기존 `extracted/oracle-python` 의존성을 사용하도록 고친 뒤 수집했다. 새 패키지 설치는 없다.

CD판은 로컬 소유자 getter `004015d0`를 사용하고, HP를 signed WORD로 읽으며, 편집/미션 모드 관문 없이 Hurt를 호출한다. 이 차이는 기록과 fixture에만 남겼고 이번 제품 구현에는 10.78 동작만 적용했다.

## 검증과 보존

새 검사 세 개를 추가했다. 두 개는 원본10.78의 160입력과 현재 모드 조회/단락 평가/지연된 경계 요구를 확인하도록 작성했다. Session 검사는 실제 Tutorial5의 적 사제에 대한 미처리 명령0 반환과 Cast/Drop 부모 위임을 통한 가상 소유자 변경, HP/SP/송신 보존을 확인하도록 작성했다. **이번에는 검사 실행 파일을 실행하지 않았다.**

Release 빌드는 게임·라이브러리·검사 실행 파일을 모두 생성했다. 첫 빌드의 새 검사 초기화에서 C4244 경고가 나서 바이트 타입을 명시했고, **최종 Release 빌드가 경고/오류 없이 종료0**으로 끝났다. 원본 자료 해시 감사와 현재 소스/핀/빌드 감사도 각각 종료0이다. 빌드와 읽기 전용 감사의 최종 기록은 `cpppj/object-command-session.json`, 로그 접두는 `extracted/object-command-20261020-`다. 실제 게임/단위/전체 회귀/메뉴 클릭 검증은 사용자 지시대로 후속 통합 검증에 이월한다. 이전 1772 통과나 원본320반환을 이번 C++ 검사의 통과 결과로 세지 않는다.

현재 변경 직전 소스와 일치하던 핀만 **128보고서·366항목** 갱신했다. 시작 소스와 일치하지 않던 기존/역사 핀 93항목은 그대로 남겼다. 보고서별 새 이력과 핀만 역변환하면 변경 전 JSON과 의미가 같음을 확인했다. 과거 실행·바이너리·원본 기대값·기존 이력은 보존했다. 새 읽기 전용 감사는 `python tools/cpp_object_command_audit.py --verify`이며, 게임이나 검사를 실행하지 않는다.
