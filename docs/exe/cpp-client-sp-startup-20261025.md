2026-10-25 **단위423**이다. 이전422는 `b6bc3e05 / 20261025-16 CP`로 Player/CoreData와 Login 슬롯·전체2833검사를 마쳤다. AGENTS/양 인계를 재독했으며 현재/마지막 전체 정밀 디컴파일은 **HJOW-Athlon / 2026-10-23**으로 같다. 보호1821파일 기준은 `extracted/cpp-client-sp-startup-423-baseline.json`이다. ## 원문 순서와 먼저 고정한 할당 관측

원문 WinMain **004391ed→0040eba0**은 창 생성/GetWindowRect 직후이며 옵션/화면/ColorSort/구름/Session보다 앞선다. 실제 초기화는 같은 RawGameRandomSeed의 Reseed→GameRandom(100)→offset/추적 DWORD→32번 순열 교환→다시 항등→32개 operator_new(36)→initialized1 순서다. 기존 Session 생성자에서 매번 SP를 초기화하던 위치는 이 공통 시작과 다르다. [앞선 수명 조사](cpp-kencloud-client-lifetime-next-20261024.md)의 SP 선행 조건을 이번에 실제로 연결한다.

새 `decomp_sp_initialization.py`는 제품 변경 전에 원문0040eba0/004558c0의 실제 두 몸체를 실행했다. 재시드 결과와 서로 다른36BYTE 할당 입력만 명시 장치이며 SP/순열/offset/난수 기대값을 제품에서 계산하지 않는다. **48관측(정상12/중단36)**에서 두 x87 모드의 차이0이다. 첫 생성/이미 초기화된 저장소의 명시 재초기화, 첫/16번째/32번째 할당의 미반환 부분 효과를 고정했다. 첫 포인터는 첫 할당 정상 반환 직후 공개되며 initialized는 끝에서만1을 쓴다. 재초기화 중단은 앞선 초기화 완료값과 아직 덮지 않은 이전 행을 보존한다.

첫 도구 실행은 과거 개별 `extracted/sprotate/originals/functions.tsv` 부재로 종료1이었다. 원문 실행/fixture 생성 전의 실패이며 `native1.log`를 보존했다. 현재 호스트의 전체 정밀 함수표에서 두 몸체의 실제 분리 범위를 읽는 것으로 교정한 `native2.log`는 종료0이다. 새 fixture/Native 보고서는 그 뒤 고정했으며 기존 회전/보상 fixture와 보호 원문은 수정하지 않았다. 원본 게임이나 새 전체 디컴파일은 실행하지 않았다.

## 같은 Client 저장소와 직접 참조

`ClientSpGlobals`는 같은 ClientRandomGlobals/기존 RawGameRandomSeed/기존 ScrambledSpStore와 실제 추적 DWORD 하나를 장기 소유한다. 생성자와 getter는 주소만 연결하고 초기화하지 않는다. PATCH Run의 원래004391ed 위치에서만 최초 명시 초기화를 수행한다. 실제 Client의36BYTE 할당 입력은 기존 CurrentAllocationBytes 장치로 제공한다. 독립 fixture의 균일 fill 입력은 명시 검사 경로로 유지한다. Host의 분산32행 물리 표현과 실제 pointer의 절대주소 동일성을 혼동하지 않는다.

할당 입력이 정상 복귀한 각 행만 현재 분산 저장소에 공개하며, 이후 중단이 앞선 효과를 되돌리지 않는다. 첫 배열의 실제 비NULL 관문도 첫 행 복귀 직후 갱신한다. 이 공개 시점과 부분 내용은 Native48전체와 대조한다. 기존 Get/Set/Rotate의 계산과 실제 같은 GameRandom 참조는 재사용한다.

실제 Session은 초기화 완료된 같은 SP와 같은 난수 소유자를 요구하고, SP를 재초기화하거나 지역 사제 상태로 추적 주소를 다시 연결하지 않는다. Login/저장/객체/HP/SP 소비자는 같은 저장소를 직접 빌린다. 소유자 없는 독립 Session은 기존 지역 SP/추적 초기화 의미를 유지한다. 실제 사제 회복의 추가 참조는 공유0054d4e0을 직접 읽고 쓰며 Session 지역 `patch.sequence`와 프레임별로 동기화하지 않는다. 기존 독립 회복 fixture의 값형 입력/세 getter 경로는 유지한다.

`sp_globals` 진단 행은 실제 초기화 여부/첫 배열 비NULL/288DWORD 폭/offset/추적 DWORD/첫 순열/같은 게임 난수/Session 동일 저장소 여부를 읽기만 한다. SP.Get의 lazy 초기화 관문을 진단에서 호출하지 않는다.
