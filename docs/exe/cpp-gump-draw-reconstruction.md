# 공통 Gump Draw·클립 보호 복원

작업 PC: **HJOW-Athlon**, 기록일: **2026-10-12**. AGENTS.md·두 LEFT_JOBS를 확인했고 착수 시 Git 트리는 깨끗했다. 현재 PC와 마지막 디컴파일 수행 PC가 일치했다. `gumpdraw` **8/10/10개**를 Ghidra 읽기 전용으로 내보냈다. 원본/복사본 게임·analyzeManager·클론 창은 실행하지 않았다.

## 완료 범위

패치 10.78의 **00466310**, CD/추가판의 **00492aa0** 공통 Draw 몸체를 `GumpDraw`로 복원했다. `BindGumpDraw`는 공통 kind 2 토큰을 같은 `GumpCollection` 저장소의 현재 플래그/경계와 가상 처리기에 연결한다. `GumpPixelTarget`은 현재 VFX 클립을 사용하는 직교 선·이미지 픽셀 출력을 제공한다.

이번 완료 범위는 가상 표 **+0x24** 처리기를 호출하는 공통 보호 경로다. 각 파생 Gump의 생성/분류/실제 Draw 몸체, 글자/가격 이미지 공급, 실제 Client/GameWorld 프레임의 자동 연결은 후속이다. 현재 메뉴 전체를 이 경로로 전환하거나 실제 GUI 출력 일치를 검증한 작업은 아니다.

## 현재 플래그와 클립

Draw 직전에 raw **+4 bit 0x00400000**을 읽는다. 이 비트가 없으면 위치/경계를 조회하지 않고 가상 Draw만 호출하며, 그 처리기가 바꾼 클립은 그대로 남는다. visible/dead는 수집 단계의 필터다. 공통 Draw에는 해당 필터나 자식 순회가 없다. 자식은 수집된 표시 항목으로 별도 제출된다.

비트가 있으면 실제 Bounds→Position→CRT 절삭으로 영역을 얻는다. 월드 투영이 현재 화면 클립을 바꿀 수 있으므로 **경계 조회가 끝난 뒤의 현재 논리 클립**을 저장한다. Gump의 네 경계를 각각 기존 클립 범위로 제한하고 새 클립을 설정한 뒤 가상 Draw를 호출한다. 화면 밖 영역은 경계로 접힐 수 있고, 빈/역전 영역도 Draw 호출을 생략하지 않는다.

패치의 **00464200→00445290**, CD의 **00492c80**에서 각 좌표는 `max(min(value, high), low)`의 원본 순서로 제한된다. 단순 교차 사각형으로 바꾸거나 네 좌표를 정렬하지 않는다. 기존 `ClipScreenRect`의 같은 계산을 재사용한다.

화면 setter **004a1580/CD 00422e10**은 half-open 논리 경계와 inclusive VFX 경계를 함께 쓴다. VFX right/bottom은 논리 끝점에서 DWORD로 1을 뺀 값이다. INT_MIN에서 INT_MAX로 감기는 것도 보존한다. `SetGumpDrawClip`이 같은 두 상태를 설정한다.

정상 반환에서 가상 처리기가 만든 현재 클립 대신 저장한 **논리 영역**을 다시 setter에 넘긴다. 따라서 초기 VFX 전역이 논리 전역과 불일치하더라도 보호 분기의 반환 후에는 저장 논리 영역에 맞게 재설정된다. CD의 **00492b0f→00492d50** 복구 조각도 실제 명령으로 관찰했다. 중첩 Draw는 각 단계의 현재 클립을 따로 저장/복구한다.

호스트 `ClipGuard`는 C++ 예외에도 복구한다. 원본 PE의 정상 경로에서는 SEH 연결/해제를 감사했고, **실제 PE 예외 전파는 실행하지 않았다.** C++ 예외 검사는 호스트의 보호 계약을 검증한 별도 근거다.

## 픽셀 출력과 연결

`GumpCollection::Flags`는 Bounds와 같은 저장소에서 플래그를 읽는다. 수집→CRT 정렬→공통 kind 2→실제 클립 보호→`PlanButtonDraw`의 네 선/이미지 합성을 한 검사에서 연결했다. 부모 항목을 그렸다고 자식의 별도 제출에 부모 클립을 추가하지 않는다.

`GumpPixelTarget`은 매 선/이미지 호출에서 현재 inclusive VFX 전역을 읽는다. 끝점 +1과 표면 교차는 64비트에서 계산하여 큰 signed 끝점도 안전하게 처리한다. 선은 양 끝을 포함하고 입력 순서대로 덮으며 색 번호는 BYTE로 저장한다. 이미지는 기존 VFX 해제 결과의 투명도와 불투명 0/255, 선택적 **소스** 색 치환을 보존한다. 이미지 좌표는 해제한 픽셀 영역의 왼쪽 위다. SHP 기준점/질감 반복/텍스트의 상위 배치는 기존 계획과 실제 파생 처리기에서 공급해야 한다.

## 독립 관찰과 검증

`tools/decomp_gumpdraw_oracle.py`는 세 독립 PE의 전체 공통 Draw/위치/경계/CRT/ClipGump 생성/복구/화면 setter 몸체를 제한된 x86에서 실행한다. 가상 Draw와 월드 투영만 완성 입력 경계다. 가상 처리기의 클립 변경은 다시 실제 setter를 실행하고, 중첩 Draw는 다시 실제 루트를 정상 반환까지 실행한다. 경계에서 기대 제한/배치/캐시를 계산하지 않는다.

판본당 **476개**, 새 독립 원본 **1,428개**·누적 **514,551개**다. 두 x87 정밀도의 **중첩 포함 정상 루트 반환 3,288회**를 관찰했고 모든 상태/호출 관찰이 일치했다. 가상 호출 당시 클립 두 전역과 최종 클립, 전체 노드 캐시, 투영 순서, 실제 진입/setter 호출/정상 반환을 저장한다. 읽기 전용 노드/SID/가상 표·미사용 저장소와 ABI/x87/SEH·허용 실행/쓰기·SHA를 감사한다. 노드 좌표/크기는 유한 입력이며 게임/GUI/OS/assert 호출은 0이다.

새 C++ **10개**, Release 경고/오류 **0**·CTest 내부 **768개·실패 0**(154.49초, 전체 154.54초), 근거 감사 **115종**·새 변이 **11개 모두 검출**(`--focused`, 변이 전 사본 전체 검사 통과). 집중 검사 **10개·실패 0**. 새 변이는 클립 bit/복구·독립 제한/투영 후 저장·빈 영역 가상 호출·flagless 변경 유지·VFX 끝점/현재 클립·선 마지막 픽셀·이미지 색 치환·공통 분배 연결의 차이를 모두 검출했다. 최종 미검출/건너뜀 **0개**, 사본 소스 바이트 복구 완료.

실제 정상 SHP **297개**를 새 Gump 픽셀 경로와 기존 클론 VFX 사이에서 대조했다. 원본 게임 화면 캡처 일치의 근거는 아니다. 판본별 109/94/94개 실제 첫 정상 프레임을 읽기 전용으로 해제하여 생성 후 바뀐 현재 클립으로 비교했다. 픽셀 콘솔 도구의 빌드/출력 로그는 `extracted/gumpdraw-assets{,-build}.log`다.

로그: `extracted/gumpdraw-{export,export-cd,smoke,oracle,build,focused,ctest,audits,mutations}.log`. 내보내기: `extracted/gumpdraw/{originals,originalCD,original1037}/`. 도구/fixture/JSON은 UTF-8이며 AGENTS.md·보호 원본·dotnetpj는 변경하지 않았다. 커밋/푸시는 없다.
