# 썬 캐논 실제 Missile 사정선 종점 (2026-10-16)

현재/마지막 전체 정밀 디컴파일 PC는 **HJOW-Athlon / 2026-10-16**이다. 보호된 10.78 디컴파일과 PE를 정적으로 확인했으며 게임/GUI는 실행하지 않았다.

## 원본 방향·종점

`00481750`은 포구→목표 중심 또는 코너의 방향을 `0041ce90(..., cardinal=1)`로 네 방향 중 하나로 양자화한다. TYPE128이면 발사 자산의 현재 frame으로 `00466df0` 방향 허용 표를 검사하고, 현재 프레임에서 발사 가능한 방향을 고른다. 방향이 이미 일치할 때 원본 반환점은 북/남 `({from.x, to.y})`, 동/서 `({to.x, from.y})`다.

`RawGunTarget::MayFire`는 자산 중심→표적 중심으로 프레임/방향 조합을 제한한다. 그러나 `RawMissile::Construct`는 SHP/TYPE 핫스폿으로 보정한 포구와 목표 중심 또는 코너를 `rayEnd`에 전달한다. 두 방향 계산의 입력이 다르므로 사전 발사 허용을 `rayEnd`의 방향 일치 보장으로 간주하지 않는다. 단위96에서 방향 불일치 보정까지 연결했다.

원본 PE의 표와 분기에서 확인한 10.78 Sun Cannon 발사 프레임0..3 및24..27의 방향은 각각 남·북·서·동(`4,0,6,2`)으로 대응한다. 불일치 때는0·2·4·6 순서로 현재 프레임의 허용 방향을 선택하고 TYPE+44의 사정거리를 정수로 절삭한다. 그 거리를 방향별 정수 이동표에 곱해 포구에 더하고1..255로 제한한 뒤 축 정렬 종점을 반환한다. **이전에 “난수 보정”으로 기록한 것은 오해였다.** `0049ace0`은 사정거리 getter, `004e49c0`은 `__ftol`이며 이 경로에는 난수 소비가 없다.

## 구현·검증 범위

`RawProjectileGeometry::CannonRayEnd`가 방향 일치와 사정거리 보정 분기를 모두 계산하며 `RawCampaignSession`의 Missile `rayEnd` callback에 연결했다. TYPE 사정거리는 같은 실제 자산 정의의 float 값을 사용한다. 정수 곱의 DWORD 감김과 float 저장 순서도 보존한다. TYPE71 및 다른 판본/타입, 허용 방향이 없는 프레임, 비유한 좌표와 int32 범위 밖의 보정 거리는 명시적으로 거부한다. 실제 게임의 유효 TYPE128 사정거리는 이 범위에 속한다.

`RawMissile::Construct`는 비영 효과 타입의 `flightEffect` 연결 여부를 포구 조회 전에 검사한다. 따라서 현재 비행 효과11이 미연결인 전체 Session에서는 새 포구·종점 조회까지 도달하지 못한다. 기하 단위 검사 통과를 실제 썬 캐논 생성·Pop·비행 성공으로 합산하지 않는다.
