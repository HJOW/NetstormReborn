2026-10-09, **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-09.** AGENTS.md·두 LEFT_JOBS와 현재/마지막 호스트 일치를 확인했다. 새 `priestspawn` 목록을 같은 PC에서 읽기 전용으로 내보냈다(10.78 8개·CD/추가 10.37 각각 7개). 원본 게임/복사본·클론 창 실행, 보호 파일·AGENTS.md·dotnetpj 변경, 커밋/푸시 없이 정적/제한 기계어/콘솔 검사를 수행했다.

[`RawPriestSpawn`](../../cpppj/src/o/RawPriestSpawn.h)는 위 생성 함수 전체의 조건·좌표·호출 순서를 복원한다. `MakePriestSpawnHooks`는 같은 풀의 종속 해방에서 `spawnPriest`만 실제 몸체로 연결한다.

1. 입력 WORD 전체와 `WORD&0x7f` 소유자를 함수 진입 값으로 유지한다. 두 좌표에 `0.99999f`를 넓은 정밀도로 더한 뒤 CRT 방식으로 절삭한다. 정수 좌표를 float에 저장하는 원본 스냅을 정상 지도 범위에서 보존한다.
2. 시작점부터 **북→동→남→서**로 각 변 길이 `1,1,2,2,...,11,11`의 나선을 걷는다. 원본의 8방향 표 0/2/4/6번이며 stage 2~23의 `stage/2` 길이다. 총 **132개 후보**를 확인하고 마지막 실패 후보 뒤 이동도 수행한다. 범위 밖 후보도 예산을 소비한다.
3. `0<x<255 && 0<y<255`인 후보만 공간 바이트를 읽는다. **spot==0이면 타입별 배치 검사를 생략하고 바로 생성한다.** 그 밖에는 타입 배치 검사에 `(type,x,y,0,소유자,0)`을 전달하고 반환값이 0이 아니면서 **검사 전에 읽은 spot**의 `0x10` 비트가 없으면 생성한다. 검사 콜백에서 현재 공간을 지워도 이미 읽은 비트로 해당 후보를 판단한다.
4. 생성 `(type,0)`→새 자산에 입력 WORD 전체 실제 쓰기→현재 새 타입과 현재 다리 타입 DWORD가 같으면 표면 알림→가상 소유자 `(new,WORD&0x7f)`→가상 Pop `(new,선택된 정수 x,y,0)` 순서다. 종속 해방 본체의 생성 후 **원래 후보 WORD 재읽기**와 달리 이 함수의 WORD는 값 인자로 고정된다.
5. Pop 뒤 현재 새 자산 타입의 genus를 읽는다. Carrier 마스크 `0x30000`이 있으면 가상 `+0xcc` 상태 검사를 호출하고 그 반환값은 이 생성 함수에서 사용하지 않는다. CD는 Carrier가 아니면 생략한다. 패치는 Carrier 누락의 무조건 assert가 있으며 C++는 예외로 진단한다.

자리를 못 찾으면 CD는 조용히 반환한다. 패치는 현재 debug 조건이 0이면 반환하고, 켜져 있으면 원본의 Damageable.cpp 0x62 assert에 해당하는 예외를 낸다. 입력 NaN/무한대·정수 범위 밖 좌표·비자산/타입 표 밖 번호와 누락된 하위 훅은 효과 전에 거부한다.

마지막 가상 호출은 **상태 검사**다. 실제 사제 가상 표의 `+0xcc`는 `00426fc0`/CD `004e50d0`이며 genus `0x320000` 조건·현재 공간·가상 `+0xc8` 결과를 조회하는 몸체다. 이번 구현은 래퍼의 genus 분기까지만 실제 수행하고 가상 몸체는 `checkCarrier` 경계다.

## 실제 생성/소유자 연결과 제한

새 두 판본 통합 검사는 종속 해방→사제 나선→**실제 서버 SID 할당·사제 생성자·공통 postCreate**→**실제 RawPriestOwner/SquidOwner**를 연결한다. 예측/클라이언트 SID로 만든 부모와 contained 후보에서 서버 영역 첫 SID(패치 15000/CD 6000)를 만들고, 부모/종속/새 사제로 freeCount가 3 감소하는 것을 확인한다. 입력 WORD `0x8101`을 복사한 뒤 실제 로컬 소유자 표시로 새 사제 WORD는 `0x8181`, 소유자는 1이 되며 원래 후보 WORD는 유지된다. 선택 좌표는 `(21,22)`다.

이 통합은 빈 공간에서 배치 검사 호출이 없으며 **일반 사제 Pop과 가상 Carrier 상태 검사는 기록 경계**다. 실제 비표면 공간 등록·보호막/회복 예약·전체 생성 수명이 완성된 것은 아니다. 독립 fixture에서도 배치 검사, 생성, 가상 소유자/Pop/상태 검사, 표면 알림은 함수 진입에서 대체한다. 배치 검사 내부의 공간/관계/지형 조건과 일반 Pop은 다음 단계다. 원본에서 assert하는 소유자 범위 등 하위 함수의 모든 계약이 fixture의 기록 대체로 검증되는 것은 아니다.

## 독립 대조와 검증

[`decomp_priestspawn_oracle.py`](../../tools/decomp_priestspawn_oracle.py)는 실제 세 PE에서 **10.78 408개·CD 414개·추가 10.37 414개, 총 1,236개**를 두 x87 정밀도로 실행한다. 두 정밀도의 관찰이 같다. 스냅/CRT·132개 나선·경계/공간 조건·WORD 쓰기·Carrier 래퍼/현재 genus·정상 반환은 실제 명령이며 중간 구간 대체는 없다.

일반/미세 경계 좌표와 `(0,0)`·`(255,255)`, WORD 상위 비트와 low 7비트, 빈/지면/0x10 공간, 배치 검사 실패/첫 성공/세 번째 성공/132번째 성공/교대/0xffffffff 반환을 교차한다. 검사 중 현재/다음 공간 변경, 검사/생성 중 다리 타입 변경, Pop 중 새 타입/현재 genus 변경도 포함한다. CD 두 판본에는 Pop 뒤 비 Carrier genus의 정상 생략 6행씩을 추가했다. 같은 입력은 패치에서 무조건 assert이므로 정상 fixture에서 제외한다.

각 PE·두 정밀도 합계: 실제 사제 진입/스냅은 패치 816회·CD/10.37 828회, CRT는 3264/3312/3312회다. 실제 WORD/Carrier 래퍼는 480/492/492회, 실제 현재 genus는 960/492/492회다. 기록 대체 배치 검사는 각 판본 **40,468회**, 생성/소유자/Pop은 480/492/492회, 가상 Carrier 검사는 각 480회, 표면 검사는 각 240회다. 생성 실패와 검사 생략도 포함하며 새 슬롯은 생성되지 않아도 전체 비교한다.

C++는 현재 다리 전역·모든 외부 사건의 순서/인자·새 raw 전체 바이트·전체 지도 Adler-32를 독립 관찰과 비교한다. 원본 실행기는 cdecl EIP/ESP·각 thiscall/cdecl 인자·보존 레지스터·x87·허용 코드/스택/WORD 쓰기, assert/OS 0회와 파일 SHA/실제 진입/대체 호출 수를 검사한다. 패치의 정상 자리 탐색 실패는 debug 전역 0으로 실행하며 C++ 별도 검사에서 debug 켜짐과 Carrier assert 진단을 확인한다.

검증 결과와 다음 작업은 [LEFT_JOBS.md](../../LEFT_JOBS.md)에 기록한다. 최종 Release 경고/오류 0·CTest 내부 **320개·실패 0**(95.78초)·감사 **43종 모두 통과**이며 새 독립 입력을 더한 누적 x86은 **213,325개**다. 로그는 `extracted/cpp-priestspawn-build-final.log`, `cpp-priestspawn-ctest-final.log`, `cpp-priestspawn-oracle-final.log`, `cpp-priestspawn-audits-final.log`다.
