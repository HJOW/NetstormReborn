## 복원 범위와 근거

## 생성과 부분 필드 초기화

Slider는 기본 `(0,0,0,1)` 등록 생성 뒤 값/범위/페이지/방향/step/자식·보조 필드를 초기화한다. 원본이 쓰지 않는 +bc는 보존한다. 입력 폭/높이 중 **0인 축만 40**으로 치환하며, height < width면 가로 방향이다. signed 정렬 BYTE의 실제 초기값은 Slider **39**, 화살표 **1**, 손잡이 **51**이다.

감소/증가 화살표에 각각 `new(0x178)`을 요청하고 손잡이는 패치 `0xd8`, CD `0xd4`를 요청한다. 호스트 allocator는 이 요청에 맞는 안정된 파생 노드를 공급한다. 실패 0은 생성자를 생략한 뒤 원본처럼 해당 자식 필드에 저장한다. 원본 null 접근 지점은 호스트 예외로 거부한다. 이전에 생성한 자식을 자동 정리하는 새로운 실패 정책은 넣지 않았다.

가로 방향의 화살표는 3/1(왼쪽/오른쪽), 세로는 0/2(위/아래)다. 세 자식을 만든 뒤 감소→증가→트랙의 **현재 토큰**을 가상 Attach로 부착한다. 부모 값은 위치 0→range 0..100→page 10→position 50으로 초기화하며 기존 Slider의 재그리기/재부착 콜백을 사용한다.

폭의 배율 계산은 두 판본 모두 저장 전 FILD 정수 값을 사용한다. 높이는 패치만 지역 float32를 다시 읽고 CD는 FILD 값을 유지한다. 짧은 축 절삭도 패치 세로 분기에서는 저장 전 폭을 사용하고 그 밖에는 저장한 축을 읽는다. 중간값 위치를 실제 명령으로 판독해 반영했다. 일반 double 복원과 극단 x87 80비트 값의 독립 대조는 남았다.

화살표는 기존 빈 라벨 돌 버튼 생성에 `{0,0,color,0,0,0,1,1}`의 명시 문맥을 넘기고, 파생 표·팝업 유지 bit 0x20·정렬·방향을 설정한다. 원본의 돌 버튼 미작성 라벨 꼬리/문맥 일부와 배경 소유 관계는 기존 처리기가 유지한다.

손잡이는 **`GumpBackgroundNode`를 상속**하도록 기존 표시 저장소를 확장했다. 기본 배경 `(0,0,0x03ec0000,0x201,현재 기본 type,현재 기본 frame)` 생성 뒤 파생 표/handle 0·정렬·정수 크기·+b8/+bc 인자 사본을 쓴다. 이전 y/x는 원본처럼 미작성 상태를 보존한다. type 0이면 기존 shape/타일 필드도 기본 생성 규칙대로 보존한다.

## 실제 그래픽 출력

화살표는 기존 실제 돌 버튼 Draw를 호출한 뒤 현재 Bounds를 다시 읽는다. 네 좌표를 2씩 안쪽으로 줄이고 기본 문맥의 +88 색으로 삼각형 세 선을 호출한다. 중점은 **DWORD 합 / 2의 0 방향 절삭**이다. direction 1/2/3은 오른쪽/아래/왼쪽, 그 밖에는 위쪽이다. 원본처럼 눌림/비활성 글자 문맥으로 삼각형 색이나 위치를 바꾸지 않는다.

손잡이는 기본 배경 Draw 뒤 현재 Bounds+handle 사각형을 기본 배경 type/frame으로 다시 출력한다. **+b8/+bc의 생성 인자 사본은 이 Draw에 사용하지 않는다.** 포함 선택 좌표인 handle right/bottom을 +1하지 않고 원본 half-open 배경 함수에 전달한다. 선택과 출력의 끝점 차이도 유지한다. 기본/내부 질감과 명암/테두리·현재 클립/색 표는 기존 실제 배경 처리기를 사용한다.

`BindScrollGumpWidgetDraw`는 Slider 부모의 **빈 Draw**, 두 표시 자식의 실제 Draw를 기존 kind 2 분배에 연결한다. `BindScrollGumpWidgetLifetime`은 세 파생 scalar를 공통 기본 소멸/하위 BYTE bit 0 반납으로 연결한다. 자식 우선 삭제/등록 해제는 기존 수명 처리기가 먼저 수행한다. 실제 자산 로딩 뒤 `ScrollGumpWidgetState.defaultType`과 기본 frame을 공급하고, 각 처리기의 노드 조회가 같은 객체를 반환하게 구성해야 한다. defaultType의 PE 초기값 0은 자산 로딩 후 값이 아니다.

## 일반 8비트 VFX 선

새 `VFXLine`은 일반 선의 **mode 0 단색 BYTE** 경로다. `GumpPixelTarget::Lines`의 대각선 분기를 연결했고 기존 직교 선 경로를 유지한다. 화살표 삼각형이 동일 표면/현재 클립에 실제 픽셀을 쓴다. 색 치환/사용자 콜백 mode는 포함하지 않는다.

- 입력/출력 끝점은 양 끝 포함이며 pane 원점의 래퍼 감산/커널 재가산이 상쇄된 화면 절대 좌표를 사용한다.
- 주축과 방향은 원래 두 끝점으로 정한다. 분수는 **floor(min(|dx|,|dy|) × 2^32 / max)**이고 대각선 동률은 원본 특수 경로다.
- clip은 표면과 교차한 inclusive 경계에서 왼쪽→오른쪽→위→아래 순서로 판정한다. 두 끝점이 같은 바깥 반평면이면 버린다.
- 주축 경계 교차는 원래 시작점 기준 곱의 high DWORD+low bit 31 반올림이다. 부축 경계 역산은 시작점에서 `(거리-0.5)/분수`의 ceil, 끝점에서 `(거리+0.5)/분수`의 ceil-1을 사용한다. 현재 잘린 두 점으로 기울기를 새로 계산하지 않는다.
- 시작 분수 위상은 **abs(잘린 주축 시작-원래 주축 시작) × 분수 + 0x80000000**의 하위 DWORD다. 주축 픽셀마다 ADD carry로 부축을 이동한다. 잘린 선이 원래 선의 위상을 유지한다.

호스트 표면 범위 밖 쓰기와 signed 거리 INT_MAX 초과·DIV 몫 overflow·비정상 클립 수렴 실패는 거부한다. 정상 8비트 GUI 좌표의 복원 범위와 원본의 불가능한 메모리/정수 입력을 구분한다. 이 수식/픽셀의 독립 원본/C++ 대조는 아직 수행하지 않았다.
