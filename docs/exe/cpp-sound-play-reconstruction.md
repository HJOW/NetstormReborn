2026-10-10. **마지막 디컴파일 수행 PC: HJOW-Athlon, 2026-10-10.** AGENTS.md·LEFT_JOBS.md·관련 문서를 확인했고 현재 호스트가 마지막 디컴파일 PC와 같다. 같은 PC에서 새 `soundplay` 목록 **19/16/16개**를 읽기 전용으로 내보냈다. 10.78 싱글플레이 우선, Windows 안정 구동 2차, outpost/LAN 3차, 한국어/요구사항/MCP 4차를 유지했다. 원본 게임/복사본·클론 창은 실행하지 않았고 **소리 장치도 열지 않았다.**

[앞 단계](cpp-sound-process-reconstruction.md)의 소리 프로세스는 재생/정지를 훅으로 요청하기만 했다. 이번에 그 요청을 받는 **재생 계층**을 복원했다.

- `SoundList`의 머리 필드 접근과 복제 항목 추가.
- 연결: `MakeSoundProcessHooks`(소리 프로세스 → 재생 계층), `MakePriestShieldNoticeHooks`(보호막 로컬 안내 소리), `MakePriestFallSound`(사제 낙하 소리).

## 항목 머리와 복제 항목

이름 표의 항목 머리(0x1c바이트)는 재생 상태를 담는다.

| 오프셋 | 필드 | 뜻 |
|---|---|---|
| `+0x00` | Buffer | 장치 버퍼. 0 = 아직 적재하지 않음, 0xffffffff = 파일이 없거나 만들지 못함 |
| `+0x04` | Root | 같은 이름의 첫 항목(자기 자신이면 원본 항목) |
| `+0x08` | Next | 같은 소리를 겹쳐 재생하려고 만든 다음 복제 항목 |
| `+0x0c` | Attenuation | 소리별 감쇠. 적재가 파일 이름의 `-숫자`에서 읽어 쓴다 |
| `+0x10` | Volume | 마지막 재생/갱신의 음량 인자 |
| `+0x14` | Serial | 재생을 시작할 때마다 매기는 일련번호 |
| `+0x18` | Priority | 재생할 때의 우선 인자 |

같은 소리를 겹쳐 재생하면 버퍼를 복제해 **같은 이름의 새 항목**을 표 끝에 붙이고 사슬(Root → Next → …)로 잇는다. 새 복제 항목은 이름·Root·Next·Buffer만 쓰므로 **감쇠가 0으로 남는다**(겹쳐 재생한 소리는 파일 감쇠만큼 더 크게 난다 — 원본 그대로). 복제 항목은 이름 표의 한도(0x7fb0) 검사 없이 추가된다. C++은 표 끝(0x8000)을 넘을 때만 `std::length_error`로 막는다.

## 전역 재생

`Play(소리, 반복, 음량, 좌우, 우선, 한도)`의 순서:

1. 준비되지 않았거나 소리가 0이거나 옵션 `sound`가 꺼져 있으면 0.
2. **우선이 0일 때만** 동시 재생 한도를 본다: `maxSimulSounds`가 0이 아니고 재생 수가 그 이상이면 0.
3. 항목의 버퍼가 0이면 원본 항목을 적재한다(이미 적재돼 있으면 건너뜀). 그래도 0이면(버퍼가 지워진 복제 항목) 원본 항목의 버퍼를 복제해 되살린다. 실패하면 기록(줄 784)하고 그 항목을 돌려준다.
4. 버퍼가 소리 없음 표식이면 재생하지 않고 항목을 돌려준다.
5. 항목이 재생 중이 아니면 그 항목을 쓴다. 재생 중이면 사슬을 원본 항목부터 따라가며 재생 중인 항목을 세고,
   - `한도`가 0이 아니고 센 수가 그 이상이면 0,
   - 쉬고 있는 항목을 만나면 그것을 쓰고(버퍼가 지워졌으면 **요청한 항목의 버퍼**를 복제해 채운다. 실패 줄 828),
   - 사슬이 모두 재생 중이면 버퍼를 복제해 새 복제 항목을 만든다(실패 줄 840 — 이때는 요청한 항목을 돌려준다).
6. 쓸 항목에 우선·일련번호·음량 인자를 적고, `음량 인자 + 전체 음량 − 감쇠`를 [-10000, 0]으로 잘라 SetVolume, 좌우 값을 SetPan, `Play(0, 0, 반복 != 0)`을 부른다. 재생 수를 1 늘리고 쓴 항목을 돌려준다.

재생 수는 재생할 때 늘고 **정지를 호출할 때만** 준다. 스스로 끝난 소리는 수를 줄이지 않는다(원본에는 표 전체의 상태를 다시 세는 `004a8e60`이 따로 있다 — 미복원).

기계어로 확정한 인자의 뜻: 둘째는 **반복**(DSBPLAY_LOOPING), 다섯째는 **우선**(동시 재생 한도를 건너뛰고 항목에 기록), 여섯째는 **같은 소리의 동시 재생 한도**다. 앞 단계 문서에서 "추정"으로 둔 부분이 이것으로 정리된다. 소리 프로세스의 한 번 재생 + 위치 조합은 `flags & 8`을 위치 한 번 재생의 넷째 인자로 넘기므로 **그 값이 반복 인자가 된다**(우선은 0). 원본의 인자 순서가 그렇고 C++도 그대로 따른다.

패치판에는 여기에 **변조 감지용 고의 고장**이 하나 끼어 있다. 전역 `005318ec`(초기 6, 검사에 걸리면 0~8 가운데 미리 뽑아 둔 값이 들어간다)가 7이면 SetPan 뒤에 버퍼 포인터를 null로 바꿔 Play를 불러 멈춘다. CD판에는 없다. **옮기지 않았고** 자리만 주석으로 남겼다.

## 위치 재생과 화면 계산

`월드→화면`은 `x × 16 + 0.5`, `y × 11 + 0.5`를 0쪽으로 절삭해 카메라 원점을 뺀다. `화면 안`은 화면 영역에서 좌우 40·상하 30픽셀 여유 안이다. 화면 가로 절반을 `h`(0쪽 절삭), 가로 중심에서의 거리를 `c`, 세로 중심에서의 거리를 `d`라 하면

- 좌우 = `±10000 × c² ÷ h²` (왼쪽이 음수, `swapLeftRightSpeakers`면 부호 반대, 가운데는 나눗셈 없이 0),
- 음량 = `−1000 × (c² + d²) ÷ h²` (세로 거리도 가로 절반으로 나눈다),

둘 다 [-10000, 10000]으로 자른다. 곱셈은 32비트로 넘치므로 화면에서 아주 먼 점의 값은 뜻이 없지만(그런 점은 화면 안 판정에서 먼저 걸러진다) 원본과 같은 값을 낸다. 가로가 2픽셀보다 좁으면 원본은 0으로 나누어 멈춘다(C++은 `std::domain_error`).

`PlayOnceAt(x, y, 소리, 반복, 우선)`은 화면 안일 때만 `Play(소리, 반복, 음량, 좌우, 우선, 0)`을 부른다.

`PlayLoopAt(x, y, 현재, 소리)`는 소리 프로세스가 매 프레임 부른다.

1. 옵션이 꺼졌거나 장치가 없으면 0.
2. `현재`와 `소리`가 둘 다 있으면 이름을 비교한다. 같으면(복제 항목 포함) `현재`를 계속 쓰고, 다르면 `현재`를 **재생 중인지 묻지 않고** 정지한다.
3. 화면 안이고 `현재`가 재생 중이 아니면 `Play(소리 또는 현재, 반복, 0, 0, 우선 없음, 한도 1)`로 시작한다. 그래서 같은 소리는 위치 반복으로 하나만 난다.
4. 화면 밖이면 재생 중인 `현재`를 정지하고 0을 돌려준다.
5. 재생 중이면 위치에 맞는 음량/좌우를 다시 정한다. 이 두 설정은 **0이 아닌 모든 반환**을 실패로 기록한다(전역 재생은 음수만).

CD판은 3번에서 전역 재생 함수를 그대로 호출한다. 패치판은 그 호출이 인라인돼 있어 함수가 길지만(970바이트) 논리는 같다 — 두 판본의 관찰이 기록 문장의 파일 이름/줄 번호를 빼고 전부 일치했다.

대체한 장치는 "재생하면 재생 중(반복이면 반복 비트), 정지하면 멈춤"만 흉내 내는 상태표다. 가짜 버퍼는 COM 객체 모양(가상 표 포인터)만 갖추고 원본이 `call [vtable + 오프셋]`으로 들어오는 순간을 가로챈다. C++ 검사의 장치도 같은 규칙과 같은 버퍼 값(`0x16001000 + 16 × 순번`)을 쓰므로 표 전체 바이트를 그대로 비교한다.

한계: 실제 DirectSound의 동작(재생이 끝나면 상태가 바뀌는 것, 버퍼를 잃는 조건, 복제 버퍼의 음량 공유 등)은 관찰하지 않았다. 원본이 멈추는 입력(위 절)과 손상된 사슬은 입력에서 뺐다. 변조 감지 값은 초기값 그대로 두었다.

## C++ 검사

[`SoundPlayTests.cpp`](../../cpppj/tests/SoundPlayTests.cpp)의 새 검사 5개.

1. **세 PE 관찰 재생(3개).** 연산 묶음을 실제 `SoundList`·`SoundPlayer`에 같은 순서로 적용해 연산별 사건·반환과 마지막 상태를 비교하고, 좌표 계산 행을 네 함수에 대조한다.
2. **보호막에서 장치까지.** 두 raw 배치에서 실제 보호막 생성 wrapper → 이름 표 → 소리 프로세스 → 재생 계층 → 장치 호출을 잇는다. 생성 직후 로컬 안내 소리(`ourPriestImmobile.wav`)가 우선 재생으로 적재·재생되고(감쇠 300 + 전체 음량 −200 → −500), 첫 프레임에 보호막 소리가 적재 → 반복 재생 → 위치 음량/좌우 갱신, 다음 프레임에는 갱신만, 화면 밖으로 나가면 정지, 다시 들어오면 같은 버퍼로 재시작, 보호막이 자기 삭제하면 종속 form 정리에서 정지와 재생 여부 확인이 장치에 도달한다. 사제 낙하 소리는 화면 안에서만 재생된다.
3. **거부와 진단.** 빠진 장치 효과·표 밖 항목·좁은 화면·버퍼 없는 항목의 교체(보고 155·156 뒤 예외)·소리 없음 항목(장치에 닿지 않음)·가득 찬 표의 복제 항목.

변이 확인([`cpp_mutation_check.py`](../../tools/cpp_mutation_check.py), 저장소 밖 사본): 새 변이 **15개**(우선의 한도 건너뛰기, 한도 경계 두 가지, 음량 상한, 복제 항목의 감쇠, 쉬는 항목을 채우는 원본, 다른 이름 교체 때 정지, 화면 밖 정지, 위치 설정 실패 기준, 좌우 바꿈, 음량의 나눗수, 화면 여유, 정지 뒤 되돌림, 유일성 보고 조건, 반 픽셀) — 15개 모두 검출됐다(아래 "최종 검증").
