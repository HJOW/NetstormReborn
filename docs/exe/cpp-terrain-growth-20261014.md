# 실제 일반 초기 지형 성장

작업 PC와 마지막 정밀 디컴파일 PC는 **HJOW-Athlon**이다. 최신 확대 내보내기는2026-10-14의 Dais이며, 이 지형의 좁은 내보내기는13일 밤의 패치14/CD16 함수다. AGENTS.md와 두 인수인계를 다시 확인했고 보호 원본 PE/AGENTS를 보존했다. 게임·GUI 실행은 없다.

## 같은 context의 실제 배열

`RawTerrainGrowth`는 `RawTerrainContext`가 소유한 code/region 배열과 현재 bounds, `ChunkMap`의12바이트 항목, 현재 noRegion을 참조한다. 임시 지역 mask를 렌더 자료로 복사하는 기존 미리보기 경로와 별도로 실제 `x*256+y` 배열에 쓴다. 지형 생성 뒤 `RawTerrainStamp`가 이 같은 배열을 읽도록 구성할 수 있다.

| 단계 | 10.78 | CD 10.72 |
| --- | --- | --- |
| 일반 통로/성장 상위 | `004c10a0` | `0049e160` |
| 청크별 성장 순회 | `004c0ec0` | `0049ded0` |
| 3×3 성장 | `004c0800` | `0049d690` |
| 단일 칸 추가 | `004c0780` | `0049d5b0` |
| 사각형 채우기 | `004c0930` | `0049d810` |
| 빈틈 보정 순회 | `004c0cf0` | `0049db10` |
| 빈틈의 연속 이웃 | `004c0c30` | `0049da90` |

상위 순서는 전체 청크 통로→전체 청크 성장→두 번 빈틈 보정이다. 통로의 두 번째 지역 청크에는 별도의10×10 사각형을 더한다. 이미 `x`인 칸은 region을 덮어쓰지 않는다. 성장은 현재 지역의 `x`에서 Y외부/X내부3×3을 추가하며 연속 실패1000회와 성공 후 실패 한계 재설정을 보존한다.

빈틈 순회는 Y의 bottom직전과 X의 right-1직전이라는 서로 다른 끝 조건을 가진다. 같은 지역 `x`가13번 이웃 조회에서5개 이상 연속하고 대각선에서 끝날 때 해당 빈 칸을 메운다. 앞선 칸의 변경을 다음 칸이 즉시 읽는다.

## CD의 생략된 this 확인

CD 디컴파일의 `004a59d0(limit)` 표기만 읽으면 난수 저장소를 오인할 수 있다. 실제 호출자는 `0049e415 lea ecx,[esp+0x34]`로 로컬seed를 전달하고 `004a59d0→004a59a0`이 그 DWORD를 갱신한다. seed 준비 역시 실제 기계어에서 지역 방문 번호×0x10e3+recordBYTE를 저장한다. 두 판본 모두 이 로컬 난수를 소비하며 게임 전역 난수는 보존한다.

첫 소수 실행에서 CD core `004a59a0`의 빠진 허용 범위를 발견했다. 실패 로그를 보존하고 현재 호스트의 전체 정밀 metadata에서 그 한 몸체만 선택해 추가했다. 선택 범위와 PE/metadata SHA는 보고서에 기록한다. 기존 helper의 완료 관찰을 새 입력에 합산하지 않는다.

## 전수 대조

빈/단일/연결/다른 지역/넓은 청크/기존 문자 입력6종, seed3종, 선택 지역3종을 교차했다. 양판본 **108개 고유 정상 입력**이며 두 x87 정밀도의216회 반환이 모두 같은 결과다. 매 입력의 **전체65,536BYTE code와 region**을 손실 없는 RLE로 보관하고 C++에서 기대 배열을 계산하지 않고 직접 비교한다. 게임 전역 난수 보존과 assertion0도 확인했다.

첫 공유 Release의 **C++2검사/실패0**로 모든 배열을 전수 대조했다. 같은 owned 배열 참조와 mapping/마지막SID/predictable 보존 검사도 통과했다. 최종 공유 빌드/전체 검사는 단위09 종합 보고서에 기록한다.

```text
python -X utf8 tools/decomp_terraingrowth_oracle.py --verify
python -X utf8 tools/analyze_terraingrowth_cpp_binding.py --verify
```

## 후속 범위

이 단위는 일반 생성 분기다. archipelago 성장/상위wrapper·Stamp/Factory/실제 지면 프레임·edgeFarm 이후 순서·Fort 저장 객체/로딩 깊이·GameWorld 입력/표시·캠페인 완주는 후속이다. 배열 밖 손상 좌표를 정상 칸으로 clamp하지 않는다. 기존 초기Context224/Stamp1560과 같은 입력의 재생성은 이번108개에 추가하지 않는다.
