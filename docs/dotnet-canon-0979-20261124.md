# dotnetpj 0.979 — Build에 전투 생성 0x23·전투 제거 0x24·항해 오류 0x25 수신기 연결

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 같은 장기 기본 표를 공유하는 `ClientPacketDispatch.Build`/`InstallDefaults`에 원문 앱 전역 0x23 전투 생성·0x24 전투 제거·0x25 항해 오류 수신기를 연결했다. 이것으로 `InstallClientPacketDefaults`의 270행 중 DN 미연결 수신기는 수송·메타 연결 런타임(R11)과 Root 생성 부모만 남는다. 0x88·0x67 Build 연결과 제품 기존 경로는 바꾸지 않는다. RU-3 나머지·R4-4 정기 두 단위는 후속에서 잇는다.

## 변경과 원문 대응

- 0x23 후크는 실제 장기 장치를 공유한다. CS·진단·수준9 로그는 실제 owner이며, 기존 전투이면 로그만 남기고 조용히 돌아가고 신규 전투는 기록 식별자·위치를 쓴 뒤 공장 TYPE 앞에서 멈춘다(cpppj `NativeMetaBattleCreate.cpp` 확인). 새로 만든 본체가 없다. 0.979에서 추가됐다.
- 0x24 후크는 실제 장기 장치와 호출자 진단 장치를 공유한다. 없는 전투이면 로그만 남기고 조용히 돌아가며, 유효 전투는 하차 앞에서 멈춘다. 새로 만든 본체가 없다. 0.979에서 추가됐다.
- 0x25 후크는 실제 장기 장치와 호출자 진단·알림 장치를 공유한다. 미발견 구독자는 빈 기록 읽기를 거부하고, 오류 1은 번역 앞에서, 오류 5는 Tell 없이 성공으로 꾸미지 않으며, Tell 뒤에는 표시 앞에서 멈춘다. 새로 만든 본체가 없다. 0.979에서 추가됐다.
- 0x23·0x24·0x25의 수준9 로그는 원문 대응으로 같은 호출자 진단 장치에 코드 9를 붙인다(cpppj `ClientMetaPacketReceivers.cpp`·`NativeMetaBattleCreate.cpp` 확인).
- 수송 팩토리(`ClientCampaignTransport.Make`)는 같은 `InstallDefaults`를 공유하므로 세 항목을 자동으로 공유한다.
