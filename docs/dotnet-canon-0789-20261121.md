# 0.789 객체 패킷 수신 하위 본체

NativeGameplay26F 연결에 필요한 객체 수신 본체를 옮겼다. 2ch의35BYTE 수신, 2dh 내용물·2eh 삭제·65h 감시, 53h 단일·62h 목록 삭제, 4ah/4bh 검증, 7ah 압축 해제와 공통 WORD setter가 대상이다. GameAux의 검증SID·이전 검증SID·수신TYPE 문맥은 새로 복사하지 않는 장기 DWORD 상자로 유지한다. 원문 근거의 마지막 수정 커밋은 `extracted/dotnet-0789/source-revisions.json`에 기록했다. PORT_MAP에 실제9쌍을 추가했고 기존 GameAux 대응 상태는 유지했다.

수신 중 공장·진단·로그·소유자·기술·삭제 콜백이 입력과 실제 슬롯을 바꿀 수 있다. 원문에서 보관하는 SID/슬롯과 이후 다시 읽는 현재 필드를 구별했다. 내용물의 첫 배치와 감시 전용 부착, 환불 전 저장한 삭제 플래그, 목록 삭제의 현재 signed count, 검증의 정상 반환 시점에만 지우는 SID/TYPE 문맥을 보존한다. WORD setter는 현재 다리 TYPE 검사 전에 실제 WORD를 저장한다. 압축 수신은 먼저64BYTE 지역 입력을 복사하고 같은 송수신 owner 캐시를 갱신한다. 기본 HP/zOrder는4번 필드 뒤에 항상 선택하며14/15번 필드는 입력을 소비하지 않는다. 정의되지 않은 물리 입력은 앞선 효과를 유지한 채 실패한다.

신규27건 포함 집중52건이 통과했다. 실제 RawSquidFactory/RawSquidTransmission 송신→목적지 공장 Take/RawSquidWord/SquidOwner→수신의 연결, 전체 슬롯 바이트, 반환 SID 변경, 진단 복귀 후 현재 값, 콜백 실패 전 부분 저장, 압축 마스크/캐시/기본값을 검사했다. 이 연결 검사는 전체 월드 공간 Pop이나 Root 설치의 완료를 뜻하지 않는다. 최초 테스트 컴파일의 WORD 길이 인자 범위를 바로잡은 후 최종52건을 확인했다. 새 독립 원본 PE/CPP Source 관찰 기대값은 만들지 않았으며 기존397자료의 모든 항목·헤더·SHA·행 수가 그대로다.
