# 0.779 실제 Root UI 수신과 뉴스 문맥

HostChatReceive가 같은 실제 Client/Surface/구독자·Player 동맹표·현재 월드의 숨김9BYTE·설정·창/공유 로그·팔레트와 등록 버튼을 수신 본체에 연결한다. 설치는 Player를 할당하거나 모드/본문을 조회하지 않는다. Identity는 사용 시점의 Root 조회 함수를 사용한다. 설정값0과 실제 키 누락은 원문처럼 ReadInt→ReadString으로 구별하며 무시 목록과 관계표는 매번 현재 값을 읽는다.

GumpButtonTree에 같은 BSS0 채팅 알림 등록 ID와 PulseRegisteredIfIdle을 연결했다. serial 재검색 없이 현재 등록 칸을 읽고 pressed/value/pulse 관문 뒤 실제 버튼 SetPulse와 idle 표를 사용한다. 없는 칸은 false, 범위 밖이나 미복원 버튼 필드는 명시 오류다. Native HUD의 실제 ID 작성자는 아직 남았다.

Root가 전체 실제 창 생성 뒤 수신 소비자를 설치하고 ReceiveNativePacketChat을 제공한다. 뉴스는 시각 store→기존 서버별 설정 저장→같은 실제 HTML 생성기 순서로 연결했다. HTML 배치는 원문 LoadingHtmlContext처럼 현재 지도 문맥을 유지해 이미 만든 창의 재부착과 후속 창도 현재 영역을 읽는다. 뉴스에서 NativeMapView 미설치는 화면 전체로 대체하지 않고 실패한다. 같은 장기 WorldAudio를 첫 메뉴 전에 준비하고 위치 없는 Chat 요청은 기존 이름표/SoundPlayer에 우선순위0으로 전달한다. 미션은 이 장치를 재사용한다.

신규2건 포함 최종 집중26건이 통과했다. 실제 고정41h→창/공유 로그/버튼 idle, 창0·자기/타인 음향 선택·현재 무시 목록·부분 버퍼 앞뒤 보존, 실제 옵션0/누락, 뉴스 저장 콜백 뒤 바뀐 본문·HTML 창·현재 지도 변경/재부착/후속 생성, 같은 시각 재수신 생략을 확인했다. 기존 HTML/수신/장기41h 검사도 통과했다. 첫 빌드는 테스트의 Kernel 네임스페이스 오류로 실패했고 이를 수정했다. 원문 본체/기대값을 바꾸어 통과시키지 않았다. 기존 nullable 경고 외 새 경고는 없다.

기존396fixture 항목/헤더/기대값을 모두 유지했고 PORT_MAP에 실제 소비자6쌍을 추가했다. 최종 빌드 대표3시작 모두 종료0·덤프 전체바이트/지표0.776 일치·원본1392파일 불변이다. cpp_sync와 최종 감사가 통과했다. CPP/디컴파일 변경·외부 접속은 없고 실제 포획/희생·특정 적 공격·시나리오 승리는 재현하지 않았다.

근거는 extracted/dotnet-0779/의 test.log(첫 컴파일 실패)·test-final.log/client-final.trx·test-verified.log/client-verified.trx·source-revisions.json·fixture-audit.json·cpp-sync.log·capture-verified.py/.log·capture-summary.json·capture-originals-audit.json·capture-verified/*/dn/*·audit.py/.log·final-audit.json이다. capture.py/.log 및 capture/*는 Identity getter 최종 정리 전의 별도 관측으로 보존했다.

공통 Dispatcher/PacketRegistrationTable·현재 Source/송신 부모는 Root 미설치이므로 전체 송수신 완료로 계산하지 않는다. 실제 수신 소비자는 설치됐으나 공통41h가 이를 부르는 전송 설치·Native HUD 창/Enter/알림 ID 작성·제출/송신·NativeMapView 공급자는 남았다. 다음0.780은 정기 전체 회귀, 이후0.781은 실제 Root 제출/전송 연결이다. 전체 목표는 미완료다.
