# webpj 단독 미션 내부 전송(zacket/LocalMissionTransport) — WB04-E324 (2026-11-12, 4-C)

3.1절 4-C 의 **`zacket/` LocalMissionTransport**(기준선 439줄 = `.cpp` 305 + `.h` 134, 기준선 뒤 +21/−34줄)를 `core/local-mission-transport.js` 로 옮겼다. 단독 미션의 실제 Zone(0x1a)/로그인(0x27) 바이트 작성·읽기, Zone 을 현재 Player9 에 설치하는 004b4be0, 그리고 같은 프로세스 안의 zlocal 두 끝(클라이언트 9 끝·accepted 서버 끝)과 byte 큐를 하나의 패킷 분배기에 잇는 내부 전송이다. 이미 옮긴 `RawPacketDispatch`(E306)·`RawConnectionRegistry`(E308)·`RawTransportPolling`(E310)·`RawPlayerParticipation`·`RawMissionLogin`(E319) 사이를 실제 바이트 왕복으로 묶는 단위이다. 게임·브라우저 실행과 디컴파일은 하지 않았고, cpppj 단위 시험 실행 파일(`netstorm_tests.exe --filter`, 게임 실행 아님)만 돌렸다. 이 모듈은 DOM 을 쓰지 않는다.

## 1. 규칙

- **패킷 작성/읽기:** `makeLocalMissionZone()` 은 512 예약 전체 0xff 에 헤더(버전 1·0x1a), +4 `0x82000004`, +14 client 수 1, 네 정적 이름(`zsimpson`·`jgreer`·`kdemarest`·`tbratton`)의 슬롯 네 개를 모두 쓴 뒤 선언 길이를 첫 슬롯 기준 86 으로 확정한다. `makeGuideMissionZone(handle)` 은 한 슬롯에 handle 만 쓰고 선언 길이 4(관찰 전)를 둔다. `makeLocalMissionLogin(subscriber, handle, fortImage)` 는 FortImage+67 예약에 +8 subscriber DWORD, +12 nameLen BYTE(NUL 포함, BYTE 로 감김), +13 이미지 크기 DWORD, +17 이름, +17+nameLen 이미지를 쓰고 선언 길이를 `17 + nameLen + 크기의 하위 WORD` 로 둔다. `readLocalMissionLogin(packet)` 은 같은 위치를 읽되 이미지·nameLen 의 NUL 범위가 실제 저장소를 넘으면 거부한다. 이름은 "바이트 = 문자 코드" 이진 문자열(0xff 를 넘는 문자는 거부)로 주고받는다(`raw-mission-client-packets.js` 관례).

- **전송 `LocalMissionTransport(players, server, hooks[, registry, registrations])`:** players 는 같은 Player9 원문, server 는 현재 서버 모드(boolean·`{ value }`·함수), hooks 는 분배 장치 다섯 개(+선택 `sent`·`players`)다. 생성 때 0x87 bootstrap 에 비NULL 빈 관찰기·버전 1/정책 0·길이 0x112 를 둔다. `registerLogin(receive)` 는 0x27 버전 1/정책 0 과 실제 로그인 몸체를 등록한다(없으면 `open` 거부). `open(port, connectImmediately=true)` 는 두 노드를 같은 객체 안에서 초기화(클라이언트 sender 9, 주소 20BYTE: [0]=20, [2..3] 포트 big-endian, +16 `0x10d`, 서버 주소 = 클라이언트 주소)하고 요청하면 `connect()` 한다. `connect()` 는 시계 두 번(수신·heartbeat) → flags 0x26 → 존재 → 등록소 토큰 → 9번 칸 등록이며 시계 예외의 앞선 쓰기는 남는다. **서버 끝은 `poll()` 의 `acceptPending()`**(클라이언트가 있을 때만, sender 0·flags 0x24·시계 두 번·첫 빈 pending)에서 생긴다. `assignConnection(pending, owner)` 는 서버 모드·현재 pending 번호·그 칸의 현재 노드가 서버 끝일 때만 등록소 재배치(+buffered: flags 2·서버 누적 비움)를 한다.
- **송신:** 번호 송신은 현재 Registry 노드를 고르고(−31..21 밖은 연결 없음), 클라이언트 끝은 존재·flags 2·미닫힘·반대 끝 생존, 1..8 은 현재 Player9(`hooks.players()` 가 있으면 그것) +0x50 bit 0 관문을 거친다. 원시 작성기(`sendMutable`)만 연결이 선택된 뒤 observer(1) 를 부르고, observer 뒤 노드가 반납/재배치되면 보내지 않는다. 서버 끝이 아직 buffered 가 아니면 완성 프레임을 바로 상대 큐에, 아니면 송신 누적(65531 상한)에 넣고 `sent(node, packet, 선언 길이)` 를 기록한다. 등록소의 가상 송신 장치는 같은 노드로 직접 보낸다(번호 재선택·Player 재검사 없음). `flush()` 는 0..21 순회로 누적을 집합 프레임(첫 BYTE 0xff·kind 4·전체 WORD)으로 확정한다(pending 은 대상 아님).
- **수신:** `poll()` = 닫힌 끝 반납 → accept → pending −1..−31 각 한 번 → 정상 0..21(again 동안 반복). 끝마다 접속 완료 표시(flags 0x20)는 type 1 통지, 반대 끝 상실은 한 번만 type 2 통지로 직접 분배한다(마지막 수신 version BYTE 사용). 프레임은 단일 observer(0)(집합·폐기 검증 제외) 뒤 `dispatchFrame`: 단일은 분배기에, 집합은 내부 패킷마다 now → 버전 정책 → 기록 → observer(0) → receive(깊이 증감) 순서이고 길이 오류는 terminate 뒤 false, 끝에 깊이 0 이고 닫혔으면 등록소 소멸/반납 뒤 false 이다. 종료된 CD 검증 0x7f/0x80 은 송수신하지 않는다(AGENTS 클라이언트 유효성 검사 비활성화, cpppj 와 같음).
- **정리:** `closeAll()` 은 자기 두 끝만 닫힘 표시 후 깊이 0 이면 바로, 아니면 분배가 끝난 뒤 반납한다. `dispose()`(C++ 소멸자)는 장치 호출 없이 등록소의 별칭/등록만 지운다.
