# TAFF 아카이브 (`netstorm.tarc`)

> 분석 상태: **완료** (전체 246개 엔트리 추출·복호화 검증)
> 도구: [`tools/taff.py`](../../tools/taff.py)

## 개요

게임 데이터 일부(오브젝트 정의 `.type`, 일부 미션 스크립트·요새, 번역 테이블 등)를 하나로 묶은 파일이다.
엔트리 데이터는 고정 키 XOR 로 인코딩되어 있다. 모든 정수는 **리틀 엔디언**이다.

## 파일 구조

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0x00 | 10 | 매직 `"TAFF v0.2"` + `0x1A` |
| 0x0A | 2 | 0 (패딩) |
| 0x0C | 4 | 0 (용도 미상) |
| 0x10 | 4 | 2 (용도 미상, 버전 필드 추정) |
| 0x14 | 4 | 엔트리 개수 N (원본: 246) |
| 0x18 | 4 | 2 (용도 미상) |
| 0x1C | 4 | 이름 인덱스 테이블 오프셋 (0x2C) |
| 0x20 | 4 | 디렉터리 오프셋 (0x404) |
| 0x24 | 4 | 디렉터리 크기 (바이트) |
| 0x28 | 4 | 데이터 영역 오프셋 (= 디렉터리 오프셋 + 디렉터리 크기) |
| 0x2C | 4×N | 이름 인덱스 테이블: 각 엔트리 레코드의 디렉터리 기준 오프셋 |
| 디렉터리 | 가변 | 엔트리 레코드 N개 (아래) |
| 데이터 영역 | 가변 | 엔트리 데이터 (XOR 인코딩) |

### 엔트리 레코드

| 크기 | 내용 |
|---|---|
| 4 | 데이터 영역 기준 오프셋 |
| 4 | 크기 (바이트) |
| 가변 | 이름, NUL 종료 ASCII. 형식 `\d\altar.type` (구분자 `\`) |

레코드는 이름순(대소문자 무시)으로 정렬되어 있다. 마지막 엔트리의 끝은 파일 끝과 정확히 일치한다.

## 인코딩

엔트리 데이터 각 바이트를 키 `"mydoghasfleas"` (13바이트) 와 XOR 한다.
키 위치는 **엔트리 시작 기준 0부터** 순환한다.

```
plain[i] = enc[i] ^ KEY[i % 13]
```

키 문자열은 `Netstorm.exe` 안에서 `"TAFF v%d.%d"` 문자열 바로 뒤에 저장되어 있다.
같은 키가 `options.cfg`, `setup.cfg` 에도 쓰인다 ([config.md](config.md)).

## 내용물 (원본 기준)

| 확장자 | 개수 | 내용 |
|---|---|---|
| `.type` | 119 | 오브젝트 정의 스크립트 (텍스트) → [type.md](type.md) |
| `.english` / `.german` / `.french` / `.spanish` / `.portuguese` | 50 / 39 / 2 / 2 / 2 | 미션 스크립트, 도움말, 설정(`config.*`), 번역 테이블(`xlat.*`) → [xlat.md](xlat.md) |
| `.fort` | 32 | 요새/맵 데이터 (바이너리, 느슨한 `d/*.fort` 와 같은 포맷) |

## 파일 탐색 규칙 (추정, 4단계에서 확인 필요)

`d\` 폴더의 느슨한 파일과 아카이브 안의 파일이 같은 가상 경로(`\d\이름`)를 공유한다.
어느 쪽이 우선하는지는 실행 파일 분석으로 확인한다.
