# 파일 조회 순서 (느슨한 파일 + TAFF 아카이브)

> 분석 상태: **정적 분석 완료** (2026-09-28). 동적 검증은 아직 하지 않음
> 근거: `Basefile.cpp`(FUN_0041b4c0 파일 열기, FUN_0041ab10 존재 검사, FUN_0041a240 아카이브 내 이름 검색),
> `Configinterface.cpp`(디컴파일 46,760~46,900행: 데이터 폴더 결정·아카이브 등록)
> 클론 구현: `src/Netstorm.Assets/GameFileSystem.cs`

## 1. 시작 시 준비

1. 설치 폴더로 `chdir` 한 뒤 현재 폴더를 **기본 경로**(VA 0x544d80)로 저장한다.
2. 기본 경로에서 `*.tarc` 를 찾아 **찾은 순서대로 모두** 아카이브 목록(연결 리스트 끝)에 등록한다 (FUN_0041b9d0, 같은 이름은 한 번만).
3. 레지스트리의 CD 경로가 있으면 **보조 경로**(VA 0x544e80)로 저장하고, 그 폴더의 `*.tarc` 도 뒤이어 등록한다.
   CD 경로가 없으면 보조 경로 = 기본 경로.

원본 설치본에는 `netstorm.tarc` 하나뿐이다.

## 2. 파일 열기 순서 (FUN_0041b4c0, 상대 경로일 때)

| 순서 | 위치 | 비고 |
|---|---|---|
| 1 | 기본 경로 + 이름 (디스크) | `fopen` 성공 시 바로 사용 |
| 2 | 아카이브 목록 (등록 순서) | 처음 찾은 아카이브의 엔트리. 아카이브 플래그 bit 1 이 켜져 있으면 `mydoghasfleas` XOR 복호화 |
| 3 | 보조 경로 + 이름 (디스크) | |
| 4 | 아카이브 목록 (다시) | 2와 같음 |
| — | 모두 실패 | `unable to open: %s` 출력 후 예외 |

* **느슨한 파일이 아카이브보다 우선한다.** 따라서 `d/` 에 같은 이름의 파일을 두면 아카이브 내용을 덮어쓸 수 있다
  * ⚠ 패치 이력(`PatchFixs.txt` 10.70 V5.3)은 "치트 방지로 하드디스크 파일보다 tarc 를 먼저 읽도록 바꿈"이라고 적는다. 이 정적 분석과 반대이므로 적용 범위(파일 종류·함수)를 exe 와 동적 분석으로 다시 확인해야 한다 — [sources/README.md](../sources/README.md) 3절 #3
  (현재 원본 설치본에는 `d/` 와 아카이브 양쪽에 있는 파일이 없음 — 2026-09-28 확인).
* 존재 검사 FUN_0041ab10 은 아카이브를 먼저 보고 결과 코드(1=디스크, 2·4=아카이브, 3=보조 디스크, 5=절대 경로)만 다르게 돌려준다.
  실제로 여는 순서는 위 표와 같다.
* 절대 경로이면 먼저 그대로 연다. 쓰기 모드이면 실패 시 바로 예외. 읽기이면 기본 경로 접두어를 떼고 아카이브 → 보조 경로 순서로 다시 찾는다.

## 3. 아카이브 안 이름 비교 (FUN_0041a240)

* `_stricmp` — **대소문자 무시** 완전 일치.
* 요청 이름이 `.\` 로 시작하면 `.` 을 떼고 비교한다 (예: `.\d\xlat.german` → `\d\xlat.german`).
* 아카이브 엔트리 이름은 `\d\altar.type` 처럼 `\` 로 시작한다.
* 설정의 경로 지정값은 `DataDir = "\D"` 를 써서 `\D\tutorial1.english` 같은 이름을 만든다 ([config.md](config.md) "치환 규칙").

## 4. 클론 구현 (`GameFileSystem`)

* 위 우선순위를 그대로 따른다: 데이터 폴더 디스크 → 데이터 폴더의 `*.tarc`(이름순) → 보조 폴더 디스크.
* 경로 정규화: `\` → `/`, 앞의 `./` · `/` 제거, 소문자. 디스크 조회는 경로 조각마다 대소문자 무시(Linux 대비, `GameDataLocator`).
* `Find("d/offical*.english")`: 파일 이름 부분의 `*`·`?` 와일드카드로 디스크와 아카이브를 함께 검색 (원본 `guideSpec = "{DataDir}\offical*.{currentLanguage}"` 용).
* 텍스트는 `OriginalText.Decode` 로 읽는다: UTF-8(BOM 또는 올바른 UTF-8) → 그대로, 그 밖에는 Windows-1252.
  원본 파일은 Windows-1252, 클론에서 새로 만드는 한국어 파일은 UTF-8 이다.
* 검사: `tests/Netstorm.Assets.Tests/TextResourceTests.cs` — 합성 아카이브로 우선순위 확인, 원본에서 공식 미션(아카이브)·팔레트(디스크) 조회 확인.
* 2026-09-28 후속: `GameResources`를 통해 게임 실행 프로젝트의 설정·팔레트·셰이프·타입·맵 조회에 연결했다.
  타입의 느슨한 파일 우선순위와 UTF-8 속성도 검사했다. [실행 자산·설정·언어 연결](../runtime-resources.md)
