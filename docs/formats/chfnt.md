# 비트맵 글꼴 캐시 (`d/!<글꼴>.<스타일>.<크기>.<굵기>.chfnt`)

> 분석 상태(2026-10-05): **머리·네 정수 표·VFX 글리프 확정, cpppj 해독/출력 구현.** [두 판본 함수·글꼴 전수 대조](../exe/cpp-renderer-reconstruction.md). 원본 18개 캐시·4,608글리프를 독립 해독기와 비교했다.

## 용도

게임이 Windows GDI 글꼴(Arial, Courier New)로 글자 256개를 그려 만든 **런타임 캐시**다.
실행 파일(`FUN_004a34a0`)은 `"!%s.<스타일>.%d.%d.chfnt"` 파일을 먼저 읽고, 없거나 읽기에 실패하면 GDI 로 다시 만들어 저장한다.
따라서 원본 자산이라기보다 재생성 가능한 중간 산출물이다.

* 스타일: `normal`, `italic`, `bold`, `underline`, `strikeout`
* 이름의 숫자: 글자 크기(12/13/14/20/48), 굵기(0 또는 700)
* 256자 = Windows-1252 코드 페이지 → **한글 없음**

## 확인된 구조

| 오프셋 | 내용 |
|---|---|
| 0x00 | 매직 `"BitmapFontData"` + `0x1A 0x00` (16바이트) |
| 0x10 | u32 ×5: 버전(1), 높이, 어센트, 디센트, 글자 수(256) |
| 0x24 | i32 ×256: 측정 전진 폭(ABC B+C) |
| 0x424 | i32 ×256: ABC A |
| 0x824 | i32 ×256: 실제 그리기 전진 폭(ABC B+C) |
| 0xC24 | u32 ×256: 글리프별 블록 바이트 수 |
| 0x1024 | 256개의 독립 VFX `1.10` 블록, 각 한 프레임 |

원본 읽기 `004a3240`·쓰기 `004a3090`와 CD `00425980`·`004257f0`에서 확인했다. 메모리 포인터 표는 저장하지 않는다. 공백은 특수 빈 프레임이며 폭은 그대로 진행한다. 저장된 ABC A를 출력 x에 다시 더하지 않는다. 불투명 글리프 색 100을 요청한 글자 색으로 치환한다. 이름의 크기는 포인트가 아니라 CreateFontA의 양수 픽셀 높이다.

## 클론 방침

* 한국어: `fonts/` 의 D2Coding (LEFT_JOBS.md 1.5절)
* cpppj 영어: 원본 캐시를 그대로 해독해 쓴다. 캐시가 없거나 손상됐으면 같은 GDI 글꼴로 메모리에서 생성하며 원본 파일을 쓰지 않는다. OS 차이 때문에 생성 결과의 픽셀 동일성은 보장하지 않는다.
* cpppj 한국어: 실제 원본 게임 플레이 복원 뒤 진행한다. [현재 우선순위](../cpp-playable-plan.md).
