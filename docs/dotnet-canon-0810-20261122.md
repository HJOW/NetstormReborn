# dotnetpj 0.810 — 실제 건물 캡처 분배와 35h 작성 검증

2026-11-22 · HJOW-Athlon · 새 `Netstorm.Game`/`Netstorm.exe` 경로 유지. 전체 목표와 M1은 미완료다.

## 변경과 실제 범위

35h의 파편 선행을 연결하면서, 낙하 대상95/157이 Source의 `IsPlainBuildingCapture`에 속하지만 현행 Game의 기본/추가 그림 분배에서 빠진 것을 확인했다. Source의 다섯 워크샾과 일반 건물 조건을 `RawPlainBuildingCapture`의 **TYPE/VT17쌍**으로 이식하고 Game의 같은 `RawShapeToBuffer`에 연결했다. 실제 TYPE 기본 프레임과 원본 빈+a4를 사용하며, 이름이나 TYPE만 같은 다른 파생을 일반화하지 않는다. 기존 Factory/유닛·소유자 색표·보호 RLE·원본 범위 검사는 그대로 사용한다.

`BattlePacketWriter.WriteDropIslandPacket`은 이미 `Netstorm.Net/RawBattleBroadcast.cs`에 있었다. 새 작성기를 중복 구현하지 않고 기존20BYTE 작성과 실제 원격 전용 방송에 독립 원문 검사를 추가했다. **패킷 작성 검증을35h 수신 완료로 세지 않는다.** 현재 실제 고정 수신은17/26이며35/38/39/3a/3b/3c/73/74/86의9본문과 전체26F/Root가 남았다.

파편 Frame/Lifetime/System은0.809 완료 상태다. 이번 단위는 그 실제 캡처 누락과 작성기 검증을 처리했다. 실제 Host/Game의 파편 설치·현재 시각/카메라/픽셀·감시 쌍의 전체 가상 삭제·35h DropIsland 결선은 다음0.811에서 계속한다.

## 검증

- 실제 Game 생성자와 보호 자산이 조립한 캡처로 **워크샾2,115·섬 조각162·제네레이터180·타워120, 합계2,577입력**의 메타데이터와 전체 픽셀이 일치했다. 세 제네레이터1,844,370픽셀과 두 타워1,317,660픽셀도 각각 전수 일치했다. 입력 기준점만 세션 메모리에서 명시 변경하고 검사 뒤 복원했다. 파편 생성/소진을 함께 확인했다고 확대하지 않는다.
- TYPE129/128이 같은 VT를 공유해도 미지원128은 기존 경계를 유지하고, 틀린 VT/짧은 입력도 새 일반 캡처로 인정하지 않는다. 별도 Source 식 감사는 실제 CPP 조건과 상수에서 판정을 읽어 **256TYPE×172주소=44,032조합**을 비교했으며, 허용17쌍이 같았다. 이 정적 감사는 PE 독립 관측 수와 별도다.
- 기존 작성기의 **독립336입력**은 두 정밀도의 전체20BYTE와 뒤쪽canary4가 일치했다. 모든 부족 용량0..19는 쓰기 전에 거부했다. 같은 실제 방송기가 로컬·NULL·비접속 대상을 제외하고 원격 연결에만35h를 전달했다. 기존 Net 제품 코드는 수정하지 않았다.
- 신규 **Client8건**을 포함해 최종 **Core29·Client69, 합계98건 통과·실패0·미실행0**이다. 기존 연소·건설·업그레이드·현재 캡처·공통 표시/파편 수명·자료 등록을 함께 확인했다. 기존 검사 본체/이름은 수정하지 않았다.
- Release 솔루션 빌드는 오류0·기존 검사 경고6이다. 실제 새 Game의 같은 최종 DLL로 대표3시작(`thewarbegins`·`tutorial1`·`surrounded`)이 모두 종료0이며 전체 덤프/지표는0.808과 같다.0.809의 같은 세 덤프와도 결과가 같다. 검사/실행 DLL이 같고 실행6파일의 전후 해시가 같다.
- 원본 **1,392파일**의 이름/전체 해시가 전후와0.808 전체 장부에 대해 불변이다. Source8파일·기존 Net 작성기·AGENTS.md·README.md 전체도0.809와 같다. 원본 게임 실행이나 포획/희생·특정 적 공격·승리 재현은 수행하지 않았다.

정기 전체 기준은0.808의 **5,744통과·실패0·M1 0/34**이며 다음 전체는0.812다. 이번 집중98건을 전체 회귀 결과로 바꾸어 쓰지 않는다.

## 자료와 인계
