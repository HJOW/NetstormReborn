# dotnetpj 1.089 — 미션 채팅 사건과 임시 HUD 연결

2026-11-27, HJOW-Athlon. 전체 UberRoot 결선 전의 공통 루트에 실제
`HudDock` 사건 라우터를 설치했다. 채팅 열기·닫기와 구분선 이동/크기
사건만 현재 루트에서 도킹 본체로 보내고 기본 사건은 설치 전 공통
처리기로 전달한다. 호스트 종료 때 라우터를 비활성화하며 뒤에 설치한
다른 파생 처리기는 끊지 않는다. 최초 숨김의 지도 갱신은 이제 실제
구분선 방송으로 전달한다.

- 실제 공통 트리·채팅 공장·도킹 본체와 `HostMenuInput.Dispatch`에 문자
  Enter를 공급해 숨김→재열기→숨김, 입력 표시·지도 영역 변경과 라우터
  반납 후 전달 중단을 검증했다. 관련 집중 검사 18/18 통과.
- 대표 세 미션 CPP/DN 실행 각 종료 0, DN 덤프는 0998과 바이트 일치,
  원본 1,392파일 불변. 기존 원본 대비 차이로 비교 도구 종료 1이다.
  `extracted/dotnet-l2-1089-chat-route/`. `cpp_sync.py` 종료 0.
- `thewarbegins` 실제 창의 초기 미니맵 차이는 여전히 1/6,000픽셀이다.
  창에 WM_CHAR Enter를 보내는 자동 시험은 프로세스 종료 0·스냅샷 전후
  변화 0이었다(`extracted/dotnet-chat-1089-live/`). 이후 computer-use로
  실제 창을 활성화하고 Enter를 보냈지만 채팅창은 열리지 않았다.
  별도의 임시 진단 빌드에서는 키 누름·문자 이벤트 어느 쪽도 콘솔에
  관측되지 않았다. 입력 전달이 확인되지 않았으므로 이 관측은 채팅
  동작의 성공이나 제품 입력 결함의 확정이 아니다. 진단 코드는 제거하고
  Game을 다시 빌드했으며 테스트 창 정상 종료·원본 1,392파일 불변을
  확인했다(`extracted/dotnet-chat-1089-diagnostic/`의 원본 감사).

실제 물리 키보드 Enter와 채팅 입력/닫기 확인, 전체 UberRoot 수명 및
미션 전환은 남는다. 자동 창 입력의 포커스·전달 환경을 먼저 확인한다.
미니맵 1픽셀은 1.088의 원본 객체 결손과 연결해 R4 상태 일치에서 해결한다.
