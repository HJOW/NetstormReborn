# WB04-E750 미션 로그인과 게임 수신 등록 왕복

미션 서버의 `27h` 수신이 같은 Session의 `load()` 뒤 Carrier·건설·연구 수신기를 원본 순서로 등록하도록 연결했다. E720~E739에서 Carrier typed 등록이 끝까지 연결되었고 건설·연구 등록도 E717·E718에서 구현되어 있었으므로, 그 뒤에 남아 있던 임시 미연결 예외를 제거했다. 기존 공개 메서드 이름 `registerCarrierCommandPrefix`는 호출자 호환을 위해 유지한다.

근거는 기준선 `225553df`의 `RawCampaignSession.cpp` 4186행 및 4984~5002·5262~5435행이다. 기준선 이후 이 파일의 변경은 없다. Native 수신 분기와 앱 Client 수명은 이 단위에서 연결하지 않았으며 새 원본 fixture나 게임 실행은 없다.

Tutorial 1 실제 세션의 내부 전송으로 월드 설치부터 `27 29 67 2b 2b 2b 28 81 84 2a 32 6e` 수신 순서와 Player 알림·채팅 호출, phase 14·Ready 및 다음 펌프를 확인했다. 테스트의 채팅과 UI 알림은 명시적인 기록용 외부 장치이며 실제 브라우저 UI가 아니다. 관련 집중 검사 96건이 통과했다.

최초 실행에서 기존 검사에 남은 임시 예외 기대가 클라이언트 Player 패킷의 채팅 외부 장치 미연결 오류로 바뀌었다. 검사에서 실제 호출되는 `addChat`·`clearChat`·Player 알림 장치를 기록하도록 공급한 뒤 왕복이 완료됐다. 제품 코드에 빈 성공 장치는 추가하지 않았다.

Node v26.13.0 전체 회귀 6,242건이 통과했고 실패·취소·건너뜀은 0건이다. 대응표 오류는 0건이며 E746의 v22 검사 뒤 다섯 번째 v26 전체 회귀다.

나머지 개발자 명령, 로그인 행 base 뒤 32커밋 판정, Native 분기, 브라우저 앱의 미션 수명·입력·표시 및 실제 플레이 검증은 남아 있다.
