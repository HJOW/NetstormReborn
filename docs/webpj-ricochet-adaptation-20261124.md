# webpj 아이스 반사 변위 0 지역점의 웹 적응 판정 (WB04-E1296, 2026-11-24)

대응표 `CampaignClientServices.cpp` 행이 partial로 남은 마지막 이유였던 "ricochet 값의 비결정성(E1226)"을 웹 적응으로 인정하고 행을 `port`로 올렸다. 코드는 바꾸지 않았다.

## 무엇이 다른가

- 원문(10.78)의 아이스 반사는 변위 0일 때 지역점 8바이트를 **초기화하지 않은 스택 값**에서 읽는다. 값은 실행마다·호출 경로마다 달라 유효한 지역점으로 읽히면 반사가 일어나고 아니면 일어나지 않는다. cpppj는 이를 `CurrentRicochetScratchBytes`로 프로세스 메모리에서 조회하는 임시 장치로 재현한다.
- 웹은 같은 읽기를 공급하지 않으면 "현재 지역점 8BYTE 입력 미연결" 오류로 프레임 루프가 멈췄다. E1226이 앱 서비스가 없을 때 0점(유효 판정 실패 → 반사 없음)을 공급하도록 Session 기본값을 정했다(`raw-campaign-session-combat.js`, `tests/raw-campaign-session-combat.test.mjs`).

## 판정

- 원문 값은 호출 순간의 스택 잔재이므로 **어떤 구현도 원문과 같은 값을 재현할 수 없다**(cpppj의 프로세스 메모리 조회도 같은 호출 경로에서 우연히 같은 값을 읽는 장치일 뿐이다). 따라서 "비결정 입력의 결정적 대체"는 동등성 문제가 아니라 의도된 웹 적응이다.
- 0점 대체가 보수적인 선택인 까닭: 반사가 일어나지 않는 쪽은 원문에서도 항상 가능한 결과이고(스택 값이 무효로 읽히는 경우), 일어나는 쪽은 임의 좌표로 아이스가 튀는 오류 후보라 게임 규칙을 해치지 않는다.
- 이 적응을 쓰는 경로는 변위 0 반사뿐이다. 같은 행의 나머지 메모(E837~E1227의 "앱 연결 잔여")는 후속 단위(E951~E1230 앱 결선, E1263 점검 4D-6b, E1225·E1231 입력 큐 소비 전수)가 모두 닫았다.

대응표는 메모에 이 판정(E1296)을 붙이고 `partial` → `port`로 올렸다. partial 8 → 7행, 남은 줄 수 11,798 → 11,425.
