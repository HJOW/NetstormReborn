# dotnetpj 0.987 — RU-3b 네 공장·바깥 UI 설치(Root·메시지 공장 집합과 미션 진입 결선)

2026-11-25, HJOW-Athlon. R4-6 Root 공장 묶음의 RU-3b 첫 단계다. 실제 게임 Root의 네 공장 가운데 Root(NSInfo 창)와 메시지 공장을 만들고 미션 진입 경로에서 소유한다. 생산 공장은 세션 장치(0.825~0.837·`BuildProductionWorldDevices`), 채팅 공장은 메뉴 경로(`_nativeChatWindows`)로 이미 소유하므로 런타임 장치로 묶는다. 생산 패널 표시는 R5, 메뉴 왕복 정리는 SL-7에서 잇는다.

## 변경과 원문 대응

- `HostRootFactorySet`: 첫 NSInfo 창과 둘째·세째 추가 창, `RawUberMessageProbe`를 같은 주인에 소유한다. `HostNsInfoRootDevices.Build`로 0.986 묶음을 만들고 같은 `RawFileName` 고리를 메시지 공장과 공유한다. `OwnsToken`으로 살아 있는 루트 토큰만 판정해 F6 등 바깥 토큰과 구별하고, `CloseAll`·`Dispose`로 자기 owner 범위에서만 반납한다. 생성 실패는 만든 창을 반납한 뒤 다시 던진다. 0.987에서 추가됐다.
- `ClientGameplayGlobals.StateAuxFC4`: 00594fc4의 별도 현재 DWORD다. 최초 BSS0이며 battle과 fort bool과 합치지 않는다. cpp `ClientGameplayGlobals.h`의 `stateAuxFC4_`를 이식했고 NSInfo 플레이어 입력의 실제 보조 값 주인이 된다. 0.987에서 추가됐다.
- `ClientHostGame.EnsureRootFactories`: 미션 저장소와 같은 메뉴 주인으로 집합을 만든다. 바깥 읽기는 cpp `UberGump.cpp` 2200행의 같은 주소 분기를 따른다(배경 TYPE·프레임, fortGump 블록 = 배경 TYPE − 70, 화면 Basic 색, MetadataMode 실전역, NSInfo 명령 상수). 번역은 같은 xlat 표, 문자열은 같은 사전 저장소, 변경은 메뉴 다시 그리기다. 소유자는 실제 Pool, 기술 합계는 `ClientMetaCoreWeight`, 랭크 그림은 `ChatPrefixIcons`와 icon 자산, 설명은 TYPE·번역·설정 치환, 진단은 로그다. RU-3a 갈래는 실제 마우스·상태 outbox·미션 음향·기본 입력·메타 배치·구독자·보조·87BYTE 기록·팬시 메뉴·정렬 메뉴를 잇고, 참가자 메뉴·중앙 카메라·전투 옵션 4종은 해당 단계(R5·R11)의 명시 오류로 남긴다. 진입 경로에서 호출하지 않으므로 덤프를 바꾸지 않는다. 0.987에서 추가됐다.
- `StartMission`: 진입할 때 집합을 만들고 `HostMissionRuntime` 장치에 생산 Gump·채팅 공장과 함께 넘겨 실제 Root가 소유한다.
- PORT_MAP에 3행을 더했다. `RawMenuControls.cpp`→`HostRootFactorySet.cs`, `ClientMain.cpp`·`UberGump.cpp`→`ClientHostGame.RootFactories.cs`.
