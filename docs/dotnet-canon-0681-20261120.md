# 0.681 실제 건설 진행·완료 장치 연결

- 일시: 2026-11-20, HJOW-Athlon.
- 근거: `RawCampaignSession.cpp`의 `ConnectBuilding`(3752~3768), `RawGameAuxState.h`, 앞 단위의 원본 대조 건설 진행/밀어내기/표시 본체다.
- 상태: 실제 장치 연결과 집중 검증을 완료했다. 전체 목표는 미완료다.

## 연결

진행과 표시는 같은 세션의 Host·Kernel·원본 풀을 사용한다. 현재 ProcessTime, 소유자, 권한, 진단, GameAux의 진행 TYPE·즉시 건설/신전 플래그·밀어내기 마스크를 읽는다. 새 GameAux 상자는 원본의 최초값을 사용하고 일반 월드 준비로 지우지 않는다.

제품 `HostMissionConstruction`은 같은 실제 17번 표시 생성과 30번 진행을 연결한다. 실제 음향 이름 표·47번 소리 프로세스·위치/전역 재생기를 사용하고 `buildDoneSound` 문자열이 없으면 준비 소리는0이다. 화면 갱신은 같은 dirty 큐에 실제 화면 영역을 요청한다. 완료는 실제 최대HP·contained 조회/삭제·Unpop/Repop·현재 관계/지도/탐색기에 따른 유닛 밀어내기로 이어진다. 사제 이동 TYPE와 기존 경로 해제도 실제 사제 월드 장치에서 읽는다.

진행 반납은 같은 세션과 본체의 정체성을 함께 확인해 실제 Form 삭제로 처리하고 표시/팔레트보다 먼저 수행한다. 외부 Kernel 소유자는 보존한다.

새 공장 배치 검사에서 기존 월드 Pop/Unpop의 건물 옆면과 전용 후처리 연결 누락이 드러났다. 같은 실제 옆면 장치를 연결하고, 공장/자산/펜스 후처리가 먼저 또는 나중에 생성돼도 살아 있는 월드 분배기에 같은 본체를 연결한다. 공통 성공이나 가짜 공간 처리를 넣지 않았다.

## 검증

Release 최종 집중 **29/29건 통과·실패0**, 명령 종료0이다(`extracted/dotnet-0681/progress-release.trx`, `extracted/dotnet-0681-release.log`). 신규5건과 기존 사제/연소/건설/플레어21건·지역 소유권3건을 확인했다. 실제 제품과 같은 공장 생성자·SHP·지형 도장·옆면·공간/그래프·전용 후처리·표시/음향 장치를 사용했다.

- 지정8초/기본10초의 17→30→47 부착, 중간 HP, 최대HP 도달, 실제 Unpop/Repop, abstract 해제, 진행/진행음 삭제와 다음 순회의 표시 삭제를 확인했다.
- 시작 뒤 현재 권한과 비영 QuickBuild를 바꾸어 HP·종료 관문이 현재 값을 읽는지 확인했다. 현재 진행 TYPE getter와 1초 이하의 무진행음 분기도 확인했다.
- 진행 종료/반납이 다른 Kernel 객체를 보존하고 같은 Form·표시 등록만 반납하는지 확인했다.
- 실제 사제 이동 TYPE의 경로 Form을 붙인 뒤, 같은 contained 삭제와 공간 해제/재등록으로 사제를 다음 실제 지면 칸에 옮기는 것을 확인했다.

최초 빌드의 검사 using 누락은 수정했다. 첫 실제 배치에서는 건물 옆면 미연결로 신규4건이 실패했고, 옆면 연결 후에는 전용 후처리 미연결로 같은4건이 실패했다. 검사 장면의 지형 바인딩 누락도 고쳤다. `progress-bound.trx`·`progress-final.trx`에서29건 통과 후 중복 초기화 정리까지 반영한 최종 `progress-release.trx`를 확인했다. 최종 검증 뒤 제품 소스는 추가 변경하지 않았다.

새 fixture는 없고 연결337개를 유지한다. 이전 단위의 원본 본체 대조와 실제 제품 장치 연결을 구별한다. 포획/희생·특정 적 공격·승리 재현은 수행하지 않는다.

## 잔여 작업

이 단위의 private 효과 본체는 `Displace`만 소비한다. `DropIsland`의 실제 낙하 표시와 원격 전송은 아직 연결하지 않았고, 선택 시 명시 오류다. 건설 요청/수신·업그레이드 요청/완료·현재 AI 통지·나머지 캡처/전용 색표·R5 월드뷰도 남는다. 다음 정기 전체 회귀는0.684다.

0.682 업그레이드 연결은 `RawCampaignSession.cpp`3186~3191행과 `RawSurfaceDepend.cpp`를 이어서 확인한다. 레벨 쓰기와 프레임 보정은 기존 `SetFortObjectLevel`·`FactoryPostPop.AdjustFrame`이 있다. 감시 쌍은 기존 `RawDependFormHost`를 같은 실제 공장/현재 역할에 연결해야 한다. 자산 watcher를 ProcessForm의 `NotifyDependency`로 처리하지 않는다. C#의 `RawSurfaceStorage.AssetDeletion.cs::NotifyAssetDependency`는 이미 실제 자산 가상 통지를 일부 제공하며, 장기 감시 연결 자체는 후속이다.
