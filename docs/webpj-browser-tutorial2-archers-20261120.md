# Tutorial2 D~G 실제 진행 (WB04-E1083)

한국어 Tutorial2를 실제 Chromium에서 D 안내 뒤까지 이어 진행했다. 생산 격자의 썬 디스크 발사기 항목을 왼쪽 클릭으로 집어(실제 이미지 픽셀 적중) 사제 주변의 합법 자리에 내려놓으면 D가 E(무기 표시)로 넘어가고, 두 번째 발사기를 내려놓으면 F(에너지)가 열린다. F의 두 번째 쪽(F1)을 확인으로 닫고 완성된 신전을 왼쪽 클릭해 선택하면 몇 초 뒤 G(에너지, 세 번째)가 열린다. 생산·건설 SP가 발사기마다 줄어드는 것(3900→3600)과 신전 선택은 기존 입력·생산 경로 그대로 동작했다.

## 발견하고 고친 문제

두 번째 발사기의 항목 클릭이 아무 사건도 만들지 못했다. 첫 발사기가 완성되며 Session이 입력 큐에 올린 발사기 배치 통지(`0x030000b0`, 전역 005429b4의 PE 초기값)가 큐 머리에 남았고, 앱 입력 프레임은 원본 순서를 지키려고 구현되지 않은 명령 앞에서 소비를 멈추기 때문에 뒤의 클릭까지 막혔다. Tutorial 판정용 통지 명령 다섯 개(발사기 배치·포함 `0x030000b0`·`0x030000b1`, 기술 `0x020000b5`, 포획 `0x020000d7`, 상승 `0x020000df`)를 소비 허용 목록(`TUTORIAL_NOTICE_COMMANDS`)에 넣었다. 소비된 사건은 먼저 `tutorial.event`가 받고 해당 단계가 쓰지 않으면 원본 주 루프처럼 버려진다.

F1은 버튼 표가 없는 구간이지만 앱이 기본 확인 버튼을 붙이므로 모달이며, 확인으로 닫아야 게임 시계가 재개되어 신전을 선택할 수 있다.

## 검증

`e2e/korean-mission.spec.js`의 한국어 Tutorial2 흐름(신전·워크샾 자연 완공, 생산 투입, 발사기 두 개 배치, F1 신전 선택)이 G 안내 표시까지 통과한다. 입력 큐 소비 허용을 포함한 미션 진입(`tutorial-menu-start`)과 `campaign-request-frame`·`client-uber-hud` Node 시험 8건이 통과했다.

## 남은 일

G 이후의 발사기 두 개 추가(합법 자리 탐색 범위 확장 필요), H(에너지 소비 안내), H1의 발사기 우클릭 → Salvage(나머지 객체 메뉴), I 완료 버튼(튜토리얼 나가기·Tutorial3 시작)은 아직 확인하지 않았다.
