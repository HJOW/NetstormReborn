# dotnetpj 0.834 — 실제 CRT·등록 TAFF·색표 캐시 파일 연결

작업일2026-11-22, PC HJOW-Athlon. Source 파일 본체/열기 정책을 실제 CRT·현재 등록·사용자 캐시에 연결했다. 실행 경로는 `dotnetpj/src/Netstorm.Game/bin/Release/net10.0/Netstorm.exe`다. 실제 Game의 최초 호출/소유자/F7과 Root 조립은 다음 단계이며 이번 실제 파일 검사를 Client 시작 설치로 확대하지 않는다.

## 변경

- `TaffArchive`가 등록한 실제 절대 SourcePath와 DataOffset/Flags를 보관한다. flags는 등록 때 읽은 DWORD이며 외부 원시 배열이나 현재 디스크 헤더 변경으로 다시 읽지 않는다. 기존 snapshot Read는 유지했다.
- `GameFileSystem.FindArchiveOpen`은 선택한 기본/보조 목록과 등록 순서·첫 중복 엔트리를 사용한다. Source의 ASCII BYTE/구분자·처음./한번 제거 규칙으로 조회하고 내용/현재 파일 존재/경로 고리를 소비하지 않는다. 익명 메모리 아카이브의 실제 파일명이 없으면 선택 지점에서 명시 진단한다.
- `RawBaseFileEnvironment.OpenByPolicy`는 같은 GameFileSystem/FileNameOwner·현재 root/TAFF 메타데이터·가상 게임 CWD/실제 검색 장치를 빌린다. BYTE를 OS 경계에서 엄격히 UTF-8로 바꾸며 잘린 UTF-8은 디스크 실패0으로 남겨 뒤 원시 TAFF 조회를 유지한다. Source의 현재 기본/보조 root·드라이브 상대/루트 디렉터리·UNC 의미를 보존했다. .korean 대체/Probe/ReadOnly/ACP 등 상위 API 전체를 이 정책 환경으로 대신하지 않는다.
- `WindowsBaseFileDevice`는 실제 ucrtbase의 wide fopen/fread/fwrite/fseek/ftell/fclose/feof를 Source 상태/장치에 제공한다. 실제 배열/offset을 pin하므로 짧은 읽기는 같은 목적 접두만 변경한다. Windows long32/size_t·부분 반환 무시·0요청·실제 EOF와 FILE별 별도 키/정리 수명도 유지한다. 새 실행 파일은 추가하지 않았다.
- `ClientColorSortInput.InitializeCache`의 실제 파일 overload가 서로 다른 reader/writer를 scope 소유한다. 현재24BYTE 초기 할당과 공용0 scratch4096, 원문 파일 순서의 같은9표·소유자 초기화와 현재 primary를 공급한다. 정확 파일 열기 예외에서만 재생성하고 실제 FILE/키를 정상/실패 모두 정리한다. Source의 별도 raw24BYTE와 호스트 여섯 필드를 ABI 직렬화로 혼동하지 않는다.

## 검증

실제 Unicode/보충문자 디스크에8201BYTE 쓰기·r+b의 기존 꼬리 보존, 부분 읽기 접두/잔여·long32 위치/길이·EOF와 빈 파일을 확인했다. 실제 TAFF를 등록한 뒤 payload를 변경하면 RawRead는 새 ZBCD를 읽고 기존 snapshot은 ABCD를 유지한다. 이동 뒤에도 metadata는 원래 파일명/위치/flags를 반환하고 실제 Open은 정확 marker로 실패한다. 실제 FILE/키 정리 뒤 keyLength 보존도 확인했다.

첫 중복/선택 목록·등록 flags·익명 출처 거부와 실제 비암호 TAFF의 평문 읽기를 검사했다. 실제 상대 writer의 보조 경로 성공, 직접 장치 실패의 우회 금지, 이미 찾은 TAFF 열기 실패의 보조 파일 우회 금지도 확인했다. 암호 파일의4BYTE 공급/9BYTE 요청은 이전 scratch 잔여까지 처리한 전체9BYTE 기대와 일치한다.

실제 캐시 miss는 독립 고정 입력53비트 관측의 전체9표를 원문 파일 순서로 평문2304BYTE 생성했다. 다음 hit은 현재 빨강을 다르게 공급해도 파일의 표를 읽으며 실제 OwnerTables 준비와 두 FILE 정리를 확인했다.513BYTE 짧은 hit은 접두만 쓰고 미읽은 행0·파일 불변을 유지한다. 부모 폴더 없는 writer 실패도 선행 owner/MapsReady를 남기고 두 FILE을 정리한다. 신규 실제 사례는8건이며 예비8건 모두 통과했다.
