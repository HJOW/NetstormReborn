# dotnetpj 0.829 — 생산 부모·예산·공통 출력과 실제 역할 참조

작업일2026-11-22, PC HJOW-Athlon. Source RawProductionControls의 실제 부모/예산/패널·자식 조립을 같은 공통 트리/문자/자산에 연결하고 내용물 종류의 양방향 참조를 교정했다. 실행 경로는`dotnetpj/src/Netstorm.Game/bin/Release/net10.0/Netstorm.exe` 한 곳이다. 일반 Game Root의 공장 공급과 실제 ClientProductionSync/Session 설치 범위는 계속 남았다.

## 변경

- `ContainedFinderState.ContainedTypeBox` 하나가 Source의 실제 containedType DWORD를 소유한다. `ClientGameplayGlobals.ContentFormTypeBox`가 이를 직접 빌려 검색기→생성기 역할과 반대 방향 쓰기 모두 같은 주소에 반영한다. 기존 독립 SharedContainedType getter의 계약은 보존한다. 실제 순회 중 종류 변경, BYTE와 높은 DWORD 비교, 같은 Box를 유지한 일반 reset을 확인했다.
- `HostProductionWindows`는 Source 부모/예산 파생과 단일 `ProductionMaintenancePanel`을 같은 실제 객체에 보관한다. 초기 Construct는 원문8노드·40폭·화면 높이·도움말/시계 순서다. 별도 Open의80폭/하단80예약·즉시Sync와 구별한다. 예산의 금액별 색/아이콘·점멸·완급/fort 즉시 반영, 현재 높이의 Push/재부착/깊이, 같은 serial 조회/안내와 입력·Idle 분배도 이식했다.
- 이미 완성한 InventoryGump/InventoryItemGump/ImageGump/ProductionHintGump·구분선 기하/입력을 같은 공통 트리와 현재 물리에 조립한다. 실제 정의/SHP는 `HostHtmlText`가 보유한 MarkupGameAssets에서 빌리고 Game 프로젝트의 클래스를 Client가 참조하지 않는다. 실제 current 색표는 OwnerColorTableState 토큰 배열을 그대로 빌리며 독립 UI 문맥만 기존 Source fallback을 사용한다.
- 공통 Text/Style/배경·현재 외부 그림 문맥과 weak 가상 분배/자기 등록 반납을 연결했다. 안내 형제를 먼저 정리한 뒤 현재 등록 순서로 자기 노드를 정리하고 부분 생성/반복 세대도 반납한다. 팝업 정리는 실제 `HostHtmlMenus.RequestClosePopups`→`MenuGumpInput.ClosePopups`와 구조 변경 통지를 사용한다.

실제 Session이 필요한 동기화/dirty·유지 본체 생성·커서 취득/취소·Form과 정보 메뉴는 `HostProductionDevices`의 선택 장치다. 이식한 UI 본체가 미선택 Runtime을 만들거나 빈 성공으로 대신하지 않는다. 일반 Root가 실제 현재 장치를 공급하는 설치와 Source loaded/editorUiInstalling/editorPrefixUiInstalling 범위, 초기 Client 색표/F7 공급, Native GumpForm의 부모 소실 진입점 연결은 후속이다. 이번 클래스 생성만으로 이들 완료를 주장하지 않는다. Source의 자동 입력용 Report/Point 진단도 남았다.

## 검증

양방향 역할 참조와 기존 실제 AI/생산 검사136건이 통과했다. 새 역할 사례는 같은 Box 쓰기/읽기와 실제 RawContainedFinder.Begin/Next 중 현재 종류 변경을 검사한다. 임의 기대값으로 조회 결과를 대신하지 않는다.

생산 부모 새5사례가 모두 통과했다. 640×480/643×480/1024×768의 실제 자산/글꼴·공통 출력으로8노드/원문 기하·도움말8문자열/번역4회·시계1회/생성 중 config0회·Player 미할당을 확인했다. 실제 그림 변화와 화면 밖 행 padding 불변, 기존 UI 보존/소유 문자열 반납도 검사했다. 실제 ClientSpGlobals의 분산 저장소로 예산 완급/fort 반영을 확인했고 Resize는 같은 토큰/serial·동일 높이에서 전체 깊이를 보존한다. 번역 누락의2개 부분 등록과3세대 생성/반납도 확인했다. Runtime 내용물/전투 플레이나 CPP 전체 픽셀 바이트 일치를 대조한 검사는 아니다.

예비 컴파일의 Game 자산 클래스 참조를 실제 공통 자산 어댑터로 교정했다. 첫 부모 검사5건은 구분선 생성 부착에서 미설치 팝업 장치에 도달해 실패했다. 실제 공통 메뉴 입력/팝업 정리를 공급한 두 번째5건은 모두 통과했다. 실제 Runtime 장치 누락을 무동작으로 바꾸지 않았고 CPP 자료/기대 출력은 변경하지 않았다.
