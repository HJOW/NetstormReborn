# dotnetpj 0.841 — 기본 Host 장치 지연 설치와 동일 자원 예약

2026-11-23, HJOW-Athlon. Native Root 조립에 앞서 장기 Process 저장소의 생성 순서를 맞췄다. 전체 Native Root·Load/Editor 공개는 미완료다.

## 변경

- CPP `RawProcessHostStorage.cpp`의 세 최초 등록 API를 새 `RawProcessHostStorage.Defaults.cs`에 이식했다. 수명·공장/깊이·직렬화 함수 슬롯을 Host/독립 Kernel 생성 전에 보관한다. 실제 Host 생성에서는 직렬화→공장→수명 순으로 설치한 뒤 같은 Host를 공개한다. 등록/Host 생성에서 실제 getter나 송신을 실행하지 않는다.
- Native `RawSurfaceStorage.Processes`는 같은 FactoryExecutor/공유 PostPop 깊이 getter를 최초 등록한다. 현재 Runtime이 있으면 기존 실제 Runtime 장치를 우선하는 Host 계약은 유지한다.
- `BindResourceDevices`의 조기 Host 생성·중복 공장 예외 무시를 제거했다. 실제 자원 장치 함수 값만 복사하며, 외부 Client Kernel/Frame을 이후 결합할 수 있다.
- 자원 Regular 구성은 확보한 동일 객체를 `InitializeReserved`한 뒤 실제 Host에 부착한다. 두 번째 객체를 할당하지 않으며 사건·float 비트·count0·부착 뒤 현재 시각을 보존한다.
- 실제 Storage의 기본 수명/전체 Regular 분배·전체 파생 직렬화/송신 부모는 아직 후속이다. 세 등록 API 이식을 해당 전체 연결 완료로 세지 않는다. 전용 VT를 payload/no-op으로 통과시키지 않는다.
- PORT_MAP 이전1640자료행의 값/순서/base를 보존하고 새 Defaults 파일의 CPP/H 대응2쌍을 추가했다. 자료1642(port1154/L1 481/session7), fixture452개다. 이 쌍의 CPP 소스는 이미 대응된 단위이므로 대응626/1240단위·106,131/169,438줄 집계는 그대로다.
