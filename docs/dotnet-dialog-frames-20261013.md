# dotnetpj 초기 브리핑·안내 종료의 프레임 잠금

후속 [튜토리얼 후속 안내·게임 시각 타이머](dotnet-stage-frames-20261013.md)에서 +78/+80의 0.5초/10프레임, +98의 2·4초와 단계 판정의 실제 화면 연결을 추가했다. 이 문서와 근거 해시는 초기/재개 구현 당시 상태이며 새 연결의 동작 대조는 아직 미수행이다.

2026-10-13, 작업/마지막 디컴파일 PC **HJOW-Athlon / 192.168.0.94**. AGENTS.md와 두 LEFT_JOBS를 읽고 cpppj 메뉴 출력/입력 구현을 완료한 뒤 사용자 요청으로 dotnetpj를 진행했다. 앞선 cpppj 변경을 보존했다.

[실제 세션 시계와 정지 소유권](dotnet-session-clock-20261012.md)의 후속으로 **초기 브리핑의 10프레임·안내 종료 후 재개의 7프레임**을 게임 화면에 연결했다. 9-1 A 전체 완료가 아니다. 이번 단계는 정적 분석과 컴파일로 진행했으며 동작/픽셀의 원본 일치를 검증하지 않았다.

## 원본 근거

[안내창 정지 분석](gameplay/dialog-pause.md)을 현재 PC의 정밀 디컴파일과 원본 10.78 기계어로 다시 확인했다. `tools/ghidra/dotnetdialogframes-functions.json`의 **7개** 함수를 읽기 전용으로 내보냈다. 자료는 `extracted/dotnetdialogframes/originals/{creation.c,functions.tsv,assembly.txt}`, 정적 기록은 `tools/analyze_dotnet_dialog_frames.py` / `dotnetpj/recovery-dialog-frames-evidence.json`이다.

| 기능 | 원본 함수/필드 |
| --- | --- |
| 초기 미션 안내 상태 | 004c2990, +84=10, +78=0, +80=0.5f |
| 스크립트 정지 소유 | 004c2a40, +b8 |
| 초기 A. 요청·팝업 닫기·정지 | 004c2a90 |
| 잠금/재개 프레임 판정 | 004c34c0, +84 / +c8 |
| 현재 다이얼로그가 없는지 | 004c8e90, 00565dd4=0 |
| 안내창이 있는지 | 004c79a0, 005cab2c>0 |
| 루트 팝업이 있는지 | 004641d0, 직계 자식 flags 0x4000 |

초기 잠금은 열린 다이얼로그가 있으면 10으로 되돌리고, 없으면 화면 프레임마다 1을 줄인다. 0이 되는 프레임에 A.를 요청한다. 재개는 이 미션이 정지를 소유하고 초기 잠금이 0일 때만 판정하며 **안내창 없음·현재 다이얼로그 없음·루트 팝업 없음**이 7프레임 연속이어야 한다. 차단 조건이 다시 생기면 연속 수를 0으로 되돌린다. 초나 24Hz 규칙 틱으로 이 수를 환산하지 않는다.

원본 ShowTechnology의 00492b60 경로는 controlled 세로 메뉴를 만들고 00475ca0으로 루트에 부착한다. 메뉴의 실제 Attach가 root sticky 0x4000을 세우므로 지식 격자는 재개를 막는 팝업으로 연결했다. 원본 전체 다이얼로그/팝업 트리와 클론의 모든 창 대응은 아직 독립 대조하지 않았다.

## 구현

`MissionDialogFrameGate`는 초기 잠금·정지 소유권·재개 연속 수를 보관한다. `FortMapViewer.Update`의 `finally`에서 **실제 화면 Update당 한 번** 진행하므로 지식창·안내창·컨텍스트 메뉴·외부 창 입력 차단의 조기 반환에서도 프레임 수가 유지된다. 실제 숫자 시계는 기존 `BattleSessionFrameClock` / `OriginalGameClock`을 공유한다.

- 미션 생성 시 A.를 즉시 열지 않는다. 튜토리얼 세션 생성자의 초기 A. 이벤트는 화면 잠금이 열 때까지 보류한다. 10번째 프레임에 기존 OpenBriefing을 호출하고 성공하면 컨텍스트/미션/지식 팝업을 닫는다.
- 이 잠금 동안 월드 시각/규칙은 실행 상태에 따라 진행한다. 다만 초기 안내 전에 튜토리얼 단계가 넘어가지 않도록 `TutorialFrameLocked`를 추가했다. 기존 개발용 RunsTutorial 설정과 독립적이며 헤드리스 기본값은 false다.
- 실제 안내가 열리면 ScriptDialog 소유권을 잡는다. 안내를 닫아도 그 소유권을 유지하고, 7번째 빈 화면 프레임에서만 해제한다. Manual/다른 뷰어의 소유권은 기존 중첩 처리기가 보존한다.
- 외부 도움말/옵션의 **입력 처리 후 현재 상태**를 새 인자로 전달한다. 같은 클릭이 창을 닫고 지도에도 적용되는 것을 막는 기존 inputBlocked 이력을 재개 조건으로 사용하지 않는다.
- 클론 어댑터는 TutorialDialogOpen을 안내, 외부 도움말/옵션·Leave 확인을 다이얼로그, 지식/컨텍스트/미션 메뉴를 팝업으로 보고한다. 지식창과 일반 메뉴가 스스로 새 Pause를 추가하지는 않는다. 이미 스크립트 정지를 소유한 경우 재개를 보류한다.
- 초기 잠금/실제 정지 중에는 명령 및 규칙 틱의 튜토리얼 단계 변경도 보류한다. 이 상태는 세션 검사합에 포함했다. **기존 검사합 숫자는 변경될 수 있다.**
- 기존 자동 진단에 briefing-frames/resume-frames만 추가했다. 사용자 게임 화면에는 이 구현 값을 표시하지 않는다.

현재 표시 상태에서 재개 조건을 판정하므로 원본 Gump 지연 삭제/실제 소멸 시점까지 완전히 같다고 주장하지 않는다. 후속 튜토리얼 단계의 +78/+80(0.5f) 지연과 전체 미션 프레임/AI/단계 타이머는 이번 범위에 포함하지 않았다. 경고 창의 정지 분류도 기존 구조를 유지한다.
