# 1.202 실제 음악 파일 스트리밍 저장소

실제 Winmm `mmioOpenW`·RIFF/fmt/data 탐색·Seek·부분 Read·Close를 제공하는 WindowsMusicFileStore를 추가했다. 재사용하지 않는 DWORD 토큰이 실제 포인터 폭의 HMMIO를 소유하고 실패한 열기는 진행한 헤더/형식 부분 출력과 닫힌 토큰을 남긴다. 읽기 목적지의 미작성 꼬리는 보존하며 전체 음악 표본을 적재하지 않는다. 같은 파일 resolver와 Unicode 실제 경로를 사용한다.

저장소의 재귀 잠금은 파일 위치/토큰 수명을 보호한다. 실패 헤더/보고 예외는 자기 실제 핸들을 닫고, fmt16 보정은 보고 전에 복사한 지역 형식과 DWORD 곱셈 감김을 보존한다. 새 MusicFileHeader/MusicOpenHooks는 채널 Open에 실제 부분 출력을 전달하며 FileHooks는 기존 함수 슬롯을 값 복사한 뒤 파일 장치만 연결한다.

첫 집중은79통과·검사1실패였다(`extracted/dotnet-1200-tests/focus.trx`). 28BYTE로 잘린 입력의 fmt 접두부가 읽힌다고 가정했지만 실제 Winmm은 `fmt.Size`를 선언16에서 잔여8로 줄였다. CPP와 DN은 모두 최소16 관문에서 Read 전에 반환하므로18BYTE 전체 보존이 맞다. 제품 코드는 바꾸지 않고 이 실제 경계를 검사하도록 수정했다. 선언18/실제16 입력도 추가해 정확16BYTE 읽기·bits/cbSize 보정 뒤 data 부재 실패를 확인한다. 직접 Winmm 관측은 `extracted/dotnet-1202-winmm-chunk-probe.json`에 남겼다.

정식 재빌드 뒤 FileStore **7/7 통과**, 전체 집중 **91/91 통과·실패0**다(`extracted/dotnet-1203-tests/focus.trx`). 실제 보호 자료 사본의 음악9개 헤더·앞/중간/끝256BYTE, 짧은 읽기 꼬리·실패/보고 예외·만료 재닫기·Unicode 경로·32개 동시 파일을 검증했다. 음향 장치·worker·게임 창을 열지 않았다. Release 오류0·기존 경고25이며 `extracted/dotnet-1203-build.log`와 같은1.200 출력 폴더를 사용했다.

아직 HostMissionAudio의 실제 음악 소유자나 DirectSound 음악 버퍼에 조립하지 않았다. 다음1.203에서 같은 실제 파일 저장소를 Open/EnsureBuffer와 전체 선택 표본에 연결한다. PORT_MAP에 실제 헤더/파일 원문 대응3행을 등록했고 전체 이식 기준은 유지했다.
