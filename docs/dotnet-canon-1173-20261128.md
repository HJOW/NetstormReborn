# 1.173 고정 프레임과 게임 시각 비교 조건

기존 1-1 관측의 `frame` 행을 IEEE 754 배정밀도로 해석하면, 같은 25ms 고정 실행의 40프레임에서 CPP 게임 시각은 **9.35초**, DN은 **1.00초**다(`extracted/dotnet-terrain-1171-fixed/{cpp,dn}/f40.tsv`). 기존 0.998 수집의 90프레임은 CPP 10.60초, DN 2.25초로 차이는 각각 **8.35초**다. CPP 보고서의 40프레임 벽시각은 10.10초이며 게임 정지 시간도 별도다. 두 관측의 프레임 번호는 스크립트 기준이지 같은 게임 시각을 보장하지 않는다.

경로상 CPP는 시계 초기화 후 `Client::PumpMessages`에서도 고정 시계를 전진시키며, 시작 그림의 `RunTitleBitmaps`는 입력이 없으면 각 3초씩 최대 세 차례 벽시각 대기를 수행한다. DN의 기존 `--mission` 직접 진입은 같은 시작 대기 경로를 밟지 않고 `HostFrameDriver.BeginFrame`에서 고정 시계를 전진시킨다. 이 시작 절차 차이는 관측된 시간 차이를 설명하는 중요한 경로이나, 각 대기·정지 구간이 8.35초를 정확히 어떻게 구성하는지는 별도 계측하지 않았다. 임의 시간 보정을 제품에 적용하지 않았다.

따라서 1.169의 같은 번호 프레임에서의 미니맵 픽셀과 다리 출현 관측, 0.998의 덤프 결과 자체는 유지하되 같은 게임 시각에서의 동등성이나 다리 생성 원인의 증거로 해석하지 않는다. 34경로 재수집 역시 기존 절차의 현행 상태 확인이며, 양쪽 시작과 시각을 정렬한 별도 비교 및 실제 동작 검증이 필요하다. 실제 게임 추가 실행이나 공격·승리 조작은 이 단위에서 수행하지 않았다.
