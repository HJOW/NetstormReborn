# dotnetpj 0.831 — 현재 파일·키·부분 입출력 본체

작업일2026-11-22, PC HJOW-Athlon. 최초 색표 캐시가 요구하는 Source RawBaseFileIO의 전체11개 본체와 현재 상태/장치 경계를 이식했다. 실제 CRT/열기 정책/TAFF와 Client 연결은 계속 남았다. 유일한 실행 경로는 `dotnetpj/src/Netstorm.Game/bin/Release/net10.0/Netstorm.exe`다.

## 변경

- `RawBaseFileState`는 실제 FILE/키 토큰과 flags/base/length/keyLength를 같은 객체에서 공유한다. 호스트 포인터 폭과 원문 DWORD를 구분하고24BYTE ABI를 가장하지 않는다. Construct는 원문의 FILE/키/길이3필드만0으로 만든다.
- Disk Open은 부분 파일 bit0/base/length를 먼저 지우고 rb/r+b/w+b3모드 중 선택한다. mode1 실패에서 create가 있을 때만 w+b를 재시도한다. Subfile Open은 FILE 성공 뒤에만 길이/bit0/base/seek를 설정한다. 실패 또는 잘못된 모드에도 선행 부분 효과를 보존한다.
- SetKey는 이전 키 반납→키0/길이0→현재 첫NUL 길이→실제 할당→현재 입력BYTE/NUL 복사 순서다. 할당/반납 장치가 같은 입력/상태를 변경해도 원문 위치에서 재조회한다. 빈 C문자열과 키 없음은 구분하며 물리 부족/할당 실패를 성공으로 바꾸지 않는다.
- Seek/EOF/Length는 signed32와 DWORD 감김, 부분 파일 전용 끝 기준 부호, strict EOF, tell 뒤 현재 base/length, 현재 FILE의 재조회를 유지한다. Close 정상 반환 뒤에만 부분 플래그/위치/FILE을 지우며 Destruct는 그때 현재 키를 반납하고 keyLength는 남긴다.
- Read/Write는 실제 부분 반환을 재시도 조건으로 쓰지 않는다. 직접 읽기는 목적 접두만 바꾸고 암호 읽기는 요청한4096BYTE 묶음 전체에 이전 scratch 잔여까지 XOR/복사한다. 현재 키/길이는 각 장치 뒤 재조회하며 파일 위치 기반 키DWORD는 묶음 사이 이어간다. 쓰기 입력은 변경하지 않는다. 선택 진단이 복귀하면 원문처럼 현재 상태로 계속하며 미선택 장치는 요구하지 않는다.

이번 API는 FILE/키의 플랫폼 장치를 주입하는 본체다. 실제 사용자 Cache 파일, Source FileSpecQuery/RawFileName.Device/RawBaseFileOpenPolicy의 현재 고리·검색/출처 선택, 등록 TAFF metadata와 현재 디스크 읽기는 후속이다. 기존 GameFileSystem snapshot 전체 읽기를 이 API의 파일 입출력으로 대신하지 않았다. Core→Assets 참조 방향을 유지한 현재 GameFileSystem owner 대여도 실제 연결 단계에서 수행한다.
