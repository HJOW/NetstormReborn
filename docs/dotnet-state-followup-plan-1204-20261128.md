# 1.204 이후 실제 옵션·음악·State 연결

현재1.200~1.203 코드는 커밋됐고 집중91/91이 통과했다.1.205 옵션 교정도 완료해 집중50/50·대표3진입 불변을 확인했으며1.206 Client 전체3,053통과·실패0을 확인했다. 정기1.204는7,543통과·기존 사용자 옵션2실패·하드웨어1미실행이다. Core/Assets는 통과했다. 목표는 계속 진행하며 아래 번호는 이 인계를 작성한 시점의 다음 순서다.

1. **1.205 옵션 덮어읽기 수정.** HostStartupScene.cs·HostUserOptionsRootTests.cs 두 파일의 수정/집중/대표 진입이 완료됐다([근거](dotnet-canon-1205-20261128.md)). 원문 Config first-key/Append를 바꾸지 않고 원래 options.cfg 위치 이후의 유효 사용자 선언 중복만 제거한 뒤 원시 본문을 같은 위치에 넣어 ARGS/user.cfg 우선순위를 보존한다. 설치의 미지정 선언만 보충해 주석/서명 누적을 막는다. 전체 decode 완료 뒤 반영하여 잘못된 UTF-8은 설치값을 보존한다. 저장된 오래된 InstallDir/CDDir보다 현재 설치 경로를 마지막에 적용한다. 명시 설치값·사용자 첫 중복/빈값/escape/치환과 미지정 설치값·재저장·경로 이동 회귀가 필요하다. 1.205a Release·집중50/50·1.206 Client 전체3,053통과가 완료됐다.
2. **1.206 Client 전체 재검증 완료.** 수정된 Client3,053통과·실패0·하드웨어1미실행을 확인했다([근거](dotnet-canon-1206-20261128.md)).1.204 Assets383·Core4121은 바뀌지 않은 코드/자료인 경우 합산 근거로 사용하고 실제 재실행과 구별한다. 첫 실패 TRX/로그를 덮지 않는다.
3. **1.207 음악 Fill/COM 완료.** Release와집중66/66·원문5,088행을확인했다([근거](dotnet-canon-1207-20261128.md)). `extracted/dotnet-1205-draft/`의 MusicChannel.Stream.cs·WindowsSoundDevice.Music.cs·SoundMusicControl.Stream.cs·MusicChannelStreamTests.cs·WindowsMusicBufferDeviceTests.cs 초안5개를 검토 후 제품 경로로 옮긴다. `extracted/dotnet-1206-draft/SoundMusicControl.Runtime.cs` helper도 **같이 먼저** 옮겨 ForPrimary/명시 primary/동일 명령 잠금 의존을 만족한다. 기존 SoundMusicControl에 partial, Game.csproj에 좁은 native Span 용 AllowUnsafeBlocks가 필요하다. musicstream5,088행을 링크/목록 등록하고 실제 DLL/COM ABI·빈 Span 포인터·두 구간 직접 쓰기/예외 Unlock·개별 Release를 검사한다. 합성 COM을 실제 하드웨어 성공으로 세지 않는다.
4. **1.208 음악 Runtime/협조 worker 완료.** Release·집중75/75·원문4,800행과실제worker검사를확인했다([근거](dotnet-canon-1208-20261128.md)). `extracted/dotnet-1206-draft/`의 나머지 MusicRuntime.cs·WindowsMusicRuntime.cs·MusicChannel.Runtime.cs·MusicRuntimeTests.cs를 옮긴다. helper는 앞 단위에서 이미 반영했는지 확인한다. 같은 전역/primary identity·두96BYTE 선택 초기화·500ms worker·실제 Win32 callback 수명·완전 합류를 검사하고 musicruntime4,800행을 링크/목록 등록한다. fixture SHA는73730a938998de015746d41b64c01d32d63f1e99cd5a74406fb9bb51ca9d734b다. 기존 `--verify` 감사는 추출 의존 파일30개 누락으로 실패했으며 존재한11개 의존 SHA 불일치0이다(`fixture-audit.json`). 실제 PE 오라클 재실행 완료로 간주하지 않는다.
5. **1.209 실제 HWND 완료.** 최종 MonoGame 창 생성 뒤 UI 스레드에서 같은 SDL DLL의 생존 포인터로 네이티브 HWND를 조회해 HostMissionAudio에 전달했다. DLL 추가 참조/구조체72BYTE·숨긴 실제 SDL 창·가시성/프로세스 포함 집중17/17, 별도 Explicit 실제 하드웨어1/1과 비음소거 제품 진입이 통과했다. 최종 제품 Main의 정상 Dispose 뒤 메모리 진단을 배출해 서로 다른 SDL/HWND와 실제 장치 초기화 성공을 확인했다. 생성자 진단 예외의 자기 장치 반납도 보강했다. 6. **1.210 정기 실패와 후속.** Assets383·Core4121·Client3073통과 및 로그 검사1실패를 확인했다([첫 결과](dotnet-canon-1210-20261128.md)).1.210a에서 프로세스1회 표준 출력 캡처 검사만 새 자식 프로세스로 격리했고 최종 집중11/11이 통과했다([교정](dotnet-canon-1210a-20261128.md)). 1.211에서 CPP ClientAudio.cpp93~103처럼 장기 device/player→files→2채널→ForPrimary→Runtime→Selection→Scene을 같은 HostMissionAudio에 조립했다([검증](dotnet-canon-1211-20261128.md)). OpenDevice는 실제 Initialize/초기 소리/Runtime.Initialize, 종료는 Runtime 완전 합류→device.Shutdown→files.Dispose 순서를 보존한다. State 미션 반납에서 장기 음악 owner를 닫지 않는다. 기존 다섯 검사 조립은 준비 생성자로 옮겼고 별도 실제 음악 하드웨어1/1도 통과했다.1.212에서 Client 전체로 실패 교정과1.211을 함께 재검증하며, 변경되지 않은1.210 Assets/Core 합산과 실제 재실행을 구분한다. SceneMusic/옵션 UI·State 외부 장치·실제 State3/7/13·UiMode2/3 부모와 GUI 왕복은 그 다음이다.

Fill/Runtime/HWND는1.207~1.209에서, 장기 음향 owner/옵션 본체/로그 어댑터는1.211에서 제품 반영·집중/실제 경계 검증을 마쳤다.1.211은 집중368/368·별도 Explicit 실제 음악1/1·대표3진입 및 실제 Main의 화면/덤프/보호 불변을 확인했다([근거](dotnet-canon-1211-20261128.md)). 정기1.210 실패의 전체 재검증은1.212에서 잇는다. 그 뒤 미검증 SceneMusic 부모는 [실제 후속 A–H](dotnet-scene-followup-plan-1211-20261128.md) 순서다. agent가 만든 초안을 무검증 완료로 세지 않는다. R6 실제 Load9단계·AI Drops/Bridges 및 같은 게임 시각 비교는 [1.199 계획](dotnet-state-followup-plan-1199-20261128.md)의 C를 유지한다. NativeLoaded·픽셀·난수를 강제로 맞추지 않는다.

최초 초기화/옵션 적용/State 옵션 해석의 서로 다른 순서와 SceneMusic 실제 getter·날씨/Thunder 부모는 [1.206 장기 음향 후속](dotnet-audio-owner-followup-1206-20261128.md)을 따른다. CloseDevice에서는 파일 저장소를 유지하고 최종 Dispose에서만 폐기한다.
