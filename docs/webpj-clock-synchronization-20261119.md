# WB04-E821 게임 시계 동기화 보정

기준선 `225553df`의 `GameClock::BindSynchronizationTicks`와 게임 시각 계산을 이식했다. 시계는 Client의 같은 `0055b4ac` DWORD를 매 조회에 읽고 밀리초 원점과 보정을 unsigned 32비트로 감산한다. 벽 시각에는 보정을 적용하지 않으며 정지 중에는 저장된 게임 시각을 유지한다. 기준선 이후 `GameClock.cpp/.h` 변경은 없다.

실제 `ClientLocalStateGlobals`와 `RawClockSynchronization.poll()`의 표본 계산이 같은 상자를 통해 시계에 반영되고 State 정리가 보정을 0으로 되돌리는지 검사했다. 양수·음수 비트·감김·정지/재개도 확인했다. Client/브라우저에는 아직 실제 GameClock 소유자가 없으므로 생성 시 장기 전역 결선은 4D-7에 남는다. 게임 창은 실행하지 않았다.

검증: 집중 검사 30건과 최종 변경 뒤 Node v26.13.0 전체 6,310건 통과(실패·취소·건너뜀 0). 집중 검사에는 원본 시계 fixture 114행과 시간 동기화 Poll의 cpppj 합성 장면 24건이 포함된다. 바인딩의 선행 조회를 수정하면서 실행 중이던 회귀는 중단하고 최종 상태로 다시 실행했다. 대응표 1,160행 오류 0이며 E819 Node v22 전체 검사 뒤 v26 회귀 2/8회다.
