# webpj 일반 프레임 예외 후 계속 진행

- 단위: WB04-E1338, 2026-11-26, HJOW-Athlon.
- 사용자 결정: 일반 예외는 상세 오류를 기록한 뒤 다음 프레임을 진행한다(비동기 질문 명시 답변).

`Netstorm._runFrameSafely()`를 실제 requestAnimationFrame 콜백과 검사 전용 고정 시각 프레임에 연결했다. 원래 Error 객체와 스택을 console에 보존하고 상태·프레임 시각·미션·고정 프레임 번호를 기록한다. 실패한 본문은 재실행하지 않고 다음 표시 기회에서 새 프레임을 처리한다. 예약 핸들은 콜백 시작 때 반납해 본문의 첫 줄에서 실패해도 계속할 수 있다. 정상 경로의 예약과 중복되지 않고 숨김·앱 해제 상태에서는 다시 예약하지 않는다. 고정 시각 모드도 시간과 프레임 수를 앞으로 진행한다.

초기화·자산 적재 실패의 오류 화면과 이벤트 콜백의 기존 예외 전달 정책은 유지한다. 다음 프레임 진행은 실패 중간에 수행된 게임 갱신을 되돌리지 않으므로, 이 동작은 실행 연속성을 위한 사용자 선택이며 트랜잭션 복구가 아니다. 반복 오류도 매번 원래 원인을 기록한다.

검증은 Node 오류·Client 시계 13/13(4.6초), 운영 번들 일치 1/1(49.7초), Chromium 3/3(1.6분)이다. 실제 Tutorial1 진입 후 한 프레임의 본문을 의도적으로 실패시키고 오류 문맥·원인·그 뒤 100ms 이상 실제 프레임 진행과 미션 유지·pageerror 없음까지 확인했다. 기존 고정 시각 두 실행의 화면·덤프 동일성과 cpppj 오라클 대조도 통과했다. 전투 목표는 재현하지 않았다.

첫 Node 검사에서 Node26 localStorage 실험 경고가 비동기 console 수집에 섞인 1건을 발견했다. 런타임 경고가 출력될 기회를 검사 전에 주고 게임 진단만 수집하도록 고쳤다. 제품 예외를 무시하거나 검사를 완화한 것은 아니다.

운영 번들은 3,446,031바이트로 다시 빌드했다(webpack 성공). 로그는 Git 제외 `webpj/extracted/webpj-e1338-{node-final,bundle,e2e,build}.log`다. 전체 회귀 주기는 E1336 뒤 2/4, Node22는 E1332 뒤 6/8이다.
