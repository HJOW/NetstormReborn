## 판정과 수정

CP1386의 `RawProductionControls.cpp` 변경을 DN의 같은 격자 생성·부모 소실·일반 Bind·Idle·종속 삭제와 대조했다. 1.116은 통지 안에서 Form을 먼저 지우고 Object도 0으로 만들었다. 현재 부모 번호가 Player에 남으면 다음 Idle에서 두 격자를 같은 소멸한 부모에 다시 연결한다. CPP의 보완대로 부모 소실에서 `Flags & ~0x40`과 `Form=0`만 쓰고 Object를 보존한다. Form은 통지 복귀 뒤 공통 종속 삭제에 맡긴다. 일반 Bind의 부모0 무동작은 유지한다.

이는 원본 004644e0의 부모0 무동작과 의도적으로 다른 결함 수정이다. 원본 실행으로 잠재 결함을 재현한 것은 아니며, 원본 흐름의 근거는 [CP1386 판정](exe/cpp-production-grid-parent-loss-1386-20261129.md)을 따른다. 새 디컴파일·CPP 수정·원본 게임 실행은 없다.

## 재현과 검증

`NativeProductionGridsReceiveActualParentDeletion`의 실제 Native 장면(TYPE80·152)에 부모 소실 뒤 Idle을 추가했다. 최초 검사는 장면의 모드가 재연결 분기를 선택하지 않아 기대했던 유지 경계에 도달하지 않았다(2실패). 이를 결함 재현으로 세지 않는다. 전투 모드와 Player의 오래된 부모 번호를 명시 입력으로 보완한 뒤, 수정 전 두 경우 모두 연결 호출이 **2→4회**로 늘어 실패했다. 자연 플레이에서 이 오래된 번호가 남는 빈도까지 입증한 것은 아니다.

수정 후에는 두 TYPE 각각 새 부모 교체 유무를 나눠 네 경우를 확인한다. 부모 소실 callback 안에서는 기존 두 Form이 여전히 할당되어 있고, 공통 삭제가 돌아온 뒤 반납되어야 한다. 옛 부모를 유지한 Idle은 새 연결을 만들지 않으며, 새로 살아 있는 부모를 선택한 Idle은 두 격자를 정상 연결해야 한다. 실제 FIFO 풀에서 옛 Form 번호를 다른 할당에 재사용한 뒤 패널을 닫아도 그 슬롯의 타입과 할당이 보존되어야 한다.

Idle의 내용물 갱신은 검사 입력으로 false를 제공하고, 부모 비교 뒤 Maintenance 입구에서 명시 예외를 내 관측을 끝낸다. 제품의 완전 적재·생산 유지 관문을 열거나 빈 성공으로 대체하지 않는다. Game의 생산 루트 Idle을 다시 켠 작업도 아니다.
