# webpj 허용 미션의 실제 아군 AI 검사 절차

**현행 범위(2026-11-29 사용자 goal):** 캠페인1-1~1-5·스커미시만 실제 아군 AI로 포획/희생·특정 적 공격·승리를 검사한다. 1-6/튜토리얼/후반 해당 목표 검사는 생략하며 단순 진입·대기·생산·건설은 허용한다. E1494의 [범위](webpj-autoplay-scope-20261129.md), E1495의 [사제 보호 전략/메뉴 대기](webpj-ally-ai-conditions-20261129.md)를 따른다. 아래E1349 검증수와 옛 확장 기록은 당시 결과다.

- 단위: WB04-E1349, 2026-11-26, HJOW-Athlon.
- 대상: 캠페인1-1~1-5와 Skirmish. Tutorial·나머지 캠페인은 helper가 페이지 접근 전에 거부한다.

사용자 지시의 아군 AI 방식을 위해 `e2e/ally-ai-test-control.js`를 마련했다. `debug.html`의 ES 모듈 앱에서 미션 진입 전에 `installAllyAi(page, mission)`을 호출하면, 원래 MissionStart가 끝난 직후 같은 Session의 실제 AI 생성기를 호출한다. 현재 살아 있는 로컬 사제와 비어 있는 brain을 요구하고 중복 설치를 거부한다. 아군은 어려움·적은 쉬움으로 조회하며 C++ 테스트 옵션과 같은 조건이다. 시작 자금 덮기 옵션은 쓰지 않는다.

600바이트 설정은 실제 미션 AI 전역으로 초기화한 뒤 C++ `PrepareLocalTestAiSettings`와 같이 현재 이름·현재 SP·동맹을 보존하고 추가 기술 목록을 비운다. 동맹 필드는 공유 상수 `AI_SETTINGS_ALLY_MASK_OFFSET`를 사용한다. 생성 전후 실제 Player 이름·동맹·지갑·기술 목록과 생성된 brain을 별도로 읽어 확인한다. 그 뒤 발생하는 자원 채취·지출·건설·공격은 원래 AI와 Kernel이 수행한다. HP·게임 단계·승패·플레이어 활성 플래그를 직접 바꾸지 않는다.

실행: `cd webpj` 후 `npx playwright test e2e/ally-ai-test-control.spec.js --workers=1`. 첫 검사는 허용 목록 밖 이름의 거부를, 둘째 검사는 캠페인1-1의 실제 브리핑 단추와6000프레임 자연 진행을 확인한다. 고정 시각의100프레임 묶음 호출은 각 프레임의 Kernel·Renderer를 모두 실행한다.

Chromium2/2 통과(2.9분). 허용 밖 미션5개는 페이지에 접근하지 않고 거부했다. 캠페인1-1에서는 실제 brain 생성, 이름·자금3000·동맹·기술의 생성 전후 동일성을 확인하고6000프레임 동안 자연 생산·다리 건설·사제 생존과 오류0을 확인했다. 두 JS 파일의 Node 문법 검사와 자료 추적 목록3/3(8.6초)도 통과했다. 초기 기술 목록 관측이 원문 진단 대상 TYPE0을 조회한 것을1 이상 유효 범위로 바로잡았다. 게임 제품 코드는 변경하지 않았다.

이 단위는 아군 AI 검사 기반을 닫으며 포획·희생·승리 재현은 후속 미션 단위에서 별도로 기록한다. 기존 제품의 `CampaignTestPlay` 제외 분류와 `effects.testPlay` 거부는 유지된다. 검사 helper가 진단 페이지의 실제 생성기를 사용하므로 해당 제품 모듈을 추가할 필요가 없다.
