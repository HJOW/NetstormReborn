# 1.205 사용자 옵션 덮어읽기와 저장 왕복 교정

1.204에서 드러난 기존 사용자 옵션 결함을 HostStartupScene에서 수정했다. Core Config의 첫 키 우선·Append·치환·SaveText는 바꾸지 않았다. 명령행과 앞선 user.cfg는 원래 우선순위를 유지하며, 유효 사용자 루트 옵션은 원래 `[options.cfg]` 위치에서 설치 옵션/뒤의 기본값보다 먼저 읽힌다.

사용자 파일은 원문 XOR→첫NUL→서명/명시 UTF-8 BOM 순서로 먼저 전부 해석한다. 손상된 명시 UTF-8은 어떤 키도 부분 적용하지 않는다. 임시 Config에서 원문 GetRaw가 인식하는 선언 키만 찾고, 원래 옵션 위치 이후의 해당 중복만 제거한 임시 suffix를 만든다. 원시 사용자 본문과 앞선 ARGS/user.cfg·나머지 dev/setup/END를 한 번의 Assign으로 결합한다. 빈값·첫 사용자 중복·백틱 escape·치환 원문을 새 값으로 직렬화하지 않는다.

설치 옵션의 미지정 키는 원시 선언 줄로만 보충해 재개 때 설치 주석/빈줄/서명이 저장물에 계속 누적되지 않게 했다. 사용자 본문의 주석/서명/순서는 보존한다. 저장된 오래된 END의 InstallDir/CDDir는 현재 실제 설치 루트를 마지막에 기록해 대체한다. 실제 설치/보호 원본 파일을 고치지 않는다. CPP ClientMain의 CLI 앞·옵션 파일 위치 계약을 따르며, 기존 DN의 부분 사용자 파일에 없는 설치값 유지 정책도 보존했다. 새 전체 CPP 기준을 올린 작업은 아니다.

자체 임시 설치 사본에서 설치 키 누락/명시3·설치 중복, 사용자5 저장/재개·두 번째 저장 길이/세 번째 저장 전체 바이트, CLI/user.cfg 우선1, raw 중복/빈값/escape/치환/한글/서명 첫줄, 오래된 경로, 잘못된 UTF-8의 무적용, NUL 뒤 손상 무시를 검사했다. 신규12건을 포함한 사용자 옵션16·읽기 전용 설치2·파일3·시작 장면26·색표3, 집중 **50/50 통과·실패0**다. `extracted/dotnet-1205-tests/options.trx`와 로그를 남겼다.

첫 빌드는 BOM collection literal의 int 추론으로 CS1929 한 건이 실패했다(`extracted/dotnet-1205-build.log`). 명시 byte 배열로 교정한1.205a는 **오류0·기존 경고19(증분 빌드)**, 54.89초·종료0이다(`extracted/dotnet-1205a-build.log`). 출력은 `extracted/dotnet-1200-artifacts/`다. 팀 실제 소스는 빌드 전에 동결했고 다음 음악 초안은 제품에 넣지 않았다.

thewarbegins·tutorial1·surrounded를 격리 사용자 루트에서120프레임 진입/대기해 세 종료0·기존90프레임 덤프 불변을 확인했다.1-1의30/40/45/50/60/70 여섯 화면은1.189와 같고 보호 원본1,392파일도 불변이다. 실행 인자·고정25ms/시각1760000000·옵션·스크립트·실행파일/관리 DLL SHA는 `extracted/dotnet-ui-options-1205/run.json`·`run.py`에 있다. 전체 State 왕복이나 자연 플레이/동일 게임 시각 대조 완료가 아니다.

수정된 Client 전체 재검증은1.206으로 별도 실행한다.1.204의 첫 전체 실패와 Assets/Core 통과 결과를 보존하며, 같은 Data override를 사용해 실패를 숨기지 않는다.
