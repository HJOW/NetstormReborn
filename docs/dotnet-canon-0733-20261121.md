# 0.733 실제 Runtime의 State 반납과 Surface 대여

ClientStateRuntimeRetirement와 HostSession.StateRuntime을 추가했다. 같은 실제 Client/Session/Player 고정뷰·Kernel·Surface 세대를 각 호출에서 확인하고 AI owner1~8, Player 링크, 단일 Kernel.Clear의 실제 정상 복귀 증빙을 소비한다. known0/Core0 뒤 Pool 앞에서만 실제 owner 반납을 요구한다. 빈 callback은 실제 Gameplay/Surface/Player 대여가 남아 있으면 실패한다. owner 반납 실패 뒤에는 소비한 Process 증빙을 되풀이하지 않고 동일 owner 반납만 재시도한다. 첫 메뉴도 실제 Player 기록·장기 Deck 메모리와 Kernel을 사용하며 비영 brain의 소멸 장치 부재와 잘못된 Deck 토큰을 명시 거부한다.

HostSession의 실제 장기 ProcessHost 대여에 ClearProcessesForState/ReturnProcessBindingsForState를 연결했다. 정상 반환 뒤 Regular 잔류를 종료용 Drain으로 다시 지우지 않는다. 이전 Regular 처리기 복원은 현재 대여가 살아 있는 일반 종료에서만 수행하며, Native 반납 뒤의 Depend Form 슬롯은 뒤따르는 실제 Pool 초기화가 반납한다. 건설/연소/사제/생산 등 현재 모듈과 Player 고정뷰는 실제 외곽 수명 반납 전에 놓는다. 원본 전역·Player base·현재 옵션을 반납 과정에서 재초기화하지 않는다.

HostMissionRuntime은 Gameplay와 함께 실제 Surface 준비 대여도 보유한다. 제품 StartMission은 Session 생성 전 대여를 확보하고 완성 뒤 CreatePrepared로 같은 대여/세대를 인계한다. 적재·공개 실패에서는 caller가 자식 정리를 마친 뒤 자기 대여를 반납한다. Host 종료도 Session 자식→Runtime Gameplay/Surface→외부 표시/소리 장치 순서로 바꿨다. 준비 대여는 Pool/장부/모드/난수를 초기화하지 않는다. Uses는 살아 있는 같은 대여의 인계 정체성만 검사하는 관리 코드 보조 API다.
