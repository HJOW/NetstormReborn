# dotnetpj 1.043 — WP-5c Edit 목록 스크롤 소비 결선

2026-11-26, HJOW-Athlon. WP-5의 세 번째 조각이다. 목록 표시(TellMapMenus, 0.363)와 50칸 캐시 확장·무제한
개수(0.363·0.386)는 있었지만 이동 행 소비가 메뉴 소유자(R7) 잔여로 남아 있었다. 이번에 입력 분배
(FortSelection.Dispatch의 ScrollMapList 명령)와 실제 선택기 결선(HostEditorSelection)을 이어
50행 창 스크롤이 같은 캐시 재사용·재표시까지 동작함을 확인했다.

## 변경과 원문 대응

- `dotnetpj/src/Netstorm.Client/Mission/FortSelection.cs`: `FortSelectionHooks.ScrollMapList`를 추가하고
  `Dispatch`에 `ScrollMapList(0x02000134)` 분기를 두었다. 이동 행의 10진 인자를 목록 창에 더한다.
  숫자가 아니면 소비하지 않고, 효과 미연결은 명시 실패한다. 1.043에서 추가했다.
- `dotnetpj/src/Netstorm.Client/Host/HostEditorSelection.cs`: `Dispatch`에 `ScrollMapList`를 실제 목록
  상태에 연결했다. 창 첫 번호를 0 아래로 내리지 않고, `KeepCache`를 세운 뒤 `LoadEditable`로 다시
  표시한다(표시 때 창 범위로 맞춘다). 1.043에서 추가했다.
- `dotnetpj/src/Netstorm.Client/Gump/TellMapMenus.cs`: 이동 행 소비 위치 주석을 현행 결선에 맞게
  고쳤다(R7 잔여 → FortSelection.Dispatch 소비). 1.043에서 수정했다.
- `dotnetpj/tests/Netstorm.Client.Tests/FortScrollRootTests.cs`: 신규 5건. ±50 전달, 비숫자·떼기 거부,
  미연결 명시 실패, 실제 선택기의 창 이동·캐시 유지·재표시·하한 고정을 대조한다. 1.043에서 추가됐다.
