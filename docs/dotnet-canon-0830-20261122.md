# dotnetpj 0.830 — 최초 고정 ColorSort와 캐시 부모·화면 값 복사

작업일2026-11-22, PC HJOW-Athlon. 실제 생산 공장에 앞선 최초 ColorSort 입력/저장소와 캐시 부모를 이식했다. 유일한 실행 경로는 `dotnetpj/src/Netstorm.Game/bin/Release/net10.0/Netstorm.exe`다. OS 파일/VFS 장치와 실제 Client 시작/F7 호출은 다음 단위이며 이번 모듈 검사로 설치 완료를 주장하지 않는다.

## 변경

- `RawColorMapCache`의 준비/정상 읽기/정확 typed catch/재생성/정리 본체 전체를 이식했다. Path→현재 primary 한 번→8행의 고정색/항등/14DWORD 복사/저장 명도 비교→실제 소유자 초기화 순서를 보존한다. 비교는 원문 double 0.800000011920929보다 클 때뿐이며 NaN/동률은 치환하지 않는다. 물리 부족은 앞선 첫 solid/identity 저장 뒤에만 거부한다.
- reader의 끝8BYTE만0으로 만들고 raw reader/writer의 나머지를 임의 초기화하지 않는다. 실제9개 출력은 부분 read의 접두 효과를 그대로 남기고 반환 길이로 재시도/재생성을 선택하지 않는다. 정확 `ColorCacheUnableToOpenException`만 별도 재생성으로 이동하고 다른 오류를 전파한다. 정상/예외의 같은 파일 정리와 writer의 독립 실패 범위도 보존했다.
- `ClientColorSortInput`은 같은 최초 RGBX256/정상 생성한 raw primary/9표/두2048BYTE 소유자 표/OwnerColorTableState를 소유한다. 명시 Capture 이외의 팔레트/화면 변경은 입력을 다시 캡처하지 않는다. 실제 할당 입력을 받는 CaptureWithPrimary와 명시 초기 바이트 입력을 구별하고 정상 Construct 뒤에만 primary를 발행한다. OwnerTables와 Logical/각 map의 배열 정체성은 명시 재캡처/재계산에서도 유지한다.
- Rebuild는 기존 Sprite/Preview 본체에 미노출 RGB1.6/저장 명도/항등 표를 합성한다. RGB 최소값은 float로 좁히고 명도 최소값은 double이며 후보 순서/엄격 비교/예약 번호 덮어쓰기를 보존했다. InitializeCache는 같은 출력 배열을 원문 파일 순서 `[2,7,6,4,3,5,1,0,8]`로 제공한다. 재생성이 성공하면 후속 쓰기 실패에서도 MapsReady=true가 남는다.
- Screen의 고정 Logical/현재 Maps getter를 이식했다. LoadPalette의 기본 Colors는 현재 화면 RGB를 계속 쓰며 명암만 현재 Maps→고정 Logical→독립 현재 RGB 순서다. Source의 GumpShadeMaps 두 std::array 값 대입처럼 현재 표를 같은 화면 내부 두256BYTE에 복사한다. 외부 표와 별칭으로 묶지 않으며 Bind/LoadPalette/매 ShadeMaps 조회 뒤에도 화면 내부 배열 정체성은 유지한다.

`ClientColorMapFile.cpp`의 부모 조립/같은 출력 연결은 이식했으나 실제 CRT/VFS Open/Read/Write 장치는 아직 없다. 기존 GameFileSystem의 전체 읽기를 부분 FILE 입출력으로 가장하지 않았다. RawBaseFileIO/RawBaseFileOpenPolicy/FileSpecQuery의 파일/키/현재 디스크·등록 TAFF metadata 수명을 이식한 뒤 actual Game 시작에서 먼저 팔레트 캡처→캐시 초기화→Screen 재연결을 공급한다. `!color.dat`라는 이름 자체는 암호 판정이 아니며 archive encrypted에서만 실제13BYTE 키 mydoghasfleas와 NUL을 설치한다.

## 검증

원문 캐시 부모/catch/cleanup의 독립130관측에서 전체 소유자 표4096BYTE·9표2304BYTE·reader/writer48BYTE·쓰인 접두·현재 primary/ownerDWORD·typed 분배/cleanup·모든 호출 순서를 비교했다. 현재 source/owner/path 변경, 짧은 read/write, 선택 장치 중단/다른 오류/정확 marker와 cleanup 예외를 포함한다. cache hit의 미선택 장치와 빈 raw source의 선행 부분 효과도 검사했다.

고정 입력 독립6관측의 전체9표를 비교했다. 기본53비트3행은 전체가 일치하며 확장64비트3행은 원문에서 별도로 관측한 명도 표 차이를 유지하고 나머지8표는 일치한다. 64비트 명도 결과를53비트 성공으로 합산하지 않았다. 명시 재캡처/실패 primary 발행 거부, 두 화면 크기/현재 팔레트 변경/같은 padding·primary·고정 RGB, 원문 파일 순서/짧은 읽기/재생성·선택 쓰기 실패도 확인했다. 신규 실제 사례는10건이다.

첫 신규 검사는6통과/2실패였으며 실패 원인은 검사에서 지원하지 않는768BYTE 팔레트를 만든 것이었다. 지원 BGRX1024BYTE로 바로잡은10건은 모두 통과했다. 첫 전체 집중670건/대표3시작도 통과한 뒤 Source PaletteShade.h의 값 복사를 추가 확인해 Screen의 별칭 연결을 같은 내부 배열 복사로 보정했다. 최종 보정본에서도 **Core65·Client605, 합계670통과/실패0**이며0.829 집중의 모든 이름을 보존했다. 전체0.828 대비 신규16건은0.829의6건과 이번10건이다. NETSTORM_DATA 없이 Release 오류0·기존 경고6다.
