# 데모 360초 재시작과 데모 장시간 진행 확인 (WB04-E1125)

데모 미션은 시작할 때 `demoRestartTimer = 360`(초)으로 종료 기한(현재 게임 시각 + 360)을 정하고, 프레임 게이트가 기한이 지나면 `endDemo` 로 `MissionReload` 명령을 입력 큐에 예약해 같은 데모를 처음부터 다시 시작한다(원본 `UberGump.cpp:1156` 의 `endDemo` = 일반 큐 예약, 프레임 콜백 안에서 월드를 해제하지 않음). 웹은 이 흐름을 E1085(Restart Mission)와 `raw-mission-frame-gate.js` 로 이미 갖췄지만 실제 재시작은 확인한 적이 없었다.

## 확인한 것

- **장시간 진행(조사).** Demo 목록의 세 데모(DemoStormRages·GuardMyBack·DissolvedAlliance)를 각각 420초 진행했다. 세 데모 모두 360초 부근에서 월드가 새로 만들어져 `[Demo]` 안내 창이 다시 뜨고(DemoStormRages 는 안내가 약 15초 뒤 자동으로 닫힘) 그 뒤로 계속 진행했으며 페이지 오류는 0 이었다.
- **새 시험.** `e2e/demo-start.spec.js` 에 `데모 종료 기한이 지나면 같은 데모를 새 월드로 다시 시작한다` 를 더했다. 데모를 시작하면 종료 기한이 시작 시각 + 360초(300~360초 범위)이고, 기한을 1초 뒤로 앞당기면 **다른 월드 객체**로 같은 데모(`DemoStormRages`, 데모 표시 1)가 다시 시작되며 기한이 새로 잡히고 오류가 없음을 확인한다(데모 시험 6건 통과).

## 남은 경계

- 재시작 뒤 게임 시계(`gameSeconds`)는 0 으로 돌아가지 않고 이어진다(앱 전체 시계). 종료 기한은 재시작 시각 기준으로 새로 잡히므로 반복에는 영향이 없다. 원본의 미션 시계 초기화 규칙은 별도 확인이 필요하다.
- Auto-Demo(메인 메뉴 무활동 뒤 자동 시작)는 E1092의 시험으로 이미 확인했다. 사람이 입력할 때 데모가 끝나는 흐름은 같은 시험의 앞부분(Demo 목록 시작·Leave)으로 확인했다.
