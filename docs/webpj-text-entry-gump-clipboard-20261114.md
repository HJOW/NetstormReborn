# webpj 문자 편집 Gump·clipboard·편집 문맥 TextEntryGump/TextClipboard/RawTextEntryContext (WB04-E439, 2026-11-14)

RawMenuControls 선행 **TextEntryGump 425줄·TextClipboard 100줄·RawTextEntryContext 13줄(기준선 `1f00a25a`의 .cpp/.h 줄 수, todo→port, 합계 538줄)**을 새 모듈 [`www/ui/text-entry-gump.js`](../webpj/www/ui/text-entry-gump.js)·[`www/ui/text-clipboard.js`](../webpj/www/ui/text-clipboard.js)로 이식했다(RawTextEntryContext는 구조체만 있는 헤더라 `createRawTextEntryContext`). 기준선 전체 소스를 읽었다. **전용 PE fixture는 없다.** cpppj에도 직접 시험이 없고 아래 검사는 기준선 소스 계약·손 계산 값·실제 `TextEntryStorage`/`TextEntryBuffer` 위의 동작으로 한 것이며 원본 직접 관측 수치가 아니다.

## 기준선 뒤 변경 (3.6절)

- **TextEntryGump·TextClipboard**: cpppj `1d5b1f437`(6차 한국어 K1)이 확장 표시 토큰(한글) 처리를 더했다. TextEntryGump는 문자 경계 이동/삭제(`PreviousDisplayText`/`NextDisplayText`)·확정 입력(`IsCommittedTextInput`/`CommittedTextBytes`)·열 스크롤 경계 보정·Console 단어 시작 보정·줄 그리기 선택 보정을, TextClipboard는 `CF_UNICODETEXT` 읽기/쓰기(`readUnicode`/`writeUnicode`, `Win32DisplayTextClipboardDevices`)와 `DisplayText` 변환을 더했다. 웹은 문자열을 UTF-16으로 다루는 자체 한국어 경로를 쓰므로(3.6절 K1 행, 순서 10) **이 분기들은 이식하지 않고 기준선 동작만 옮겼다.** 판정 기록으로 두 PORT_MAP 행의 base를 `1d5b1f43`으로 올렸다(둘은 E438에서 3.6절 K1 행 영향 목록에 이미 올렸다). RawTextEntryContext는 변경이 없다.

## 구현

- **`TextEntryGump`(원문 Editgump VT `00508e10`, Console VT `00506a6c`)**: `construct`는 배경 생성 → 노드 필드(종류 BYTE 15, 점멸 시각 `now()+0.5`, 크기 float32 `width×scale`, `textContext = [0, 글꼴, 색, 0,0,0,1,1]`, 플래그 `|0x400400`) → 실제 0x28 버퍼 확보·구성(실패하면 `assertion(0x31)`) → `idle(true)` → 초기 본문 Reset/Redraw → 세로(10×100)/가로(100×10) Slider 생성·숨김·우하단 기준 부착 → `setScroll(0,0)` → 초기 본문이 있으면 전체 선택(`shiftEnd`=길이) 순서다. `constructConsole`은 기본 생성 뒤 종류 10·autocomplete/제출/단어 0·단어 재설정 1·수신 대상 강조 1이다. `attach`는 공통 부착 → 두 Slider Push → 크기 복사·표시 비트 → 재부착 → 현재 스크롤 재적용이다. `setScroll`은 줄을 `0..줄 수-1`로 clamp한 **뒤** 열을 **쓰기 전의 현재 scrollLine** 줄 길이로 clamp하고, 새 줄/열을 쓴 다음 두 `_ftol`(높이/M 높이, 너비/M 폭)로 줄/열 page를 구해 가로 Slider(현재 줄 길이-1 범위/page/위치) → 세로 Slider(줄 수-1) 순으로 주고 두 Slider의 현재 position을 되읽어 저장한 뒤 Redraw한다(`relativeScroll`은 signed 감김 덧셈). `idle`은 dead/읽기 전용이면 무효과이고 시각이 점멸 시각 이상일 때 위상+1·Redraw·(두 번째 시각+0.5)다. `setText`/`appendText`/`copyText`/`setExcluded`(이전 소유 먼저 반납·LF 제거)/`setHorizontal`/`destruct`(소유 버퍼만 Destroy→반납)가 나머지 공개 경로다.
- **`handle`(원문 004528e0)**: 뗌/명령 비트/코드 0x10000·0x20000/읽기 전용이면 입력 블록을 건너뛴다. 일반 문자는 선택을 교체해 넣고(`maxLength`가 양수면 현재 length+1이 **엄격히 작을 때만**, 선택 길이는 빼지 않음·못 넣어도 반환 1), 제외문자는 입력하지 않고 반환 0이다. Left/Right/Home/End는 shift가 없으면 한 칸/끝으로, 있으면 첫 키에서만 기준을 잡아 선택을 늘리며(End는 원문처럼 +dc 기준 열 delta), Backspace/Delete는 선택 또는 한 글자, Ctrl+Backspace는 전체 Reset, Insert는 Ctrl 복사/Shift 붙여넣기(제외문자 거름), Shift+Delete는 Cut, Enter는 multiline이면 LF 삽입 뒤 Enter 사건을 `node.serial`로 올리며(전달 값 10), Tab/ESC/위/아래는 반환 0이다. 처리 뒤 변경 통지 → Redraw → 입력 전달 순이고, 슬라이더 변경/단계 사건은 별도 분기(모르는 serial은 `assertion(0x246)`, 단계는 가로 Slider 1~4만 ±M 폭)다.
- **`handleConsole`(원문 0043f8a0)**: Tab은 선택이 없고 autocomplete가 있을 때 새 단어(공백/탭/콜론 바로 뒤까지 거슬러 찾은 문자열)나 반복 Tab의 null을 `complete`에 보내 결과로 단어를 교체한다. Enter는 `submit` 토큰이 있으면 현재 본문을 제출한 뒤, Shift 키(0x100000)를 뺀 모든 입력은 단어 재설정을 켜고 기본 `handle`에 위임한다.
- **`draw`(원문 00451f00)**: 배경을 그린 뒤 M 높이로 표시 줄 수를 계산한다(`ftol(높이)`를 줄높이로 나눈 나머지가 있으면 한 줄 더하는 원본 정수 관문, 줄높이 0과 `INT_MIN/-1`만 오류). 줄마다 LF를 공백으로 바꿔(빈 줄은 공백 한 칸) 열 스크롤만큼 앞을 자르고, 선택이 없으면(Console 강조가 켜져 있고 콜론이 있으면 `recipient(이름)`이 유효할 때 콜론까지 노랑으로 그린 뒤 나머지를 접두 폭에서 이어) 한 번에, 선택이 있으면 앞/선택(평면 배경색 반전)/뒤를 따로 그리고 선택 사각형을 현재 위치에서 채우며, 선택이 없는(시작=끝, -1이 아님) 줄에는 위상이 홀수이고 읽기 전용이 아닐 때만 1칸 폭 caret을 그린다.
- **`TextClipboard`(원문 004dd810/004dd870)**: `read`는 `output[0]=0`을 먼저 쓰고 형식 → Open(NULL 창) → Get → Lock → strncpy 복사(남은 칸 0) → Unlock → Close 순이며 형식/Open 실패는 Close하지 않고, `write`는 Open → Empty → Alloc(0x2000, 길이+1) → Lock → 복사+NUL → Unlock → Set(1) → Close 순이다(할당 실패는 Close만, NULL Lock은 RangeError). 웹 적응: Win32 직접 호출 대신 브라우저의 붙여넣기 스냅숏/쓰기 함수로 같은 아홉 호출을 에뮬레이트하는 `createWebTextClipboardDevices`(Windows-1252)를 두었다. `bindTextClipboard`는 편집 문맥에 같은 장치 수명을 공유하는 두 callback만 설치한다.
- 웹 적응 표기: 문자열 인자는 NUL로 끝나는 `Uint8Array`(또는 바이트 문자열), `logic_error`→`Error`, `invalid_argument`→`TypeError`, `out_of_range`/`length_error`→`RangeError`, `optional`→`null`/`undefined`, 글꼴·픽셀·Slider·트리는 호스트 훅(`measure`/`drawText`/`fill`/`sliderRange` 등)이다.

## 검사와 발견

새 시험 파일 4개, **59건 통과**: `text-clipboard.test.mjs`(9), `text-entry-gump.test.mjs`(15, 생성/부착/스크롤/점멸/문자열 접근/소멸), `text-entry-gump-input.test.mjs`(18, 입력/Console/Draw), `text-entry-gump-edge.test.mjs`(17, 경계 값), 지원 틀 `text-entry-gump-support.mjs`. 편집 버퍼는 실제 `TextEntryStorage`/`TextEntryBuffer`이고 Slider 값 처리는 웹 `ScrollGump`와 같은 계약(정렬·같으면 최대+1·page 제한·위치 제한)을 틀 안에서 재현했다. 글 폭은 바이트당 8·높이 16으로 두어 표시 줄 수/선택 사각형/caret 좌표를 손으로 계산했다.

**최초 실패와 교정(제품 결함 아님, 시험 기대값 오류 4건):** `setScroll`의 가로 Slider 범위는 줄을 쓴 **뒤의 새 줄**(`scrollLine`을 먼저 쓴다) 길이이고 열 clamp만 쓰기 전 줄을 쓴다는 점, `relativeScroll`의 열 clamp도 쓰기 전 줄 길이로 한다는 점, 점멸 시계는 구성 때 한 번 읽는다는 점, 단계 사건의 `measure` 횟수는 처리기 자신의 측정에 `setScroll`의 측정이 더해진다는 점을 바로잡았다(모두 C++ 순서를 다시 읽어 확인).

**변형 확인:** 연산자/정수 상수 변형 538개(text-clipboard 41·text-entry-gump 497) 중 480개를 잡았다. 처음 생존 105개 중 47개는 경계 시험으로 잡았다: void 비트(8)·dead 비트(0x10000), 초기 본문 첫 NUL 절단, 예약 필드 기본 0, Console/Slider 조회의 Error 구분, 측정 길이 인자(-1/명시), 짝수 delta·줄 수와 같은 줄 번호·Right 한 칸, 제외문자 LF 처리, `maxLength` 1, 코드 0x10001/0x20001, Console 특수 코드, 짝수 끝 단어 교체, ASCII 공백 범위(9~13), 줄높이 `INT_MIN`/-1 단독 조건, 1023/1024바이트 줄, 빈 줄에 앞 줄 글자가 남지 않음, 열 스크롤 1/길이와 같음, 줄 맨 앞 콜론, 선택 1칸 앞/짝수 길이 끝, 선택 구간 줄과 -1/-1 줄의 caret 억제. 남은 58개는 동등 변형이다: 이 호출 경로에서 도달할 수 없는 방어 검사(`piece` 범위 8·선택 인덱스 5·줄 끝/선택 뒤 범위·단어 선택 범위·호출자가 null 을 넘기지 않는 `terminated(null)` 분기와 0 주소 제외문자의 빈 배열 크기), 곧바로 덮어쓰는 초기화(점멸 시각·시작 스크롤·`selection` 초기값·caret 측정의 같은 쌍 인덱스), 슬라이더 clamp로 같아지는 값(줄 clamp `<`/`<=`·`+1`의 select clamp), 값이 같아지는 case 라벨(Tab/ESC는 제어 코드, 위/아래는 0x100 이상이라 `default`와 같은 결과), 확보 크기가 한 칸 큰 임시 배열, `CONTROL` 마스크의 최하위 비트(해당 키 코드의 최하위 비트가 0), clipboard 쪽의 4GiB 한도·반환값을 무시하는 Unlock/Empty·typed-array 범위 밖 쓰기.

## 남은 경계

- 실제 Gump 트리/Slider/글꼴 그리기와의 연결, Console/ChatWindow가 이 입력기를 쓰는 부분, 붙여넣기 이벤트에서 스냅숏을 채우는 호스트, 한국어 확장 토큰 분기는 별도 단위다. 앱의 입력은 아직 간소화판이며 실제 미션은 플레이할 수 없다. 원본 파일 변경과 게임/브라우저 실행은 없다.
