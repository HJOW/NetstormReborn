# webpj 스커미시 월드의 실행 모드와 비미션 너겟 판정 (WB04-E1270, 2026-11-23)

[LEFT_JOBS 점검](webpj-left-jobs-audit-20261123.md)(E1263)이 4D-1c 에 남긴 "`PlaceBattleNuggets` 의 비미션 정상 생성은 12차 실제 스커미시 Session 에서 검증한다"를 실제 Chromium 에서 확인했다.

## 확인

- 스커미시(Campaign ▸ Skirmish ▸ Start)를 시작한 월드의 객체 종류를 세었다(기본 설정으로 시작): 플레이어 2·사제 2·섬 27·섬 종유석 27·간헐천 27·무섬 243·가장자리 농장 577·갯벌 2,710·가장자리 536 등. **너겟 객체는 없다.** 65초 뒤에도 같다(보충 없음).
- 모드: `missionPost` 참·`ownerMode.battle` 참·`fort` 거짓. 스커미시는 단독 미션 모드로 도는 전투 월드다.
- 원문 `PlaceBattleNuggets`(`RawCampaignSession.cpp:5771`)와 `ReplenishNuggets` 는 `missionPost`(비미션 전투 = 멀티플레이) 관문 뒤에서만 너겟을 놓거나 보충한다. 단일 미션 모드에서는 관문이 닫혀 너겟이 없는 것이 원문과 같다(E1227 의 단일 미션 너겟 관문 확인과 같은 경로).

## 판정

비미션 너겟 배치·보충은 웹 단독 플레이(캠페인·데모·스커미시 모두 미션 모드)에서 도달하지 않는다. 4D-1c 를 닫았다. 스커미시에 너겟을 더하려면 별도 기능 결정이 필요하며 12차 요구에는 없다.

## 고정

새 e2e `e2e/skirmish-world-mode.spec.js` 가 스커미시 월드의 `missionPost`·`battle` 모드, 너겟 객체 없음, 간헐천 존재, 사제 2명 이상을 확인한다. 이 모드가 바뀌면(예: 스커미시를 비미션 전투로 바꿈) 이 시험이 먼저 알려 준다.
