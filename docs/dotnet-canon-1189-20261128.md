# 1.189 NSInfo의 실제 TYPE과 참가자 색상

`cpppj/src/client/UberGump.cpp`와 `UberHud.inc`의 NSInfo 바깥 전역 읽기를 제품 결선과 비교했다. 원본 `0x5411c8`은 `fortGump`의 블록에 70을 더한 런타임 TYPE인데 DN은 이미 런타임 번호인 `BackgroundType`에서 70을 뺐다. 이 값은 참가자 창의 버튼 TYPE 포인터 생성에 직접 쓰인다. 원본의 기본색 네 주소, 명명색 한 주소와 참가자 슬롯별 두 색상 배열도 DN의 임시 대체색 또는 누락과 달랐다.

현재 메뉴의 런타임 TYPE과 현재 화면의 실제 기본·명명 팔레트 항목을 원본 주소별로 읽도록 공통 장치를 추가하고 제품 공장에 연결했다. 두 배열은 각 여덟 DWORD와 정렬된 주소만 처리하며, 다른 주소는 기존 외부 장치가 처리한다. 전역 색상은 호출할 때마다 현재 화면에서 읽는다.

중복되지 않는 검사 표로 정확한 주소와 두 배열의 경계를 확인하고, 설치 자산과 실제 NSInfo 창을 생성하여 참가자 여덟 명의 버튼 TYPE을 확인했다. NSInfo 및 관련 Root 집중 검사 **86/86 통과**, Release 빌드 오류 0·기존 경고 8, `cpp_sync.py` 종료 0이다.

별도 빌드에서 `thewarbegins`, `tutorial1`, `surrounded`의 진입·대기는 모두 종료 0이고 90프레임 세션 덤프는 1.175와 같다. 1-1 여섯 화면은 1.188과 픽셀 단위로 같다. 원본 1,392파일은 전후 불변이며 실행 결과는 `extracted/dotnet-state-ui-1189/`, 집중 검사 결과는 `extracted/dotnet-1189-tests/`에 있다. 이 경로의 화면 불변은 NSInfo의 모든 사용자 조작이 검증됐다는 뜻이 아니다. 전체 HUD 부모와 State 전환, 참가자 메뉴의 제품 종단 검증은 여전히 남는다.
