# dotnetpj 최근 변경 점검과 표시 상자 수정

2026-10-09, `HJOW-Athlon`, .NET SDK 10.0.401. 점검 기준은 `c2e1cf4`의 최근 dotnetpj 변경이다. AGENTS.md와 두 인계 문서를 읽고, 마지막 디컴파일 PC와 현재 PC가 같음을 확인했다. 기존 C++ 소스와 원본 x86 fixture는 읽기만 했다. 새 디컴파일/내보내기·원본 게임 실행·cpppj/LEFT_JOBS.md/AGENTS.md/원본 변경·커밋/푸시는 하지 않았다. 사용자에게 허용받은 클론 창 검사를 실행했다.

## 확인한 진행 상황

- **점유 지도:** `SpotMap`의 마스크·좌표 복구·행 우선 OR/AND·패치 중복 조기반환·CD 계속 처리는 기존 C++ spot 구간과 맞는다. 기존 단위 검사 7개도 통과했다. 해시·표면 word·하위 효과와 세션 `BattleMap._occupied` 교체는 포함하지 않는다.
- **다리 누적 제작:** 확정 배치 명령에서 실제 놓은 칸을 `PlayerState.RecordMade`로 기록하고 튜토리얼 A/B/C가 `MadeWithFlags(0x4)`를 조회한다. 저장 다리는 명령 경로를 타지 않으며 회수/붕괴로 누적 수가 줄지 않는다. 전체 공통 postPop의 비용·공급/작업장 목록·원본 통계 표를 이식한 것은 아니다.
- **표시 순서:** 저장 객체의 초기 `_sorted`가 깊이→y→x 순서를 사용한다. 완전 동률은 안정 정렬이다. 이동 후 좌표 재정렬·새 객체/다리/지면을 함께 정렬하는 전체 표시 목록은 아직 없다.
- **표시 경계:** Core의 `DisplayBounds.Bounds`는 원본 368개와 맞지만 뷰어 연결에 아래 반올림 순서 문제가 있었다. 선택/체력 상자에만 사용하며 그림 배치·그림자 합성·이동형 클릭 판정은 기존 경로다.
- **비트맵 글꼴:** 코드에는 이미 `.chfnt` 판독기와 검사 4개가 있었다. 캐시 18개·4,608글리프·302,480픽셀 판독이 통과했다. 인계의 미완료 표시는 낡은 상태였다. `OriginalUiSkin`은 여전히 기존 `DrawString`을 쓰며 영어 UI/폭 측정 연결은 남았다.

점검 전 Release는 경고/오류 0, **886개 통과**(Assets 285 + Core 601)였다. 인계의 882개는 글꼴 검사 4개를 반영하지 않은 값이다. 아래 수정 후 최종은 **888개**다.

## 확인한 오류와 수정

뷰어는 `(worldPixel − camera) × zoom + center`를 계산한 **뒤** `+0.5`와 절삭을 수행했다. 원본은 `trunc(world × 16/11 + 0.5)`를 **먼저** 계산하고 정수 카메라를 뺀다. 화면 좌표가 음수일 때 두 순서가 다르다.

예를 들어 월드 `(100.25,200)`, 카메라 `(2117,2609)`, 중심 `(512,384)`, 1배이면 원본 기준점은 `(-1,-25)`다. 기존 뷰어는 이를 `(0,-24)`로 바꿨다. 표시 크기 `(17,9)`, hotspot `(3,-3)`의 정상 상자는 `(-4,-22,14,-12)`이며 기존 상자는 x/y에서 각각 1픽셀 밀린다.

`DisplayBounds.BoundsInView`가 월드 투영을 먼저 수행하고 뷰어의 카메라/중심/확대를 적용한다. `FortMapViewer.EntityFrameBox`는 이미 옮긴 화면점 대신 기준점 보정을 포함한 월드 좌표를 공급한다. Q16 hotspot·치수와 +1 규칙은 유지한다. 소수 카메라와 1배 이외의 배율은 클론 뷰어의 확장 계약이며 원본의 추가 줌 기능 복원을 뜻하지 않는다.

새 검사 2개는 기존 fixture 중 실제 1배 84행을 그대로 재생하고 카메라를 옮겨 음수 화면 좌표에서도 기대 경계의 단순 이동인지를 확인한다(**168개 대조**). 기대값은 저장된 원본 경계이며 구현으로 재계산하지 않는다. 소수 카메라·0.5배·범위 보호도 검사한다. 수정 전 뷰어의 float 연산을 정적으로 재현한 결과 84행 모두 이동된 원본 경계와 불일치했다(`extracted/dotnet-review-projection-20261009.json`). 새 계산은 모두 통과한다.

추가로 글꼴 payload 주석을 **4132 = 0x1024**로 바로잡았다. 파일 오프셋 계산은 원래 맞았으며 글꼴 실행 코드는 바꾸지 않았다. 표시 클래스의 낡은 미연결 설명도 수정했다.
