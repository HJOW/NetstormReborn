# webpj 문자 편집 버퍼 원본 관측 연결 (WB04-E481, 2026-11-15)

3.8절 이월 목록의 "텍스트 입력/진단 나머지" 중 `text-entry-buffer`를 원본 10.78 독립 x86 관측 **570행**(285입력 × 두 정밀도)에 대조했다. 570행 모두 첫 실행에서 일치했고 이식 결함은 나오지 않았다. `PORT_MAP`의 "전용 PE fixture 없음"과 모듈·시험 머리의 "cpppj에도 직접 시험이 없다"는 오기였다(같은 감사의 다른 오기와 같다).

## 비교한 것

`tests/text-entry-native-fixtures.test.mjs`가 cpppj `TextEntryBufferTests`의 장치 구성을 옮긴다. 앞 11열(입력)만 장치에 공급하고 뒤 11열(관측)은 비교에만 쓴다.

- **13개 진입**: construct(28)·destroy(8)·select(72)·insert(104)·reset(6)·lines(26)·lineCount(18)·lineLength(16)·copyLine(212)·copyAll(12)·copy(8)·cut(10)·paste(50).
- **명시 장치**: 가상 주소 `0x01010000 + n × 0x10000`의 `size + 16`바이트 블록을 주는 할당기(호출 번호별 실패 입력 포함), 재할당(이전 블록 앞부분 복사·이전 블록 반납 표시), 해제, 주소→살아 있는 보기 조회, clipboard 읽기(256바이트 영 채움)/쓰기.
- **비교 항목**: 완료 여부, 현재 10DWORD(부호 없는 값), 할당 블록 전체(공칭 크기·반납 여부·가드 포함 바이트), 출력 2048바이트, copyLine 선택 쌍, clipboard 출력, 외부 호출 순서·인자, 반환값, 스택 정리량(4 + 인자 × 4)과 native 명령 수.
- **부분 중단 10행**: 호출 번호별 `control/stop` 효과로 재할당·할당·해제 뒤 중단했을 때 이미 쓴 부분 효과가 되돌아가지 않는 점을 확인한다.

## 독립 확인과 변형 확인

자동 변형(연산자·상수) 240개를 새 시험으로 돌려 163개가 잡혔고 77개가 살아남았다. 살아남은 77개를 기존 `text-entry-*` 시험 여섯 개까지 합쳐 다시 돌리면 26개가 남는다. 남은 26개 중 하나가 실제 공백이었다: fixture 의 `construct` 명시 중단은 두 번째 할당(`mutation0283`)뿐이라 **첫 번째 할당에서 중단했을 때** 가상표·선택(0,0)·capacity 0 이 먼저 쓰이고 나머지가 이전 값으로 남는 순서가 비교되지 않았다. 기준선 소스(`TextEntryBuffer.cpp` Construct)의 순서로 독립 시험을 더해 닫았다(수동 변형 3개 모두 잡힘).
