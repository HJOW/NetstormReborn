# webpj NSInfo 일반 부착 원본 관측 연결 (WB04-E488, 2026-11-15)

3.8절 이월 목록의 `hud-nsinfo-attach`를 원본 10.78 독립 x86 관측 **310행**(155입력 × 두 정밀도)에 대조했다. 310행 모두 첫 실행에서 일치했고 이식 결함은 나오지 않았다. `PORT_MAP`과 모듈·시험 머리의 "전용 PE fixture 없음/cpppj에도 직접 시험이 없다"는 오기였다.

## 비교한 것

`tests/hud-nsinfo-native-fixtures.test.mjs`가 cpppj `HudNsInfoTests`의 입력 구성을 옮긴다. 앞 6열(입력)만 장치에 공급하고 뒤 8열(관측)은 비교에만 쓴다.

- **입력**: 8개 노드의 원문 0x11c 바이트(읽지 않는 확장 영역 포함 — 같은 `decodeGumpNode`/`encodeGumpNode`로 기본 160바이트를 읽고 나머지는 보존), 24개 현재 전역(메타맵 `[22]`·플레이어 인식 `[23]` 포함), 부착 인자(x·y 비트·부모·모드), 호출 번호별 명시 변경(노드 raw 필드 `flags`/`baseWidth`/`baseHeight`/`scale`/`background`·전역·중단).
- **장치**: 기본 부착(표시 해제 비트 지우기·위치 쓰기·0 이 아니면 부모 쓰기), 현재 배경 Push(표시 해제 비트 켜기), 배경 부착, 메타맵 배치. 노드 주소는 원문 격리 주소 ↔ 1 기반 안정 토큰으로 오간다.
- **비교**: 완료 여부, 8노드 raw 전체(주소 순서), 24전역, 호출 순서 문자열, 스택 정리량(완료 시 20), native 명령 수. 메타맵 본문의 완료 검증으로는 확장하지 않는다(cpppj 와 같음). 부분 중단 8행에서 이미 쓴 부분 효과가 되돌아가지 않는 것도 확인된다.

## 변형 확인

자동 변형 28개 중 12개가 잡히고 16개가 생존했다. 생존 16개는 노드 클래스 필드 기본값(`0`/`8`)과 생성자 인자 검증(`||` 연결)으로, 이 시험은 모든 필드를 원문 raw 로 설치하고 훅을 항상 연결해 가려지지 않는다. 기존 `ns-info.test.mjs`와 합치면 16개 모두 잡힌다(생존 0).

## 남은 것

`hud-nsinfo-create`(170행)는 전체 자식 생성(`HudNsInfoCreate`)을 다룬다. 같은 원본 raw 노드를 다섯 파생 종류(기본·NSInfo·PlayerInfo·BattleInfo·버튼)로 읽는 0x180 바이트 할당 레코드, 512바이트 번역 문자열 장치, 13개 전역, 호출 번호별 명시 실패/중단 장치가 필요한 큰 틀이라 후속 단위로 남긴다.
