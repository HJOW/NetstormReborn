# dotnetpj 1.111 — 생산 패널의 기존 동기화 본체 연결

2026-11-27, HJOW-Athlon. 제품 생산 패널의 `Synchronize`를 기존 `ClientProductionSync.SynchronizeProductionControlContents`에 연결했다. 현재 Runtime을 빌리는 경우 기존 세션의 적재 관문과 생산 동기화 본체를 그대로 사용하고, 월드가 없는 경우 같은 Client의 장기 Player·Deck을 사용한다.

- 생산 HUD 모드 사건이 다리·텔레포트 격자의 현재 기술 부모를 순서대로 바인딩하고 두 노드의 Form 공개 뒤 동기화를 부르는 것을 경계 관측으로 검사했다. 별도로 월드 없는 같은 사건이 실제 동기화 본체를 호출해 현재 Deck을 생성하는 것과 미적재 세션의 기존 거부 경로를 검사했다. 실제 Native Form의 생성·부착과 중첩 삭제는 1.109 검사에 있다.
- 첫 검사에서 새 장면의 Player 기록을 초기화하지 않아 두 건이 범위 오류로 실패했다. 실제 Client 초기화를 적용한 뒤 관련 Client 검사 **14건 통과**, `cpp_sync.py` 종료 0, 제품 Release 빌드 오류 0이다.
- `extracted/dotnet-l2-1111-production-sync/`의 대표 세 미션에서 CPP·DN 여섯 실행이 모두 종료 0, DN `f090.tsv`는 0.998과 바이트 일치, 원본 1,392개 파일은 전후 불변이다. 비교기 종료 1은 기존 L2 차이다.

제품 미션에서 해당 사건과 완전 적재된 생산 동기화를 재현한 검사는 아직 없다. 생산 루트 유지 Idle, 실제 내용물 갱신·유지, 일반 자산의 UI 통지, 정렬 본체 통합과 사제 포획 안내는 미완료다. 34경로도 재측정하지 않았다.
