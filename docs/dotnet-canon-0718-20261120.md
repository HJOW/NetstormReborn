# 0.718 실제 Host 프로세스의 현재 Runtime 묶음

실제 HostSession의 PlayerProcesses를 기존 ProcessHostRuntimeBindings 조회 경로로 연결했다. 같은 실제 삭제기·공장·공통 Pop 깊이·현재 시각을 사용하며 기존 Regular/자산/전송 등록은 같은 현재 묶음을 갱신한다. 묶음은 Session이 소유하고 Host의 조회 슬롯은 약하게 참조한다. 외부가 이전 묶음을 강하게 보유하더라도 명시 반납 뒤에는 같은 슬롯을 비워 현재 본문으로 다시 선택되지 않게 한다.

Runtime 공개 전후의 장치 생성에 현재 pin 함수 사본을 전달한다. 실제 프로세스 호출은 기존 Core RuntimeCallGuard가 정상/예외 복귀까지 같은 외곽 owner를 보유한다. 아직 외곽 Runtime을 공개하지 않은 준비 단계도 실제 묶음의 ActiveCalls로 전체 반납을 거부한다. 최종 Player/Deck/사제/생산 정리가 정상 복귀한 뒤만 현재 프로세스 슬롯을 반납하며 실패 시 앞선 부분 효과를 롤백하지 않는다.

Client 집중82건이 모두 통과했다(신규4건). 실제 공장으로 Form을 만들고 Kernel에 Regular를 부착해 공개전후의 실행·활성 호출수·명시 반납 거부·외곽 종료 지연·실제 효과 예외 복귀·자식 정리와 외부 묶음 보유 후 슬롯 반납을 확인했다. 기존 Player/사제/업그레이드/후처리/고정 수신/Runtime 검사도 포함한다. 근거는 `extracted/dotnet-0718/client-fixed.log`와 `host-process-fixed.trx`다.

초기 빌드는 새 검사에서 RegularHandler의 count 인수를 빠뜨려 실패했다. 이를 교정한 첫82검사는77통과/5실패였다. 제가 반납 코드를 예약 소비 위치에 잘못 넣은 제품 문제1곳과 새 검사 부모가 void여서 Regular가 실행되지 않은 입력 문제를 확인해 최종 정리 위치/명시 배치 상태로 교정했다. 기존 화신 Pop 회귀를 포함한 최종82건은 모두 통과했다. 초기 로그와 `host-process-corrected.trx`도 같은 증거 디렉토리에 보존했다. 기대값이나 원본 fixture를 완화하지 않았다.

실제 DN thewarbegins 시작/종료1회는 종료0이며 덤프 전체 바이트가0.716과같고원본1392파일SHA도불변이다. 영어1024×768창/음소거·시드1760000000·25ms/90프레임이다. 근거는 `extracted/dotnet-0718/smoke.py`·`smoke-summary.json`·`smoke/thewarbegins/dn/run.json`/`f090.tsv`다. 실제 포획/희생·특정 적 공격·승리 재현은 하지 않았다.

PORT_MAP에는 RawSurfaceWorld.cpp/.h의 현재 ProcessRuntime 조립에 대응하는2행만 추가했다. 기존 PlayerWorld의 큰 Session 매핑 기준은 이번 작은 수명 분기만으로 갱신하지 않았다. cpp_sync 종료0·연결fixture360개불변이다. 현재 Host/Kernel의 실제 장기 RawProcessHostStorage 승계와 Client FrameTimeBox·GameClock의 제품 프레임 설치, Factory 전체 대여/건설 효과는 계속 남는다. 이 단위는 그 전체 연결을 완료한 판정이 아니다.

다음0.719는 기존 공장 호출의 실제 외곽 대여를 이어간다. 전체Login/State/전송Root와기타R4차이도남으며M1/전체목표는미완료다. 정기전체회귀는0.720이다.
