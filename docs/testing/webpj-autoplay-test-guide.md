# webpj 아군 AI 플레이 검사 안내

현행 범위: 2026-11-27 사용자 지시. 단순 미션 진입과 안내 메시지 표시만 확인하는 검사는 모든 캠페인에서 가능하다. 목표 수행·생산/건설·공격·사제 포획/희생·승리 등 실제 플레이 검사는 아군 AI 방식으로만 진행하며 캠페인1-1~1-6과 스커미시로 제한한다.1-6 이후의 실제 플레이는 건너뛰고 사용자가 확인한다. 앞서 완료한 수동 조작 검사는 당시 이력이며 이번 목표에서 다시 실행하는 근거로 사용하지 않는다.

실제 목표 검사는 debug.html의 ES 모듈 앱에서 e2e/ally-ai-test-control.js의 installAllyAi를 미션 진입 전에 설치한다. 원래 MissionStart 직후 현재 로컬 Player의 실제 AI를 생성하며 현재 SP·이름·동맹·기술을 보존한다. 아군 어려움/적 쉬움은 검사 정책이다. 이미 실제 로컬brain이 있으면 C++ CreateLocalTestAi처럼 교체하지 않고 재사용한다. SP/HP/기술/완료값이나 목표 판정을 직접 변경하지 않는다.

기본 서버는 webpj에서 node server.js로 켠다. 자연 승리와 저장을 관찰하는 명령은 다음과 같다.

```powershell
node tools/ally-ai-campaign-flow.cjs thewarbegins 60000
node tools/ally-ai-campaign-flow.cjs dissolvedalliance 60000
```

첫 인자는 내부 미션 이름이며 여섯 캠페인만 허용한다. 둘째 인자는100~120000 사이의 실제 프레임 상한이다. 기본은 masterofwhirligigs/60000이다. 아군 AI와 원래 Kernel·Renderer를 매 프레임 실행하고 최종 물리 출력만 미룬다. 상한에서 승리가 없으면 검사 종료1로 실패를 남긴다. 게임 예외/오류 여부와 승리 미달을 구분한다.

1-1~1-5에서 실제 승리하면 새 완료값 저장, Next Mission의 실제 World/브리핑, 같은 저장소의 새로고침과 메뉴 해제/실제 브리핑을 확인한다.1-6 완료 뒤에는 Next Mission을 누르지 않고 원래 Leave Missions/새로고침/완료값 보존만 확인해 후속 캠페인 플레이를 시작하지 않는다. 실제 저장값을 다른 브라우저에 읽히는 호환 검사는 출처를 명시하며 새로운 자연 승리로 세지 않는다.

별도 단순 진입/안내 검사는 아군AI 플레이 관문과 다르다. 모든 캠페인을 로드해 첫 안내를 확인할 수 있지만 거기서 목표 수행·공격·생산 등의 실제 플레이를 이어 가지 않는다. 과거 수동 L3/건설 e2e 전체를 이 목표에서 일괄 재실행하지 않는다. 각 검사 소스의 실제 동작 범위를 확인해 선택한다.

검사 제어기의 집중 검사는 npx playwright test e2e/ally-ai-test-control.spec.js --workers=1이다. 허용 밖 미션은 실제 페이지 접근 전에 거부한다.1-6의 초기 SP4000/이름/동맹/기술 보존과15초 실제AI 진행,1-1의6000프레임 자연 진행을 확인한다. 이 제어기 검증을 미션 승리 완료로 사용하지 않는다.

출력은 Git 제외 webpj/extracted 아래에 쓴다. 같은 미션을 다시 실행하면 기본 파일명이 같으므로 이전 결과를 먼저 별도 폴더/해시와 보존한다. 사용자 저장소와 원본 파일은 수정하지 않는다. 현재 범위의 근거와 완료/미완료 상태는 LEFT_JOBS.webpj.md가 기준이다.

실제 AI 수집기 `tools/ally-ai-campaign-flow.cjs`는 프레임 오류를 발견하면 단언/브라우저 종료 전에 `extracted/ally-flow-미션이름-failure.json`에 당시 시각·안내·관측·전체 오류·가능한 Session 덤프를 남긴다. 최종 Canvas 출력만 복구해 `-failure.png`도 저장하며 게임 프레임이나 명령을 추가하지 않는다. 덤프/화면 저장 실패는 원래 프레임 오류를 가리지 않는다. 이 파일은 실제 승리/완료 저장 결과와 구별한다(E1413).
