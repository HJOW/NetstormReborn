# dotnetpj 0.835 — 실제 시작 색표·캐시·소유자 옵션 수명 연결

2026-11-22, HJOW-Athlon. 실행 경로는 `dotnetpj/src/Netstorm.Game/bin/Release/net10.0/Netstorm.exe`다. 첫 팔레트부터 실제 TYPE/사용자 캐시/소유자 색표를 같은 Client 수명에 설치했다. F7의 상위 일반 입력은 아직 미연결이며 Config 변경 구독을 F7 완료로 세지 않는다.

## 변경

- `HostStartupScene.Draw`에 첫 팔레트 직후의 명시 준비 경계와 fort 전환의 색표 재계산 경계를 추가했다. 독립 `Draw(screen)`은 실제 캐시/Player를 만들지 않는다.
- 실제 `ClientHostGame`은 최초 팔레트→같은 Clock/Player→고정 RGB/primary→음향/커서·실제 TYPE→사용자 `Cache/!color.dat`와 소유자 표→Screen 순서로 조립한다. 초기 표시와 메뉴 재합성이 같은 경계를 사용한다.
- `HostStartupColorMaps`가 같은 `ClientColorSortInput`을 보관하고 실제 CRT reader/writer 캐시 입구를 호출한다. 실제 TYPE 188개와 `TypeTable.Find("bridge")`의 실제 번호82를 사용한다. C++ 자산 block에만 필요한70을 다시 더하지 않는다.
- fort 전환은 최초 RGB/primary·같은9배열을 유지하고 현재 red로 재계산한다. Screen은 같은 입력/9표 getter를 빌리며 자신의 두 명암 배열에 값 복사한다. 새 Screen이나 반복 Draw에서 primary/Player/TYPE/캐시를 다시 만들지 않는다.
- 같은 Config의 OnChanged에 자신의 핸들러만 추가하고 해제한다. 준비 전 쓰기는 원문처럼 무시하며 준비 뒤 `useBanners` 변경이 같은 현재 표와 전체 dirty를 동기 갱신한다. 초기 Enabled를 설정값으로 임의 덮거나 준비 뒤 강제 재해석하지 않는다.

- 같은 최종 빌드의 대표3미션 시작은 모두 종료0이다. 전체 덤프/지표가0.832와 같다. 사제 포획/희생·특정 공격·승리 입력은 보내지 않았다.
