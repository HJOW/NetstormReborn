# dotnetpj 화면 프레임의 명령·다리 스캔 원본화

작업 PC: `HJOW-Athlon`, 2026-10-11. [인계 9-1 A](../LEFT_JOBS.dotnetpj.md#original-parity-plan)의 첫 구현 단계다. **A 전체 완료는 아니다.** 기존 24Hz 구조를 그대로 유지해도 원본과 같다는 2026-10-05 판단은 폐기한다. 명령과 스캔을 실제 프레임에 연결했고, 나머지 시간 모델은 계속 옮겨야 한다.

## 판정 근거

[원본 메인 루프](exe/main-loop.md) 2·3·5절에서 10.78은 프레임 시각을 고정하고 입력·명령, 다리 스캔 `00422bc0`, 프로세스 커널 순으로 한 번씩 처리한다. 명령은 그 프레임의 그리기에 반영된다. [붕괴 복원](exe/cpp-bridgedecay-reconstruction.md)의 x86 기대값은 실제 프레임 간격으로 SID 처리량을 정한다. 14ms에서는 `trunc(0.014 / 10 × 8001) = 11`이고 24Hz에서는 33이다. 따라서 평균 초당 진행량이 비슷해도 각 다리의 최초 처리 시각과 주기 마지막 구간은 다르다.

변경 전 세션은 14ms 첫 두 화면에 아무 명령도 처리하지 않았으며, 첫 논리 틱에서 스캔을 33개 진행했다. 정지 중 입력은 `RunTicks(1)`을 호출해 선택·이동을 누를 때마다 시간과 다른 유닛 로직까지 진행했다. 지도 배치·다리 입력은 화면의 `UpdateSession` 뒤에 있어 다음 화면까지 처리가 밀렸다.

## 구현 범위

- `BattleSession.Advance`는 실제 프레임 시각 `FrameSeconds`를 누적하고 명령 → 다리 스캔·지상 지지 → 남은 논리 틱 → 미션 판정을 처리한다. 논리 틱이 없는 프레임에도 명령과 스캔을 처리하며, 따라잡기 틱마다 스캔을 반복하지 않는다.
- `ProcessCommands`는 시각을 늘리지 않고 명령을 처리한다. 정지 중 선택·배치·회수에 사용하고, 같은 틱의 옛 사건을 다시 소비하지 않도록 이번 명령의 사건만 튜토리얼에 전달한다.
- 실제 지도 입력은 배치·다리까지 모은 뒤 세션을 갱신한다. 그 프레임에 정지로 바뀌어도 이미 받은 명령은 처리한다.
- 생성자는 기존 게임 시각을 이어받을 수 있도록 시작 프레임 시각을 받는다. 다리 스캔 초기화는 그 시각에 `지금 + 10초`를 적용한다. 0이 아닌 원본 시각도 빼거나 재정규화하지 않고 double 비트로 대조한다.
- 검사합에 프레임 시각과 논리 누적기의 잔여 시간을 포함한다. 동일한 **명령열과 프레임 시간열**은 결정적이다. 서로 다른 화면 간격에서는 원본 스캔 상태가 달라질 수 있으므로 전체 검사합이 같다는 옛 전투 테스트 가정은 폐기했다. 해당 테스트는 전투 사건·피해·포대 상태를 계속 검증하고 스캔·검사합의 차이도 단언한다.
- `RunTicks`는 기존 규칙 검증과 CLI 앞당기기의 1/24초 합성 프레임으로 유지한다. 정수 틱에서 합성 시각을 계산해 10초 경계의 누적 오차를 피하며 실제 프레임의 잔여 시각은 보존한다. 이 helper만으로 실제 화면 프레임의 원본성을 주장하지 않는다.

`UiAutomation`에 `remember-detail 키`와 `assert-unchanged-detail 키`를 추가했다. `simulation`, `tick`, `frame-seconds`, `scan-cursor`를 실제 화면 상태에서 읽어 정지 조작 전후를 정확히 비교한다. 사용자 화면에는 진단 값을 표시하지 않는다.

## 검증

Release 빌드 경고·오류 0. 단위 **964개**(Assets 327 + Core 637), 실패·건너뜀 0.

새 `BattleFrameTests` 12개 중 네 시간열은 `cpppj/tests/fixtures/bridgedecay-x86.tsv`의 **10.78 Scan 1,948행과 Init 4행**을 실제 세션 `Advance`에 순서대로 넣는다. 14ms 760행, 24Hz 500행, 60Hz 660행, 불규칙 28행 모두 프레임 시각·커서·다음 시각 double 비트가 일치했다. 이는 원본 함수의 시간·스캔 상태 대조이며 실제 원본 게임 화면이나 전체 프로세스 실행을 검증한 것은 아니다.

나머지 새 테스트는 첫 14ms 프레임의 명령 실행, 정지 중 반복 입력의 시간·위치 보존, 실제 다리의 배타적 SID 구간 처리, 긴 5초 프레임의 한 번 스캔, 같은 시간열의 결정론, 비정상 간격 거부를 확인한다.

신규 실제 GUI는 **4회/76개 단언** 통과했다. 영어·한국어 1024×768, 영어 1280×720, 한국어 1280×800에서 정지 중 선택·이동·재선택과 대기를 거쳐 틱·프레임 시각·스캔 커서가 그대로였으며 표시 좌표도 대기 중 바뀌지 않았다. 재개 뒤 실제 남쪽 목표에 도착했다. 정지 중에는 이동 방향이 아직 갱신되지 않으므로 `priest:-:moving`, 재개·도착 뒤에는 `priest:E:idle`을 검사한다. 좌표 반올림으로 도착 직전에도 `121`이 보일 수 있어 실제 `idle`을 기다린다.

기존 전체 GUI **49회/626개 단언**과 월드 표시 순서 GUI **7회/36개 단언**도 통과했다. 신규 정지 검사까지 합쳐 **60회/738개 단언** 모두 통과했다. 캠페인 목록·버튼·도움말 Menu/Mission/Workshop·이동·건설·생산·recordplay 10개·TEST01 네 조합·TEST02 영어/한국어·전투 12장면·전체화면 저장/재실행/창 복귀를 확인했다. 월드 표시 검사는 저장/신규/역순 생성 세 조건의 겹침 **509화소씩 차이 0**, 움직이는 사제의 표시 순서 변경·실제 선택, 두 와이드 화면비의 숨김/복귀까지 재검증했다.

## 다음 단계와 제한

1. **A의 나머지 시간 모델을 먼저 옮긴다.** 이동·전투·건설·생산·수확·의식·AI·튜토리얼과 화면 애니메이션은 아직 정수 틱·보간이다. 이를 실제 시각과 원본의 `지금 + 간격` 타이머, 이동의 절대 시각 보간으로 바꿔야 한다. 이벤트에 적는 Tick도 아직 논리 틱 번호다.
2. `FrameSeconds`와 기존 `Seconds`는 이 과도 단계에서 분리돼 있다. 특히 긴 프레임에서 논리 따라잡기 8틱 상한 때문에 둘의 간격이 커진다. 명령은 틱을 기다리지 않지만 건설·재충전 예약 시각은 아직 논리 틱 기준이다. 이 상태를 최종 구조나 완전한 원본 동작으로 판정하지 않는다.
3. MonoGame의 14ms 고정 화면 갱신·따라잡기와 대기 방식도 남아 있다. 실제 벽시계의 불규칙 프레임을 입력으로 쓰는 전체 루프 이행 및 9-1 D는 후속이다. 원본의 실제 루프 간격 실측 없이 모든 장치에서 14ms라고 단정하지 않는다.
4. 이동 명령을 정지 중 내리면 기존 화면 보간 잔여량 때문에 새 경로의 시작 표시가 소폭 달라질 수 있다(신규 GUI에서 115 → 115.01). 이후 정지 대기 중에는 위치가 유지됨을 검증했다. 절대 시각 이동으로 옮길 때 이 시작 보간도 정리한다.
5. 그래프 크기·실제 표면 identity·전체 객체 생성 순서 및 투사체 SID는 아직 근사 또는 미연결이다. 같은 SID·시각의 스캔 커서가 맞는다고 실제 모든 맵의 붕괴 위상이 같다고 주장하지 않는다.

A 이후에는 C → B → D·E·F 판정과 실제 캠페인 완주→진행 저장→재실행→다음 미션 해제를 이어간다. 원본 게임 실행·새 디컴파일·cpppj/AGENTS.md/원본 자료 수정·커밋/푸시는 없었다. 마지막 디컴파일 호스트는 기존 기록의 `HJOW-Athlon`이다.
