# dotnetpj 0.913 — RU-3 플레이어 패널 원문 입력 이식

2026-11-24, HJOW-Athlon. RU-3 일곱 번째 묶음이다. PlayerInfo 패널의 원문 입력을 같은 파생 노드/CS·87BYTE 옵션과 실제 메뉴·송신에 연결했다. 제품 기존 경로는 바꾸지 않는다.

## 변경과 원문 대응

- `BattleOptionSlots`는 `cpppj/src/o/RawBattleOptionSlots.cpp`의 슬롯 색/랭크/특수 읽고 쓰기 6종을 이식했다. 24DWORD 랭크 표·signed0..7 관문·BYTE 감김 규칙(색 7↔0, 랭크 23↔0, 특수 `!=1` 비교)을 원문대로 유지하며 무효 슬롯은 읽기 없이 0을 반환한다. 합성 옵션 기록 검증이라 신규 fixture는 없다.
- `NativePlayerInfoInput.Handle`은 `cpppj/src/client/NativePlayerInfoInput.cpp`의 `HandleNativePlayerInfo(0047a900)`를 이식했다. 같은 실제 노드/CS/메뉴/송신 장치를 빌리며 미연결 장치는 일반 성공으로 꾸미지 않고 명시 실패로 둔다. 네 공장 설치·바깥 UI·NativeRoot/HUD 창 생성·Enter·HUD 작성자·메타 배치 입력/특수 그림·Root reply 저장은 후속 단위에서 잇는다.
- 준비 버튼은 소유자일 때 CS 플래그 2번 비트를 버튼 값대로 쓰고 송신한다. 시작 버튼은 최초 1회만 `0x12`를 송신하고 예약한다. 소유자가 아니면 준비/시작 모두 0을 반환한다.
- 좌/우 태그 사건은 해당 분기에서 항상 1로 소비한다. 랭크/색 변경은 헤더 전에 바꾸고 Special은 헤더/초기 payload 뒤에 바꾼 뒤 `4000h`를 OR한 플래그와 현재 옵션 87BYTE(`0x57`)를 송신한다. 추방 확인은 `BeginFancy` 이후 이름 NUL 경계·256BYTE 경계를 검사하고 Yes/No 항목을 같은 `5429dc` 명령으로 작성한다.
- 처리하지 않은 입력은 원문대로 0을 반환한다(기본 처분 전달 없음).

## 검증

- Release 클라이언트 빌드는 오류 0이다. 신규 경고 0이다.
- 신규 17건(슬롯 8건·입력 9건)은 통과/실패 0이다. 색/랭크 감김·특수 전환·랭크 표·무효 슬롯·짧은 물리, 준비 설정/해제·시작 1회·비소유자·좌행 변경·특수 보조·추방 메뉴·우행 변경·미처리/미연결이 이웃 43건과 함께 60건 통과한다.
- 같은 최종 빌드에서 대표 3경로(`thewarbegins`·`tutorial1`·`surrounded`)는 모두 L2 미일치(예상)이며 전체 덤프/지표가 0.912와 같다(`thewarbegins` cpp1941/dn1911/only30, `tutorial1` cpp843/dn838/only5, `surrounded` cpp6420/dn6408/only12). 원본 파일은 작업 전후 `git status`에 없고 전후 불변이다. 근거는 `extracted/dotnet-l2-0913-*/`의 각 실행 로그와 요약이다.
