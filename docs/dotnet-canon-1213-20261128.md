# 1.213 Scene A 현재 Player·battle·Cloud와 단일 결과 상자 결선

SceneMusicState가 실제 장기 Player의 현재 DWORD와 Cloud의 같은 redraw 상자를 읽고 쓰도록 연결했다. Game의 기존 State 자원 바인딩을 사용하며 장면 감독의 Start/Frame은 켜지 않는다. **집중41/41통과**, 대표3미션과 추가 실제 Main 진입은 모두 종료0이다. 기존 덤프·여섯 화면·보호1,392파일도 불변이다. 결과 상자는 하나로 준비했지만 메뉴·이탈·로그인 등 실제 결과 부모의 조립 완료를 뜻하지 않는다.

선행 [1.211 장기 음향 owner](dotnet-canon-1211-20261128.md)와 [1.212 Client 전체 재검증](dotnet-canon-1212-20261128.md)을 유지한다. 이번 단위는 [Scene 후속 계획](dotnet-scene-followup-plan-1211-20261128.md)의 A다. 월드 조회 B, 파일 팔레트 C, 팔레트 소비자 D, Thunder E, 감독/Start/Frame과 State 호출자 F–H는 별도 미완료다.

## 현재값과 같은 DWORD 주소

`dotnetpj/src/Netstorm.Client/Audio/SceneMusic.cs`에 다음 경계를 추가했다. 기존 독립 fixture의 명시 입력 API는 보존한다.

| 원문 주소·소비 | 실제 결선과 계약 |
| --- | --- |
| PlayersReady `00595344` | 새 CurrentPlayersReady getter가 같은 Gameplay.Player.PlayerKnown의 전체 DWORD를 읽는다. Next는 색인을 먼저 저장하고 ready를 읽으며, 비영일 때만 local getter와 희생 판정을 선택한다. |
| LocalPlayer `00540c70` | 새 CurrentLocalPlayer getter가 같은 Player.BattleOwnerBox.Value를 읽는다. TemplateOwner와 합치거나 byte로 자르지 않는다. ready getter의 재진입 효과로 local getter가 바뀌면 뒤 실제 소비 위치에서 그 현재 getter를 읽는다. |
| CurrentBattle `00594fbc` | 기존 getter를 유지하고 같은 Surface.Storage.OwnerMode.Battle을 매 소비 위치에서 조회한다. 이미 저장한 Battle fallback을 현재값으로 복사하지 않는다. |
| Result `005c85ac` | get-only ResultStateBox 한 UIntBox를 SceneMusicState가 소유한다. 기존 ResultState 속성은 그 Value의 view다. 현재 이름 조회가 결과를 바꾸면 뒤 fanfare 관문이 같은 현재값을 읽는다. |
| PaletteDirty `0059a8b0` | PaletteDirtyBox와 BindPaletteDirty가 실제 startup.Cloud.WorldRedrawBox를 참조로 빌린다. 기존 PaletteDirty는 그 Value의 view다. 연결 때 이전값을 복사하거나 새 상자를 0으로 초기화하지 않는다. MapRevision `005949d4`와 다른 주소다. |
| SongEnd `00565e68` | 기존 같은 DoubleBox와 State 쓰기를 유지한다. 음수0·NaN payload를 포함한 원시8BYTE도 정규화하지 않는다. |

현재 getter가 없으면 기존 PlayersReady/LocalPlayer/Battle 명시 fallback을 읽는다. 실제 연결이 fallback 값을 덮지 않으며, getter를 제거하면 그 위치의 기존 fallback을 다시 사용한다. PaletteDirty는 실제 Cloud를 빌리기 전에는 독립 상자를 사용한다. 팔레트 후단이 정상 복귀한 뒤 같은 dirty를1로 쓰고 번개·효과음으로 진행하는 순서, 후단 예외에서 앞선 Tint만 남기는 부분 효과도 유지한다.

ResultState와 PaletteDirty의 관리 자동 필드를 UIntBox view로 바꿨으므로 SceneMusicState 자체의 managed 내부 layout은 바뀐다. 이 클래스는 고정 raw 레이아웃 계약 타입이 아니다. 실제 음악 채널96BYTE, 현재 이름256BYTE, 공유 DWORD와 SongEnd의 원시 비트 계약은 바꾸지 않았다.

## Game의 실제 바인딩과 정체성 관문

`ClientStateResources.BindCurrentMusicOwners`는 Surface.Gameplay, Local.Gameplay, Connections.LocalState, Surface.Clock.LocalState, Storage의 Authority/GameAux 및 Patch1078 판본을 먼저 확인한다. 모든 검증이 끝난 뒤 getter 세 개와 선택된 실제 Cloud 상자를 연결한다. 서로 다른 owner를 섞으면 기존 delegate·상자·값을 변경하기 전에 실패한다. 연결 자체가 시각·난수·파일·곡·채널을 소비하지 않는다.

`ClientHostGame` 생성자의 기존 BindStateResourceOwners 호출 위치를 유지했다. `ClientHostGame.StateResources.cs`가 이 helper를 호출하고, startup이 있으면 기존 ClientStateWorldGlobals.Bind와 같은 context를 그대로 설치한다. startup이 없는 호스트에는 실제 Player/battle getter만 연결하며 Cloud를 대신 생성하지 않는다. 자산 없는 경로를 완전한 Scene 준비 성공으로 표시하지 않는다. getter는 이전 HostSession을 캡처하지 않고 같은 장기 Surface/Gameplay의 현재값을 읽는다.

`ClientHostGame.ColorMaps.cs`는 기존 음향 owner가 있으면 HWND 조회·로그·다른 자산 준비 전에 RequireMusicOwner로 Audio.Scene의 동일성을 확인한다. 다른 기존 owner를 임의 반납하지 않는 순수 검사다. 새 음향 owner는 지역변수로 만든 뒤 같은 Scene인지 확인하고 Game 필드에 공개한다. 그 검증에서 실패하면 pending owner를 Dispose하고 최초 예외를 다시 전달한다. 부수 정리 예외는 최초 Exception.Data에 보호 기록하며 최초 오류를 덮지 않는다.

이 identity helper는 관리 환경의 실제 공유 owner를 검증하는 통합 경계다. CPP에 이미 동일 helper와 세 현재값 callsite가 있었다고 주장하지 않는다. CPP ClientMain의 CurrentBattle 연결과 ClientAudio.ResultState 참조는 실제 근거지만, 현재 CPP의 playersReady/localPlayer/paletteDirty를 실제 Player/Cloud에 직접 묶는 callsite는 확인되지 않았다. CPP의 미제공 희생·대기실 false/빈 표시 callback도 DN의 실제 준비 성공으로 복제하지 않는다.

## 결과 부모의 남은 실제 조립

canonical 결과 주소는 StateResources.Music.ResultStateBox다. NativeMainMenuStateGlobals.Outcome, RawBattleLeave의 BattleAbortStateGlobals.Outcome, MissionLoginTimerState.RequestPhase가 이후 같은 상자를 빌려야 한다. 현재 Game에는 이 세 부모의 실제 조립이 아직 없다. State6 결과 복귀와 BattleCompletion 부모도 같은 결과 주소를 써야 하지만 이번 단위에서는 만들지 않았다.

숫자가 같은 독립 UIntBox를 각 부모에 주거나 매 프레임 값을 복사하는 방식은 이 결선의 대체가 아니다. 실제 부모 이식 시 메뉴의 곡 요청 뒤 결과0 쓰기, 이탈의 현재0일 때3 쓰기, LoginTimer의4 요청 뒤 실제 AbortBattle이 바꾼 현재값 보존을 각각 확인해야 한다. 이번 단위에서 결과를0으로 강제하거나 미완성 부모를 호출하지 않는다.

## 실제 제품 진입과 분리한 Main 진단

`extracted/dotnet-scene-owners-1213-baseline/run.json`은 apphost로 음소거 대표3미션 thewarbegins·tutorial1·surrounded를 실행한 기록이다. `extracted/dotnet-scene-owners-1213-diagnostic/run.json`은 sound0/music1인 thewarbegins의 추가 실제 Main 진입1회다. 두 run은 같은 제품 관리 DLL 세트를 기록하며 Netstorm.dll SHA-256은 `f3a6f727906cacf7db35299e487152ce35cb5cd2787e12316dfbe409b530e5ed`다.

네 진입 모두120프레임·고정25ms·고정 Unix시각1760000000·종료0이다. 각90프레임 덤프는 기존1.173 DN 덤프와 바이트가 같다. 두 묶음 각각1-1의30/40/45/50/60/70 여섯 논리 화면은1.189 기준과0픽셀 차이이며, 보호 originals1,392파일의 전후 SHA가 같다. 이 불변은 같은 게임 시각의 CPP 대조나 전체 L2 34경로 완료를 뜻하지 않는다.

baseline의 native_window/device_ready/runtime_initialized/runtime_shutdown 배열은 비어 있다. 정상 ErrorLog.Note의 메모리 ring 정책에 따른 미관측이며 장치 성공·실패로 해석하지 않는다. diagnostic은 선행1.209의 `extracted/dotnet-1209-ring.ps1`과 실제 invocation.json을 사용해 같은 Program.Main을 STA에서 실행했다. 실제 Main이 정상 Dispose한 뒤 검사 WARN으로 기존 메모리 ring을 보존하는 helper 범위이며, 제품 Scene/Runtime/loaded/RNG 값은 외부에서 바꾸지 않았다.

추가 실제 INFO는 SDL=`0x20AE36E9C60`→HWND=`0x6C0772`와 같은 HWND의 장치 초기화 성공을 기록한다. Runtime.Initialize 정상 복귀 관측은 Thread=`0xB5C`·Shutdown 이벤트=`0xB58`·MusicInitialized=True, 종료 반납 관측은0/0/False다. fatal 배열은 비어 있다. 이 값은 해당 실행의 관측값이며 고정 주소가 아니다. 실제 음악 파일/커서 진행·합류 하드웨어의 별도 검증은1.211 근거를 유지하며 이번 Main 진입으로 재실행했다고 주장하지 않는다.

## 남은 범위와 다음 관문

이번에는 감독을 생성·Start·Frame하지 않았고 실제 희생/대기실 B, 파일 팔레트 C와 소비자 D, Thunder E, 최초 Issue/intro/Start/Chat 순서 F, 현재 Frame G, State7/정리/결과 부모 H를 완료하지 않았다. 실제 메뉴 음향/옵션 UI, 전체 State GUI 왕복·NativeLoaded/미션 적재 부모·AI 진행, 미니맵 잔여1픽셀·동시각 CPP 비교도 미완료다. 값0/false·빈 callback·강제 loaded·난수 보정으로 이 공백을 감추지 않는다.

마지막 정기 회귀의 수집 기준은1.210이며 그 뒤 제품 단위는1.211과1.213 두 개다.1.212는1.211 뒤 Client 전체 재검증이다. 앞으로 제품 두 단위를 더 진행한 뒤 다음 정기 관문을 수행한다. 이번41건 집중을 Client 전체의 새 전수 실행으로 표시하지 않는다.
