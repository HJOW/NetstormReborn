# dotnetpj 0.981 — 0x0f 서버 목록 갈래를 실제 NSInfo 주인에 연결

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 같은 장기 기본 표를 공유하는 `ClientPacketDispatch.Build`/`InstallDefaults`에 선택적 `nsInfo`·`saveServers` 주인을 추가하고 0x0f Root 로그인의 서버 값·목록·저장 후크를 실제 NSInfo 장치에 연결했다. 0x23·0x24·0x25 Build 연결과 제품 기존 경로는 바꾸지 않는다. RU-3 나머지·R4-4 정기 두 단위는 후속에서 잇는다.

## 변경과 원문 대응

- 0x0f의 Checksum·Server 후크는 호출자가 묶은 NSInfo 저장소(`ClientNsInfoGlobals.SetServerValue`·`UpsertServer`, 원문 대응 확인)에 쓰고, SaveServers 후크는 호출자가 묶은 실제 저장 장치를 쓴다. 버전 거부이면 next12·+50 0만 쓰고, 일치하면 구역 정리를 실제로 수행한 뒤 서버 값·목록을 실제 저장소에 쓰고 목록을 저장한다. 주인이 없으면 받는 즉시 명시 실패한다. 새로 만든 본체가 없다. 0.981에서 추가됐다.
- Root(`ClientHostGame`)는 실제 NSInfo 전역(`_nsInfoGlobals`)과 실제 서버 목록 저장(`SaveRootServerList`→`RootServerListDisk.Save`, 사용자 Saves)을 묶었다. Tell·Run·메뉴는 후속에 둔다.
- 수송 팩토리(`ClientCampaignTransport.Make`)는 기본값(주인 없음)으로 같은 표를 공유하므로 동작이 바뀌지 않는다.
