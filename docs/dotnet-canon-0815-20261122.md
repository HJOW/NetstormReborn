# dotnetpj 0.815 — 현재 AI 지갑과 실제 Host 장치

작업일2026-11-22, PC HJOW-Athlon. 직전0.814의 첫 장치 설치/같은 Surface 공유 위에서 Native Root가 필요로 하는 누락 AI 하위를 이었다. 전체 Native Root 조립은 계속 남아 있다.

## 구현

`RawAiWallet`은 cpppj RawAiWallet.cpp/h의 지갑 가산00413bb0·잔액00413c20 전체를 이식한다. 현재 비활성→signed owner 비양수→현재 Player9+b0→NULL brain 관문을 지난 뒤에만 실제0xb08 메모리를 선택한다. 가산은+2d8 DWORD 감김 쓰기 뒤 데모 getter를 실행하고, 참이면 저장해 둔 같은 brain의 현재 본체를 다시 읽어 signed1190 하한을 적용한다. Player 포인터가 바뀌어도 처음 저장한 토큰을 다른 brain으로 바꾸지 않는다. 잔액 조회는 데모/SP/난수/화면을 읽거나 쓰지 않는다.

설치 시 함수 객체만 보관하며 현재 Player 배열·Session·모드 값을 읽지 않는다. 독립 고정뷰와 실제 현재 base getter를 구별한다. 알려진 Player9 폭 밖·짧은 본체·해제 토큰은 호스트 물리 계약 예외로 거부한다. 원본의 미정 범위 밖 접근을 성공 결과로 합성하지 않는다. 메모리 접근과 `IRawRuntimeLease`를 함께 빌리고 가산·데모 후 재조회 또는 실패가 끝난 뒤 반납한다. 일반 owner는 보유만 하며 임의 IDisposable을 반납하지 않는다.

`ClientSurfaceGlobals.CreateAiWallet`은 같은 장기 Player records/current challenge와 호출자가 공급한 현재 데모 getter를 사용한다. 비영 brain에 도달했을 때 같은 Pool의 실제 현재 Session을 골라 `BorrowAiWalletMemory`로 전체 Runtime을 빌린다. 새 Session/AI 본체/값형 지갑을 만들지 않는다. 장기 Source 객체 통지도 challenge·signed owner·현재 기록의 brain 관문 뒤에만 같은 실제 Session/pin과 기존 `RawAiObjectNotice.Notice`를 사용한다. Host에 미설치된 큰 통지는 명시 실패하며 로그만 남기는 성공으로 대체하지 않는다.

`HostSession(sharedSurface:...)`의 Player 기록 인자 생략 경로도 같은 Surface.Gameplay.PlayerRecords를 빌리도록 수정했다. 0.814에서는 Pool/장부 등은 공유했지만 이 인자를 생략하면 독립 배열을 만들 수 있었다. 다른 기록 owner를 명시하면 실제 초기화 전에 거부한다. 인자를 모두 명시한 현재 일반 Root의 owner는 그대로다.

## 원본 근거와 검사

`reverse-engineer-anything` 스킬로 보호 원본의 같은 SHA256을 열고 REA Ghidra12.1.4의 procedure_info 두 건과 read_bytes 두 건을 수집했다. 가산은98바이트/28명령, 잔액은54바이트/17명령의 완전한 연속 함수 범위다. 정적 메타데이터만으로 실행 결과를 주장하지 않고, 해당 PE/REA 바이트가 같은지 확인한 뒤 두 함수만 Unicorn에 격리 실행했다. 유일한 외부463b50은 명시 데모 반환/메모리 변경 입력 경계다. 원본 게임 프로세스·OS 호출을 실행하지 않았다.

`tools/decomp_ai_wallet_oracle.py`가 가산2400/잔액120, 합계2520행을 생성한다. 두 함수의 모든 명령 주소를 방문했고 모든 입력의 ret/ESP+4/ESI 보존을 확인했다. 결과는 C++/C# 모델이 아니라 실행한 전체 Player1620바이트와 두0xb08 본체의 SHA256·잔액·데모 호출 수다. 원본 파일은 불변이며 fixture SHA256은c842f5c847a5e4076ea3a4dd7ce4ea0e22e88e6d0b4d982f6d25d9f9791a7e29다. 범위 밖 owner9의 접근은 이 Native 정상 입력 집합의 근거에 포함하지 않고 호스트 계약 검사로 구별한다. 데모 중 메모리 교체 입력도 경계의 재조회 계약 검사이며 실제 게임 사건 재현으로 세지 않는다.

Core는 원본2520관측과 비활성/NULL/현재 base 교체·짧거나 해제된 본체·대여 반납·데모 실패 prefix·실제 SP 부모의 float/정수 지갑/화면 순서를 검사한다. Client는 실제 Player owner/전체 Runtime의 지연 종료·다음 Session 재대여·같은 brain 재조회·실패 후 pin 반납과 실제 자산/Host AI 통지 본체를 검사한다. 준비 전 기록과 다른 기록 owner도 확인한다. 신규13(Core8/Client5) 포함 최종 Core51·Client73 합계124건이 통과했다. 최종 Release 오류0/기존 Client 경고3이다. 초기에는 자료 머리글을 데이터로 세던 규약 불일치1건과 테스트의 실제 지역/AI 조립 선행 누락1건이 있었고 수정 뒤 최종 관문에서 모두 통과했다. 주석 머리글 변경 전후2520개 데이터 행은 완전히 같으며 native-header-audit.json에 보존했다.

같은 최종 빌드의 thewarbegins·tutorial1·surrounded 3시작은 모두 종료0, 전체 덤프와34지표가0.812와 같다. 원본1392파일의 전후/기준선 해시가 같고 Game 실행6파일도 전후 불변이다. 검사 복사본과 실행 폴더의 제품 DLL도 일치한다. 전체 회귀 결과로 확대해 판단하지 않는다.

공유 원본 관측 자료는 새 ai-wallet-x86.tsv 한 개이며 Core 단일 소비자다. 기존 fixture manifest426행과 PORT_MAP1534행의 값·순서·base를 보존해 각각427/1539기록으로 늘렸다. Source/보호 문서8파일의 전체 내용도 직전0.814 Git blob과 같다. REA 근거4건을extracted/dotnet-0815/rea-evidence.json으로 내보내고 close_binary를 완료했다.

## 계속 남은 일

일반 Root는 아직 Native 전송을 설치하지 않았고 새 지갑 factory도 전체 Native Reward 장치 조립에서 공급해야 한다. 현재 일반 Root는 이미 실제 Player 기록을 명시했으므로 이번 기본 인자 보완을 Native Root 활성화로 판단하지 않는다. 실제 Menu의 현재 데모 getter와 SP/Editor/Refresh 장치, Source ClientMain447~536의 PostPop 선택 재검사·전송·Resource·Reward·Deletion·표시/음향·Dais/고유 VT/Runtime pin 전체 조립을 계속한다. 새 지갑/AI 진입점을 만들었다는 이유로 전체83VT나 장치 설치를 완료 처리하지 않는다. 기존 PlayerPre/Residence/Dude도 중복 구현하지 않는다.
