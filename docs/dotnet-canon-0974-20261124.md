# dotnetpj 0.974 — Build에 Root 로그인 응답 0x0f 수신기 연결과 Root 송신 후크 정렬

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 같은 장기 기본 표를 공유하는 `ClientPacketDispatch.Build`/`InstallDefaults`에 원문 앱 전역 0x0f Root 로그인 응답 수신기를 연결하고, Root(`ClientHostGame`)의 패킷 후크를 수송 팩토리와 같은 모양(송신 기록·Player 조회·지연 분포)으로 맞췄다. 0x1d Build 연결과 제품 기존 경로는 바꾸지 않는다. 세션·메뉴 결합 후크 중 참가자/전투 묶음(NSInfo·생성·좌석·Tell·번역·안내·표시 장치 필요)과 Root Source 공개·제출 갈래, RU-3 나머지·R4-4 정기 두 단위는 후속에서 잇는다.

## 변경과 원문 대응

- 0x0f 후크는 실제 장기 장치와 0x1d와 같은 호출자 진단·설정·알림 장치를 공유한다. 상태·51×144 기록·갱신 예약·정리·진단은 `connections`·`surface`의 같은 owner이며, 버전 확인은 `ClientMetaVersion.Check` 본체를 재사용한다. 버전 거부이면 next12·+50 0만 쓰고 목록·존을 건드리지 않으며, 일치하면 구역 정리를 실제로 수행한 뒤 서버 값·목록·저장에서 실제 NsInfo 저장소 요구로 명시 실패한다. 구역 정리는 `RawMetaZoneCleanup` 본체를 공유하며 비영 마커 삭제에서만 실제 세션을 pin한다(`ClientStateStorageCleanup.ClearMetaZones`와 같은 계약). 새로 만든 본체가 없다. 0.974에서 추가됐다.
- Root의 `PacketDispatchHooks`에 실제 송신 기록·Player 조회·지연 분포를 묶었다. 수송 backend가 붙기 전까지 호출되지 않는 dormant 후크이며, 동작·판정·덤프를 바꾸지 않는다. `Record` 갈래(0.970)·진단·설정 갈래(0.973)에 이은 Root 후크 정렬의 마지막 조각이다.
- 수송 팩토리(`ClientCampaignTransport.Make`)는 같은 `InstallDefaults`를 공유하므로 0x0f 항목을 자동으로 공유한다.
