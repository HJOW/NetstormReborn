# 0.617 cpp 파서 테이블 덤프와 섬별 J-기준점 확정 (원인 좁히기)

- 일시: 2026-11-18, HJOW-Athlon
- 범위: R4-2 지면 프레임 불일치의 원인 좁히기. cpp 파서를 직접 빌드·실행해 isle 테이블을 덤프하고 DN과 대조한다. 제품 코드 변경은 없다.
- 목표: 0.616에서 막힌 cpp 테이블 확인(g++ 부재)을 cl.exe 도구 체인으로 해결하고, 테이블 가설을 확정·제외한다.

## 원인

- 0.616까지 DN 테이블은 파일과 일치(`GroundTypeTableTests` 317·첫 J 172)하고, J-분류도 cpp와 94%(1275/1353셀) 일치하나, cpp 덤프는 서쪽 섬 J-기준점 280·동쪽 섬 244로 갈린다.
- `terrainstamp-x86.tsv` oracle 780행이 통과하므로 스탬프 논리는 입증됐고, CRT 상수(`511160713`→99회→`296677442`)도 양쪽 덤프에서 일치한다. 남은 용의자는 테이블·성장 코드·후처리 덮어쓰기였다.

## 좁히기 (증거)

- **cpp 도구 체인 확보.** `VsDevCmd.bat`는 python subprocess에서 실행이 실패한다(인용·`/s`·네트워크 경로 오류). 대신 MSVC 루트·Windows SDK 버전을 glob으로 찾아 `INCLUDE`·`LIB`·`PATH`를 직접 설정하고 `cl.exe`를 호출하면 빌드·링크·실행이 된다(14.52.37025·SDK 10.0.26100.0 확인).
- **cpp isle 테이블 덤프.** `RiftTypeDefinition::Parse`+`FrameTable`만 쓰는 임시 콘솔로 tarc의 isle.type을 덤프한 결과 317클러스터·J-first 172·J-count 1이다. DN(`GroundTypeTableTests`)·독립 python 파싱과 세 값이 모두 일치한다. 테이블 가설은 세 방향에서 제외됐다.
- **J-집합 완전 겹침.** DN J-집합 1063셀 = cpp 서쪽 집합 666셀 ∪ 동쪽 집합 397셀과 정확히 일치한다(교집합 666·397, 여집합 0). 같은 셀이 양쪽에서 J-분류를 받는다.
- **차이 구조.** 지면 프레임 차이는 1060셀이 9의 배수(섬별 기준점 차이 72·108 + chosen 차 ±27)이고 나머지만 비배수다. 동일 테이블·동일 CRT·동일 분류에서 chosen까지 같아야 하므로, cpp 섬별 기준점(280/244)은 스탬프 입력(성장 코드·매핑) 쪽에 원인이 남았음을 뜻한다.
- **소유자 격차 확정.** DN 지면 소유자는 전 셀 0인 반면 cpp는 서쪽 섬 1·동쪽 섬 2다. 슬롯 지역 WORD는 양쪽이 1353/1353 일치(서쪽 0·동쪽 1)하므로 지역 자체는 같고, 지역→소유자 배분(DN 미구현 `RawRegionPaint`·`RawRegionOwnership`, R4-2 잔여)이 소유자 차이의 원인이다. 프레임에는 직접 닿지 않는다(FrameAt은 소유자를 읽지 않는다).
- **후처리 덮어쓰기 제외 유지.** `Generate`는 적재 깊이 0에서 실행되므로 `IslandPostPop.Prefix`의 `WriteFrame`이 닿지 않고, 분배 경로도 지면 프레임을 쓰지 않는다(0.616 기록 유지).

## 수정

- 제품 코드 변경 없음.
- `dotnetpj/tools/export_cpp_frametable.py`: 신규. tarc에서 isle.type을 꺼내 임시 C++ 콘솔로 파싱·덤프하고 317·172·1을 단언한다. MSVC 탐색·직접 환경변수·g++ 폴백을 포함하며, 0.616의 "g++ 부재 보류"를 해소한다.

## 검증 (증거)

- `python -X utf8 dotnetpj/tools/export_cpp_frametable.py`: `clusters 317 (기대 317)`, `jfirst 172 (기대 172) jcount 1 (기대 1)`, `C++ 파서 테이블이 DN 테이블과 일치합니다.` 종료 0.
- Release 빌드 영향 없음(도구 스크립트만 추가).
- PORT_MAP 변경 없음.

## 남은 작업 (0.618 이후)

- DN 미구현 지역 칠하기·소유자(`RawRegionPaint`·`RawRegionOwnership`)를 세션 Generate 경로에 연결한다. 소유자 격차의 직접 원인이자 L2 `owner_equal` 개선 항목이다. 프레임 쪽은 J-집합이 이미 일치하므로 소유자 연결 뒤 3경로 재수집으로 프레임 일치율 변동을 함께 확인한다.
- cpp 섬별 기준점(280/244)의 잔여 미스터리는 성장 코드 입력 대조가 필요하면 같은 cl 패턴으로 cpp 성장 드라이버를 확장한다.
