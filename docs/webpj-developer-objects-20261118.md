# WB04-E744 개발자 객체 명령 앞단

`31h`의 `dump`/`d`, `setOwner`/`so`, `destroy`/`de`를 현재 Session의 Pool·월드·소유권 장치에 연결했다. 서버 소유자 변경은 Unpop→부호 있는 BYTE 소유자→Repop 순이며, 클라이언트는 현재 좌표 강조와 로그를 사용한다. 삭제는 서버에서 살아 있는 슬롯에만 전달하고 조회는 강조 뒤 실제 추적 장치를 요구한다.

근거는 기준선 `225553df`의 `RawCampaignSession.cpp` `ExecuteDeveloperCommand`이며 기준선 이후 해당 파일 변경은 없다. 새 원본 fixture나 직접 cpppj 검사는 없다. 선택된 화면 강조·객체 추적 장치가 없으면 해당 위치에서 명시 오류를 내며 다른 개발자 명령도 아직 미연결이다.

독립 검사에서 서버·클라이언트 분기, 효과 순서, 소유자 부호 확장과 SID 경계를 확인했다. Tutorial 1 Session의 실제 `31h` 분배기에서 반환된 객체 삭제 요청이 무시되는지 확인했다. 관련 집중 검사 41건이 통과했다. 실제 게임 플레이나 객체 변경의 화면 결과는 이번 검사가 아니다.

Node v26.13.0 전체 회귀 6,230건을 통과했다. 대응표 오류는 0건이며 Node v22 전체 재검사 주기는 6/8회다.

다음은 `31h`의 나머지 개발자 명령과 내부 로그인 서버 후반·응답 왕복이다. Native 분기, 행 base 뒤 변경 판정 및 앱 미션 연결도 남아 있다.
