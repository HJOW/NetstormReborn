# dotnetpj 튜토리얼 후속 안내·게임 시각 타이머

2026-10-13, **작업/마지막 디컴파일 PC: HJOW-Athlon**. AGENTS.md와 두 인수인계를 읽고 cpppj GumpForm 작업을 마무리한 뒤 사용자 요청으로 dotnetpj를 진행했다. 앞선 cpppj 코드·근거 파일을 보존했다. 이 PC의 창 실행 허용 지시를 확인했으며 이번 단계는 정적 분석과 컴파일로 진행했다.

[초기 브리핑 10/재개 7프레임](dotnet-dialog-frames-20261013.md)의 후속으로 **튜토리얼 1·2 단계 판정을 실제 화면 프레임에 연결**했다. 다음 단계 안내의 **0.5초 게임 시각 지연→연속 10프레임**, 튜토리얼 2의 **2·4초 임시 타이머**, 보정 안내의 동기 정지를 추가했다. 9-1 A 전체 완료나 원본 동작 대조 완료를 뜻하지 않는다.

### 디컴파일 C의 시간 변환 보정

004c33f0의 C 출력에는 현재 게임 시각을 float로 변환하는 식이 나타난다. 실제 기계어는 **004c3423 `fld DWORD [esi+80]` → 004c3429 `fadd QWORD [0055b4d0]` → `fstp QWORD`**다. 따라서 현재 시각의 double을 유지하고 지연 float만 확장했다. 시간 합/포함 경계의 독립 PE/C# 비트 대조는 아직 수행하지 않았다.

## 후속 안내 잠금

`MissionDialogFrameGate`를 기존 초기/재개 잠금과 공유한다. 단계 예약 시 현재 게임 시각+0.5f를 다음 시각으로 저장하고 카운터를 10으로 둔다. 초기 A. 요청 여부는 별도 필드로 보관하여 후속 잠금이 생겨도 초기 브리핑을 다시 요청하지 않는다.

화면 프레임에서 다음 시각에 도달했거나 실제 게임 시계가 정지한 경우에만 카운터를 판정한다. 그 시점에 다이얼로그가 있으면 10으로 되돌리고 없으면 1을 줄인다. 시각 미도달 중에는 다이얼로그에 의한 재설정도 하지 않는다. 0이 된 호출에서만 현재 단계의 안내를 연다. 이는 **0.5초 경과 후 화면 프레임 10개**이며 10/24초를 더하는 식으로 환산하지 않는다. 정지 중 조건은 시간 지연을 우회할 수 있다.

현재 안내/외부 도움말·옵션/Leave 확인을 다이얼로그 차단으로 전달한다. 지식/컨텍스트/미션 메뉴는 기존 팝업 판정을 사용한다. 전체 Gump 등록·지연 삭제와 클론 모든 창의 정확한 대응은 아직 독립 대조하지 않았다.

후속 안내가 실제로 열리면 기존 OpenStage가 F8 복귀 지점을 기록하고 루트 팝업을 닫으며 같은 ScriptDialog 정지 소유권을 잡는다. 안내가 없거나 설정만 실행하는 섹션이어도 잠금 요청은 한 번이다. 안내 종료 후의 재개는 기존 7개 빈 화면 프레임이며, 후속 잠금이 남은 동안 재개하지 않는다.

## 화면과 규칙 세션 연결

`BattleSession.TutorialFrames.cs`는 화면과 같은 잠금/보정 Tell 콜백을 보관한다. 실제 지도에서 `ConnectTutorialScreenFrames`를 연결하고 `FortMapViewer.Update`의 `finally`에서 다음 순서로 한 번 처리한다.

1. `BattleSessionFrameClock.RawGameSeconds`의 현재 원본 게임 시각을 고정한다.
2. 초기/후속 안내 잠금을 판정하고 필요하면 현재 단계 안내를 연다.
3. 기존 재개 7프레임을 판정하고 실제 정지 소유권을 동기화한다.
4. 남은 단계 잠금이 0일 때 튜토리얼 함수 1·2를 한 번 호출한다.

이 연결에서는 `ProcessCommands`와 따라잡기 `Step`이 튜토리얼을 다시 호출하지 않는다. 규칙 틱이 **0개인 화면에도 한 번** 판정하고, 여러 틱을 처리한 화면도 한 번이다. 지식/안내/메뉴/외부 입력 차단의 조기 반환에서도 같은 `finally`를 거친다.

원본은 **정지 중에도 잠금이 0이면 단계 함수를 호출**한다. 신전/워크샾 단계의 옵션·기술 허용, 회수 허용, 임시 타이머 기록·선택 정리 같은 처리도 유지한다. 단계 증가 함수는 실제 정지/남은 잠금을 확인하고 거부한다. 초기/후속 10프레임이 남은 동안에는 단계 함수 자체를 호출하지 않는다.

F4 복귀/회수의 성공 사건은 이번 화면 전용 목록에 보관한다. 일반 화면 알림의 Drain 이후에도 읽을 수 있지만, 매 화면 판정 뒤에는 지운다. 차단한 이전 화면의 사건이나 같은 틱에 남은 사건 전체를 다음 화면에 재생하지 않는다. 원본 실제 명령 ID/명령별 호출 순서 전체의 복원은 후속이다.

## 튜토리얼 2 임시 타이머

실제 화면은 +98에 대응하는 `TutorialStages.TimerSeconds`를 사용한다. **현재 원본 게임 시각+double 간격**, 없음 표지 0, 포함 만료 경계를 유지하며 24Hz 틱으로 올림하지 않는다.

- 단계 C: 선택이 신전일 때 2초 타이머를 시작한다. 만료 후 NotVortex를 요청하고 선택을 푼다. 선택 해제만으로 타이머를 지우지 않으며 만료 확인은 신전 선택 조건 안에 남는다.
- 단계 F: 신전 선택에서 4초 타이머를 시작한다. 이후 선택이 바뀌어도 예약을 유지하고 만료되면 단계 진행/선택 해제를 수행한다.
- 단계 H: 회수를 허용하고 이번 화면의 회수 성공 사건에서 2초 타이머를 시작한다. 만료 시 단계 진행을 요청한다.
- 단계가 실제로 증가하면 임시 타이머를 0으로 지운다. 정지 때문에 증가를 거부하면 그 값은 유지한다.

NotVortex는 코어가 화면 콜백으로 즉시 연다. 실제 Tell이 성공하면 정지 소유권과 팝업 정리를 바로 반영하므로 같은 C 판정에서 덱 조건도 충족한 경우 뒤의 단계 증가가 거부된다. 섹션이 없어 열지 못한 경우에는 새 정지를 잡지 않는다. 다음 단계 안내를 조건 달성 순간에 즉시 열지 않는다.

## 헤드리스·진단과 한계

화면 연결 전 헤드리스의 기존 ProcessCommands/RunTicks·TimerTick·즉시 안내 이벤트는 유지한다. 이는 기존 합성 진행 API의 호환 경로이며 원본 실제 화면 시간 모델의 완전한 대조 결과가 아니다. `TimerTick`은 실제 화면에서는 진단값이고 판정은 TimerSeconds를 읽는다.

화면 연결 시에만 실제 시각·절대 타이머·잠금/재개·이번 화면 명령을 검사합에 추가했다. **실제 화면의 검사합 숫자는 달라질 수 있다.** 자동 진단에 `stage-at`/`tutorial-time`/`tutorial-timer`를 추가하고 사용자 게임 화면에는 구현 값을 표시하지 않는다.
