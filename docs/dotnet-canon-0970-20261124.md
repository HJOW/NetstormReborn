# dotnetpj 0.970 — Build에 전투 시작 1a/1b 수신기 연결과 Root 기록 갈래

2026-11-24, HJOW-Athlon. R4-6 전송·수신 묶음이다. 같은 장기 기본 표를 공유하는 `ClientPacketDispatch.Build`/`InstallDefaults`에 원문 앱 전역 1a/1b 전투 시작 수신기를 연결하고, Root(`ClientHostGame`)의 실제 기록 조회·열기를 묶어 1a/1b의 기록 갈래를 연결했다. 2번 Build 연결과 제품 기존 경로는 바꾸지 않는다. 세션·메뉴 결합 후크 중 0x1d/0x66·0x0f/0x26·참가자/전투 묶음과 Root Source/Record/Sent 중 송신·제출, RU-3 나머지·R4-4 정기 두 단위는 후속에서 잇는다.

## 변경과 원문 대응

- `ClientPacketDispatch.Build`/`InstallDefaults`는 선택적 `recordRequested`·`openRecord`를 받는다. 없으면 요청 0(기록 미열기)·열기 명시 실패(R7)이며, 수송 팩토리(`ClientCampaignTransport.Make`)는 기본값으로 같은 표를 공유한다. Root는 `PacketRecordOwner.Requested`·`Open`을 넘겨 기록 갈래를 연결한다. 0.970에서 추가됐다.
- 1a/1b 후크는 실제 장기 장치만 묶는다. 상태·ZonePending·게임 포트·구독자·검사·진단·복제 장부·연결 끊기는 `connections`·`game`·`surface`의 같은 owner이며, Source 선택은 같은 `PacketSources` 장부에서 최신 실제 coordinator만 고른다. 1a/1b 수신의 상태 쓰기·복제·연결·기록은 원문 순서대로 수행한 뒤 next7/current7 인계 앞에서 실제 UI State 부모 요구로 명시 실패한다. 메뉴가 있을 때의 성공 합성과 미설치의 침묵 통과를 모두 두지 않는다. 새로 만든 본체가 없다.
- `ClientHostGame.InstallClientPacketDispatch`는 실제 기록 조회·열기를 묶는다. 종료·닫기·반납은 수송이 없어 계속 명시 거부한다.
