# WB04-E1471 공통 모드 공개 API와 적합성 입력

공통 v0.1.0을 `webpj/www/modding/mod-api.js`의 순수 `ModRuntime`으로 구현했다. 게임 참조·주소·원본 명령 번호는 받지 않고 등록/사건 동안의 조회 사본·구독·독립 RNG·제한된 명령/로그 출력만 만든다. 실제 Session/큐·격리 실행·관리 화면은 다음 단위이며 아직 제품에서 모드를 실행하지 않는다.

공개 이름/버전/한도를 공통 JSON과 정확히 대조한다. 조회/사건은 사본이며 getter/심볼/빈 배열칸/순환/과대/비유한 데이터는 경계를 통과하지 않는다. 구독은 사건 시작 목록으로 실행하고 게임 시간 역행·사건 번호 누락·다른 미션 전달을 거절한다. 처리되지 않은 예외/비동기 반환이면 해당 인스턴스를 반납하고 미반영 출력은 폐기한다. 입력은 클릭/키 요청 값으로만 정규화하며 아직 큐에 쓰지 않는다.

공통 적합성 디렉터리에 같은 `.nsmod.json` 패키지·다섯 사건/상태 경계·WB 기준 출력, Python 정수 연산으로 독립 계산한 RNG 벡터3개/24표본, V8 sin/cos/atan2/pow 29개 double 비트 입력을 고정했다. WB 기준 출력은 원본 게임/DN 실행 오라클이 아니다. DN 구현 중지 및 MOD-2~5 미완료를 유지한다. 이 명세 보강에서 명령 결과에 원래 요청의 eventSequence를 포함하고 사건 번호의 정확한 증가·시간 역행 금지를 명시했다.

검증: 새 공개 API20건과 기존 InputQueue 원자성2건, 합계22/22·실패/취소/건너뜀0. 최초 ESLint는 사용하지 않는 private 필드1건으로 실패했고 해당 필드를 제거한 뒤 전체 검사 종료0이다. 운영 빌드도 선행 ESLint 뒤 종료0(webpack60.979초), 번들3,517,946바이트로 기존과 바이트 동일하다. 아직 참조되지 않는 새 공개API 파일은 운영 번들에 추가 실행되지 않는다. 별도 재번들 바이트 일치 검사1/1도 통과했다(148.906초). 실제 게임 실행은 이 단위에 없다.

다음은 호스트에서 출력/명령을 다시 검증하고 같은 원래 InputQueue에 원자적으로 추가하는 층, 실제 Session의 사본 조회·이벤트/게임 시계 장벽, 격리 로더/관리/보관, 브라우저 적합성 순서다. 현재 정기 주기는 Node26=2/4·Node22=6/8이며 마지막 전체는 E1469의6934건이다. 새20건을 포함한 다음 전체 예상은6954건이고 실제 수를 최종 결과로 사용한다.
