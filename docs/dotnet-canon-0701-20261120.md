# 0.701 로컬 미션 상태 전이와 실제 블록 별칭

`RawLocalMissionState.cpp/.h`의 Request·Poll·Run과 상태7~10/13/14를 Core에 이식했다. 다섯0x90바이트 블록은 같은 실제720바이트를 빌린다. immediate+84의 메뉴창은 `UIntBox(Memory<byte>)`로 같은4바이트를 공유한다. 기존 자체 값과 내부ref 소비자는 유지하고 외부 DWORD를 빌릴 때 Value/ref/외부 쓰기가 모두 같은 저장소에 반영된다.

상태7은 정리 전 Zone·조건부 시각/출처 보관, 제목 첫BYTE0, 정리/CD결과/명령창, 현재 재접속 표식 재조회, 실제 Zone의 설치 후 핸들 재조회/반납, Renderer/UI, 주변음 기한과 즉시8 요청을 원문 순서로 실행한다. 상태13은 주소 조회 전에 선택한 실제 Core 메모리를 유지하고 callback 뒤 현재 Template owner는 따로 읽는다. 주소의 family별 포트·시각 하위DWORD·revision/BYTE·재접속SP를 보존한다.

상태9 timeout과 큰 부모의 조기 반환은 공통 확정을 수행하지 않는다. 나머지는 전체 블록을 old/phase로 확정한 뒤 현재 첫DWORD만0으로 쓰고 즉시 요청이 있을 때만 같은Run을 이어간다. 송신 중 실제 수신은 큐에 예약하고 확정 뒤 분배한다. 실행 중 중첩Run/분배는 거부하며 예외가 나도 실행 guard를 회수한다. 큰 메뉴·메타 부모와 상태15 서버 인수는 선택된 실제 하위가 필수이며, 제품Root에는 아직 설치하지 않았다.

독립 원본 `local-mission-state-x86.tsv`의33입력 전부에서 다섯 블록720바이트·현재 전역15개·두double 타이머·Core192바이트·효과 순서가 일치했다. 고정 trace의 Seed/Cursor 이름은 기존 관찰 명칭이며 실제 의미는 CD 확인/Renderer 경계다. 추가 검사는 실제 DWORD의ref/외부 별칭과 canary, 상태10 확정 뒤 큐 수신/꼬리 추가, 누락 효과의 중간 쓰기와 재시도, 메타 callback 뒤 현재 flags/next 재조회, 큰 부모의 반환 종류, 현재 주소20바이트 별칭, 공통 상태4/12/14/16과 인수15→16을 확인했다. 일반 전투의 동시접속 listener·두난수 밀도 호출·채팅40h/80h 순서와 기존 주변음 기한77→110.5도 확인했다. 이 일반 전투 추가 검사는 C++ 몸체를 근거로 하며33개 native 관측 범위에는 포함되지 않는다.
