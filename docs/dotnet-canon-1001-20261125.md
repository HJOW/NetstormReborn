# dotnetpj 1.001 — R4-7c2 CD 장면 대조

2026-11-25, HJOW-Athlon. R4-7 데모와 보류 검사 묶음의 R4-7c2 단계다. F3에서 미룬 검사 중 두 장면
(`FortWorldLoadBindingTests` 전체 월드 장면·`NormalTerrainWorldBindingTests` 3장면)의 CD 행을 DN 실제
CD 장면으로 재현 실행하고 원본 CD 골든과 대조했다. 표면 월드 CD 조립이 없어 막혀 있던 부분을 제품 코드에서
연결했다. 전체 회귀는 6,939통과/실패0을 유지한다.

## 변경과 원문 대응

- `dotnetpj/src/Netstorm.Core/Original/RawSurfaceWorld.cs`: 저장소와 같은 수의 TYPE 표를 빌린 CD 171개
  월드도 실제 실행기를 조립한다. 저장소 없는 CD 껍데기와 패치 조립 조건은 그대로 둔다. 근거: F3 보류 장면의
  CD 재현. 1.001에서 추가됐다.
- `dotnetpj/src/Netstorm.Core/Original/RawGraph.cs`: CD 풀에는 171개 TYPE·프레임 표도 받는다. 기존 검사가
  쓰던 188개 표도 CD 풀에서 그대로 받는다. 근거: 같은 CD 재현. 1.001에서 추가됐다.
- `dotnetpj/src/Netstorm.Core/Original/RawSquidFactory.cs`·`RawSquidDestroy.cs`·`RawPostPop.cs`·
  `RawSquidReward.cs`: 같은 188·171 허용을 적용했다. `RawSquidReward`는 CD 장면에서 SP 저장소 없이도
  만들 수 있고 지갑 가산에서만 저장소를 요구한다. 근거: 같은 CD 재현. 1.001에서 추가됐다.
- `dotnetpj/src/Netstorm.Core/Original/RawSidPool.cs`: `ServerFirstValue`·`PredictableFirstValue`를
  판본별 실제 경계(CD 6000·14000)로 읽는다. 0.609 하네스(15000·23001)는 CD 생성 진단과 어긋나 CD 재현을
  막았으므로 실제 경계로 바꿨다. 슬롯 폭 하네스(50바이트)는 그대로다. 근거: 같은 CD 재현. 1.001에서 추가됐다.
- `dotnetpj/src/Netstorm.Core/Original/RawPostPop.cs`: `Validate`의 지원 표 조회를 판본별로 한다(원문
  `SquidPop::Supports(판본)`와 같게). DN `Pop` 사전 검사는 이미 판본별이므로 패치 동작은 그대로다. 소유자·
  추가 바이트 오프셋을 판본별로 읽는다(패치 34·40, CD 32·35). 근거: 같은 CD 재현. 1.001에서 추가됐다.
- `dotnetpj/tests/Netstorm.Core.Tests/FortWorldLoadSceneTests.cs`: 두 판본 골든 행을 각각 실행한다.
  1.000에서 패치판만, 1.001에서 CD판을 이었다.
- `dotnetpj/tests/Netstorm.Core.Tests/NormalTerrainWorldSceneTests.cs`: 장면을 판본별로 조립하고 두
  장면을 두 판본에서 실행한다(거부 검사는 패치판만). 1.000에서 패치판만, 1.001에서 CD판을 이었다.
- `dotnetpj/tests/Netstorm.Core.Tests/FortObjectLoadTests.cs`: 실제 CD 경계(서버 6000)에 맞게 서버 SID
  기대값을 고치고 예측 진단이 나지 않음을 명시한다. 하네스 시절(서버 15000·진단 복귀) 주석을 바꿨다.
- `dotnetpj/tests/Netstorm.Core.Tests/FarmClusterTests.cs`: 고객 영역을 판본별 끝까지 확보한다(패치
  5~14998, CD 5~5998). CD 장면 풀을 서버로 만들고 서버 목록 전체를 확보한다.
  1.000에서 패치판을, 1.001에서 CD판을 이었다.
