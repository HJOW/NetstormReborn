# 몽키 시험과 미니맵 확인 (WB04-E1128)

사람이 하는 조작을 흉내 낸 임의 조작과 좌하단 미니맵 상호작용을 실제 Chromium 에서 확인하는 시험을 더했다. 앱 코드는 바꾸지 않았다.

## 몽키 시험 (`e2e/monkey.spec.js`)

- 환경 변수 `NETSTORM_MONKEY_SECONDS` 를 정한 실행에서만 돈다. 캠페인 1-1(시드 둘)과 스커미시(AI 3명) 세 조합에서 고정 시드의 난수로 맵 왼쪽 클릭·오른쪽 클릭(35%·25%), 단축키 29종(P·R·N·Q·W·A·S·Z·Y·X·E·Esc·F2~F9·Shift+F9·T·Tab·Enter 등, 25%), 왼쪽 HUD 클릭(7%), 안내 창 닫기(8%)를 150ms 간격으로 섞는다.
- 페이지 오류가 나거나 입력 큐 머리가 0.75초 넘게 남는(먹통) 순간 바로 멈추고 마지막 조작 8개와 큐 머리 코드를 알려 준다. 시드가 같아 같은 조작열을 다시 만들 수 있다.
- 조사 결과: 세 조합 모두 150초 동안 오류·먹통이 없었다(미션을 떠나는 일도 없음). 조사 중 알려진 `Islandlist.cpp:676 bcr.isValid()` 표시 진단만 오류로 세지 않는다.
- 한계: 임의 좌표라 건물·유닛에 맞는 확률이 낮아 깊은 경로(메뉴 항목 실행 등)는 잘 닿지 않는다. 장시간 진행(`campaign-long-run`·`skirmish-long-run`)과 함께 보완 수단으로 쓴다.

## 미니맵 (`e2e/minimap.spec.js`)

캠페인 1-1 에서 미니맵 왼쪽 위 쪽을 누르면 카메라가 20 이상 멀리 이동하고(화면에서도 시점 사각형이 옮겨 감), 누른 채 끌면 카메라가 계속 따라가며(10 이상), F5(내 사제 보기)가 시작 시점 쪽으로 되돌림을 확인한다. 오류 0. LEFT_JOBS 의 'Uber HUD 나머지' 에 남아 있던 '미니맵 클릭·드래그 실사용' 을 이것으로 확인했다.
