# dotnetpj 0.845 — 건설 상태 codec·수신과 Native 기본 writer

2026-11-23, HJOW-Athlon. 기존 ConstructionProcess에 Source0x37 상태 쓰기/읽기/수신과 실제 Host/패킷 등록을 연결했다. 실제 전체 Native Root/Load·Editor 공개는 계속 미완료다.

## 변경

- 새 `RawConstructionData.cs`는 Source `RawConstructionData.cpp/.h`의 의미 필드 codec과 두 생성 경로/실제 수신을 이식한다. 같은 fields의 Dirty/Start/End/Sound/Additional, 부모 인자와 force·길이·미작성 tail·정상 끝 dirty0을 보존한다. 최대30BYTE의 부족 쓰기는 변경 전에 거부하며 Read는 선택 저장 직전 검사해 앞선 부분 효과를 유지한다. IEEE64비트는 산술 없이 복사한다.
- Receive는 최초 Form/mask를 캡처하고 free의ff/live의부모bit 진단 뒤 현재 packet/PID/TYPE를 다시 읽는다. hooks 함수는 값 복사한다. 실제 새 객체 수신은 같은 Pool의 ConstructionProcess/Host/Kernel로 소유권을 넘기며 다른 Pool·부모 DWORD 상위/범위 오류를 거부한다. 미설치/NULL 필드·할당 실패를 성공으로 바꾸지 않는다.
- `RawGameAuxState.ConstructionHeader`는 현재37/1 BYTE를 장기로 보관한다. 일반 준비가 재초기화하지 않는다. Native `SerializeProcessForm`의 실제 ConstructionProcess 분기는 같은2048BYTE/현재 헤더로 `WriteProcess`를 호출한다. actual 부착/PID/FormPacket에서 같은 객체와 미작성 tail을 확인했다.
- Net의 `RegisterConstructionData`는 같은0x37칸의 observer를 지우고 version1/mismatch0과 실제 수신을 등록한다. 길이/송신자/연결에 새 정책을 넣지 않는다. 변수 길이0x37의 이 등록 API를 나머지8고정26F 완료로 세지 않는다. 실제 Root 전체 등록 부모는 후속이다.
- 기존 `constructiondata-x86.tsv`의3PE×1780=5340관측을 Core한 소비자에 링크했다. fixture454개이며 이전453행의 값/해시/순서를 보존했다. PORT_MAP 이전1648행을 보존하고 새 codec/등록 파일에4쌍을 추가했다. 자료1652(port1164/L1 481/session7), 대응627/1240단위106,278/169,438줄·미대응613단위63,160줄이다. 부분 이식을 포함하는 대응 집계다.

## 검증과 한계

처음 관문은 PATCH codec 관측이 통과했고 CD2관측의 raw 슬롯 비교가 실패했다. CD 원문36BYTE와 관리 Pool50BYTE를 구분해 원문 prefix와 추가 영역 보존을 각각 대조했다. 이어 CD Wrapper의 실제 Host를 만들려다 기존 RawSquidDestroy의188TYPE 전용 경계에 도달했다. CD Host 제품 복원을 주장하지 않고 CD 래퍼가 읽는 실제 객체 fields/식별자만 입력으로 공급했다. PATCH 래퍼/새 수신/등록은 실제 Host/Kernel에서 검사했다. 제품의 삭제/TYPE 보호 조건은 완화하지 않았다. 첫 두 로그/TRX를 보존했다.

최종 새7사례 포함 집중23/23 및 확대 Core179·Client72 합계251건 통과/실패0이다. 세 PE의5340행은 필드7항목·사건·부모 출력·전체 packet·원문 raw/호스트 추가 영역을 대조했다. 실제 PATCH Host의 새 서버 Form/현재PID·부분 갱신, 0x37 등록/수신 시각/기록 깊이, 부족 쓰기 무변경/부족 읽기 prefix, Native 부착/현재 헤더/일반 준비 보존·FormPacket을 확인했다.
