# dotnetpj 1.080c 관측 — 미니맵 화면과 채팅창 겹침

2026-11-27, HJOW-Athlon. `thewarbegins`를 1024×768, 영어, 고정 시드
1760000000·25ms·100프레임으로 각각 실행해 논리 BMP를 수집했다. 양쪽
실행 종료 0이며 원본 1,392파일은 전후 불변이다. 실행과 이미지:
`extracted/dotnet-l4a-1080-minimap/`.

화면 왼쪽 아래 80×75 영역은 CPP와 DN의 RGB 6,000픽셀이 모두 다르다.
CPP에는 검정 바탕과 지도·카메라 선이 보이고 DN은 RGB (83,80,81)의
단색이다. DN의 같은 단색 영역은 x=0~191, y=668~767에 걸쳐 있으며,
미션 시작 코드에서 200×100 채팅창을 (0, 화면 높이-100)에 부착한 위치와
일치한다. 이 관측은 미니맵 자체의 픽셀 일치를 판정할 수 없음을 뜻한다.

정적 추적: 미니맵 공장은 장기 저장소 생성자를 사용하고 실제 미션의
`BindWorld` 호출은 없다. 따라서 현재 Pop/Unpop 변경 알림도 미연결이다.
`Refresh`를 진입 때 한 번만 호출하므로 이후 지형·카메라 갱신 경로도
검증되지 않았다. 종료 시 `RawMinimapControls.Dispose` 호출 또한 호스트에
없다. 이들은 관측된 코드 상태이며 수명 시험 완료를 뜻하지 않는다.

다음은 CPP `UberRootGump::Layout`·`HudDock`의 실제 자식 등록과 채팅창
기하/표시 상태를 제품에 연결하고, 같은 월드의 Pop/Unpop 연결·프레임
갱신·종료/실패 반납을 검증하는 것이다. 임의로 채팅창만 숨겨 픽셀을
맞추지 않는다. R5-4c3c와 R5-4d는 미완료다.
