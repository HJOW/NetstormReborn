# 1.191a 미니맵 재생성의 현재 카메라 crop 복구

1.191의 독립 리뷰에서 카메라를 이동한 뒤 State로 미니맵을 재생성하는 경우를 보강했다. 노드 생성자는 새 기하를 만들지만 공유 dirty 캐시의 카메라/사각형은 종전 값이다. 두 입력이 같고 큐도 비어 있으면 첫 Refresh가 Rebuild를 생략해 crop이0으로 남았다. 기존 카메라0의 재생성 검사로는 드러나지 않았던 결함이다.

제품1.191 DLL을 참조한 별도 신규 회귀 검사에서 카메라(256,192)의 cropX **기대48·실제0** 실패를 먼저 보존했다(`extracted/dotnet-1191a-minimap/before.txt`). 원본 `Open`과 같이 새 노드를 만든 경우에만 `FullRefresh=1`을 예약하도록 수정했다. 기존 노드의 반복 부착이나 카메라 요청에 전체 갱신을 추가하지 않는다.

소스 한 타입을 별도로 컴파일한 확인은 통과했으나 이를 정식 통합 검사로 세지 않았다(`after-source.txt`). 이후 실제 Release 제품/검사 통합 빌드에서 이동한 카메라의 crop·전체 픽셀 복원·동일 bitmap·반복 부착의 갱신값 불변을 포함한 미니맵 **17/17 통과**를 확인했다. 같은 실행의 HUD/생산/실제 자산/자료 목록을 포함한 전체 집중은61/61이다(`extracted/dotnet-1193-tests/hud.trx`). 전체 State 부모와 AI 생성 차이·실제 미션 전환 완료를 뜻하지 않는다.
