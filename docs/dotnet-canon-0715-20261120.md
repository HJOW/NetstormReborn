# 0.715 고정 App 수신기와 실제 Session 엔트리 분배

cpppj의 NativeLoginPacketReceivers.cpp/.h와 RawCampaignSession.cpp의 고정 수신 분배를 같은 실제 장기 소유자에 연결했다. 15행의 주소·길이·버전·observer 종류를 보존하며 기존 67h App 전역 F는 설치 시 그대로 둔다. 나머지 14F 중 52h는 현재 장기 Player 기록에 직접 쓰고 64h는 같은 장기 활동 표를 사용한다. 두 본문은 Session·연결·payload를 요구하지 않는다. 나머지는 배송 때 현재 실제 HostSession과 전체 HostMissionRuntime을 빌려 불변 Native 엔트리로 분배하며 현재 packet 종류나 등록표로 함수를 다시 선택하지 않는다.

Session의 현재 Login 묶음은 기존 실제 서버/클라이언트/metadata 본문을 사용한다. 같은 Player 물리·현재 Player 상태·옵션 물리를 검증한다. 두 동맹 본문은 Login 없는 Editor에서도 같은 참여 모듈을 사용한다. 3dh는 입력 부분뷰 자체의 self bit를 수정해 같은 물리를 방송하고, 78h는 최초 선택한 Login을 보유해 양방향 동맹·방송 뒤 해당 상태 효과를 호출한다. Login이 없으면 Editor 상태 효과를 사용한다. 도달한 위치에서만 효과를 요구해 앞선 부분 쓰기와 방송을 보존한다. 실제 Player 고정뷰 반납은 자식 정리 뒤 이 모듈 참조도 해제한다.

Client 집중 27건이 모두 통과했다(신규 14건, 기존 Player/Runtime/활동 13건). 근거는 `extracted/dotnet-0715/client-initial.log`와 `native-login-initial.trx`다. 15행 전수 metadata·같은 F 대여, 여섯 불일치 거부, observer 진단 뒤 현재 필드 재조회, 장기 직접 수신과 외부 함수 교체, 등록표/packet 번호 변경 후 저장된 F, 현재 Login 교체, 실제 Runtime 배송 중 Player 반납 거부, 실제 예외 복귀와 외곽 종료, 동맹 물리 부분뷰·현재 Login 보유·미연결 상태 효과의 부분 쓰기를 확인했다. 빌드의 기존 TerrainCarrier nullable 경고 3개는 그대로다.

제품 Root의 전체 Login/상태/전송 bridge 설치는 아직 남아 있다. 불완전한 전체 bridge를 실제 시작 경로에 설치하지 않았으며 이번 단위만으로 실제 Login→Ready→Start 완료나 M1 개선을 판정하지 않는다. 실제 포획/희생·특정 적 공격·승리 재현은 하지 않는다. 다음 0.716에서 전체 검사와 65 시작 실행을 수행하며, 0.714의 Player 헤더 변경을 별도로 감사한다.

PORT_MAP에 고정 App 설치 2행과 실제 Session 분배 2행을 추가했다. cpp_sync 종료 0이며 기존 연결 fixture 360개는 그대로다. 원본·CD·AGENTS.md는 수정하지 않았다. 전체 목표는 미완료이며 다음 구현은 기존 월드/건설 효과의 실제 Runtime pin 결선과 전체 Login/상태/전송 부모 연결이다.
