# 1.212 장기 음향 통합 뒤 Client 전체 재검증

1.211b의 동결 검사 DLL로 Client 전체를 다시 실행했다. **3,105통과·실패0·종료0**,6분8초다. `--no-build --no-restore`와 `NETSTORM_DATA=extracted/dotnet-oracle-data`를 사용했으며 이번에는 빌드하지 않았다. 원시 자료는 `extracted/dotnet-1212-Client.log`·`extracted/dotnet-1212-regression/Client.trx`·`summary.json`이다. 무응답 진단이 실행을 중단하거나 덤프를 만들지 않았다.

1.210에서 실제로 검사한 변경 없는 Assets383·Core4121을 합치면 **7,609통과·실패0**다. Core/Assets 소스는1.209 이후 바뀌지 않았고 fixture/기대값도 이번 단위에서 변경하지 않았다. Assets/Core를 이번에 재실행한 것은 아니다. summary에는 각 TRX 출처·실제 결과·이번 재실행 여부·제품5개 관리 DLL과 검사 DLL SHA를 보존했다. 게임 DLL은1.211과 같은 `ccc4da2dde700436fcb0cce3d3d598e03e79142118eedbe9cf6fd72ced9d9bed`다.

Client TRX 총3,107개 결과 중 두 Explicit 음향 검사는 `NotExecuted`다. 실제 결과의 Passed3105/NotExecuted2를 VSTest Counters.notExecuted0과 구별한다. 기본 회귀의 미실행을 성공으로 바꾸지 않는다. 기존 효과음 하드웨어는 [1.209](dotnet-canon-1209-20261128.md)에서, 새 음악/worker·재열기/반납 하드웨어는 [1.211](dotnet-canon-1211-20261128.md)에서 각각 별도1/1 통과했다. 이 두 실행을 이번 기본 회귀의 실행 수에 더하지 않는다.

1.210의 `ErrorLogTests.StandardStreamsTeeToBuffer`와1.211 첫 집중의 `MusicRuntimeTests.ShutdownWaitReleasesCommandGateAndRejectsNewPlay`가 이번 전체에서도 각각 Passed임을 확인했다. 기존 공통 BurningContext의 HWND0 조립에서 실패했던 검사들도 포함해 전체가 통과했다. [1.210 최초 실패](dotnet-canon-1210-20261128.md)·[1.210a 검사 격리](dotnet-canon-1210a-20261128.md)·[1.211 최초 집중/교정](dotnet-canon-1211-20261128.md)의 기록은 보존한다.

fixture521개·PORT_MAP1942행은1.211과 같으며 동기화 종료0은 `extracted/dotnet-1211-sync.log`의 근거를 사용한다. 실제 게임 세 미션과 sound0/music1 Main의 HWND·장치·worker 생성/반납, 덤프·여섯 화면·보호1,392파일 불변은1.211의 별도 실행 근거다. 이번 Client 전체 검사를 새 게임 진입/원본 해시 수집이나 전체 L2 재수집으로 표시하지 않는다.

장기 음향 owner 통합과 기존 전체 회귀 실패 교정은 재검증됐다. 다음은 [Scene 후속 A–H](dotnet-scene-followup-plan-1211-20261128.md)의 실제 현재 공유 값·월드 조회·파일 팔레트/소비자·Thunder·감독/Start/Frame·State 호출자다. 메뉴 음향/옵션 UI·전체 State GUI 왕복·AI 진행과 미니맵1픽셀·동시각 M1/L4a는 아직 미완료다. 준비 중인 ignored 초안을 제품 완료로 세지 않는다.
