# 0.723 실제 Client 프레임 실행 순서

실제 ClientHostGame.Update를 원문 ClientMain의 현재 연결 가능한 단계 순서로 수정했다. 고정 시각 전진 뒤 같은 Frame을 캡처하고 음향 프레임/메뉴 Tick/편집 Poll을 진행한 다음 스크립트와 실제 입력을 처리한다. 설정 저장 뒤 주변음→바람을 실행하고, 지연 삭제/Idle과 연소 표시 준비 뒤 Kernel을 실행한다. 종료 입력은 이 후행 갱신들을 실행하지 않는다. 이전에는 Kernel을 입력·주변음·바람·표시 준비보다 먼저 실행하고 있었다.

PrepareNativeFrameInput은 실제 BeginFrame의 캡처 콜백에 연결했다. 같은 시계·현재 세션·현재 메뉴를 기존 장치로 호출하며, 시간을 추가로 전진하거나 난수 상태를 보정하지 않는다. 아직 연결되지 않은 연결 감시/SceneFrame/미니맵/전투 후처리를 빈 단계로 만들지 않았다. 미션 없는 Client의 장기 Surface/주변 환경과 영화 갱신 잠금도 후속 범위로 남긴다. 이번 연결이 전체 원문 루프 복원 완료를 뜻하지는 않는다.

기존 Client 프레임/Native prefix/입력 스크립트/실제 Player·Priest·Process 경계 집중 95건이 모두 통과했다. 검증은 extracted/dotnet-0723/client-initial.log 및 client-frame-order.trx에 있다. 기존 소스의 nullable 경고 3건은 유지됐으며 오류는 없다. cpp_sync 종료 0·연결 fixture 360개 불변이다. 이미 현행 ClientMain.cpp/.h를 추적하는 실제 Root 매핑은 유지했다.

실제 thewarbegins/tutorial1/surrounded의 시작 세 경로가 모두 종료 0이고 원본 1392파일 SHA가 불변이다. 조건은 시드 1760000000·25ms/90프레임·영어 1024×768 창/음소거다. 포획/희생·특정 적 공격·시나리오 승리는 실행하지 않았다. 근거는 extracted/dotnet-0723/capture.py, capture.log, capture-summary.json, change-details.json, capture-originals-audit.json 및 각 capture/<mission>/dn/run.json·f090.tsv다.
