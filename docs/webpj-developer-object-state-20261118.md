# WB04-E745 개발자 객체 상태 명령

`31h`의 `setLocalHitPoints`/`slhp`, `setAbstract`/`sa`, `applyDamage`/`ad`를 현재 Session의 Pool·월드·피해 장치에 연결했다. HP와 추상 상태는 원본 순서대로 Unpop·현재 슬롯 갱신·Repop을 수행하고, HP 명령은 이후 화면 강조와 실제 최대 HP 로그를 사용한다. 피해 명령은 부호 있는 입력을 원본 DWORD로 전달한다.

근거는 기준선 `225553df`의 `RawCampaignSession.cpp` `ExecuteDeveloperCommand`이며 기준선 이후 해당 파일 변경은 없다. 새 원본 fixture나 직접 cpppj 검사는 없다. 선택된 화면 강조·피해 장치가 없으면 해당 위치에서 명시 오류를 내며 다른 개발자 명령도 아직 미연결이다.

독립 검사에서 HP 쓰기·추상 상태 진단 후 현재 슬롯 재조회·피해 전달과 입력 오류의 순서를 확인했다. Tutorial 1 Session의 실제 `31h` 분배기에서 불완전한 HP 입력의 로그 경로를 확인했다. 관련 집중 검사 43건이 통과했다. 실제 공격·게임 플레이나 객체 변경의 화면 결과는 이번 검사가 아니다.

Node v26.13.0 전체 회귀 6,232건을 통과했다. 대응표 오류는 0건이며 Node v22 전체 재검사 주기는 7/8회다.

다음은 `31h`의 나머지 개발자 명령과 내부 로그인 서버 후반·응답 왕복이다. Native 분기, 행 base 뒤 변경 판정 및 앱 미션 연결도 남아 있다.
