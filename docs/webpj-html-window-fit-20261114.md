# webpj HTML 전체 크기·배치 (WB04-E457, 2026-11-14)

기준선 `1f00a25a`의 `HtmlWindowFit.cpp/.h`를 `www/ui/html-window-fit.js`로 온전히 이식해 기존 `tell-window.js` 부분 대응을 대체했다. 기준선 뒤 변경은 없어 base를 유지했다. 같은 현재 HTML 부모/본문/버튼/메뉴의 기본주소를 빌리며 별도 표시용 배치 모형을 만들지 않는다.

## 현재 주소와 계산

버튼별 실제측정 뒤 현재행/개수 재조회, 최대폭과버튼간격, 요청폭40감산, 본문natural조회와폭20재측정, 현재뷰한도·요청높이65감산·같은높이50폭복원·종횡비, 실제화면한계뒤slider/scrollable/request, 전체부모크기·한/두메뉴pop과열수/높이·버튼균등폭·본문부착·전체화면/지도직사각형중앙좌표·부모Attach뒤깊이보정을 원문순서로 옮겼다.

새 float저장마다 FST32 반올림과기존float비트캐시해제를 수행한다. 원문 signedDWORD 감김·정수나눗셈0방향절삭·signed64 `_ftol`뒤낮은DWORD·비정상값경계를 구별한다. 측정/Push/Attach/메뉴pop이 바꾼 현재부모/자식은 원문과 같은 위치에서 다시 읽고, 이미잡은실제객체참조는 그호출동안 보존한다. 하위장치가 없으면 선택한 위치에서 실패하며 앞선측정/쓰기/메뉴효과를 되돌리지 않는다.

## 검증

집중 **3건 첫 실행 통과**. `cpppj/tests/fixtures/html-window-fit-x86.tsv` **원본10.78 160행**(두FPU제어입력)의26객체×9필드, 부모6필드, 제어20행, 현재전역9DWORD, 메뉴스택·측정횟수·완료/중단·외부호출순서가 모두일치했다. fixture는 원래cpppj것을읽기만하며 manifest의 `html-window-fit`으로 연결했다. 새로운 원본실행/fixture생성은 없다.

추가 검사는 실제같은주소거부·필수장치·signed음수count·물리20행한계와 앞선20측정효과다. 실제 `HtmlWindowGump` 생성/버튼/본문을 같은 `GumpCreate` 등록표와 `GumpTree`에 연결한 장면은 독립측정(본문80×12, 버튼30/50)을 사용한다. 요청폭200에서 부모200×77·중앙(220,201.5), 버튼폭50·좌표(42,42)/(107,42), 본문(60,20), 깊이`0xffffffb0`와 같은5노드 등록을 손계산 결과와 대조했다. 이 검사의 기본생성/측정은 명시 하위계약이며 실제stone/Style/원본글꼴픽셀 대조가 아니다.

전체 회귀는 Node v26.13.0·v22.23.3에서 각각 **4,731건 통과, 실패0**, 대응표984행 오류0이다. Node v24는 이 PC에 없어 실행하지 못했다. 실제 앱은 기존 TellWindow 경로이며 이번 단위가 변경하지 않는다. RawMenuControls에서 실제stone/scroll/Style/메뉴/HTMLMetadata/Factory와 이가상Attach를 결선한 뒤 픽셀·기하·입력·수명을 대조하고 기존경로를 교체한다. 보호원본/디컴파일/cpppj파일은 변경하지 않았고 게임/브라우저실행도 없다. 실제 미션플레이는 아직불가다.

다음은 HtmlWindowMetadata의 원시버퍼/명령고리/메뉴현재값과 기준선뒤NB08 목록삽입 변경을 판정한 뒤 이식한다. 이후 Factory·TellSection·HtmlTextParser partial을 마무리하고 허브를 조립한다.
