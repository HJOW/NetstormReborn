# 0.687 공유 패킷 분배·등록과 실제 연구 운반

- 일시/호스트: 2026-11-20, HJOW-Athlon.
- 상태: Net 본체/원문 등록과 실제 세션 검증 완료다. 제품 Poll 설치와 전체 목표는 미완료다.
- 근거: cpppj `RawPacketDispatch`/`RawPacketFrame`/`PacketRegistrationTable`과 `RawFactoryResearch` 등록이다. 기존 정밀 디컴파일 소스·보호 실행 파일은 수정하지 않았다.

## 같은 실제 표와 버퍼

Net 사전 구현을 검색에서 놓쳐 Core에 중복 등록표를 작성했다가 첫 컴파일에서 발견했다. 중복 Core 파일은 제거했고 기존 `Netstorm.Net.PacketRegistrations`를 보완했다. 분배기/연구 등록도 같은 Net 모듈과 표를 사용하며 Client는 Net을 참조한다.

기존 얕은 snapshot과 baseline 별칭을 값 snapshot으로 바꿨다. 공개 슬롯 객체를 유지하며 자기 세대가 바꾼 값만 복원한다. 관찰기가 버리던 pin은 `using`으로 콜백 복귀 때 반납한다. 실제 세션 owner는 약하게 빌리고 실행 중에는 owner와 대여를 함께 보유한다. 반납 콜백 복귀 전 새 세대·전역 수정/초기화를 거부한다. 생성 실패 전 finalizer 활성화도 방지했다. 세대 번호는 주소 비교 대용이며 Runtime owner를 대신하지 않는다.

관리 입구는 같은 운반 배열의 `Memory<byte>`/`ReadOnlyMemory<byte>` 뷰다. 집합 observer도 부분뷰를 빌려 쓰므로 전체 배열 사본으로 대체하지 않는다. 기존 메타데이터 소비자의 공개 속성/`LastType()`는 유지했다. `LocalMissionTransport.RegisterMutableDispatch`는 기존 읽기 입구와 상호 교체하고 소멸 때 두 callback을 놓는다. 실제 지연 FIFO 본체는 미이식 경계다.

## 분배와 실제 수신

단일의 버전→현재 시각→10번 이상 기록→현재 F, 집합의 현재 시각→버전→기록→현재 관찰기0→저장 type의 현재 F를 구별한다. 예외에서 깊이/pin을 복구하고 원문 선언 WORD와 실제 버퍼 길이를 같게 강제하지 않는다. 고정 F snapshot·직접 nullable 호출도 구별한다.7f/80 외부 검증은 cpppj 정책대로 기록/수신 전에 무시한다.

58h의 실제 빈 관찰기·버전1/정책0·길이16을 설치하고 `HostSession.RegisterFactoryResearchCommands`가 동일 연구/업그레이드 본체를 등록한다. 실제 세션 검사는 큐/Poll→분배기→58h→연구 예측 교체 또는 SP 차감/사건3·그림/완료를 통과한다. 기록·깊이/pin 반납·등록표 복원도 확인했다. 제품 `ClientHostGame`의 양끝/Poll·입력 설치 완료를 뜻하지 않는다.

## 검증

Core Release 집중 **45/45건**과 실제 Client 세션 집중 **62/62건**, 합계 **107건 통과·실패0**다(`packet-dispatch-core-complete.trx`, `packet-dispatch-host.trx`, `extracted/dotnet-0687-core-complete.log`/`dotnet-0687-client.log`). 전체265 WORD·순서·버전 정책·현재 표 재등록·깊이/예외·세대 반납/승격·backend 분리와 같은 운반 소유 배열의 부분뷰를 검증했다.
