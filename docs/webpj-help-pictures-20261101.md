2026-11-01, **HJOW-Athlon**(마지막 전체 정밀 디컴파일 호스트와 같은 PC 이지만 이번 단위는 디컴파일 소스를 읽지 않았다. 근거는 cpppj 의 복원 소스 `StyleTextMarkup.cpp`·`Markup.cpp`·`RiftType.cpp`·`TypeParser.cpp`·`RiftTypeTable.cpp`·`TypeLoadOrder.cpp` 와 [그 근거 문서](exe/cpp-style-text-markup.md)·[Markup 그림 문서](exe/cpp-markup-picture.md)·[.type 형식](formats/type.md)·[셰이프 형식](formats/shp.md)이다). 사용자 요청("webpj 다음 작업 진행")으로 [인계](../LEFT_JOBS.webpj.md)의 '다음' 첫 항목 **도움말 그림(아이콘) 지원**을 했다. `cpppj/`·`dotnetpj/`·`originals/`·`originalCD/`·AGENTS.md·공통 `LEFT_JOBS.md`·`README.md`(이전 단위에서 받은 '공통 파일은 나중에 몰아서 갱신' 지시를 이어 지킴)·공유 명칭 JSON·`docs/formats/` 는 수정하지 않았다(읽기만). 원본 게임·analyzeManager 는 실행하지 않았고, 브라우저는 우리 웹 클론만 띄운 Edge 헤드리스다.

## 1. 범위와 결과

이전에는 본문 그림 명령 `~[I이름.프레임]`(도움말의 `<!"이름.프레임">`)을 **fortGump 숫자 프레임**만 해석해(스톰 파워 아이콘) 그 밖의 그림은 그리지 않고 콘솔에 경고만 남겼다. 이제 원본 규칙대로 전체 타입 표(`.type` 116개)와 셰이프 블록을 써서 해석한다.

| 대상 | 결과 |
|---|---|
| 영어 도움말 | 그림 조각 182개(44개 주제) 모두 해석 — 실제 그림 168개, 크기 0 인 조각 14개 |
| 한국어 도움말 | 그림 조각 181개(43개 주제) 모두 해석(`map` 주제가 영어 대체라 1개 적음) — 실제 그림 167개, 크기 0 인 조각 14개 |

화면에 나오는 것: 신전·워크샾·제네레이터 건물 그림(`~[Iwindvortex.*]` 등 세 퓨리 소개와 에너지 설명), 스톰 간헐천·스톰 크리스탈 그림, 썬/썬더 캐논 그림과 에너지 요구 기호(`mana.2`·`mana.3`), 주문 아이콘 18개(`bomb*.1`)와 오벨리스크(`buried`), 플레이어 목록·챌린지 링 창의 아이콘(`fortGump.L*`·`icon.B*`·`93.109~113`), 팀 방패·핸디캡 아이콘, 챌린지 링·지역 그림(`battleIsland`·`challengeIsland`), 영어 도움말의 님버스 지도(`map` 주제의 `buried.2`, 408×595). 크기 0 인 14개는 `mana.8~11`(아래 4절 1번).

## 2. 원본 규칙(cpppj 근거)

| 단계 | 규칙 |
|---|---|
| 타입 | 첫 캡처를 CRT 정수로 읽어 0 이 아니면 그 번호, 0 이면 같은 문자열을 타입 이름 표에서 **대소문자 무시**로 찾는다(`fortgump`·`FortGump` 같다). 못 찾으면(-1) 그림이 없다. 자산 타입의 번호는 **70 + 로딩 순서(0~115)** 이고 타입 표 전체 크기는 188 이다. |
| 프레임 식 | 첫 글자가 `*`(`#`·`&` 는 65×60 상자 맞춤)이면 **gumpFrame**(`gumpframe` 클러스터 번호, 없으면 -1 이라 **defaultFrame**). 첫 글자가 `A ≤ 글자 < A + letterKinds` 이면 그 방향 글자를 가진 **첫 클러스터 번호 + 뒤의 숫자**(`fortGump.L6`·`icon.B0`). 그 밖은 식 전체를 숫자로 읽는다(`mana.2`·`93.113`, 글자 구간 밖 글자는 숫자 0 이 되어 프레임 0). |
| 클램프 | 프레임이 0 미만이면 0, **프레임 수(클러스터 수) 이상이면 프레임 수**로 바로잡고 그 번호에는 그림이 없어 크기 0 조각이 된다. |
| 셰이프 | 그림은 타입의 셰이프 블록(블록 번호 = 로딩 순서)의 **논리 프레임 = 클러스터 번호(레이어 0)** 이다. 그림자 레이어는 그리지 않는다. 폭·높이·기준점은 프레임 앞 36바이트 추가 헤더 값이고 기준점은 타입 기준점(`hotFootRatioX/Y` × 16/11 을 0쪽으로 버림)을 **하위 16비트로 뺀 값**이다. |
| 줄 배치 | 그림 조각의 기준선(올림 높이)은 기준점 y, 높이는 그림 높이이다(이미 구현된 `ui/style-text.js`). |

`.type` 문법은 `typename 이름 … typeflags … ; { 키 = 값 ; … }` 다음에 `클러스터이름 : 플래그 : "그림.gif" #번호 [: …] ;` 줄이 파일 끝까지 이어진다. 클러스터 이름은 방향 글자(A~Z)·변형(없으면 'P')·번호(하위 8비트)로 쪼개고, 플래그 7종(`fringe`·`suck`·`rim`·`lit`·`unlit`·`cracked`·`hard`)은 코드 비트, `default`(마지막 것)·`gumpframe`·`baseframe`·`help` 는 특수 프레임 번호가 된다. `help` 가 한 번이라도 나오면 그 뒤의 `default` 는 도움말 프레임을 바꾸지 않는다.

## 4. 원본과 다르게 둔 점·가정

1. **`mana.8`~`mana.11`(윈드·레인·썬더·썬 에너지 기호)은 크기 0 이다.** 10.78 패치의 `mana.type` 이 클러스터 8개(A01~A08)뿐이라 번호 8 이상은 원본 규칙대로 그림이 없다(cpppj 가 원본 기계어에서 확인한 "프레임 수 이상은 무자산" 규칙). 영어 `help.english` 는 옛 판본 번호(`mana.8~11`)를 그대로 써서 도움말의 "에너지 기호" 줄 앞이 비어 보인다. **실제 10.78 화면에서 이 줄이 어떻게 나오는지는 원본 도움말 화면으로 확인하지 못했다**(원본 스크린샷은 F1 첫 화면뿐이고 원본 게임은 실행하지 않았다). `mana.2`·`mana.3`(캐논 건설 에너지 요구 기호)은 그려진다.
2. `*` 그림은 **큰 건물 그림(기본 프레임)** 이다. `.type` 에는 도움말용 `help` 클러스터(`b_wtemple.GIF` 등)가 있으나 `*` 규칙은 그것을 쓰지 않는다(cpppj 규칙대로). 그래서 `themeHelp`·`influenceHelp` 에서 건물 그림이 줄을 100~150 픽셀 높이로 만든다.
3. `#`·`&`(상자 맞춤·색 치환) 그림은 지원하지 않고 null(경고)이다. 현재 도움말에는 쓰이지 않는다.
4. 레이어 0(본체)만 그린다(그림자 레이어 없음). 타입별 테마 팔레트는 쓰지 않고 다른 스프라이트와 같은 게임 팔레트로 그린다.
5. 타입 이름은 자산 타입 116개만 찾는다(내장 프로세스 타입의 이름은 모두 `…ProcessType` 이라 그림 이름과 겹치지 않는다). 내장 번호(70 미만)·여분(186~187)은 크기 0, 표 밖 번호는 null 이다.
6. 한 타입의 `.type` 을 읽지 못하면 그 타입만 프레임이 없는 타입이 되고 콘솔에 경고한다(지금 116개 모두 읽힌다).

## 6. 남은 일

1. **`mana.8~11` 줄의 원본 모습 확인**: 원본 10.78 의 F1 도움말(님버스의 세계/세 퓨리 → "에너지" 항목)을 한 번 열어 이 기호 줄이 비어 보이는지 확인한다(원본 실행은 개발자 확인 필요). 다르게 나오면 `.type` 패치 차이(클러스터 수)를 다시 따져 본다.
2. `#`·`&` 상자 맞춤·색 치환 그림(인벤토리·지식 창 등 미션 구현 때 필요), 도움말 `<info>` 머리글(타입 그림·능력치)은 미션·게임 화면 구현에서 이 타입 표를 그대로 쓰며 이어간다.
3. 도움말 그림 시험 화면의 한국어·영어 비교와 큰 건물 그림 줄의 스크롤 감각 확인(개발자 검수).
4. 맨 위 인계의 나머지(미션 스크립트 한국어·Auto-Demo·Options −40 규칙·본문 끌기 Overlay·커서 2~14), 그 뒤 정적 맵 화면(M2) — 이 타입 표와 셰이프 대응은 M2 의 지형·건물 그림에도 재사용된다.
