# 0.765 실제 Chat Identity와 대상 검사

ClientChatIdentityRuntime이 실제 장기 Game/Surface/Subscriber/Chat을 기존 RawPlayerIdentity 본체에 연결한다. 각 진입에서 현재 표시 이름을 먼저 읽고 현재 CoreData.Players의 정확한 PlayerBytes 배열을 복사 없이 다시 빌린다. Player 재할당 뒤 이전 배열을 계속 쓰지 않으며 기존 Core의 byte[] 참조 계약도 유지한다. 현재 소유자·구독자·주소·전투/편집/메타 모드는 사용 위치에서 조회한다. 메타 CS 제공자는 선택된 메타 검색에서만 필요하다. 부분 Memory 뷰는 현재 실제 Root 경로의 계약 밖이며 명시적으로 실패한다.

ChatRecipients는 원문 네 구분자, 전체 토큰 길이와 40BYTE 복사 경계, 부분 초기화, Identity 우선 조회, 빈 키를 포함한 여덟 채널 번역 순서를 복원했다. 번역 callback 뒤 같은 지역 이름을 다시 읽으며 mode와 미작성 꼬리를 보존한다. 일반 이름 getter는 실제 SOMEONE 실패 이름과 NUL 포함 복사를 유지한다.

실제 Game에 BSS0 LocalAddress 슬롯을 추가하고 Host에 같은 소유자의 Identity/대상 검사/제출 binding API를 연결했다. 실제 LAN 주소 writer, CS와 ChatWindow/Console UI가 이 API를 설치·소비하는 경로는 후속이다. 일반 메시지/패킷 전달도 아직 연결하지 않았다.

신규 7건을 포함한 집중 검사 19건이 모두 통과했다. 기존 원문 대상 검사 350관측과 실제 Identity 접합 48관측의 전체 지역 바이트·결과·효과 순서를 대조했다. fixture의 일반 헤더를 포함한 물리 행은 각각 351/49이며 기존 386항목·헤더·기대값은 유지하고 두 원문 링크를 추가했다(총388). 같은 facade에서 Player 재할당, 늦은 이름/메타 관문, fallback과 꼬리 보존도 확인했다. 새 경고는 없다.

대표 thewarbegins/tutorial1/surrounded 시작은 모두 종료0이고 전체 덤프 바이트·지표가 0.764와 같다. 원본 1,392파일 불변, cpp_sync 종료0, 최종 감사 종료0이다. PORT_MAP에 네 대응을 추가했다. CPP/디컴파일 변경이나 외부 접속은 없으며 실제 포획/희생·특정 적 공격·승리는 재현하지 않았다.

근거는 extracted/dotnet-0765/의 test.log·client.trx·source-revisions.json·register.log·fixture-audit.json·cpp-sync.log·capture.py·capture.log·capture-summary.json·capture-originals-audit.json·capture/*/dn/*·audit.py·audit.log·final-audit.json이다. 다음0.766은 같은 실제 소유자의 일반 Chat 메시지/패킷과 창 UI 연결을 진행한다. 다음 정기 전체 회귀는0.768이며 전체 목표는 미완료다.
