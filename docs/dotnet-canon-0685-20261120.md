# 0.685 원문 생산 Deck·추첨·Player 링크 정리 기반

- 일시: 2026-11-20, HJOW-Athlon.
- 근거: `RawProductionDeck.cpp/.h`·`RawDeckDraw.cpp/.h`·`RawPlayerLinksCleanup.cpp/.h`다. 디컴파일 자료는 변경하지 않았다.
- 상태: 원문 본체/저장소·집중 검사·자료 해시 검증을 완료했다. 제품 연구 연결과 전체 목표는 미완료다.

## 구현

`RawProductionDeckStorage`는 Player+68의 불투명 DWORD와 실제352바이트 블록을 연결한다. 기존 포인터를 먼저 조회하고 없는 경우에만 명시 fill 입력으로 할당한다. 생성 초기화는 다섯 DWORD만 쓰고 항목·두 패딩·미정 꼬리를 보존한다. free0은 무효과이며 비영 토큰은 실제 소유자만 반납한다. 블록 반납과 새 세션에서 다음 주소를 되감지 않는다.

`RawProductionDeck`는 같은 `RawPlayerWorld`의 현재 templateOwner와9개 기록을 사용한다. 공통 항목 추가의 진단/쓰기 순서, 전체 type DWORD와 BYTE 비교, 최초 일치의 signed power 활성화,5바이트 전방 압축과 꼬리 보존을 이식했다. 일반 모듈 소멸은 현재 자기 소유 포인터만 지우고 외부 교체 포인터는 보존한다. 저장소는 외부 장기 owner를 받을 수 있지만 실제 Client 장기 소유자 설치는 후속이다. 반납한 블록의 이전 바이트 뷰는 호출자가 재사용하면 안 된다.

`RawDeckDraw`는 공통 초기화/추가와 Open/Close/Draw를 담당한다. Open0seed만 전역 난수를 소비하며 Draw는 현재 벽시각의1013배/ftol 낮은DWORD에서 만든 독립 난수를 쓴다. 합계 진단/로그 뒤 현재 표를 재계산하고, 시각 효과 뒤 현재 항목을 읽는다. optional power 분류는 출력이 요청된 경우에만 호출한다. BYTE 추첨 수와 DWORD 누적 수의 감김과 효과 실패 이전의 부분 쓰기도 유지한다.

`RawPlayerLinksCleanup`는 매 load/store에서 현재 Player base를 조회한다. 각 기록의 기술/개수0쓰기→현재 Deck 포인터 읽기→실제 free→현재 base 재조회/후속0쓰기 순서다. free0/owner 조건·기술 객체 삭제를 추가하지 않았다. 전체 부모가 정상 복귀한 같은 Deck만 반납 증빙을 발급하며, 소비는 동일 모듈·호출 복귀·실제 블록0·세 링크0을 요구한다. 관리 코드의 증빙은 약한 owner 정체성과 단일 소비로 표현한다. 진행 중 관리 모듈 소멸도 명시 거부한다. Native 전체 Runtime 반납/pin 체계의 연결 완료를 뜻하지 않는다.
