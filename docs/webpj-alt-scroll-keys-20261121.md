# Alt 스크롤 연결과 원본 조작키 대조 (WB04-E1145)

원본 도움말 `NetStorm User Interface`(웹 도움말 주제 `interface`)가 적어 둔 조작키를 웹 미션 화면에서 실제로 눌러 대조했다. 방향키 스크롤은 원본에 없다(웹과 같음). 원본에 있는데 웹에 없던 **Alt 스크롤**을 연결했다.

## 원본 도움말의 조작 (요약)

- 왼쪽 클릭: 선택, 오른쪽 클릭: 메뉴. **Alt 를 누르고 있으면 커서 쪽으로 화면이 움직인다**(전체 화면에서는 커서를 화면 가장자리에 대면 움직임. 가운데 휠 버튼은 Alt 와 같음). Esc: 위쪽 옵션 메뉴.
- F1 도움말, F2 건물 숨김, F3 채팅 창, F4/H 집(신전), F5 사제, F6 지식, F7 섬 색, F8 목표, F9 온라인 목록, Shift-F3 섬 테마, Shift-F7 화면 저장, Shift-F9/Pause 정지, Tab 최근 다섯 유닛 순환, Ctrl-F5 또는 N 운반체 순환, T 시간 표시, P/R 사제 선택(두 번이면 이동), D 마지막 생산 유닛 쥐기, C 회전 방식, U 마지막 잃은 유닛으로 이동, E 마지막 다리 슬롯, Q/W/A/S(Z/X) 다리 조각 쥐기, **Shift+숫자 0~9 화면 위치 기억 / 숫자 키 그 위치로 복귀**.

## 웹 실제 점검 (The War Begins!)

| 키·조작 | 결과 |
| --- | --- |
| F4 (집), F5 (사제) | 정상(서로 다른 위치로 점프) |
| 화면 가장자리에 대기 | 정상(정확한 가장자리 픽셀에서 4방향 모두) |

| **Shift+숫자 저장 후 숫자로 복귀** | **동작하지 않음**(미구현, 아래 남은 것) |
| **H (집으로 점프)** | **동작하지 않았음 → E1146 에서 수정**(원본 도움말 "F4 or H"). 선택 키 분배기는 H 를 이미 처리했지만 브라우저 문자 키 허용 목록 `[nprqwaszyxet]` 에 `h` 가 없어 사건이 큐에 들어가지 않았고, 입력 루프의 `selectionKey` 에도 빠져 있었다 |

| 가운데(휠) 버튼 누른 채 이동 | 정상(Alt 와 같은 경로, 선택은 바뀌지 않음, E1148 에서 e2e 로 고정) |
| 우클릭 메뉴가 열린 채 Esc | 원본과 같음(조각을 쥐지 않았으면 게임 메뉴막대를 열고 한 번 더 누르면 닫음) |
| D·C·U·Tab·Ctrl-F5 | 처리 코드가 웹에 없거나(D·C·U) 이 미션 시작 상태로는 확인할 수 없음(Tab·Ctrl-F5) |

## Alt 스크롤 원인과 수정

- 원인: 원본 `4d6b54`(Alt/가운데 버튼 카메라 이동)의 본체 `processCameraPan` 은 웹에 이식(E437)돼 있었지만 앱 입력 루프가 부르지 않았다. 원본의 포인터 폴링은 Alt 를 폴링한 결과(`POINTER_POLL = 0x12`)이고, 이동 경로는 Alt 또는 가운데 버튼이 눌린 동안만 켜진다. cpppj `UberGump::PollCameraPan` 이 같은 일을 한다.
- 수정:
  - `www/ui/uber-gump-camera.js` 에 `pollCameraPan(mouse)` 를 더했다(설정 `scrollWhileMouseOut`·대화상자·활성 여부·화면 크기·월드 지도 영역을 호출마다 읽어 `processCameraPan` 에 넘기고, 목표 요청은 가장자리 스크롤과 같은 `requestCameraDelta`).
  - `www/netstorm.js` 미션 입력 루프가 커서 갱신 뒤 이를 부르고, 이동 경로가 처리한 프레임(true)에는 큐의 사건을 일반 입력으로 나누지 않고 버린다(원본·cpppj 와 같음).

## 시험

- `tests/uber-gump-camera.test.mjs`: 누름/뗌·가운데 버튼·Shift 한 축·대화상자·창 밖(설정 on/off)·월드 지도 영역 기준을 검사한다.
- `e2e/mission-camera-alt.spec.js`(Chromium, `NETSTORM_E2E_ASPECT` 로 화면비 선택): Alt 를 누르고 포인터를 오른쪽 아래·왼쪽 위로 옮기면 카메라가 따라 움직이고, 떼면 멈추며, F4·F5 가 다른 위치로 점프한다. 연결을 빼면 실패한다. 4:3·16:9 에서 통과했다.

## 남은 것

- **Shift+숫자 화면 위치 기억 / 숫자 키 복귀**: 원본 도움말에 있으나 웹과 cpppj 모두 구현이 없다. 원본 바이너리에서 처리(키 코드·저장 대상·복귀 방식)를 확인한 뒤 연결해야 한다.
- D(마지막 생산 유닛 쥐기)·C(회전 방식)·U(마지막 잃은 유닛으로 이동)는 문자 키 허용 목록과 입력 루프에 없어 눌러도 아무 일이 없다. Tab(최근 다섯 유닛 순환)·Ctrl-F5(운반체 순환)는 유닛이 있는 미션 상태에서 확인해야 한다.
