# dotnetpj 공유 SID와 다리 붕괴 스캔의 세션 연결 — 2026-10-09

작업 PC는 `HJOW-Athlon`(Windows, .NET SDK 10.0.401)이다. AGENTS.md와 두 인계 문서를 읽고 LEFT_JOBS.dotnetpj.md 4-5의 사용자 결정에 따라 구현했다. 기존 디컴파일의 마지막 PC도 `HJOW-Athlon`이어서 그 결과를 읽었다. 디컴파일·내보내기 산출물은 바꾸지 않았다. cpppj·원본 파일·AGENTS.md·LEFT_JOBS.md도 수정하지 않았다.

## 정적 근거

`extracted/refined/originals/Netstorm.c`의 다음 함수를 읽었다. 새 원본 게임 프로세스를 실행하지 않았다.

- `Construction.cpp`의 `00442c80`은 전달받은 SID 목록을 배치한다. 그 함수 자체가 할당 flags를 고르는 것은 아니다. 서버의 건설 확정 `00444590`은 `004af530(type, 0)`으로 목록을 만들고, 클라이언트의 임시 배치 `004433b0`은 flags 2를 쓴다. `004af530`은 인자를 `004af1d0`에 그대로 전달한다. 현재 싱글 플레이는 서버 영역을 쓴다.
- 저장 오브젝트 로더 `Template.cpp`의 `004bdc60`도 `004af530(type, 0)`을 쓴다. `004be160`은 청크 안 저장 순서대로 읽고 `004be2c0`·`004be3c0`은 청크를 y→x로 돈다. 클론의 `FortMap.Objects` 순서(Chaff→TerrNN, 청크·레코드 순)를 유지했다. 본섬 생성과 동적 받침·내용물 등 사이에 추가되는 원본 오브젝트의 전체 순서는 아직 같다고 주장하지 않는다.
- `Clientmain.cpp`의 `004395df`는 `004af170(120000)`을 호출하고 `004af170`은 이 값을 `004abb10`으로 전달한다. 풀은 **120,000슬롯**이고 연결 값은 16비트다. C#의 65,535슬롯 제한을 120,000으로 바꾸고 원본처럼 연결 값의 넘침을 보존했다. 서버 목록은 15000~23000, 마지막 빈 슬롯은 예약 꼬리여서 처음에는 **8,000개**를 할당할 수 있다. 세션은 예측 영역을 사용하지 않는다.

## 구현

`BattleMap.Sids`가 한 판의 공유 서버 풀이다. 저장 엔티티·저장 noIsland 논리 지면·다리·건설 현장·생산 예약·초기 AI 수집자·비행체가 이 풀에서 번호를 받는다. noIsland는 번호만 받고 기존처럼 엔티티·점유를 만들지 않는다. 저장 다리는 로더가 먼저 받은 번호를 `AddStored`로 전달해 두 번 할당하지 않는다. 독립 격자를 세션에 직접 전달하는 경로도 풀과 실제 bridge 타입 번호를 연결한다.

다리의 `Sequence`는 `Sid`로 바꿨다. 좌표와 SID 조회를 함께 관리하며 붕괴·약화·좌표 교체 때 번호를 반납한다. 엔티티의 회수·파괴·낙하·생산 취소·도착 전 공사장 취소도 번호를 FIFO 꼬리에 돌려준다. 번호 재사용에 세대 비트는 추가하지 않았다.

`BridgeGrid.Update(now, delta, paused)`는 `BridgeDecayScan.Advance`의 `[begin,end)`를 SID 순으로 돈다. 24Hz에서 보통 틱은 33슬롯, 10초 경계 틱은 남은 슬롯을 처리하고 커서를 초기화한다. 빈 슬롯과 다른 종류의 오브젝트는 건너뛴다. 안내·일시정지 중 기존 화면이 틱을 호출하지 않으면 스캔도 진행하지 않는다. 직접 `Update(now)`를 호출하면 그 호출은 스캔 한 번이며 여러 틱을 재생하려면 각 틱을 호출해야 한다.

번호 소진은 **새 코드의 안전 처리**로 명시했다. 원본의 최대 50개 다리 삭제는 미복원이므로 새 배치·건설은 비용과 점유 변경 전에 `ObjectLimit`으로 거부하고, 다리 조각도 필요한 번호를 전부 확보할 수 있을 때만 놓는다. 집은 조각은 유지한다. 자동 비행체·AI 초기 생성은 여유가 생길 때까지 건너뛴다. 초기 맵 자체가 풀을 넘는 경우에는 로딩 예외이며 거대 맵의 원본 소진 복구는 후속이다.

검사합에는 다리 SID·스캔 커서/주기 끝·서버 빈 목록 연결/상태/타입·풀 카운터를 넣었다. 같은 보이는 월드라도 다음 생성 번호가 다른 상태를 구분한다. 기존 검사합 테스트는 고정 숫자 대신 동일 명령열의 두 실행을 비교하므로 새 고정 검사합을 적지 않았다.

## 검증과 기대값 변경 이유

- Release 빌드: 경고 0·오류 0. 전체 **872개 통과**(Assets 281 + Core 591, 기존 861 + 통합 검사 11). 기존 x86 fixture **48,639입력**의 파일과 계산 기대값은 바꾸지 않았고 전체 테스트에 포함해 통과했다.
- `SidSessionTests`: 실제 크기 초기화·16비트 연결, noIsland/엔티티/다리의 공유 번호, 실제 `b10` 저장 다리 번호 재사용, 33슬롯의 배타적 끝, 마지막 구간·10초 재설정, 정지·새 판 초기 시각, 두 다리 삭제 경로, 엔티티 반납, 조각의 부분 생성 방지·비용 유지, FIFO 상태 검사합을 확인했다.
- 합성 맵 테스트의 엔티티·명령·목표·공급원 번호는 `OriginalData.Sid(저장순번)`으로 바꿨다. 체력·피해·비용·자원 개수·이동 기대값은 그대로다. `X86SidTests.InvalidInput`의 잘못된 상한만 65536에서 120001로 바꿨다. 원본의 초기화 인자가 120000이기 때문이다.
- `BridgeGridTests`는 큰 시각 점프 대신 24Hz를 재생해 구간의 알림을 모은다. 수명 기대값은 동일하다. 첫 슬롯 다리의 첫 방문은 10초가 아니라 1/24초이며 금 감은 30+1/24초, 붕괴는 70+1/24초다. `BattleSessionTests`는 SID로 해당 틱을 계산해 전후를 검사한다.
- `GroundSupportTests`의 한 칸짜리 분리 다리는 SID 15001이므로 첫 틱에 삭제되고 위 유닛도 같은 틱에 낙하한다. 기대 틱을 240에서 1로 바꿨다. 적 다리 위 지지 검사는 다섯 칸 연결망을 사용해 작은 그래프 즉시 삭제와 지지 소유권 판정을 분리했다.
- 원본 맵 아홉 개의 5분 저장 다리 회귀는 **90% 이상 생존 기준 그대로 통과**했다. 새 수명·그래프 조건을 완화하지 않았다.
- 클론 창 자동 검사: 캠페인 1-1·1-2 진입, 조각 집기·배치 모드·메뉴 복귀, 16:9 해상도·전체화면/창 복귀·설정 저장 통과. 메뉴 캡처 18개와 로그는 `extracted/screens/dotnet-sid-session-20261009/`에 있다.

추가 창 검사는 `BridgeTheGap` (43,31)에 한 칸 조각을 놓고 일반·금 감·붕괴 후 화면을 캡처했다(`17-sid-normal.png`·`18-sid-cracked.png`·`19-sid-collapsed.png`). 같은 맵의 게임 시작 시각 0에 놓은 SID 15003은 헤드리스에서 30.041667초에 금, 70.041667초에 붕괴했다. 창 검사에서는 이미 커서가 지나간 뒤에 놓아 첫 방문이 다음 주기 10.041667초이며 금은 40.041667초·붕괴는 80.041667초다. 이는 배치 후 항상 10초 경계부터 수명을 세는 동작과 구분된다. 창 자동 입력은 초기 마우스 상태가 풀린 뒤 클릭하도록 1초 대기를 둔다.

남은 근사는 실제 표면 오브젝트 identity·지속되는 Graph의 표면 수·전체 원본 생성 순서다. 투사체는 현재 `CombatShot` 기록이라 SID 오브젝트가 아니며 동적 받침/내용물 오브젝트도 별도 SID로 만들지 않는다. 따라서 커서 알고리즘과 현재 월드의 SID별 스캔은 정확하지만 원본 플레이의 절대 스캔 위상까지 동일하다고 보장하지 않는다. 다음 작업은 4-3 spot 지도 클래스와 4-1 실제 그래프 연결이다.
