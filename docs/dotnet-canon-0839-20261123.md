# dotnetpj 0.839 — Native Player 정기와 현재 Template 후단

2026-11-23, HJOW-Athlon. 같은 Native Root의 Player 상태/정기 장치를 실제 Session에 연결했다. 전체 Native Root·Load/Editor 공개는 계속 미완료다.

## 변경

- `RawSurfacePlayerRegular.cpp`의 최초 현재 Player 상태 설치, 약한 Template 후단, 실제 Regular 확보/같은 객체 초기화·Host 부착, 현재 VT·로그/진단·원문 본체 분배를 이식했다. 첫 설치는 owner/known/게임값을 쓰지 않으며 다른 판본·전송 없는 설치·재설치·World 대여 뒤 설치를 거부한다.
- `RawPlayerRegular.Run`에 실제 `PlayerWorldState`/`SquidOwnerMode`를 빌리는 경로를 추가했다. 첫 로그 뒤 현재 battle을 읽고, 실제 pin 뒤 Template owner를 읽으며, State 쓰기 뒤 Notify에 현재 owner를 다시 읽는다. 기존 값형 검사 API도 같은 본체를 사용한다.
- 제품 최초 Native 전송/선택 장치 설치 뒤 같은 Gameplay.Player 주소를 연결했다. Graph/Player 로그는 같은 사용자 로그 장치에 전달한다. 실제 Session의 Player 정기 분배는 이 장기 본체를 사용하고, 현재 Template getter·Notify·Runtime pin만 약하게 빌린다. Session 반납은 자기 대여만 해제한다. 같은 실제 Host에 사건2·payload60·현재 시각·count0이 생성된다.
- World 없는 **전체 기본 Regular 분배기**는 아직 미연결이다. 이번 실제 호출자는 Session의 기존 Player 가상 분배다. 다른 VT·Template 없는 선택 분기를 payload 반환이나 가짜 성공으로 대체하지 않는다.
- PORT_MAP의 이전1636행 값/순서/base를 보존하고4쌍을 추가했다. 자료1640(port1152/L1 481/session7), fixture452개다. 재집계는 CPP1240단위169,438줄 중626단위106,131줄 대응·614단위63,307줄 미대응이다. 부분 이식/연결을 포함한다.

제품 변경 뒤 Release 솔루션 빌드는 오류0·기존경고6이었다. 새 검사 장면을 붙이는 동안 도우미/형식 이름 컴파일 오류를 바로잡았다. 첫 새7검사는6통과/1실패였고, 실제 지역 장치 앞의 지형 바인딩을 검사 장면에서 빠뜨린 문제였다. 기존 제품 보호 조건을 완화하지 않고 같은 지형 장치를 설치했다. 첫 로그/TRX는 `preflight`로 보존했다.

최종 새7/7 및 확대 Client71/71·Core30/30 합계101건이 통과했다. 현재 mode/owner 재조회, 비로컬/count0의 float 비트 보존, 실패 prefix/Notify 뒤 State 보존과 pin 반납, 잘못된 대여 반납 거부, 실제 공유 Surface·Host 사건2 예약/현재 Template 표시를 확인했다. 새 원본 fixture를 생성한 검증은 아니다.
