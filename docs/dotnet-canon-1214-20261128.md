# 1.214 Scene 월드 조회와 현재 가상80 분배

원본 희생·대기실 판정의 두 상위 함수와 실제 현재 Surface 조회를 연결했다. Game는 기존 State 소유자 검증 뒤 같은 Surface와 기존 `_challenge`를 빌린다. **집중75통과·실패0**, 대표3미션 종료0·기존 화면/덤프·보호1,392파일 불변이다. 감독 생성·Start/Frame과 날씨 효과는 아직 F–G의 후속이다. 사용자 요청으로 이 단위 문서·커밋 뒤 목표를 일시 중지한다.

## 조회와 현재 소유자

`SceneMusicWorldQueries`의 희생 판정은 같은 등록 목록에서 첫 살아 있는 소유 사제를 찾고, 현재 좌표의 거의올림 중심에서 반경3·flags1 일반 finder로 첫 Flags2 `0x400000` 후보를 찾는다. 후보 owner/dead/free 필터나 TYPE165 고정 조건은 추가하지 않는다. 현재 프레임 DWORD를 먼저 저장한 뒤 그 후보의 현재 VT+80 Count를 읽고 기존 StageFromCount에 전달한다. 기존 BattleSession의 희생 표시나 Player 기술 조회를 빌리지 않는다.

대기실 판정은 현재 Challenge → 전체 PlayerKnown → 현재 BattleOwner getter → 복귀 뒤 현재 CS 참가자 `+0xa4` DWORD 순서다. 일반 모드/Known0은 자연 false이며, 선택된 CS0·미등록 물리는 임의 false로 숨기지 않는다. Game의 같은 `_challenge`는 이미 패킷·채팅·NSInfo가 사용하는 장기 소유자다. ClientConnectionGlobals에 CS가 있는 것으로 가정해 별도 소유자를 만들지 않았다.

실제 두 인자 ForCurrentSurface는 같은 Surface의 SceneMusicVirtualCount를 만든다. 생성·결선은 TYPE 적재, CS 준비, 목록 초기화, 시각·난수·파일·곡을 실행하지 않는다. Game의 SceneMusicWorld는 이전 Session을 캡처하지 않으며 같은 장기 표/풀의 이후 변경을 읽는다. 세 인자 overload는 독립 검사의 명시 외부 경계를 보존한다.

## 현재 VT와 기존 의식 본체

현재 VT가 지원되는 실제83개 중 하나인지 확인하고 공통81개는 기존 RawSquidLevel, 제단 `005076b8`은 현재 DaisType의 첫 typed 후보에 다시 가상 분배, Dais `00507950`은 기존 의식의 같은 CountIn을 선택한다. TYPE 생성자와 현재 VT의 쌍 일치를 강제하지 않는다. 알 수 없는 VT와 손상된 자기 재귀는 명시 실패다. finally는 호스트 재귀 표식만 반납하며 게임 전역을 복구하지 않는다.

RawTempleRitual.Count의 기존 본문을 static CountIn으로 추출해 두 소비자가 함께 사용한다. PATCH의 frame36 signedDWORD와 CD의 frame34 BYTE 폭을 그대로 유지한다. 이번 실제 월드 adapter는 PATCH만 허용하며 CD 새 실행 검증을 뜻하지 않는다.

실제 자산의 genus 후보는 TYPE165 dais와 TYPE169 daisExtraFrames다.169 생성자는 `0044a420`으로 진단 정상 복귀 뒤 같은 Dais VT를 저장한다. 이전 조사에서 미해결 기록을 base fallback으로 읽은 추정은 정정했고 제품·기대값에 사용하지 않았다.

## 검증과 남은 범위

기존 Scene9,339행과 의식6,720행 기대값은 수정하지 않았다. HostSession의 기존 Dais 고정 hook, FortLoad의 미연결 VirtualCount 등 일반 세션 소비자는 R6에서 같은 실제 분배기로 이어야 한다. 이번 장기 월드 대여를 그 소비자나 감독 F–G의 실제 실행 완료로 표시하지 않는다. 전체 State 부모·NativeLoaded·게임 시각/RNG 차이와 미니맵 수명·픽셀 관문도 계속 미완료다.

## 사용자 요청 중지와 재개

1.214를 마치고 문서·로컬 커밋 뒤 목표를 일시 중지한다. 다음 C/D/E/F 준비물은 모두 미수입·미빌드·미실행 상태로 동결했다. 실제 파일/loaded 입구를 먼저 마무리하고, 현재 UI 색 갱신과 Thunder 부착/모드 수명 뒤 감독/Start/Frame·State 부모로 잇는다. 상세 경로와 한계는 [후속 계획9절](dotnet-scene-followup-plan-1211-20261128.md#9-1214-중지-시점의-재개-준비물)과 LEFT_JOBS.dotnetpj.md에 기록했다.

정기1.210 뒤 제품211·213·214 세 단위를 마쳤으므로 다음 제품 단위 뒤 전체 회귀다. 이전1.212 합산7,609는 당시 결과이며 변경된 Core의 현재 전체 재검증으로 세지 않는다. 다른 채팅의 CPP/WB 수정은 이번 DN 커밋에 포함하지 않고 push도 하지 않는다.
